测量的人有时会把一张纸标签系在北畦的篱笆上，标签上不写死 120，只写「看这一条」。之后谁改标签旁边的木桩读数，北畦的长度就变了。C++ 的引用就是这种标签：它不是一份独立的厘米数，也不是可以晚点再系上的空绳。声明引用的那一行必须指出它系在谁身上。没有「先有标签、以后再决定系哪一条」这种写法。

语法是在类型和名字之间写一个 `&`。`int &edge = north;` 让 `edge` 从这一刻起就是 `north` 的另一个名字。两个名字读到的是同一块 `int`。这和指针不同。指针可以是空的，可以先声明再赋值，赋值会改指针自己指去的地址。引用没有空值这一档，也不能在出生之后改去绑另一个对象。你后来写 `edge = south`，编译器把它当成「把 `south` 里的数抄进 `edge` 所系的那个对象」，也就是抄进 `north`。北畦变成南畦的读数，南畦自己还在。两条边都变成 150 时，若你以为标签换了挂靠，就会把北畦的木头也锯成南畦那么长。

这个规则要在初始化时就付账，是因为引用在语言里被做成「对象的别名」，而不是「可更新的地址变量」。别名若允许暂时不指向任何对象，后面每一次使用都得问它是不是空的，那和指针就没有差别了。设计者把空值从引用的取值里拿掉，换来的是声明处必须有一个活着的对象。代价是你失去了延迟绑定：函数开头不能先写 `int &edge;` 再在某个分支里绑定。那一行本身就过不了编译。不能运行的块里留着这个失败的形状，是为了让你看见诊断会发生在声明上，而不是发生在第一次使用上。

还有一种绑不上的情况：非 const 引用不能绑到纯右值。`int &edge = 120;` 没有一个可以修改的对象，120 只是表达式的结果。语言拒绝这种绑定，免得你通过引用改一个即将消失的临时量。const 引用可以绑到临时量，并且会把临时量的寿命延长到引用的寿命那么长。菜地的长度需要能改，所以这一章用普通引用，绑到有名字的 `int` 上。临时量那条路不拿来装测量值。

取舍对着指针来说最清楚。指针能表示「还没量」：空指针就是还没系上。引用把「还没量」推出了类型系统，你必须用别的办法表示缺失，例如单独的状态码，那是失败那一章的事。指针能在循环里改去指向下一畦；引用做不到，你要么再声明一个新引用，要么就通过现有引用改当前这一畦的数值。改数值往往正是你想要的：纸标签留在北畦上，你修正的是读数，不是把标签撕下来贴到南畦。若业务真的是「标签改贴」，引用是错误的工具，应当用指针或用下标。

生命周期是第二笔账。引用不延长你绑上的那个自动变量的寿命（const 引用延长临时量是例外，不是常规）。`north` 若是某个函数里的局部变量，返回 `int&` 指向它，调用方拿到的就是悬空别名。这份单文件教程把引用和它绑的 `int` 放在同一个 `main` 里，`north` 活得比 `edge` 长，悬空不会发生。等到类里出现引用成员，绑定会挪到构造函数的初始化列表，对象仍然不能比那块 `int` 更长寿。那一章再写。这里先记住：引用在出生时绑上，绑上的对象必须盖过引用的一生。

下面先让两个名字读到同一个 120。输出写成 `120 120`，用来证明别名和原名一致。若只有一个 120，无法分辨你是印了两次北畦，还是印了北畦和某个碰巧相同的字面量。

```cpp run expect="120 120" title="标签和木桩是同一个数"
#include <iostream>
int main() {
  int north = 120;
  int &edge = north;
  std::cout << north << " " << edge << "\n";
  return 0;
}
```

第二份程序通过标签改读数。`edge = 90` 之后打印 `north`。终端里应当是 90，而不是原来的 120。90 不在最初的三条边里，它是修正值，用来把「改的是对象」这件事从字面量里区分出来。若输出仍是 120，说明赋值没有通过引用写进去，或者你打印的是另一个变量。

```cpp run expect="90" title="改标签就是改北畦"
#include <iostream>
int main() {
  int north = 120;
  int &edge = north;
  edge = 90;
  std::cout << north << "\n";
  return 0;
}
```

第三份程序演示那个容易看反的赋值。南畦是 150，北畦起初是 120，`edge` 绑在北畦上。`edge = south` 之后，两个变量都是 150。期望子串用 `150 150`，避免单独的 `150` 把「只改了一边」也放过去。南畦的变量没有被绑成引用，它仍是自己的对象；北畦的对象被写了。标签没有搬家。

```cpp run expect="150 150" title="赋值不会改挂靠"
#include <iostream>
int main() {
  int north = 120;
  int south = 150;
  int &edge = north;
  edge = south;
  std::cout << north << " " << south << "\n";
  return 0;
}
```

```cpp norun title="没有对象的引用"
#include <iostream>
int main() {
  int &edge;
  std::cout << edge << "\n";
  return 0;
}
```

只读块里的 `int &edge;` 没有初始化。这在编译期就会停，所以不能放进可运行示例。旁边若再写一行 `int &ghost = 120;`，同样会停：字面量不是可以修改的对象。两种失败都发生在绑定的那一刻，而不是发生在打印的那一刻。可运行的三份程序都在声明的同一行完成绑定，并且绑定的是有名字、活在 `main` 里的 `int`。

再把「别名」说得操作一点。读取 `edge` 就是读取 `north`，取 `edge` 的地址会得到 `north` 的地址。语言没有给你一个「引用本身的存储」让你重新赋值成另一个地址。有的实现会用指针来实现引用，那是实现的事，不是你可以依赖的对象模型。你在源码里写不出「引用的引用再改一改」这种第二层标签。需要一层可改的地址时，回到指针，并接受空指针和未初始化指针这两类 C 里已经熟悉的风险。

零还没有进入这一章的条件。北畦被改成 90，90 不是 0。若把长度改成 0，引用仍然绑着那块 `int`，0 是一个真实的存储值。它和「引用不存在」不是一回事。下一章会把 0 放进 `if`，在那里 0 为假，非零为真。那是条件的规则，不是引用突然松开了。一块被量成 0 厘米的畦仍然有标签，只是它在分支里走失败的那一支。把这两件事叠在同一次修改里，很容易以为「赋 0」等于「解除引用」。并不是。

和拷贝相比，引用省下一次厘米数的复制。三条边都是 `int`，复制便宜，省下的那一点几乎测不出来。引用的价值不在速度，而在「两个名字是否故意共用一块存储」。函数参数若按值传递，函数里改的是副本，调用方的北畦不动；按引用传递，函数改的就是调用方那一块。失败那一章需要把结果写回调用方时，会用这种参数。这一章先在 `main` 里把共用写对，免得参数列表同时带来新的语法。

绑定发生在初始化，这句话还可以从参数列表再看一遍。函数参数里的引用，在调用发生的那一刻绑定到实参上，而不是在函数体的第一行。所以你写不出「参数先是空的，函数里再决定绑谁」。调用方必须已经有一个对象。这就是后面 `keep` 要求调用方先准备 `out` 的原因：输出参数的引用要有地方可绑。若调用方只想表达「我还没有准备好接收」，引用帮不上忙，需要另一个通道，例如返回状态、让输出参数保持原样。

const 引用多一个能力：它可以绑到临时量上，临时量的寿命被拉到引用结束。非 const 引用故意没有这个能力，否则你可以通过别名修改一个马上要销毁的值，修改无处可去。菜地的长度需要写回木桩，所以用非 const，并且木桩是有名字的局部变量。只读地看一条边时，const 引用足够，而且能接受一个当场算出来的和。这一章的三份程序都要写，因此都没用 const。练习里的加 5 也是写。若你以后只打印、不修改，把 `&` 左边加上 const，可以防止函数体里的手滑赋值。

别名还有一个和调试有关的面。打印 `north` 和打印 `edge` 在生成的代码里常常是同一次读取，优化器知道它们是一块存储。你在中间插入的日志若只印一个名字，不要以为另一个名字还留着旧值。第二份程序把北畦改成 90 之后，不存在「标签是 90、木桩仍是 120」这种分裂。分裂只存在于按值拷贝里。拷贝的代价是两个数以后各改各的，你必须记得哪一个才是工单上的那条边。引用的代价是你必须记得赋值会打到原对象。两种代价都真实，选哪一种取决于你是想要独立的草稿，还是想要改到原件。

指针能重绑，所以它适合「这张纸标签今天下午改贴到南畦」。引用适合「标签钉死了，人只改读数」。把指针的习惯带进引用，最常见的动作就是写出 `edge = south` 还以为标签搬家。第三份程序的 `150 150` 就是这个动作的证据。若业务真的要搬家，应改用指针，并处理空指针：还没贴上的标签不能解引用。引用把这段处理从类型里删掉了，换来的是声明行必须完整。删掉的处理不会在运行时回来提醒你，它只在你试图写一个没有初始化的引用时，于编译期出现。

最后谈寿命和循环。循环的每一圈若想用引用指向当前元素，引用可以绑到 `beds[i]`，但这个引用不能留到向量增长之后，也不能留到 `beds` 这个数组本身销毁之后。这一章的数组是 `main` 里的局部对象，程序结束前都活着，所以还碰不到悬空。等向量那一章开始 `push_back`，搬家会让旧地址失效，引用仍天真地绑在旧地址上。引用不会因为目标被收走就自动变成空。它没有空这一档。所以「先绑上」和「目标一直活着」是两句，缺一句都会错，只是错的时刻不同：前一句错在编译，后一句错在运行。

## 小结

引用在声明的那一行就绑到一个已经存在的对象，之后没有空值，也不能改挂到另一块对象上。`edge = south` 把南畦的 150 抄进北畦，两个名字都变成 150，标签仍系在原来的木桩上。没有初始化的引用、以及绑到字面量上的非 const 引用，都留在不能运行的形状里。

下一章用同一块菜地写分支和循环。0 在条件里为假，80 为真。引用继续表示「这个名字就是那一条边」，条件则决定这条边算不算进周长。不要用给引用赋 0 来假装标签被拆掉了。

## 练习

把引用绑到中畦的 80 上，然后通过引用加上 5，打印结果。应当看到 85。85 是修正后的中畦，用来证明加法通过别名写进了原来的对象。不要再声明一条未使用的北畦。

::: answer 参考答案：中畦加五
```cpp run expect="85" title="参考答案"
#include <iostream>
int main() {
  int mid = 80;
  int &edge = mid;
  edge = edge + 5;
  std::cout << mid << "\n";
  return 0;
}
```
:::

声明北畦 120 和它的引用，两边都打印，中间用一个加号连接，得到 `120+120`。加号是你插入的字符，用来强调两个名字读的是同一块存储，而不是两次独立的测量。

::: answer 参考答案：同一个读数
```cpp run expect="120+120" title="参考答案"
#include <iostream>
int main() {
  int north = 120;
  int &edge = north;
  std::cout << north << "+" << edge << "\n";
  return 0;
}
```
:::
