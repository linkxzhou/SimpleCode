纸标签已经能系在某一畦上。下一步是决定这条边要不要记进当天的工单。中畦只有 80 厘米，不到一米。若工单只收录「至少一米」的边，中畦就该被点名成短的。北畦 120 和南畦 150 过线。门槛用 100，是因为这组数里只有 80 落在下面，判断的结果不会含糊。

`if` 看的是条件的值。比较式 `mid < 100` 得到布尔结果，真就走第一支，假就走 `else`。整数也可以直接放进条件：0 为假，任何非零为真。80 为真，120 为真，150 为真。这和某些语言把 0 也当成真值的习惯相反，和 C 一致。你从 C 走来，这条规则不算新，但在 C++ 里它仍然咬人，因为一个长度变量既是厘米数，又可能被你顺手当成「有没有量过」。0 厘米是一个合法的存储值，它在算术里加上去不改变和，在 `if (length)` 里却会走进失败的一支。两条规则同时为真，混在一次判断里就会把「没量」和「量出来是零」写成同一种样子。

这一章选择把它们拆开演示。第一份程序只用比较，不用整数的真假。中畦 80 小于 100，打印 `短`。打印一个汉字而不是打印 80，是为了让期望子串表达「分支走了哪边」，而不是表达「数还在」。若比较写反，终端里会是 `长`，和期望对不上。

```cpp run expect="短" title="不到一米"
#include <iostream>
int main() {
  int mid = 80;
  if (mid < 100) {
    std::cout << "短\n";
  } else {
    std::cout << "长\n";
  }
  return 0;
}
```

第二份程序把 0 放进条件，不写比较运算符。缺失的读数用 0 存着。`if (missing)` 为假，走 `else`，打印 `无`。这里的 0 不是「引用松开了」，引用那一章已经把这件事分开。这里的 0 是条件转换：整数到布尔，零变成假。非零会打印 `有`。我们不在这份程序里放一个非零数，免得两支输出叠在一起，子串无法分辨你走了哪边。

```cpp run expect="无" title="零走假的那一支"
#include <iostream>
int main() {
  int missing = 0;
  if (missing) {
    std::cout << "有\n";
  } else {
    std::cout << "无\n";
  }
  return 0;
}
```

循环把三格都看一遍，其中一格故意是 0，用来把「看过」和「加进和里」拆成两个数。数组的三格是 120、0、150。`seen` 每转一圈加一，不管格子里是不是 0。`sum` 只在 `if (beds[i])` 为真时才把格子加进去。0 为假，所以和不包含那一格。看过的次数是 3，和是 270。期望写成 `3 270`。若你把 `seen` 也放进那个 `if`，次数会变成 2，空读数就从记录里消失了，好像下午只量了两次。次数消失是工单的错误，不是循环没转。

```cpp run expect="3 270" title="看过三格加进两格"
#include <iostream>
int main() {
  int beds[3];
  beds[0] = 120;
  beds[1] = 0;
  beds[2] = 150;
  int sum = 0;
  int seen = 0;
  int i = 0;
  while (i < 3) {
    seen = seen + 1;
    if (beds[i]) {
      sum = sum + beds[i];
    }
    i = i + 1;
  }
  std::cout << seen << " " << sum << "\n";
  return 0;
}
```

`while` 的条件是 `i < 3`。`i` 从 0 走到 2，三次都进循环体，然后 `i` 变成 3，条件为假，循环结束。下标 0 在数组里是第一格，在条件里却是假。这一个 0 身兼两职，正是这一章要你分开记的原因：作为下标，0 是北畦的位置；作为长度，0 是「不要加进和里」的信号。位置上的 0 不能用 `if (i)` 去跳过，否则北畦的 120 会因为自己住在下标 0 而被丢掉。长度上的 0 才用 `if (beds[i])` 过滤。两个 0 写在同一种整数类型里，过滤哪一个必须看名字，不能看类型。

`for` 能把初值、条件和步进写在一行里，这一份程序用 `while` 是为了把步进留在循环体底部，让你看见 `seen` 的增加和 `i` 的增加是两句。步进若写成 `i = i + 1`，和 `++i` 在这里等价，因为没有别的表达式同时读 `i`。不要把 `++i` 塞进 `beds[i]` 的同一个表达式里再交给 `<<`。上一章说过，C++14 不保证那种副作用的次序。循环体里一句做一件事，次序由语句的先后决定，这是有保证的。

取舍在于用 0 当「跳过」的信号是否诚实。若某条边真的可能是 0 厘米——比如畦还没翻，长度就该记 0——那它既是测量结果，又会被 `if (beds[i])` 当成缺失。和会少掉一个合法的 0，次数若只在真分支里增加，也会少一次。这种编码在三格演示里很省事，上了真实工单就会撒谎。后面用返回值表示失败时，长度和状态会分成两个通道：状态用 0 和 1，长度只在状态为成功时才可读。这一章先让你看见混用的后果，`3 270` 就是那个后果的正脸：看过三格，加进的只有 270，中畦被 0 替换之后从和里消失了。

花括号在这份方言里不是可选的装饰。只有一条语句时，语法允许省略，但省略之后再插一行调试输出，那一行会落在分支外面，看起来像两条路径都会打印。我们每次都写花括号，让路径的边界出现在源码里。缩进不会被编译器读取，和 Python 不同；花括号才会。`-Werror` 不会因为你缩进错了就失败，所以不要靠缩进表达「这行属于 `if`」。

三条原始边 120、80、150 里并没有 0。第二、第三份程序为了让假值出现，把中畦换成 0，这是实验，不是改了菜地的地契。练习和后文若没有声明，仍用原来的三条。控制流没有改变它们的存储，只决定哪些参与打印、哪些参与求和。

条件表达式的值要先转换成 `bool`。比较运算直接得到 `bool`。整数会按零与非零转换。指针会按空与非空转换，这一章没有用指针。流对象以后也会在条件里变成「上次操作是否成功」，那是它自己定义的转换，不是整数规则的推广。三种来源都写在 `if` 后面时，阅读的人要先问：这里的假是零、是空指针，还是流失败？名字应当告诉你。`missing` 表示没有读数，`mid` 表示厘米，以后的 `getline` 的返回值表示读取是否完成。不要用同一个 `n` 既当长度又当状态。

`else` 挂靠的是最近的、还没有 `else` 的 `if`。花括号把这件事变明显。若省略花括号，再嵌一个 `if`，后面的 `else` 会挂到内层，外层的失败路径就丢了。三格循环里如果写成「小于 100 就再判断是否大于 0，否则计入长边」，省略花括号会把「长边」配错对象。我们每次写上花括号，让挂靠出现在源码的形状里，而不是出现在你对优先级的记忆里。缩进只服务眼睛。编译器不读缩进。

循环还有一条和 0 相邻的边界：`i < 3` 在 `i` 等于 3 时停止，循环体看不到下标 3。下标 3 本来就越界。条件用小于而不是小于等于，是为了让最后一格的下标是 2。若你写成 `i <= 3`，最后一圈会读到数组外面，那不是「多看了一格空读数」，是未定义行为，打印出来的可能是任何残值，甚至根本不打印。`-Werror` 不一定能指出这个下标。边界要靠你把「元素个数」和「最后一个合法下标」分成两个数：个数是 3，最后下标是 2。

`break` 和 `continue` 能改变圈的走向。这一章的循环不需要它们，三格都要看完，`seen` 才能是 3。若在读到 0 时 `break`，南畦的 150 不会进入和，`seen` 也会停在 2 或更小，看你把递增写在 `break` 之前还是之后。提前结束适合「已经找到一条就停」的搜索，不适合「下午的记录要数完」的统计。搜索留到算法那一章用 `min_element` 表达，它会看完整个范围并返回最小元素的位置，你自己的循环就不用半路 `break`。看完和提前停是两种工单，不要用同一个循环骨架硬塞。

开关语句这一章也不用。三条边不是一组稀疏的枚举码，用 `switch` 去匹配 120、80、150 会把测量值当成分支标签，以后长度改成 121 就掉进 `default`。比较式 `>= 100` 对一整段范围都有效，比枚举三个字面量更接近「不到一米」这句话。`switch` 适合离散的、你列得完的状态，例如成功与失败的代码若已经收成枚举。现在状态还是裸的 0 和 1，用 `if` 更直接。

整数的真假还有一个符号问题。-5 非零，放进 `if` 会走真的一支。若缺失的读数有时被写成 -1 而不是 0，`if (beds[i])` 会把缺失当成一条真实的边加进和里，和会被拉低，次数却以为自己很完整。所以真值转换只在你确信「非法值只有 0」时才诚实。上一组演示把中畦换成 0，是因为我们约定这一次的空读数就是 0。一旦约定放宽到负数，条件必须写成比较，例如 `beds[i] > 0`。比较把符号说出来了，真值转换没有。

再把「看过」和「加进」放回没有零的那组原始边上看一遍。120、80、150 三格都非零，`if (beds[i])` 不会丢掉任何一条，和是 350，次数也是 3。这时真值转换看起来无害，因为数据里恰好没有零。无害来自数据，不来自规则。规则仍是零为假。换一天中畦没量成，有人顺手写上 0，同一份循环会突然少掉 80，而源码一行没改。所以阅读循环时要问：作者是故意用真假过滤缺失，还是以为自己只是在做加法？第三份程序把 0 写进中畦，就是为了让这个问题有一个看得见的答案：次数 3，和 270。没有这个对照，350 会让人以为过滤不存在。

循环变量 `i` 的生命停在循环结束之后仍然还在，因为它声明在循环外面。结束时它等于 3。若你在循环后打印 `i`，看到的是个数而不是最后一条边的下标。这个 3 不是南畦。不要把循环后的 `i` 拿去当 `beds[i]` 的下标。示例不打印它，是为了不给这种误用提供一个看起来合法的输出。需要个数时用一个专门的 `seen`，或者在向量那一章改问 `size()`。数组没有 `size()` 成员，个数要你自己用常量 3 守住，常量写错时循环会越界，编译器仍可能沉默。

## 小结

比较式适合表达「不到一米」。整数直接放进 `if` 时，0 为假，非零为真，80 会走进成功的一支。循环里把「看过的格数」和「加进去的厘米」分成两个变量，0 厘米可以占着一格却不进入和。下标 0 是位置，不是缺失；不要用 `if (i)` 跳过北畦。

下一章把「两条边里谁更长」和「一条边自己的长度」收成函数。同一个名字可以有两份参数列表，这是重载。分支仍写在函数体内，0 仍然为假，只是调用方终于不用把比较式复制三遍。

## 练习

数一数 120、80、150 里有几条不小于 100。应当打印 2。用循环或三次比较都可以，但计数变量必须被打印。不要把 0 塞进这组数，这道题要的是门槛，不是真值转换。

::: answer 参考答案：过线的两条
```cpp run expect="2" title="参考答案"
#include <iostream>
int main() {
  int beds[3];
  beds[0] = 120;
  beds[1] = 80;
  beds[2] = 150;
  int wide = 0;
  int i = 0;
  while (i < 3) {
    if (beds[i] >= 100) {
      wide = wide + 1;
    }
    i = i + 1;
  }
  std::cout << wide << "\n";
  return 0;
}
```
:::

只在南畦不小于北畦时打印 `南`。150 不小于 120，所以应当看到这个字。比较的两边都用变量，避免把字面量直接写进 `cout` 而让分支变成摆设。

::: answer 参考答案：南畦更长
```cpp run expect="南" title="参考答案"
#include <iostream>
int main() {
  int north = 120;
  int south = 150;
  if (south >= north) {
    std::cout << "南\n";
  } else {
    std::cout << "北\n";
  }
  return 0;
}
```
:::
