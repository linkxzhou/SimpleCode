字条 `buy pen` 在向量那一章写在源码里，下标可以心算。真正的木牌是别人刻的，文字从标准输入进来。这一章只用 `std::getline` 读一行。围栏上的 `stdin` 就是那块木牌：进程启动时，这些字节已经排在输入里，读完后默认还会遇到结束。你不用在终端里再手打一遍，除非你把示例改成自己的草稿再点工具栏上的运行。

`getline` 把一行放进 `std::string`，并且不把末尾的换行留在字符串里。换行只是记录的分隔，不是字条的内容。所以木牌上写着 `buy pen` 再加一个换行时，字符串里是七个字节的 `buy pen`，没有第八个换行字节。这和 C 的 `fgets` 不同，`fgets` 往往把换行留在缓冲里，你要自己削掉。少一次削，也少一次「削错长度」的机会。代价是你失去了「缓冲里还能看到分隔符」的痕迹：空行和「什么都没读到」必须靠别的办法分辨，不能靠最后一个字节是不是换行。

第一份程序就是这次读入的全部契约。它不检查流的状态，因为围栏保证有一行 `buy pen`。读到的内容原样插入，期望子串就是 `buy pen`。函数末尾没有写 `return`，从 `main` 掉出去在 C++ 里等同于返回 0。别的函数没有这个特权。这里只为了让这一份和木牌的最小形状一致，后面的程序仍写上 `return`，免得你把特权用到普通函数上。

```cpp run stdin="buy pen\n" expect="buy pen" title="木牌上的原文"
#include <iostream>
#include <string>
int main() {
  std::string line;
  std::getline(std::cin, line);
  std::cout << line << "\n";
}
```

第二份程序面对一块空白木牌：输入是一个换行，没有别的字符。`getline` 成功，字符串为空。成功和「有字」不是一回事。我们把空字符串印成 `空`，而不是把它当成失败，也不是再插入一个空行让终端看起来什么都没有。什么都没有的终端无法和「你忘了插入」区分。`空` 这个字是程序的判断，不是输入的回声。

```cpp run stdin="\n" expect="空" title="只有换行"
#include <iostream>
#include <string>
int main() {
  std::string line;
  if (!std::getline(std::cin, line)) {
    std::cout << "失败\n";
    return 0;
  }
  if (line.empty()) {
    std::cout << "空\n";
    return 0;
  }
  std::cout << line << "\n";
  return 0;
}
```

`line.empty()` 为真当且仅当长度为 0。0 在这里是字节数。条件里我们调用了 `empty()`，没有写 `if (!line.size())`。两种写法对空串都成立，因为长度为 0 时 `size()` 为假。`empty()` 把意图写成单词，避免再把「字节数为零」和「状态失败」看成同一个 0。流失败是第三种情况，走上面的 `if (!std::getline(...))`。

第三份程序不提供任何字节，输入直接结束。`getline` 失败，流变成假，我们打印 `失败`，并且不把空字符串当成木牌上的字。失败时 `line` 可能是空的，看起来和空白木牌一样。若不检查流，两种情况都会插入一个空行，工单会把「没有木牌」记成「木牌是空的」。返回值通道仍是这一章的做法：流对象在条件里为假就表示这次读取没有完成。我们不 `throw`，也不调用会抛异常的转换去解析这一行。

```cpp run stdin="" expect="失败" title="没有字节"
#include <iostream>
#include <string>
int main() {
  std::string line;
  if (!std::getline(std::cin, line)) {
    std::cout << "失败\n";
    return 0;
  }
  std::cout << line << "\n";
  return 0;
}
```

第四份程序回到有字的木牌，并沿用 `substr` 的契约。起点 4，长度 3，从 `buy pen` 取出 `pen`。先确认读取成功，再切。起点是字节下标，不是「第几个单词」。空格占一个字节，所以 `p` 在下标 4，而不是下标 3。若输入换成中文，下标仍按字节走，一个汉字通常占三个字节，切错一个就会切断编码。这行英文每个可见字符恰好一个字节，心算才和眼睛一致。

```cpp run stdin="buy pen\n" expect="pen" title="从读到的行里切"
#include <iostream>
#include <string>
int main() {
  std::string line;
  if (!std::getline(std::cin, line)) {
    std::cout << "失败\n";
    return 0;
  }
  std::cout << line.substr(4, 3) << "\n";
  return 0;
}
```

一次 `getline` 只消费一行。若围栏里还有第二行，它留在输入里，这份程序看不到。循环可以把行全部读完，直到流失败。待办那一章不靠循环读很多行，它把读到的第一行放进向量，再放上源码里的另外两条，用来保持次序。这里先把「一行」的边界看清：分隔符是换行，字符串里不保留它，失败和空行分开打印。

取舍对着 `operator>>` 来说。`std::cin >> line` 会按空白切开，`buy` 和 `pen` 会变成两次提取，空格本身被丢掉。木牌上的空格是字条的一部分，丢掉之后就不再是原来的七个字节。`getline` 只把换行当分隔，空格留在结果里。代价是你要自己处理一行里的内部结构：要单词时再切，要整数时再解析。解析整数若用 `std::stoi`，非法输入会抛异常。这一章不解析整数，失败只来自流本身。厘米仍然写在源码里，不从这行字条里挖。

还有一层和缓冲有关。`getline` 会阻塞到看见换行或结束。围栏把输入一次送完并送出结束，所以教学程序能够返回。若结束信号不来，读取会停在下一次等待，抽屉里表现为超时，超时不是字条内容。写交互程序时要知道：你看到的「一行」取决于对方是否写下了换行。只有 `buy pen` 七个字节、没有换行、也没有结束时，`getline` 仍在等。我们的围栏两种收尾都给了，示例才走得完。

`string` 会按需要变长，木牌这一行很短，不需要你事先声明一个 64 字节的数组。变长的代价仍是可能搬家，但 `getline` 写完之后我们不再持有指向内部缓冲的指针，只使用 `string` 自己的接口。不要在读入之后取 `line[0]` 的地址存进一个引用，再对 `line` 做会重新分配的操作。这一章的 `substr` 在读取完成之后立刻进行，中间没有第二次增长。

`getline` 还有一个容易忽略的返回：它返回的是流本身的引用，所以才能放进 `if`。流在失败时转换为假，成功时转换为真。真并不表示字符串非空。空白木牌那一份已经把这两层拆开。若你写成 `while (std::getline(std::cin, line))`，循环在失败时停止，空行却会进循环体，因为空行是成功。循环体里要再判断 `empty()`，决定空行是跳过还是记成一件空白的活。这一章没有写这个循环，待办只需要第一行。循环的形状先记在这里，免得你把 `while (getline)` 理解成「跳过空行」。它不跳过。

结束和换行的组合有四种值得在脑子里过一遍。有字有换行：成功，字符串是那些字。只有换行：成功，字符串为空。有字但在结束前没有换行：通常仍然成功，字符串里是那些字，因为结束也可以终止一行。一个字节都没有就结束：失败。围栏的第一份和第四份属于第一种。第二份属于第二种。第三份属于第四种。第三种在「对方忘了换行但送出了结束」时出现，抽屉的输入若只有 `buy pen` 七个字节再加结束、没有换行，`getline` 仍能交出这七个字节。我们的围栏写了 `\n`，是为了让木牌的形状和人敲回车一致。不要依赖「没有换行也能读到」当作格式的一部分，那是结束信号捎带的行为，交互输入里结束往往要人再按一次文件结束，时机不稳定。

读取失败之后，流处于失败状态。若你不清除状态，同一次进程里再读也会立即失败。示例在失败时直接返回，没有第二次读取，所以不用清除。需要清除时会用到流的状态位操作，那是另一层接口，这一章不展开。返回之后进程结束，状态自然消失。下一次点击是新进程，流是新的。你不用在程序末尾「复位」，也做不到把复位保留给下一次点击。

`substr` 放在成功分支里，是因为失败时字符串可能为空，起点 4 已经越界。越界会走向异常，而异常不能当这条路径的失败通道。先看流，再看 `size()` 是否至少为 7，然后再切，才把所有失败留在返回值上。第四份程序的围栏保证了内容，仍先检查了流。它没有再检查长度。若有人把输入改成 `hi`，`substr(4, 3)` 就会碰到越界。健壮的切法是：长度不够就打印 `失败` 并返回 0，不去调用 `substr`。练习里的前三个字节对 `buy pen` 是安全的，对一个更短的行则需要这道检查。检查用比较，不用异常。

字节数 7 包括空格。空格是字条的一部分，不是 `getline` 的分隔符。若用提取运算符，空格会把字条切成 `buy` 和 `pen` 两次读取，你得自己再拼回去，拼的时候还要决定中间是一个空格还是多个。`getline` 把这个决定留给木牌的原文。原文里有几个空格，字符串里就有几个。这是它适合当待办第一格的原因：第一格要原样，不要被空白规则改写。原样的代价是你不能假设没有前导空格。前导空格会让 `substr(0, 3)` 切到空格而不是 `buy`。围栏的输入没有前导空格，切出来才是三个字母。

读入的字符串和源码里的字面量 `buy pen` 在成功时字节级相同，这是围栏和程序之间的约定，不是 `getline` 会自动去掉首尾空格。它只去掉它当作分隔符吃掉的那个换行。行中间的空格、行首的空格都会留下。测试期望用 `buy pen` 这个子串，行首若多一个空格，子串仍可能匹配，因为这六个字母加一个空格还在更长的字符串里。要抓行首空格，期望就不够，得看 `size()` 是否仍是 7。练习里打印 7，就是用长度把「多一个空格」挡在外面：多一个空格会变成 8。长度是比子串更严的检查，子串是比长度更直观的检查。两份程序各用一种，合在一起才是这行字条的完整形状。

流的假值来自失败位，不是来自字符串里存着 0。不要用 `if (line)` 这种写法，`string` 没有「作为条件时看自己是否为空」的转换。空不空问 `empty()` 或 `size()`。失败不失败问 `getline` 的返回流。两个问题两个表达式，避免再造一个什么都表示的 0。

## 小结

`getline` 把 `buy pen` 读进字符串并丢掉换行，输出仍是这七个字节。只有换行时读取成功但字符串为空，程序打印 `空`。一个字节都没有时流为假，程序打印 `失败`，不去把空字符串当成木牌。`substr(4, 3)` 从读到的行里取出 `pen`，第二个参数仍是长度。

下一章把这一行放进待办向量的第一格，后面再跟上另外两条，次序保持写入的次序。不排序。最短、次数那些问题若还要问，继续用上一章的算法，而不是把待办按字母重排。

## 练习

读入 `buy pen` 之后只打印它的字节数。应当看到 7。不要把换行算进去，`getline` 已经把换行留在输入的外面。

::: answer 参考答案：七个字节
```cpp run stdin="buy pen\n" expect="7" title="参考答案"
#include <iostream>
#include <string>
int main() {
  std::string line;
  if (!std::getline(std::cin, line)) {
    std::cout << "失败\n";
    return 0;
  }
  std::cout << line.size() << "\n";
  return 0;
}
```
:::

从同一行的起点取 3 个字节，应当打印 `buy`。这道题确认起点可以是 0，长度仍是第二个参数，而不是终点下标。

::: answer 参考答案：前三个字节
```cpp run stdin="buy pen\n" expect="buy" title="参考答案"
#include <iostream>
#include <string>
int main() {
  std::string line;
  if (!std::getline(std::cin, line)) {
    std::cout << "失败\n";
    return 0;
  }
  std::cout << line.substr(0, 3) << "\n";
```
