向量里的 120 和字符串里的 `north` 仍然是两份记录。工单若问「北畦有多长」，你得自己记得这两个数是一对。类把一对收成一个对象。这一章用 `struct`，成员默认公开，教学代码可以直接读 `length`。真要守住「长度必须为正」这种不变量，成员会改成私有，修改只走函数，那是下一章状态码要接上的地方。现在先让卡片上的字和数能被打印。

第一份程序只有北畦。对象先默认构造，再给成员赋值。`name` 是 `std::string`，默认构造出来是空串，然后被赋成 `north`。`length` 是 `int`，默认没有一条对你有意义的厘米数，必须在打印前写上 120。输出 `north 120`。两个成员都出现，避免只打印数字时看不出卡片是否带上了名字。

```cpp run expect="north 120" title="北畦的卡片"
#include <iostream>
#include <string>
struct Bed {
  std::string name;
  int length;
};
int main() {
  Bed north;
  north.name = "north";
  north.length = 120;
  std::cout << north.name << " " << north.length << "\n";
  return 0;
}
```

默认构造再赋值，中间有一小段时间卡片上的长度是未指定的。若有人在赋值前打印，读到的不是 120。把设值收进构造函数，对象一诞生就同时拥有名字和厘米，那段空窗就没有了。构造函数的初始化列表比在函数体里赋值更合适：列表直接用给定的值构造成员，函数体里的赋值是先默认构造再改。对 `int` 和 `string` 来说，两种写法都能得到正确结果；对引用成员来说，只有列表这一条路，因为引用不能先默认构造再绑。第三份程序走那条路。第二份程序先用普通成员加一个函数，让「问长度」变成卡片自己的动作。

`centimeters` 写成 const 成员函数。它只读 `length`，不修改卡片。const 在这里是给调用方的承诺，也是给以后的 const 对象留的门。函数返回 120。名字仍然打印出来，证明这张卡片不是一个只含整数的伪装。

```cpp run expect="north 120" title="卡片自己回答长度"
#include <iostream>
#include <string>
struct Bed {
  std::string name;
  int length;
  int centimeters() const {
    return length;
  }
};
int main() {
  Bed north;
  north.name = "north";
  north.length = 120;
  std::cout << north.name << " " << north.centimeters() << "\n";
  return 0;
}
```

成员函数和外面的 `longer` 不一样。它隐式收到这张卡片，名字叫 `this`，这一份函数体没有写 `this->`，因为 `length` 已经在类的作用域里。若参数也叫 `length`，成员会被挡住，必须写成 `this->length`。我们不制造这种遮挡。函数放在类体内，单文件不用另写类外定义。类一变大，把函数体挪出类会让卡片的轮廓更好读，那是文件变长之后的取舍，三行数据还没到那个地步。

第三份程序让卡片不保存厘米的副本，而保存对一块 `int` 的引用。测量值仍住在 `main` 的 `north` 里，卡片只是系在上面的标签。引用成员不能在构造函数体里才绑定，声明它的类必须在初始化列表里完成绑定：`: length(n)`。参数 `n` 自己也是引用，这样绑上去的是调用方那块 `int`，不是构造函数参数的副本。若参数按值传递，列表会绑到那份即将销毁的副本上，卡片活下来之后引用已经悬空。这是引用那一章的寿命规则在构造函数里的形态。

通过卡片把长度改成 90，再打印原来的 `north`。应当看到 90。卡片和变量共用一块存储，赋值不会把引用改挂到别的畦上。

```cpp run expect="90" title="卡片系在原来的变量上"
#include <iostream>
struct Bed {
  int &length;
  Bed(int &n) : length(n) {}
  int centimeters() const {
    return length;
  }
};
int main() {
  int north = 120;
  Bed card(north);
  card.length = 90;
  std::cout << north << "\n";
  return 0;
}
```

带引用成员的类，复制赋值会被删除：赋值需要把右边的引用重绑到左边，而引用不能重绑。复制构造仍然可以写成「新卡片也绑到同一块 `int`」。这一份程序两种拷贝都没有做。若你以后把这种卡片放进 `vector`，向量增长时要拷贝或移动元素，引用成员会让这件事变得难写，也容易悬空。所以前两份程序用值成员装厘米，向量装它们才自然。引用成员用来表达「卡片并不拥有测量值」，它的代价是卡片的寿命不能超过那块 `int`，而且容器不再是默认就好用的家。

公开数据成员的取舍也记一笔。公开让示例短，调用方可以写 `north.length = 0`，卡片不会抗议。0 又是那个两面的数：作为长度它可以进向量，作为条件它为假。类若要守住「打印之前长度必须为正」，就得把成员藏起来，用返回状态的函数修改。下一章做这件事，仍不用异常。构造函数若 `throw`，对象是否诞生、成员是否已析构，在这份 wasm 上不可靠，所以不变量不用抛异常来守。

三张值卡片可以放进向量，次序仍是 push 的次序。这一章的可运行例子各放一张，是为了把成员、成员函数、引用绑定分成三次修改。练习里会放两张。不要给类再添一个从未被调用的方法，未使用的私有函数有时能通过编译，未使用的局部变量不行；无论哪一种，这一章都不留摆设。

构造的顺序由成员在类里的声明顺序决定，不由初始化列表里书写的顺序决定。若 `name` 写在 `length` 前面，就先构造 `name`，即使列表里先写了 `length`。两者互不依赖时，次序看不出来。一旦某个成员的初值要用到另一个成员，声明顺序就变成语义。引用成员尤其如此：它没有「先默认再赋值」的阶段，列表里必须出现它，而且它绑上的对象不能是尚未构造完的、寿命更短的兄弟成员的临时副本。把引用绑到同一个对象里的另一个成员上可以做，但要非常清楚两者的声明顺序和对象的整体寿命。菜地的卡片把引用绑到 `main` 里的 `int` 上，避开了「成员互相绑」这种更陡的形状。

默认构造之后再赋值，对 `string` 意味着先做出空串，再把字符拷进去。初始化列表则直接用给定的字符构造。结果相同，中间状态不同。若构造函数体里调用了别的函数，而那个函数又回头看这张卡片，赋值式的写法会让对方看见空名字。列表式的写法在函数体开始前就完成了成员，函数体里看见的是完整卡片。我们的示例没有这种回调，仍推荐列表，是为了和引用成员的唯一合法写法保持一致。一种构造习惯，少记一种例外。

成员函数的 const 是承诺的一部分。const 对象只能调用 const 成员函数。若 `centimeters` 忘了写 const，一份只读的卡片就无法回答自己的长度，你只好把卡片改成非 const，只为了问一个问题。问问题不该要求写权限。写权限留在真正修改长度的函数上。修改函数这一章没有写，因为修改的合法性要等失败那一章的状态码。现在的赋值发生在类的外面，类还没有机会拒绝 0。这是公开成员的直接后果：规则写在调用方的自觉里，不写在类型里。

复制一张值卡片会得到另一份名字和另一份厘米。之后改其中一张，另一张不动。这和引用成员相反。值语义适合「每张工单自己留一份底」，引用语义适合「所有卡片看同一块木桩」。向量默认按值语义存放元素，所以值卡片放进去之后，向量拥有自己的副本，原来的局部变量可以先销毁。引用卡片放进向量之前，你必须保证那块 `int` 比向量更长寿，而且向量的重新分配会复制卡片、让新卡片也绑到同一块 `int`。能做，但很容易在函数返回时把向量带出 `int` 的寿命。教学代码把引用卡片留在 `main` 的栈上，旁边就是那块 `int`，两者一起结束。

继承这一章不引入。南畦不是北畦的一种特殊类型，它们是同一类卡片的两个值。用派生类去区分南北，会把数据做成类型，每加一条边就多一个类。数据用值表示，类型保持一个 `Bed`，新的边只是新的对象。这和「重载不该为了第四条边再加一份函数」是同一类判断：变化的是数量和数值时，用对象和容器；变化的是行为的种类时，才考虑新的类型或新的函数。量长度这个行为对三条边是一样的。

成员的默认公开来自 `struct` 这个关键字。若写成 `class`，成员默认私有，示例里的 `north.length = 120` 就会在编译期停住，除非你写上 `public`。两种关键字在其余规则上几乎相同，差别主要是这个默认。选择 `struct` 是为了让第一份程序把数据摊开，读者先看见名字和厘米是一对，再看见函数。选择 `class` 并立刻私有化，会把「如何拒绝 0」提前变成必须回答的问题。那个问题属于返回状态的一章。关键字因此按章节的需要选，而不是按哪一个听起来更高级。

对象的赋值是按成员抄写。`Bed a = b;` 在值成员的情况下得到两份独立数据。之后 `a.length = 90` 不会让 `b.length` 变成 90。这和引用成员相反，也和「两个名字是同一块 `int`」相反。卡片是值的时候，赋值是复印；名字是引用的时候，赋值是写原件。看赋值符之前先看左边那个名字的类型。类型决定这一笔写到哪里。

## 小结

`Bed` 把名字和厘米放在一起，`centimeters` 只读地返回长度，北畦打印出来是 `north 120`。引用成员必须在初始化列表里绑到一块活得更久的 `int` 上，通过卡片赋 90 会改到原来的变量。引用成员不适合再装进会搬家的向量。

值成员的卡片仍允许调用方把长度写成 0 或负数。下一章用一个返回状态的函数拦住这种写入：成功才把数写进输出参数，失败时调用方不去读那个参数。异常继续留在不能运行的块里。

## 练习

做一张南畦的值卡片，名字 `south`，长度 150，用 `centimeters` 打印长度。应当只看到 150。名字要赋上，即使这道题的期望不检查它，未赋值的字符串不是这张卡片的一部分；既然赋了，就在同一行把名字也打印出来，期望改看 `south 150`。

```cpp run expect="south 150" title="参考答案"
#include <iostream>
#include <string>
struct Bed {
  std::string name;
  int length;
  int centimeters() const {
    return length;
  }

int main() {
  Bed south;
  south.name = "south";
  south.length = 150;
  std::cout << south.name << " " << south.centimeters() << "\n";
  return 0;
}
```

北畦 120 与中畦 80 各做一张只含长度的卡片，两张都按值保存厘米，按声明顺序打印，中间一个空格。应当看到 `120 80`。不要使用引用成员，这道题要的是各自拥有自己的数。
