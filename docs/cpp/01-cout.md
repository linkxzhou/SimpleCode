上一章把北畦、中畦、南畦加成了 350。加总把顺序藏起来了：120 加 80 与 80 加 120 印出来是同一个和。一旦你要把三条边按测量的次序念出来，次序就变成输出的一部分。`std::cout` 的 `<<` 是插入，不是赋值，也不是把右边整段句子倒着吐出来。

运算符本身是左结合的。`std::cout << 120 << " " << 80` 的意思是 `((std::cout << 120) << " ") << 80`。每一次 `<<` 都返回左边的流，下一次再往这股流里放东西。所以先离开进程的是 120，然后是一个空格，然后是 80。人眼从左扫到右，和嵌套调用展开的顺序是一致的。这和某些语言里「右边先准备好再交给左边」的直觉不同。在 C++ 里，插入动作的嵌套结构把已经求完值的结果按书写顺序放进流。

C++14 对另一件事保持沉默：重载运算符的两个操作数，求值顺序没有被规定死，它们和函数参数一样。`<<` 在标准库里是函数，不是一条机器指令。若你把 `++n` 或一个会自己打印的函数直接写进链的中间，那个副作用可能在相邻的插入之前发生，也可能在之后发生。链保证的是「这一次插入放进去的那个值」，不是「参数表达式里的副作用按源码从左到右排队」。可靠的写法是：带副作用的计算先做完，放进一个已经被读过的变量，再把变量送进 `<<`。变量没有副作用，次序就只剩嵌套本身。

空格不会自动出现。`<<` 只插入你交给它的东西。120 后面紧接 80，终端里是 `12080`，读者无法知道这是两条边还是一万两千零八十厘米。测量记录要能被分开朗读，分隔符就得写进链里。换行同样要自己写。`std::endl` 会插入换行并冲洗缓冲，在这个短程序里多一次冲洗没有收益，还把「换行」和「冲洗」绑在同一个词上。我们用 `"\n"`，让换行只表示记录结束。

取舍放在这里。格式串把「先印什么、后印什么」写在一个字符串里，参数按格式说明的出现顺序被消费，这在 C 里很熟。插入链把每个值的类型交给重载，少了格式与参数对不上的那类错，代价是分隔、换行和次序都摊在一串运算符上，漏一个空格不会编译失败，只会让两个数粘住。粘住是逻辑错误，退出码仍是 0。`-Werror` 不负责这件事。你要核对的字符串必须真的被插入，包括那两个空格。

还有一层取舍和性能有关，但在这三行输出里几乎看不见：`cout` 和 C 的标准输出在默认情况下会同步，以免两种接口交叉打印时次序错乱。同步让每次插入更稳，也更慢。菜地的三条边不值得为了速度关掉同步。若以后在别的工程里看到 `sync_with_stdio(false)`，要知道那是在用速度交换「和 `printf` 混用时的次序保证」。这个抽屉的例子不混用，所以保持默认。

三条边仍是 120、80、150。第一份程序把它们和空格一起插入，期望子串是完整的 `120 80 150`。不要只期望 `120`，那会把粘连的 `12080` 也放过去。

```cpp run expect="120 80 150" title="按测量次序"
#include <iostream>
int main() {
  std::cout << 120 << " " << 80 << " " << 150 << "\n";
  return 0;
}
```

若输出是 `150 80 120`，那是你把字面量写反了，不是 `<<` 从右边开始执行。左结合意味着改次序的唯一办法是改源码里从左到右的那些操作数。把南畦写在最左边，南畦就先离开。这看起来像废话，正是为了抵消「流运算符大概和赋值一样从右往左」的错觉。赋值 `a = b = 0` 确实是右结合，插入不是。

第二份程序故意不加空格，让粘连变成看得见的结果。它仍使用同一组数，只是把分隔从链里拿掉。你应当看到 `12080150`。这个字符串不能被三个独立的整数解析还原成唯一的测量：它也可以被读成 12、080、150 或其他切法。记录一旦粘连，地块的形状就丢了。所以「能编译、退出码是 0」不足以证明记录可读。

```cpp run expect="12080150" title="没有分隔就会粘住"
#include <iostream>
int main() {
  std::cout << 120 << 80 << 150 << "\n";
  return 0;
}
```

第三份程序把次序和副作用拆开。中畦不写成字面量，而写成一个函数的返回值。函数只返回 80，自己不打印。返回值在进入插入链之前已经是一个普通的 `int`。即便 C++14 允许这个函数调用和旁边的字面量在求值时间上交错，它也没有额外的输出，终端里的字符次序仍由三次插入的嵌套决定：先 120，再空格，再 80，再空格，再 150。若你让这个函数内部也 `cout` 一段话，那段话插在哪里就不再有保证。教学例子不那样写，免得把未定义的交错当成语言的承诺。

```cpp run expect="120 80 150" title="先算完再插入"
#include <iostream>
int mid_bed() {
  return 80;
}
int main() {
  int north = 120;
  int mid = mid_bed();
  int south = 150;
  std::cout << north << " " << mid << " " << south << "\n";
  return 0;
}
```

三个名字都被插入使用了。`mid_bed` 没有未使用的参数。把计算收进函数，是为了给下一章的重载做铺垫，这一章还不过载：只有一个参数列表。函数放在 `main` 上面，因为单文件里调用点要看得到声明，而我们不另存头文件。

再看一个容易误判的成功。若删掉整条 `cout`，三个变量仍然算得出来，进程仍然可以 `return 0`。空终端不是「菜地长度为 0」，是结果没送出进程。零作为数值和零作为退出码是两回事。中畦的 80 也不是假。假和真留到控制流那一章，那里会看见整数 0 在 `if` 里站在失败的一边，而 80 站在成功的一边。插入这一章不利用这个事实，三个数都要出现在流里，包括最短的那条。

和 `printf` 比，插入的好处是 120 这种 `int` 不需要你写 `%d`。代价是你失去了「宽度、填充、进制」都挤在格式串里的那种紧凑。菜地的记录不需要补零，十进制就够。真要补零，应当用流的操纵符，并且在同一条链上把操纵符也当成一个插入步骤来读：它改变的是后面的格式状态，不是把前面已经插入的数字改掉。状态会留在 `cout` 上，直到你改回来。这个抽屉的例子不改格式状态，免得一条边的格式漏到下一条边。

再把左结合拆成调用的形状来看。第一次插入的左边是流对象，右边是 120，返回的仍是流。第二次插入的左边是上一次的返回值，右边是空格。第三次才轮到 80。人写代码时容易把整条链看成一个「打印函数收到了三个参数」。它不是。参数的分组是两两进行的，每一对都先完成左边的插入，再处理右边那个已经求好的值。分组一旦看清，就不会再期待编译器把最右边的 150 先送出去。

副作用的交错可以用一个只返回数、不打印的函数来隔离，前面的例子已经这么做了。若函数里还改了一个全局的厘米计数，那个计数的变化时刻就落到了未规定的求值顺序里。全局状态在这个抽屉里本来也活不过下一次运行，可同一次运行内部，未规定的顺序仍会让你看见不稳定的中间值。稳定的办法是让函数只计算，不碰流，也不碰别的可变全局。计算的结果放进局部变量之后，插入链上就只剩下没有副作用的名字。名字的求值没有「先改谁」的问题，剩下的次序就是嵌套本身，而嵌套是规定好的。

分隔符还有第三种容易漏掉的形态：行尾。三条边若各占一行，期望子串仍可以是 `80`，但读者要靠换行知道 80 是完整的一条，而不是 180 或 800 的一部分。这一章把三条放在同一行并用空格分开，是为了让一次输出同时展示次序和分隔。换行留到需要「记录结束」的时候再用。`endl` 额外要求冲洗，短例子里冲洗只增加一次同步，不改变厘米的值。默认的 `cout` 在进程正常结束时会冲洗，所以 `"\n"` 足够让终端看见这三行字。若进程被中途杀掉，缓冲里没冲洗的内容可能消失。教学运行会把进程跑完，这个风险不在示例的退出路径上。

和格式串相比，插入的另一个差别是进制和宽度要靠流的状态，而不是靠每个值旁边的说明。你一旦让流进入十六进制，后面的 150 也会按十六进制离开，除非你再改回来。状态是流的属性，不是某一个插入的属性。三条边都用十进制，示例就不碰这种状态。真要在同一条链上混用进制，应当在每个值之前写明，并在用完后恢复，否则南畦的 150 会变成别的数字，心算复核会失败，而编译仍然成功。成功只说明类型匹配，不说明人还能读。

最后把「先算完」落实到表达式的粒度。`north + mid` 可以写在链的中间，加法本身没有输出副作用，结果是一个临时的 `int`，插入它是安全的。不安全的是那些既产生值又改同一块标量的写法，例如在链里同时读 `n` 和 `++n`。那是未定义行为，不是「顺序不确定」而已。未定义行为和未规定求值顺序要分开记：顺序未规定时，几种顺序都合法，输出仍是程序的一种可能；未定义时，编译器不必保存你以为的任何一种顺序。菜地的例子停在未规定这一层的外侧，只插入算完的值，让输出只有一种。

## 小结

链式 `<<` 是左结合的嵌套调用，已经求完的值按你写下的顺序进入流。空格和换行不会被自动补上，三条边要写成 `120 80 150` 这种能分开朗读的记录。会改状态或会自己打印的表达式先执行完，再把结果放进变量；C++14 不保证那些副作用沿着链从左到右发生。

下一章给这些厘米一个可以共用的名字。引用一旦绑上北畦，后面的赋值改的是那一条边的长度，而不是把标签改挂到另一条边上。插入的次序先记熟，免得引用那一章同时在跟两个问题打架。

## 练习

把南畦放在链的最左边，北畦放在最右边，中间仍用一个空格。输出应当是 `150 120`。这道题用来确认次序来自你书写的位置。不要打印中畦，避免期望子串和三边那一版缠在一起。

::: answer 参考答案：先南后北
```cpp run expect="150 120" title="参考答案"
#include <iostream>
int main() {
  std::cout << 150 << " " << 120 << "\n";
  return 0;
}
```
:::

用逗号而不是空格分开北畦和中畦，得到 `120,80`。逗号是你插入的字符，不是 `cout` 的默认分隔。两个数仍然来自同一块菜地。

::: answer 参考答案：逗号分隔
```cpp run expect="120,80" title="参考答案"
#include <iostream>
int main() {
  int north = 120;
  int mid = 80;
  std::cout << north << "," << mid << "\n";
  return 0;
}
```
:::
