你若已经能用 C 把一组整数加起来，C++ 在这个抽屉里不是另一门陌生的手艺，而是在同一支 clang 上多出来的一层标准库和类型规则。编译器仍是 clang 8 那一代的前端，标准库是 libc++，语言方言大致落在 gnu++14。点 Run 之后，唯一的源文件被编译、再链接成 wasm，然后作为新进程执行。退出码不是 0 时，`main` 里的输出语句没有机会跑。终端里先出现的是诊断，不是你心算过的厘米数。

`-Werror` 把这份前端默认会发出的警告变成错误。未使用的局部变量不要留：名字一旦写出来，就得出现在某个表达式里。移植到打开更多警告的编译器时，沉默的声明会变成失败；就算这里没响，一个算了却从不打印的长度，也会让菜地的周长看起来像没量过。每次运行都是新进程，全局变量活不过下一次点击，所以三条边长要写在源码里，反复出现。

多出来的第一样东西是 `std::string`。C 里一条畦的名字通常是字符数组，长度要你自己记得，多写一个字节就可能越界。`std::string` 把自己的长度带在对象里，拼接和拷贝由对象负责。多出来的第二样是 `std::vector`。三条边今天够用，明天若在南边又量出一条，定长数组要么预留过大，要么你亲手 `realloc`。向量按需变长，元素仍是连续存放的，遍历的写法后来可以交给算法。多出来的第三样是引用、重载、函数模板和一套不靠你手写循环的算法。它们都还是静态类型：写错了，编译期就停，而不是在 wasm 里把厘米印成地址。

这层东西换不来的，也要在开篇说清。没有第二个源文件，头文件护符和跨翻译单元的链接在这里无用武之地，函数都写在同一个 `main` 上方。没有 `<thread>`，围篱笆不会派一条后台线程去量另一边。没有 `<filesystem>`，这一次写进内存的笔记，下一次点击不会还在。`std::optional` 是 C++17 的类型，这份方言里不要用它表示「可能没有的长度」。`std::sort` 会把 libc++ 里依赖 `__lttf2` 的路径拉进链接，而这条 wasm 链接线没有那个长双精度辅助符号，链接失败发生在你只对 `int` 排序的时候。后面会用最小值、最大值和计数代替排序。异常同样不可靠：可运行的例子用返回值表示失败，`throw` 只出现在不能运行的块里，用来记住「外面的 C++ 会这么写，这里不要」。

取舍是具体的。C 的 `printf` 把格式串和参数拆成两套系统，格式写错时，不少编译器要到运行才用错误的宽度去读参数。`iostream` 的 `<<` 把类型交给重载，少了一类格式串错误，代价是链式插入的写法要单独学，而且 C++14 并不保证操作数里的副作用按你眼睛扫过的顺序发生。`string` 和 `vector` 会在对象销毁时释放自己的缓冲，你少写一次 `free`，也少了一次「忘记释放」；代价是你要接受它们在变长时可能整块搬家，之前握住的地址会失效。引用不能为空，初始化时就必须绑上一个对象，这比可空指针少一种崩溃，也少了「先声明、以后再指」的自由。这些代价后面分章展开。这一章只把账记清：你得到的是类型和容器，你交出去的是异常、排序、线程、文件系统和多文件。

例子始终用同一块菜地。北畦 120 厘米，中畦 80 厘米，南畦 150 厘米。80 是短的那一条，后面用它做门槛；150 是长的那一条；三者之和是 350。换一套数会把注意力从语言机制上挪走。名字可以是英文标签 `plot`，也可以是中文「北畦」。中文在源码里按 UTF-8 保存，clang 接受；`string::size()` 数的是字节，不是你眼睛看见的字数。这个差别留到向量和字符串那一章细算，这里先让一条英文标签和三个整数能单独编译、单独打印。

每个可运行块都自带 `#include` 和 `main`，因为块会被抽出来单独编译，散文不会进入编译器。期望是输出的子串：印出 `350` 时，后面的换行不算失败，缺了这三位才算。不要为了多出来的空行去改期望。

下面先把三条边加起来。没有向量，是为了让 350 来自加法，不来自容器。这也是和 C 最靠近的一层：你仍要自己写表达式，只是把结果交给 `cout`，而不是交给带 `%d` 的格式串。

```cpp run expect="350" title="三边相加"
#include <iostream>
int main() {
  std::cout << (120 + 80 + 150) << "\n";
  return 0;
}
```

350 可以复核：120 加 80 是 200，再加 150 是 350。若终端里是 200，优先怀疑漏写了南畦，而不是怀疑 `cout` 会随机少加一次。南畦是这组数里最长的，后面拿它和中畦比，正是因为两者离得远。漏掉它，菜地会被说成只有北边和中间那么窄。

下一步让地块有一个名字。`std::string` 在声明时就持有自己的字符，`<<` 知道怎么把这段字符送出进程。你没有写长度参数，也没有写格式说明。这就是相对 `printf("%s", ...)` 多出来的那一点：类型在重载里，不在格式串里。标签用英文，是为了让这一章的期望子串和后面「字节数」的讨论分开。

```cpp run expect="plot 120" title="地块有名字"
#include <iostream>
#include <string>
int main() {
  std::string label = "plot";
  int north = 120;
  std::cout << label << " " << north << "\n";
  return 0;
}
```

`label` 和 `north` 都被读了。若你调试时再声明一个 `int spare = 80` 却不打印、不参与运算，就删掉它。注释掉的声明不会进编译，却会让读者以为中畦已经放在变量里。

第三步把三条边放进向量，只为了看见「个数由容器回答」。这一章还不变长、不取子串，那些是后面的主题。这里的收获很窄：你问 `size()`，得到 3，这个 3 不是你另写的一个魔数。若你删掉一次 `push_back` 却忘了改手写的次数，C 数组经常就这样撒谎；向量的 `size()` 跟元素一起走。代价是多包含一个头，并且接受元素类型必须在编译期说死。三条边都是 `int`，说得死。

```cpp run expect="3" title="容器回答个数"
#include <iostream>
#include <vector>
int main() {
  std::vector<int> beds;
  beds.push_back(120);
  beds.push_back(80);
  beds.push_back(150);
  std::cout << beds.size() << "\n";
  return 0;
}
```

输出是单独的 `3`。不要把期望写成 `1`，因为 120 和 150 里都含有数字 1，子串会误伤。个数和边长分两章细看：这一章只确认容器肯告诉你它有多长。

```cpp norun title="这份运行时做不到的"
#include <iostream>
int main() {
  /* 不要包含 <thread> 或 <filesystem>。
     不要在可运行示例里 throw。
     不要 std::sort，链接会要 __lttf2。
     不要 std::optional，那是 C++17。 */
  std::cout << "skip\n";
  return 0;
}
```

只读的那一块故意不能运行。它旁边的话是限制，不是待办。把 `throw` 或 `std::sort` 抄进能运行的例子，不会得到一块更完整的菜地，只会得到一份在这个目标上过不了编译或链接的文件。

再把「提前失败」的账说完。把警告当成错误，教学示例会变笨：你不能留一个「先声明以后再用」的变量穿过好几次编辑。好处是失败发生在有行号的时候。单文件也是取舍。真实的测量程序会把换算、存储、界面分成多个翻译单元，否则一个文件会长到无法审查。这里的目标是看清语言，边界靠函数和参数，不靠链接器。进程模型同样如此：每次运行都清空，调试时不会被昨天写到一半的向量污染；你也不能在这一章把 350 写进文件，指望下一章打开它。跨章节的记忆只能写在散文和字面量里，所以 120、80、150 不能换。

和 C 相比，你少写的是格式串、手工扩容和一批空指针检查的样板；你多写的是类型名、头文件和「这个对象活着，缓冲就在」的习惯。样板少了，并不等于规则少了。引用必须在出生时绑上，零在条件里为假，`substr` 的第二个参数是长度，`size()` 对中文是字节。这四条会在后面咬人，开篇先把它们当成这层 C++ 的地契，而不是当成可选的风格。

把这层增益放到链接上看，会少一些含糊。C 与 C++ 在抽屉里共用 clang 前端和 wasm-ld，C++ 多出来的是把源码当成 C++ 来解析、把 libc++ 的头放进搜索路径，以及在链接时带上 C++ 标准库和 ABI 支持。你写下 `std::vector`，实现就不再只是一个结构体加几次自己调用的 `malloc`。模板在头文件里展开，展开之后的符号未必只跟你写过的 `int` 有关。`std::sort` 就是这样把长双精度比较的辅助符号拖进链接的。开篇不把排序当成禁忌的词，而把它当成这条链接线还付不起的依赖。最小值和计数付得起，所以后面的章节用它们回答「最短是哪条」「过线有几条」。

手写循环在三条边上几乎和容器一样短。容器的收益要等第四条边出现时才看得清：上界来自 `size()`，你不用同时改正循环里的魔数。代价是诊断有时指向标准头内部，第一眼不像自己的行。三条边若编译失败，先核对每次 `push_back` 的类型是不是同一个 `int`，再核对有没有把一个手写的 `3` 和 `size()` 并排放着却各改各的。两套长度一分叉，和就不再是 350。这一章的向量示例只问容器自己的个数，不再平行维护一个计数变量。

再比较内存的所有权。C 里一条名字常常是你分配的缓冲，长度用另一个参数传来传去，释放点要你自己记得。`std::string` 把缓冲和长度捆在对象里，对象离开作用域时缓冲跟着走。你少了一次 `free`，也少了一次「释放之后还用旧指针」的窗口。代价是复制字符串会复制字符，函数若按值接收很长的名字，开销在调用边界上。菜地的标签只有几个字节，按值或按 const 引用都看不出时间差。后面仍把会改调用方的参数写成引用，把只读的长对象写成 const 引用，是为了把「改不改」写在类型上，而不是为了省那几个字节。

最后把进程模型说成测量习惯。每一次 Run 都从空的地址空间开始，昨天留在向量里的第四条边不会还在。这让示例可重复：350 只可能来自你这次写上的三个字面量。代价是你无法用一次运行给下一次运行留作业。作业只能写成源码或写在围栏的输入里。所以这十二条都守着同一块地：北 120，中 80，南 150。换数会让后面的门槛 100、字条 `buy pen`、待办的次序全部失去对照。

你从 C 带来的判断力大部分还能用。整数除法仍会截断，`120 / 80` 得到 1 而不是 1.5，这一章故意不做这个除法，免得在还没讨论类型的时候先把平均边长说成一个偏小的整数。指针仍可能悬空，数组下标仍可能越界，`-Werror` 不会替你证明下标小于长度。C++ 多给你的是一套默认更完整的对象，不是一套自动正确的几何。对象会在销毁时收拾自己，下标和正负号仍要你看。

## 小结

这一章之后，先分清两件事：程序有没有诞生，以及诞生之后印出的是不是 350。编译或链接失败时，去读诊断的名字，不要改期望子串。你在 C 之外得到的是 `string`、`vector`，以及后面才会展开的引用、重载、模板和算法；你没有得到可用的异常、可用的 `std::sort`、线程、文件系统和第二份源文件。

三条边长固定为 120、80、150。下一章只问一件事：几个值接在同一个 `<<` 后面时，它们按什么顺序离开进程。个数、引用和变长都先放着，免得一章里同时改两套规则。

## 练习

只打印南畦与中畦的差。150 减 80，结果应当是 70。不要另起一组长度，也不要打印解释性的句子，这样期望子串不会和说明文字缠在一起。差可以用一个 `int` 接住，但这个 `int` 必须出现在 `cout` 里。

::: answer 参考答案：长短之差
```cpp run expect="70" title="参考答案"
#include <iostream>
int main() {
  int south = 150;
  int mid = 80;
  std::cout << (south - mid) << "\n";
  return 0;
}
```
:::
