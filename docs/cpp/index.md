C++ 在这里由 clang 配合 libc++ 编译成 wasm 再运行。点代码块上的 Run，编辑器里的单文件会经过编译和链接。警告当成错误。未使用的变量会让这次运行失败。

每次运行都是新进程。没有线程，没有文件系统库，也没有第二份源文件。iostream、string、vector 和 algorithm 可以用。异常在这份工具链上不可靠，可运行示例用返回值表示失败，throw 只出现在只读块里。

期望是输出里的子串。编译失败时终端里是诊断，不是你想打印的那句话。

```cpp norun title="只读"
/* 不要写 throw。这份 wasm 工具链上的异常不可靠。
   也不要使用 thread 或 filesystem。 */
```

```cpp run expect="42" title="相加"
#include <iostream>
int main() {
  std::cout << (19 + 23) << "\n";
  return 0;
}
```

```cpp run expect="你好" title="问候"
#include <iostream>
int main() {
  std::cout << "你好\n";
  return 0;
}
```

「只读」故意不能运行。先读它旁边的限制，再回到能点 Run 的例子上改一个值。不要把只读块当成坏掉的按钮。

### 读「相加」

做完上一例再做这一例。把代码收成一行来记：`#include <iostream> int main() { std::cout << (19 + 23) << "\n"; return 0; }`。先盖住终端，写下你预测的输出，里面要能找到「42」。这是子串：前面可以有别的字，后面通常有换行。

然后点这个代码块上的 Run，不要点工具栏。代码块会备份草稿、写入示例再执行。找不到这段文字时，先看退出码。不是 0 就读错误类型，不要改期望。是 0 但内容不对，就只改产生该值的那一处。改完用工具栏的 Run，因为再点代码块会把修改盖掉。预测对了之后点撤销。

做完上一例再做这一例。把代码收成一行来记：`#include <iostream> int main() { std::cout << "你好\n"; return 0; }`。先盖住终端，写下你预测的输出，里面要能找到「你好」。这是子串：前面可以有别的字，后面通常有换行。

然后点这个代码块上的 Run，不要点工具栏。代码块会备份草稿、写入示例再执行。找不到这段文字时，先看退出码。不是 0 就读错误类型，不要改期望。是 0 但内容不对，就只改产生该值的那一处。改完用工具栏的 Run，因为再点代码块会把修改盖掉。预测对了之后点撤销。

### 限制：只读

这一段故意不能运行。旁边的限制是：在可运行示例里 throw，或包含 thread、filesystem。。做法是：每个示例都是一份能单独编译的完整程序。。把它留在抽屉里对照，不要粘进主编辑器再点工具栏的 Run。能运行的例子在它前后，改那些例子时不要把这里的调用加进去。

### 只改一处：相加

这一例要避开的失误是：留下未使用的变量。。对应的做法是：失败用返回值表示。。

把代码收成一行来核对：`#include <iostream> int main() { std::cout << (19 + 23) << "\n"; return 0; }`。盖住终端，先写下预测，里面要能找到「42」。然后点这个代码块上的 Run。结果不同时，只改产生该值的那一行，再用工具栏的 Run 看新结果。不要把两处不相关的改动叠在一起。确认之后点撤销，下一例才会从文档里的代码开始。

若出现报错，先看错误类型的名字，再回到本章的常见错误。期望是子串，多出来的说明行不算失败，缺了「42」才算失败。

### 只改一处：问候

这一例要避开的失误是：忘了换行，下一行结果粘在一起。。对应的做法是：要核对的文字用 cout 打出来。。

把代码收成一行来核对：`#include <iostream> int main() { std::cout << "你好\n"; return 0; }`。盖住终端，先写下预测，里面要能找到「你好」。然后点这个代码块上的 Run。结果不同时，只改产生该值的那一行，再用工具栏的 Run 看新结果。不要把两处不相关的改动叠在一起。确认之后点撤销，下一例才会从文档里的代码开始。

若出现报错，先看错误类型的名字，再回到本章的常见错误。期望是子串，多出来的说明行不算失败，缺了「你好」才算失败。

## 读完再动手

本章要留下的是 「用 cout 看见结果」、「知道警告会让编译失败」、「把做不到的写法留在只读块」。合上抽屉之前，用自己的话说出每一项目标对应哪一个示例的标题。对不上标题，就还没有把目标和代码连起来，先别展开练习答案。

练习的答案默认折着。先在编辑器里自己写，再展开对照。对照时只看输出是否包含期望的那几个字。两道都过了再进入下一章。下一次运行是新进程，这次的变量不会留下。

把这一章当成一次可以反复撤销的实验。点代码块上的 Run 会用示例覆盖编辑器，原来的草稿先备份。你改过的内容如果还想留着，先复制到别处，再点下一例。工具栏的 Run 不会从文档重写编辑器，所以它用来看你改过的版本。两种按钮各做各的事。下载进度写在按钮旁边，第一次打开这种语言时要等它结束，再判断示例是不是写错了。

记录你预测错的那一次。写下你以为会打印的文字，以及实际多出来或少掉的部分。进入下一章之前，要能用一句话说清差在哪。通过只说明期望的那几个字还在，不说明你已经看懂产生它的那一行。章节标题下的目标就是这份验收清单。差两个字也不要靠改期望凑过去。

## 常见错误

- 在可运行示例里 throw，或包含 thread、filesystem。
- 留下未使用的变量。
- 忘了换行，下一行结果粘在一起。

## 最佳实践

- 每个示例都是一份能单独编译的完整程序。
- 失败用返回值表示。
- 要核对的文字用 cout 打出来。

## 小结

C++ 101 的例子经 clang 和 libc++ 编译后运行。结果靠 cout。异常不放进可运行示例。
