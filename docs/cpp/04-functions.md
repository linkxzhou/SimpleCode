分支已经能挑出短畦。若北畦和中畦比一次、中畦和南畦比一次、北畦和南畦再比一次，比较式会在 `main` 里复制三份。复制会漂移：其中一处把门槛从严格大于改成不小于，另一处忘了改，工单上就会出现两个「更长」的答案。函数把这一份比较收成一个名字，调用点只负责交出两条边。

先写只接受两个 `int` 的 `longer`。它返回较大的那个数。80 和 150 进去，150 出来。相等时返回哪一个都一样，函数里用 `>` 而不是 `>=`，相等就落到 `return b`。菜地的三条边互不相等，这条分支碰不到，但写出来是为了让每条路径都有返回值。非 void 函数若有一条路径走到右花括号外面，clang 会诊断，`-Werror` 会让这一次运行根本不开始。

```cpp run expect="150" title="两条里更长的"
#include <iostream>
int longer(int a, int b) {
  if (a > b) {
    return a;
  }
  return b;
}
int main() {
  std::cout << longer(80, 150) << "\n";
  return 0;
}
```

参数按值传递。函数里即使写 `a = 0`，调用方的中畦仍是 80。这一份函数没有写那句赋值，因为用不到的修改会让读者以为调用方也被改了。按值的代价是复制。`int` 的复制可以忽略。真正的代价是语义：函数答应「只问不改」。若以后要修正某一畦的读数，参数得改成引用，调用方才会看见修正。那是另一种函数，不应当偷偷换在这个名字下面。

重载是下一步。同一个名字 `span`，一份参数是一条边，返回它自己；另一份参数是两条边，返回它们的和。调用 `span(120)` 时，编译器只找得到一份可行的参数列表，就是那一个 `int`。调用 `span(120, 80)` 时，两份列表都在，参数个数把第二份选出来，结果是 200。重载决议看的是参数的个数和类型，不看返回类型。你不能写两个 `span`，都收一个 `int`，一个返回厘米、一个返回米。那两份声明在调用点无法区分，编译会停。

为什么允许同一个名字，而不是强迫你写成 `span_one` 和 `span_two`？当两份函数表达的是同一件事——「这几条边合起来有多长」——名字保持一个，读调用的人不用先记后缀。一条边的跨度就是它自己，两条边的跨度是和，这个延伸还算诚实。代价是读实现的人必须把两份函数体都看完，才能确定某一次调用会进哪一份。份数一多，名字就变成一个小的重载集合，调用点看起来简单，决议却要在脑子里重放。菜地只有两份，集合还小。若第三份的含义已经变成「平均」而不再是「跨度」，就该换一个名字，而不是再加一层重载。平均和求和不是同一件事，共用名字是在用决议代替文档。

```cpp run expect="120 200" title="一条或两条"
#include <iostream>
int span(int a) {
  return a;
}
int span(int a, int b) {
  return a + b;
}
int main() {
  std::cout << span(120) << " " << span(120, 80) << "\n";
  return 0;
}
```

两份 `span` 都写在 `main` 前面。单文件没有头文件可以预先声明，定义本身就是声明。若把它们挪到 `main` 下面又不写前置声明，调用点会看不见名字。这个失败是单文件教程的形状决定的，不是重载的特殊规则。

第三份程序碰那个返回值的坑。有人喜欢让 `span` 在参数不是正数时返回 -1，成功时返回和。120 与 80 得到 200，0 与 80 得到 -1。-1 不在合法的厘米里，所以这一次还能分辨。期望里要能找到 `-1`，同时 200 也在输出里，证明成功的路径没被你改丢。问题在于：返回通道只有一条。长度和失败挤在同一个 `int` 里。哪天某条计算真的可能得到 -1（比如北畦减南畦的差，方向反了），调用方就无法知道这是长度还是拒绝。0 更危险。若用 0 表示失败，而某一畦的跨度恰好可以是 0，`if (span(...))` 会把合法的 0 厘米当成失败，因为 0 在条件里为假。上一章的真值规则在这里变成返回码的陷阱。

```cpp run expect="-1" title="失败和长度挤在一起"
#include <iostream>
int span(int a, int b) {
  if (a <= 0) {
    return -1;
  }
  if (b <= 0) {
    return -1;
  }
  return a + b;
}
int main() {
  std::cout << span(120, 80) << "\n";
  std::cout << span(0, 80) << "\n";
  return 0;
}
```

这份函数没有和前面的 `span` 重载冲突，因为它活在另一次编译里。每个可运行块都是完整程序。把三份函数贴进同一个文件时，两个参数的 `span` 会有两份定义，链接会抱怨重复符号。教程把它们拆开，是运行方式的限制，也是一种提醒：重载集合要放在同一次编译里才能互相看见。

取舍可以记成一句操作上的话。重载适合「参数不同、意图相同」。意图不同时，多一个名字比多一份参数列表更不容易在三个月后被看反。返回 -1 适合「负数永远不是合法结果」的窄情况，菜地的差有时就是负数，所以这条路走不远。下一章还不用状态码，先把边长放进能变长的向量，让记录的个数不再写死成两份参数。三个数硬写成 `span(int, int, int)` 也行，但第四条边出现时你还得再加一份重载。那是重载的尽头：个数一旦不固定，参数列表就该让位给容器。

函数体里的 0 仍然为假，这一章却没有写 `if (a)`，而写了 `a <= 0`。负数也要拒绝，单靠真值转换会把 -5 当成真，从而返回一个负的「跨度」。真值转换只管零和非零，不管符号。门槛若是「必须为正」，就要写比较，不要偷用条件转换。这和上一章「0 厘米被跳过」是相邻的坑：跳过用的是真假，拒绝非法用的是比较。两套条件都合法，表达的工单不一样。

内联、静态、跨文件的链接说明，在这个抽屉里都排不上。只有一个翻译单元，编译器是否把 `longer` 嵌进 `main` 不影响你看见的 150。不要为了教程去写 `inline` 或拆成两个 `.cpp`。做不到的拆分不是这一章的主题，主题是名字和参数列表。

重载决议还可以从「谁能被调用」往下看，而不是只看个数。两个参数都是 `int` 时，只有两参数的 `span` 可行。若再提供一份 `span(double, double)`，传入两个 `int` 仍然优先选 `int` 那份，因为精确匹配优于需要转换的匹配。传入一个 `int` 和一个浮点字面量时，两份都要经过某种转换，决议可能变得含糊，编译直接停下来要求你改调用。含糊比选错更好：选错会静静地用另一套精度去加厘米。这一章不引入 `double`，就是为了让个数成为唯一的区别，决议的理由可以用手指着参数列表数出来。

函数的定义在单文件里也是声明。若两个重载互相调用，被调的那份必须出现在前面，或者先写一条只有签名的声明。互相递归在菜地的跨度里用不上。需要先声明的情况通常是：你想把实现按阅读顺序放，而不是按调用顺序放。阅读顺序把 `main` 放在文件底部是一种口味，调用顺序把被调函数放在上面是另一种。这个抽屉选择后者，省掉一批只有签名的前置声明。前置声明的代价是签名会写两遍，改参数时容易只改一处。定义即声明时，签名只存在于一处。

返回值的通道一旦被哨兵占用，调用方的检查就会变形。`if (span(a, b) < 0)` 能认出 -1，`if (!span(a, b))` 却认不出 -1，因为 -1 非零，条件为真。同一份失败，两种检查，一个看见，一个看不见。这就是哨兵比「单独的状态整数」更难教给下一个人的原因。状态整数约定 0 是失败，`if (!keep(...))` 和「零为假」是同一条规则，不用再记「负数才是失败、零却是合法长度」这种例外。例外在三行示例里还能记住，在十个调用点里会被人抄错。

按值传递还意味着参数的修改是草稿。你可以在 `longer` 里写 `if (a < 0) a = 0;` 再比较，调用方的原变量不变。这种草稿适合「把非法值先夹进范围再比」，但它把拒绝藏进了函数内部，调用方不知道自己的负数被换成了 0。菜地的 `longer` 不夹，它假定两边都已经是量过的正数。拒绝放在进入比较之前，由返回状态的函数做。职责分开之后，`longer` 的身体才能短到只剩一个比较。短不是目的，目的是读者能在一屏里看完「谁更大」而不被清洗数据的逻辑打断。

内联与否不改变这些语义。编译器可以把 `longer` 嵌进调用点，嵌进去之后 150 仍是 150。你不需要写 `inline` 来保证这一点，也不该为了「看起来更快」把函数体抄回 `main`。抄回去的那一刻，三处比较又开始各自演化。函数的价值是只有一份身体。重载是在「一份身体」和「一个名字」之间做的折中：身体仍按参数列表分成几份，名字合成一个。份数增加时，折中会向坏的方向走，那时就该换成容器加一个循环，而不是再添一份 `span`。

参数个数相同、类型不同的重载，这一章没有写成可运行的例子，但决议的方向值得先放在心里。`span` 若另有一份接受两个 `const std::string &`，传入两个整数仍走整数那份，传入两个字符串才走字符串那份。传入整数和字符串各一，则没有可行函数，编译停止。停止比悄悄把整数格式化成文字再拼接要好，因为拼接出来的「跨度」不再是厘米。厘米的加法只在整数那份里发生。文字的事情留给模板那一章，而且那里用的是比较，不是拼接。名字 `span` 不承担比较。一个名字只做跨度，比较另起 `longer` 和以后的 `smaller`。

## 小结

`longer` 把比较收进函数，两条边里较大的那个被返回，80 和 150 得到 150。`span` 的两份重载靠参数个数区分：一条边返回自己，两条边返回和，120 与 `120 80` 的和在同一次输出里是 `120 200`。决议不看返回类型。

用 -1 表示失败能应付这一次演示，因为它和 200 长得不一样。它挤占了返回通道。0 若再拿来当失败，又会和条件里的假值缠在一起。下一章先不解决失败，只让同一批边长住进向量，个数用 `push_back` 增长，而不是用第三份、第四份重载去追。

## 练习

写一个 `shorter`，返回两个正整数里较小的那个。用中畦和南畦调用，应当打印 80。两条路径都要有 `return`，不要留一条走到函数末尾的路。

::: answer 参考答案：较短的一边
```cpp run expect="80" title="参考答案"
#include <iostream>
int shorter(int a, int b) {
  if (a < b) {
    return a;
  }
  return b;
}
int main() {
  std::cout << shorter(80, 150) << "\n";
  return 0;
}
```
:::

再写一份三个参数的 `span`，把 120、80、150 加起来打印。应当看到 350。这一份不要和失败码混在同一个函数里，三个参数都视为已经量过的正数。

::: answer 参考答案：三边的跨度
```cpp run expect="350" title="参考答案"
#include <iostream>
int span(int a, int b, int c) {
  return a + b + c;
}
int main() {
  std::cout << span(120, 80, 150) << "\n";
  return 0;
}
```
:::
