重载能应付一条边或两条边。第四条边出现时，你不会想再写一份四个参数的函数。`std::vector` 把个数从类型里拿掉，放进运行时的长度。元素类型仍在编译期说死：这一章前半是 `vector<int>`，后半用 `string` 存文字。两者都是「同一批菜地记录」的容器，一个装厘米，一个装名字和字条。

向量从空开始才看得出变长。声明 `std::vector<int> beds;` 之后 `size()` 是 0，0 在这里是个数，不是某条边的长度。第一次 `push_back(120)` 之后个数变成 1，下标 0 上是北畦。输出写成 `1 120`，个数和元素都在，避免只看 120 时误以为你打印的是字面量。空向量上不要读 `beds[0]`，那个位置还不存在。越界不是一个干净的失败码，它是未定义行为。这一章的每次数组式访问都发生在 `push_back` 之后，并且下标小于 `size()`。

```cpp run expect="1 120" title="先放下北畦"
#include <iostream>
#include <vector>
int main() {
  std::vector<int> beds;
  beds.push_back(120);
  std::cout << beds.size() << " " << beds[0] << "\n";
  return 0;
}
```

第二份程序把中畦和南畦也放进去。顺序就是测量顺序：120，然后 80，然后 150。`beds[1]` 是 80。个数是 3。期望 `3 80` 同时检查这两件事。向量不会因为你觉得 80 太短就把它排到别的位置。它也不排序。排序留到算法那一章，并且在这个抽屉里不能用 `std::sort`。这里的次序就是 `push_back` 的次序。

```cpp run expect="3 80" title="三条都在"
#include <iostream>
#include <vector>
int main() {
  std::vector<int> beds;
  beds.push_back(120);
  beds.push_back(80);
  beds.push_back(150);
  std::cout << beds.size() << " " << beds[1] << "\n";
  return 0;
}
```

`push_back` 可能让缓冲搬家。容量不够时，向量分配一块更大的内存，把旧元素拷进去，释放旧块。你若在第一次 `push_back` 之后就取 `beds[0]` 的引用或指针，再继续 `push_back`，那条引用可能指着已经释放的地址。引用必须在初始化时绑上一个对象，这条在前面成立；对象若被容器扔掉，引用不会自动改绑到新地址。演示程序不握着元素的引用跨越 `push_back`。需要长期指着某一畦时，要么在所有 `push_back` 完成后再取下标，要么改用不会搬家的结构。下标在搬家之后仍然有效，因为它不是地址，而是「第几格」：只要你不在中间插入或删除，`beds[1]` 还是中畦。

`string` 是另一份变长记录，单元是字节，不是你眼睛里的「一个字」。字条 `buy pen` 有 7 个字节：三个字母、一个空格、三个字母。`substr` 的第一个参数是起点，从 0 数；第二个参数是要取的长度，不是终点下标。从下标 4 取 3 个字节，得到 `pen`。若把第二个参数当成终点，写成从 4 到 6 那种别的语言的习惯，你仍然碰巧得到 3，因为 6 减 4 再加一这种算法我们并没有用。契约就是起点加长度。长度给大了，库会停在字符串末尾，不会把后面的内存也带出来；起点若大于 `size()`，这一份标准库会抛异常。异常在这个抽屉里不可靠，所以起点一定要先和 `size()` 比过，再调用 `substr`。可运行例子只用已知落在内部的起点。

中文名字把字节这件事说死。`北畦` 两个字，UTF-8 里各占 3 个字节，`size()` 是 6，不是 2。`substr(0, 3)` 取出前三个字节，正好是「北」。`substr(0, 1)` 会切断一个字的编码，终端里不一定是一个可读的汉字。我们打印 `pen`，再打印 `北畦` 的字节数，期望里同时放上 `pen` 和 `6`，写成 `pen 6`。这样子串既证明切的是长度，也证明中文没有按字数计。

```cpp run expect="pen 6" title="长度是字节"
#include <iostream>
#include <string>
int main() {
  std::string note = "buy pen";
  std::string name = "北畦";
  std::cout << note.substr(4, 3) << " " << name.size() << "\n";
  return 0;
}
```

`note` 和 `name` 都用上了。不要再声明一个不用的 `std::string spare`。`substr` 返回一个新的 `string`，原来的 `note` 不被切断，后面若再打印 `note` 仍是整句 `buy pen`。这一份程序没有再打印它，是为了让期望只含切出来的那一段和字节数。新字符串的代价是一次拷贝。三条短记录不值得为了避免拷贝去改底层缓冲。需要零拷贝的视图是更新的标准，不在这份 gnu++14 的常用子集里，我们不引入。

向量和字符串的取舍可以放在一起看。两者都把「存多少」从程序员的魔数改成对象自己回答的 `size()`。向量的元素是同质的，`int` 就是 `int`。字符串的元素在实现上是 `char`，一个 Unicode 字可能跨过好几个 `char`。所以向量的 `size()` 对厘米来说就是「几条边」，字符串的 `size()` 对中文来说不是「几个字」。同一套名字，两种单位。读代码时要看容器里装的是什么，不能看见 `size` 就当成视觉上的个数。

容量和长度也不是一个数。`size()` 是现在有几个元素，`capacity()` 是已经留出的格子。`push_back` 之后长度加一，容量可能不变，也可能一下子变大。教学输出不打印容量，因为它由实现决定，期望子串会飘。你要依赖的是长度和下标，不是容量的具体数值。提前 `reserve` 可以减少搬家，三条边不需要。若你握着引用跨越增长，`reserve` 也只是把搬家推迟到超过预留的那一次，不是把引用变成永远有效。

字条 `buy pen` 会在读入那一章从标准输入再来一次。这一章它写在源码里，是为了让 `substr` 的下标可以被心算复核：位置 0 是 `b`，位置 4 是 `p`。输入那一章才把同一行从进程外面送进来。不要在这里改成别的英文，否则后面的期望对不上同一张字条。

容量的增长策略由库决定，常见的做法是按倍数扩大，以免每放入一条边就整块搬家。倍数使总的拷贝代价相对最终长度仍是线性的，而不是每次加一就付出当前长度那么多拷贝。你不该依赖具体的倍数，也不该依赖某一次 `push_back` 之后容量恰好等于长度。依赖容量的示例会在换一个标准库时改变输出。我们打印的是 `size()` 和下标上的厘米，这两样在契约里是稳定的。

搬家时，元素用它们的拷贝或移动构造进新缓冲。`int` 的拷贝就是把厘米再写一遍。`string` 的拷贝会复制字符，短字符串有时被实现存在对象内部，不另分配，这是优化，不是你能在源码里看见的分支。无论哪种，旧缓冲里的指针和引用都会失效。迭代器同样失效。下标不失效，因为下标不是地址。需要「记住中畦」时，记住下标 1，比记住指向元素的引用更耐增长。等所有 `push_back` 结束，再取一次引用，引用的寿命就从取的那一刻算起，并且你答应之后不再增长这个向量。

`substr` 的长度参数还有一个容易和终点混淆的边界。起点 4、长度 3，覆盖的下标是 4、5、6，最后一个下标是起点加长度减一。若你来自「区间含头不含尾」的切片，终点应写成 7，长度仍是 3，两种说法描述同一段 `pen`。标准库选择了起点加长度，所以调用点直接写「要几个字节」。给长度 0 会得到空串，空串的 `size()` 是 0，0 又是那个在条件里为假的数。空串是一次成功的切片，不是失败。失败是起点越界，而越界在这份库里走异常。我们不把长度 0 当成错误，也不去触发越界。

中文的字节边界不能用眼睛对齐。`北畦` 六个字节，前三个是「北」，后三个是「畦」。从下标 1 取三个字节，会从前一个字的中间开始，切出的内容不是一个合法的汉字序列。终端可能显示替换符，也可能显示乱码，期望子串无法稳定写成一个汉字。所以切中文之前先按编码的宽度对齐起点。英文的 `buy pen` 每个字符一字节，对齐是自然的。两种文字放在同一个 `string` 类型里，类型不会提醒你当前的起点是不是字符边界。提醒只能写在测量记录的约定里：中文名字整段使用，或者只在已知的三字节边界上切。

向量要求元素类型在编译期固定，这是它和「什么都能装的列表」的差别。厘米和名字不能放进同一个 `vector<int>`。要成对存放，要么用两个向量按下标对齐，要么用下一章的类把一对收成一个元素类型。两个向量对齐的代价是你可能只给其中一个 `push_back`，下标就错位，北畦的名字配上了中畦的厘米。类把一次 `push_back` 变成同时放入一对，错位不再发生。类的代价是多一个类型。三条边还没到必须成对的程度时，分开的向量更直白；工单开始问「这条名字对应哪段厘米」时，类更不容易撒谎。

下标的类型是无符号的大小类型，和 `int` 的循环变量混在一起比较时，可能把负数提升成一个很大的无符号数。这一章的示例在放入之后直接用字面量下标 0 和 1，不拿一个可能为负的 `int` 去比 `size()`。若你以后写 `for` 循环，把下标也声明成与 `size()` 相同的无符号类型，或者先把 `size()` 取出来再保证循环从 0 向上走、并且上界就是那个大小。负数下标不是「从末尾数」的意思，那是别的语言的习惯。这里的负数下标在转换之后会落到很远的位置，读取是未定义行为。中畦只在下标 1，不在 -1。

再确认切片不会改原串。`note.substr(4, 3)` 得到新字符串 `pen`，`note` 仍是 `buy pen`，长度仍是 7。若后续待办要把整行放进第一格，应放入 `note` 本身，而不是放入切出来的 `pen`。`pen` 只是示范长度参数的产物。把产物当成原文，木牌就少了 `buy ` 这四个字节。四个字节里还有一个空格。空格也是原文。

## 小结

空向量经三次 `push_back` 变成 120、80、150，个数是 3，中畦在下标 1。次序跟插入次序走，容器不替你排序。增长可能搬家，所以不要握着元素引用跨越 `push_back`。

`substr(起点, 长度)` 从 `buy pen` 的下标 4 取出 `pen`。`北畦` 的 `size()` 是 6 个字节，不是两个字。起点必须落在已有的字节范围里，避免走到不可靠的异常路径。下一章把名字和厘米收进同一个对象，向量里装的就不再是裸的 `int`。

## 练习

在 120、80、150 之后再放入 100，打印向量的个数。应当只看到 4。不要打印容量，也不要排序。

::: answer 参考答案：第四条边
```cpp run expect="4" title="参考答案"
#include <iostream>
#include <vector>
int main() {
  std::vector<int> beds;
  beds.push_back(120);
  beds.push_back(80);
  beds.push_back(150);
  beds.push_back(100);
  std::cout << beds.size() << "\n";
  return 0;
}
```
:::

标签 `north-bed` 里，从下标 6 取 3 个字节。应当打印 `bed`。先数清楚连字符占一个字节，起点不是按单词算的。

::: answer 参考答案：切出 bed
```cpp run expect="bed" title="参考答案"
#include <iostream>
#include <string>
int main() {
  std::string label = "north-bed";
  std::cout << label.substr(6, 3) << "\n";
  return 0;
}
```
