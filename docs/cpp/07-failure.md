卡片已经能装下 120。它也装得下 0 和负数，因为 `int` 并不知道厘米必须为正。工单若把非正数当成一条边，后面的「不到一米」会把 0 当成假，把 -5 当成真。两种错误长得不一样，来源却相同：写入的时候没有拒绝。拒绝需要一条失败通道。

这一章的通道是返回值，不是异常。函数 `keep` 返回 `int`：1 表示把长度写进了输出参数，0 表示拒绝。输出参数是引用，必须在调用方先有一个对象，函数才能绑上它。这和引用的出生规则是同一条。失败时函数不去写那个对象。调用方手里可能还留着上一次的 42，42 不是这次测量。所以失败的分支只打印 `失败`，不去读引用里的旧值。成功的分支才打印写进去的厘米。

为什么不用异常？外面的 C++ 常常在「长度非法」时 `throw`。抛出之后，调用栈上的析构会在栈展开里运行，调用方用 `try` 接住。这份 wasm 工具链的异常不可靠，展开和捕获不能当成教学例子的地基。可运行程序若依赖 `throw`，你看到的可能是链接失败、中途退出，或根本不是你写的那句诊断。把 `throw` 放在不能运行的块里，是为了记住这种写法的形状，同时不让它参加运行。能事先判断的失败——参数是不是正数——用 `if` 就够了。不需要等到对象已经半构造好再抛出去。

返回 0 和 1 也有代价。0 在条件里为假，所以 `if (!keep(...))` 读起来像「没有留住」。这很顺手，也和「长度本身可以是 0」终于分开了：0 是状态，不是厘米。代价是调用方可能忘记检查，直接读输出参数。语言不会强迫你检查这个 `int`。忘记检查时，失败路径会把旧值当成新测量，退出码还是 0。`-Werror` 看不出这种逻辑错误。例子里把检查写在打印的正前方，让忘记检查的那种写法没有出现在可运行块里。

另一笔代价是每层调用都要把状态往上传。异常若可靠，深层的拒绝可以跳过中间层；返回值要求中间层要么处理，要么转交。菜地的调用只有一层，`main` 自己检查，转交还显不出来。层数变多时，返回值会让签名变长，这是诚实的代价，不是样板可以随便删掉的部分。

```cpp norun title="抛出不参加运行"
#include <iostream>
int main() {
  throw 0;
  std::cout << "不会到\n";
  return 0;
}
```

只读块里的 `throw 0` 表示「有人用一个整数当异常对象」。它不返回状态，也到不了后面的插入。可运行的三份程序都改用 `keep` 的返回值。不要把 `throw` 抄进它们。

第一份是成功。北畦 120 是正数，`keep` 把它写入 `out`，返回 1。`out` 事先被设成 42，成功路径会覆盖 42。打印出来的应当是 120，不是 42。若你看到 42，说明函数没有通过引用写入，或者你在成功之前就把旧值打印了。

```cpp run expect="120" title="正数被留下"
#include <iostream>
int keep(int value, int &out) {
  if (value <= 0) {
    return 0;
  }
  out = value;
  return 1;
}
int main() {
  int out = 42;
  if (!keep(120, out)) {
    std::cout << "失败\n";
  } else {
    std::cout << out << "\n";
  }
  return 0;
}
```

第二份把 0 送进去。0 不是正数，函数返回 0，并且不写 `out`。`out` 里仍然是 42。分支打印 `失败`。期望是这两个汉字，而不是 42，也不是 0。打印 0 会让人以为测量结果是零厘米；打印 42 会让人以为拒绝没有发生，旧的哨兵值混进了工单。失败的定义在这一章就是：调用方不消费输出参数。

```cpp run expect="失败" title="零被拒绝"
#include <iostream>
int keep(int value, int &out) {
  if (value <= 0) {
    return 0;
  }
  out = value;
  return 1;
}
int main() {
  int out = 42;
  if (!keep(0, out)) {
    std::cout << "失败\n";
  } else {
    std::cout << out << "\n";
  }
  return 0;
}
```

第三份送进 -3。负数和 0 走同一条拒绝，因为条件是 `<= 0`。若只写 `if (!value)`，-3 非零，会被当成成功写进卡片，然后在「不到一米」的判断里变成真。那是更难查的错：状态返回了 1，长度却是负的。比较运算符把符号也纳入拒绝。输出仍然是 `失败`。`out` 先放着南畦的 150，用来强调失败时连一个看起来很合法的旧值也不打印。150 若出现在终端里，就是读了不该读的输出参数。

```cpp run expect="失败" title="负数同样不写"
#include <iostream>
int keep(int value, int &out) {
  if (value <= 0) {
    return 0;
  }
  out = value;
  return 1;
}
int main() {
  int out = 150;
  if (!keep(-3, out)) {
    std::cout << "失败\n";
  } else {
    std::cout << out << "\n";
  }
  return 0;
}
```

三份程序的函数体相同，数据不同。重复是因为每个块单独编译，不能共享上一块的定义。阅读时把它们当成同一种约定的三次调用：120 被留下，0 被拒绝，-3 被拒绝。约定本身只有两条：返回值是状态，引用里的数只在状态为 1 时有效。

和上一章的 -1 哨兵比，输出参数把长度和状态拆开了。长度通道上可以出现任何写进去的正数，状态通道上只有 0 和 1。你不会再把 -1 误读成一条向西的差。代价是调用处变长，而且 1 和 0 没有类型上的名字。有人会定义枚举来给状态起名。枚举在这份方言里可用，但三行例子用裸的 0 和 1 更接近条件的真假，省一次类型介绍。枚举的好处是防止你把状态和厘米加在一起；裸 `int` 做不到。菜地的 `main` 没有把返回值和长度相加，这个风险先留在口头上。

`string` 的 `substr` 在起点越界时会抛异常，`vector::at` 在下标越界时也会抛。可运行代码继续避开它们：下标用 `size()` 守住，再用 `operator[]`。这一章的失败都是我们自己能先判断的那种，判断完就返回 0。标准库里那些会抛的接口，不拿来当失败通道的示范。

状态码的取值要少，少到调用方记得住。这里只有 1 和 0。若再加一个 2 表示「太长，超出篱笆库存」，调用方的 `if` 就不够，必须分支成三段。三段不是不能写，而是每加一种失败，所有调用点都要意识到新的数字。菜地目前只拒绝非正数，一种失败就够。真出现「太长」，可以仍返回 0，另用一个输出参数写明原因；那会把接口再加宽。加宽之前先问这种区分会不会改变调用方的动作。若两种失败都是「不要写入、打印拒绝」，就不要分成两个码。

输出参数在失败时保持原值，这个约定必须写进函数的说明里，因为类型系统看不见。有的接口习惯在失败时把输出写成 0，让旧值消失。那样做的好处是调用方即使误读，读到的也是一个明显的空数，而不是上一轮的 42。坏处是 0 又回到了长度通道，和「0 厘米」分不清，也和状态码的 0 分不清。我们选择不写，把误读的后果留得更刺眼：你可能打印出 42 这种根本不在地里的数，从而发现自己忘记了检查。刺眼比沉默地变成 0 更容易在示例里被期望子串抓住。期望写的是 `失败`，42 一出现就对不上。

引用参数不能用来表示「可以不提供的输出」。调用方必须有一个 `int`。若某条路径根本不需要接收长度，你仍得准备一个变量，失败时不去读它。这看起来浪费，换来的是函数签名里没有空指针。空指针能表示「我不接收」，也能表示「我忘了接收」，两种意思在调用点长得一样。引用把忘了接收变成编译错误：你不写这个参数，调用就过不了。忘了检查返回值仍然是运行时的逻辑错误，编译器不管。能让编译器管的那一半，已经用引用管了。

异常若在可靠的工具链上，会把「忘记检查」变成「没人接住就终止」。终止比悄悄用 42 更安全，也更吵。这份 wasm 不把终止和栈展开当成可依赖的行为，所以安全的那一半我们用肉眼检查来换。检查就写在调用的下一行，不隔着别的逻辑。隔得越远，42 越有机会被别人当成测量。示例把 `if` 直接套在 `keep` 外面，就是把距离缩到最短。

`throw 0` 那个不能运行的块还说明一件事：异常对象可以是一个整数，不一定是某个异常类。语言允许，教学上却更容易和状态码混淆。看见 `throw 0` 的人可能以为这就是「返回 0」。它不是返回。它离开函数的方式和 `return 0` 不同，调用方的下一个语句不会执行，除非有人接住。接住的语法这一章不写进可运行代码，因为接住本身依赖那套不可靠的机制。记住形状即可：可运行的失败是 `return 0`，不可运行的对照才是 `throw`。

最后把「先判断、再写入」放进类的未来。私有的 `length` 配一个 `keep` 这样的成员函数，外界就无法直接赋 0。成员函数返回状态，成功才改成员。这比公开成员多一层缩进，少一类「卡片上出现负数」的状态。这一章先把函数写成自由函数，是为了让参数和返回值都露在外面，不被类的语法挡住。类的封装是下一步的收紧，不是失败通道的替代品。通道仍然是返回值。

返回 1 表示成功，是为了让它在条件里为真。有人习惯返回 0 表示成功，和进程退出码对齐。那种对齐会让 `if (keep(...))` 的意思整个反转：真分支变成失败。同一份源码里，进程的 `return 0` 仍表示进程成功，函数的 `return 0` 若表示函数成功，阅读时必须看清你站在哪一层。这一章故意让函数的 0 表示失败，让 `if (!keep(...))` 读成「没有留住」，和整数为假的规则同向。进程末尾仍 `return 0`，因为进程完成了「把失败打印出来」这件事，进程本身不是失败。两层退出码不要合成一个习惯。

输出参数的初值 42 或 150 是哨兵，用来抓住误读。哨兵不该是一个可能的合法测量。120、80、150 都可能合法，所以哨兵避开了它们。42 不在这组边长里，150 在第三份里被当作旧值，期望却是汉字 `失败`，因此 150 即使合法也不会被这道期望放过。练习把初值设成 7 和 80，同样要求成功时看见新值、失败时看见汉字。汉字和数字的差别让子串不会误伤。

## 小结

`keep` 遇到正数返回 1 并写入引用，遇到 0 和负数返回 0 且不写入。调用方只在返回 1 时打印那块 `int`，失败时打印 `失败`，不去读事先放着的 42 或 150。0 作为状态为假，和「厘米可以是 0」不再共用一个通道。

`throw` 只留在不能运行的块里。下一章写一个比较函数模板，让整数和字符串共用一份「谁更小」的函数体。比较假定两个值都已经合法，失败仍在进入比较之前用返回值处理，而不是在模板里抛出去。
