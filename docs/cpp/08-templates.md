`longer` 和 `shorter` 已经能比较两个 `int`。字条之间也需要「谁更小」：`mid` 和 `north` 按字典序谁在前。若把函数体复制一份，把 `int` 改成 `std::string`，两份函数会一起漂移。某一天整数那份把相等时的选择改了，字符串那份忘了改，工单上的「较小」就不再是同一种规则。函数模板把类型留成参数，函数体只写一次。

`template <typename T>` 后面的 `smaller` 还不是一份具体的函数。它是一份配方。调用 `smaller(150, 80)` 时，编译器从两个 `int` 推出 `T` 是 `int`，按配方生成一份只接受 `int` 的函数。调用两个 `std::string` 时，再生成另一份。生成发生在编译期，发生在这个翻译单元里。没有第二份源文件可以把配方藏进去再链接。配方必须写在调用点看得见的地方，所以它放在 `main` 上面。

参数写成 `const T &`。引用在参数初始化时绑到调用方的对象上，`const` 答应函数不通过这层绑定去改厘米或改字条。返回则按值，把较小的那个拷出来。对 `int` 拷贝很便宜。对 `string` 会拷贝字符。菜地的标签很短，拷贝可以接受。返回引用会省下拷贝，但要求返回的对象活得比函数调用更久；两个参数都是引用，返回其中某一个的引用在这个函数里是安全的，因为它们绑的是调用方的对象。我们仍返回值，让调用方拿到一份自己的副本，不把寿命问题再叠进这一章。

第一份程序只生成整数版本。150 和 80 里较小的是 80。相等时 `a < b` 为假，函数返回 `b`。两条边不相等，这条路径只是为了让每个分支都有返回值。

```cpp run expect="80" title="较短的厘米"
#include <iostream>
template <typename T>
T smaller(const T &a, const T &b) {
  if (a < b) {
    return a;
  }
  return b;
}
int main() {
  std::cout << smaller(150, 80) << "\n";
  return 0;
}
```

第二份程序把同一份配方用在字符串上。`mid` 和 `north` 的第一个字母分别是 `m` 和 `n`，`m` 在前，所以较小的是 `mid`。两个参数类型必须相同，配方才能推出唯一的 `T`。一个 `int` 和一个 `string` 放进同一次调用，没有一种 `T` 同时满足两边，编译会停。那是类型系统在替你拒绝「厘米和单词比大小」。重载可以给这种混合单独写一份函数，模板不会猜测你想先把整数格式化成文字。

```cpp run expect="mid" title="字典序里更小的标签"
#include <iostream>
#include <string>
template <typename T>
T smaller(const T &a, const T &b) {
  if (a < b) {
    return a;
  }
  return b;
}
int main() {
  std::string left = "mid";
  std::string right = "north";
  std::cout << smaller(left, right) << "\n";
  return 0;
}
```

第三份程序让字典序和「谁更短」分家。`z` 只有一个字节，`apple` 有五个。按长度，`z` 更短。按 `<`，`apple` 更小，因为 `a` 在 `z` 前面。模板生成的函数只会用 `<`，它不知道长度。输出是 `apple`。若期望写成更短的那个，你是在用另一套比较，而配方里没有那套比较。这是模板的代价：一份函数体把一种意思固定下来，类型可以换，意思不能在生成时偷偷换成「按字节数」。真要按字节数比字条，应当写一个普通函数去调用 `size()`，或者在算法那一章用谓词。不要改这个模板去特化成两种意思，否则调用点的 `smaller` 又变成需要翻实现才能懂的名字。

```cpp run expect="apple" title="较小不是更短"
#include <iostream>
#include <string>
template <typename T>
T smaller(const T &a, const T &b) {
  if (a < b) {
    return a;
  }
  return b;
}
int main() {
  std::string left = "z";
  std::string right = "apple";
  std::cout << smaller(left, right) << "\n";
  return 0;
}
```

和重载比，模板少写一份函数体，多了一层「`T` 必须支持 `<`」的约束。约束在这份方言里不是用概念写出来的，调用到不支持 `<` 的类型时，错误出现在模板实例化的那一行，诊断往往指向函数体内部，而不是指向你的调用。读诊断时先看是哪一次调用推出的 `T`，再看 `<` 为什么不存在。重载的诊断通常更靠近调用点，因为候选函数就写在那里。菜地的类型只有 `int` 和 `string`，两者都有 `<`，诊断不会在示例里出现。这个优点是换来的：你放弃了「每种类型一份手写函数、错误停在调用旁边」的直白。

宏也能把类型擦掉，但宏在编译之前替换文本，没有参数的类型检查，也没有作用域。一个叫 `smaller` 的宏会碰到任何同名标识符。模板只在实例化时生成函数，名字遵循普通的作用域。这个抽屉不用宏来做比较。

失败通道不放进模板。`smaller` 假定两个值都已经合法。0 若作为厘米走进来，它会参与 `<`，可能成为「较小」的结果，那是一个真实的数，不是拒绝。拒绝仍用上一章的 `keep`：非正数根本不要进入比较。模板里若 `throw`，就又把不可靠的异常当成了控制流。可运行的三份程序都只返回较小值。

同一份源文件里可以既有模板，又有一个专门的 `smaller(int, int)` 重载。决议会优先考虑非模板的精确匹配。我们不写那份额外的重载，免得读者不确定生成的是哪一份。一个名字，一种意思，类型由调用推导。

推导只看调用的参数，不看你希望返回什么。`smaller(150, 80)` 两边都是 `int`，`T` 就是 `int`。你不能指望编译器从「我把结果赋给 `std::string`」倒推出 `T`。返回类型出现在参数的后面，推导发生时还没看赋值的左边。若两边参数类型不一致，又没有你手写的转换，推导失败，错误停在调用点。这比生成一份奇怪的函数再在函数体里失败要接近你写下的那一行。仍有一些错误会进到函数体，例如 `T` 没有 `<`。那时诊断会提到实例化的深度。先找到是哪一个调用引起的，再读运算符。

同一份配方生成的两份函数是不同的函数。整数那份不会因为你后来调用了字符串就改变行为。它们共享源码，不共享运行时的状态。模板里若放一个函数内部的静态计数器，每一份生成的函数有自己的计数，而不是所有类型共用一个。菜地的 `smaller` 没有计数器。需要「一共比较了几次」这种跨类型的统计时，不要把计数放进模板的静态变量里，那会按类型拆开，和你的直觉相反。统计放在调用方，调用方看得见每一次调用。

const 引用参数还防止了一类手滑：函数体里写 `a = b` 会编译失败，因为 `a` 是 const。比较函数不该交换或覆盖两条边。若比较需要草稿，先按值取到局部变量再改局部变量。返回值已经是按值的副本，调用方拿到的较小值和原来的两条边是三份存储，改返回值不会改北畦。这和引用参数「改的就是原件」相反。参数用引用是为了少拷贝、并且只读；返回用值是为了把结果交出去、并且和原件脱钩。两个方向的选择可以同时出现在一个函数里。

模板和重载可以共存，但共存时要知道非模板函数在精确匹配时更优先。若你留下一份手写的 `smaller(int, int)`，整数调用不会再走到模板。手写的那份若忘了处理相等，整数的行为就和字符串分家，而调用点看起来仍是同一个名字。这正是模板想避免的漂移。所以这一章不留手写的那份。名字下面只有配方。需要不同意思时，换名字，例如 `shorter_text` 按字节数而不是按字典序。

宏做不到这个优先规则，也做不到作用域。模板的实例化发生在编译期，错误的类型不会拖到运行才在比较里崩溃。崩溃式的比较通常来自你自己写下的错误运算符，那仍是编译期的事，只要类型根本没有 `<`。有 `<` 但意思不对，例如字符串的字典序被你当成了长度，编译期帮不上忙，因为类型上的 `<` 是合法的。第三份程序的 `apple` 就是这种合法而不符合工单的结果。工单若要更短的字条，不要调用 `smaller`。函数名会撒谎，类型系统不会拦。

把失败放在模板外面还有一个编译期的理由。模板生成的代码里若包含 `throw`，每一份实例都带着那条不可靠的路径。生成的份数随调用的类型增加。把拒绝留在 `keep` 这种普通函数里，异常路径不会被复制进每个类型的比较。可运行的比较函数因此只有一条直线：看 `<`，返回较小的那个。直线短，才放心得进下一章去调用标准库里同样短的算法。那些算法内部也是模板，它们同样假定元素已经能比较，而不负责替你拒绝负数。负数若混进向量，`min_element` 会诚实地把它当成最小的厘米。诚实在这里是危险的。进入算法之前先过滤，过滤用返回值。

配方写在头文件里才是多文件工程的常态，因为实例化发生在调用的翻译单元，调用方必须看见身体。这个抽屉只有一个文件，身体放在 `main` 上面就已经看见了。不要把模板的身体藏进一个不会被包含的注释里，也不要假设链接器会从别处找来一份 `smaller<int>`。没有第二份目标文件。若实例化没有在这个文件里发生，链接时就会缺少符号。我们的三次调用都在同一个 `main` 里，整数一份、字符串两份，三份都会生成。第三份和第二次都是字符串，它们共用同一份生成结果，不会因为字面量不同就再生成一版。生成看类型，不看值。`apple` 和 `mid` 走同一份字符串比较。

返回按值时，字符串的副本在返回之后属于调用方的临时对象，再被 `<<` 使用。临时对象活到这条语句结束，足够打印。不要把返回值绑到一条生命周期更长的引用上再在后面使用，除非那是 const 引用并且你清楚临时量被延长到引用的寿命。这一章直接插入，不延长。插入结束，副本就可以销毁。北畦的原字符串不受影响。

## 小结

`smaller` 的函数体只写一次，`T` 在调用时从参数推出来。150 和 80 得到 80，`mid` 和 `north` 得到 `mid`。参数是 const 引用，在初始化时绑上，函数不改调用方的对象。

`<` 对字符串是字典序。`apple` 比 `z` 小，尽管它更长。按字节数比较是另一种意思，不塞进这个模板。下一章不再自己写循环去找最小的厘米，而向标准库要 `min_element`、`count` 和 `count_if`。仍然不排序。

## 练习

写一个模板 `larger`，返回两个值里较大的那个。用 80 和 150 调用，应当打印 150。相等时返回后一个参数，两条路径都要有返回。

::: answer 参考答案：较大的厘米
```cpp run expect="150" title="参考答案"
#include <iostream>
template <typename T>
T larger(const T &a, const T &b) {
  if (a > b) {
    return a;
  }
  return b;
}
int main() {
  std::cout << larger(80, 150) << "\n";
  return 0;
}
```
:::
