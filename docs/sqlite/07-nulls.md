前面的三本书每一本都有册数。店里还会有一本样书，书名已经进了目录，册数还没人填。这个「还没填」不是 0。0 表示我们数过，一本不剩。没填表示我们还没数。把两者写成同一个数，盘点会在开口之前就结束。SQL 用 NULL 表示没填。它不是一个值，是这个格子里没有值的标记。正因为不是值，它和任何值的比较都得不到真，包括和另一个 NULL 比较。

先把比较本身放在桌面上，不需要表。NULL = NULL 的结果不是真，也不是假，这个结果仍是 NULL。你问「这个结果是不是 NULL」，得到 1。两个连续的判断看起来像绕口令，其实是唯一能把这件事说清楚的办法：等号没有成立，所以你不能用等号去找空；判断结果本身是空，所以打印等号的结果时你看见的是空白，空白又像没有输出。IS NULL 把未知变成一个可以核对的 1。

```sql run expect="1" title="空等于空并不成立"
SELECT (NULL = NULL) IS NULL;
```

有人写成 WHERE NULL = NULL，指望选出「两边都未知」的行。选不出来。未知不被 WHERE 收留。也有人写成某个列等于 NULL，同样选不出来。下面用存货证明这件事。样书的册数插入 NULL，另外三本照旧是 3、1、2。条件写成 copies = NULL，计数是 0。条件写成 copies IS NULL，计数是 1，那一本就是样书。两个计数并排，期望是 0|1。

```sql run expect="0|1" title="等号找不到样书"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2),
  ('样书', NULL);
SELECT
  (SELECT COUNT(*) FROM books WHERE copies = NULL)
  || '|' ||
  (SELECT COUNT(*) FROM books WHERE copies IS NULL);
```

0|1 是这一章的门。左边的 0 会骗过所有觉得「空当然等于空」的人。他们的查询不报错，只是永远少一行，少的那一行又恰好是数据有问题的那一行，于是脏数据在最需要被看见的时候隐形。右边的 1 才是「把缺失当成缺失来找」。IS NOT NULL 则是反过来，留下三本已经填了册数的书。

计数从这里开始分家。四行都在，COUNT(*) 是 4，它数行，不看格子里有没有册数。COUNT(copies) 是 3，它数这一列上非空的格子，样书不计入。两个函数的名字都叫计数，中间那个星号和列名的差别比一个符号能表达的更大。星号是「有这一行吗」，列名是「这一行在这列上有值吗」。盘点种数时，样书已经是一种书，用星号。盘点「有册数记录的种数」时，用列名。用错一个，样书要么被当成已经有库存，要么被当成店里没有这本书。

```sql run expect="4|3" title="行数和有册数的行"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2),
  ('样书', NULL);
SELECT COUNT(*), COUNT(copies) FROM books;
```

总和更滑。SUM 跳过 NULL，不把样书当成 0 册加进去，所以四行的册数和仍是 6，和没有样书时一样。这会让人放心，也会让人麻痹。放心的是：未知没有污染已经知道的 6 册。麻痹的是：你看总和完全正常，就以为表里没有缺口。缺口在计数的分家那里，不在总和里。平均同样跳过 NULL。四行的平均仍是 2，不是 6 除以 4。若你认为样书应当按 0 册参加平均，要把空先换成 0，再平均。换还是不换，是店规，不是函数的默认。默认是「未知不参加运算」。

空范围上的总和连「跳过一些空、留下一些数」的机会都没有。问一本店里不存在的书，例如书名是「没有这本书」，WHERE 留下零行。零行上的 SUM 不是 0。0 表示加过，加数都是零或者正负抵消。这里没有加数。结果是 NULL。用 IS NULL 把它打成 1，免得空白再次假装成没运行。

```sql run expect="1" title="没有行可加，和就不是零"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2),
  ('样书', NULL);
SELECT SUM(copies) IS NULL
FROM books
WHERE title = '没有这本书';
```

COALESCE 用来在你做出店规之后落地。它从左往右取第一个不是 NULL 的参数。把空的总和换成 0，写成 COALESCE(SUM(copies), 0)，空范围就会显示 0。这个 0 是你说「没有就当零」之后的 0，不是引擎自己的判断。我喜欢把 COALESCE 放在最外层的展示上，而不是放在每一行的册数上到处替换。到处替换会把「没填」提前抹掉，后面的 COUNT(copies) 就再也看不见缺口。先让缺口存在，再在某一份给店长看的查询里决定用什么数字顶上。

拼接也会被空传染。书名 || 一个 NULL 的备注，整段变成 NULL，不是书名后面多一个空白。你想要「没有备注就什么都不加」，得先把备注换成空字符串。空字符串是值，它等于另一个空字符串，长度是 0，和 NULL 完全不是一类东西。样书的册数不要插成空字符串来冒充未知。空字符串进了整数亲和的列，可能留下文本或者变成 0，两条路都比直接写 NULL 更难解释。未知就写 NULL。

NOT NULL 约束把「可以不填」这扇门在写入时关上。copies INTEGER NOT NULL 之后，再插入样书那种不带册数的行，语句失败，退出码不是 0。已经在表里的三本书不受影响，失败的是这一条插入。主键顺便也不允许重复，重复的书名或重复的身份会同样失败。可运行的脚本不演示失败。你需要的是失败时长什么样的一句心里有数：约束的名字会出现，books.copies 这种列名会出现，后面的查询可能没跑到。调试时先看是哪一条插入被拒，不要去改已经正确的 SELECT。

若缺失是合法的，就不要加 NOT NULL，然后在查询里用 IS NULL 把它们找出来，当成一份待补的清单。样书就该出现在那份清单上。把它挡在门外，只说明你的店规不允许未填册数的行存在，不说明 NULL 从这个世界消失了。连接配不上时，右表的列仍会是 NULL，那是读出来的缺失，不是插入时写进去的缺失。两种来源，同一种比较规则。你在这一章学会的等号失灵，在左连接的河岸身上同样失灵。

三值逻辑还影响 OR 和 AND。真 OR 未知，结果是真，因为已经有一边确定成立。假 AND 未知，结果是假，因为已经有一边确定不成立。未知 AND 未知，仍是未知。WHERE 只收留真。所以一个由未知参与的条件，可能因为另一边已经为假而被丢掉，也可能因为另一边已经为真而被留下，剩下的情况才是神秘的消失。三本书加一本样书，足够你把这些组合写成查询来试。试的时候把结果收成计数，不要凭空白终端下结论。

排序时 NULL 的位置也由此而来，不过那一章再细说。这里先给一个预感：既然空不是值，它就没有和 1、2、3 同一种大小。引擎仍得给它一个位置才能排序，SQLite 把空放在比任何值都小的那一头。升序时样书会排在河岸前面。这不是「样书的册数是负数」，是「缺失被安排在序列的一端」。安排是实现给出的规则，你的报表若需要「缺失放在最后」，要明确写，不要赌默认。

未知会沿着运算传播，这是它和 0 最实用的差别。0 加 3 得到 3。空加 3 得到空。样书的册数若参加「再进一册」这种加法，结果仍是未知，不会变成 1。你无法靠算术把缺失修成一个数。修要么是一次真正写下册数的更新，要么是展示时的替换。更新表示盘点发生了，替换表示这一格给店长看时暂时用某个数顶上。混成同一步，你会以为样书已经被数过，表里却仍然是空。COUNT(copies) 还会继续少它，你对着已经替换过的报表却看不见这个少。

不等于也救不出样书。册数不等于 3，不会把空选出来。你想要「除了夜航以外的每一本」，样书会失踪，尽管它的书名分明不是夜航。书名不等于夜航，才能把样书留下，因为书名那一列是有值的。只在册数上写不等于，等于假设每一行都有册数。假设在前三本上成立，在样书上不成立。成立过的假设是最难被重新检查的，因为旧查询在旧数据上一直是对的。

全表求和时，样书不把 6 拖成空，因为还有三个真正的数。报表因此看起来健康。健康旁边应当能算出星号计数与列计数的差，差是 1，就是还没填的那本。差为 0 才表示没有缺口。只刊登 6，缺口是隐形的。空值这一章把 4 和 3 并排摆出来，就是为了让这个差有地方可算，而不是为了多记两个函数的名字。

逻辑值在这里也不是一种真正的类型。比较得到的未知，打印出来像空白，你无法把它存成一种叫做布尔的列再读回来还叫布尔。需要保存「我们还没数」时，就保存 NULL，不要保存一个哨兵数字，例如用 -1 代表未填。哨兵会参加求和，全店的册数会少一，而且 -1 在没有检查约束时是合法整数。NULL 不参加求和，这正是它适合当「未填」的原因，也是它不适合当「零册」的原因。两种业务不要抢同一个表示。

多个参数的替换从左到右取第一个已经知道的值。样书的册数未知时，可以先看备注里有没有人手写的数字，没有再用 0。这是一条店规链条，不是数据本身的层次。链条写在查询里，表里的未知就还在，下一次换店规不必改历史。把链条写进更新，未知就永久变成了链条当时的选择。永久的选择要配得上一次真正的盘点，不配得上「报表今天想显示 0」。

外连接制造的未知和插入的未知，在 IS NULL 面前一样。河岸没有借出时，借阅人是未知；样书没有册数时，册数是未知。找出它们的句子是同一种句子。差别只在未知的来源要不要修。样书的册数也许明天就填上，用更新。河岸的借阅人也许永远不该填，因为没有人借，修它反而是造假。看见未知先问来源，再决定是填、是留，还是在这一份展示里替换。来源不同，手就不同。

## 小结

NULL 不是 0，也不是空字符串。NULL = NULL 不是真，结果仍是 NULL，所以 WHERE 里的等号找不到样书，IS NULL 才找得到。COUNT(*) 把样书算进行数，得到 4；COUNT(copies) 不算空格子，得到 3。SUM 跳过样书，三本的 6 册还在；可是一个书名谁都不匹配的空范围，SUM 本身是 NULL，不是 0。

0 是你用 COALESCE 做出的店规，或者是数过之后的结果。约束可以把不允许的缺失挡在写入时，连接仍会在读的时候制造新的缺失。下一章让查询的结果去喂给另一条查询：平均册数不再手写，而是从这批书里算出来，再用来决定谁留在柜台上。
