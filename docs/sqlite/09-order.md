前面好几次查询都带了排序，我当时说它是脚手架。现在把脚手架换成合同。没有 ORDER BY 的结果，顺序是存储的事故：今天可能按插入先后出来，因为这张小表的扫描刚好那样走，明天加了索引、做了删除再插入、换了一点数据，顺序就可以换。事故若连续多次看起来一样，会被人抄进界面，变成「默认按入库时间排」。入库时间根本不在表里。你看见的只是行被写下时的痕迹。痕迹不是承诺。要承诺，就写下按哪一列、朝哪个方向。

三本书仍是夜航 3、河岸 1、旧书店 2。按册数从少到多，应当是河岸、旧书店、夜航。查询把三行都打出来，期望抓住中间那一本的书名和册数，旧书店|2。抓住中间，是为了证明不是只排对了第一行。只看第一行，你会在升序和「碰巧河岸插在最前」之间分不清。

```sql run expect="旧书店|2" title="册数从少到多"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title, copies
FROM books
ORDER BY copies ASC, title ASC;
```

第二排序键是书名。现在三本的册数都不一样，第二个键不改变结果。它仍然要写。合同是写给将来的并列的。假如盘点之后旧书店也变成 1 册，和河岸并列，只按册数排序再 LIMIT 1，引擎可以交出海岸，也可以交出旧书店，两次运行都合法。界面上的「册数最少的一本」就会跳。加上书名，并列时按书名的码点再比一次，胜者唯一。码点顺序不是拼音顺序，也不是笔画顺序。旧和河哪个在前，由字符的编码决定，不一定符合你的书架审美。审美若重要，就加一列专门的陈列序号，按那一列排，不要指望中文在默认对照里走出你想要的字典序。

降序把夜航放在第一。LIMIT 1 切下这一行。没有排序的 LIMIT 1 是抽一行，有排序的 LIMIT 1 才是「册数最多的一本」。最多若并列，仍要第二键，否则「一本」没有定义。下面这份册数没有并列，夜航是唯一的 3，期望写夜航|3。

```sql run expect="夜航|3" title="最多的一本"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title, copies
FROM books
ORDER BY copies DESC, title ASC
LIMIT 1;
```

LIMIT 写在 ORDER BY 后面，这个书写顺序和执行时你该有的心理顺序一致：先排成一列，再切。优化器也许能少排一些，那是它的自由，语义上仍然是排好再切。不要为了想象中的速度而拿掉排序，换来一个不稳定的「第一名」。三行的表没有速度问题。有速度问题的表，正确的做法是给排序的列准备索引，而不是把合同撕掉。

OFFSET 跳过排好之后的前若干行。从少到多跳过 1 行，再取 2 行，得到旧书店和夜航。期望仍钉住旧书店|2，让你看见跳过的是河岸而不是随便跳过谁。OFFSET 的代价在三行上看不见：被跳过的行通常仍要排完，才能知道谁是第几名。页码越深，跳过的越多，每一页都从第一名重新排起。小店的存货清单不必为这件事焦虑。你要知道分页不是一个免费的窗口函数，它是「扔掉前面的名次」。真的要稳定的翻页，以后会用「上一页最后一个键」来写条件，而不是用越来越大的 OFFSET。那是这一章不必写出的下一层，点到为止，免得你以为 OFFSET 是唯一的翻页工具，又免得你在三行上提前写一套键集分页。

```sql run expect="旧书店|2" title="跳过最少的那本"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title, copies
FROM books
ORDER BY copies ASC, title ASC
LIMIT 2 OFFSET 1;
```

NULL 在排序里有一个固定的、但不符合「未知不该有大小」这种洁癖的位置。SQLite 把空当成比任何值都小。升序时，册数为空的样书排在河岸前面；降序时，样书排在最后。这不是样书的册数为负，是缺失被安置在序列的一端。若你的清单希望「没填的放到最后，不管升序降序」，要在 ORDER BY 里写明，例如用一个表达式把空映射成降序时的一端。不写，就接受默认：升序，空在最前。默认让「第一名」可能变成一本还没盘点的样书。LIMIT 1 会把它切下来，界面宣布最少库存是空白。空白不是最少，是你没写第二套规则。

和分组连在一起时，排序的对象是组，不是原始的行。按架子求和之后，ORDER BY SUM(copies) 排的是架子。没有这句，甲和乙谁在前又是事故。分组那一章我用架子名字排序，是为了稳定，不是因为名字比册数更重要。重要的是你点名了某一列。LIMIT 作用在组的结果上，同样要先有顺序，才能说「和最大的那个架子」。

DISTINCT 也会受到顺序的影响：先去重还是先排序，结果的集合一样，取出前几名时不一样。需要「不同的册数里最小的两个」，先想清楚集合，再想清楚顺序，最后才切。顺序写在错误的层次上，LIMIT 会切到你没打算给它的那一层。

最后说一种不该用排序去冒充的计算。找最大册数，MIN 和 MAX 已经能回答数。只有在你需要「那一行的书名」时，才有理由排序再切，或者用上一章等于最大值的子查询。子查询在并列时会交出每一本并列的书，排序加 LIMIT 1 只会交出一本。两种都诚实，回答的是不同的问题：「有哪些书并列第一」和「请给一本第一，并列时按书名决胜」。店长要哪一种，句子里就写哪一种。不要用 LIMIT 1 的结果去声称没有并列。

第二排序键我写得很固执，是因为 LIMIT 会把不稳定放大成可见的跳变。没有切片时，两行并列只是互换位置，眼睛还能看见两本都在。加上只取一行，互换就变成这一本消失、那一本出现。消失最像删除，于是你会去翻有没有人写过 DELETE，其实没有人删，只是决胜的键没写。旧书店和河岸一旦册数相同，按书名再比至少稳定。稳定用的是编码顺序，不是拼音，也不是你希望的书架审美。审美若重要，加一列陈列序号，按那一列排。陈列序号是业务，改它可以改变展示，而不必假装册数变了。

按表达式排序时，别把已经拼好的展示句子拿来排。整数 10 和 3，按数排是 3 在前；拼成文本之后，字符 1 会排在字符 3 前面，十册反而冒到三册之上。这一章直接排册数那一列，就是为了躲开字典序。展示用的「册」字留在另一层，不要回流进排序键。排序键应当是你真的想比的那个量。

跳过行数的翻页还有一个业务上的洞。有人在你看着后面几名时插入了一本册数更少的书，名次全体后移，下一页可能重复看见上一页的最后一本，或者漏掉刚好被挤走的那本。用「册数大于上一页最后一本」来续，插入的影响就局限在新书该出现的位置。三行的清单看不出这个洞。看不出的时候先把合同写对，不要把跳过行数抄进一个会同时进货的系统，还以为自己只是在用这一章的语法。

和分组一起排序时，按总和排，排的是定义良好的数。按组里随便捡来的书名排，顺序会跟着那个没承诺的值抖动。抖动像数据坏了，其实是排序键本身没有定义。没有定义的键，再稳定的引擎也只能给你一个偶然的稳定。偶然稳定是测试的敌人：测试一直绿，直到某一天扫描顺序变了。

方向要写出来。升序是默认，不写 ASC 结果一样。我仍写上，因为降序必须写，一行里若有的列升、有的列降，省略会让人猜哪一列用了默认。猜在两列时还有可能猜对，三列时就该把每列的方向都变成字面。册数降序、书名升序，是「先比谁更多，同样多再按名字」。反过来写，就变成先按名字分组再比册数，夜航会因为它的码点而移动，不再稳坐最多的那一把交椅。列的先后就是比较的先后。这和 WHERE 里条件的先后不一样，过滤的 AND 不在乎书写顺序，排序的键在乎。

只取前两名时，把 LIMIT 放在语句末尾，不要试图用 WHERE 写「册数排进前二」。册数本身不知道自己的名次。名次是排序之后才有的。用子查询先找出第二名的册数，再过滤大于等于它的行，能在并列时把所有并列都留下，这和 LIMIT 2 不同。LIMIT 2 在旧书店和另一本同样是 2 册时，仍只给两行，可能切掉同样有资格的第三本。你要「前两名的名额」还是「达到第二名成绩的所有书」，是两个句子。三本书目前成绩都不同，两个句子碰巧选出同一批，不要用碰巧来合并它们的含义。

空册数的样书若混进升序，会占据第一名。界面若写着库存最少，样书会获胜，尽管它还没被数过。把样书赶去队尾，可以在排序键里用一个表达式：有册数的在前，缺失的在后，然后才比册数。表达式比修饰语更不依赖版本是否认识某两个英文单词。默认行为已经稳定，不符合店规就改键。改键之后，期望也要跟着改，因为第一名真的换人了。不要只改句子、留下旧的期望，那会训练你把失败当成显示问题。

页的大小是 LIMIT 的数，不是数据里的属性。每页两本，三本书就有一个只剩一本的尾页。尾页不是错误。用 OFFSET 去取尾页时，跳过的行数必须和前面各页的大小一致，否则会重复或开天窗。这种算术放在查询外也行，放进脚本里就要用你自己算得清的常数。三本书、跳过两本、留下一本，常数是 2 和 1。常数来自你对页的定义，不是来自册数那一列。册数负责名次，页的大小负责切多厚。两件事都写清楚，清单才不会在某一页上厚薄无常。

## 小结

顺序只有写进 ORDER BY 才是合同。夜航、河岸、旧书店按册数从少到多，中间是旧书店的 2 册。LIMIT 在这份合同上切片，才能说自己取到了最多的一本；OFFSET 跳过的也是名次，不是碰巧被扫描器先看见的行。

并列时第二键决定胜者。中文的默认顺序是编码顺序，不是拼音。空值在升序里比任何册数都靠前，第一名可能因此变成还没盘点的样书。下一章不再排这些行，而是让若干写入共享命运：要么一起留下，要么一起撤销，并且用查询把撤销之后的空证明出来。

## 练习

按册数从多到少取出第一本的书名。应当是夜航。排序和 LIMIT 都要在，缺了排序，这个练习就只是在抽一行。

::: answer 降序的第一名
```sql run expect="夜航" title="合同上的第一"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title
FROM books
ORDER BY copies DESC, title ASC
LIMIT 1;
```
:::

从少到多跳过两行，只留最后一本的册数。跳过河岸和旧书店之后，应当剩下夜航的 3。OFFSET 是 2，LIMIT 是 1。

::: answer 排到最后的册数
```sql run expect="3" title="跳过两名"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT copies
FROM books
ORDER BY copies ASC, title ASC
LIMIT 1 OFFSET 2;
```
:::
