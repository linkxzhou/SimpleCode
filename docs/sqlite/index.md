很多人学 SQL 时手里已经有一台不会关机的数据库。表是昨天建的，行是同事插进去的，查询像在翻一本一直摊开的账。这个抽屉不是那样。点 Run，SQLite 以批处理打开一份只活在内存里的库，读完你这份脚本，进程结束，内存交还。没有服务器地址，没有上次留下的磁盘文件，也没有「连接还在所以表还在」这回事。后面每一章的建表语句都要再写一遍，不是我舍不得省略，是因为上一份脚本里的夜航、河岸、旧书店已经随那次进程一起没了。

空是教学条件，也是这门课最值得留下来的脾气。脚本必须自己把舞台搭好：要用的表在同一份里建出来，要给人看的结果用 SELECT 打出来。插入成功时，批处理往往一声不吭，终端是空白。空白不是失败，是这种工具对「没有结果集的语句」的沉默。你如果只写了建表和插入，退出码可以是 0，屏幕上却没有任何格子，于是你开始怀疑按钮没点到。核对库存、册数、余额，一律写成查询。比对时期望抓的是结果单元格里的文字，是整段输出当中的一段子串，不是图形工具里画出来的表头。多出来的列只要不把你要的那段切碎，子串就还在；缺了那段，退出码就算是 0 也仍然是错的。

默认的列表模式把同一行的若干列用竖线拼起来。夜航有 3 册，打出来是夜航|3。竖线不是数据的一部分，是显示时的分隔。所以期望写成夜航|3，而不是带框的表格，也不依赖打开表头之后才出现的列名。列名会跟着显示选项变，格子里的值不会因为你喜不喜欢表头而改意义。批处理还会拿掉欢迎横幅和提示符，输出里剩下的几乎就是结果。这是好事：你要找的子串不会被提示符切成两半。

下面第一份脚本什么业务表也不建。sqlite_master 是目录，库一诞生就有这张系统表，可里面还没有你的用户表。计数是 0。这个 0 是「空」的正面证据，比空白终端更值得信任，因为空白终端至少有两种完全不同的意思。

```sql run expect="0" title="还没有你的表"
SELECT COUNT(*) FROM sqlite_master WHERE type = 'table';
```

有人把「能查询」理解成「库里一定已经有业务表」。这里刚好相反。表达式和系统目录在空库里就能回答，业务表要你自己造。JSON 那些函数不在这门课的约定里，可运行的脚本不要去调用它们。ATTACH 可以把另一个文件挂进来，可挂出去的文件不会活到下一次 Run。用它假装持久化，下一份脚本会踩空。能运行的例子只使用这一次内存里刚刚出现的对象。

第二份脚本让目录里出现一张表，仍然不插入书。你要看的是计数从 0 变成 1，证明建表在这一次连接里生效，同时记住这个 1 出不了这次运行。我故意还不把三本书放进去，是想把「对象存在」和「行存在」拆成两件可以分别核对的事。初学时这两件事常被揉成「我写了 SQL，所以数据应该在」。写了，只说明语句被接受；在不在，要看查询。

```sql run expect="1" title="这一次里有一张表"
CREATE TABLE books(title TEXT, copies INTEGER);
SELECT COUNT(*) FROM sqlite_master WHERE type = 'table';
```

第三份才把这门课会反复遇见的三本书放进去。夜航 3 册，河岸 1 册，旧书店 2 册。数目是故意选的：后面比大小、求和，都会回到 3、1、2。这里先只核对河岸那一行。单独一个数字 1 太容易和别的计数撞车，所以期望写成带着书名的格子。书名用单引号包住。这一章还不到展开引号规矩的时候，你只要先看见：书名是值，copies 那一列是整数，两者在输出里被竖线隔开。

```sql run expect="河岸|1" title="三本书进了这一次的库"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books VALUES ('夜航', 3), ('河岸', 1), ('旧书店', 2);
SELECT title, copies FROM books WHERE title = '河岸';
```

你也许想在脚本末尾再查一次，看看「刚才那张表还在不在」。在同一份脚本里它当然还在，连接没有断。断的是 Run 的边界。每一次按钮都是新进程、新内存。想证明下一次是空的，不是在脚本尾巴上再查，而是重新跑第一份什么都不建的脚本，让目录计数回到 0。这个习惯请留住。后面凡是看起来像「接着上次改」的例子，其实都是把建表和插入重新演一遍，再多做一件新事。重复的插入是舞台布景，新加的那一句才是这一次的变化。

还有一种空白更容易误判。只插入、不查询，终端是空的。查询了一个谁都不符合的条件，终端也可以是空的，但那是零行的结果集，语句本身成功。两者看起来像，意义相反。前者是你没要结果集，后者是结果集里没有行。分开它们的办法，是永远写出你预期会有格子的查询。如果零行本身就是你想证明的事，就改成计数，让 0 变成一个看得见的格子，像第一份脚本那样。不要把「没有输出」写成期望。没有输出可以被太多种原因冒充，包括你根本没执行到那一句。

批处理读的是整份脚本，不是一行一行等你敲回车。前面某一句写错时，后面的语句可能没机会执行。于是你以为删除没生效，其实是建表已经失败，执行停在半路，最后那条查询根本没跑。读错误时先看是哪一句，不要只盯着脚本最后一行。这门课能点 Run 的例子都安排成成功路径，退出码是 0。会故意失败的写法，我放在不能运行的块里，或者只在散文里描述你会看见的那句报错，避免一键运行变成一键中断。中断不是不能讲，而是不该让核对用的期望去匹配一段不稳定的错误英文。错误文本会跟着版本改用词，格子里的 0 和河岸|1 不会。

```sql norun title="不要把持久化写进可运行例子"
-- ATTACH 出去的文件，下一次 Run 不在。
-- json() 这一系函数，这门课当它不存在。
ATTACH DATABASE 'shelf.db' AS shelf;
```

上面这一段不能运行。它留在这里，是为了让你看见那两件做不到的事长什么样，不是为了让你点下去收一个红的退出码。能点的三份都在它前面：空目录、一次建表、三本书里的河岸。

关键字大小写不改变意义。select 和 SELECT 是同一个词。我全篇用大写关键字、小写的表名和列名，只是为了让眼睛能把结构从数据里分开。书名保持中文，因为这是一家中文书店，不是一套为了迁就键盘才存在的示例数据。注释用两条横线写在行尾或单独成行，批处理会跳过它们。不要把要核对的数字只写在注释里。注释不进结果集，期望看不到它。

系统目录还能告诉你表是怎么建的，sql 那一列里躺着当时的建表语句。这一章不查那一列，是因为期望若去匹配整段建表文本，你一改列的类型提示，测试就碎了。计数只问「有没有」，不问「长什么样」。长什么样交给后面的章节用业务查询来证明。业务查询读的是行，不是目录。目录适合回答「这次运行是不是真的从零开始」，不适合回答「河岸还有几册」。

为什么坚持用同一批书，而不是每章换一组顾客和订单？因为你要看的是操作符带来的差别，不是记忆新名词的差别。夜航始终是 3 册，直到有一章明确把它卖掉一本。河岸始终是 1 册，直到有一章把它删掉。旧书店始终是 2 册。册数一旦在你脑子里站稳，MIN、MAX、SUM 打出来的 1|3|6 就不是魔术，而是你自己会算的那三个数。连接时新出现的是借出记录，不是另一套书。事务里滚动的也是这些册数变成的明细。若每章换数据，你会把力气花在认名字上，却没注意到谓词多了一个 AND。

字面量的下一章先不建表。你会看到 20 除以 6 得到 3，而不是带小数的商；1 除以 0 得到 NULL，脚本并不因此停下；双引号在标准里是名字，在 SQLite 里还会做一个兼容用的退让。那些计算还用不到存货表。表从这一章的三本书开始。过滤、汇总、借出、改册数、空值、子查询、排序和事务，都还是这三本。账本要到最后才把册数拆成一笔笔进出。在那之前，把这三本书当成同一家店的存货，不要当成三个随便取的字符串。

若你来自会把文件写到磁盘的命令行，会觉得「不留下」像一种残缺。对浏览器里的这一次运行，不留下是边界：没有可以信任的持久目录，也不该让教程去申请一块下次还在的存储。测试也因此变简单。同一份脚本跑十次，结果不该漂。会漂的是那些依赖昨天残留的行、依赖当前时间、依赖没有写进脚本的附件的例子。这门课把那些依赖都看成缺陷，不看成贴近生产的真实感。生产里的库当然持久，可你学习一种语言的语义时，持久只会使「这次观察到的」和「上次留下的」缠在一起。先在空库里把语义看清，再把同一份语句拿到长久的库上用。顺序反了，你会用残留数据给错误的查询配上正确的样子。

## 小结

这次运行结束之后，什么都不欠你。目录里的表、插入的行、打开了却没提交的事务，都随内存一起走。所以「脚本能单独读懂」比「脚本写得短」更重要。短，是建立在一台永远开着的库上的；那台库这里不存在。

核对只认查询打出来的格子。竖线是列与列之间的默认分隔，期望抓的是子串。插入的沉默和零行的沉默，要用一个会出字的查询拆开。下一章先不建表，把除法和引号在表达式里算清楚。算清楚之后，同样的三本书才会稳稳地进表，否则你连打出来的 3 是商还是册数都分不清。

## 练习

不建任何表，只问目录里有几张用户表。你要的格子是 0。写了建表，这个练习就做成了另一件事：你是在证明「能创建」，不是在证明「默认是空的」。

::: answer 空目录
```sql run expect="0" title="用户表还是零"
SELECT COUNT(*) FROM sqlite_master WHERE type = 'table';
```
:::

把旧书店放进一份新的脚本，册数 2。列的顺序是书名然后册数。查出这一行，输出里要能看见书名和册数被竖线隔开。不要只计数。计数证明有一行，证明不了你插入的是这本、是这个数。

::: answer 旧书店进库
```sql run expect="旧书店|2" title="只核对这一本"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books VALUES ('旧书店', 2);
SELECT title, copies FROM books;
```
:::
