表里有了三行之后，下一个问题不是再塞一行，而是柜台只肯看见其中一部分。WHERE 做的就是这件事：在行还是行的时候丢掉一些，留下一些。它不是循环里的 if，尽管效果有点像。if 是你站在一行前面决定走不走；WHERE 是你把一个谓词交给引擎，让它交出满足谓词的那个集合。集合可能是两行，可能是一行，也可能是空的。空的时候语句仍然成功。你若期待「至少响一下」，会把正确的空结果当成查询写错了。

布景不变。夜航 3 册，河岸 1 册，旧书店 2 册。每一份脚本都重新建表、重新插入，因为这一次 Run 看不见上一章的表。重复的部分请当成同一家店在重新开门，新的只有谓词。

先用一个比较把「至少两册」留下来。3 和 2 都满足，1 不满足。河岸离开这张结果，不是被删除，是这次投影没选中它。表里的河岸还在，同一份脚本里你再问一次不带条件的计数，仍然是 3。过滤不改存储。这一点和后面的删除相反，现在先把边界划清，免得你在练习里用 WHERE 当橡皮。

```sql run expect="旧书店|2" title="至少两册"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title, copies FROM books
WHERE copies >= 2
ORDER BY copies;
```

我在这份查询里加了排序，只为了让两行的输出顺序稳定，好把期望钉在旧书店|2 这一行上。夜航|3 也会出现在后面。排序的道理下一章之后还会专门讲，这里把它当成核对的脚手架，不是这一章的主题。主题是比较：大于等于把边界上的 2 留了下来。写成大于，旧书店会消失。边界属于谁，要写在运算符里，不要写在心里。

第二份把两个条件叠上去。至少两册，并且书名里带「店」。夜航有册数，没有这个字；旧书店两个都有。AND 要求两边都成立。OR 则是一边就够。优先级上 AND 比 OR 更紧，写混合条件时请加括号，不要凭从左到右的语感。这一份只用 AND，括号可以不加，可我仍建议你在脑子里把整个 WHERE 读成一个命题，而不是两句中文用顿号连着。

```sql run expect="旧书店" title="册数和书名同时满足"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title FROM books
WHERE copies >= 2 AND title LIKE '%店%';
```

LIKE 的百分号是「这里可以有任意一串」。百分号在两边，就是书名中间某处出现店。旧书店符合。若你写成 '%店'，是要求以店结尾，这本仍然符合；写成 '店%'，是要求以店开头，这本就不符合了。下划线匹配一个字，这三本书的名字用不上，知道它存在即可，免得你以后把下划线当成普通字符去搜一本叫 a_b 的书，结果多匹配了一堆。

LIKE 还有一条对这批中文书名几乎隐形、对英文会忽然显形的规则：默认情况下，它对 ASCII 字母不区分大小写。'Ab' LIKE 'ab' 成立。中文的店没有大小写可分，所以你在旧书店上看不见这条规则，于是会把它忘了。哪天书名里混进英文书名的大小写，LIKE 会把它们收成一伙。若你要的是对大小写敏感的匹配，用 GLOB，星号代替百分号，并且大小写要自己写对。两套通配符不要混在一个模式里。用错的那一个不会报错，只会悄悄少行或多行。

第三份用名单和闭区间，仍然是这三本。IN 列出允许的书名。BETWEEN 写出册数的闭区间，两端都算在内。河岸的 1 不在 2 和 3 之间，所以即便书名在名单里，AND 也会把它挡下。夜航两个都过。我把名单写成夜航和河岸，故意让河岸在名单里却在区间外，好让你看见 AND 不是「名单优先」。谓词没有优先的那一边，只有都要。

```sql run expect="夜航" title="名单和闭区间"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title FROM books
WHERE title IN ('夜航', '河岸')
  AND copies BETWEEN 2 AND 3;
```

BETWEEN 写成 copies BETWEEN 2 AND 3，和 copies >= 2 AND copies <= 3 是同一件事。有人把 BETWEEN 读成「在两者中间、不含两端」。那是日常用语，不是这条语法。两端包含，是闭区间。册数恰好为 2 的旧书店若被你用 BETWEEN 1 AND 2 去问，它在里面。你若想要开区间，就写大于和小于，不要跟 BETWEEN 较劲。

否定用 NOT，放在整个命题前面，或者用 NOT IN、NOT LIKE。否定一个很宽的条件，剩下的集合会大得超出你的想象。NOT copies >= 2 会留下河岸，这还好。一旦列里出现未知的空值，否定会变得不符合直觉：未知的否定仍是未知，未知进不了 WHERE 的「留下」。这一章的三行都有明确的册数，所以你还看不见这件事。我先把话放在这里，是为了让你不要用这三行的成功去发明一条「WHERE 就是布尔代数」的完整定律。布尔代数里非真即假。SQL 的比较会遇到第三种结果，那一章会用同一批书再加上一本没有册数的样书给你看。现在若写 copies = NULL，不会选出任何一行，既不是河岸，也不是夜航。等于不知道，这个命题本身不知道，WHERE 不收留不知道。想表达「我就是要找还没填册数的」，以后写 IS NULL，不写等号。

还有一条和过滤的时机有关，现在先记住结论，分组那一章再用。WHERE 在分组之前作用在原始的行上。它看不见「这一组的总和」。你不能在 WHERE 里写 SUM，引擎会拒绝，因为总和那时还不存在。觉得「先加总再丢掉小组」的时候，那是另一种子句的工作。能用 WHERE 表达的，就不要推到那一步。把行丢掉再去数，和数完再丢掉组，答案经常不同。三本书这么少，两种写法你都能心算，正好用来核对自己有没有把时机弄反。

过滤条件里也可以放表达式。copies * 2 >= 4 和 copies >= 2 在正数上一样，可左边的写法把意图藏进算术里，读的人要先做一遍除法才知道你在说「至少两册」。把算术留在确实需要换算的时候，例如页数和印张。册数的门槛就写册数。表达式若调用了会得到 NULL 的运算，整行会在你没注意到的时候消失。除以零就是这种运算。copies / (copies - copies) 这种荒唐的条件不会把脚本打停，它会让比较变成未知，行被滤掉。你看见零行，会去查插入，其实插入是好的，坏的是条件里有一条安静的空。

字符串的等号是精确的。'旧书店' 和 '旧书' 不相等，LIKE 才负责模糊。不要习惯性地给每个书名都套上百分号。精确的名字用等号更快让人读懂，也避免「店」匹配到另一本你还没进货、名字里碰巧有店的书。IN 是一串精确等号的缩写。名单很长时它比一串 OR 清楚。名单若来自另一张表，会变成子查询，那是后面的事，这一章的名单是字面量，白纸黑字的三本书里的两本。

最后把「过滤不修改」再证明一次的想法留在散文里，不另开新数据。你在至少两册的查询里看不见河岸，回到建表的那一份脚本不加 WHERE，三行都在。练习里我会让你分别做这两件事，避免它们在同一次修改里缠在一起。写条件的时候先用 SELECT 看会被选中的行，再考虑以后的删除要不要用同一条件。这一章还没有删除。你现在看到的每一行消失，都只是这一次投影的消失。

比较的两边类型不同时，引擎仍会试着给答案，而不是拒绝运行。册数和带引号的数字比较，可能因为转换而成立，于是错误的引号在过滤里也能活。河岸的册数若真的被存成了汉字「一」，它既不会被大于等于 2 选中，也不会被等于 1 选中，它掉进你没为它写过的缝里。缝里的行不是被删除，是没有任何一条你写过的谓词认识它。过滤结果比预期少的时候，先对那一列取类型名，再怀疑 AND 的逻辑。逻辑在这三本上很短，类型被亲和改写过之后才会变长。

OR 把网张大。册数等于 1，或者书名里有店，会同时放过河岸和旧书店。读的人若只看见前半句，会以为结果都是薄薄的一册。每一边 OR 都是一扇独立的门。即便只有一个 OR，也用括号把整句命题括起来。三行的成员你数得过来，正好核对括号有没有改变谁进来。等行数多到数不过来，括号的形状就是唯一还能读的说明。

等号要求逐字相同。多一个空格的书名不会等于旧书店，模糊匹配却可能还认为自己成功了。核对失败时，先把条件里的字面量和表里的字面量都打出来，看是不是眼睛自动把它们读成了一样。逻辑改动要放在字面量已经一致之后。先改逻辑，常常是在一条并不存在的差别上加了新的差别。

过滤还可以把计算留在条件里，但计算一复杂，读者就不再知道门槛是多少册。夜航的 3 乘以 2 再和 4 比，跟直接问至少两册，在正数上结果相同，读起来却像在考人。册数的门槛就写册数。页数换成印张、定价换成折扣，那种时候再把算术放进 WHERE，并且在旁边用一列把换算结果打出来，让期望核对的是换算后的数，而不是让人重新心算一遍你的公式。公式若含有除法，记住两个整数相除会丢掉小数，门槛会被这个丢掉悄悄挪动。20 除以 6 再去和 3 比，比的是 3，不是三点三三。条件因此成立或失败，可能和你在纸上用小数估算的方向相反。

空字符串和空值在过滤里也不是邻居。这一章的书名都写满了，等号和模糊匹配都对着真正的字。若某行的书名是长度为零的文本，它不等于 NULL，模糊匹配一个百分号却可能把它卷进来，因为空串也是串。你以后加数据时不要用空串代表「书名未定」。未定是缺失，缺失不该被百分号当成一种书名。现在三本书的名字都完整，正好让你把模糊匹配的注意力放在「店」和「航」这些真正的字上。

## 小结

WHERE 交出的是满足谓词的那些行，不改表里的存货。夜航 3 册、旧书店 2 册会在「至少两册」里相遇，河岸要等条件放宽才回来。AND 是两边都要，BETWEEN 含两端，IN 是精确名单，LIKE 的百分号才是模糊，并且对英文字母不区分大小写。

等于 NULL 不会帮你找到缺失的册数，因为比较的结果是未知，未知不被留下。分组之前才能用 WHERE，所以它看不见总和。下一章把留下来的行收成一个数，你心算过的 3、1、2 会以最小值、最大值和总和的面目再出现一次。

## 练习

只留下册数恰好等于 2 的书，打出书名。三行都要先插入，否则你可能只插入了旧书店，练习就变成了「表里只有它」，而不是「从三本里筛出它」。

::: answer 恰好两册
```sql run expect="旧书店" title="等于二"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title FROM books WHERE copies = 2;
```
:::

书名里要有「航」。用 LIKE，不要用三个等号去碰运气。册数不限制。应当只看见夜航。

::: answer 书名里的航
```sql run expect="夜航" title="模糊在字，不在册数"
CREATE TABLE books(title TEXT, copies INTEGER);
INSERT INTO books(title, copies) VALUES
  ('夜航', 3),
  ('河岸', 1),
  ('旧书店', 2);
SELECT title FROM books WHERE title LIKE '%航%';
```
:::
