SELECT 不必跟着一张表。这句看上去像语法冷知识，其实是这门语言的重心：查询先是一串表达式，表是表达式去取数的地方之一。柜台还没建档的时候，你已经可以让它算册数、拼书名、判断一个条件是不是真的。若你把 SQL 理解成「先打开文件再打印」，没有 FROM 的查询会显得像省略号没写完。它没有省略。投影的就是这些字面量本身。

这门课的三本书先以字面量露面，不进表。夜航 3 册，河岸 1 册，旧书店 2 册。同一行里交替放书名和册数，是为了让你看见文本和整数可以并排出格，中间仍是那条竖线。书名用单引号。单引号里面是值。这一条先记住，下面的双引号会来拆台。

```sql run expect="夜航|3|河岸|1|旧书店|2" title="三本书还只是字面量"
SELECT '夜航', 3, '河岸', 1, '旧书店', 2;
```

现在把计算器里最容易想错的运算单独拿出来。店里若按 6 本一捆去分 20 本样书，整数除法给你的是捆数，不是每人分到的小数。20 和 6 都写成不带小数点的整数时，商是 3，余数是 2。剩下的 2 本不会被四舍五入进第 4 捆。SQL 在这里不肯偷偷变成浮点，是有原因的：账上的册数是离散的，3.333 捆没有办法上架。若语言悄悄给出小数，你下一行拿它去跟整数比较，等于和不等都会变得难解释。想要小数，就让其中一个运算数变成实数，例如写成 20 / 6.0。那时候你得到的是一条很长的小数，这门课不把那条长小数写进期望，因为显示出来的位数不是你要掌握的规则，规则是「两个整数相除，结果仍是整数，小数部分被丢掉，朝零的方向截」。负数也同样朝零，而不是朝负无穷去取整。样书没有负数捆，这里不展开，但你以后看见 -20 / 6 得到 -3 时，不要以为它和地板除法是同一种。

```sql run expect="3|2" title="二十本分成六本一捆"
SELECT 20 / 6, 20 % 6;
```

余数运算符和除法是一对。只看商，你会以为 20 被整齐地分完了。商加回去的验算是 3 * 6 + 2。把验算写成查询也可以，可这一章的期望停在 3|2，因为余数已经把「没分完」说完了。用浮点去除，再自己取整，往往比直接用整数除法更难读，而且二进制小数会在别的比例上留下你没预料的尾巴。册数、人数、页码这些本来就是整数的量，保持整数除法，把「要小数」写成一个显式的决定。

除以零是另一件我希望你现在就看见的事，而不是等报表炸了再回头。SQLite 对 1 / 0 的态度不是抛出错误、让整份脚本停住，而是给出 NULL。NULL 的类型名用 typeof 打出来是 null。下面把「它是不是 NULL」和「类型名是什么」放在同一行。前一个格子是 1，因为判断成立；后一个格子是 null 这四个字母，是类型的名字，不是空格子。空格子是 NULL 本身被打印出来的样子，类型名则是一个普通的文本。

```sql run expect="1|null" title="除以零不成错，成空"
SELECT 1 / 0 IS NULL, typeof(1 / 0);
```

为什么不报错？因为这门引擎把除以零看成「这个格子算不出数」，而不是「这次计算在道德上失败了」。一张报表里若有一行的分母碰巧是 0，作者希望其余行还在。这个选择是善良的，也是危险的。善良在于脚本继续往下走，你还能看见别的书。危险在于空会传染：NULL 再加一个数，还是 NULL；你拿一份含有除零的明细去求和，可能会得到空，而不是一个少掉坏行的总数。后面讲聚合时你会再遇见「空着的和不是零」。现在先记住现象本身，别在练习里写 1 / 0 然后等着一条错误信息来证明你意识到了风险。错误信息不会来。来的是一个打印出来像空白的值。要用 IS NULL 把它变成看得见的 1。

文本怎么拼，也容易被别的语言带歪。加号不是拼接。拼接用两条竖线。数字和文本相遇时，SQLite 会按自己的规则去转换，转换的结果经常不是你想贴在书名后面的那串字。册数要出现在句子里，先把它当成文本来写，或者明确转换。这一章的书名都直接用单引号，不去跟整数相加。相加是算术。3 + 1 + 2 等于 6，那是三本书的册数之和，是后面 SUM 要再现的那个 6，不是字符串。

双引号的问题比拼接更隐蔽，因为它有时看起来「也能用」。标准 SQL 里，单引号包的是文本，双引号包的是标识符，也就是表名、列名这种名字。SQLite 为了迁就把双引号当字符串用的习惯，做了一件我建议你不要依赖的事：如果双引号里的名字对不上任何列，它就退让，把那一对引号当成字符串。于是在还没有表的时候，SELECT "夜航" 会愉快地打出夜航，类型还是 text。你以为双引号被证明「就是字符串」。证明是假的。退让只发生在名字落空的时候。一旦查询的范围里真有这个名字，同一对引号会忽然改口，去取那一列的值。

先看退让。这里没有名为 title 的列，双引号里的 title 被当成四个字母的文本交出来。

```sql run expect="title" title="名字落空时的退让"
SELECT "title";
```

再看同一对引号遇到真列名。子查询造出一个临时的结果，列就叫 title，值是夜航。双引号的 title 取出夜航，单引号的 title 仍然是那四个字母。两个格子并排，期望是夜航|title。这一行就是这一章要你改掉的判断：引号的形状决定你在说值还是在说名字，而 SQLite 的退让会在「名字还不存在」的阶段把这个区别藏起来。哪一天你加了一列，恰好和某个双引号里的词同名，原来充当文本的字面量会变成那一列，查询不报错，结果却换了意思。这种错最适合在三个月以后咬人，因为语句一个字都没改。

```sql run expect="夜航|title" title="名字对上以后引号改口"
SELECT "title", 'title' FROM (SELECT '夜航' AS title);
```

所以要打印的句子只用单引号。要引用别扭的列名才用双引号，并且列名最好从一开始就取得不必引用：用 title、copies 这种简单名字。中文书名是值，不是列名。把书名写成双引号，在这份空查询里可能碰巧打出正确的字，那是退让，不是规则站在你这边。

条件表达式也有一个从别的语言带过来会踩空的点。CASE WHEN 后面跟的是「真不真」，不是 C 语言那种随便什么数都能当条件、但你得自己记得非零为真的那种松散约定在 SQL 里完全一样。在 SQLite 里，0 就是假，NULL 也不是真。CASE WHEN 0 会走到 ELSE，不会走到 THEN。有库存和无库存如果写成 WHEN 0，你得到的是无，尽管你可能觉得「我都写了 0 了，0 像一个明确的回答」。0 是明确的，它明确地不成立。非零的数才成立，所以 WHEN 2 会走到 THEN。NULL 走不到 THEN，因为未知不是真。简单形式的 CASE 表达式另外用等号去配，CASE 0 WHEN 0 能配上，那是相等，不是真值判断。两种写法长得近，语义不一样。这一章用的是 WHEN 后面直接放条件的那种。

取子串同样有一条来自传统、不是来自 C 的下标。substr 从 1 开始数。旧书店的第 1 个字是旧，从第 2 个字起取 2 个字是书店。下标写成 0，你不会得到旧，你会得到空。空再次安静地出现，不报错。把 0 当成起始位置的人，会在书名截短时截出空白，然后去怪数据脏了。数据没有脏，位置数错了。长度参数是要取的字数，不是结束位置。取到末尾可以省略长度，但省略之后你更要确定起点是 1 还是 2。中文在这里按字数，不按字节。旧书店是三个字。若你用字节长度去切，会切在一个字的中间，那是别的接口的算法，不是 substr 的算法。

```sql run expect="无|旧|书店" title="零是假，子串从一开始"
SELECT CASE WHEN 0 THEN '有' ELSE '无' END,
       substr('旧书店', 1, 1),
       substr('旧书店', 2, 2);
```

把这一行读慢一点。第一格是无，因为 WHEN 0 不成立。第二格是旧，证明起点是 1。第三格是书店，证明从 2 起、长度为 2，没有把旧算进去，也没有停在结束下标那种算法上。三个事实放在一起，是因为它们都来自「表达式自己就能算」，不需要表来撑场面。等下一章把这三本书真正插入之后，书名和册数会从字面量变成格子里的值，除法、空、引号和子串的规则却不会因此改写。你在表上看到怪结果时，先回到没有表的这一行，往往发现怪的是表达式，不是行丢了。

typeof 还会告诉你整数、实数和文本的名字：integer、real、text。3 是 integer，3.0 是 real，哪怕数值上你觉得相等。相等比较有时会把它们看成同一类数，可类型名不同。需要小数却写成两个整数相除，类型名会揭穿你：结果仍是 integer。需要文本却写成了双引号的列名，类型名救不了你，因为列里的值本来就是 text，和字面量的 text 长得一样。区分它们要靠上一份例子那种对照，不是靠 typeof 单独一跳。

余数和商要一起读。只记住 20 除以 6 得 3，会把剩下的 2 本样书从脑子里抹掉。抹掉之后你去进货，架子上少的就是这 2 本，而查询看起来一直是对的。把 3|2 当成一个结果，而不是两个无关的技巧。商告诉你能装几捆，余数告诉你捆完之后手里还剩什么。账上这两种数都要有去处，要么继续散放，要么凑成下一捆，不能因为整数除法不报错就把余数当成已经消失。

## 小结

没有表的查询是合法的，因为它投影的是表达式。整数除法保留整数，20 除以 6 是 3，余数单独拿。除以零变成 NULL，脚本继续，这个继续是你以后必须防备的安静。双引号是名字；只有名字落空时，SQLite 才退让成文本。退让让错误的引号在早期看起来能用。

0 在 WHEN 里是假，子串从 1 开始数，长度是字数不是结束下标。下一章把夜航、河岸、旧书店从字面量放进表。放进去之后，单引号仍然是值，册数仍然是整数，你在这一章看到的 3、1、2 会变成行，而不是消失进一种新的算术。

## 练习

17 本按 5 本一组分，整数商是多少。不要写成浮点。若你得到一条小数，说明有一个运算数已经不是整数，规则就换成了另一条。

::: answer 十七除以五
```sql run expect="3" title="商是三"
SELECT 17 / 5;
```
:::

旧书店从第二个字开始取两个字，应当得到书店。同时确认 WHEN 0 不会选中前面的分支。两个结果用竖线连在同一行，避免你只看对了其中一半。

::: answer 子串与假的零
```sql run expect="书店|无" title="起点是二，零走向否则"
SELECT substr('旧书店', 2, 2),
       CASE WHEN 0 THEN '有' ELSE '无' END;
```
:::
