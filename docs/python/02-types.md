东柜的架上有一册《小径》，库存先记成整数 1。馆员阿宁把这个数告诉林夏，林夏在自己的纸条上也写了 1。随后有人把架上的库存改成 0。林夏纸条上的 1 不会跟着变成 0。纸条抄的是当时的数，不是一根连到架子上的线。若库存不是一个数，而是一本可以往里夹借书卡的册子，两个人手里拿着的是同一本册子，其中一个人夹进一张卡，另一个人翻开也能看见。Python 的赋值更接近「给对象贴一个名字」，而不是「在名字里挖一个格子把值倒进去」。整数这种对象拒绝被改写，所以你以为的修改其实是让名字改去指另一个整数。列表允许就地修改，所以两个名字可以看见同一次修改。这一章用同一批书把这两种情况分开。

先看整数。`stock = 1` 做的事是：找到或创建一个整数对象 1，让名字 stock 指向它。`seen = stock` 并不复制出一个新的 1 再放进 seen。它让 seen 也指向 stock 此刻指向的那个对象。此刻两者看见的都是 1。下一行 `stock = 0` 让 stock 改去指整数 0。seen 没有被这行提到，它仍然指着原来的 1。这就是重新绑定。你若指望 `seen = stock` 之后两者永远锁在一起，会在下一行赋值时失望。失望的原因不是赋值只成功了一半，而是第二行赋值根本没承诺「以后保持同步」。它只承诺在这一行执行的那一瞬间，两个名字指向同一对象。

这个模型和「变量是盒子」的说法冲突。盒子模型在教初学时很顺口：盒子 stock 里装了 1，赋值给 seen 就是把 1 抄进另一个盒子。抄进去之后，改其中一个盒子，另一个当然不变。这个故事刚好能解释整数的结果，所以它会在整数上一直看起来是对的，直到你遇到列表。列表若也是「把盒子里的东西抄一份」，那么 append 就不该被另一个名字看见。可它会被看见。为了让一种说法同时覆盖整数和列表，不如放弃盒子，改说名字是标签。标签可以揭下来贴到别的对象上。对象自己能不能被修改，是对象的事，不是标签的事。

整数不能被就地改写，是语言的选择，也是一种保护。若整数 1 这个对象本身能被改成 0，进程里所有指向 1 的地方会一起变，包括你没打算参与这次库存调整的那些名字，甚至包括写在代码里的字面量 1 若与它共享身份。加法会失去稳定的含义。所以「把库存减一」在 Python 里是「算出另一个整数，再让名字指向它」。`stock = stock - 1` 看起来像在修改 stock，读的时候要在脑子里拆开：右边先用当前指向的整数算出一个新整数，左边再把名字贴过去。旧整数若还有别的名字指着，就留下；若没有任何名字指着，就由解释器稍后回收。你不需要，也不能，命令整数把自己减一。

下面这一块把过程印出来。seen 在重新绑定之后仍然是 1，stock 变成 0。两行输出都要看。期望只抓住 1，是为了强调「另一个名字没有被带走」。你自己跑的时候把第二行也读完。

```python run expect="1" title="整数重新绑定"
stock = 1
seen = stock
stock = 0
print(seen)
print(stock)
```

若把中间一行 `seen = stock` 删掉，seen 这个名字根本不存在，打印它会是 NameError。绑定是名字进入存在的方式。没有绑定过的名字，不是「里面装着空」，而是解释器不认识这几个字母。这和空字符串、和整数 0、和空列表都不同。那三种是真正的对象，有类型，可以交给 print。未绑定的名字连对象都没有。借书台上没人登记过的读者，不是一位名叫空的读者。

列表走另一条路。`holding = ["小径"]` 创建一个列表对象，里面有一个字符串，名字 holding 指向这整个列表。`alias = holding` 让 alias 指向同一个列表，不是指向里面的那个字符串，也不是一份新的列表。随后 `holding.append("海边")` 并不创建新列表，也不让 holding 改去指别的对象。它向那个列表对象发消息：在末尾再放入一本书。因为 alias 和 holding 指着同一对象，alias 翻开时也能看见海边。这就是就地修改，也叫变异。append 的返回值是 None，它的效果体现在对象身上，而不是体现在一个你必须接住的新列表上。你若写成 `alias = holding.append("海边")`，alias 会变成 None，原来的列表倒是被修改了，只是你失去了指向它的那个名字。这个坑和整数那一边「忘记接住新值」正好相反。整数运算把新值交出来，你不接住就丢了。列表的 append 把效果留在对象上，你若去接它的返回值，接到的是 None。

```python run expect="海边" title="列表就地修改"
holding = ["小径"]
alias = holding
holding.append("海边")
print(alias[1])
print(holding)
```

`alias[1]` 取出第二本，下标从 0 开始，所以 1 是海边。第二行 print 会把整个列表的文字打出来，里面同时有小径和海边。两行都是同一次 append 的后果。若你希望 alias 保持「只有小径」的那一份记录，就不该让它和 holding 指向同一列表。你需要一份副本。副本是列表那一章的主题，那里会用切片造出新列表。这一章先把「没有副本」的后果看清楚，否则你会在学会复制之前先学会错误的安心。

同一个名字可以先后指向不同类型的对象。Python 不要求你在第一次使用 stock 时宣布它永远是整数。下一行可以让它指向一个字符串。这给借书台的草稿带来自由：一个叫 note 的名字，上午指着册数，下午可以改指一句说明。自由的代价是读代码的人不能只看名字就知道现在能对它做什么。对整数可以做减法，对字符串做减法会在运行时失败。失败不是在你写那一行的时候由一个单独的编译步骤拦截，而是等执行到那一行才出现。有的语言选择在运行前拒绝这种改指，换来更早的错误和更重的声明。Python 选择把声明的负担拿掉，把核对留到运行。本课程的例子会在要紧的地方用 type 把当前的类型印出来，不是因为每次赋值之后都该检查，而是因为教材需要让你看见标签被揭下来、贴到了另一种对象上。

```python run expect="int" title="名字可以改指别的类型"
stock = 3
print(type(stock).__name__)
stock = "三册"
print(type(stock).__name__)
```

第一行输出是 int，第二行是 str。`type(stock)` 得到的是类型对象，`__name__` 是它的名字。直接 print 类型对象会带上尖括号和 class 这个词，那些字符在不同显示方式下容易让人以为输出不稳定。我们只取名字。注意第二行的 stock 已经不再是整数，你不能指望它还等于 3。上一行的 print 使用的是当时的对象，打印完毕并不把类型冻住。

布尔值和整数的关系容易让人把真假当成另一种小整数来用。True 和 False 是布尔对象，它们的类型名是 bool。在需要数字的地方，True 会被当作 1，False 会被当作 0，这是历史留下的兼容，不是邀请你用 True 加 True 来表示两册书。册数就用整数。是否在架上，若只有「在」和「不在」两种答案，可以用布尔。下面这一块不拿布尔去做加法，只确认类型名，并确认比较的结果是布尔而不是字符串「是」。比较运算符交回来的是对象 True 或 False，print 时显示成英文单词。你若写 `print("是" if stock == 3 else "否")`，那是你自己把布尔翻译成中文，翻译发生在条件表达式里，不是布尔对象自己会说中文。

```python run expect="bool" title="比较得到布尔对象"
stock = 3
same = stock == 3
print(type(same).__name__)
print(same)
```

输出先是 bool，然后是 True。`==` 问的是值是否相等，不是两个名字是不是贴在同一个对象上。整数 3 和另一个写出来的 3 在值上相等。身份是否同一，用 `is`。小整数有时会共享身份，这是解释器的优化，不是你该依赖的规则。比较册数、比较是否为 0，用 `==`。`is` 留给「是不是 None」这种身份问题，以及你确实在问「是不是同一个列表对象」的场合。把 `is` 用在整数上，小数字会碰巧通过，大数字或不同运算得到的相等结果可能不共享身份，判断就会无故失败。

浮点是另一种数，不是「更细的整数」。`1.5` 的类型名是 float。它能表示半册这种库存里本不该出现的量，也带着二进制小数的误差。册数、天数、索书号里的序号，都不要用它来当权威记录。什么时候需要除法的小数结果，标准库那一章会在滞纳金上用 math 处理，并且会把除法的结果收成确定的整数。这一章若在库存上引入 0.1，后面的相等判断会开始依赖误差，而我们还没有工具去谈误差。所以库存保持整数，书名保持字符串，在架与否若需要，保持布尔。三种对象，三种能做的事。

字符串和整数一样，不能就地改掉其中一个字符。你不能写 `title[0] = "某"` 去把书名的第一个字换掉。那一行会在运行时抛出 TypeError，因为字符串不支持按位置赋值。想要新书名，就做出一个新字符串，让名字指向它。这和 `stock = 0` 是同一类动作：重新绑定。字符串的具体切法和拼接放到下一章。这里要把它归到「不可变」这一边，和整数站在一起，与列表分开。不可变的实际后果是：你把字符串交给另一个名字，然后让原来的名字指向新字符串，另一个名字仍看见旧的。没有一种 append 能在别人看不见的情况下把字塞进同一个字符串对象。

None 表示「没有对象可供使用」，它自己却是一个对象，类型名是 NoneType。函数若没有写 return，就会交回 None。列表的 append 也交回 None。把 None 和 0、和空字符串混为一谈，会在借书台上把「没查到」印成 0 册或印成空白书名。三种都可能在条件判断里被视为假，那是下一章控制流要拆的事。类型这一章先坚持：它们是不同的对象。需要区分时，用 `is None`，不要用 `== 0` 去猜。

把库存和在架书目放在一次运行里，可以看到两种对象并肩工作，而不会互相把规则传染给对方。整数的重新绑定不影响列表；列表的 append 也不把整数变成容器。下面这一块先让 stock 从 1 变成 0，同时让另一个名字保持 1；再让书目列表增加一本。输出里既有被留下的 1，也有被加进去的夜航。

```python run expect="夜航" title="两种对象各走各的路"
stock = 1
seen = stock
stock = 0
holding = ["小径", "海边"]
alias = holding
holding.append("夜航")
print(seen)
print(alias[2])
```

seen 印出 1，alias 的第三项是夜航。若有人用盒子模型预言，他会说 seen 和 stock 各有各的盒子所以 seen 是 1，这句他碰巧说对；他又会说 alias 和 holding 各有各的盒子所以 alias 不该看见夜航，这句就说错了。一个模型若只能在一半的对象上成立，它就不该继续当你的默认模型。标签模型在两边都成立：整数那一侧，stock 的标签被揭走了；列表这一侧，两个标签还贴在同一个对象上，对象的内容变了。

还有一种容易混淆的写法：`holding = holding + ["夜航"]`。加号对列表会做出一个新列表，再让 holding 指向新列表。若 alias 还指着旧列表，alias 看不见夜航。这和 append 的效果不同，尽管两句的中文都可以说成「加上夜航」。读代码时要看右边是不是产生了新对象，以及左边是不是只把一个名字贴了过去。`+=` 对列表往往走就地修改，对整数走重新绑定，因为它本质上要看对象有没有就地加的能力。这种分裂是为了让 `+=` 在两种对象上看起来都像「增加」，实现却各自选择最自然的做法。自然的代价是你不能只背「加等号一定造新对象」或「加等号一定改原来的」。看对象。列表用 append 或 `+=` 时，默认怀疑它会改到所有指向它的名字；整数用 `+=` 时，默认相信其他名字还指着旧值。

类型转换是你显式要求的新对象，不是标签偷偷换了。`int("3")` 从字符串做出一个整数，原来的字符串若还被别的名字指着，仍然是字符串。`str(3)` 做出字符串 `"3"`，原来的整数还是整数。转换失败会抛出 ValueError，例如 `int("三")`。不要用转换去猜测读者的输入「大概是数字」。输入那一章会读到一行文本，你若直接把它和整数相加，失败方式是 TypeError，因为字符串和整数不能相加。那是类型不同，不是值不合法。两种错误都值得看见，但它们的名字不同，处理的位置也不同。这一章的例子不读取输入，转换只在你已经握着一个写明的字符串时才出现。

最后把话说死一点，避免后面几章反复打补丁。名字没有类型，对象有类型。赋值移动的是名字到对象的箭头。不可变对象上的「变化」是新对象加移动箭头。可变对象上的方法可以不移动箭头而改变对象内部。两个名字能不能看见同一次变化，取决于它们是否还指向同一个对象，不取决于它们的拼写像不像。库存用整数，书目用列表，书名用字符串。需要副本时去下一章以外的列表章学习怎样复制，不要在这一章用「再赋值一次」幻想自己已经复制了列表。

## 小结

`seen = stock` 让两个名字指向同一个对象。随后 `stock = 0` 只移动 stock 的箭头，seen 仍看见原来的整数。列表的 append 不移动箭头，它改变列表对象的内容，因此所有指向该列表的名字都看得见新书。名字可以改指另一种类型，需要核对时看 `type` 的名字，比较册数用 `==`。字符串和整数站在不可变一边，列表站在可变一边。
