`print` 把对象变成文本写到标准输出，默认在末尾加换行。`#` 后面直到行尾是注释，解释器会跳过。

缩进在 Python 里是语法，不是装饰。同一块里的行必须使用相同的空格数。本教程统一用 4 个空格。

```python run expect="Ada Lovelace" title="名片"
print("Ada Lovelace")
print("数学家")
# 这一行不会出现在输出里
print(2026)
```

```python run expect="*\n**\n***" title="三行星号"
print("*")
print("**")
print("***")
```

::: note
输出里的引号属于源代码，不会打印出来。要打印引号，需要写在字符串里面。
:::

```python run expect="她说：你好" title="字符串内容"
print("她说：你好")
```

print 把对象转成文本写到标准输出。多个参数之间默认加空格，结尾默认加换行。你可以用 sep 改分隔符，用 end 改结尾。教学里多数时候保持默认，这样每一行输出对应一次 print，读终端时不容易串行。注释从 # 开始直到行尾，解释器直接跳过，所以注释里写错字不会让程序失败，但会让下一周的你读不懂。

缩进是语法的一部分。同一个块里的语句必须使用相同数量的空格，本教程统一四个空格。Tab 和空格混在一起时，看起来对齐，解释器却报 IndentationError。编辑器里请打开「用空格代替 Tab」。空行可以随便留，它不开始新的块，只是让眼睛休息。

字符串字面量外面的引号不属于输出。要在句子里出现引号，外层用单引号、内层用双引号，或者反过来。print 本身不负责对齐和表格，复杂的排版留给格式化，下一章再细说。现在先保证：你写在引号里的字，会原样出现在终端里。

运行按钮把这段代码放进编辑器之后，你仍然可以在编辑器里再加一行 print。那一次点击工具栏上的 Run，跑的是你改过的版本，不再自动对照文档里的期望。文档块上的期望只在从文档运行时才比较。

print 的 end 参数默认是换行。把它改成空字符串，下一次 print 就接在同一行。调试布局时这很有用，也很容易让两行结果粘在一起，所以改完 end 记得在最后一次打印恢复换行。sep 只影响同一次 print 的多个参数，不影响下一次调用。

注释不会执行，但错误的注释比没有注释更糟。写「这里把结果乘 2」而代码在除，读者会按注释改代码，把对的程序改错。注释只补充代码看不出来的约束，例如「种子必须固定，否则测试不稳定」。

四个空格是本教程的约定，不是解释器的唯一选择。解释器只要求同一块内部一致。你如果从别处贴来带 Tab 的代码，先全部换成空格再运行，否则报错位置会落在你以为没问题的那一行。

编辑器替换发生在运行之前。你看到终端有输出时，左侧已经是示例代码。想保留自己的草稿，先撤销，或者在运行前复制到别处。撤销只恢复最近一次被文档替换的内容。

print 是这一章唯一负责让终端发生变化的函数。赋值、注释和空行都不会自己产生输出。多个参数默认用空格隔开，并以换行结束。sep 只影响同一次调用里的参数，end 只影响这一次的结尾。把 end 设成空字符串，下一次 print 会接在同一行；最后一次记得恢复换行，否则下一行结果会粘上来。

注释从 # 到行尾，解释器跳过。注释写错不会让程序失败，却会让你按错误的说明去改对的代码。只写代码看不出来的约束，例如「这里必须四个空格，因为下面的块要和它对齐」。不要用注释重复 print 已经表达的动作。

缩进是语法。同一块里的语句必须使用同样的空白。本教程统一四个空格。Tab 和空格混用时，屏幕上可能对齐，解释器却报 IndentationError，行号落在你以为没问题的那一行。从别处粘贴代码后，先把制表符换成空格再运行。空行不开始新的块，只是让眼睛休息。

引号不属于输出。句子里要出现引号时，外层和内层互换单双引号。文档块上的期望只在从文档运行时才比较；你在编辑器里加了一行 print 之后，点的是工具栏，那一次不再自动对照文档。

### 读「不换行」

先做这一例。代码收成一行是 `print("A", end="") print("B")`。先盖住终端，用手算结果，纸上的文本里要能找到「AB」。这是子串：前面可以有别的输出，后面通常有换行，不要要求整屏只有这几个字。

然后点这个代码块上的 Run，不要点工具栏。代码块会先备份草稿，再把示例写进编辑器并执行。终端里用眼睛找「AB」。退出码不是 0 时，先读错误的类型和最后一行，此时不要改期望。退出码是 0 但找不到这段文字，说明打印了别的值，回到产生该值的表达式，只改一处。

改过之后再点代码块上的 Run，会把你的修改盖掉。要验证修改，点工具栏上的 Run。预测和新输出一致后，点撤销，把草稿还给自己。一次只改这一例，不要连着改两个代码块。

## 最佳实践

- 同一代码块只用空格缩进，并且统一成四个空格。
- 注释解释为什么，不重复代码已经写出的动作。
- 一次 print 对应一行输出，调试时更容易对上终端。

## 小结

print 负责把值写到标准输出，# 开头的文字会被跳过，缩进决定语句属于哪一块。先把这三件事写对，后面的类型和循环才有地方落脚。

## 常见错误

- 混用 Tab 和空格。缩进不一致会直接报 IndentationError。
- 忘记字符串两端的引号，解释器会把文字当成变量名。
