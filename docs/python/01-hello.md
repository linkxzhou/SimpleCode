借书台和读者之间隔着一张条子。条子上如果什么都不写，对方只能看见一张空白。Python 进程和你之间也隔着这样一条缝：进程结束之后，留在终端里的只有它写到标准输出的字节。没有 print，计算可以在内存里发生，你却无从核对。这一章只解决三件很小的事：怎样把字送出去，怎样在源码里留下给人不留给解释器的话，以及为什么行首的空格会改变程序的结构。三件事都围着东柜的同一张借条转，从只写柜台名，到写上值班的人，再到按册数决定印哪一句。

print 是一个函数。括号不是装饰，在 Python 3 里省略括号会让这一行变成语法错误，而不是「用旧式语句打印」。参数放在括号里，解释器先求出参数的值，再把这个值的文字形式写出去，默认在末尾加一个换行。引号用来标出一段文本从哪里开始、到哪里结束，它们自己不会出现在输出里。你若在期望里写上引号，核对会失败，不是因为中文没送出去，而是因为终端里根本没有那些引号。下面这一块是本章第一个可运行的例子，它只印柜台名，好让我们先确认通道是通的。

```python run expect="借书台" title="柜台名"
print("借书台")
```

终端上是借书台三个字，然后换行。进程随之退出，退出码是 0，因为没有发生错误。这一块没有定义函数，没有读取输入，也没有留下任何文件。下一块即使还想谈同一张柜台，也必须把要印的字再写一遍。上一章已经把「每次运行都是新进程」说清楚了，这里不再把那个事实当成新鲜事，只是遵守它。

print 可以接受多个参数。多个参数之间默认用一个空格隔开，仍然只在整行末尾加一次换行。这和你写两句 print 不同。两句 print 是两行；一次 print 里的两个参数是同一行上的两段。借条有时需要一行里既有读者又有书名，有时需要分成两行以便盖章。选哪一种，取决于你要给人看的版式，不取决于解释器更喜欢哪一种。空格这个默认分隔符偶尔会碍事：你想让「林夏」和「小径」紧贴一个书名号，中间却多出一个空格。那时与其跟分隔符搏斗，不如先把整句拼成一个字符串再打印。拼接留到字符串那一章，这里只要知道 print 的职责是送出，不是排版引擎。

还有两个不那么显眼的开关。`end` 决定末尾写什么，默认是换行；把它改成空字符串，下一次 print 会接在同一行后面。`sep` 决定多个参数之间写什么，默认是空格。这两个开关都是每次调用自己的选择，不会变成进程级的配置。你在某一句里把 `end` 改掉，下一句又恢复成换行。这很适合在借条末尾补一个句号，而不想为了句号再起一行。它也很容易把输出粘成一长串，让你在核对时期望找不到换行处的那个词。本课程的例子多数时候保持默认，就是为了让每一句 print 对应终端里的一行，眼睛好对。

注释从井号开始，直到这一行结束。解释器读到井号，会把它和它右边的字全部丢掉，再继续读下一行。注释因此可以写中文、写临时的册数、写「这行先别删」，都不会变成输出，也不会变成语法。它服务的是下一个打开这份源码的人。在借书台，这个人常常就是下一班的馆员，也可能就是两小时之后的你。注释不服务解释器，所以它也不能代替 print。你把唯一一句 print 注释掉，进程会安静地成功退出，终端是空的。空输出不是错误，退出码仍是 0。测试会说期望的字没出现，你若先去找异常，会一无所获。这是注释最常见的坑，它就发生在你以为自己只是「暂时关掉」的那一刻。

注释还有一种更隐蔽的误用：用它保存已经被放弃的旧句子，让源码里同时存在两套说法。下一班分不清哪一套才是现在的规矩。与其留着被注释的 print，不如删掉。版本管理若存在，旧句子还在历史里；在这门课的单块源码里，历史并不存在，留着的注释就是唯一的旧句子，它会冒充当前的意图。井号不会开启一个可以跨行的注释块。你若想像其他语言那样用一对标记包住整段，Python 没有那种标记。连续多行的说明，就连续写多行井号。有人用成对的三重引号当作多行注释，那其实是一个字符串字面量，只是它没有被赋给任何名字，于是被求值之后丢掉。它能凑合着用，却会在缩进和引号嵌套上添乱。这一章的例子坚持用井号。

下面这一块在柜台名下面加上值班的人。注释解释为什么要分成两行，解释器却只看见两句 print。你把注释整行删掉，输出不变。你把其中一句 print 前面加上井号，输出就少一行。这个对照比任何口诀都更能记住注释的边界。

```python run expect="阿宁" title="值班条"
# 分成两行，是为了让下一班能单独盖值班章
print("借书台")
print("阿宁")
```

输出两行：先是借书台，然后是阿宁。期望只要求出现阿宁，借书台多出来也不妨碍核对。这和真实的检查习惯一致：你往往先找关键的那个名字，而不是要求整张纸一个多余的字都没有。若两行的顺序反了，期望仍然能对上，因为我们只写了子串。顺序错了却仍然通过，是子串期望的局限。读示例时要自己看完整输出，不要把测试的宽容当成版式已经正确。

缩进在很多语言里只是礼貌。写不写空格，结构都由花括号决定，空格只是让人好读。Python 把这件事倒了过来：行首的空白就是结构。冒号表示「下面开始一个块」，块里的行要比冒号那一行多缩进一层。块结束的标志不是一个闭合的括号，而是缩进退回去。这个设计回避的是一种常见的分裂：眼睛看见的层次和编译器看见的层次不一致。有的代码花括号包住了三行，排版却把其中一行顶到了最左边，读的人会漏看。Python 拒绝这种分裂。你看见的退格，就是块的结束。

代价是空白字符变得有语义。多按一个空格，可能就是另一个块，或者直接是语法错误。从别处粘贴代码时，制表符和空格混在一起，眼睛对齐了，解释器却认为层次不同。这种错误的信息是 IndentationError 或 TabError，进程不会走到 print。你若在已经缩进的块里再混用两种空白，失败发生在解析阶段，计算根本没开始。本课程的例子统一用四个空格，不用制表符。四个还是两个，语言都接受，只要同一块里一致。四个空格是这里的约定，好让所有借条的层次用同一种宽度对齐。

缩进错误还有一个近亲：你把本该留在块里的一行退了出去，语法却仍然成立。程序能跑，印出来的却是另一套逻辑。例如在判断册数的分支里，你本想让「可借」和册数都在条件成立时才打印，却把印册数的那一行退到了和 if 对齐的位置。它就变成无条件执行。终端里永远有册数，测试若只检查「可借」两个字，会放过这个错误。所以缩进不只是「别写错到无法运行」，还是「别让一行悄悄脱离它的块」。读别人的借条时，先看冒号，再看下一行的行首，确认那些空格确实多出来一层。

下面这一块让册数决定印哪一句。册数是 2，大于 0，所以走进 if 下面那一层，印出可借。else 下面那一层在这次运行里不会执行，它仍然要缩进正确，因为解析器在运行之前就检查整块结构。你不能因为某一支「今天走不到」就把它的缩进写乱。写乱了，整份源码都无法启动。

```python run expect="可借" title="缩进决定哪一句"
copies = 2
if copies > 0:
    print("可借")
else:
    print("已借出")
```

把 `copies` 改成 0 再跑，输出会变成已借出。改的是数据，不是结构。两支的 print 都缩进了四格，和 if、else 这些引导行区分开。若你把 print 顶到行首，和 if 对齐，解释器会认为这个块是空的，从而在 if 那一行报错：它期望缩进的块，却遇到了退回去的一行。错误发生在解析，不会印出可借或已借出。空块在 Python 里要用 pass 占位，不能真的什么都不写。pass 的意思是「结构上需要有一行，运行时什么都不做」。控制流那一章的死循环会用到和 pass 类似的占位，这里先知道有这个词即可。

注释和缩进会一起作怪。井号开头的行，其行首空白不参与块的结构，因为它在被当作代码之前就被丢掉了。你可以在一个缩进块的中间写一行顶格的注释，下一行再回到原来的缩进，块仍是连续的。这给了说明文字一点自由，也给了粗心一点空间：你以为那行顶格的注释把块截断了，于是在后面又写了一个和 if 对齐的 print，结果那个 print 并不在分支里。看结构时，先忽略注释行，再看剩下的代码行的行首。

有时你想确认「这样缩进到底算不算错」，又不想让整块示例变成无法运行的文件。可以把有问题的源码放进字符串，交给 exec。exec 会在运行时去解析那段文本。解析失败会变成可以接住的异常，于是我们能把异常的类型印出来。下面这段字符串的第二行多了两个空格，它并不属于任何块，因此是 IndentationError。外层这段示例本身的缩进是合法的，所以抽屉里的运行会成功，输出是错误的名字，而不是一次崩溃。这和直接把错误缩进写在顶层不同：顶层的错误会让进程非零退出，没有你的 print。两种呈现都有用。顶层错误用来体会「程序没诞生」；exec 用来在一篇必须能核对的文章里展示错误的名字。

```python run expect="IndentationError" title="对不齐的缩进"
source = "print('借书台')\n  print('阿宁')\n"
try:
    exec(source)
except IndentationError:
    print("IndentationError")
```

字符串里的 `\n` 是换行，第二行的两个空格是罪魁。print 的参数用了单引号，是为了不和外面的双引号打架。单引号和双引号在 Python 里没有功能差别，都表示字符串。输出里既没有借书台，也没有阿宁，因为那段源码没有被成功执行。印出来的 IndentationError 是外层 except 写的字，不是解释器自动替你翻译的中文。解释器的原始信息是英文，这里我们选择只报告类型名，好让期望稳定。

把这一章收束到借条上。第一块只证明字能出去。第二块用注释说明两行的理由，注释不影响输出。第三块用缩进把「可借」关在条件里面。第四块说明缩进写错时，失败发生在执行那些行之前。你以后会看到更深的嵌套：循环里再套条件，条件里再调用函数。层次变多时，四个空格的台阶会变长。不要用减少缩进来「节省空间」。空间不是这里的稀缺资源，可辨认的层次才是。若一个块深到你数不清台阶，那是该把里面的一段提成函数的信号，函数那一章会接上这个话题。现在先把一层台阶写对。

空行在 Python 里通常没有结构意义。你可以在两句 print 之间空一行，让借条的两段在源码里分开，输出仍然是紧挨着的两行，中间不会多出一个空行，除非你打印了一个空字符串。有人以为源码里的空行会变成终端里的空行，于是在核对时找不到那一行空白，开始怀疑 print 丢了输出。空白要出现在终端，就必须是某次 print 的内容，或者是 `end` 里写进去的换行。源码的排版空白和输出的空白是两套东西。注释也属于源码的排版，同样不会渗进输出。

最后分清三种「没有字」的情况，免得后面调试时混在一起。第一种：进程失败，终端里是回溯，没有你的句子。缩进错误属于这一种。第二种：进程成功，但你把 print 注释掉了，终端是空的。第三种：进程成功，print 了一个空字符串，终端有一个换行，看起来也像空。三种情况的退出码和输出并不相同。看的时候先看退出码，再看有没有回溯，最后才数空行。借书台清点时也是这个顺序：先看锁有没有打不开，再看单子是不是空白，最后才数格子里有没有书。

## 小结

print 把值的文字写到标准输出，并默认换行。引号、括号留在源码里，不会跟着出现在终端。注释从井号开始，只给下一班的人看；把唯一的 print 注释掉，进程会成功，输出却是空的。缩进是块的边界，不是排版爱好。条件下面的语句要比引导行更深一层，同一层里不要混用制表符和空格。缩进不合法时，失败发生在那些语句执行之前。
