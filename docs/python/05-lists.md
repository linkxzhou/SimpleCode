东柜墙上有一份借出名单，从上到下是夜航、小径、海边。这份名单是列表。类型那一章已经见过两个名字贴在同一个列表上时，append 会同时被两边看见。这一章把那份名单当作唯一的业务数据，看三种不同的写法分别做了什么：就地增加一本，切出一份看起来一样的新名单，以及当每一行本身又是列表时，切片为什么仍然会漏。三件事都从同一批书出发，免得你以为不同的结果来自不同的数据。

列表用方括号写出来，元素用逗号分开。空列表写成 `[]`，它是真值里的假，也是一个可以 append 的对象。append 在末尾放入一个元素，修改的是这个列表对象，返回 None。insert 可以指定位置，同样就地修改，同样返回 None。按下标赋值，例如 `loans[0] = "诗选"`，换掉那个位置上的元素，列表对象还是原来的那个。这些操作的共同特点是：指向该列表的所有名字都看得见变化。你若只想让墙上的那份变，而手里的抄件不变，抄件就必须是另一个列表对象。

先看就地增加。名单从两本开始，append 夜航。打印最后一本，确认增加发生在原对象上。这里只有一个名字，所以还看不出共享。它用来把「增加」的基准固定下来，下一块再引入第二个名字。

```python run expect="夜航" title="在原名单末尾追加"
loans = ["小径", "海边"]
loans.append("夜航")
print(loans[-1])
print(len(loans))
```

负的下标从末尾数，`-1` 是刚刚放进去的夜航。长度变成 3。len 对列表计数的是元素个数，不是里面字符串的字符数。夜航这一项自己的长度是 2，那是字符串的事，问的是 `loans[-1]` 的 len，不是 loans 的 len。两个长度都叫长度，对象不同。

现在把同一份名单交给第二个名字，再 append。第二个名字看见的长度会变成 4。这不是函数调用把名单「传过去」了，这一章还没有自己的函数，这只是两个标签。墙上和手里是同一张纸。

```python run expect="4" title="第二个名字看见追加"
loans = ["夜航", "小径", "海边"]
hand = loans
loans.append("诗选")
print(len(hand))
```

若 hand 应当保持三本，以便和改过的墙上那份对照，就不要写 `hand = loans`。切片 `loans[:]` 会做一个新列表，把原列表里的元素按顺序放进去。新列表和旧列表不是同一个对象。随后对旧列表 append，新列表的长度不变。元素若是字符串这种不可变对象，两边各自持有的那些字符串也不会被其中一边改写，因为字符串本来就不能就地改。于是这份切片在「元素是书名字符串」的前提下，表现得像一份完整的抄件。

```python run expect="副本仍是3" title="切片得到另一份名单"
loans = ["夜航", "小径", "海边"]
hand = loans[:]
loans.append("诗选")
print(f"副本仍是{len(hand)}")
print(f"墙上是{len(loans)}")
```

输出两行，副本仍是 3，墙上是 4。`loans[:]` 的起和止都省略，表示从开头到结尾，步长是 1。它和 `loans[0:3]` 在这份长度为 3 的名单上结果一样，但写成 `[:]` 时你不用自己数长度，也不会在名单变长之后忘了改止点。切片的止点同样不包含。`loans[:2]` 只有夜航和小径，没有海边。你可以用它做「只抄前两本」的不完全副本。不完全副本仍然是新列表，之后对原列表的 append 不会把新书推进这前两本里。

`list(loans)` 也能做出新列表，效果和全切片相近。用哪一种，团队里统一即可。这门课用切片，因为同一种写法还能表达「只取一段」。不要用 `hand = loans` 再假装自己复制过。那一行没有复制。

删除也分就地和交出新列表。`pop` 拿走某个位置的元素并交回来，列表变短。不给位置时拿走最后一项。`remove` 按值找到第一项相等的元素并删掉，找不到会抛出 ValueError。它不返回被删的值，返回 None。切片赋值可以把一段换成另一段，甚至换成空段，从而删掉中间几本，这仍然是就地修改。想要「去掉前两本之后的新名单」而不动墙上那份，就写 `loans[2:]` 并把结果绑到新名字上，不要用切片赋值。

排序有一对容易看错的兄弟。`loans.sort()` 就地重排，返回 None。`sorted(loans)` 交出一个新列表，原来的顺序还在。借出名单若要按书名排一份给读者看，同时保留墙上的出借顺序，就用 sorted，把结果绑到新名字。若墙上的顺序本身就该被重排，才用 sort。下面这一块保留原顺序，打印排序后的第一本和原名单的第一本，证明它们可以不同。书名是夜航、小径、海边。按字符排序时，具体哪一本排在最前取决于字符的顺序，我们把排序结果和原名单都印出来，用原名单的第一本「夜航」作为期望，确认 sort 的那种就地效果没有发生在原名单上。

```python run expect="夜航" title="sorted 不改墙上的顺序"
loans = ["夜航", "小径", "海边"]
shown = sorted(loans)
print(loans[0])
print(shown[0])
```

`loans[0]` 仍是夜航。`shown[0]` 是排序后的第一本，可能不是夜航。期望只锁定原名单没被 sort 改掉。你若写成 `loans.sort()` 再打印 `loans[0]`，原顺序就没了，这一块的期望会失败。失败是有益的，它说明你选了就地的那一个。

浅拷贝是切片帮不上忙的那一层。借出记录有时不是一个字符串，而是一行里再套一个小列表：读者和书名。`records[:]` 做出新的外层列表，可每个元素仍然是原来的那个内层列表。外层的 append 不会被另一边看见，内层的 append 却会。下面这一块先切片，再往第一行里追加柜台名。副本的第一行末尾也能看见东柜。这不是切片坏了，是它只复制了外层。

```python run expect="东柜" title="内层仍是同一行"
records = [["林夏", "小径"]]
copied = records[:]
records[0].append("东柜")
print(copied[0][-1])
```

要让内层也分开，得在复制时为每一行走进一层，做出新的内层列表。对这种只有一层嵌套、元素是字符串的记录，可以写成 `[row[:] for row in records]`。这叫列表推导。方括号里先写新元素长什么样，再写从哪里取。它会造出一个新列表。推导不是就地修改 records。下面这一块用推导复制每一行，再往原记录的第一行追加东柜。副本的那一行长度仍是 2，没有东柜。

```python run expect="2" title="每一行单独切片"
records = [["林夏", "小径"], ["周予", "海边"]]
copied = [row[:] for row in records]
records[0].append("东柜")
print(len(copied[0]))
print(copied[0][0])
```

长度 2，第一格仍是林夏。若嵌套更深，这种只切一层的写法又会不够。那时要么写一个明确的递归复制，要么重新设计数据，让内层变成不可变的元组。元组用圆括号，写成之后不能 append，也不能按下标赋值。它可以当字典的键，列表不行，下一章会用到这个差别。借出名单若只是书名的序列，列表就够。若每一行是固定的「读者、书名」而且不准备再往行里追加字段，元组能防止有人 append 一个柜台名进去。这一章仍用列表，是为了把浅拷贝的坑留在能演示的形状里。

推导还可以用来过滤。`[name for name in loans if name != "夜航"]` 得到一份没有夜航的新名单，原名单不动。过滤和切片一样交出新列表。不要在 for 循环里一边遍历列表一边 append 或 remove 同一列表的元素，那样下标会错位，有的元素会被跳过，有的删除会让循环提前走到末尾之外。需要边看边删时，先做出新列表，再让名字指向新列表。这是「就地修改」和「遍历」撞在一起时的具体坑，它不出现在单独的 append 示例里，所以容易被忘掉。

列表可以和字符串互转，但那是两种对象。`"".join(["夜航", "小径"])` 得到一个字符串。join 的接收者是分隔符，参数是字符串的列表。分隔符若是顿号，印出来就是给人看的一行。split 走相反的方向，从字符串做出列表。join 不会修改原来的列表。你打印列表时看到的方括号和引号，是列表的文字形式，不是 join 的结果。借条要给人看，用 join 或 f-string；程序要继续按本处理，就留在列表里。不要把已经 join 好的字符串再当列表去 append。

同一份借出名单在这一章里走了四步。append 让所有指向它的名字看见新书。全切片让书名字符串的名单分成两份。sorted 再分出一份顺序不同的，墙上的顺序还在。记录变成列表套列表之后，只切外层不够，要每行再切，东柜才不会出现在副本里。下一步把「按索书号找到那一行」从列表的线性查找换成字典，键必须是不可变的。列表当键会失败，那正是因为列表还能像这一章这样被就地修改：键如果会变，它在字典里的位置就不再可信。

还有一种重复会共享内层。`blank = [[]] * 3` 看起来像三行空记录，实际上是同一个内层列表被放了三次。你往第一行 append 读者，三行都会出现这个读者。星号复制的是引用，不是每一行的新列表。书名字符串的 `["小径"] * 3` 碰巧安全，因为没有人能就地改掉字符串里的字。记录是列表时，星号和浅切片是同一类坑，只是星号更不容易看出来，源码里根本没有第二个方括号被写三次。要三行真正分开的空记录，写成 `[[] for _ in range(3)]`。推导每次执行一次 `[]`，所以是三个对象。这个差别在借书台的空白表格里最伤：你以为填了第一格，打印时三格都有字，统计册数会变成三倍。

下标越界是另一种失败，和共享无关。空名单上取 `loans[0]` 会 IndexError，进程失败。取之前先看长度，或者在你明确知道至少有一本时再取。负下标在空名单上同样越界，`-1` 并不是「如果没有就算了」。没有最后一本，就是没有。不要用异常去代替长度检查，除非缺失在这份脚本里真的罕见。名单来自刚刚的过滤时，空是正常结果。

切片越界则宽容。`loans[10:20]` 在一份只有三本的名单上得到空列表，不抛异常。宽容让「抄一段」容易写，也让写错的起止变成悄悄的空抄件。你以为抄到了诗选，其实起止落在名单外面，副本是空的，原名单没动。核对副本时看长度，不要只看没有异常。

## 小结

append、按下标赋值和 sort 修改列表对象本身，所有指向它的名字都看得到。切片和 sorted、列表推导交出新列表。元素是字符串时，全切片足够分开两份书名。元素仍是列表时，外层切片共享内层，追加到内层的柜台名会从副本里露出来。遍历时不要就地删同一列表的元素。
