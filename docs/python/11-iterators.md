含有 `yield` 的函数返回生成器。每次 `next` 或 for 循环才往下走一步，做到哪算到哪，不会先把无限序列放进内存。

生成器表达式和列表推导式很像，只是用圆括号，而且是惰性的。

```python run expect="[0, 1, 4, 9]" title="有限生成器"
def squares(limit):
    n = 0
    while n < limit:
        yield n * n
        n += 1

print(list(squares(4)))
```

```python run expect="[1, 2, 3]" title="只取前几项"
def positives():
    n = 1
    while True:
        yield n
        n += 1

def take(source, count):
    result = []
    for item in source:
        if len(result) == count:
            break
        result.append(item)
    return result

print(take(positives(), 3))
```

```python run expect="[(1, 2), (2, 3), (3, 4)]" title="滑动窗口"
def window(items, size):
    for i in range(len(items) - size + 1):
        yield tuple(items[i:i + size])

print(list(window([1, 2, 3, 4], 2)))
```

迭代器是带 __next__ 的对象，每次给出一个值，耗尽时抛 StopIteration。for 循环会接住这个异常，所以你自己写 for 时看不到它。iter(对象) 向对象要迭代器。列表、字符串、字典都是可迭代对象，但它们自己不是迭代器：你可以多次 for 一个列表，每次都重新开始。迭代器通常只能走一遍，第二遍是空的。

生成器用 yield 写出迭代器，函数执行到 yield 就暂停，下次从那里继续。生成器适合无限序列或很大的序列，因为值是一个一个产生的，不会先占满内存。对无限生成器不要 list() 整个对象，用 islice 或自己的计数器只取前几项。

生成器表达式写成圆括号，和列表推导很像，但不会立刻做出列表。(n * n for n in range(3)) 是生成器。把它传给 sum 或 join 时，元素被消费掉。再传一次就没有了。

yield from 可以把另一个可迭代对象交出去，写遍历树或串联序列时比手写循环短。本章的例子保持一层，先把「暂停和恢复」看清楚。不要在生成器里夹杂 input，除非你确定每一次 next 时期望谁来喂输入。

列表可以多次 for，是因为每次 for 都调用 iter 得到一个新的迭代器。生成器函数每次调用也得到一个新生成器。已经创建的那一个生成器，走完就空了。函数和它返回的生成器不是同一个东西。

yield 暂停时，局部变量都还在。下次 next 从 yield 的下一行继续，不是从函数开头。这就是它能记住「产到哪了」的原因。在 yield 之前做的准备工作只发生一次，除非你重新调用函数。

StopIteration 是 for 正常结束的信号，不要用它表达业务错误。业务上「没有更多数据」如果是错误，抛别的异常。自己写 next 循环时才需要自己捕获 StopIteration。

生成器表达式的圆括号在作为唯一参数时可以省略一层，例如 sum(n for n in nums)。写不明白就保留括号。它和列表推导的方括号只差一个符号，差在「现在就做出列表」还是「用的时候再算」。

for 循环向对象要迭代器，然后一直取下一项，直到耗尽。耗尽时的异常被 for 接住，所以你自己写 for 时看不到它。列表、字符串、字典可以多次 for，因为每次 for 都重新要一个迭代器。迭代器本身通常只能走一遍，第二遍是空的。

生成器函数执行到 yield 就暂停，下次从那里继续。它适合很大或无限的序列，因为值是一个一个产生的。对无限生成器不要 list() 整个对象。用计数器或 islice 只取前几项，并在取用的地方写明个数。生成器表达式写成圆括号，传给 sum 之后元素就被消费掉，再传一次结果是 0。需要再用就重新创建，不要把用完的生成器存起来当列表。

yield from 把另一个可迭代对象交出去。本章先保持一层，把暂停和恢复看清楚，再考虑用它串联序列。不要在生成器里夹杂 input，除非你确定每一次 next 时期望谁来喂输入。文档测试不会替你交互地回答生成器中途的提问。

区分三件东西：可迭代对象、迭代器、生成器函数。函数本身不是它返回的生成器。调用函数得到一个新的生成器，旧的那个不会因此复活。

## 练习

写一个生成器，依次产出前 4 个偶数：0 2 4 6。

::: answer 参考答案：偶数
```python run expect="[0, 2, 4, 6]" title="参考答案"
def evens(count):
    n = 0
    while n < count:
        yield n * 2
        n += 1

print(list(evens(4)))
```
:::

写一个生成器，依次产出 2 和 4，打印它们的和。

::: answer 参考答案：两个偶数
```python run expect="6" title="参考答案"
def evens():
    yield 2
    yield 4
print(sum(evens()))
```
:::

## 最佳实践

- 无限序列用生成器，并且在取用时限制次数。
- 生成器表达式只消费一次，需要再用就重新创建。
- 能多次遍历的数据用列表，一次性的流水用迭代器。

## 小结

for 消费迭代器直到结束。生成器用 yield 暂停，序列只走一遍，无限序列必须限制取用的个数。

## 常见错误

- 对无限生成器直接 list()。它永远不会结束。先限制次数。
- 生成器只能向前走。用过一次再 for，不会重新开始，需要再调用函数。
