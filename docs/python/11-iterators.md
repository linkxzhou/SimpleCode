催还如果先把整面墙抄成一个新列表，再开始打电话，抄写会发生在第一通电话之前。墙不长时这没什么。墙若很长，而你只需要找到第一本逾期的，前面的抄写就是白做。生成器把「下一本是什么」推迟到你真的要的时候。你写一个带 yield 的函数，调用它并不立刻跑完函数体，它交回一个生成器对象。你每次向这个对象要下一本，函数体才前进到下一个 yield。不要的那些本，可以根本不产生。

这个设计和列表的差别在于结果存在哪里。列表把元素放在内存里，你可以反复从下标 0 开始看。生成器不保存已经交出的元素，它只记得执行到了函数的哪一行。走完一遍，就没有下一本了，再要会得到 StopIteration。你不能把同一个生成器当成长久的催还名单来回扫描。需要两遍，就重新调用那个函数，得到一个新的生成器。这是惰性的代价。惰性省下的是还没被要到的工作；付出的是不能回头。

先写一个只交出书名以「径」结尾的生成器。名单仍是夜航、小径、海边。next 取第一本匹配的。我们不把生成器打印出来。打印生成器会看到它的内存地址，地址不稳定，期望无法写死。打印 next 的结果，结果是书名。

```python run expect="小径" title="只要下一本逾期"
def overdue(books):
    for book in books:
        if book.endswith("径"):
            yield book

pending = overdue(["夜航", "小径", "海边"])
print(next(pending))
```

调用 overdue 的那一行几乎立刻返回。for 循环还没有开始。next 才让它走进去，跳过夜航，在小径处 yield。yield 把小径交出来，同时记住下次要从循环的下一轮继续。再 next 一次，海边不以径结尾，循环结束，函数体走完，抛出 StopIteration。下面把第二次索要放进 try，打印用尽，证明没有第三本，也证明生成器不会回到小径重新开始。

```python run expect="用尽" title="第二遍不会自动重来"
def overdue(books):
    for book in books:
        if book.endswith("径"):
            yield book

pending = overdue(["夜航", "小径", "海边"])
print(next(pending))
try:
    print(next(pending))
except StopIteration:
    print("用尽")
```

第一行是小径，第二行是用尽。若在用尽之后再次调用 overdue，传入同一批书，又能得到小径。新的调用是新的生成器，旧的那个仍然用尽。不要试图 reset 旧的那个。重新调用更清楚。

for 循环内部也是在要下一项，并且会接住 StopIteration 作为正常结束。所以你写 `for book in overdue(books)` 时不必自己 try。循环结束就是用尽。在循环里 break，生成器停在中途，已经 yield 过的那些不会保存，还没 yield 的也不会再自动继续，除非你还握着那个生成器去 next。break 之后若不再使用它，剩下的书就被留下了，这正是「只找到第一本就停」想要的省。

列表可以一次性逼生成器交完。`list(pending)` 会不断 next 直到用尽，做成一个列表。做成之后，pending 已经用尽，再 list 一次得到空列表。这个顺序很坑：你为了调试打印了 list(pending)，生成器就被消费掉了，后面的正式循环什么都看不到，而且没有异常，只是空的。空循环容易被看成「今天没有逾期」。其实是你把逾期在调试时用掉了。调试时要看内容，就重新调用函数，或者把 list 的结果绑到新名字，后面用那个列表。不要用了生成器又以为它还满着。

```python run expect="0" title="做成列表之后原生成器是空的"
def titles(books):
    for book in books:
        yield book

pending = titles(["小径", "海边"])
copied = list(pending)
print(len(copied))
print(len(list(pending)))
```

第一行是 2，第二行是 0。期望锁定 0，就是锁定「第二次已经空了」。copied 里仍有两本，需要反复使用时用 copied，不要用 pending。

惰性还体现在生成器表达式上。圆括号的 `(book for book in books if book.endswith("径"))` 看起来像列表推导，但不会立刻做完。它交回一个生成器。方括号的推导会立刻做完，得到列表。你若只取第一本，圆括号这一份可以少做后面的判断。对三本书，差别看不见。差别在「判断很贵」的时候才重要，例如每一本都要查一次字典或做一次解析。借书台的书名结尾判断不贵，仍值得把两种括号分开，免得以后在贵的判断上先抄满一整份列表。

yield 也可以一次都不到。若没有任何书以径结尾，第一次 next 就用尽。调用 overdue 本身仍然成功，它只是交回一个空的生成器。空生成器和空列表在 for 里都不执行循环体，这一点相似。不同的是空列表的真值是假，生成器的真值是真。你不能用 `if pending` 判断还有没有书。生成器对象存在，就是真，哪怕它下一本都交不出来。这个坑专门咬从列表迁到生成器的代码：原来的 `if not shelf` 得换成别的办法，例如先取一项，或者改回列表。要判断有没有，就得去要，而一要，那一项就被消费了。可以把它存下来再决定。不要只问生成器真假。

```python run expect="没有" title="生成器不能靠真值判断空"
def overdue(books):
    for book in books:
        if book.endswith("径"):
            yield book

pending = overdue(["夜航", "海边"])
try:
    first = next(pending)
    print(first)
except StopIteration:
    print("没有")
```

这里没有匹配，所以印没有。若把真值判断写在 next 之前，`if pending` 会走进「有」的分支，然后 next 才失败。顺序上你已经对馆员说了有书。所以先要，再说话。

无限的生成器可以表示「按规则不断产生」，例如不断给出下一个序号。它必须配一个会停的消费者：取前三项就 break，或者 next 固定次数。不要对无限生成器调用 list。list 会一直要下去，直到进程被停掉。这和死循环是同一类问题，只是循环藏在 list 的实现里。本课程不把无限生成器放进可运行例子。催还名单是有限的三本书。有限，才能在一篇文章里走完。

生成器函数里 yield 之前的代码，在第一次 next 时才执行。若你在函数开头就打印「开始催还」，这句打印不会发生在调用 overdue 的那一行，而发生在第一次 next。把初始化放在调用处和放在第一次 yield 之前，时机不同。需要在「还没人要书」时就做的事，不要放进生成器函数的前部。这个延迟是特性，也是读代码时要在脑子里改时钟的地方。

和迭代器协议相关的还有 `__iter__` 和 `__next__`。生成器已经替你实现了它们。你很少需要手写一个类去变成迭代器，除非状态复杂到 yield 写不清楚。手写时要小心：`__iter__` 若返回 self，这个对象就和生成器一样只能走一遍。`__iter__` 若每次返回一个新的生成器，for 就可以反复使用它。借书台的催还用函数加 yield 就够。类那一章的条子不必都变成迭代器。

把三本书的生成器收成一句能执行的对照。列表推导立刻得到只含小径的列表，长度是 1，而且可以再次取下标。生成器表达式要到 list 时才完成同样的过滤。两边的结果都是小径。我们打印两边的书名，确认过滤条件一致，同时记住只有列表那一份能看第二遍。

```python run expect="小径" title="方括号立刻做，圆括号先不做"
books = ["夜航", "小径", "海边"]
ready = [book for book in books if book.endswith("径")]
lazy = (book for book in books if book.endswith("径"))
print(ready[0])
print(next(lazy))
```

两行都是小径。ready 在下一行仍然可以 ready[0]。lazy 再 next 就会用尽。选择方括号还是圆括号，取决于你要不要保留结果、会不会只取一部分。催还只找第一本时用 yield 或圆括号，找到就停。要做成今天的纸质清单贴在墙上，用列表，因为纸质清单会被看很多遍。

yield 交出的是对象的引用，不是抄件。若你 yield 的是列表里的那一行小列表，调用者 append 一个柜台名，原名单的那一行也会变。惰性省掉的是「何时取出」，不是「取出的是副本」。需要副本时，在 yield 之前做切片，交出新的那一行。书名是字符串时没有这个差别，因为调用者改不了字符串。催还若从「书名」升级成「一行记录」，就要重新检查 yield 出去的是不是唯一的那一行。生成器不会因为你用了 yield 就自动复制。

生成器可以在 yield 之后继续做清理，例如打印已经交完。这句打印发生在消费者停止索要之后的某一刻，具体说，是消费者用尽它或者关闭它的时候。时机不如放在调用者的循环之后那么直观。借书台的「催还结束」应当由取书的那一层打印，而不是藏在生成器的末尾。藏在末尾时，你若只 next 一次就不再使用，结束句可能要等到生成器被回收才出现，回收时机不稳定，不能放进期望。例子里因此不在 yield 之后打印。

把生成器传给另一个函数，函数里的 for 会把它用尽。调用者再 for 一次就什么都没有。这和把列表传进去不同，列表在函数里被读取后仍然满着。写函数的参数名时，若参数可能是生成器，就不要遍历两遍。要两遍，先在函数里 list 一次，然后遍历那个列表，并在文档里说明你会消费传入的迭代器。消费是副作用，尽管它不修改书名。副作用是「这份待办被看完了」。调用者若还要自己看，就会看见空的待办，还以为今天没有人逾期。

range 也是惰性的。`range(1000)` 不会先做出一千个整数的列表。for 需要下一个时才产生。所以用 range 数逾期天数不会先占满一张大名单。你仍然不该写一个没有上限的循环去消耗它，除非另有 break。惰性不是无限的许可证，它只是把工作推迟。推迟到你写出一个不会停的消费者时，工作会一次不落地发生，进程还是停不下来。有限的书架、有限的 range，配会结束的 for，才是这一章的用法。

把生成器放进字典之前，先把它走完成列表或走完成具体的书名。生成器本身不可哈希，也不能当 json 的值。dumps 遇到生成器会失败，因为它不是字符串、数字、列表或字典。催还的结果若要写进报告，就在报告之前用 list 收下你需要的那一部分，并接受这个生成器已经用尽。报告要的是稳定的文本，不是一份还会继续变的待办。待办留在原来的书名列表里，报告只摘抄此刻要催的那些名字。

## 小结

带 yield 的函数返回生成器，函数体在 next 或 for 时才往前走。打印生成器对象会带上不稳定的地址，应当打印它交出的书名。走完一遍再要，得到 StopIteration，for 会把这当作结束。list 会把它用尽，第二次就是空的。生成器的真值不能用来判断还有没有下一本。无限生成器不能交给 list。
