Python 在这里由 CPython 3.11 解释执行。点击代码块上的「运行」，示例会替换主编辑器里的内容，并立刻执行。编辑器原来的草稿会先备份，可以撤销。

每次运行都从空白内存开始：没有网络，写过的文件也不会留到下一次。适合学习语法，不适合安装第三方包。

```text title="纯文本"
这段没有对应的运行时，所以没有运行按钮。
```

```python norun title="不执行"
# 只读示例：本环境没有网络，不要在可运行代码里访问外网。
# import urllib.request
```

```python run expect="你好" title="第一声问候"
print("你好")
```

同一本书里也可以放别的语言。下面这段会切换到 Ruby，并在需要时下载 Ruby 运行时。

```ruby run expect="来自 Ruby 的 42" title="跨语言示例"
puts "来自 Ruby 的 42"
```

这个抽屉里的 Python 跑在 CPython 3.11 上。点 Run 时，示例会先把编辑器里的草稿备份下来，再替换成文档里的代码并执行。撤销能把草稿找回来，所以你可以放心把示例跑一遍，再改成自己的版本。每次运行都是新进程：变量、打开的文件、import 进来的模块都不会留到下一次。教程里的例子因此都写成「从零开始也能跑」的完整脚本。

这里没有网络，也装不了第三方包。标准库里随解释器带来的模块可以用，requests、numpy 这一类不行。一次运行内部可以创建文件，进程结束这些文件就消失。学习语法够用，不适合拿来做需要持久化的项目。

代码块有三种。带 Run 的会真正执行，期望输出是输出文本里的一段子串，测试用它判断示例有没有跑对。只读块故意不能运行，用来展示这个环境做不到的事，例如访问外网。纯文本块没有对应的运行时，所以没有运行按钮。同一章也可以放别的语言：运行时会切换侧栏选中的语言，第一次使用会下载对应的 wasm，进度显示在按钮旁边，按钮本身仍然写着 Run。

阅读顺序建议是：先看这段话在讲哪一个限制，再看示例如何把限制变成可以观察的输出，最后改一个字重跑。输出比期望多一行通常仍然包含期望子串，但你要能指出多出来的那一行是哪句 print 打的。不要把浏览器里能跑的代码原样贴进来，这个解释器没有网页，也没有 pip。

把一次运行想成一张白纸。文档不会偷偷帮你保留上一个格子里的答案，所以示例开头该 import 的就 import，该赋值的就赋值。这样你把代码复制到自己的电脑上时，也不依赖编辑器里残留的状态。

工具栏上的 Run 和代码块上的 Run 外观一样，行为略有差别：代码块会先切换语言、写入示例再运行；工具栏只运行编辑器里当前的内容。下载进度不写在按钮文字上，而写在按钮旁边，避免两个 Run 看起来一个长一个短。

只读块不是坏掉的按钮。它提醒你：这段代码在本环境里会失败，或者会把测试拖进死循环。遇到只读块，读注释里的原因，然后回到能运行的例子上改一两个值。跨语言的例子会切换侧栏，Ruby 那一段就是故意放在 Python 书里，让你看见切换和下载。

期望输出是子串。程序可以多打印一行标题，只要那一行关键结果还在。但不要靠多打印来掩盖算错的数。退出码不是 0 时，先看终端最后的异常类型，再对回刚才改过的那一行。

把这一章当成整本书的运行约定。每次点 Run 都启动一个新的 CPython 3.11 进程，上一个示例里的变量、import 和临时文件都不会留下。后面每一个可运行块都要自己带齐开头：要算的值写在打印前面，要用的模块写在第一行。抄到自己的电脑上时，也不该依赖编辑器里残留的名字。

限制分三层。第一层是环境没有的能力：没有网络，不能 pip 安装第三方包，进程一结束，刚才写出的文件就消失。第二层是文档故意不让跑的块。纯文本块没有对应的运行时；标了 norun 的 Python 块有运行时，但执行它会拖住测试或超出这个沙箱。第三层才是普通示例。读的时候先看围栏上的标记，再看旁边为什么这样标。

工具栏上的 Run 和代码块上的 Run 外观相同。差别在点击之后谁来填编辑器：代码块会切换语言、写入示例再运行；工具栏只运行编辑器里已有的内容。下载进度写在按钮旁边，不写进按钮文字，两个 Run 才不会一个变长一个变短。书里的 Ruby 块是为了让你看见切换语言和第一次下载。

撤销只找回最近一次被文档替换之前的草稿。连续打开两个示例，一次撤销回不到第一个之前。想留住自己的练习，先复制出去，或在打开下一例之前先撤销。期望是子串。多打印一行通常仍然算对，但你要能指出那一行是哪句 print。退出码不是零时，先看异常类型。

### 读「相加」

先做这一例。代码收成一行是 `print(19 + 23)`。先盖住终端，用手算结果，纸上的文本里要能找到「42」。这是子串：前面可以有别的输出，后面通常有换行，不要要求整屏只有这几个字。

然后点这个代码块上的 Run，不要点工具栏。代码块会先备份草稿，再把示例写进编辑器并执行。终端里用眼睛找「42」。退出码不是 0 时，先读错误的类型和最后一行，此时不要改期望。退出码是 0 但找不到这段文字，说明打印了别的值，回到产生该值的表达式，只改一处。

改过之后再点代码块上的 Run，会把你的修改盖掉。要验证修改，点工具栏上的 Run。预测和新输出一致后，点撤销，把草稿还给自己。一次只改这一例，不要连着改两个代码块。

## 最佳实践

- 每个可运行示例都写成完整脚本，不依赖上一次运行留下的变量。
- 需要外网或第三方包时改成只读块，并在旁边说明为什么不能跑。
- 期望输出写成稳定的子串，不把整段解释器横幅写进 expect。

## 小结

Python 101 的例子都在一次全新的 CPython 3.11 进程里运行。Run 会替换编辑器并可以撤销；没有网络和第三方包；只读块用来标出做不到的事。

## 常见错误

- 把 Python 2 的 print 语句写进来。3.11 里 print 是函数，必须加括号。
- 以为上一次运行的变量还在。每次运行都是新进程。
