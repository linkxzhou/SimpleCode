借书台的抽屉里如果留着上一班的铅笔和没写完的条子，下一班会以为那些字还有效。这本 Python 快速入门故意不留这种抽屉。你按下某一块代码上的 Run，浏览器拉起的是一份新的 CPython 3.11，把这一块源码当成整个程序交给它，等它退出，再把标准输出和退出码送回来。上一块里绑定过的柜台名、读者、册数，随着那个进程一起结束。下一块即使看起来紧挨着，也是另一次启动。把它想成每次都换一张新的借书单，而不是一个和你共用了一下午的交互提示符。

这个限制是课程设计，不是解释器天生健忘。Python 在你自己的电脑上完全可以开一个一直活着的 REPL：你先敲 `desk = "东柜"`，下一句再打印 `desk`，名字还在。那种会话适合摸索。它不适合当教程的载体。教程若悄悄记住上一块的赋值，示例就依赖一种读者看不见的状态。你把其中一块复制到编辑器外面，单独运行，会因为缺少那个没被写出来的名字而失败。失败的样子还很冤枉，回溯指向的是「名字未定义」，而你在网页上明明刚刚见过它。所以这里的每一块可运行代码都得自己站得住。该 import 的写在块里，该赋值的也写在块里。

代价是重复。同一位读者的名字可能在连续三块里各写一遍。读起来像馆员把借条抄了三份。换来的是每一份都能单独核对：输出里出现的字，都能在这一块的源码里找到来源。你不必在脑子里维护一份「到目前为止解释器还记得什么」的清单。这份清单在真实的 REPL 里很有用，在一篇会被人从中间翻开的文章里则会撒谎。

白纸还有一层更具体的边界。进程里可以用解释器自带的标准库，不能靠网络现装第三方包。没有 pip，也没有出口去连一座包仓库。json、math 这一类模块随进程到来；requests、numpy 不在。一次运行内部如果写出一个文本文件，那个文件只活到进程结束。下一块即使使用相同的路径，也看不到上一块留下的字节，因为磁盘上的那一层对教程来说是临时的。学习语法够用。拿来做需要记住昨天借出了哪一册的系统，会在第二次点击时失去全部记录。

因此读后面的章节时，可以带着一个固定的核对顺序。先看这一段在回避哪种隐藏状态，再看示例如何把判断变成终端里能核对的文字，最后只改一处再跑。输出和期望不一致时，先读退出码。不是 0，就看错误类型和最后一行，不要先改期望去迁就。是 0 但找不到那段文字，说明打印了别的值，回到产生该值的表达式。期望本身只是输出里的一段子串，不是要求整屏只有那几个字。多出来的说明行通常仍然算通过，但你得能指出多出来的那一行是哪一次 print 打的。

代码块并不都是同一种东西。有的只是一段话，有的是故意不执行的 Python，有的会真正启动进程。先看纯文本。它没有对应的语言运行时，因此没有 Run。它适合放一句你不希望被当成程序的话。

```text title="纯文本"
这段没有对应的运行时，所以没有运行按钮。
```

纯文本块解决的是「这段话看起来像代码，但不该被运行」的场合。只读块则相反：语言标签是 Python，解析器知道它是 Python，我们却标成不执行。用来标出这个环境做不到的事，比把做不到的事写成一个会失败的可运行例子更诚实。失败的例子会把读者的注意力吸到回溯上，而这里要说的是边界本身。下面这段若真的去访问网络，解释器没有那条路，教程就不该假装它能成功。

```python norun title="不执行"
# 只读示例：本环境没有网络，不要在可运行代码里访问外网。
# import urllib.request
```

只读不是为了少写测试。它是一种声明：注释里的那条 import 不在本课程的能力范围里。你若把它改成可运行再补上真正的请求，得到的不是一个更完整的借书台，而是一次在没有出口的进程里失败的尝试。失败信息会谈论网络，不会谈论借还。那会把这一章带离它要建立的规矩。

能跑的块必须把结果写出来。引号不属于输出。你若把引号也写进期望，测试会对不上，因为终端里没有那些引号。这和抄写借条是一样的：引号是你做的记号，不是条子上的字。先看一个最小的可运行例子，它不读输入，只确认解释器肯把中文送到终端。

```python run expect="你好" title="第一声问候"
print("你好")
```

print 会在末尾加换行。括号和引号留在源码里。终端上只有你好这两个字，外加换行。源码是 UTF-8，终端也按 UTF-8 显示，你不需要为这两个汉字写转义。长度和切片以后会按不同的单位计算，那是字符串那一章的事。现在只要确认：引号里面的汉字会原样出现，引号本身不会。

同一章也可以放下一种别的语言。下面这块是 Ruby。点它的 Run，侧栏会改选 Ruby，第一次使用还要下载 Ruby 的运行时。进度出现在按钮旁边，不写进按钮文字，免得两个 Run 一个变长、一个保持原样。下载完，终端里应当能找到那句来自 Ruby 的话。

```ruby run expect="来自 Ruby 的 42" title="跨语言示例"
puts "来自 Ruby 的 42"
```

跨语言不是装饰。它让你看见抽屉并不把整本书焊死在当前语言上：运行时跟着代码块走。Python 的进程和 Ruby 的进程是两次启动。你不会在 Ruby 里看见刚才那个 print 留下的名字，Ruby 也不认识 Python 的 f 字符串。42 在这里只是一句话里的数字，不是一个要在两种语言之间传递的对象。没有任何共享内存把 Python 的借书单递到 Ruby 手里。若你希望两种语言描述同一位读者，就把读者的名字分别写进两块源码。这看起来笨，它避免了一种更糟的设计：教程作者在后台维护一张跨语言的表，读者却以为是语言自己记住了。

回到 Python。下面两块故意写成前后相承的叙事，可它们在运行时毫不相承。第一块把柜台名放进名字 `desk` 并打印。第二块若直接打印 `desk`，会得到 NameError，因为第二块是新进程，那个名字没有被写进这一块。所以第二块自己再绑定一次，并改用读者的名字来证明「上一块的状态没有流过来」。你在阅读时会觉得阿宁还站在东柜，那是文章的连贯，不是进程的连贯。

```python run expect="东柜" title="这一次的柜台"
desk = "东柜"
print(desk)
```

```python run expect="林夏" title="下一次仍要自己带上名字"
reader = "林夏"
print(reader)
```

把这两块连起来看，叙事是：东柜今天由某位馆员值班，来借书的人是林夏。程序却没有这条叙事。每一块只知道自己字面写下的东西。这是白纸原则最容易被忽略的一种疼：文章可以用「接着」这种词，进程不会。后面每一章的例子都会沿用借书台、林夏、同一批书名，那是为了让你的注意力放在语言机制上，而不是每次都先记住一套新的业务。沿用发生在纸面上。运行时每次都要把这些名字再写出来。

还有一种块会停住。死循环在控制流那一章会出现，并标成跳过冒烟，免得自动测试一直等。你在抽屉里仍可以手动运行它，但要准备自己停掉，再去跑下一块。确认停掉之后，下一例才会真正开始。这套交互现在先记住一句就够：教程里的「能跑」不等于「冒烟测试会跑」。能跑指的是它具备启动进程的资格；冒烟会跳过那些设计上不结束的进程。

失败也是白纸的一部分。语法错误会让进程以非零退出码结束，终端里是解释器的回溯，不是你 print 的句子。这时候期望对不上，因为根本没有走到 print。先看是哪一行解析失败，再谈输出。把一段能运行的代码改出一个缩进错误，是认识这个环境最快的办法：你立刻能分清「程序说话」和「解释器抱怨」。缩进错误的具体形状留到下一章。这里要建立的是阅读回溯的顺序：错误类型、文件里的行、那一行附近你刚才改过的字符。

输出里偶然出现的地址和当前时间不适合当期望。内存地址每次进程都可能不同，时钟每秒都在走。本课程的例子若需要「随机」，会把种子写死，并且往往不打印随机数本身，只打印由它决定的、稳定的结论。这一章的例子连随机都不需要。它们打印的是源码里已经写明的汉字。你核对时可以用眼睛对，也可以相信期望子串：只要那几个字出现在输出里，这一块就算说到做到。

工具栏上的 Run 和代码块上的 Run 外观相同，职责不同。工具栏只跑编辑器里当前这份文本，不会替你换语言，也不会把文档里的示例贴进来。你在编辑器里改了一下午的草稿，和某一块示例，是两份文本。Run 示例之前，编辑器里你自己的内容会先被记住，便于你之后撤销回来。这个记住发生在编辑器，不发生在 Python 进程里。不要把它理解成「解释器帮我保存了变量」。保存的是你的草稿字节，下一次进程启动时仍然从那一块的源码重新读。

按钮上的字写的是当前语言的快速入门，不是课程编号。打开抽屉，标题和按钮用的是同一个名字。内部的目录 id 仍然是 python，那是给程序看的，不出现在按钮上。你切换到别的语言，按钮上的语言名会跟着变。若那一门的书还没写完，界面会告诉你即将推出，那是因为目录还空着，不是因为运行时不存在。Python 这一门的运行时就是这一次次新鲜的 CPython 进程。

把三件事留下。每一次 Run 都是新进程，示例必须自洽。纯文本、只读、可运行三种块各有用途，只读用来标出做不到的事，例如没有网络。跨语言块会换运行时，甚至触发下载，按钮本身仍然写着 Run。下一章不再谈抽屉，只谈如何把一句话送到终端，以及为什么空格和缩进在 Python 里不是排版。

## 小结

这本快速入门不提供一个越聊越记得你的解释器。它提供很多次很短的进程，每次只对一块完整的源码负责。这个选择让示例可以离开抽屉仍然成立，也让你无法把「我刚才定义过」当成程序的一部分。纯文本块没有运行时，只读块拒绝执行做不到的事，可运行块用打印出来的字接受核对。Ruby 那一块说明运行时跟着代码走，不跟着上一块的变量走。
