借条要离开这一次进程，交给另一块代码，就不能只靠内存里的字典。另一块是另一次启动，上一章已经把这个限制说成白纸。白纸并不禁止你把字典写成一段文本，再在同一次进程里读回来，证明这段文本自己携带了读者和书名。json 就是这种文本的一种格式。它随 CPython 一起来，不需要安装。滞纳金则是另一件小事：天数乘以单价常常得到小数，柜台只收整数分，math.ceil 负责向上收。这一章只用这两件标准库里的工具。不用网络，不装第三方包，也不把随机和日期拉进来凑数。

import 把模块的名字引进当前这次进程。`import json` 之后用 `json.dumps` 和 `json.loads`。dumps 从对象做出字符串，loads 从字符串做回对象。名字是复数形式的 dump 加上 s，表示对字符串而不是对文件。对文件的 dump 需要一个打开的文件对象，本课程不把借条留在磁盘上给下一次运行，所以只用字符串这一对。每一块需要 json 时自己 import。上一块 import 过，下一块不会记得。

字典里的键在 json 里必须变成字符串。我们的索书号本来就是字符串，读者名和书名也是。整数天数可以放进 json，读回来仍是整数。元组会变成列表，因为 json 没有元组这种类型。读回来的列表和你当初放进去的元组不是一回事，若你依赖元组不可变，要在读回来之后自己再转一次。这一章的借条只用字典、字符串和整数，绕开这个损耗。布尔和 None 也能往返，它们在文本里写成 true、false 和 null，大小写和 Python 不同。loads 会把它们变回 Python 的 True、False 和 None。你自己拼接一段看起来像 json 的文本时，若写成 Python 的 True，loads 会失败。让 dumps 去产生文本，不要手写。

汉字必须原样出现在文本里。dumps 默认会把非 ASCII 字符写成 `\u` 转义，功能上仍能 loads 回来，可你打印这段文本时看见的不是借条，而是一串数字。把 `ensure_ascii=False` 传进去，文本里就是汉字。下面这一块把林夏和小径写进字典，变成文本，再读回来，打印读者。期望是林夏，证明往返没有把读者弄丢。

```python run expect="林夏" title="借条写成文本再读回"
import json
slip = {"reader": "林夏", "book": "小径", "days": 3}
text = json.dumps(slip, ensure_ascii=False)
print(text)
restored = json.loads(text)
print(restored["reader"])
```

打印 text 会看见花括号和引号，那是 json 的样子，不是 Python 字典的样子。引号在 json 里总是双引号。键的顺序按字典的插入顺序写出，3.11 的 json 模块保持这个顺序，所以同一份 slip 每次 dumps 的文本一致。不要把键排序与否当成业务。读回来用键取读者，不依赖顺序。若文本被改坏，loads 抛出 json.JSONDecodeError。那是异常，上一章的办法可以接住它并印出类型名。借书台不该在文本坏了的时候猜一个空读者。

```python run expect="JSONDecodeError" title="坏掉的文本不要猜"
import json
try:
    json.loads('{"reader": 林夏}')
    print("竟然成功")
except json.JSONDecodeError as exc:
    print(type(exc).__name__)
```

这一段坏在汉字没有放进引号。成功的那句 print 不会执行。类型名足够让期望稳定，不必把整段错误信息抄进期望。接住之后进程成功。不接住，这一块就无法作为可核对的例子。和列表当键时的处理是同一策略：故意的失败要变成可见的类型名。

json 不是 Python 源码。不要用 eval 去读借条。eval 会执行文本里的任意表达式，而借条将来可能来自读者输入。即使在这门课里文本是你自己 dumps 出来的，习惯也该定成 loads。loads 只认数据，不认函数调用。这个限制正是你要的。它换来的是类型比 Python 窄：不能直接表示元组，不能表示自定义的借书对象。对象要变成字典再 dumps。类那一章会有借书对象，到那时转换是显式的几行，而不是 json 突然学会了你的类。

滞纳金用 math。`import math` 之后调用 `math.ceil`。单价 0.4 元，逾期 3 天，乘积是 1.2。柜台不收零头以下的小数，向上收到 2。ceil 的返回是整数，不是仍带着小数的浮点。直接 int(1.2) 会截成 1，那是向零砍掉小数，和「向上收」不是同一种规则。借书台若用 int 截断，会少收。少收在一次运行里只差一分的样子，规则错了却会在每一张条子上重复。下面把公式写在源码里，不把 2 这个结果写死成唯一的数而不写来源。打印的是 ceil 的结果。

```python run expect="2" title="滞纳金向上取整"
import math
rate = 0.4
days = 3
fee = math.ceil(rate * days)
print(fee)
```

1.2 这种小数能被二进制浮点比较好地表示，这个例子才敢直接乘。单价若是 0.1，乘以某些天数会得到一个略小于理论值的浮点，ceil 可能仍然碰巧正确，也可能在边界上让你吃惊。更稳的柜台算法是全程用分做整数：单价 40 分，天数 3，乘积 120 分，再按元显示。整数路径不需要 ceil。这一章仍然展示 ceil，是因为你总会遇到已经是浮点的测量，需要知道向上和截断的差别。知道之后，能改成整数分就改成整数分。math 里还有 floor 和标准的四舍五入途径。滞纳金选 ceil，是业务选择，不是 math 只有这一个函数。

不要为了取整去安装别的包。标准库里的 math 已经在进程里。没有 pip，也没有网络可以去下载一个「更好的小数库」。做不到的事用只读块记一笔，避免后面为了凑工具去写一个会失败的请求。

```python norun title="不走网络"
# 本环境没有网络，也不能 pip 安装第三方包。
# 滞纳金和借条只用 math 与 json。
```

只读块里的话是边界。json 和 math 是边界里面的东西。urllib、requests、任何需要出口的客户端都在边界外面。日期库 datetime 虽然也在标准库里，这一章不用它来算逾期，因为「今天」会让输出随运行的日期改变，期望就无法固定。逾期天数在例子里是写死的整数 3。随机数同样不用。需要稳定，就把数据写在源码里。

把两件工具放进同一次盖章。先算费用，再把读者、书、费用放进字典，dumps 之后读回来，打印费用。这样 json 里的整数费用和 math 的结果是同一个数。若 dumps 之前不小心把费用转成了带单位的字符串「2元」，读回来就不是整数，后面的加法会失败。类型要在进 json 之前定好。文本里的汉字用 ensure_ascii=False 保留。

```python run expect="2" title="费用写进借条"
import json
import math
rate = 0.4
days = 3
fee = math.ceil(rate * days)
slip = {"reader": "林夏", "book": "小径", "fee": fee}
text = json.dumps(slip, ensure_ascii=False)
restored = json.loads(text)
print(restored["fee"])
print(restored["book"])
```

第一行是整数 2 的文字，第二行是小径。fee 在文本里没有引号，因为它是数字；book 有引号，因为它是字符串。你打印的是读回来的对象里的值，不是整段 text。若期望写成整段 json，就要把花括号和引号都算进去，稍有空格不同就会对不上。取一个字段来核对，更接近柜台真正关心的问题：这张条子上的费用是多少。

模块的名字就是命名空间。`math.ceil` 不会和你自己的函数 ceil 撞车，只要你的函数不叫 math。若写 `from math import ceil`，ceil 就直接进入当前名字，少打几个字，也更容易在以后遮住别的 ceil。这门课在调用点保留 math. 和 json.，让人看见工具来自哪里。来源可见，比短两行更重要。标准库很大，不需要在这一章浏览完。你遇到文件路径、统计和日期时再去查对应的模块。查到的模块若会把当前时间或随机序列印出来，就要先想怎样让它在测试里稳定。想不稳，就不要把它放进可运行的例子。

json 的 loads 结果是新的对象。你修改读回来的字典，不会改动当初 dumps 的那个字典，因为它们中间隔着文本，没有共享内部的列表。这可以当作一种笨但清楚的深拷贝，前提是数据都能被 json 表示。含有元组或自定义对象时，这条路会变形或直接失败。列表套列表的借出记录若只含字符串，经 json 走一圈可以得到真正分开的副本。这比手写的逐行切片更省事，也更慢，而且会丢掉元组与整数键。知道它是转换，不是原样照相。

费用的边界要单独算一次。单价 0.4 乘以 0 天是 0，ceil 之后仍是 0，不该催出一笔一元钱。单价乘以 1 天是 0.4，ceil 到 1。若你先把单价收成整数再乘天数，0.4 会被收成 1，三天变成 3，和「先乘再收」不是同一个柜台。顺序写在源码里：先乘，再 ceil。不要把 ceil 套在单价上。math.ceil 对已经是整数的 2 得到 2，不会再加一。它只在有小数部分时才向上。这让你可以把「也许已经是整数」的结果再送进去而不必先分支。分支留给负数。负数滞纳金没有业务意义，ceil 对负数的定义是走向正无穷方向的整数，不等于「去掉小数」。不要把负数天数送进这个公式来观察语言，先在进入 math 之前拒绝小于 0 的天数。拒绝是条件，不是 math 的责任。

json 对象里的数字若大到超过普通浮点能精确表达的整数，往返可能不再是同一个值。借书台的费用是很小的整数，用 json 的数字正好。不要把索书号当成数字放进去。`I247.5` 不是合法的 json 数字，索书号必须是字符串。把号写成整数 247 会丢掉字母和层次，读回来无法对上架子。字段的类型是契约：reader 和 book 是字符串，fee 和 days 是整数。dumps 不会替你检查契约，它只负责把 Python 对象写成它认得的文本。契约靠你在放进字典之前遵守。

模块只在这一次进程里存在。你在交互草稿里试过 `import math`，下一份可运行块仍要自己写 import。这不是 math 特殊，是每次 Run 都换进程。把 import 放在用到它的块的顶部，读的人不用向上翻章。循环里面反复 import 没有必要，解释器会复用已经载入的模块，但写在循环里会让人以为载入和滞纳金计算绑在一起。载入一次，计算多次，import 留在块的最上面。

dumps 还有一个容易忽略的默认：键必须是字符串，Python 的字典若用了整数键，dumps 会直接失败，而不是把 12 收成 "12"。索书号因此从一开始就用字符串保存，不要先用整数序号再指望 json 帮忙转换。转换要写，就在放进字典之前用 str 写明。写明的转换会出现在源码里，失败也会出现在你自己的那一行，而不是出现在报告函数的深处。

## 小结

json.dumps 和 json.loads 在字符串和字典之间往返。汉字要传 ensure_ascii=False 才直接出现在文本里。坏文本抛出 JSONDecodeError，不要用 eval。math.ceil 向上取整，和 int 的截断不同；能用整数分就不必依赖浮点。这两件都在标准库里。本环境没有网络，也不要 pip。日期和随机若会让输出不稳定，就不要放进可核对的例子。
