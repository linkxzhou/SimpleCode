函数那一章的盖章每次收到书名和名单两个参数。参数一多，调用处就得记住顺序。借书台更自然的说法是：这张条子自己知道读者是谁、书是哪一本，你让它报出一行文字。类就是用来做出这种条子的。你定义一次 Slip，然后做出两张具体的条子，一张给林夏的小径，一张给周予的海边。两张条子的数据不该缠在一起。缠在一起的方式很具体：把列表写在类上，而不是写在每一张条子上。self 就是「这一张」的那个名字。

class 下面写函数，第一个参数按约定叫 self。调用时你不把 self 递进去。`slip.line()` 这种写法会把 slip 自己作为第一个参数传给 line。解释器替你做了这件事。你若把定义写成没有 self 的 `def line():`，调用 slip.line() 时会因为多出来的那个实例而 TypeError。这和普通函数不同。普通函数的参数个数就是你调用时要给的个数。方法多出一个被点号左边的对象占用的位置。self 这个名字不是关键字，你换成别的也能运行，但换了之后下一班的人会读不懂。保持 self。

`__init__` 在你写出 `Slip("林夏", "小径")` 时被调用。它的工作是把这一张条子的数据绑到 self 上。`self.reader = reader` 的意思是：这个实例的 reader 指向传入的字符串。参数名和属性名可以相同，点号让它们分开。没有点号的 reader 是参数，有点号的是实例上的属性。忘记写 self. 就会变成给本地名字赋值，实例上什么都没留下，方法再去读 self.reader 时会 AttributeError。这个坑发生在初始化，不发生在类的名字上。

```python run expect="林夏《小径》" title="这一张条子报自己的行"
class Slip:
    def __init__(self, reader, book):
        self.reader = reader
        self.book = book

    def line(self):
        return f"{self.reader}《{self.book}》"

slip = Slip("林夏", "小径")
print(slip.line())
```

line 使用的是这一张的 reader 和 book，不是某个全局变量。再做一张条子，第一张的行不该变成周予。下面印出两行，证明两个实例各有各的属性。

```python run expect="林夏《小径》" title="两张条子互不覆盖"
class Slip:
    def __init__(self, reader, book):
        self.reader = reader
        self.book = book

    def line(self):
        return f"{self.reader}《{self.book}》"

first = Slip("林夏", "小径")
second = Slip("周予", "海边")
print(first.line())
print(second.line())
```

第一行仍是林夏的小径，第二行是周予的海边。属性存在实例上，查找时先看实例，再看类。你在某张条子上写 `first.note = "加急"`，只有 first 有 note，second 没有。这和字典按键存储很像，实例内部确实用一种字典保存你赋给 self 的名字。知道这一点，就不会去问「类怎么知道林夏这四个字」。类不知道。是 first 这个对象知道。

类的属性则是所有实例共享的。把 `books = []` 写在 class 下面、方法外面，这个列表属于类。`__init__` 里若写 `self.books.append(book)`，查找 books 时实例上没有这个名字，就会找到类上的那一个列表，append 改的是它。第二张条子创建时，列表里已经有第一本书。下面印出第二张条子看见的长度。长度是 2。这就是共享名单的坑，和函数默认参数是同一类问题：可变对象活在比「这一张」更长的地方，又可以被就地修改。

```python run expect="2" title="类上的列表被两张条子一起改"
class Slip:
    books = []

    def __init__(self, book):
        self.books.append(book)

Slip("小径")
second = Slip("海边")
print(len(second.books))
```

修法是在 `__init__` 里写 `self.books = [book]`，或者每张条子只保存自己的 book，根本不维护一张总名单。总名单若需要，就放在柜台对象上，由柜台持有一个列表，条子不要用类属性去充当全局变量。下面每张条子只在自己的列表里放自己的书，第二张的长度是 1。

```python run expect="1" title="名单做在实例上"
class Slip:
    def __init__(self, book):
        self.books = [book]

Slip("小径")
second = Slip("海边")
print(len(second.books))
print(second.books[0])
```

第二张的名单里只有海边。第一张若还留着名字，它的名单里只有小径。类上不再有那个会长大的列表。不可变的类属性，例如 `counter_name = "东柜"`，共享通常是你想要的：柜台名对所有条子相同，而且没有人会 append 它。共享出问题的条件仍然是：那份数据可变，并且你以为它是每一张私有的。

方法的第一个参数必须是实例，还有一个例外形状：类方法和静态方法。这门课的借条用不上它们。若你看见没有 self 的方法却通过实例去调，先检查是不是漏写了参数，而不是先去学装饰器。装饰器那一章会包函数，不要在这里提前把 `@staticmethod` 当成省略 self 的官方办法。省略 self 的官方办法是确认这个函数根本不需要实例上的数据，那它也许不该写在类里面。

打印实例时，默认的文字含有类名和内存地址。地址每次进程都可能不同，不能放进期望。定义 `__str__` 来提供给人看的文字，print 会调用它。`__repr__` 提供给调试看的文字，在交互环境里直接敲对象名时用。两者可以相同，也可以让 repr 更接近源码。下面让 `__str__` 返回和 line 一样的句子，这样 print(slip) 的输出稳定。

```python run expect="林夏《小径》" title="打印时用自定义的文字"
class Slip:
    def __init__(self, reader, book):
        self.reader = reader
        self.book = book

    def __str__(self):
        return f"{self.reader}《{self.book}》"

print(Slip("林夏", "小径"))
```

不要在 `__str__` 里打印地址或当前时间。不要把 `__str__` 写成会修改实例的函数。转成文字应当是查询。查询不该盖章。若盖章和查询混在一个方法里，你为了看一眼输出就改变了名单，测试会变得难以重复。

继承可以让还书条子共用借书条子的读者和书名，再多一个天数字段。子类的 `__init__` 要自己调用父类的初始化，否则父类负责的属性不会出现。调用写成 `super().__init__(reader, book)`。漏掉这行，再读 self.reader 就是 AttributeError。继承不是复制粘贴。它是查找链：实例上没有的属性，去类上找，类上没有，去父类找。方法也走这条链。子类定义了同名的 line，就用子类的，这叫覆盖。覆盖时若还想要父类的句子，就在子类方法里调用 super 的版本，再拼接。不要复制父类的 f-string 到子类里各改一点，两处会再次分叉。

这一章的可运行例子不展开一个长长的继承树。借书台只有一种条子时，硬造一个父类「纸」没有收益。继承在第二种条子出现、并且它确实是第一种的特例时才划算。用组合也可以：还书记录里放一张 Slip，而不是去继承它。组合让「有一张条子」这个关系写在属性上，比「是一种条子」更不容易把初始化链写断。两种做法都合法。先把 self 和类属性的共享写对，再决定要不要子类。

相等也要提一句。两张内容相同的条子，`==` 默认比较是不是同一个对象，不比较读者和书名是否一样。`Slip("林夏", "小径") == Slip("林夏", "小径")` 是 False。若业务上内容相同就算同一张，需要定义 `__eq__`。定义了相等却不定义哈希，这种对象就不能再当字典的键。借条要不要当键，通常不要，键用索书号更合适。所以这一章不为了相等去实现一整套比较。知道默认的 `==` 问的是身份，就不会在测试里用它判断两张新做成的条子内容是否一致。判断内容，就读属性，或者比较 `__str__` 的结果。

把类想成做条子的模具，把实例想成模具压出来的那一张。模具上可以刻柜台名这种大家都一样、又不会被改掉的字。每一张上的读者必须在压出来的时候写到 self 上。列表这种会生长的记录若刻在模具上，所有新条子都会往同一张纸上继续写。刻在每一张上，纸才是分开的。

属性的查找顺序会让类上的名字遮住你的眼睛。某一张条子还没有 `self.note` 时，若类上恰好有同名的字符串，读取 `slip.note` 会得到类上的那个字符串，不会得到 AttributeError。你以为这张条子有备注，其实备注是模具上的默认句。一旦你对这张条子写了 `slip.note = "加急"`，实例上就有了自己的 note，以后读取不再看见类上的那句。于是第一张被改过的条子和其余没被改过的条子，读到的来源不同。默认句若是不可变的字符串，这种遮盖至少不会让人 append。默认句若是列表，没写过自己的 note 的那些条子会共享类上的列表，一改全改；写过 `self.note = []` 的那张则独立。读代码时看见 `self.books.append`，先问 books 最初是在 `__init__` 里赋给 self 的，还是只在类上出现过。只在类上出现过，就是共享。

方法里调用另一个方法，写成 `self.line()`，不要写成 `line()`。没有 self 的调用会去找一个全局函数，全局没有这个名字时是 NameError，即使类里明明定义了 line。点号是在说「用这一张的查找链」。查找链能找到被子类覆盖的版本。你在父类方法里写 `self.line()`，而子类覆盖了 line，运行时走的是子类，这通常是你想要的多态。你若把父类的 line 函数对象提前取出来再调用，可能会绕过子类，也可能在参数上少了实例。初学先坚持通过 self 调用。

打印用于调试时，优先 `__str__` 里的稳定句子，而不是把整个实例丢进默认格式。默认格式里的地址在两次运行之间会变，期望对不上，你还会误以为程序不稳定。地址变了不代表读者变了。要核对的是读者和书名。把这两项写进 `__str__`，测试和馆员看的是同一句话。

类的主体在定义时执行，和函数体不同。class 下面的 `books = []` 会在 class 语句执行时就创建一个列表。方法体则要等到调用。所以共享列表的诞生很早，早于任何一张条子。你不能指望「还没人借书，类上的列表就是每次新建」。它只新建那一次。这和函数默认参数在 def 时创建是平行的两件事。一个挂在函数上，一个挂在类上。看见可变对象被放在这两处，就假设它会被所有调用、所有实例碰到，直到你看见每一次调用或每一个 `__init__` 里都有新建。

两张条子的方法是同一份函数，不是每张条子各抄一份代码。不同的是调用时传进来的 self。你不会因为做了第二张条子就多占一份 line 的字节码。占多份的是实例上的读者和书名。这个分工让类适合描述许多张结构相同的条子，而不适合当成「只使用一次的脚本」。只有一张条子时，一个字典一样能装读者和书名。类的价值在第二张出现、并且你希望两张都长着同一组方法的时候。东柜至少会借出两本，所以模具是划算的。

## 小结

方法的第一个参数 self 就是点号左边的那张条子。`__init__` 里用 `self.reader = reader` 把数据留在实例上。两张条子因此可以各报各的行。写在类上的列表会被所有实例 append 到同一处，第二张看见的长度是 2。把列表赋给 self，才是这一张私有的。`__str__` 用来提供稳定的打印文字，不要把地址印进期望。
