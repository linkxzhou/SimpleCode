类型标注不改变 CPython 的运行结果，它是给人和检查工具看的说明。本环境不会做类型检查，写错标注程序仍会运行。

最后用一个固定棋盘判断井字棋胜负。输入可以换成别的九格，但示例本身不依赖随机。

```python run expect="42" title="标注"
def add(a: int, b: int) -> int:
    return a + b

print(add(20, 22))
```

```python run expect="4.0" title="列表标注"
def average(nums: list[int]) -> float:
    return sum(nums) / len(nums)

print(average([2, 4, 6]))
```

::: note
3.11 可以直接写 list[int]。标注不会在运行时拒绝错误类型。
:::

```python run expect="X" title="井字棋"
def winner(cells: str) -> str:
    lines = (
        (0, 1, 2), (3, 4, 5), (6, 7, 8),
        (0, 3, 6), (1, 4, 7), (2, 5, 8),
        (0, 4, 8), (2, 4, 6),
    )
    for a, b, c in lines:
        if cells[a] == cells[b] == cells[c] and cells[a] != ".":
            return cells[a]
    return "平"

print(winner("XXXOO...."))
```

小项目把前面的类型、分支、函数和输入输出放进一个能读完的脚本。范围要小：一次运行、标准输入、标准输出、没有网络、不保留文件。待办清单、计分、简单的棋盘判断都适合，因为规则可以用纯函数表达，测试只看打印出来的文本。

先写数据怎么表示。一条待办可以是字典，也可以是只有两个字段的小类。字段少就用元组或字典，字段会继续长再引入类。然后写「一条命令进来，状态如何变」的函数，最后才写读输入的循环。这样核心逻辑不依赖 input，你可以在函数里直接传入字符串做试验。

输入按行处理。strip 去掉首尾空白，split 最多分成命令和正文两段，避免正文里的空格被切碎。空行直接跳过。未知命令打印一句固定的提示，而不是抛到栈顶，因为用户打错字是预期内的事。

结束条件用输入结束（EOF），不要写死循环等一个永远不来的命令。文档运行会在样例输入之后送上 EOF。你自己在终端里可以按 Ctrl-D（macOS / Linux）结束输入。打印结果时每一行都带上稳定的前缀或固定格式，后面的人才能用子串做自动检查。

项目的主循环尽量短。读一行、分给函数、打印函数的返回值。函数返回文本而不是自己 print，测试时就可以直接调用函数，不必模拟输入。文档里的完整示例仍然从 stdin 读，是为了让 Run 按钮的体验和命令行一样。

拆分命令时，如果行里没有空格，split 的结果只有一段。访问第二段之前先看长度，否则抛 IndexError，用户只是忘了写正文。提示语固定成「需要正文」这一类短句，期望输出才稳定。

状态放在循环外面的列表里。放在函数的默认参数里会跨调用残留，那是默认参数那一章的坑，不要在项目里再踩一次。进程结束列表就没了，这是环境限制，不是 bug。想保存到磁盘，只能在同一次运行里写文件再读回，下一次 Run 看不到。

输出格式先定再写。例如每行一个标题，或者第一行是数量、后面每行一条。自动测试只检查子串，但你自己阅读终端时，固定格式能一眼看出少了一条还是多了一条。

## 最佳实践

- 把规则写成不读输入的函数，循环只负责取行和打印。
- 命令拆分限制次数，保留正文里的空格。
- 未知命令给出固定提示，不用异常充当正常分支。

## 小结

小项目限制在一次运行和标准输入输出之内。先定数据，再写纯函数，最后用按行循环把命令接起来。

## 常见错误

- 以为标注会在运行时拒绝错误类型。CPython 默认不检查，3 仍然可以传给标注成 str 的参数。
- 井字棋只查一行。对角线和列也要列进胜负组合。
