墙上的借出名单按顺序放着，找一本要从前看到后。索书号一旦固定，更好的问法是：这个号现在在谁手里。字典就是为这种问法准备的。你给它一个键，它给你对应的值。东柜的键用索书号字符串，值用读者的名字。同一批书仍然是小径、海边、夜航，只是这一章不再靠它们在列表里的位置，而靠写在书脊上的那串号。

字典用花括号写出，每一对是键、冒号、值。空字典写成 `{}`，不要写成 `[]`，那是空列表。取值为 `desk[key]`。键存在就得到值；键不存在就抛出 KeyError，进程会失败。这个失败是字典在拒绝猜。它不给你一个默认的空名字，因为空名字看起来像一位真的读者，只是字少。你若确实想在缺失时得到一个备用说法，用 get，并把备用说法写在参数里。get 在键缺失时返回你给的备用值，不抛异常。备用值要选一个不可能和真读者混淆的句子，例如「不在架」，不要选空字符串。空字符串可能是某条记录还没填名字，和「根本没有这个号」分不清。

键必须可哈希。解释器要能根据键算出一个稳定的位置，并且在键放进字典之后，这个位置不能因为键的内容被修改而失效。整数、字符串、布尔、元组这些不可变对象可以当键。列表不行，它还能 append。你把列表放进方括号里当键，在构造字典的那一刻就会得到 TypeError，信息里会提到 unhashable。这个错误不该让整块示例以非零退出码结束，否则我们无法用期望去核对错误的类型。把它放进 try 里，打印异常的类型名。打印类型名而不是整段英文信息，是为了不把期望绑在某一句英文的措辞上。类型名 TypeError 在 3.11 里是稳定的。

先看成功的查找。索书号 `I247.5/12` 对应林夏。键是字符串，和书名「小径」不是同一个东西。书名给人读，索书号给字典用。两者可以同时出现在值里，但这一章的值先只用读者名，让键的规则单独显现。

```python run expect="林夏" title="用索书号找到人"
desk = {"I247.5/12": "林夏", "I247.5/18": "周予"}
print(desk["I247.5/12"])
```

方括号里的键必须写完整。少一个字符就是另一个键，会 KeyError，不会近似匹配。字典不做「差不多的索书号」。要模糊查找，你得自己遍历所有键，那是另一段循环，字典不会偷偷帮你做。精确，是用键换值这一设计的交换条件：换来的是不必扫描整面墙。

缺失的键用 get。下面问一个架上没有的号，备用说法是不在架。注意 get 不会把这个备用说法写进字典。下一次再 get，仍然缺失。若你希望缺失之后字典里就有了这条记录，那是赋值，不是 get。两种动作不要并成一句「查一下」。

```python run expect="不在架" title="没有这个号"
desk = {"I247.5/12": "林夏"}
print(desk.get("Z9", "不在架"))
print("Z9" in desk)
```

第二行是 False。`in` 对字典问的是键，不是值。林夏在不在值里，`in` 不会告诉你。要问值，得看 `desk.values()`。这个不对称是有原因的：键是用来定位的，值允许重复，两位读者可以同名，定位却不该含糊。用 `in` 找读者名会得到假的安心，因为你问错了方向，结果是 False，你以为没有这个人，其实人在，只是他不是键。

现在看列表当键。键是 `["小径", "海边"]`，一个人想用「这一批书」当作一条记录的索引。列表可以改，所以解释器拒绝。我们接住 TypeError 并印出类型名。except 里不要再抛出去。这一块的进程应当成功，输出里有 TypeError 这个词。

```python run expect="TypeError" title="列表不能当键"
try:
    desk = {["小径", "海边"]: "林夏"}
    print(desk)
except TypeError as exc:
    print(type(exc).__name__)
```

若把列表先放进元组，键就合法：`{("小径", "海边"): "林夏"}`。元组建好之后不能 append，哈希才有意义。代价是你不能在这条记录放进字典之后再往书单里加一本。要加，就做一个新元组，删掉旧键，放上新键。这比列表麻烦，麻烦是故意的。允许就地修改的键会让字典内部的位置和键的内容对不上，查找会找不到明明还在的记录，或者撞上别的记录。拒绝列表，是为了避免这种更难解释的丢失。

元组里如果又套了列表，整个元组仍然不可哈希。可哈希要求它的内容也都能哈希。`("小径", ["东柜"])` 当键一样会 TypeError。坑不在圆括号的形状，而在里面有没有可变对象。检查键时看它最终是不是全部由不可变的东西组成。

赋值 `desk[key] = value` 在键已存在时换掉值，键不存在时新增一对。它不返回有用的值。下面先记录林夏借走小径的号，再把同一号改成周予，表示过户。打印只出现周予。旧值被覆盖，不是被追加。字典的一个键只对应一个值。若一个号要记住先后两位读者，值本身应是一个列表，由你 append。那时要注意：值的列表是可变对象，两个键若指向同一个列表，append 会同时改变两边。这和列表那一章的共享是同一个坑，只是共享藏在值里，不在键里。

```python run expect="周予" title="同一个号只留当前这位"
desk = {"I247.5/12": "林夏"}
desk["I247.5/12"] = "周予"
print(desk["I247.5/12"])
print(len(desk))
```

长度仍是 1。覆盖不是新增。你若希望留下林夏的历史，就不要覆盖，把值做成列表，或者换一个新键，例如在键里带上日期。键的设计决定了你能问什么。只以索书号为键，就只能问「现在谁拿着」。既要问现在又要问历史，一个字符串键不够，那是数据形状的选择，不是字典方法没背全。

遍历字典默认走过键。`for key in desk` 每次得到一个索书号。值要用 `desk[key]` 再取。`items` 一次给出键和值，适合同时印号和人。插入的顺序在 Python 3.11 里会被遍历保留，这是语言现在的保证，不是偶然。尽管如此，借书台的业务不要依赖「谁先被写进字典谁就印在前面」来表示催还的优先级。优先级若重要，就放进值里，另写排序。顺序保证让程序的输出稳定，便于测试；把它当成业务规则，会在某一次你用不同顺序构造字典时打乱催还。稳定和规则是两件事。

删除用 `del desk[key]` 或 `pop`。pop 交回被删的值，键不存在时可以给一个备用，免得 KeyError。del 在键不存在时抛异常。清点时若不确定号还在不在，先用 `in` 或用 pop 的备用值。不要为了删除去捕获所有异常，那样会把类型错误也吞掉。这一章捕获 TypeError 是因为我们故意制造它，并且只捕获这一种。

值可以是字典。一层索书号指向一个小字典，里面再放读者和应还日期。取的时候连续用两次方括号。中间任何一层的键缺失都会 KeyError。这种嵌套适合固定的几项信息，不适合无休止地加深。深了之后，复制时又会遇到浅拷贝：外层字典的 copy 方法只做浅层，内层字典仍共享。和列表的切片是同一类限制。需要完全分开时，逐层做新字典，或者等标准库那一章用 json 走一遍文本，再读回来，得到的是新的结构。json 那条路有类型上的代价，这里先不走，只记住浅拷贝不够。

最后把不能当键的和能当键的放在一次对照里。字符串键成功取出林夏；列表键失败，类型名被印出来。对照放在同一进程里，是为了让你看见失败被接住之后，后面的语句仍然可以运行。接住不是把错误藏起来了事，这一块把类型名交给了输出，读者能核对。若 except 下面只有 pass，运行会成功，输出却是空的，测试和馆员都看不见发生过 TypeError。那就不是展示，是沉默。

```python run expect="TypeError" title="先查到人，再拒绝名单当键"
desk = {"I247.5/12": "林夏"}
print(desk.get("I247.5/12", "不在架"))
try:
    bad = {["小径"]: "林夏"}
    print(bad)
except TypeError as exc:
    print(type(exc).__name__)
```

第一行是林夏，第二行是 TypeError。get 用了一个存在的键，所以备用说法不会出现。这让你看清 get 的备用只在缺失时启用。列表键的失败不影响已经建好的 desk，因为异常发生在另一条语句上，desk 的名字仍然指向原来的字典。除非你在 try 里先把 desk 重新绑定了，再失败。写 try 时注意失败点之前有没有把旧名字盖掉。

`setdefault` 和 get 不同。它在键缺失时把备用值写进字典，再返回这个值。若备用值是一个新列表，缺失的索书号会因此拥有自己的列表，方便你随后 append。若键已经存在，setdefault 返回旧值，不会用备用值覆盖。坑在于备用列表在调用 setdefault 之前就已经被创建。你若把同一个列表对象传给两次 setdefault，两个缺失的键会共享它。写成 `desk.setdefault(call, []).append(reader)` 时，空列表字面量在每一次执行这行时都新建，所以不共享。把空列表先放进一个名字再传两次，就共享。这和函数默认参数的时机很像，只是创建发生在调用表达式里，不发生在 def。看备用对象是不是每一次都新做出来的。

两个字典合并时，同样的键只能留一个值。`{**old, **new}` 或 `|` 都会让右边覆盖左边。借书台若用合并表示「下午的登记压过上午」，覆盖是对的。若两边都要保留，值就得是列表，合并之前先把两边的列表接成新列表，而不是让后一个读者把前一个冲掉。合并做出新字典，不修改 old，除非你用的是就地更新的方法。`update` 就地写入，所有指向 old 的名字都看得见。又是标签和对象的差别：合并运算符移动的是一个新对象上的内容，update 改的是原来的对象。

键的比较用 `==`，不是用身份。字符串 `"I247.5/12"` 即使是重新拼接出来的，只要字符相同，就能取到林夏。这是你想要的。你不需要保存当初那个字符串对象。列表当键被拒绝之后，不要改用「把列表转成它的字符串形式」当键来投机，`str(["小径"])` 带上括号和引号，和书名本身不同，也和读者输入不同。真要复合键，用元组。

## 小结

字典用键取唯一的当前值。字符串和元组可以当键，列表不行，构造时会 TypeError。缺失键用方括号会 KeyError，用 get 可以交回你写明的备用说法，并且不会把备用写进字典。`in` 问的是键。覆盖赋值不增加长度。遍历顺序在 3.11 里稳定，催还的优先级仍应写在数据里，而不是赌插入顺序。
