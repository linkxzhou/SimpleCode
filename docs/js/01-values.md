`let` 可以重新赋值，`const` 不能改绑定，但对象的内容仍可改。`typeof null` 是 `"object"`，这是历史遗留，判断空值请直接和 `null` 比较。

```js run expect="string" title="类型"
const name = "Ada";
let year = 2026;
year = year + 1;
console.log(typeof name);
console.log(year);
```

```js run expect="2 1" title="交换"
let a = 1;
let b = 2;
const t = a;
a = b;
b = t;
console.log(a, b);
```

```js run expect="object" title="typeof"
console.log(typeof null);
console.log(typeof 1);
console.log(typeof undefined);
```

let 可以重新赋值，const 不能改绑定。const 的对象仍然可以改字段，因为绑定没变，变的是对象里面。var 会提升并且函数作用域很大，新代码不用它。

typeof 对数字、字符串、函数给出预期的名字，对 null 却给出 "object"。这是旧bug，判断空值请和 null 比较，不要看 typeof。undefined 表示还没有赋值，和 null 的「有意为空」不是一回事。

交换两个绑定需要第三个名字，或者用解构 [a, b] = [b, a]。解构读起来短，初学时两种都要认识。数字和字符串用 === 比较，不要用 ==，除非你正在演示类型转换。

模板字符串可以插值。示例为了少写转义，常用加号。效果一样：左边和右边都变成字符串再接上。

重新赋值和修改字段要分开说。const 挡住的是 a = 别的东西，挡不住 a.n = 1。如果你希望对象也不能改，需要冻结，本章不依赖冻结，只把绑定规则讲清楚。

typeof 的返回值全是字符串。比较时写成 typeof x === "string"，不要忘记引号。null 的 typeof 是例外，单独记一条就行，不必把它理解成「null 真的是对象」。

交换如果写成 a = b; b = a; 两个都会变成原来的 b。第三个变量或解构才能留住原来的 a。这和后面的数组没有关系，只是绑定。

let 可以重新赋值，const 不能更换绑定。const 的对象仍然可以改字段，因为绑定没变，变的是对象里面。若你希望连字段都不能改，需要冻结，本章不依赖冻结，只把绑定规则讲清楚。var 会提升并且作用域是整段函数，新代码不用它。

typeof 对数字、字符串、布尔和函数给出预期的名字，对 null 却给出 object。这是遗留行为。判断空值请和 null 比较，不要看 typeof。undefined 表示还没有赋值，和 null 的「有意为空」不是一回事。声明了 let x 却不赋值，typeof x 就是 undefined，此时没有异常。读取一个从未声明的名字才会报错。

交换两个绑定可以用第三个名字，也可以用解构一次完成。解构读起来短，两种都要认识。数字和字符串用 === 比较。== 会做类型转换，教学示例不靠它得到正确结果。模板字符串可以插值，示例为了少写转义，有时用加号，效果是先变成字符串再接上。

读示例时分开两句话：这个名字还能不能指向别的值，这个对象里面的字段还能不能改。混在一句「const 就是不能变」里，下一章改字段时就会惊讶。

## 最佳实践

- 新代码只用 let 和 const，不引入 var。
- 判断 null 用 === null，不用 typeof。
- const 对象要改字段可以，要换整个对象就改用 let。

## 小结

let 和 const 控制绑定能不能换，typeof null 是历史例外。比较值用 ===。

## 常见错误

- 用 var 并依赖提升。新代码用 let 和 const，作用域更好懂。
- const 对象就以为字段也不能改。冻结的是绑定，不是对象内容。
