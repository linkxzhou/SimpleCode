函数声明会被提升，箭头函数不会。箭头函数没有自己的 `arguments`。默认参数在调用时、且调用者没传该参数时才求值。

闭包让内部函数记住外部的 `let`。

```js run expect="42" title="两种函数"
function add(a, b = 1) {
  return a + b;
}
const mul = (a, b) => a * b;
console.log(add(41));
console.log(mul(6, 7));
```

```js run expect="1" title="计数器"
function counter() {
  let n = 0;
  return () => {
    n += 1;
    return n;
  };
}
const next = counter();
console.log(next());
console.log(next());
```

```js run expect="21" title="记忆化"
function memo(fn) {
  const saved = new Map();
  return (n) => {
    if (!saved.has(n)) saved.set(n, fn(n));
    return saved.get(n);
  };
}
const fib = memo((n) => (n < 2 ? n : fib(n - 1) + fib(n - 2)));
console.log(fib(8));
```

函数声明会被提升，同一作用域里可以先调用后定义。箭头函数和函数表达式不会提升，必须先写出值。箭头函数没有自己的 arguments，也没有自己的 this。需要剩余参数时写 ...args。

默认参数在调用方没传该参数时才计算。传 undefined 也会触发默认值，传 null 则不会。这个差别要记住，否则你以为 null 会换成默认值，结果函数收到了 null。

闭包让内层函数看见外层的 let。计数器每次调用都改同一个 n。在循环里创建闭包时，用 let 而不是 var，每一轮才有自己的绑定。

递归要有停止条件。记忆化用 Map 把算过的参数存起来。Map 的键可以是数字，普通对象的键会被转成字符串。本章的斐波那契用 Map 或对象都可以，因为键是小整数。

函数是值。你可以把它放进数组，也可以当参数传给另一个函数。这是后面 map 的基础：map 接收的就是函数。

闭包不是复制，是引用。外层 n 变了，内层下次读到的就是新的 n。计数器利用的就是这一点。如果你在内层写 let n = 1，那是一个新的局部变量，外层的 n 不会增加。

递归深度有限。能写成循环的计数不要为了形式改成递归。斐波那契这种重复子问题才值得递归加记忆。

函数声明会被提升，同一作用域里可以先调用再定义。函数表达式和箭头函数不会提升，必须先写后用。新代码如果依赖提升，读的人要来回跳，本章更推荐先定义再调用。箭头函数没有自己的 this，也不适合当需要 prototype 的构造器。回调很短时用箭头，逻辑超过一行就写成有名字的函数。

默认参数只在没传或传入 undefined 时启用。传入 null 不会触发默认值，null 会原样进来。这和「没传」不是一回事。需要把 null 也当成缺省时，在函数体里自己判断。剩余参数是一个真数组，可以 reduce。已经有数组时，调用处用展开把元素拆开，不要把整个数组当成第一个参数。

闭包记住外层变量。计数器返回的函数每次改的是同一个绑定。循环里创建函数并读取循环变量时，用 let 可以让每一轮有自己的绑定；用 var 则会都看到最后一轮。递归要有停止条件。这个环境栈不深，能写成循环就写循环。

函数是值。你可以把它放进数组，也可以传给别的函数。这是后面 map 的基础。

## 最佳实践

- 箭头函数不依赖 arguments 和 this。需要它们时用 function。
- 默认参数不要假设 null 会触发，只有省略或 undefined 才会。
- 循环里创建函数使用 let，避免所有函数看见最后一轮的值。

## 小结

函数声明会提升，箭头函数不会。闭包记住外层变量，默认参数只在没传或传入 undefined 时启用。

## 常见错误

- 在箭头函数里用 arguments。改用剩余参数 ...args。
- 递归的 const fib = (n) => fib(...) 在记忆化包装之前调用自身。上面先写成依赖外部名字的形式。
