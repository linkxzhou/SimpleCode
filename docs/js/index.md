很多人把 JavaScript 理解成浏览器里那层会改页面的胶水。打开这门课的抽屉时，这个理解要先放下。这里的引擎是 QuickJS，一次运行就是一份脚本从第一行走到最后一行。没有 `document`，没有 `window`，没有 `fetch`，也没有 npm 可以去装一个库。`import` 和 `export` 没有加载器可接，所以每一段可运行的例子都必须自己包含它用到的名字。上一段里的变量不会活到下一段，因为每一次 Run 都是一次新的执行，不是一次会话。

这个限制不是为了把语言削薄，而是为了把语言和宿主分开。浏览器给 JavaScript 的是页面、事件和网络；Node 给它的是磁盘、包和进程。QuickJS 在这个抽屉里只给语言本身。你仍然能学值、字符串、函数、对象、类、错误、迭代和微任务，因为这些不依赖页面。你学不到的是「点按钮之后」。若例子需要按钮，它就不该出现在可运行块里。只读块可以提一句那种代码为什么在这里会失败，但不要让可运行块去调用不存在的宿主。

查看结果的办法是 `console.log`。它把参数变成文字，多个参数之间放一个空格，然后换行。期望检查的是子串：输出里找得到那段文字即可，前面可以有别的行。因此教学例子优先打印短的、稳定的字符串，而不是把整个对象丢给默认格式。对象的默认打印在不同引擎里并不适合当契约。数字和标题适合。

下面先放一条阅读清单的起点。清单上的第一本书是一个字符串值，名字叫 `title`。

```js run expect="边城" title="清单上的一个标题"
const title = "边城";
console.log(title);
```

`const` 把名字 `title` 绑到值 `"边城"` 上。名字不是值，也不是类型。类型是你事后向值询问才得到的分类。`typeof title` 问的是这个值现在是什么，不是问这个格子被声明成了什么。JavaScript 没有「声明变量时选定类型、以后只能放这种东西」的格子。这是动态类型：灵活的地方在于同一个名字可以在程序的不同时刻指向不同种类的值；代价是写错种类时，引擎往往要到那一行真的执行才告诉你。静态类型的语言把一部分错误提前到运行之前，换来的是你要在每个名字旁边做更多说明。这门课的后两章会用 TypeScript 把说明写上，但在这个抽屉里那些说明会被剥掉再执行。能跑并不证明类型写对了。本章先把「值」和「类型说明」分开，否则后面的强制转换会看起来像随机故障。

用 `let` 可以改绑。改绑换的是名字指向的值，不是把原来的值改成另一个类型。字符串值本身没有被改写，只是名字不再指向它。

```js run expect="string" title="改绑之后类型跟着值走"
let entry = "边城";
console.log(typeof entry);
entry = 120;
console.log(typeof entry);
console.log(entry);
```

第一行是 `string`，因为当时 `entry` 指向标题。第二行是 `number`，因为名字改指向页数 `120`。第三行把页数打出来，确认改绑成功。若你心里仍有一个「entry 变量的类型是字符串」，第二行会让你不舒服。不舒服是对的，那个说法不适用于这门语言。更准确的说法是：`entry` 这个名字目前指向一个数字值。以前指向过字符串，那是名字的历史，不是值的属性。

两个名字可以先后指向同一个值，然后其中一个改绑，另一个保持不动。对字符串和数字这种原始值，你感觉不到「共享」和「复制」的差别，因为你没法就地修改它们。这个差别要到数组那一章才会咬人。现在先看改绑不会波及另一个名字。

```js run expect="边城" title="另一个名字仍指向旧值"
let title = "边城";
const alias = title;
title = "围城";
console.log(alias);
console.log(title);
```

`alias` 打出 `边城`，`title` 打出 `围城`。`const alias` 的意思是这个名字不能再改绑，不是这个值被冻成了常量对象。`title` 用 `let`，所以它可以改指向 `"围城"`。若你对 `alias` 再赋值，引擎会拒绝，那是名字的规则，不是字符串的规则。选 `const` 还是 `let` 是一种取舍：`const` 让读代码的人相信这个名字一直指向当初那个值，减少「它在哪一行被换掉了」的搜索；`let` 允许计数器和游标前进。两者都不表示类型。把 `const` 理解成「常量类型」会在你把 `const` 用在数组上时崩溃，因为数组的内容以后仍能被推进去。那是后面的章节，这里先把名字和值的关系说死。

还有一件容易和类型搞混的事：注释和字符串。`//` 后面到行尾不会执行。字符串里的 `//` 只是文字。期望输出里不会出现注释。你若把要打印的标题写成注释，终端会空，检查会失败。失败的原因是那一行没有值被打印，不是检查太严。

这门课的例子沿着同一份阅读清单往下长。这一章清单上只有标题和一次改绑。下一章会问：一本还没写页数的书，和一本明确标明「没有页数」的书，在值上是不是一回事。答案会牵出 `undefined` 和 `null`。在那之前，请不要用 `==` 去比较它们。宽松相等会把一些你认为不同的值说成相等，字符串那一章会专门拆这件事。控制流那一章会再拆一次：有些值在条件里会被当成假，即使它们不是布尔值。如果你现在就用 `if (title)` 来判断「有没有标题」，空字符串会被跳过，这可能是你想要的；数字 `0` 也会被跳过，那常常不是你想要的。先记住条件看的不是类型名。

计时器不要拿来证明「过一会儿」。这个宿主上的定时不一定按浏览器的方式排队，就算排了，输出顺序也会和你在桌面 Node 上看到的不完全一样。需要先后顺序时，等到 Promise 那一章，用已经完成的 `Promise.resolve` 把步骤排进微任务。微任务会在这次运行里按确定的顺序走完。死循环会占住引擎，页面上需要停止。不要写一个故意不结束的 `while` 来观察。

可运行块里不要写这些。它们依赖的宿主这里没有：

```js norun title="这里没有页面和包"
// document.querySelector("#shelf")
// fetch("https://example.com/books")
// import books from "./shelf.js"
```

若你从浏览器教程里整段贴进来，第一处碰到 `document` 就会抛错。那不是你的标题写错了，是环境不同。把报错读完，删掉宿主调用，留下语言本身，例子才能在这个抽屉里成立。

数字运算可以直接写。`120 + 40` 是加法，结果是数字 `160`。如果一边是字符串，加号会改做拼接，那是下一章的主题，这里只提醒你：同一个符号，看的是值的种类，不是变量名字长什么样。`typeof (120 + 40)` 仍是 `number`。类型是结果值的分类。

```js run expect="160" title="页数相加得到新的数字"
const pages = 120;
const extra = 40;
console.log(pages + extra);
console.log(typeof (pages + extra));
```

`pages + extra` 产生一个新的数字值。`pages` 仍然是 `120`，因为数字不能就地被改写，加法也不修改操作数。你如果希望名字 `pages` 变成 `160`，要自己写 `pages = pages + extra`，而且 `pages` 必须是 `let`。很多人把「算出来了」理解成「原来的变量被更新了」。在 JavaScript 里，表达式的结果是一个值，要不要让某个名字指向它，是另一条语句的事。这个区分以后在函数的返回值上会再出现一次。

把 `typeof` 的结果本身也当成值来看，会更清楚。`typeof` 交回来的是一个字符串，例如 `"number"`，而不是一种只有编译器能看见的内部标记。你可以把它打印、比较、拼进句子。这带来方便，也带来一种错觉：好像类型是程序里的一等公民，可以随便传给函数做决定。可以，但那个字符串只描述这一刻的值。它不会在值被换掉之后自动更新，除非你再问一次。把 `const kind = typeof entry` 存下来，然后改绑 `entry`，`kind` 仍是旧的字符串。类型询问是一次运算，不是一份订阅。

```js run expect="number" title="询问类型得到的是字符串"
let entry = "边城";
const kind = typeof entry;
entry = 120;
console.log(kind);
console.log(typeof entry);
```

第一行是 `string`，那是询问发生时的答案，存在 `kind` 里。第二行是 `number`，因为又问了一次。两行不同，说明「类型」不是粘在名字上的标签。若你写一个函数，参数只接受 `typeof` 的结果去分支，你分支的是当时的快照。调用方稍后改绑，函数看不见。这和后面对象那一章的差别在于：对象是可变的袋子，你改袋子里的属性，所有指向这个袋子的名字都看得到；原始值的类型快照则是另一份字符串，和原值再无联系。

最后把这一章里容易混的三句话并排放着。值是运算的材料，例如 `"边城"` 和 `120`。名字是你临时给值起的，例如 `title`。类型是值的分类，用 `typeof` 询问，它不是名字的属性，也不是你在 `const` 上许的愿。阅读清单后面会变成数组、对象和类，那些都是值。数组那个值可以被推进新书，对象那个值可以被挂上页数，但名字和值的关系不变：名字指向值，改绑指向另一个值，询问类型时问的是当前指向的那个。

布尔值也是值，不是类型系统的开关。`true` 和 `false` 是两个独立的值，`typeof true` 得到 `"boolean"`。条件语句会把别的值临时看成真或假，那叫真值判断，不是把那些值变成布尔。下一章会看到缺席用 `undefined` 表示，有意的空位用 `null` 表示，两者都不是布尔。不要提前用 `if` 把它们揉成一种「没有」。揉完以后你就再也分不清是没写，还是写了空。

参考这门语言的行为时，可以对照 MDN 的 JavaScript 指南，以及 Learn X in Y Minutes 的 JavaScript 页。那些材料覆盖浏览器和更完整的标准库。本课只取语言核心，句子和阅读清单都是这里现写的，不把原文搬进来。遇到 `document` 或安装包的步骤，就停在那一行，换成这一章已经能跑的 `console.log`。

## 小结

这段 QuickJS 脚本没有页面、没有网络、也没有包管理器。`console.log` 是查看值的方式，期望匹配的是子串。每次运行互不保留变量，所以每个例子都要自己把用到的名字写全。宿主调用留在只读块里，避免一运行就因为找不到页面而停住。

名字绑的是值。`typeof` 报告的是值的种类，而且报告本身是一个字符串快照，不会跟着后来的改绑更新。`let` 改绑可以让同一个名字先后指向字符串和数字。`const` 限制的是名字不能改绑，不是值的内部以后都不能变。加法的结果是新值，原来的数字不会被改写。下一章不再只看一个标题，而要看「没写」和「写了空」是两种不同的值：`undefined` 与 `null`。
