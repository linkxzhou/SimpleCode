从这一章起，围栏里的语言是 TypeScript。运行之前，抽屉会把类型标注和 `interface` 去掉，再把剩下的 JavaScript 交给 QuickJS。编辑器里能看见的往往是去掉之后的代码，并带一行说明。能跑只说明去掉之后的脚本没有语法错误，不说明标注和值一致。类型检查器没有参与这次运行。这是取舍：你仍然可以用标注把阅读清单的形状写给读代码的人，也可以在别的环境里打开真正的检查；在这里，标注是文档，不是守卫。

第一件要打印的事很具体。待办上的一个词是买笔，它的值是字符串。标注 `: string` 写在名字旁边，表示你声称这个值是字符串。

```ts run expect="买笔" title="待办上的一个词"
const errand: string = "买笔";
console.log(errand);
```

去掉类型之后，这就是 `const errand = "买笔"`。输出是这个词本身。若把标注写成 `: number` 而值仍是 `"买笔"`，在有检查器的工程里会被拒绝。在这个抽屉里，错误的标注会被删掉，脚本照样打印。所以不要用「我点了运行」来证明类型写对了。证明类型，要靠阅读标注和值是否是同一件事，或者靠一个真正会报错的检查器。本课没有把那个检查器放进运行按钮。

书目可以用 `interface` 描述。接口在去掉之后不会留下运行时的值，它不像 `class` 那样是一个函数。接口只在标注里出现。下面一本书有标题和页数，打印标题，确认对象在运行时就是普通对象。

```ts run expect="边城" title="接口描述一本书"
interface Book {
  title: string;
  pages: number;
}
const book: Book = { title: "边城", pages: 120 };
console.log(book.title);
console.log(book.pages);
```

`interface` 没有变成原型，也没有 `label` 方法，除非你自己再写函数。这和类那一章不同。类在运行时存在，接口不存在。选接口，是因为这份数据来自对象字面量或 JSON，你只想描述形状，不想制造构造器。选类，是因为你需要共享的方法。两者可以一起用：接口描述从文本读来的字段，类在检查通过后负责行为。这里先只描述。

联合类型把「页数可能还没标」写进类型：`number | "未标"`。运行时没有联合这一个种类，只有这一次实际的值。收窄要自己做，和前面几章的 `typeof` 一样。`if (typeof p === "number")` 之后，在有检查器时，分支里的 `p` 会被看成数字。没有检查器时，这个 `if` 仍然有运行时的意义：它决定打印哪一句。标注和判断必须一致。只写联合、不写判断，下一个运算就可能把文本和数字加错，这是字符串那一章已经见过的拼接。

```ts run expect="未标" title="联合类型要自己收窄"
type Pages = number | "未标";
function show(p: Pages): string {
  if (typeof p === "number") return "页" + String(p);
  return p;
}
console.log(show(120));
console.log(show("未标"));
```

函数的参数和返回值都可以标注。`: string` 写在参数名后，返回值写在参数列表后。去掉之后，函数和普通函数一样。默认参数、闭包和 `this` 的规则都没有因为标注而改变。箭头函数当方法时仍然拿不到接收者。类型系统里可以用 `this` 参数描述接收者，那只是标注，运行时照旧。本章不把 `this` 再演示一遍，避免把已经分开的两件事叠成一句「类型会修好 this」。它不会。

下面这段故意说谎。标注说 `pages` 是 `number`，值是文本。双重断言把检查器也会拒绝的赋值强行写成合法语法。去掉断言之后，变量里就是那个文本，`typeof` 回答 `string`。

```ts run expect="string" title="断言可以让谎言跑起来"
const pages: number = "很多" as unknown as number;
console.log(typeof pages);
```

`as` 是给你用的豁免，不是转换。它不调用 `Number`，也不检查内容。真正的转换仍要写 `Number`，失败时仍是 `NaN`。把 `as number` 放在 `JSON.parse` 的结果上，是常见的偷懒：解析结果变成了你声称的 `Book`，字段却可能缺失。错误那一章的形状检查不能删掉，改成标注也不行，因为标注不会留下。稳妥的顺序是：解析，检查，再交给一个参数类型为 `Book` 的函数。检查是运行时的，标注是给人或给检查器的。两层都写，是因为它们挡住的错误不同。只写一层，另一层的错误会漏进来。

数组的元素类型写成 `Book[]`。`map` 的回调若写了返回类型，读的人知道新数组里是字符串而不是书。去掉之后，`map` 仍是上一章那个分配新数组的方法，`push` 仍改原数组。类型不会把 `push` 变成复制。可变性是运行时的行为，标注里的 `readonly` 只在检查器打开时阻止某些赋值。本课不依赖 `readonly` 来保护清单。要保护，就不要把数组交给会 `push` 的函数，或者在函数里只 `map`。

可选字段写成 `note?: string`，表示可以没有这个属性。运行时没有这个属性时，读出来是 `undefined`。可选和 `| null` 不是一回事。可选是可以不写键，`null` 是键在且值为空。值那一章的区分在类型里可以写成 `note?: string | null`，三种情况都还在：没有键、空、文本。写得越宽，调用方的判断越多。写得越窄，造对象时越不方便。清单内部用窄的接口，从 JSON 进来的边界用宽的，然后在边界上收窄。边界收窄就是那些 `typeof` 判断，不是再加一个 `as`。

泛型在这一章只需要一个直觉：`function first<T>(items: T[]): T | undefined` 表示返回值和元素是同一种，至于是书还是字符串，由调用决定。去掉之后，泛型参数消失，函数体必须自己处理空数组，例如返回 `undefined`。空数组没有第一个元素，这是运行时事实，泛型不会替你造一个假元素。调用 `first` 的人仍要处理 `undefined`，和没有类型时一样。

字面量类型可以把标题收成 `"边城" | "围城"`，于是别的书名在检查器里不被接受。运行时一个普通字符串照样能放进变量，只要你断言过，或者检查器没运行。字面量类型适合很少变化的状态，例如 `"在读" | "读完"`。书名本身不适合收成字面量，因为清单会增加。把会增长的数据写成联合字面量，每加一本书就要改类型，这个代价通常不值。状态少而稳定，用字面量联合；标题用 `string`。

接口和类型别名在这份清单上几乎都能描述一本书。接口可以多次声明、被合并成一份，类型别名不能这样合并。合并在大工程里把字段散落在多个文件，查「书到底有哪些字段」要搜索。本课只有一个文件，合并没有好处，反而让字段来源不清楚。所以书的形状只用一处 `interface`，状态用 `type` 联合。这个分工是为了读的人知道去哪看，不是因为引擎对两者待遇不同。去掉之后，两者都不存在。

结构类型看字段，不看名字。两个接口只要都有 `title` 和 `pages`，值就可以互相赋值，在有检查器时也行。名字不同并不构成运行时的区分。`instanceof` 对接口没有意义，因为没有留下构造函数。你不能在运行时问「这是不是 `Book` 接口」。你只能问字段在不在、种类对不对。这和类的 `instanceof` 是互补的：类有运行时的链，接口没有。不要写一个函数去比较接口的名字。名字在去掉之后无处可寻。

多余字段在对象字面量直接赋给接口时，检查器往往会拒绝，例如多写一个 `weight`。同一个对象若先放进变量再传，检查又可能放行。这叫超额属性检查，只发生在检查器里，而且规则比「字段必须一致」更窄。本抽屉不运行检查器，多出来的 `weight` 会留在对象上。`JSON.stringify` 会把它一并写出。若你不希望导出未知字段，就在边界上只抄 `title`、`pages` 和 `done`，构成一个新对象。抄写是运行时的过滤。期待检查器帮你丢掉未知字段，在这里不会发生。

枚举会生成真实的运行时代码，和接口不同。数字枚举还有反向映射，字符串枚举是一个对象。本课不用枚举来表示读完，因为布尔更直接，也因为枚举的生成代码和「类型会被完全去掉」这句话容易矛盾。状态若要收窄成几个字符串，用联合字面量。联合字面量去掉之后什么都不留，运行时你自己比较字符串。比较是可见的，生成的枚举对象是隐式的。隐式对象在这个单文件脚本里不值得。

函数重载是多行类型签名配一个实现。去掉之后只剩实现。重载不会在运行时按类型选分支。选分支仍靠 `typeof`。若你写了两个重载却在实现里不判断，运行时就只有一条路径。不要把重载理解成多份函数体。它是给检查器看的几句声明。清单的 `show` 只有一份函数体，里面用 `typeof` 区分数字和文本。这样没有检查器时行为也在。

可选链 `?.` 会在左边是 `null` 或 `undefined` 时停下并得到 `undefined`，不会抛。它不在本课的运行例子里，因为要讲的收窄是显式的 `if`。可选链适合一长串可能缺失的字段，短标题用 `if` 更看得出你准备了哪一种空。可选链也不会把空串换成默认值。空串会继续往下访问，若你对空串取属性，仍可能失败。默认值用明确比较，或在确认检查器可用时再用只认 `null` 和 `undefined` 的写法。本抽屉的脚本把比较写开。

只读数组类型 `readonly Book[]` 在检查器里阻止 `push`。去掉之后 `push` 照样能改。所以项目那一章用新数组来保护原清单，而不是只给参数标上只读。标上只读仍然有阅读价值：读的人知道这个函数不打算修改。价值是注释级别的，和接口本身一样。把它当成运行时的锁，会在某次「先去掉类型再跑」的调试里被打破，而且没有任何报错。锁要有运行时的行为才算锁。这里的行为是不调用 `push`。

## 小结

TypeScript 的标注写在值旁边，这个抽屉会把它们去掉再运行。`interface` 不会变成原型或构造函数。联合类型要靠 `typeof` 收窄，断言不负责转换。打印 `买笔` 只证明字符串值还在，不证明检查器看过这份标注。

形状检查留在运行时，尤其是 `JSON.parse` 之后。`readonly` 和字面量类型在没有检查器时不构成保护。下一章把这些标注用到一份完整的阅读清单上：书的数组、未读的筛选、页数的合计，都写上类型，并且仍然只依赖去掉之后能跑的那些运算。

2. `type Flag = "开" | "关"`。函数 `show` 接收 `Flag` 并原样返回。分别打印 `show("开")` 和 `show("关")`。

::: answer 参考答案
```ts run expect="关" title="参考答案"
type Flag = "开" | "关";
function show(flag: Flag): Flag {
  return flag;
}
console.log(show("开"));
console.log(show("关"));
```
:::
