阅读清单长到不止一本书时，用数组把它们按顺序放在一起。数组是对象，是一个值。名字指向这个值。把名字赋给另一个名字，两个名字指向同一份清单，不是两份内容相同的清单。这个差别在原始字符串上看不见，因为字符串不能被改。数组能被改。`push` 就是在改它。

先看一份只有两本的清单，还没有任何改动。`join` 用分隔符把元素拼成一个字符串，方便打印。它不改数组。元素本身如果是字符串，就按原样放进去。

```js run expect="边城,围城" title="两本书的清单"
const shelf = ["边城", "围城"];
console.log(shelf.join(","));
console.log(shelf.length);
```

`length` 是 `2`。下标从 `0` 开始，`shelf[0]` 是 `"边城"`，`shelf[1]` 是 `"围城"`，`shelf[2]` 是 `undefined`。越界不抛错，这和字符串取码元一样。不抛错的好处是稀疏的位置可以先空着。代价是笔误下标会得到 `undefined`，再被上一章的真值判断跳过，你可能以为那本书被筛选掉了，其实是下标写错了。打印 `length` 再决定下标，能少一类这样的错。

现在让第二个名字指向同一份清单，并 `push` 一本新书。

```js run expect="边城,围城,城南旧事" title="push 改的是原数组"
const shelf = ["边城", "围城"];
const same = shelf;
same.push("城南旧事");
console.log(shelf.join(","));
console.log(same.length);
```

`shelf` 也变成三本，`length` 是 `3`。`push` 的返回值是新的长度，不是新数组。若你写 `const next = shelf.push("城南旧事")`，`next` 是数字 `3`，`shelf` 已经被改了。两个结果都要认：返回值是长度，副作用是原件变长。只看返回值会以为自己拿到了清单；只看副作用会忘记调用的结果其实是数字，拿去 `join` 会报错。

这就是可变的取舍。原地 `push` 不分配第二份书名列表，清单很长时更省。任何别的名字、任何闭包里抓着的同一份数组，都会看见这本新书。函数那一章若把 `shelf` 闭包进两个加法器，它们就是在合写一份清单。你想要合写，就共享；你想要各自保留改之前的样子，就必须在改之前复制。

`map` 选择复制这条路。它逐个调用函数，把返回值放进一个新数组，原数组的元素和长度都不变。下面仍用三本书的标题，给每一本加上书名号。

```js run expect="《边城》,《围城》,《城南旧事》" title="map 留下原清单"
const shelf = ["边城", "围城", "城南旧事"];
const wrapped = shelf.map(function (title) {
  return "《" + title + "》";
});
console.log(shelf.join(","));
console.log(wrapped.join(","));
```

第一行没有书名号，第二行有。`map` 的回调返回什么，新数组里就是什么。若回调忘记 `return`，新数组里会是 `undefined`，`join` 会把它们收成空段。这和函数没有返回值是同一件事。`map` 不该用来做只要副作用的循环：它会白白分配数组。只要走一遍去 `push` 别的地方，用 `for` 或 `forEach`。`forEach` 不交回有用的数组，返回 `undefined`。选择 `map` 的理由是你需要那份新清单。

复制有深浅。`map` 和 `slice` 都是浅的。元素如果是字符串，字符串不可变，浅复制就够。元素如果是对象，复制的是指向对象的引用，改对象的 `pages`，原数组和新数组都能看见。这一章的元素是标题字符串，浅复制等于内容独立。对象那一章会把元素换成袋子，那时要记住：`map` 没有克隆袋子里面。

`slice()` 不带参数时交回一份元素相同的新数组。在副本上 `push`，原件保持两本。这是「我想扩展，但调用方还要旧清单」时的做法。比 `map` 更直接，因为你不需要变换元素，只需要另一个身份。

还有 `concat`，它也交回新数组，把额外的元素接在后面，原件不动。`shelf.concat("城南旧事")` 和「先 `slice` 再 `push`」的结果类似，写法更短。`concat` 若传入的是数组，会把那一层摊开。传入的若是字符串，字符串不是按字符摊开，整串是一个元素。这个不对称来自数组的摊平规则只认数组。不要把字符串的拼接习惯套到 `concat` 上。

排序会改原数组。`sort` 默认按字符串比较，数字页数会变成 `"10"` 排在 `"2"` 前面这种字典序。本章的清单按放入顺序，不排序。若以后要按页数排序，先 `slice` 再排序，避免打乱原来的阅读顺序，并传入比较函数 `(a, b) => a - b`，不要用默认比较。这里不把排序放进可运行例子，是因为标题的字典序会把讨论从「身份」带走。身份才是这一章的判断：`push` 保持身份、改变内容；`map` 改变你看见的内容，但换了一个身份，原身份的内容还在。

空数组是真，上一章说过。空数组的 `length` 是 `0`，`0` 算假。问「有没有书」用 `length === 0`，不要用 `if (!shelf)`，因为一份存在的空清单也算真，`!shelf` 为假，你的否则分支不会走。`if (!shelf)` 只在 `shelf` 是 `null` 或 `undefined` 时才成立。那是「没有这份清单」，不是「清单是空的」。两种空，和值那一章的 `null` 与缺字段是同一类问题，只是发生在整个数组这个值上。

下标赋值 `shelf[shelf.length] = "活着"` 和 `push` 一样会变长，也是改原件。它允许你在中间挖洞：`shelf[5] = "活着"` 会让 `length` 变成 `6`，中间是空位。空位在 `map` 里会被跳过，`join` 时又会变成空段。阅读清单不要挖洞。要插在中间，用 `splice`，它同样改原件。能用 `push` 加在末尾，就不要制造空洞。

`splice` 能在中间删、在中间插，并且改的是原数组。它的返回值是被删掉的那段，不是改完的清单。`shelf.splice(1, 1)` 从下标 `1` 删掉 `1` 本，返回那个被删的元素组成的数组。若你把返回值当成新的完整书架，后面的书就丢了。这和 `push` 返回长度是同一类陷阱：返回值不是「现在的清单」。想要现在的清单，看原来的名字。想要一份不动原件的删除，先 `slice` 成两段再 `concat`，或者 `filter` 掉那个标题。`filter` 交回新数组，原件还在。

`unshift` 和 `shift` 在开头插入或拿走。它们要移动后面所有下标，清单长时比末尾的 `push` 和 `pop` 贵。阅读顺序若是「新书放在最前」，这个成本可能值得，因为读的人先看见新书。若只是临时处理，末尾进出更便宜，显示时再决定顺序。不要为了「数组就像队列」而固定用 `shift`。队列是你的需求，开销取决于你选的一端。

`indexOf` 用严格相等找第一本相同的标题，找不到返回 `-1`，不是 `undefined`。`-1` 算真，所以 `if (shelf.indexOf(title))` 在找到下标 `0` 时反而走进否则，在找不到时走进如果。这是真值表和「没找到用负数」撞在一起。判断应写成 `indexOf(...) !== -1`，或使用 `includes`，它交回布尔。布尔进 `if` 不会再被零下标误伤。

稀疏数组的空洞不是 `undefined` 元素的同义词，尽管读取时都得到 `undefined`。`map` 会跳过空洞，却不会跳过明确写成 `undefined` 的槽。`join` 对两者都可能打出空段。制造空洞的赋值让这两种「空」更难分辨。清单用 `push` 保持紧凑，每个下标都有书名。若导入数据里夹着空标题，那是空字符串元素，不是空洞，筛选时用 `=== ""` 去掉。

`reverse` 和 `sort` 都改原数组。想要倒序的显示又不想打乱阅读顺序，先 `slice` 再 `reverse`。链式调用时要看清哪一步交回新数组、哪一步交回原数组。`slice` 交回新的，随后的 `reverse` 改的是那份新的，原件仍安全。若有人写成 `shelf.reverse().slice()`，先倒序的是原件，`slice` 只是抄了一份已经倒过的。链式写法从左到右执行，保护原件的那一步必须写在改动之前。

`flat` 只摊开一层数组。若某本被误写成 `[ "边城" ]` 放进书架，一层 `flat` 能把书名提出来。再深的嵌套还要再摊。摊开会丢掉「这一格原来是一组」的结构。导入数据若本来就应该是一组标签，不要对整架 `flat`，否则标签和书名混成一条。先确定每一格的种类，再决定摊不摊。`Array.isArray` 是这个决定的工具。`typeof` 对数组和普通对象都回答 `"object"`，分不开。

`fill` 会改原数组，把每一格都写成同一个值。若这个值是对象，每一格是同一个对象，改一格等于改全部。填充书目时不要 `fill` 一个对象。要三本空白草稿，就用循环 `push` 新的对象字面量，每次循环都新建。`fill` 适合填数字这种不可变的初值。书是袋子，袋子不能复制引用就算作三本。

解构可以一次取出前两本：`const [first, second] = shelf`。它不改数组。缺第三本时那个名字是 `undefined`。默认值写在解构里可以补空位，但空串不会触发默认值，因为空串不是 `undefined`。和参数默认值一样，只有缺口才补。不要指望解构默认值把空标题换成「未命名」。那需要明确的比较。

`find` 交回第一个让回调返回真的元素，没有则是 `undefined`。它不交回下标。只要书，用 `find`；还要知道位置，用 `findIndex`，没有时是 `-1`。两者都不改数组。回调里若用真值判断页数，零页又会被跳过，`find` 会去拿下一本。回调里写 `book.pages === 0` 才是在找零页那本。找不到时不要把 `undefined` 直接放进 `join` 的数组而不检查，否则输出里会多出一个单词 `undefined`。先判断再使用，和读取对象缺失字段是同一习惯。

`some` 问有没有至少一本满足条件，`every` 问是不是全部满足。空数组上 `every` 为真，因为没有任何一本违反条件。这叫空真。用 `every` 检查「每本都有标题」时，空书架会通过。若空书架不应该算合格导入，要另外判断 `length`。`some` 在空数组上为假。两个方法方向不同，空数据上的结果也不同，不能互相推导。

下标可以是表达式。`shelf[shelf.length - 1]` 取最后一本，空数组上这个下标是 `-1`，在 JavaScript 里 `-1` 会变成键 `"-1"`，不是「从末尾数」，读出来仍是 `undefined`，而且你并没有读到最后一本。从末尾取要用 `length` 判断大于零之后再减一。不要把其他语言里负数下标的习惯搬进来。搬进来不会报错，只是悄悄读到一个不存在的键。

## 小结

数组是一个值，赋值只复制指向它的名字。`push` 改这个值，所有指向它的名字都看得到新书，返回值却是新长度。`map` 分配新数组，原清单的标题保持不加书名号。`slice` 和 `concat` 也交回新身份。

共享适合大家一起改的那一份在读清单；复制适合你要保留改之前的顺序或做一种显示格式。空清单和「没有清单」不同，前者 `length === 0`，后者是 `null` 或 `undefined`。下一章把标题放进对象，属性找不到时会沿着原型去问，那是另一种共享：共享的是字段的默认值，不是数组的身份。

## 练习

1. 从 `["边城", "围城"]` 复制一份再 `push` `"活着"`。打印原清单和副本，原清单仍是两本，副本是三本。用逗号连接。

::: answer 参考答案
```js run expect="边城,围城" title="参考答案"
const shelf = ["边城", "围城"];
const copy = shelf.slice();
copy.push("活着");
console.log(shelf.join(","));
console.log(copy.join(","));
```
:::

2. 对 `["边城", "围城"]` 做 `map`，每本书名前加 `在读:`。打印原数组和结果数组两行。

::: answer 参考答案

```js run expect="在读:边城,在读:围城" title="参考答案"
const shelf = ["边城", "围城"];

  return "在读:" + title;

```
