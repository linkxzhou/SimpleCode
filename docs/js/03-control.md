分支并不打开一个新的类型系统。`if` 后面的括号里要的是一个决定：进这个分支，还是进那个分支。JavaScript 不要求这个决定必须是布尔值。它先把括号里的值按真值规则看成真或假，再选择路径。真值规则和上一章的 `==` 不是同一张表。混用两张表，页数就会在「相等」和「要不要留下来」之间给出相反的答案。

算假的值不多：`false`、`0`、`-0`、`0n`、`""`、`null`、`undefined`、`NaN`。其余都算真，包括文本 `"0"`、文本 `"false"`、空数组 `[]`、空对象 `{}`，以及任何函数。注意空数组是真。用 `if (shelf)` 判断「清单里有没有书」会在清单存在但一本都没有时仍然走进分支。要问长度，就问 `shelf.length`，而长度 `0` 又算假。`if (shelf.length)` 在空清单上会跳过，这碰巧是你想要的；它在别的数字上也会跳过零，那就不总是你想要的。

```js run expect="文字零:留下" title="零、空串和文字零"
function gate(label, v) {
  if (v) console.log(label + ":留下");
  else console.log(label + ":跳过");
}
gate("零页", 0);
gate("空标题", "");
gate("文字零", "0");
gate("空清单", []);
```

四行里，零页跳过，空标题跳过，文字零留下，空清单留下。文字零留下，是因为非空字符串都算真，内容是不是 `"0"` 无关。这和 `"0" == 0` 为真直接矛盾，如果你还记着上一章的表。并不矛盾：`==` 在比较时转换，`if` 在分支时看真值，两套规则服务两种历史习惯。你不能从其中一套推导另一套。页数字段若是文本 `"0"`，`if (pages)` 会把它当成「有页数」，`pages == 0` 会把它当成「等于零」。接下来的算术应该先做 `Number`，分支应该写 `pages !== ""` 或 `Number(pages) === 0`，把你真正的问题写清楚。

`NaN` 算假。`Number("页")` 是 `NaN`，放进 `if` 会走到否则分支。否则分支因此同时接待「转换失败」和「真的是零」——不对，零也算假，所以否则分支接待零和 `NaN` 两者。你若在否则里打印「页数有问题」，会把零页的书也叫成有问题。分开的办法是先 `Number.isNaN`，再判断数字是否小于零或等于零。多两个条件，每种结果才有自己的句子。

阅读清单现在有三行。一行是正常的《边城》120 页，一行是《未记》0 页，一行标题是空字符串、页数 90。想留下「有标题且有页数」的书时，若写成 `if (row.title && row.pages)`，后两行都会消失。空标题算假，零页也算假。零页那本是真实的条目，只是页数是零。真值判断把它和「没有标题」放在了同一次跳过里。

```js run expect="边城" title="真值筛选会丢掉零页"
const rows = [
  { title: "边城", pages: 120 },
  { title: "未记", pages: 0 },
  { title: "", pages: 90 }
];
const kept = [];
for (let i = 0; i < rows.length; i = i + 1) {
  const row = rows[i];
  if (row.title && row.pages) kept.push(row.title);
}
console.log(kept.join(","));
```

循环用下标，是为了把「走一遍清单」写显式。`for` 的三个部分是起点、继续条件、每轮之后的更新。条件 `i < rows.length` 为假时循环结束，这里的假是比较得到的布尔值，不是页数的真值。比较运算符交回 `true` 或 `false`，真值规则不会再扭曲它们。扭曲发生在你把页数本身放进 `if` 的时候。

把条件写成明确的比较，零页就能留下，空标题仍然去掉。

```js run expect="边城,未记" title="明确比较留下零页"
const rows = [
  { title: "边城", pages: 120 },
  { title: "未记", pages: 0 },
  { title: "", pages: 90 }
];
const kept = [];
let i = 0;
while (i < rows.length) {
  const row = rows[i];
  if (row.title !== "" && typeof row.pages === "number") {
    kept.push(row.title);
  }
  i = i + 1;
}
console.log(kept.join(","));
```

`while` 和刚才的 `for` 是同一件事的两种写法。`while` 适合条件不依赖一个整齐下标的时候，比如「读到空标题就停」。`for` 适合你事先知道要走完一个长度。两者都要求条件最终变成假，否则引擎不会自己停。本课不写死循环。`break` 可以提前结束整层循环，`continue` 只跳过这一轮的剩余部分。在筛选里，`continue` 常常比嵌套更深的 `if` 更容易读：条件不满足就进入下一轮。代价是阅读时要记住「这一轮到此为止」，不能以为后面的语句也会对这一行执行。

```js run expect="边城" title="continue 跳过空标题"
const titles = ["边城", "", "围城"];
const kept = [];
for (let i = 0; i < titles.length; i = i + 1) {
  if (titles[i] === "") continue;
  kept.push(titles[i]);
}
console.log(kept.join(","));
```

这里用 `=== ""` 而不是真值。标题清单里没有数字零，所以真值也能得到同样两本书。仍然写成比较，是为了让「跳过的是空标题」留在代码里，而不是「跳过一切算假的东西」。若以后有人把页数塞进这个数组，真值版本会开始丢零，比较版本仍然只丢空串。明确比较对当前数据更啰嗦，对下一次修改更稳。这就是取舍：短的条件借了真值表的方便，长的条件只回答你写下的那个问题。

`else if` 用来处理互斥的几种页数状态：负数报错，零单独说明，正数接受。一旦前面的条件为真，后面的就不再看。顺序因此是语义的一部分。把「小于零」放在「等于零」后面没有影响，因为两者不会同时成立；把「小于一百」放在「小于零」前面，负数会先被说成「短书」。写互斥分支时，先写更窄的条件，或者写彼此不重叠的比较。不要靠试运行来碰对顺序。

逻辑运算符 `&&` 和 `||` 也不总是交回布尔。`a && b` 在 `a` 算假时交回 `a` 本身，否则交回 `b`。`a || b` 在 `a` 算真时交回 `a`，否则交回 `b`。所以 `title || "未命名"` 在标题为空串时得到 `"未命名"`，在标题为 `"边城"` 时得到 `"边城"`。这很适合填默认显示。它不适合页数：`pages || 100` 会把零页换成 `100`，因为零算假。默认值若要把零留住，用上一章已经分开的判断：`pages === undefined || pages === null` 时才采用默认。语言后来有 `??`，只把 `null` 和 `undefined` 当成需要默认的情况，零和空串都会留下。本课的例子不依赖 `??`，把判断写开，这样每一种空都看得见。

三元表达式 `cond ? a : b` 是 `if` 的表达式形式，它要一个值。用它来选择两个短标题可以。用它来嵌套三层页数状态，很快就读不清。超过一个 `else` 时，写成语句。表达式和语句的差别是：表达式必须交出值，语句负责去做。`console.log` 是语句里的调用。筛选循环是语句。不要为了写成一行而把整个循环塞进三元表达式。

`switch` 使用严格相等，不走真值表，也不走 `==`。`switch (pages)` 里 `case 0` 不会接住文本 `"0"`，也不会接住空串。这和 `if (pages)` 相反，空串和零都会进 `if` 的否则，而 `switch` 把它们分成不同的 `case`。每个 `case` 后面若要停住，必须写 `break`。漏掉 `break` 会继续执行下一个分支，叫做贯穿。贯穿偶尔用来让几个书名共用一段打印，更多时候是漏写。本课的页数分支用 `if`，因为条件是范围（小于零、等于零、大于零），不是几个离散的标题。`switch` 适合离散且用 `===` 能写全的状态，例如 `"在读"` 和 `"读完"` 两个文本状态。范围判断塞进 `switch (true)` 这种写法，等于把 `switch` 用成一串 `if`，阅读时更绕，没有好处。

循环变量要用 `let` 写在 `for` 的括号里。写在外面的 `var` 会让闭包在循环结束后都看见最后一个下标。我们还没有在循环里制造闭包，但数组的 `map` 回调会碰到类似问题。`let` 每次迭代有自己的绑定，回调抓住的是这一轮的值。`var` 只有一个绑定。新代码不用 `var`。它的函数级作用域会让一个写在分支里的名字漏到整个函数，和「这个名字只在这个分支里有意义」的阅读预期不符。

`for...of` 走的是元素，不是下标。标题数组用它更短。需要下标时，普通 `for` 更直接，不必再配一个计数器。不要对数组使用 `for...in`。它走的是可枚举的键，顺序不是阅读顺序，也可能走到别的属性。对象那一章会解释键从哪来。在那之前，清单的循环只使用下标、`while` 或 `for...of`。

条件里调用函数会把副作用藏起来。`if (add("边城"))` 既加入又判断返回值，读的人容易漏掉加入已经发生。先调用，把结果放进名字，再判断。多一行，换来顺序看得见。三元表达式也有同样的问题：两个分支若都带赋值，行就太密。分支里只有标题字符串时，三元是合适的。

短路运算符可以当分支用。`title && kept.push(title)` 在标题为空串时不会 `push`，因为 `&&` 左边算假就不再算右边。它省了一层 `if`，也把「是否推进」藏进运算符。清单代码里这种写法不值得。`if (title !== "") kept.push(title)` 长几个字，问题却写在比较里。短路留给真正的默认值，例如日志字符串，不留给会改数组的调用。

嵌套循环才会遇到「`break` 只跳出一层」。外层走书架，内层走某一本的标签，想在找到标签时连外层一起停，单层 `break` 做不到。可以设一个布尔 `found`，内层打断后外层再看这个布尔。也可以给外层循环起标签，用带标签的 `break`。标签少用，因为它把跳转的目标写在循环上方，读的人要往回找。三层以内、只停一层时，普通 `break` 更清楚。清单的例子最多一层，不需要标签。知道它只破一层，是为了以后不要以为一次 `break` 会离开整个函数。离开函数用 `return`。`return` 会把值交回调用方，循环就此结束。在循环里用 `return` 表示「找到了就不用再看」，比打布尔再跳出更直接，前提是这段循环独占一个函数。循环若还负责打印汇总，提前 `return` 会把汇总也跳过。那种情况用 `break`，汇总留在循环后面。

比较链 `0 <= pages && pages < 1000` 能拦住明显离谱的页数。两边都要写，因为 JavaScript 不允许 `0 <= pages < 1000` 按数学意义连写：它会先算出 `0 <= pages` 的布尔，再拿布尔去和 `1000` 比，布尔会被转成数字，结果几乎总是真。这是一个安静的错误。范围检查写成两个比较，用 `&&` 接上。页数为零时左边为真，右边也为真，零页可以通过范围检查，这是对的。缺页的 `null` 会在比较里变成 `0`，`null <= 0` 为真，所以范围检查之前仍要先排除 `null` 和 `undefined`。否则缺页会伪装成零页通过「小于一千」。顺序是：先拒绝空，再看是不是数字，再看范围。

## 小结

`if` 使用真值表，不是 `==` 的表，也不是 `typeof` 的表。算假的是 `false`、零、空串、`null`、`undefined` 和 `NaN`。空数组和文本 `"0"` 算真。因此 `if (row.title && row.pages)` 会同时丢掉空标题和零页。

要留下零页，就写 `title !== ""` 和 `typeof pages === "number"`。`for` 与 `while` 都能走完清单，条件必须会结束。`||` 提供默认值时会把零吃掉。下一章把「走清单」收成函数，并让内层函数记住已经数过的本数；同时看 `this` 为什么不跟着写函数的地方走，而跟着调用时的接收者走。

## 练习

1. 标题数组是 `["", "围城", "城南旧事"]`。用循环跳过空串，把其余标题用逗号拼成一行打印。

::: answer 参考答案
```js run expect="围城,城南旧事" title="参考答案"
const titles = ["", "围城", "城南旧事"];
const kept = [];
for (let i = 0; i < titles.length; i = i + 1) {
  if (titles[i] === "") continue;
  kept.push(titles[i]);
}
console.log(kept.join(","));
```
:::

2. `pages` 分别是 `0`、`null` 和 `80`。对每个值打印 `缺页` 或数字本身：只有 `null` 和 `undefined` 算缺页，零要原样留下。可以用三次调用，输出里应有单独一行 `0`。

::: answer 参考答案
```js run expect="0" title="参考答案"
function show(pages) {
  if (pages === null || pages === undefined) console.log("缺页");
  else console.log(pages);
}
show(0);
show(null);
show(80);
```
:::
