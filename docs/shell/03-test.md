赋值章把钥匙放进了 `item`，也把 `$?` 抄进了名字。这一章让判断自己产生退出码。`test` 和 `[` 是内建，它们不印清单，只把「成立」写成 `0`，把「不成立」写成 `1`。脚本不会因为结果是 `1` 就停下来。`1` 是数据，和钥匙这两个汉字是同一类东西：可以抄进变量，可以在下一章交给 `if`。只有写法不被这只壳认识时，才返回 `2`，并在标准错误里说明。`2` 是用法有问题，`1` 是命题为假。

方括号是 `test` 的另一种拼法。它是一个命令名，所以左边要有空格。结尾的 `]` 是最后一个参数，也要有空格，并且必须真的写上。少了 `]`，退出码是 `2`，标准错误会说缺少 `]`。课程里的例子都把空格和右括号写全，然后立刻用 `printf` 印出 `$?`，让最后一条命令成功，终端里留下那个数字。

一个参数的 `test` 看它是不是非空。非空则 `0`，空则 `1`。两个参数时，`-n` 表示非空则成功，`-z` 表示空则成功。三个参数时，中间可以是字符串的 `=` 或 `!=`，也可以是整数的 `-eq`、`-ne`、`-lt`、`-le`、`-gt`、`-ge`。字符串比较是逐字节的相等，不是模式，也不是「看起来像」。整数比较会先把两边按十进制读成数字，再比大小。

先看字符串。`item` 是钥匙时，和钥匙相等，状态是 `0`。

```sh run expect="0" title="钥匙对上了"
item=钥匙
test "$item" = 钥匙
printf '%d\n' $?
```

换成水杯，命题为假，状态是 `1`。这不是壳坏了。`printf` 仍然执行，因为 `test` 的 `1` 不会取消后面的分号或换行。

```sh run expect="1" title="和水杯不相等"
item=钥匙
test "$item" = 水杯
printf '%d\n' $?
```

方括号写出同一件事。`-n` 在钥匙上成功，`-z` 在钥匙上失败。空赋值之后，`-z` 才成功。下面把非空的结果印出来。

```sh run expect="0" title="方括号看非空"
item=钥匙
[ -n "$item" ]
printf '%d\n' $?
```

`!=` 在两边不同时成功。钥匙和车票不同，所以状态是 `0`。不要把 `!=` 的 `0` 读成「两者相等」。`0` 只表示这条 `test` 按它的运算符成立。运算符是「不等于」，成立就是两者确实不同。

整数运算符服务步数，不服务汉字。`[ 2 -lt 10 ]` 成功，`[ 4 -ge 5 ]` 失败。`%d` 和这里的比较用的是同一种十进制阅读。步数在 `while` 那一章会从 `3` 走到 `0`，比较用 `-gt`。若把钥匙放进 `-eq`，两边都会被读成数字 `0`，因为它们不是十进制数字，阅读在第一个汉字处就结束了。于是 `[ 钥匙 -eq 水杯 ]` 也是成功。这不是在说两项相同，这是在说两个「读不成数字」的词都变成了 `0`。清单上的名字必须用 `=`。步数必须用 `-eq` 这一组。混用会得到一个看起来很顺利、实际上没比较文字的 `0`。

```sh run expect="1" title="汉字要用等号"
item=钥匙
[ "$item" -eq 水杯 ]
printf '%d\n' $?
[ "$item" = 水杯 ]
printf '%d\n' $?
```

第一行是 `0`，来自错误的整数比较。第二行是 `1`，来自字符串比较。期望写成 `1`，是为了让你看到第二行。第一行那个顺利的 `0` 恰恰是陷阱。读输出时两行都要看。

`test` 的结果可以照赋值章的办法抄下来。`[ "$item" = 钥匙 ]` 之后立刻 `st=$?`，`st` 里就是 `0`。再去 `printf`，最近状态会变成 `printf` 的 `0`，`st` 仍保存判断。若判断是 `1`，更要抄，因为你很容易接着写一条成功的命令，把 `1` 盖掉，回头却以为当时是对上了。

不支持的表达式返回 `2`。三个以上的参数拼成带 `-a` 或 `-o` 的组合，这只壳不实现，标准错误会说不支持。未知的运算符同样是 `2`。可运行的例子停在它认识的那一组：`-z`、`-n`、`=`、`!=` 和六个整数运算符。需要同时满足两件事时，下一章用两个 `if`，或者用下一章之后的 `&&` 把两个 `test` 连起来。不要在一个方括号里塞进两段比较。

`true` 和 `false` 可以当作已经知道结果的 `test`。`true` 的状态是 `0`，`false` 是 `1`，它们不看变量。调试时若想固定走某一边，可以用它们代替方括号。正式的清单仍应该去比较 `item`，否则检查没有读到你保存的那一项。

标准输出不会出现 `test` 的说明文字。你若只运行方括号，终端是空的，退出码在 `$?` 里。空终端不表示进程没跑，只表示这条内建把答案放在状态里。所以每一块都接上 `printf`。期望核对的是这个数字，不是一行中文解释。解释写在课文里，不写进 `test` 的输出。

和外部命令的 `127` 放在一起看，三种数字的分工就清楚了。`0` 和 `1` 是 `test` 对命题的回答。`2` 是 `test` 自己没看懂你的式子。`127` 是你叫了一个不存在的程序。看到 `1` 时，清单还在，你只是得知「这一项不是水杯」。看到 `127` 时，那一项根本没有被比较，因为命令没有作为内建执行。

```sh norun title="外部名字不会变成 test"
cmp 钥匙 水杯
```

`cmp` 会得到 `127` 和那句 `external commands are not available`。比较由 `test` 来做。

空字符串和缺少变量在这张表上是一样的：没赋值的名字展开成空。`[ -z "$missing" ]` 成功。这给清单一个明确的起点。你还没写 `item=钥匙` 时，非空测试失败，而不是壳去猜「也许上一块赋值过」。每一块自己赋值，再测试，状态才描述这一块。


把退出码当成数据，是因为这只壳没有别的通道可以回答「这一项对不对」。它不能启动 `grep` 或 `diff`。`test` 和 `[` 是内建函数，读完参数，返回 `0`、`1` 或 `2`。`0` 和 `1` 都是正常的回答，脚本按顺序继续。只有 `2` 表示式子没被看懂：缺了右括号、运算符不认识、或者参数个数超出它实现的那几种形状。标准错误会说明原因，标准输出仍然是空的。所以课文的每一块都在 `test` 后面接 `printf`，让数字出现在终端，也让最后一条命令成功。

方括号是同一个实现的另一种写法。`[` 是命令名，`]` 是最后一个参数。两边的空格不能省，省了就粘成别的词，要么变成未知命令，要么变成缺少 `]` 的 `2`。三个参数的形式里，中间那个词决定比较的种类。`=` 和 `!=` 按字节比较整段文字，钥匙和水杯不同，是因为它们的 UTF-8 字节不同，不是因为壳懂汉语。`-eq` 这一组先把两边按十进制读成整数。读不到数字的词变成 `0`。于是钥匙和水杯用 `-eq` 比较会得到成功，这只说明两个「读不成数」的结果都是 `0`。清单上的名字永远用 `=`。步数才用 `-lt`、`-gt`、`-eq` 这些。`08` 会按十进制读成 `8`，前导零不保留。你若把编号写成带前导零的字符串，又用整数比较，相等的是数值，不是字形。

一个参数时，非空即成功，空即失败。`-n` 和 `-z` 把这件事写明确。没赋过值的名字展开成空，`-z` 成功。这给每一块一个干净的起点：忘记赋值时，非空测试失败，壳不会去翻上一块的表。块和块之间是宿主重新启动，不是这张表活到了下一次点击。

`test` 不打印「成立」或「不成立」。空终端容易被看成没运行。数字必须由你用 `$?` 送出来，而且要趁下一条命令还没盖掉它。抄进 `st` 之后，`st` 是字符 `0` 或 `1`，可以留到 `if` 之前，也可以直接交给下一章的条件。条件若再跑一次方括号，那是另一次比较，不是把 `st` 重新解释成状态。`if` 看的是命令的退出码，不是变量里的字符，除非你把字符再交给一次 `test`，例如 `[ "$st" -eq 0 ]`。那是整数比较，合适，因为 `st` 里放的就是十进制数字。

不支持把几个比较用 `-a` 或 `-o` 串在同一个方括号里。要同时成立，用两个 `test`，中间用后面章节的 `&&`，或者用 `if` 嵌套。未知运算符返回 `2`，不要自造 `-f` 这种文件测试。这只壳的 `test` 不看文件系统。文件在不在，要靠下一章以后的重定向和 `cat` 去读，读失败会有自己的状态。不要把「文件存在」塞进这一章的运算符列表。

`true` 和 `false` 是已经知道答案的判断。它们不读 `item`。调试结构时可以用，正式清单必须去比较你保存的那一项，否则检查没有碰到数据。`:` 和 `true` 一样成功且不打印。把它们放在 `test` 旁边，是为了提醒你：状态是命令的返回值，不是终端上的句子。句子由 `printf` 负责，而且要放在你已经决定要说话的地方。

外部的比较程序走不到这些返回值。`cmp` 或 `grep` 会得到 `127`，标准错误里是 `external commands are not available`。那个 `127` 不是「两项不同」。两项不同是 `test` 的 `1`。看到 `127` 时，比较没有发生。看到 `1` 时，比较发生了，命题为假，清单还可以继续往下走。下一章的 `if` 就接在这个 `1` 上，决定印出未带，而不是结束进程。


整数阅读还有几个具体的边界，值得在用 `-eq` 之前看一眼。`printf` 的 `%d` 和 `test` 的整数运算符都按十进制读。`08` 读成 `8`，前面的零不参加比较。`3abc` 会读到 `3` 就停，后面的字母不使整个比较变成 `2`。空格开头的数字也能读出数值。这些规则对步数无害，因为步数是你自己写成的纯数字。它们对清单有害，因为钥匙会被读成 `0`，和水杯的 `0` 相等。所以「看起来比出了相等」不等于「两项是同一个词」。确认文字时只信任 `=` 和 `!=`。确认步数时，保证两边都是你写的十进制，再使用 `-gt` 或 `-eq`。

`2` 这个返回值要留在用法错误上，不要拿来表示「未带」。未带是命题为假，用 `1`。用法错误是缺括号、未知运算符、参数太多。看到标准错误里的说明，就去改式子，而不是把 `2` 交进 `if` 当成第三种清单状态。`if` 只区分 `0` 和其他。`2` 会走进 `else`，和普通的不相等混在一起，你还以为是水杯对不上。可运行的例子避开 `2`，就是为了让终端上的 `0` 和 `1` 只描述命题。

比较之前先确认值已经在变量里。`item` 若还是空的，和钥匙比较得到 `1`，和空串比较得到 `0`。这个 `1` 不是「钥匙和水杯不同」，而是「你还没赋值」。每一块都先写 `item=钥匙` 或你这一题要的那一项，再调用方括号。块与块不共享表，漏掉赋值不会沿用上一块的钥匙。沿用只发生在同一块的后半段，因为那仍是一次运行。

## 小结

`test` 和 `[ ]` 把判断写成退出码。`0` 是成立，`1` 是不成立，脚本继续。汉字用 `=` 和 `!=`。步数用 `-eq`、`-ne`、`-lt`、`-le`、`-gt`、`-ge`。把汉字交给 `-eq` 会两边都变成 `0`，比较不再看字。`-z` 和 `-n` 看空与非空。结果要用 `$?` 印出来或抄进变量。

下一章用 `if` 按这个状态选择印出「已带」还是「未带」。
