`test` 已经能把「是不是钥匙」写成 `0` 或 `1`。这一章按这个数字挑选要印的句子。`if` 先执行条件那一段，最近状态变成条件的退出码。状态是 `0` 时执行 `then` 到下一个分支之间的命令，否则去看 `elif` 或 `else`。`fi` 把整个结构收住。条件里放上一章的方括号，分支里放 `printf`。清单于是从「一个数字」变成「一句人话」。

`elif` 是再嵌一层同样的规则。上一层条件不为 `0`，才执行这一层的条件。这一层为 `0`，才执行它的 `then`。`else` 接住前面都没有成功的情况。钥匙、水杯、车票正好构成三支。下面这一块把 `item` 设成车票，前两支都对不上，走到 `else`，印出车票。

```sh run expect="车票" title="三支里的第三支"
item=车票
if [ "$item" = 钥匙 ]; then
  printf '%s\n' 钥匙
elif [ "$item" = 水杯 ]; then
  printf '%s\n' 水杯
else
  printf '%s\n' 车票
fi
```

把值改成水杯，会印出水杯，并且不会再去碰 `else`。分支是互斥的。一旦某一支的条件为 `0`，后面的条件不再执行。这和下一章的短路是同一种节省，只是 `if` 把节省写在关键字上，分支里可以放好几条命令。

```sh run expect="水杯" title="命中中间一支"
item=水杯
if [ "$item" = 钥匙 ]; then
  printf '%s\n' 钥匙
elif [ "$item" = 水杯 ]; then
  printf '%s\n' 水杯
else
  printf '%s\n' 车票
fi
```

没有 `else`、条件也不成立时，`if` 整体的退出码是 `0`。没有被选中的分支等于什么都没做，而「什么都没做」在这只壳里是成功。不要用整个 `if` 的最终状态去代表「当时条件为假」。条件为假的信息只在条件刚执行完的那一刻躺在 `$?` 里，`if` 随即就会因为它去跑另一支，或者因为没有另一支而变成 `0`。你若要记住判断，仍在条件之后、进入分支之前不好插一句抄写；更直接的办法是在分支里给一个变量赋值。`then` 里写 `label=已带`，`else` 里写 `label=未带`，分支结束后再 `printf`。变量留在同一个进程里，所以 `fi` 之后还读得到。

```sh run expect="已带" title="用变量把分支带出来"
item=钥匙
if [ "$item" = 钥匙 ]; then
  label=已带
else
  label=未带
fi
printf '%s\n' "$label"
```

条件最好保持安静。方括号不往标准输出写字，终端上就只有分支里的那一行。若把 `printf` 放进条件，它的退出码几乎总是 `0`，于是 `then` 总会执行，而且那些字会混进输出。条件的职责是交出状态，分支的职责是说话。`true` 可以当作永远成立的条件，`false` 当作永远不成立。用它们试结构时，记得它们不读 `item`。正式检查仍用方括号。

`then`、`elif`、`else`、`fi` 都是关键字。它们出现在不该出现的位置时，壳报语法错误，退出码是 `2`，后面的清单不会接着跑。关键字要写在词的位置上，不要用变量去拼出一个 `if`。这只壳没有 `eval`，也没有第二种解析。你写下来的结构就是会执行的结构。

分支里可以再放 `if`。内层仍然看退出码。例如先看非空，再看是不是钥匙。空值走外层的 `else`，印出未带。钥匙走内层，印出已带。这种嵌套在三项之内够用。再深就会难读，届时用 `elif` 把层次摊平。摊平之后每一支仍是一次字符串比较，不会因为写得长就变成整数比较。

条件是一个命令列表，不限于单个方括号。你可以用分号放两条命令，列表的状态是最后一条的状态。这很容易让人吃惊：前面的 `false` 不会阻止后面的 `true`，而 `if` 只看见最后的 `0`。需要「两边都成立」时，不要靠分号，用下一章的 `&&`。这一章的条件都写成单独一个方括号，让状态的来源只有一处。

`if` 不会创造作用域。分支里的赋值，`fi` 之后还在。分支里没有执行到的赋值，就不会发生。`item` 在条件里只被读取，方括号不会把它改掉。读和写都在同一张表上，这是不能分身的直接后果：没有一个分支跑在子壳里，所以你也不必把结果「传出来」。传出来的动作是多余的，写进变量就已经在外面了。

有人会想用函数把「已带 / 未带」包起来，在每项上调用。函数不是这只壳的语法。写成 `label() { ... }` 时，名字会被当成外部命令，退出码 `127`。重复的三行 `if` 就写在要用的地方。清单只有三项，重复比一个不存在的函数更诚实。

```sh norun title="没有函数可以收起分支"
label() {
  printf '%s\n' 已带
}
```

`exit` 放在某一支里会结束整个脚本，另一支和 `fi` 后面的命令都不会再跑。可运行的例子用 `printf` 或赋值收尾。你要的是一句结果，不是提前离开进程。

和 `test` 章的陷阱接上：条件里继续用 `=` 比较汉字。若改成 `-eq`，钥匙和水杯会被同时读成 `0`，`elif` 的那一支也会被当成成立，清单会在错误的地方说话。整数比较留给纯数字的步数。这一章的三项都是字。


`if` 接的是退出码，不是表达式的真值对象。条件那一段先作为普通命令跑完，最近状态换成它的退出码。是 `0` 才进入 `then`。不是 `0` 就去尝试 `elif` 的条件，或者进入 `else`。`elif` 在实现上是再挂一个同样的 `if`，所以规则不必另学一套。每一层仍然只看自己的条件。钥匙、水杯、车票写成三支，互斥就来自这个顺序：前面的条件一旦成功，后面的条件不再执行，后面的 `printf` 也不会说话。

没有 `else` 而且条件失败时，整个 `if` 的状态是 `0`。空的一侧被当成什么都没做，而什么都没做在这里是成功。因此你不能在 `fi` 之后读 `$?`，还以为它保留着「刚才不相等」。那个不相等只存在于条件刚结束的一刻，`if` 随即就因为它去走了另一支，或者因为没有另一支而变成 `0`。要记住结论，在分支里赋值。`label=已带` 和 `label=未带` 写在不同的支里，`fi` 之后 `"$label"` 还在。它还在，是因为分支没有跑在子壳里。没有东西需要 `export`，也没有东西会被子壳丢掉。

条件要安静。方括号不往标准输出写字，终端上就只有被选中的那一句。把 `printf` 放进条件，它的状态多半是 `0`，`then` 就会总是执行，而且那些字已经混进输出，你无法用期望去区分「条件说的话」和「分支说的话」。列表若用分号串起两条命令，状态取最后一条。前面的 `false` 不会取消后面的 `true`，`if` 只看见最后的 `0`。两边都要成立时，把连接留给 `&&`。这一章的条件保持为单独一个方括号，状态的来源只有比较本身。

关键字必须照写。`then`、`elif`、`else`、`fi` 放错位置是语法错误，退出码 `2`，执行还没开始。你不能把这些字放进变量再拼出一个 `if`，因为没有 `eval` 会把变量里的字重新解析。写在脚本里的结构就是会跑的结构。嵌套 `if` 可以，内层仍看退出码。先用 `-n` 确认非空，再用 `=` 确认是钥匙，空值走外层的另一支。三项之内嵌套一层够用。再多就改成平铺的 `elif`，每一支仍是一次字符串比较。不要在某一支里改用 `-eq` 去比汉字，否则钥匙和水杯都会被读成 `0`，错误的一支会说话。

函数本可以收下重复的分支，这只壳没有函数语法。`label() { ... }` 会被当成外部命令，`127`，并且右花括号也可能再变成另一条失败的命令。三项的分支就写在原地。重复在这里比一个不存在的抽象更可读。`exit` 放进某一支会结束整个进程，另一支和 `fi` 后面的句子都不再执行。你要的是一句「已带」或「未带」，就用 `printf`。进程留到脚本末尾，由最后一条命令的状态代表这次运行。

分支里改过的变量，没走到的那一支不会改。读 `item` 的方括号也不会把 `item` 写掉。读和写都发生在你看得见的那些行上。这使 `if` 适合清单：每一句输出都能指回某一支条件，而条件又能指回 `test` 的 `0` 或 `1`。下一章把「只有一支、而且那一支只有一条命令」收成 `&&`，省掉关键字，但不再省掉你对跳过的责任。跳过必须包括赋值和重定向，否则失败的检查仍会改掉笔记。


分支里的赋值可以不止一个名字。你可以把 `label=已带` 和 `code=0` 写在同一支，把 `label=未带` 和 `code=1` 写在另一支。`fi` 之后两个名字都还在，因为它们写在同一张表上。`code` 里的字符是你为了后面的整数比较准备的，它不会自动变成最近状态。最近状态在离开 `if` 时，往往已经是最后一条赋值或 `printf` 的 `0`。后面若要按「当时是否已带」做整数判断，用 `[ "$code" -eq 0 ]`，不要用裸的 `$?`。这一分工把 `if` 从「当场说话」延伸成「留下可以再判断的记号」。记号是变量，不是第二个进程带回来的出口。

`then` 和 `fi` 之间如果只有赋值、没有 `printf`，终端可以是空的，直到你在 `fi` 之后打印。空终端在这里表示「话被推迟了」，不表示条件没跑。调试时若什么都看不见，先在 `fi` 后加一行 `printf`，确认 `label` 有值，再决定话应该说在分支里还是说在结构外面。说在外面的好处是格式只有一份。说在里面的好处是每一支可以有完全不同的句子。三项清单两种都可以，只要期望和真正会执行的那一支一致。

`elif` 的条件在前面已经成功时不会执行。你若在那个条件里放了赋值或 `read`，那些副作用也不会发生。这和短路跳过右边是同一类节省。想让每一项都被读到，就把 `read` 放在 `if` 外面，让 `if` 只负责挑句子。清单的三项写在脚本里，不靠条件去产生数据。条件只消费已经放进 `item` 的数据。


关键字之间的换行和分号都只是分隔。`then` 后面可以立刻写命令，也可以先换行。壳在解析时把这些空白吃掉，不会因为你把 `printf` 另起一行就多执行一次。少掉 `fi` 则整段脚本在解析阶段失败，退出码是 `2`，任何分支都不会跑。所以写完条件就先写上 `fi`，再往里面填句子。这个习惯能避免半截的 `if` 把后面的练习代码一起挡在语法错误里。

## 小结

`if` 在条件退出码为 `0` 时执行 `then`，否则尝试 `elif`，再否则执行 `else`。没有 `else` 且条件为假时，整个 `if` 的状态是 `0`，所以要用分支里的变量记住「已带」或「未带」。条件保持安静，话放在分支里。汉字比较继续用 `=`。函数语法不存在。

下一章用 `&&` 和 `||` 把「成立才印」写成一条短路，右边在不该跑的时候连文件都不会去碰。
