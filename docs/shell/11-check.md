前面每一章只给清单加一种能力。这一章把它们收成一次出门检查，并且每种机制都露面：变量、`test`、循环、管道、重定向。命令仍然全是内建。没有 `fork`，所以这一次检查从头到尾是一个进程、一张变量表、一块用来交接的内存，外加一个叫 `note.txt` 的文件。

结构是故意直白的。先把要带的那一项放进 `item`。用 `printf` 把它写进 `note.txt`，这是唯一的一次重定向，用 `>` 截断，保证文件里只有这一行。再用 `cat note.txt | read line` 把这一行读回来。这是唯一的一次管道：`cat` 读文件，写到内存，`read` 从内存取走一行，放进 `line`。因为没有子壳，`line` 在竖线之后还在。然后用 `for` 走过钥匙、水杯、车票。这是唯一的循环。每一轮用一次方括号，比较 `piece` 和 `line`。相等时用 `&&` 印出该项。字符串比较用 `=`。三项里只有钥匙会印出来。

```sh run expect="钥匙" title="写、交、读、对"
item=钥匙
printf '%s\n' "$item" > note.txt
cat note.txt | read line
for piece in 钥匙 水杯 车票; do
  [ "$piece" = "$line" ] && printf '%s\n' "$piece"
done
true
```

循环的退出码是最后一轮本体的状态。最后一轮是车票，和钥匙不相等，方括号留下 `1`，`&&` 把这个 `1` 交给 `for`。字已经印出来了，脚本若停在这里，整次运行仍是非零。末尾的 `true` 把状态收回 `0`，它不印字，也不改 `line`。这是最近状态只有一格的后果：成功的那一轮曾经是 `0`，后来被最后一轮盖掉了。

把这条脚本从上往下对回前面的章节。`item=钥匙` 是赋值，值留在表里。双引号让 `printf` 拿到的是钥匙而不是 `$item` 这几个字符。`>` 把标准输出送进当前目录的 `note.txt`，所以这一次 `printf` 的字不直接出现在终端。终端上的钥匙来自循环里那次成功的 `printf`。管道若被改成外部命令，右边会是 `127`，`line` 也得不到文件里的字。`for` 的词表写死三项，不使用星号，也不使用算术去数到 `3`。方括号在不相等时状态是 `1`，`&&` 跳过打印，所以水杯和车票不会多出一行。相等时状态是 `0`，打印发生。

第二块把 `item` 改成水杯，其余不动。输出应当变成水杯。这证明循环不是写死了打印钥匙，而是在对 `line`。`line` 又来自文件，文件来自变量。链条上任何一处换成别的项，终端就换成那一项。

```sh run expect="水杯" title="换成水杯"
item=水杯
printf '%s\n' "$item" > note.txt
cat note.txt | read line
for piece in 钥匙 水杯 车票; do
  [ "$piece" = "$line" ] && printf '%s\n' "$piece"
done
true
```

第三块在打印之外留下一个状态，方便你看见判断本身。`found` 从 `0` 开始。命中时改成 `1`。循环结束后用整数比较印出 `found`。这里的 `1` 表示「找到了」，不要和 `test` 失败时的 `1` 混为一谈。标签写成 `found:`，数字的含义就钉在标签上。管道、重定向和循环仍然各有一次。判断多了一次整数比较，用来把变量里的标记显出来。汉字的那一次比较仍是 `=`。

```sh run expect="found:1" title="命中之后留下标记"
item=车票
printf '%s\n' "$item" > note.txt
cat note.txt | read line
found=0
for piece in 钥匙 水杯 车票; do
  if [ "$piece" = "$line" ]; then
    found=1
  fi
done
printf '%s\n' "found:$found"
```

`found:1` 说明车票在三轮里被对上了。若把词表里的车票删掉，`found` 会保持 `0`。标记放在循环外面初始化，是因为没命中时也需要一个明确的值。没赋过值的名字展开成空，`printf` 会印出 `found:` 后面什么都没有，你分不清是失败还是忘了初始化。

这次检查里没有出现的东西，同样是设计的一部分。没有 `cd`，所以 `note.txt` 写在当前目录。没有命令替换，所以读回文件用的是管道和 `read`，不是 `$(cat note.txt)`。没有算术，所以不对「第几项」做加法，只把词写在 `for` 后面。没有函数，所以比较就写在循环本体里。没有后台，三项是一轮接一轮。没有 here-doc，写进文件的字来自 `printf` 的参数。没有外部的 `diff` 或 `grep` 去比较文件，比较由 `test` 完成。你若把其中任何一个放回去，要么得到 `127` 和 `external commands are not available`，要么得到语法错误 `2`，要么得到一串没有执行过的字面量。

```sh norun title="这次检查仍然不能分身"
item=$(cat note.txt)
ls note.txt
diff note.txt /tmp/other
```

`$$` 在这次检查里仍然是 `1`。文件的写入、管道的缓冲、循环的赋值，都没有制造新的进程号。`$#` 仍然是 `0`。不要给这个脚本加一个必须从 `$1` 读取的项。项写在 `item=` 的右边，或者在你自己扩展时从 `read` 进入。围栏输入是另一条通道，这一章为了把重定向和管道看清楚，没有同时再接围栏。你可以在练习里把第一行改成 `read`，那是上一章的技能，和这一章的文件链条分开练。

退出码方面，最后一条 `printf` 成功，整段脚本就是 `0`。循环里那些不相等的方括号曾经把最近状态设成 `1`，随后被跳过或被下一轮盖掉。你若要保留「有没有不相等」，在不相等的分支里另设一个变量。最近状态只有一格，这是第一章就定下的记忆模型，到最后一章也没有变成一张栈。不能分身的壳，没有地方再放第二格「自动的」历史。

性能和规模也沿用前面的限制。词表三项，管道里一行汉字，文件一次写入。`while` 的十万次上限不会被碰到，因为这一章用的是 `for`。即便改成 `while read`，行数也应当就是笔记的行数。不要用一个恒真条件去扫这张清单。

把整门课收成一句可执行的话：先赋值，再按需要用引号展开，用 `test` 得到 `0` 或 `1`，用 `if` 或 `&&` 决定说不说，用会结束的循环走过已知的词，用内存管道把字节交给下一个内建，用相对路径把要留下的那一行放进 `note.txt`。外部世界的程序不在这个进程里启动。清单因此是自足的。它能检查的，是你放进变量、输入和这个文件里的那些字。


把五种机制放进同一次运行，是为了让你看见它们共享的那一个进程，而不是再学第六种语法。`item` 是普通赋值。`>` 把 `"$item"` 写进 `note.txt`，终端暂时还没有字。`cat note.txt | read line` 用唯一的管道把文件交回变量。`for` 用唯一的循环走过三个写死的词。方括号用 `=` 做唯一的那类字符串判断，`&&` 只在相等时打印。末尾的 `true` 把状态收回 `0`，因为最后一轮若不相等，`for` 会留下 `1`，即使正确的那一项已经印过。输出里的钥匙或水杯来自循环，不来自写入文件的那次 `printf`。你改 `item`，文件、`line` 和最终那一行一起改。链条是通的。

`found` 那种标记用来对付最近状态只有一格的事实。进入循环前写成 `0`，命中时写成 `1`，循环后印出 `found:1`。不要把这个 `1` 读成 `test` 的失败。失败的 `1` 是退出码，标记的 `1` 是你放进变量的字符。两者可以同时存在于一次运行的不同时刻，但不能同时挤在 `$?` 里。要历史就多占名字。壳不提供调用栈上的自动历史，因为没有函数，也没有子壳。

这次检查故意不用的东西，和它用了的东西一样说明设计。`$(cat note.txt)` 不会读文件。`ls` 和 `diff` 会以 `127` 失败，错误信息含有 `external commands are not available`。`cd` 不能换目录，所以名字是相对的 `note.txt`。星号不会展开成文件。`$((...))` 不会算「第几项」。函数和后台写不出来。here-doc 不是把字放进文件的方法，`printf` 才是。`$$` 在写入、管道和循环之后仍是 `1`。`$#` 仍是 `0`。项若来自外面，走 `read` 和围栏，不走 `$1`。

规模保持在一行、三项、一次打开。`while` 的十万次上限碰不到。若你把 `for` 换成 `while read`，行数就应当是笔记的行数，条件在读尽时变成假。恒真循环不是检查，是空转。五种机制各做一次自己的事：变量记值，重定向留值，管道交值，判断比值，循环提供被比的词。少掉任何一种，检查就退回前面某一章的局部演示。多出一种外部程序，检查就离开这只壳能够完成的范围。

练习把起点换成围栏里的水杯时，`read` 代替了第一行赋值，文件、管道和循环仍在。输入是数据，不会在读入时展开。脚本里的双引号才会在写入前展开。围栏、文件和终端是三处你可以核对的地方：围栏上写着水杯，文件里应当是水杯，终端上也是水杯。三者一致，链条就是完整的。


核对这次检查时，按字节的去向走一遍，比按章节名回忆更可靠。`item` 里的字被双引号展开，进入 `printf` 的参数，被 `>` 送进 `note.txt`。`cat` 不带其他加工，把文件放进管道内存。`read` 去掉换行，放进 `line`。`for` 的每一轮把词放进 `piece`，`[` 用 `=` 比较两段字节。相等的那一轮，`printf` 把 `piece` 送到终端。`true` 不改变这些字节，只把退出码改回 `0`。任何一步若换成外部程序，链条在那一步断开，后面的变量保持旧值或空值，终端上的汉字不再能代表文件里的字。

练习里的围栏只替换链条的第一环。`read item` 从标准输入取得水杯，后面的写入、管道和循环原样保留。这样五种机制仍然都在，只是值的来源从字面量换成了输入。来源可以换，内建的边界不换。

末尾的 `true` 容易被看成多余。它多余在输出上，不多余在退出码上。最后一轮比较车票和钥匙时，方括号失败，`&&` 不打印，`for` 把 `1` 带出循环。前面打印钥匙的那一轮，状态早已被盖掉。`true` 把整段脚本的状态设回 `0`，同时不增加一行字。你若删掉它，终端内容仍然正确，进程却以失败结束。核对输出的人看得到钥匙，核对退出码的人会以为链条断了。两条核对都要满足，所以留下这一条什么都不印的成功命令。

## 小结

一次检查里，变量保存要带的项，`>` 把它写入 `note.txt`，管道让 `cat` 把文件交给 `read`，`for` 用 `=` 找出相同的那一项。全部是内建。`$$` 仍是 `1`，`$#` 仍是 `0`。命令替换、外部命令、`cd`、通配、算术、函数和后台都不参与。最近状态仍然只有一格，要留下的标记写进你自己的变量。

练习里把起点换成从标准输入读入，或把输出改成只在车票上说话。保持五种机制时，不要为了短而调用一个不存在的外部程序。

