引号章留下了一个名字 `item`。这一章问两件紧挨着的事：这个名字怎样写进那张唯一的变量表，以及一条命令结束之后那个退出码还能活多久。两件事都发生在同一个进程里，所以没有「只对下一条命令生效」的临时环境，也没有另一个进程帮你保管上一次的状态。

赋值的形状是 `NAME=value`。名字由字母、数字和下划线组成，并且不能以数字开头。等号左边和等号本身必须紧挨着，值写在等号右边，由展开规则处理。`item=钥匙` 查完之后，表里就有了钥匙。整行如果只有赋值，没有命令名，这条「命令」的退出码是 `0`，标准输出是空的。壳不会为了确认赋值而印一行。你要用 `printf` 把值再送出来，才看得见。

```sh run expect="钥匙" title="赋值之后再印"
item=钥匙
printf '%s\n' "$item"
```

`${item}` 和 `$item` 查的是同一格。花括号把名字圈住。下面这一块用花括号，输出仍然是钥匙。

```sh run expect="钥匙" title="花括号圈住名字"
item=钥匙
printf '%s\n' "${item}"
```

可以在同一行写两个赋值，它们从左到右写进同一张表，然后退出码是 `0`。`item=钥匙 other=水杯` 之后两个名字都在。因为没有子进程，你没法把赋值包进一个会丢掉修改的括号里。子壳的语法在这里也不是隔离，圆括号会被当成命令名的一部分，走向 `127`。变量一旦写上，就留到这次运行结束。下一次点击运行才是一张新表，那是宿主重新启动了 wasm，不是壳自己分了身。

退出码是另一格记忆，名字叫最近状态。`true` 和 `:` 把它设成 `0`。`false` 把它设成 `1`。`:` 什么都不印，适合你需要一次成功、又不想弄脏清单的时候。`printf` 在格式合法时也是 `0`。展开 `$?` 时，壳把这格记忆写成十进制数字，放进当前这个词。展开发生在命令开始之前，所以 `printf '%d\n' $?` 印出的是上一条命令的状态，不是 `printf` 自己的。等 `printf` 返回，最近状态才变成 `0`。你在终端上看到的 `1`，是更早的那条 `false`。

```sh run expect="1" title="立刻读出失败"
false
printf '%d\n' $?
```

若中间又做了别的事，这格记忆会被盖住。`false` 之后先执行 `:`，再印 `$?`，看到的是 `:` 的 `0`。`false` 的 `1` 已经不在了。清单上的判断若要留到后面用，得在下一条命令之前抄进一个普通变量。`st=$?` 在展开阶段读到上一条的状态，把字符 `1` 或 `0` 放进 `st`。赋值本身随后把最近状态设成 `0`，但 `st` 里的字符还在。再后面的 `printf` 印的是 `st`，不是此刻的 `$?`。

```sh run expect="1" title="抄进变量再印"
false
st=$?
printf '%s\n' "$st"
```

这一块的输出是 `1`。若把 `st=$?` 换成先 `printf` 再赋值，`st` 会拿到 `printf` 的 `0`。抄写的位置就是含义。没有第二个进程可以在旁边帮你冻结状态，冻结的办法只有：在表里再占一个名字。

`$#` 不是最近状态。它是位置参数的个数。运行器的参数只有脚本文件，所以个数是 `0`。`$$` 也不是状态，它固定写成 `1`，表示这个实例没有另一个进程号可报。`$0` 是脚本路径。`$1` 是空。把它们和 `$?` 放在同一段里时，要用不同的标签，免得一个数字说不清自己是哪一格。

```sh run expect="n:0" title="三种不同的数字"
false
printf '%s\n' "status:$?"
printf '%s\n' "n:$#"
printf '%s\n' "self:$$"
```

第一行是 `status:1`，因为前面是 `false`。第二行是 `n:0`。第三行是 `self:1`。`status` 和 `self` 都带着数字 `1`，标签把它们分开。期望用 `n:0` 核对参数个数，避免只写一个光秃秃的 `1` 时分不清来源。

命令替换是别的壳用来把输出收进变量的办法。`item=$(printf '%s\n' 钥匙)` 在这里不会去运行括号里的 `printf`。这一词里有括号和美元符号，而且没有引号包住整个赋值的话，它仍然可能被识别成赋值，值则是字面的 `$(printf ...)` 展开结果。无论细枝末节如何，它都不会把钥匙从一次命令的输出里取回来。课程不把这种写法放进可运行块。要收下一行输出，后面用管道加 `read`，那是同一进程里的读，变量会留下来。现在先记住：输出进变量，没有一条捷径叫命令替换。

```sh norun title="不能靠命令替换收集输出"
item=$(printf '%s\n' 钥匙)
```

算术扩展同样不能用来给状态加一。`st=$((st+1))` 不会把数字加一。计数的事放到 `while` 那一章，用你自己写的下一步来做，而不是用 `$((...))`。

`exit` 会立刻结束整个壳，退出码由它的参数决定，缺省则用最近状态。因为它结束的是唯一的进程，写在中间会让后面的 `printf` 不再执行。可运行的例子不调用它。你若要观察一个非零状态，用 `false` 或 `test`，然后用 `printf` 把 `$?` 印出来，让脚本的最后一条命令仍然成功。这样终端里有数字，这次运行也正常结束。

前缀赋值在别的壳里常常只影响那一条外部命令的环境。这里没有外部命令的环境可隔离。`item=钥匙 printf '%s\n' "$item"` 会先把 `item` 设成钥匙，再执行 `printf`，而且钥匙会留在表里。它不是「只活在这一条命令期间」。清单上的赋值就写成单独的一行，读起来清楚，也避免你以为作用域会自动收回。

空赋值 `item=` 把值设成空串，退出码仍是 `0`。这和 `false` 的 `1` 完全是两回事。空值是数据，失败是状态。下一章用 `test` 把「值是不是空」「值是不是钥匙」变成新的状态，让数据再走回 `$?`。在那之前，不要把空变量理解成命令失败。

变量表是这次运行私有的。块和块之间不共享。每一块都重新写 `item=钥匙` 或 `false`。这不是啰嗦，是让每一块都能单独点运行。若省略赋值，双引号展开到的就是空，输出会变成空行，期望里的钥匙对不上，而壳不会提醒你「上一块曾经赋值过」。


变量表之所以简单，是因为没有第二个进程来持有另一份拷贝。每一次 `NAME=value` 都写进这一份表。同名再写一次，就换掉原来的值，旧值不会堆成历史。你要历史，就得自己起第二个名字，在覆盖之前把旧值抄过去。`prev=$item` 然后 `item=水杯`，`prev` 里还是钥匙。抄写是普通赋值，仍然不打印，退出码仍是 `0`。清单上若要保留「出门前本来打算带的」和「现在改成要带的」，就用两个名字，不要指望壳帮你留撤销栈。

最近状态是表外的另一格，而且只有一格。`false` 把它写成 `1`，下一条命令在展开自己的参数时可以读到 `$?`。展开先于这条命令的执行，所以 `printf '%d\n' $?` 印出的是上一格，等 `printf` 返回，这一格才变成 `0`。中间插入任何命令都会改写它，包括看起来无害的 `:` 和成功的赋值。因此「先抄到 `st`，再做别的事」不是风格，是这格记忆的容量。`st=$?` 在展开时把数字收进普通变量。赋值完成后，最近状态变成赋值的 `0`，`st` 里的字符不动。后面你印多少次 `"$st"`，得到的都是那一次抄下来的字。

这格记忆也不要和 `$#`、`$$` 混读。`$#` 是位置参数的个数，运行器只把脚本文件交给壳，所以是 `0`。`$$` 是壳在展开时写下的字符 `1`，它不查询操作系统，也不会因为你赋值、循环或写文件而变成别的数字。`$0` 是脚本路径，`$1` 是空。把 `$?` 印成单独的一行时，请同时印一个标签，例如 `status:`，这样终端上的 `1` 不会和 `self:1` 里的那个 `1` 撞车。标签是文字，写在双引号里，跟在它后面的 `$?` 才会展开。整段放进单引号，标签和美元符号都会变成字面，你就看不见状态。

前缀赋值不会自动收回。`item=钥匙 printf '%s\n' "$item"` 先写表，再执行 `printf`，钥匙留到这次运行结束。别的壳把这种前缀理解成「只放进这一条子进程的环境」。这里没有子进程，环境就是这张表。课程把赋值写成单独一行，是为了让读脚本的人不用猜测作用域。你若需要临时值，就在用完之后再赋一次别的值，收回是你的赋值，不是壳的退栈。

命令替换常常被用来把一条命令的输出收进变量。这只壳不执行 `$(...)`。括号留在值里，或者在不能运行的块里被我们明确排除。要收一行输出，用后面的管道和 `read`：左边的内建把字节放进内存，`read` 在同一个进程里赋值。那一章会看见 `item` 在竖线之后还在。现在只要知道，输出进变量没有一条叫命令替换的近路，算术扩展也不会把 `st` 加一。

`exit` 会结束唯一的进程。参数是退出码，不写参数就用最近状态。写在脚本中间，后面的 `printf` 不再执行，终端上就缺了你想核对的那一行。观察失败的办法是执行 `false` 或 `test`，立刻打印或抄写 `$?`，让最后一条命令是成功的 `printf`。这样数字在输出里，运行本身以 `0` 结束。语法错误是另一条路，退出码 `2`，来自还没开始执行的解析。赋值写错成外部命令，才是 `127`。三种结局不要混成「脚本红了」。

空赋值和未赋值在读取时都是空串。`printf` 打出空行，`-z` 会在下一章把它看成成立。空串是数据。`false` 的 `1` 是状态。你可以把状态抄进变量，那个变量的值是字符 `1`，它自己的存在并不等于最近状态。之后你若执行别的命令，最近状态变了，变量里的字符仍是 `1`。判断「现在的状态」看 `$?`，判断「当时抄下的状态」看那个变量。清单往后都靠这个区分。


还有一个容易忽略的次序。一条只有赋值的行，退出码是 `0`，但它仍然占据了「上一条命令」的位置。你若在 `false` 和 `printf '%d\n' $?` 之间写了 `item=钥匙`，印出来的是赋值的 `0`，不是 `false` 的 `1`。抄写必须紧挨着你关心的那条命令。清单上先判断、后记录名字时，把记录写成 `st=$?`，不要先去改 `item` 再回头看状态。`item` 的新旧和状态的新旧是两张账，写在同一段脚本里，读的时候按行号分开。

## 小结

`item=钥匙` 把值留在这张表里，直到这次运行结束。只有赋值的行，退出码是 `0`，并且不印字。`$?` 在下一条命令展开时给出最近状态，所以要在别的命令之前把它抄进 `st`。`$#` 是 `0`，`$$` 是 `1`，`$1` 是空。命令替换和算术扩展不负责收集输出或做加法。
