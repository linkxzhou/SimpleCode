上一章把钥匙、水杯、车票印了出来，也说明了这只壳为什么只有一个进程。这一章给第一项一个名字，然后用两种引号去读它。名字仍然是 `item`，值仍然是钥匙。换名字会把话题从引号上拉开。

引号要解决的问题很窄：一个词里面哪些字符按字面留下，哪些字符要先换成变量里的内容。壳分两步处理一个词。第一步是词法，它把引号包进去，作为一个原始词记住，空格和换行仍然负责把词切开。第二步是展开，它看着原始词里的引号种类，决定 `$` 要不要工作。单引号和双引号的差别就发生在第二步。因为没有第二个进程，展开只是在同一张变量表上查一次，查完把字符放进这个词。它不会为了展开再去启动别的程序。

单引号从开始的那个引号抄到下一个单引号，中间的每一个字节都原样留下。美元符号还是美元符号，反斜杠还是反斜杠，不会触发转义。所以 `'$item'` 这一个参数交给 `printf` 之后，终端上出现的是 `$item` 这五个字符，外加格式串要求的换行。它看起来像「没写对」，其实是单引号在履行它的合同：教学的时候你需要把变量的写法本身印出来，和它的值对照。

双引号也把空格留在同一个词里，但会展开 `$`。`"$item"` 先查到钥匙，再把这两个汉字放进参数。双引号里的反斜杠只在少数字符前生效：美元符号、双引号本身、反斜杠和反引号。`\n` 这两个字符不会在这一步变成换行，它们会带着反斜杠一起交给后面的命令。`printf` 自己再把格式串里的 `\n` 解释成换行。这是两层规则叠在一起，容易混。记法是：引号决定壳要不要查变量，格式串里的转义由 `printf` 负责。

先让两种引号面对同一个变量。赋值写成 `item=钥匙`，等号两边不要加空格，值上也不要再套引号。这只壳认赋值的方式很严格：原始词里一旦出现引号，它就不再把这一词当成赋值，而当成一条命令的名字。`item="钥匙"` 展开之后会变成试图执行名为 `item=钥匙` 的外部命令，退出码 `127`，标准错误里仍是那句 `external commands are not available`。变量表里并没有 `item`。所以值若是一个不含空格的词，直接写在等号右边。钥匙、水杯、车票都是这种词。

```sh run expect="$item" title="单引号留下写法"
item=钥匙
printf '%s\n' '$item'
```

期望里的 `$item` 是字面量。若你改成双引号再运行，输出会变成钥匙，和这一块的期望对不上。点运行之前先看清引号的方向。

下一块把引号换成双引号，赋值再写一遍，因为上一块的变量不会留下来。

```sh run expect="钥匙" title="双引号展开成钥匙"
item=钥匙
printf '%s\n' "$item"
```

两块放在一起读，才是这一章的对照：同一个名字，单引号交出写法，双引号交出清单上的那一项。也可以在同一块里各印一次，顺序固定，先写法后值，避免你以为壳会随机挑选。

```sh run expect="$item" title="先写法后值"
item=钥匙
printf '%s\n' '$item'
printf '%s\n' "$item"
```

输出的第一行是 `$item`，第二行是钥匙。期望用 `$item` 就能命中第一行。看结果时请把两行都读完。只盯着汉字，会以为单引号那一行没有发生。

没有引号的 `$item` 也会展开。`printf '%s\n' $item` 在这个值上同样印出钥匙。展开发生在每一个词的内部，展开完不会再按空格把词切开。这和 bash 不同，原因仍然是这只壳的实现范围：它替换参数，不做字段再分割。钥匙这个值里面没有空格，所以有没有外面的双引号，结果一样。一旦值里有空格，差别就出现了。赋值本身若要放入空格，不能靠引号，因为引号会破坏赋值的识别。用反斜杠把空格留在同一个原始词里：`item=hello\ world`。展开等号右边时，反斜杠消失，值变成中间有空格的 `hello world`。之后 `"$item"` 和没有引号的 `$item` 都是一个参数，里面带着那个空格。清单上的三项没有空格，课程仍建议在参数位置写双引号，好让你以后把值换成带空格的句子时，词的边界还在你写引号的地方。

格式串自己必须放在引号里。`'%s\n'` 把反斜杠和 `n` 交给 `printf`，它写成换行。若写成 `%s\n` 并且不加引号，展开阶段会吃掉反斜杠，`printf` 看到的格式变成 `%sn`，换行不会出现，字母 `n` 会贴在字的后面。上一章已经踩过这个区分，这里它和变量引号是同一套词法：反斜杠在引号外是壳的转义，在单引号内是普通字符，在双引号内只对少数字符转义。

`${item}` 和 `$item` 在这个名字上结果相同。花括号的用处是把名字和后面的字分开。双引号里的 `见${item}了` 会展开成「见钥匙了」。写成 `见$item了` 时，名字会被读到最后一个合法字符，`了` 不是名字的一部分，所以碰巧也能得到钥匙再接上「了」。花括号在名字紧贴别的字、而那个字又能算进名字时才成为必要。数字参数写成 `${1}` 也可以，但这里 `$1` 是空的。特殊参数要写成 `$?`、`$#`、`$$`，不要写成 `${?}`。花括号里的问号会被当成一个普通变量名去查，查不到就是空，不会给你退出码。

命令替换不在这套规则里。`$(...)` 不会先去执行括号中的命令。若你把这种写法放进 `echo`，括号会原样出现在输出里。那不是「先运行再贴回」的结果，只是一串字符。算术扩展 `$((...))` 同样原样留下。两者都放到不能运行的块里，避免某一块的期望碰巧含有括号，让人以为替换已经发生。

```sh norun title="替换和算术都不会先执行"
echo $(printf '%s\n' 钥匙)
echo $((1+1))
```

通配也一样。星号不会展开成文件名，它只是星号。清单不靠通配去收集桌面上的东西，它靠你写下的词。通配的例子同样不放进可运行块。

引号不创造新的变量，也不改变退出码的规则。`printf` 成功时退出码是 `0`。单引号印出 `$item` 也是成功，壳不会因为「你大概是忘了展开」而失败。失败与否是命令的约定，不是读者的意图。下一章把退出码抄进变量，你会看到：印出字面量 `$item` 的那次 `printf`，它的 `$?` 仍是 `0`。

空值值得单独看一眼。`item=` 把值设成空字符串。双引号 `"$item"` 是一个空参数，`printf '%s\n'` 再加这个参数，会印出一行空行。单引号 `'$item'` 仍然印出 `$item`。空和「没展开」在终端上长得完全不同。判断空要用下一章以后的 `test`，不要靠肉眼把空行当成失败。

双引号里可以并排写字和变量。`printf '%s\n' "项:$item"` 在 `item` 为钥匙时得到 `项:钥匙`。冒号只是字，不会触发赋值，因为赋值只在命令的开头、并且原始词符合名字等号值的形状时才成立。放在 `printf` 参数里的 `项:$item` 是文字。这种拼法适合把标签和值放在同一行，标签用固定的字，值用双引号里的变量。练习里会用到。


引号这一层值得再往下看，因为它决定清单上的字是「名字的写法」还是「名字现在的值」。壳在读脚本时并不立刻查表。它先把一串字符收成词，空格和换行负责切开，引号负责把本来会切开的字符留在词里面。等这个词真的要交给命令时，才按引号的种类决定要不要查变量表。单引号的合同是抄写。从左引号到右引号之间，美元符号不会触发查表，反斜杠也不会变成转义。你因此能把 `$item` 这五个字符印出来，当作和钥匙对照的第一行。双引号的合同是在同一张表上查一次。`"$item"` 变成钥匙，是因为赋值已经把这两个汉字放进了 `item`。查表不启动新进程，所以引号不会因为「要展开」而突然需要 `fork`。

汉字在源码里是多字节的 UTF-8。引号不按「几个字」来数，它按字节抄到下一个引号。钥匙占两个汉字、六个字节，只要这六个字节都在引号里面，它们就会整段进参数。`printf` 的 `%s` 再把这些字节写出去，终端按 UTF-8 画出来。壳本身不算字数，也不把汉字切成三个字节给你看。你若在汉字中间插入引号，切的是字节序列，屏幕上会变成残缺的编码。课程的词都不这么切。

格式串和变量用的是同一套词法，职责却不同。格式串里的 `\n` 要交给 `printf`，所以格式串放在引号里，让反斜杠活过展开。变量放在另一种引号里，决定查不查表。两件事可以出现在同一次调用：`'%s\n'` 是格式，`"$item"` 是值。调换它们，`printf` 会把钥匙当成格式去扫描。钥匙里没有百分号，扫描的结果往往只是把汉字再印一遍，可一旦某项的文字里出现 `%`，格式就会多消耗参数或留下一个光秃的百分号。清单的文字是数据，数据放在 `%s` 后面，不放在格式的位置。

没有引号的 `$item` 也会查表。查完之后，这个壳不再按空格把结果拆开。钥匙没有空格，所以拆不拆都一样。这个省略是实现范围，不是邀请你依赖它。参数位置仍写双引号，词的边界就由你写的引号决定，而不是由值里碰巧有没有空格决定。赋值则相反：原始词里出现引号，这一词就不再是赋值。`item=钥匙` 能进表，`item="钥匙"` 会变成一条名叫 `item=钥匙` 的外部命令，退出码 `127`。空格若一定要进值，用反斜杠写在等号右边，让展开去掉反斜杠、留下空格。三项清单用不到这一步，知道界线在哪里即可。

花括号只圈名字。`${item}` 和 `$item` 在「后面跟着汉字」时结果常常相同，因为汉字不算名字字符。真正要防的是后面跟着字母或数字。特殊参数不要套进花括号去碰运气。`${?}` 会去查一个名字就叫问号的变量，查不到就是空，不会给你退出码。退出码的写法是 `$?`。参数个数是 `$#`。固定的 `1` 是 `$$`。

命令替换和算术扩展不在引号规则里开工。单引号当然会把 `$(...)` 按字面留下。双引号也不会先执行括号再把输出贴回来。`echo` 若接到这种词，终端上是括号本身。那一行看起来像结果，其实是源码没被执行。通配的星号同样留在词里，不会变成文件名。这些写法放在不能运行的块里，就是为了避免某一块的期望碰巧含有括号或星号，让人以为替换已经发生。

空值在引号下很好认。`item=` 之后，双引号展开成一个空参数，`printf` 打出空行。单引号仍然打出 `$item`。空行是值，`$item` 是写法，两者都不是命令失败。失败要看退出码，下一章才把它抄进名字。这一章只要你能指着同一变量说出：哪一行是写法，哪一行是钥匙。

## 小结

单引号按字面抄写，`'$item'` 印出 `$item`。双引号展开变量，`"$item"` 在这一章印出钥匙。两者看的是同一个名字。赋值的原始词里不能带引号，否则它会变成一条不存在的外部命令。格式串放在引号里，`\n` 才由 `printf` 解释成换行。展开之后不再按空格切词。`$(...)` 和 `$((...))` 不会执行。

## 练习

让 `item` 的值是水杯。第一行用单引号印出 `$item`，第二行用双引号印出水杯。两行都用 `%s` 和换行。

::: answer 参考答案：水杯的两种引号
```sh run expect="水杯" title="参考答案"
item=水杯
printf '%s\n' '$item'
printf '%s\n' "$item"
```
:::

用双引号把固定的字和变量接在一起，印出 `项:车票`。变量的值是车票。不要把整行写进单引号，否则美元符号会留下来。

::: answer 参考答案：标签和车票
```sh run expect="项:车票" title="参考答案"
item=车票
printf '%s\n' "项:$item"
```
:::
