`if` 能按状态挑选一整段。有时候你只想在判断成立时多做一条命令，例如印出 `open`。`&&` 和 `||` 把这种「做或不做」写成两个命令之间的连接，而不是写成关键字。连接的规则很短。`&&` 先跑左边，左边的退出码不是 `0`，右边整条就不再执行，连接的状态就是左边的状态。`||` 先跑左边，左边的退出码是 `0`，右边就不再执行，连接的状态就是左边的状态。右边被跳过时，它里面的赋值、打印和重定向都不会发生。

这仍然是同一个进程里的决定。没有一个后台进程被取消，因为右边根本还没开始。壳在执行到连接符时看最近状态，决定要不要进入右边那棵命令。省掉的是一次函数调用，不是一次 `kill`。

钥匙对得上时，右边的 `printf` 会跑，输出 `open`。

```sh run expect="open" title="对上才开口"
item=钥匙
[ "$item" = 钥匙 ] && printf '%s\n' open
```

和水杯对不上时，右边不跑。为了让你看见脚本还在继续，后面再印一行 `after`。终端上只有 `after`，没有 `open`。

```sh run expect="after" title="对不上就跳过"
item=钥匙
[ "$item" = 水杯 ] && printf '%s\n' open
printf '%s\n' after
```

`false && printf` 同样跳过右边。连接的状态保持为 `1`。紧接着印 `$?`，看到的就是这个 `1`。右边若执行了，状态会变成 `printf` 的 `0`，你就分不清是跳过还是印过。跳过本身把左边的失败留在最近状态里，直到下一条真正执行的命令把它盖掉。

```sh run expect="1" title="跳过之后状态还在"
false && printf '%s\n' no
printf '%d\n' $?
```

`||` 是另一面。左边成功，右边跳过。`true || printf '%s\n' no` 不会印出 `no`。左边失败，右边才跑。清单上可以用它给一项补一句默认的话：方括号失败时印出 `未带`。成功时什么都不印，由你在别的地方处理。不要在同一行里同时写 `&&` 和 `||` 还指望它们按「并且」和「或者」的逻辑课优先级结合。这只壳把两种连接都从左往右叠。`false && printf a || printf b` 会先因为 `false` 跳过中间，整段变成失败，然后 `||` 再执行最后的 `printf`，于是印出 `b`。`true && printf a || printf b` 会印出 `a`，并且因为中间成功而跳过 `b`。读起来要跟着从左到右走。课程的清单每次只用一种连接，避免叠在一起之后要在脑中重新画树。

被跳过的右边连重定向都不做。`false && printf 'no\n' > note.txt` 不会去创建 `note.txt`。这很重要，因为重定向若发生，会把文件截断或新建，哪怕 `printf` 的内容你并不想留下。短路保护的是整个右边命令，包括它的文件操作。下一章之前就可以依赖这一点：失败的检查不应当改掉已经写好的笔记。成功时右边才会打开文件。`true && printf 'yes\n' > note.txt` 会写下 `yes`。文件那一章会专门写读回，这里先把「跳过就不动文件」记住。

`&&` 的左边可以是 `test`，也可以是别的内建。左边若是 `printf`，它几乎总是成功，右边就会总是执行，短路失去意义，而且左边的字已经输出了。所以左边放判断，右边放动作。这和 `if` 的分工一致，只是右边通常只有一条管道或一条简单命令。需要好几条命令都在成立时执行，用 `if` 把它们放进 `then`。`&&` 右边再接 `&&` 可以串，但每一段的状态都会影响下一段，读起来比 `if` 长。三项清单用一个方括号加一个 `printf` 就够。

赋值放在右边时，只有左边成功才会赋值。`[ "$item" = 钥匙 ] && label=已带` 在对不上时不会去改 `label`。原来的 `label` 还在，若原来没有这个名字，它就仍然是空。这和 `if` 的分支赋值是同一件事的短写法。你若无论成败都要给 `label` 一个字，就用 `if` 和 `else` 两边都写，不要指望 `&&` 会在失败时填一个默认值。默认值是 `||` 的工作：`[ "$item" = 钥匙 ] || label=未带`。两边同时写又会回到从左到右的叠加上面。初学的块里只放一种。

`||` 也常被用来在失败时印一句，然后让人误以为脚本因此失败。右边的 `printf` 成功之后，整段连接的状态是 `0`。最后一条若是这个 `printf`，运行看起来是成功的，终端上却有一句「未带」。状态和文字要一起看。你若希望失败保持为失败，就不要在 `||` 右边放一条总是成功的命令，或者在印完之后再执行一次 `false`。这一章的例子若需要展示跳过，就在后面用单独的 `printf` 印出 `$?`，让数字和有没有字对照。

没有子壳可以让右边「在旁边试一次」。右边要么在这个进程里执行，要么完全不执行。执行了就会改这张变量表，也会改工作目录里的文件。这就是为什么跳过必须是真的跳过，而不是跑完再撤销。壳没有撤销。`&&` 的价值是避免那一次修改发生。

```sh norun title="不能把短路包进子壳再丢弃"
([ "$item" = 水杯 ] && printf '%s\n' open)
```

圆括号不会开辟一个可以丢掉的环境。它更可能变成一条外部命令的名字，得到 `127`。短路就写在当前这段脚本里。

冒号命令 `:` 可以放在右边当一个什么都不印的成功。一般不需要。左边已经成功时，你往往希望右边做实事。左边失败时，`:` 放在 `||` 右边会把状态改成 `0`，把失败抹掉。除非你故意要把失败变成成功，否则不要这么写。


短路是 `if` 的一种压缩，压缩掉的是关键字和多条命令的位置，留下来的是同一条规则：看左边的退出码，决定右边要不要开始。`&&` 在左边不是 `0` 时不开始右边。`||` 在左边是 `0` 时不开始右边。不开始的意思很硬。右边的赋值不会写表，右边的 `printf` 不会出字，右边的 `>` 也不会打开文件。壳没有先打开再撤销的步骤。文件要么被这条命令碰到，要么完全不被这条命令碰到。失败的检查因此可以安全地接在 `&&` 左边，不必担心右边把 `note.txt` 截断。

连接从左往右叠，两种连接的层级相同。`false && printf a || printf b` 先跳过中间，整段仍是失败，然后 `||` 执行最后的打印，终端上是 `b`。`true && printf a || printf b` 印出 `a`，并因为中间成功而跳过 `b`。这不是逻辑课里「并且高于或者」的树。你若需要那棵树，就用 `if` 把层次写出来。清单的每一行只用一种连接，左边是方括号，右边是一条 `printf`。读的人不用在脑中重排。

右边一旦执行，它的状态就成为这段连接的状态，也会写进最近状态。右边被跳过时，最近状态保持左边的值。`false && printf '%s\n' no` 之后立刻印 `$?`，得到 `1`。若在这之间插入成功的命令，`1` 会消失。抄写的纪律和赋值章相同。短路没有给状态开第二格。

左边不适合放总是成功的 `printf`。那样右边总会执行，短路不再表达判断，而且字已经输出。左边放 `test`，右边放动作。需要三行动作时，回到 `if` 的 `then`，不要把三行用 `&&` 串成一条很难读的链。链上任何一环失败，后面都会停，这有时正是你要的，但失败点会藏在一长串里。三项清单用一环就够。

`||` 常被用来补一句默认的话。左边的方括号失败，右边印出未带。右边的 `printf` 成功之后，整段的状态变成 `0`。终端上有「未带」，运行却是成功的。文字和状态要一起读。你若希望「未带」仍然把脚本留在失败，就不要让最后一条是这条成功的 `printf`。教学块选择把数字单独印出来，让 `1` 可见，而不是靠进程的退出码去当唯一的信号。

没有子壳能让你「试跑右边再丢掉副作用」。圆括号不会开辟那样的环境，它往往会变成外部命令的名字，得到 `127`。右边要么在这个进程里发生，要么不发生。`:` 放在 `||` 右边会把失败改写成成功，而且什么都不印。除非你故意要抹掉状态，否则不要用它来填空。`true` 也一样。填空用明确的 `printf` 或明确的赋值，让终端或变量里看得到你的决定。

和管道的分工可以先记在这里。管道不管左边失败与否，都会让右边去读缓冲。那是字节的交接。`&&` 才是「失败就不要做右边」。清单上若既要判断又要交接字节，先用 `&&` 包住会产生字节的那条命令，再让那条命令进入管道。不要用竖线代替 `&&`。下一章的循环还会反复使用判断。每一次循环的条件都是一次新的 `test`，短路则仍然是条件内部或本体内部的一次选择。


把短路放进清单时，还可以用它保护一次赋值。`[ "$item" = 钥匙 ] && label=已带` 只有在相等时才写 `label`。不相等时，原来的 `label` 保持原样；原来没有这个名字，它就仍然展开成空。随后你若无条件地 `printf '%s\n' "$label"`，空值会变成空行，看起来像命令没说话。要避免空行，就在 `&&` 的右边直接 `printf`，让「不成立」对应「没有这行输出」，而不是「有一行空的」。另一边的默认句子用单独的 `if` 写，或者单独一条 `||`，不要和这条 `&&` 挤在同一行里比赛优先级。

右边的命令若是 `read`，跳过就意味着这一轮不消费标准输入。这和跳过重定向是同一类后果：没执行的命令不碰它的输入输出。后面的 `read` 仍会看到原来的下一行。你若本意是「无论判断如何都要读掉一行」，就把 `read` 放在连接的左边或完全外面。判断只包住你真正想跳过的那一次打印或那一次写入。

连接本身不创造新的作用域。右边执行过的赋值，左边之后的所有命令都看得见。右边没执行，那些赋值就保持跳过前的样子。读脚本时顺着从左到右的顺序走，问每一边会不会真的开始。开始了，表和文件就会变。没开始，就当这一边不存在。这个问法比记运算符优先级更接近这只壳的实现：它就是一棵从左往右长出来的二叉树，每一边是一条命令或另一段连接。

## 小结

`&&` 在左边非 `0` 时跳过右边，`||` 在左边为 `0` 时跳过右边。被跳过的命令不赋值、不打印、也不做重定向。连接的状态停在真正执行过的那一边。两种连接从左往右结合。清单上用一种连接把方括号和一句 `printf` 接起来。
