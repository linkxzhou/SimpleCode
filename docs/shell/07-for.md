`while` 那一章为了走三步，手写了从 `3` 到 `0` 的改写。清单上的三项其实已经是三个词，不需要先变成整数。`for` 的写法是 `for`、名字、`in`、若干词、`do`、本体、`done`。每一个词展开一次，赋给那个名字，然后执行本体。词的次序就是输出的次序。这里没有 C 语言那种 `for ((...))`，也没有算术扩展可以充当计数器。你把词写出来，循环就有了边界。

```sh run expect="车票" title="三个词各一行"
for item in 钥匙 水杯 车票; do
  printf '%s\n' "$item"
done
```

三行分别是钥匙、水杯、车票。期望用最后的车票来核对，阅读时从第一行看起，确认没有漏项，也没有多出星号或括号。分号可以写在词表和 `do` 之间，换行也可以。关键字 `do` 必须出现。少了它就是语法错误，退出码 `2`，本体不会跑。

名字在每一轮都被重新赋值。这和普通的 `item=钥匙` 写的是同一张表。循环结束后，`item` 仍是最后一个词，也就是车票。没有一轮跑在子壳里，所以不存在「循环变量出了 `done` 就消失」这件事。你在 `done` 后面印 `"$item"`，看到的是车票。若你希望结束之后名字表示别的东西，就再赋一次。

```sh run expect="车票" title="结束后还是最后一项"
for item in 钥匙 水杯 车票; do
  :
done
printf '%s\n' "$item"
```

本体里的 `:` 什么都不印，只为了让循环合法地走过三个词。最后的 `printf` 证明名字还在。这个结果是「不能分身」的又一处：别的壳有时会让 `for` 的每一轮进管道子壳，变量回不来。这里连管道都是同一进程，纯 `for` 更是如此。

词在使用前按那一词自己的引号展开，展开后不再按空格切开。所以词表里的 `钥匙` 是一个词。若某个词是 `"$greet"`，而 `greet` 的值里含有空格，本体里的 `item` 会得到带空格的一整段，不会裂成两个循环。清单的三项没有空格，双引号仍写在本体的 `"$item"` 上，习惯和前面几章一致。

没有词的时候，`for` 会去走位置参数。运行器没有传入位置参数，所以本体一次都不执行，名字也不被设成那些参数。不要写成 `for item in; do` 还指望它发明出钥匙。词必须写在 `in` 后面。也不要省略 `in`，语法要求这个关键字。

通配不会帮你收集词。`for item in *` 里的星号就是星号这一词，不会变成目录中的文件名。目录里有什么，这只壳的 `for` 不负责问。问目录需要外部命令，而外部命令是 `127`。清单的词表是你写下来的那三项，这是边界，也是可读性：读脚本的人不用去想象运行时的目录。

```sh norun title="星号不会变成文件列表"
for item in *; do
  printf '%s\n' "$item"
done
```

`while` 的十万次上限写在 `while` 的实现里。`for` 没有同一把计数器，它的次数等于词的个数。词表若被写成极长的一串，运行仍会很久，所以课程把词表限制在三项。不要复制粘贴出十万个词。也没有一个内建能生成从 `1` 到 `100` 的词表，因为那需要算术。需要「做三次」时，要么像上一章那样改 `step`，要么就写出三个词。

本体里可以放 `if`。例如只在 `item` 是水杯时印出 `open`，其他轮什么都不印。三次循环里只有一轮会说话。这把 `for` 和 `test` 接在一起，仍然全是内建。

```sh run expect="open" title="只在水杯上开口"
for item in 钥匙 水杯 车票; do
  if [ "$item" = 水杯 ]; then
    printf '%s\n' open
  fi
done
```

`&&` 也能放进本体，效果和这个 `if` 相同，短一些。需要 `else` 时用 `if`。不要在本体里再写一个不会结束的 `while`。两层叠在一起时，外层的三个词乘以内层的次数，必须仍然很小。

`for` 的退出码是最后一轮本体的状态。本体以成功的 `printf` 结束时，整个循环是 `0`。某一轮里执行了 `false`，若那一轮是最后一轮，循环的状态就是 `1`。前面几轮的失败不会被记住，除非你把它们抄进变量。和 `$?` 的规则一样：最近状态只有一格。要记住「三项里有没有水杯」，在命中的那一轮把 `found=1` 写上，循环后再看 `found`。初始先写 `found=0`，否则没命中时你分不清「没赋过值」和「赋成了别的」。

词表里可以出现变量。`for item in $a $b $c` 会在每一词上展开。`a`、`b`、`c` 需要在循环前赋值。展开不做字段分割，所以每个变量仍是一轮。这比把三个汉字直接写在 `in` 后面更绕，清单用直接的词。变量词表等到你真的要从前面的步骤接收名字时再用。

后台、子壳、函数都不能用来「并行检查三项」。三项是串行的三轮。串行在这里是优点：每一轮都能看见上一轮留下的变量，例如 `found`。并行需要多个进程，而这只壳没有。


`for` 把边界写在词表上。`in` 后面有几个词，本体就执行几轮。每一轮把那个词展开，赋给名字，然后跑本体。展开的规则和普通参数一样：单引号留下字面，双引号查表，查完不按空格再切开。钥匙、水杯、车票各是一轮，因为它们被空格分开，而不是因为壳知道这是三项清单。你漏写一个，输出就少一行。壳不会按「应该有三样」去补。

这不是算术循环。没有 `for ((step=3; step>0; step--))` 这种形式，也没有地方放 `$((step-1))`。解析器要看见名字、`in`、词，然后是 `do`。少了 `in` 或少了 `do`，是语法错误，退出码 `2`，本体不执行。分号或换行可以把词表和 `do` 分开。关键字不能靠变量拼出来。

名字在每一轮被重新赋值，写的是同一张表。循环结束时它仍是最后一个词。`done` 后面印 `"$item"`，看到车票。别的壳有时让循环的一轮跑进子壳，结束就丢。这里没有子壳。你若希望结束后名字回到进入循环之前的值，就在循环前把它抄到别的名字，结束后再抄回来。壳不帮你做这件事。

词表为空且仍然写了 `in` 时，实现会去走位置参数。运行器没有位置参数，本体一次都不跑。不要指望空词表发明出钥匙。星号也不是文件列表。`for item in *` 的一轮名字就是星号这个字符。目录里有什么文件，`for` 不询问。询问需要外部命令，外部命令是 `127`。词表因此应当是你读得懂的那几个字。三项足够说明次序，也远小于任何关于「十万次」的担心。`for` 的实现并不使用 `while` 那把十万次计数器，它的次数等于词数。词数由你写下来的列表决定，所以列表本身必须短。

本体里可以放安静的 `if` 或一条 `&&`。只在水杯那一轮印出 `open`，另外两轮不说话。三轮仍然都执行了，只是两轮的条件为假。`for` 的退出码是最后一轮本体的状态。最后一轮若是失败的方括号，而且你用 `&&` 把状态留在那里，整个循环会以 `1` 结束，即使中间某一轮已经成功印过字。演示若需要以 `0` 结束，就在 `done` 后面放一条成功的命令。最后一项恰好就是要印的那一项时，最后一轮的 `printf` 已经是 `0`，看起来顺利，换一个值就可能变成 `1`。不要把这种碰巧当成规则。

要记住「三项里有没有水杯」，在命中的一轮写 `found=1`，进入循环前写 `found=0`。循环后看 `found`，不要看 `$?`。`$?` 只剩最后一轮。这和不能分身是同一件事：没有一叠栈帧去保存每一轮的状态。你要的历史，用你自己的变量一格一格记下。

词表里可以使用已经赋好的变量。每个变量仍是一轮，因为不做字段分割。清单直接写汉字，读起来更短。变量词表留给「名字来自前面的 `read`」的时候。后台和函数都不能把三轮变成同时的三份检查。三轮是串行的，串行才能让 `found` 从上一轮活到下一轮。并行需要多个进程，这一章没有。


词的次序就是检查的次序。先写钥匙，终端的第一行就是钥匙。你若想把车票放在第一行，就把它写到 `in` 的第一个位置，而不是在本体里排序。没有排序内建，也没有外部的 `sort`。三项很少，次序用眼睛排就够了。本体里的 `if` 可以选择沉默，但不能把已经过去的词再取出来重排。过去的词若还需要，就在那一轮把它抄进另一个名字。抄完，名字就离开了「只在这一轮可见」的错觉。它本来就不是只在这一轮可见。

`:` 可以充当什么都不印的本体，用来把三个词走完，只在 `done` 之后看最后一个名字。这适合确认「循环确实赋值到了最后」。它不适合充当清单的输出，因为清单需要每一项或命中的那一项出现在终端。命中用 `if` 或 `&&`。全部出现用没有条件的 `printf`。两种本体不要混在同一轮里却忘了自己到底想看见几行。期望是子串，多出来的行仍在，阅读时要数行，而不是只搜索一个汉字。

名字可以选择 `item` 或 `piece`，只要和本体里的引用一致。换名字不会改变词表的含义。词表才是数据。循环变量只是这一轮的窗口。窗口在下一轮被下一个词覆盖，所以上一轮若还要参加后面的判断，就在覆盖前抄走。抄走用普通赋值，退出码是 `0`，不会把这一轮的 `test` 结果留在 `$?` 里。要两者都留，就用两个名字：一个抄词，一个抄状态。


本体执行的次数在脚本里就能数出来。三个词是三次，两个词是两次。不需要运行之后再去问壳「你循环了几遍」，因为没有这样一个内建。输出的行数应当和你允许说话的轮数一致。全部都 `printf` 时，行数等于词数。只有一轮 `printf` 时，行数是一。用这个预期去看终端，多一行或少一行都能指回词表或条件，而不是指回一个看不见的计数器。

## 小结

`for NAME in` 后面的每个词赋值给名字并执行本体。钥匙、水杯、车票是三轮。没有算术型的 `for`。星号不是文件列表。循环结束后名字仍是最后一个词。本体里用 `=` 决定要不要印。词表保持三项，不靠十万次上限来救过长的列表。

下一章把一条输出送进管道。管道是内存，不是两个进程之间的内核缓冲。

## 练习
