短路只决定一次。出门前若要按步数把同一句检查做几遍，就需要循环。`while` 反复执行条件。条件的退出码是 `0` 时，执行 `do` 和 `done` 之间的本体，然后再回到条件。条件不是 `0` 时，循环结束。结束时这条 `while` 的退出码是本体上一次的状态。本体一次都没跑过，则是 `0`。

条件必须会变成假。这只壳没有 `break`，也没有 `continue`。你写出 `break` 时，它是一条外部命令，退出码 `127`，标准错误里是 `external commands are not available`。循环却不会因此停下来，因为 `while` 只看条件的状态，不把本体里的 `127` 当成「请离开」。本体若是 `break`，条件若仍是 `true`，同一个实例会一直调用这条不存在的命令，直到超过十万次。那时壳写下 `shell: too many loop iterations`，并让 `while` 返回 `1`。这个上限是保护，不是让你把十万次当成计划。清单的例子只走三步。

算术扩展也不能把步数减一。`$((step-1))` 不会计算。它若出现在词里，就是一串字符。所以下一步要你自己写出来。`step` 从 `3` 开始，条件是 `[ "$step" -gt 0 ]`。本体里先印出当前的步数，再用 `if` 把 `3` 改成 `2`，把 `2` 改成 `1`，把其他值改成 `0`。下一次条件看见 `0`，`-gt` 失败，循环结束。三次本体，三次输出。

```sh run expect="1" title="三步之后停住"
step=3
while [ "$step" -gt 0 ]; do
  printf '%s\n' "$step"
  if [ "$step" -eq 3 ]; then
    step=2
  elif [ "$step" -eq 2 ]; then
    step=1
  else
    step=0
  fi
done
```

输出是 `3`、`2`、`1` 各一行。期望用最后一行的 `1` 就能对上，读的时候仍要确认上面还有 `3` 和 `2`，并且没有第四次。`step` 用整数比较，是因为这里的值都是十进制数字。不要把钥匙放进 `-gt`。

若一开始就是 `0`，条件第一次就失败，本体不执行。下面印出 `none`，用来证明循环没有说话。

```sh run expect="none" title="一开始就是假"
step=0
while [ "$step" -gt 0 ]; do
  printf '%s\n' loop
done
printf '%s\n' none
```

条件里不要放会成功的 `printf`。那样每一轮都会多一行，而且 `printf` 的状态是 `0`，循环无法结束。方括号是安静的条件。话放在本体里。

本体里的赋值会留下来，因为还是同一个进程。循环结束之后，`step` 是 `0`。你可以在 `done` 后面把它印出来，确认它真的走到了让条件失败的那个值。没有子壳会在每一轮复制一份 `step` 再丢掉。你看见的就是那一个变量在原地被改写。这也是为什么「暂时的循环变量」不会自动消失。`done` 之后若还要用 `step` 表示别的意思，就再赋一次值。

```sh run expect="0" title="结束后步数是零"
step=3
while [ "$step" -gt 0 ]; do
  if [ "$step" -eq 3 ]; then
    step=2
  elif [ "$step" -eq 2 ]; then
    step=1
  else
    step=0
  fi
done
printf '%s\n' "$step"
```

这一块本体不印步数，只改值，最后一行是 `0`。三轮仍然发生了，只是安静的。和上一块对照：印不印由你放进本体的 `printf` 决定，停不停由条件决定。

`for` 更适合「有哪些词」而不是「还有几步」。下一章会用它走过钥匙、水杯、车票。`while` 留在这里，是因为步数这个条件会自己变成假，而且你能看见它怎样变成假。若词表是事先知道的三项，不必先数到 `3` 再逐个映射。映射需要算术或下标，而这只壳没有算术扩展，也没有数组下标。手写三步是为了说明 `while`，不是清单的最终写法。

```sh norun title="没有 break，也没有算术"
while true; do
  break
done
step=$((step-1))
```

上面两行都不要放进可运行块。第一段会空转到上限。第二段不会把 `step` 减一。

`while` 的条件可以是 `read`。读到文件末尾时 `read` 返回 `1`，循环结束。那是后面 `read` 章的用法，标准输入由围栏提供，行数是有限的。现在的三步不依赖输入，点运行就能看到 `3`、`2`、`1`。

本体里再放 `while` 也可以，但内层同样必须会结束，并且两层的次数相乘仍然要很小。课程不嵌套循环。三步已经够说明「条件变假则停止」。

最后一条命令若是 `while`，它的退出码是最后一轮本体的状态。本体以 `step=0` 这种赋值结束时，状态是 `0`。本体以 `false` 结束时，`while` 会返回 `1`，即使条件是正常变假而离开的。离开的原因和 `while` 的最终状态不是同一个数字。调试时在 `done` 后面加 `printf`，让你要看的字出现在终端，也让脚本以 `printf` 的 `0` 结束。

和十万次的距离可以算得很粗。三步是上限的三万分之一不到。即使你把 `if` 的链条加长到十步，仍然远小于上限。危险的只有「条件不改任何会让测试失败的东西」。写每一轮之前先问：哪一个变量在动，哪一次比较会变成假。答不上来，就不要运行这段 `while`。


循环要结束，条件就必须有机会变成非 `0`。这只壳不提供 `break`。你写出来的 `break` 是外部命令，退出码 `127`，错误信息里有 `external commands are not available`。`while` 不把本体的 `127` 当成离开的信号。它只在下一轮看条件。条件若仍是 `true`，本体会再执行，再碰到 `break`，再得到 `127`。同一实例因此空转。实现在一个 `while` 超过十万次时停下，写出 `shell: too many loop iterations`，并返回 `1`。这是保护页面的上限，不是你的循环预算。三步离它很远。把步数写成十，仍然很远。危险的是条件里没有任何会改变比较结果的赋值。

算术扩展不会把 `step` 减一。`$((step-1))` 留在词里就是字符，不会变成 `2`。下一步用 `if` 写死：`3` 改成 `2`，`2` 改成 `1`，其余改成 `0`。条件用 `[ "$step" -gt 0 ]`。整数比较在这里是合适的，因为值都是十进制。不要把钥匙放进 `-gt`。本体先印当前步数再改值，输出就是 `3`、`2`、`1`。先改再印，输出会少掉刚被改掉的那一个数，你要对着脚本看，而不是对着愿望看。

本体一次都没执行时，`while` 的状态是 `0`。`step` 一开始就是 `0`，条件失败，循环不说话。在 `done` 后面印 `none`，才能把「没进循环」和「终端刚好是空的」分开。本体执行过时，`while` 的状态是最后一轮本体的状态。本体以赋值结束，状态是 `0`。本体以 `false` 结束，`while` 返回 `1`，即使离开的原因是条件变假，而不是本体失败。离开的原因写在条件里，最终状态写在本体的最后一条上。要让演示以 `0` 结束，就在 `done` 后面放 `printf`。

变量在循环里原地修改。每一轮看见的 `step` 就是上一轮留下的那个。没有子壳在轮次之间复制一份再丢弃。`done` 之后 `step` 仍是 `0`。你可以把这个 `0` 印出来，作为「条件已经变成假」的证据。它不会自动消失。后面的章节若还要用 `step` 这个名字表示别的数，就重新赋值。名字是你的，壳不划分循环作用域。

`for` 更适合已知的三个词。`while` 留在这一章，是为了让你看见条件怎样变成假。用循环去映射「第几项」会需要下标或算术，两者都没有。手写三步是教学，不是最终的清单。最终的清单在下一章把词直接放在 `in` 后面。`while read` 也是一种会结束的条件：输入读尽时 `read` 返回 `1`。那依赖围栏或文件提供有限的行，放到 `read` 那一章。现在的三步不读输入，点运行就能看见。

嵌套 `while` 时，每一层都要会结束，次数相乘仍然要小。课程不嵌套。本体里用 `if` 改值，已经是这一章需要的全部控制。不要在本体里再放一个恒真循环去「等某件事」。没有第二进程会在旁边把那件事做成，这个进程若去等，就只是在空转，直到上限。

写循环之前用一句话回答两个问题：哪一个变量在变，哪一次比较会失败。答不出就不要运行。三步的答案是：`step` 在变，它不再大于 `0` 时失败。这句话比任何退出码都更能防止十万次。


三步的改写还可以换成更少的分支，只要每一步仍然把条件推向失败。从 `2` 开始时，本体里只要区分「是 `2`」和「其他」。是 `2` 就改成 `1`，否则改成 `0`。输出若先印后改，就是 `2` 然后 `1`。这种缩短不是算术，只是把三条 `elif` 收成两支，因为起点更低。起点若是 `1`，甚至可以不用 `elif`：本体印出 `1`，然后 `step=0`。循环仍会结束。课程用 `3` 做正文，是为了让你看见不止一次改写。练习用 `2`，是为了让你自己收紧分支。两者都不接近十万次。

条件里的方括号每次都重新读 `step`。它不会记住「上次是大于 `0`」。你在本体里把它改成 `0`，下一轮就失败。你若在本体里把它改成一个更大的数，循环会继续，甚至可能永远继续。所以改写的方向必须朝向失败，而不是朝向「再来一轮看看」。没有 `break` 可以在你发现走错时拉停。走错的循环会一直走到上限，那时候终端上已经有大量输出，标准错误里才出现循环太多的说明。把方向写对，比依赖这个说明便宜得多。

本体里的 `printf` 每轮都会占用标准输出。三轮就是三行。你若在条件里也打印，行数会翻倍，而且条件的状态会被 `printf` 的 `0` 固定住，循环无法结束。把话说在本体，把比较放在条件，行数才等于步数。结束后再印一次最终的 `step`，那一行是额外的证据，不计入三步本身。证据和步数分开，期望就可以分别去对最后的 `0` 或中间的 `1`，而不必把所有行写成一个巨大的字符串。


步数变量和清单上的三项不要共用一个名字。`step` 是数字，`item` 是词。混用一个名字会让你在某一轮把钥匙赋进去，下一轮的 `-gt` 又把钥匙读成 `0`，循环提前结束，输出却像是「条件自己坏了」。分开名字之后，数字比较只看见数字，字符串比较只看见词。`while` 这一章可以根本不出现钥匙，三步本身就是主题。钥匙回到 `for` 那一章，作为词而不是作为计数。

上限的报错写在标准错误，不写在标准输出。你若只盯着期望里的数字，可能看不见那句循环太多。正常的三步不会产生这句。一旦看见它，就回到条件，找那个没有被推向失败的变量，而不是把上限调大。这只壳的上限是固定的，课程也不提供修改它的写法。

## 小结

`while` 在条件为 `0` 时执行本体。条件变假则停止。没有 `break`。`$((...))` 不会做减法。用 `if` 把 `3` 改成 `2`、`1`、`0`，整数比较用 `-gt` 和 `-eq`。循环超过十万次会被停下。例子只走三步。本体里的赋值在 `done` 之后仍然还在。

下一章改用 `for` 直接走过三个词，不再把项数当成要减的整数。

## 练习

用 `while` 从 `2` 走到结束，印出 `2` 和 `1`。`step` 用 `-gt 0` 做条件，本体里把 `2` 改成 `1`，再把 `1` 改成 `0`。不要写出第四行。

```sh run expect="2" title="参考答案"
while [ "$step" -gt 0 ]; do
  printf '%s\n' "$step"
  if [ "$step" -eq 2 ]; then

  else

  fi
done
```
