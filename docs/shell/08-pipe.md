前面的命令都把字直接写到标准输出。管道要把前一条的输出变成后一条的输入。在有 `fork` 的壳里，这是两个进程加一块内核缓冲，两边可以同时跑。wasi-sh 没有内核管道。它在内存里准备一块缓冲，先把左边的命令完整跑完，输出写进这块缓冲，再把缓冲交给右边当标准输入。右边结束，这段管道的退出码就是右边的退出码。左边的状态会被记一笔，随即被右边盖过。没有 `pipefail` 这种「左边失败也算失败」的开关。

`echo a | cat | cat` 因此可以工作。`echo` 是内建，两个 `cat` 也是。第一个 `cat` 没有文件参数时，就把标准输入抄到标准输出。抄的时候，标准输入已经是内存里的 `a` 和换行。第二个 `cat` 再抄一次。三次都在同一个进程里先后发生，不是三个进程接力。

```sh run expect="a" title="两次 cat 仍是 a"
echo a | cat | cat
```

`printf` 同样可以放在左边。格式串决定字节，右边的 `cat` 不改这些字节。

```sh run expect="hello" title="printf 接到 cat"
printf '%s\n' hello | cat
```

`hello` 这一行能看见，是因为 `cat` 把缓冲抄到了真正的标准输出。若右边也把输出送进下一段管道，终端仍然要等到最后一段才看到字。中间的缓冲不显示。调试时若觉得「左边没跑」，先看右边是不是把字留下了。左边在右边开始之前已经跑完。

这个顺序解释了一件和 bash 相反、在这里却很自然的事。`printf '%s\n' 钥匙 | read item` 会把钥匙读进 `item`，而且 `item` 在管道之后还在。bash 里 `read` 常常跑在子壳中，循环或管道一结束，变量就丢了。这里没有子壳可以丢。`read` 就是一次对同一张表的赋值，输入来自内存缓冲而不是键盘。清单因此可以用管道收集左边的一行，而不必使用不存在的命令替换。

```sh run expect="钥匙" title="读进同一张表"
printf '%s\n' 钥匙 | read item
printf '%s\n' "$item"
```

第二行 `printf` 不在管道里，它印的是变量。若把第二行也放进管道右边的后面却写错位置，容易让人以为 `read` 没赋值。看结构：竖线的右边只有 `read`，然后换行，再是独立的 `printf`。

`echo` 默认加换行，`read` 按行读，会去掉结尾的换行，所以变量里的值是 `a` 或钥匙，不带换行符。再 `printf '%s\n'` 时，换行由格式重新加上。两边对换行的处理要配成一对，否则你会对「多了一行空行」感到意外。`echo -n` 不加换行。`read` 若一直读到缓冲结束都没有换行，仍会把已有的字符交给变量，只要缓冲里确实有字符。课程的左边都写出 `\n` 或使用会加换行的 `echo`，让一行的边界清楚。

左边失败时，右边仍然会跑。`false | printf '%s\n' still` 会印出 `still`，管道的状态是 `printf` 的 `0`。`false` 没有写出字节，右边的输入是空的，但 `printf` 根本不去读输入，所以它不受影响。不要用管道表达「左边失败就别继续」。那是 `&&` 的工作。管道表达的是字节的交接。`&&` 表达的是状态的交接。清单里若两项都要，就分开写：先用 `&&` 决定要不要产生字节，再把产生字节的命令放进管道。

`cat` 若带上文件名，它读的是文件，不是管道缓冲。管道给它的标准输入会被搁在一边。这一章的 `cat` 都不带参数，专门消耗左边。文件留到下一章，用重定向和 `cat note.txt` 来做。混在一起时，先问每个 `cat` 的字节从哪来。

右边若是外部命令，仍然是 `127`。缓冲不会被交给宿主去启动另一个 wasm。`echo a | ls` 会在 `ls` 上报外部命令不可用。左边的 `echo` 已经把 `a` 写进内存，然后这些字节被丢掉，因为右边没有作为内建去读它们。可运行的管道两边都写内建：`echo`、`printf`、`cat`、`read` 都可以。`test` 不读标准输入，放在右边通常没有意义。

```sh norun title="右边不能是外部程序"
echo a | ls
```

多个竖线从左往右接。`echo a | cat | cat` 先完成 `echo` 到第一块缓冲，再让第一个 `cat` 把这块缓冲抄进第二块，然后第二个 `cat` 抄到标准输出。每一步都是「左边全部结束，右边才开始」。缓冲里是这一段的全部输出，不是一个会阻塞、会填满、会唤醒对端的内核管道。输出若非常大，内存会跟着变大。清单的一行汉字不会碰到这个问题。不要用管道去搬运你没有把握的巨大文本。这只壳也没有一个外部的 `head` 可以帮你截断。

`read` 只取一个变量名。`printf '%s\n' 'Ada Lee' | read name` 会把整行放进 `name`，包括空格，不会把 `Lee` 分给第二个变量。你多写一个名字，它也不会得到后半段。字段分裂不是这只壳的展开规则，`read` 也不另做分裂。一行就是一个值。

管道和 `for` 可以相邻，但不要写成 `for item in 钥匙 水杯; do printf ...; done | read` 还以为 `read` 能按轮次回到循环里面。右边在整个左边结束之后只跑一次。循环里的多行会连成一块缓冲，`read` 只拿走第一行。要按行处理，把 `while read` 放在右边，标准输入由这块缓冲供给，行数有限，循环会在读尽时因为 `read` 返回 `1` 而停止。那是合法的，也仍然远小于十万次。这一章用单行，把机制先看清楚。

标准错误不进管道。`test` 的报错或外部命令的那句 `external commands are not available` 仍然出现在终端的错误流上，不会变成右边的输入。所以你不能靠 `cat` 去收集那句错误。可运行例子避免制造错误流。


管道在这只壳里是一块会增长的内存，不是内核对象。左边的命令先跑完，它的标准输出写进这块内存。右边开始时，标准输入指向这块内存的开头。右边再作为左边接到下一段时，同样是先写完再读。`echo a | cat | cat` 因此得到 `a`：`echo` 写出 `a` 和换行，第一个 `cat` 因为没有文件参数而抄写标准输入，第二个 `cat` 再抄一次。三次调用都在同一个进程里排队，没有三个进程同时活着，也没有「缓冲写满就堵住左边」这种调度。清单的一行很小，内存足够。不要用它搬运没有把握的大段文本，这里也没有外部的 `head` 可以截断。

这个顺序带来一个对变量有利的结果。`printf '%s\n' 钥匙 | read item` 在右边执行 `read`，`read` 对同一张表赋值。竖线结束后，`item` 仍是钥匙。bash 里常见的陷阱是 `read` 跑在子壳，管道一结束赋值就丢。这里丢不掉，因为根本没有子壳。命令替换仍不存在，管道加 `read` 就是把一行输出收进变量的办法。收的时候换行被去掉，再印出来时由 `printf` 的格式重新加上。左边请自己写出换行，或使用会加换行的 `echo`，让一行的边界清楚。`echo -n` 不加换行，`read` 会一直读到缓冲结束，值里没有那一刀，随后的格式若再加换行，看起来仍是一行，但你少了一次「输入里本来就有换行」的保证。

管道的退出码取右边。左边的失败不会取消右边，也没有 `pipefail` 可以把左边的非零保留成整段的状态。`false | printf '%s\n' still` 会印出 `still`，状态是 `0`。`false` 没有字节，右边若不读输入，就完全不受影响。想在失败时停住，用 `&&`。竖线只交接字节。标准错误不进缓冲。外部命令那句 `external commands are not available` 出现在错误流上，不会变成 `cat` 的输入。右边若本身是外部命令，例如 `ls`，得到的是 `127`，左边已经写进内存的字节被丢掉，因为没有内建去读它们。可运行的两边都写 `echo`、`printf`、`cat` 或 `read`。

`cat` 带了文件名就去读文件，管道给它的标准输入会被搁下。这一章的 `cat` 不带参数，专门消耗左边。文件放到下一章，用重定向和 `cat note.txt`。混用之前先问字节从哪来。`test` 不读标准输入，放在管道右边通常没有意义，它的状态也不表示「输入里有没有某行」。有没有某行，要 `read` 进变量再用 `=`。

`for` 若整个接在管道左边，右边要等循环全部印完才开始，并且只跑一次。多行堆在同一块缓冲里，单独一个 `read` 只取第一行。要逐行处理，右边用 `while read`，行数有限，读尽时 `read` 返回 `1`，循环停止。那仍然远小于十万次。这一章用单行，是为了把「左边先结束」看清楚，而不把行数的问题混进来。

调试时若终端是空的，先看最后一段的输出有没有被再接走。中间缓冲不显示。也可以暂时拿掉竖线，让左边直接写到终端，确认字确实产生过，再把竖线加回去。这个办法不需要第二个进程，只是把目的地从内存改回标准输出。


左边可以是 `echo -n`，右边仍然是 `cat`。`-n` 省掉换行，`cat` 就照单全收，终端上的字可能粘在下一次输出旁边。清单不使用这种粘连。左边用默认的 `echo` 或带 `\n` 的 `printf`，让缓冲里的行是完整的。`read` 因此能按行切开。你若故意不要换行，就要在后面的格式里自己处理边界，并且让期望包含粘在一起的样子。教学块选择完整的行，是为了让 `a` 或钥匙单独成为一行，子串匹配不会误伤到别的字。

多段竖线的中间结果看不见，这和重定向把 `printf` 送进文件有点像：字离开了终端，但还在这次运行里。差别是管道的内存在这条管道结束时就不再作为输入保留，变量里的拷贝才留下。文件里的拷贝要等下一章的 `>`。所以管道适合「交接一次」，不适合「留下给再后面的第三条无关命令」。再后面的命令若还要这行字，就在 `read` 时放进变量，或者一开始就写文件。

`cat` 抄写时按块搬运，不按行解释。行的边界是数据里的换行字节，不是 `cat` 加上的。左边没写换行，右边就看不到换行。左边写了两次换行，右边就会看到一个空行。空行对 `read` 来说是一次成功的空值。你若不想要这行空值，就不要在左边多写 `\n`。格式串里一个 `\n` 对应一行，和围栏里的写法是同一纪律。

## 小结

内建之间的管道用内存缓冲。左边跑完，右边才读。`echo a | cat | cat` 得到 `a`。管道的状态取右边。`printf ... | read item` 会把字留在变量里，因为没有子壳。外部命令不能接在右边。失败时要不要继续，用 `&&` 而不是竖线。
