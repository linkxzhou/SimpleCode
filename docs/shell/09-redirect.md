管道把字节留在内存里，进程一结束，那块缓冲就没了。出门清单若要在同一次运行的后半段再读一次，可以放在变量里，也可以放进文件。这一章用文件。重定向是简单命令上的记号：`<` 把文件接到标准输入，`>` 把标准输出写进文件并先截断，`>>` 在文件末尾追加。它们由这只壳在运行该命令之前打开，仍然是同一个进程里的文件操作，不需要 `fork` 来继承文件描述符。

工作目录不能换。`cd` 不是内建，调用它会得到 `127` 和那句外部命令不可用的说明。没有 `chdir`，相对路径就落在宿主预先打开的目录里。所以文件名叫 `note.txt`，不写一层你打算先 `cd` 进去的子目录。绝对路径是否可见，取决于宿主预开了哪些目录，课程不依赖这一点。每一块在读文件之前都先写它，这样这一块自己是完整的。

先写再读。格式串用单引号，`hello` 和换行由 `printf` 写进 `note.txt`。`>` 会截断已有内容。随后 `cat note.txt` 把文件抄到标准输出。

```sh run expect="hello" title="写入再读回"
printf 'hello\n' > note.txt
cat note.txt
```

终端上的 `hello` 来自第二次命令，不是来自第一次。第一次的标准输出已经被文件接走，终端上看不见那一次的字。这是重定向的含义：输出换了目的地。若你既想在终端看见、又想留文件，就再 `cat` 一次，或者再 `printf` 一次到终端。不要指望 `>` 会抄一份到两边。这只壳没有一个 `tee` 可以分叉输出，分叉这个词在这里尤其不合适，因为没有第二个进程去接另一份拷贝。

追加用 `>>`。下面先截断写成 `hello`，再追加 `more`，然后整文件读出。两行都在。

```sh run expect="more" title="第二行追加在后面"
printf 'hello\n' > note.txt
printf 'more\n' >> note.txt
cat note.txt
```

`more` 出现，说明第二次没有把第一次截掉。若把第二行也写成 `>`，文件里就只剩 `more`。选择 `>` 还是 `>>`，就是选择「这一次是否还要旧内容」。清单若每次运行都重写笔记，用 `>`。若在同一次运行里往笔记上加项，用 `>>`。不同次点击之间文件会不会还在，由宿主的文件系统决定，课文不把下一块的正确性押在上一块留下的文件上。

`<` 让命令从文件读。`cat` 不带参数时本来就读标准输入，所以 `cat < note.txt` 和 `cat note.txt` 在这一章的效果相同：都是把文件里的字节送到终端。差别在于前者走重定向，后者走 `cat` 自己的文件参数。两种都是内建能力。下面用重定向读，好让 `<` 出现一次。

```sh run expect="hello" title="从文件接到标准输入"
printf 'hello\n' > note.txt
cat < note.txt
```

`read` 也可以从这种标准输入取一行。`read item < note.txt` 会把文件的第一行放进 `item`，换行被去掉。然后再 `printf` 到终端。这和管道加 `read` 一样，变量留在同一张表里。文件和管道是两种输入来源，赋值的规则没有变。

路径可以放在变量里。`name=note.txt` 之后，`printf 'hello\n' > "$name"` 会打开 `note.txt`，因为重定向的目标也会展开。展开发生在打开之前。目标若是空的，打开会失败，命令的状态是 `1`，标准错误里有路径和系统的说明。课程把名字写全，避免空变量造出一个失败的打开。

失败的打开不会假装写出了字。磁盘满、目录不存在、权限不够，都是打开失败。相对名字 `note.txt` 在预开的工作目录里应当能创建。若你写成一个不存在的子目录下面的文件，打开失败，后面的 `cat` 也会失败。不要用 `mkdir` 去补目录，`mkdir` 是外部命令，退出码 `127`。笔记就放在当前目录的这一个文件里。

here-doc 不是可用的重定向。`<<` 会被当成缺少目标或意外的结构，不能用来把脚本里的一段文字接到标准输入。要写进文件的字，放在 `printf` 的参数里。参数可以是汉字。`printf '%s\n' 钥匙 > note.txt` 然后 `cat note.txt`，读回的就是钥匙。字节是 UTF-8，`cat` 不解释编码，它只搬运。终端按 UTF-8 显示，你就看到钥匙。

```sh norun title="没有 here-doc，也不能 cd"
cat <<EOF
钥匙
EOF
cd /tmp
```

短路章说过，被跳过的命令不做重定向。`false && printf 'no\n' > note.txt` 不会因为右边写了 `>` 就去截断文件。文件那一章的例子都让左边真正执行。你若把判断和写入连在一起，记住跳过是连打开一起跳过的。

同一条命令上可以既有输入重定向又有输出重定向。`cat < note.txt > copy.txt` 会先按壳处理重定向的顺序打开，然后 `cat` 从输入抄到输出。为了让每一块容易读，例子把「写入」和「读出」分成前后两条命令。两条命令共享文件系统，因为还是一个进程，前一条关上文件之后，后一条能看见已经写好的字节。不需要在两条之间插入同步，写是同步完成的。

`printf` 写文件时，退出码在打开成功且格式能处理时是 `0`。你看不到终端输出，不要误以为失败。用下一条 `cat` 来核对内容。`cat` 若找不到文件，状态是 `1`，标准错误里会带上文件名。期望文字只描述成功时的那一行 `hello` 或钥匙。

覆盖是静默的。`>` 不会问你是否丢掉旧内容。教学文件只有 `note.txt` 这一个名字，丢掉的是上一轮例子留下的笔记，不是你的别的文档。即便如此，也不要在例子里对一个你不确定用途的名字使用 `>`。名字写死成 `note.txt`，就是为了让覆盖的范围看得见。


文件让一行字活过管道的那块内存。同一次运行里，前一条命令写入，后一条命令能读到，因为打开、写入、关闭都发生在这个进程里，写完才返回。不需要 `fork` 来继承文件描述符，也不需要另一个程序来同步。`printf 'hello\n' > note.txt` 把标准输出接到文件。`>` 用截断的方式打开，旧内容消失。`cat note.txt` 再把字节抄到终端。终端上的 `hello` 来自 `cat`，不是来自那次 `printf`。`printf` 的目的地已经换成文件，它不会同时再抄一份到终端。没有 `tee`，因为分叉一份输出会让人以为存在第二个接收者。要两边都有，就再执行一次会写到终端的命令。

`>>` 在末尾追加。先用 `>` 写 `hello`，再用 `>>` 写 `more`，`cat` 会看到两行。第二行若误用 `>`，文件里只剩 `more`。选择哪一个符号，就是选择旧内容还要不要。教学文件固定叫 `note.txt`，覆盖的范围看得见。不要对一个你说不清用途的名字使用 `>`。不同次点击之间文件会不会留下来，取决于宿主的文件系统，下一块的正确性不要押在上一块留下的字节上。每一块自己先写再读。

`<` 把文件接到标准输入。`cat < note.txt` 和 `cat note.txt` 在这里都把同一份字节送到终端。前者是重定向，后者是 `cat` 的文件参数。两种都是内建。`read item < note.txt` 则把第一行放进变量，换行去掉，变量留在表里。这和管道加 `read` 是同一类赋值，只是字节来自文件而不是来自左边命令的缓冲。

相对名 `note.txt` 落在宿主预先打开的工作目录。`cd` 不是内建，没有 `chdir`，你不能先换目录再写。写成不存在的子目录，打开失败，状态是 `1`，标准错误里有路径。不要用 `mkdir` 去补，它是外部命令，`127`。路径可以放在变量里再展开，`name=note.txt` 然后 `> "$name"` 会打开同一个文件。目标若是空变量，打开失败。把名字写全。

here-doc 不能用来把脚本中的一段接到标准输入。那种写法在这里是错误的重定向，而不是一份临时文件。要写入的字放在 `printf` 的参数里，汉字也可以。`cat` 按字节搬运，不解释 UTF-8。终端负责显示。格式串保持 `'%s\n'`，汉字放在参数里，避免数据里的百分号被当成格式。

被 `&&` 跳过的命令不会执行它的重定向。`false && printf 'no\n' > note.txt` 不会截断文件。这一章的例子都让写入真正发生，然后再读。判断和写入若写在一起，记住跳过包括打开。读取失败时，`cat` 的状态是 `1`，终端上没有你期望的那一行。期望只描述成功路径上的 `hello` 或追加的 `more`。

同一条命令可以同时有输入和输出重定向。为了读得清楚，例子把写和读分成前后两条。两条之间不需要额外的刷新仪式。`printf` 返回时，字节已经在文件里。随后的 `cat` 打开的是这份已经写完的内容。若你在 `printf` 之后立刻用另一个名字去 `cat`，那是在读另一个文件，空或失败都不能证明刚才的写入丢了。核对时使用同一个 `note.txt`。


写入汉字和写入 `hello` 用的是同一条路径。`printf '%s\n' 钥匙 > note.txt` 把 UTF-8 字节放进文件，`cat` 原样送回终端。你不需要为汉字换一种重定向。需要换的只有比较方式：读回变量之后用 `=`，不要用 `-eq`。文件不保存「这是汉字」的类型，它保存字节。类型是你在 `test` 里选择的运算符。

追加适合在同一次运行里逐项记账。第一项用 `>`，避免上次运行留下的旧笔记混进来。后面的项用 `>>`。读出时行的次序就是追加的次序。若每一项都用 `>`，文件里永远只有最后一项，前面的记账被你自己擦掉。擦掉是 `>` 的定义，不是故障。选择符号之前先决定这份笔记要保留几行。本章的例子一行或两行，都在脚本里写明，不依赖目录里已经存在的内容。

打开失败和写入成功在终端上都可以是「没有字」。前者状态非零，标准错误有说明。后者状态是 `0`，字在文件里。所以写入之后总是再 `cat` 一次，让成功变成可见的一行。只看空终端，无法区分这两种安静。清单要的是可见的核对，不是安静的假设。

相对路径还有一个实践上的边界。脚本里写 `note.txt`，打开的就是工作目录下的这个名字。写成 `./note.txt` 通常也指向同一处，课程统一不用点斜杠，避免把路径写成需要先切换目录才能懂的形式。切换目录的 `cd` 不可用，点斜杠并不能代替它。名字短，核对就短：写入、读出，都对着同一个 `note.txt`。

## 小结

`printf 'hello\n' > note.txt` 把一行写入当前目录的文件，`cat note.txt` 把它读回终端。`>` 截断，`>>` 追加，`<` 把文件接到标准输入。`cd` 不存在，所以用相对名 `note.txt`。here-doc 不可用。写入和读出分成前后两条内建命令，它们看见的是同一份文件。

下一章的标准输入不来自文件，而来自围栏上写好的 `stdin`。`read` 把那一行放进变量。
