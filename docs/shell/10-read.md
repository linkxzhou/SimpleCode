文件章从 `note.txt` 把字读回来。有时候字不该写进源码，也不该先落成文件，而是这次运行的标准输入。在书的围栏里，标准输入写在信息行上，例如 `stdin="Ada\n"`。`\n` 是换行。运行器把这几个字符送到壳的标准输入，然后给出结束。`read` 从这里取一行，去掉结尾的换行，放进你给出的那个变量。成功时退出码是 `0`。

`read` 只使用第一个名字。整行都放进它，包括行内的空格。再写第二个名字，也不会分到后半段。这和展开阶段不做字段分割是同一取向：一行就是一个值。名字要写成合法的变量名。读成功之后，用 `printf` 把变量印出来，终端上才看得到。`read` 自己不回显。

```sh run stdin="Ada\n" expect="Ada" title="读到 Ada"
read name
printf '%s\n' "$name"
```

围栏上的 `Ada` 不是命令行参数。`$#` 仍然是 `0`，`$1` 仍然是空。输入和参数是两条通道。清单若从参数取名字，在这种运行方式下会取到空。从标准输入取，才能在围栏里写上 `Ada`。

第二块把清单的一项放进输入。值是钥匙。脚本里不再写 `item=钥匙`，赋值由 `read` 完成。后面的方括号仍用字符串 `=`。

```sh run stdin="钥匙\n" expect="已带" title="输入决定是否已带"
read item
if [ "$item" = 钥匙 ]; then
  printf '%s\n' 已带
else
  printf '%s\n' 未带
fi
```

输入若改成水杯，同一段脚本会印出未带。课文这一块的围栏固定为钥匙，期望才稳定。你自己改围栏时，要连期望一起改。脚本不会去猜围栏作者的意图。

两行输入可以读两次。`stdin="Ada\n钥匙\n"` 提供两行。第一次 `read` 得到 `Ada`，第二次得到钥匙。然后把它们印成两行。次序和输入的次序一致。

```sh run stdin="Ada\n钥匙\n" expect="钥匙" title="名字和一项"
read name
read item
printf '%s\n' "$name"
printf '%s\n' "$item"
```

空行是成功的读取，值是空串，状态是 `0`。真正的结束才是 `1`：缓冲里再也没有字符。`while read item; do ... done` 会在每一行上执行本体，读尽之后条件变成 `1`，循环停止。行数由围栏决定，所以循环次数是小的，不会去碰十万次的上限。本体里不要再读掉下一行，否则你会跳着走。下面的围栏有两行，本体各印一次，前面加上固定的字，方便和输入对照。

```sh run stdin="钥匙\n水杯\n" expect="水杯" title="读到结束才停"
while read item; do
  printf '%s\n' "行:$item"
done
```

输出是 `行:钥匙` 和 `行:水杯`。没有第三行。`while` 的结束原因是 `read` 返回了 `1`，不是 `break`。`break` 仍然不存在。

管道也可以给 `read` 提供这一行，上一章已经这样做过。围栏和管道的差别只在来源：围栏是这次运行一开始就接好的标准输入，管道是左边命令临时做出来的缓冲。两者都把字送进同一个 `read`。若脚本里先从围栏 `read` 了一次，标准输入的位置会前进，下一次 `read` 看到的是后面的行。计划好每一行被谁读走。

没有输入时，第一次 `read` 就遇到结束，状态是 `1`，变量不会被设成一个新值。若这个名字以前不存在，它仍是空。可运行的块都带上 `stdin`，避免依赖「空输入时的沉默」。沉默容易被看成忘了写 `printf`。

`read` 不解释引号。输入里的 `$item` 就是四个字符加一个美元符号的那种字面，不会在读入时展开。展开只发生在脚本的词上，不发生在输入的数据上。这是一条安全的界线：围栏里的字是数据，脚本里的双引号才是要展开的地方。你印出 `"$name"` 时，印的是数据本身。数据里若含有百分号，放在 `printf` 的参数里，用 `%s`，不要把数据拼进格式串。格式串保持你写的 `'%s\n'`。

命令替换不能代替 `read`。你不能写 `name=$(cat)` 去把标准输入收进变量。`read` 就是这只壳提供的收法。文件则用 `<` 接给 `read`，或者用管道把 `cat note.txt` 接到 `read`。三条路最后都是一次赋值。

```sh norun title="不能用命令替换收走输入"
name=$(cat)
```

`exit` 放在 `read` 之后会丢掉后面的 `printf`。例子先读再印。若读到的值需要影响退出码，用 `test`，不要用 `exit` 把进程提前关掉。最后的 `printf` 让你看见值，也让成功的演示以 `0` 结束。

围栏字符串里的换行要写出来。只有 `stdin="Ada"` 而没有换行时，`read` 仍可能拿到 `Ada`，因为结束之前的剩余字符会构成最后一行。课程统一写成 `Ada\n`，让「一行」在围栏上就看得见。多行用多个 `\n` 分开。引号按围栏信息行的规则书写，脚本内部再按壳的引号规则书写。两套引号不要混成一层。


围栏上的 `stdin` 是这次运行一开始就接好的标准输入，和 `$1` 不是同一条通道。`stdin="Ada\n"` 把 `Ada` 和换行送进来，然后结束。`$#` 仍是 `0`。你若从 `$1` 取名字，得到的是空。`read name` 才取得到 `Ada`。`read` 去掉结尾的换行，放进第一个变量，成功时状态是 `0`。它不回显，所以后面要有 `printf`。整行进入这一个名字，行内的空格也留在值里。多写的名字不会分到后半段，壳不做字段分割，`read` 也不另做一次。

空行和结束不同。只有换行时，`read` 成功，值是空串，状态是 `0`。缓冲里再也没有字符时，状态才是 `1`，这次不会把变量改写成一个新值。`while read item` 把这个 `1` 当作条件失败，循环停止。行数等于围栏里的行数，因此远小于十万次。不要在本体里再 `read` 一次，否则你会跳着消耗下一行，输出的行数对不上围栏。`break` 仍然不存在，结束只来自 `read` 的状态。

两行的写法是 `stdin="Ada\n钥匙\n"`。第一次 `read` 得到 `Ada`，第二次得到钥匙。次序就是输入的次序。管道也可以制造同样的一行，那是左边命令的内存缓冲，不是围栏。两者最后都进入同一个 `read`。若你先从围栏读过，标准输入的位置已经前进，下一次再读围栏看到的是后面的行。计划每一行的去向。文件则用 `<` 把 `note.txt` 接给 `read`，或者 `cat note.txt | read`。三条路都是赋值，差别只在字节从哪来。

输入是数据，不是脚本。数据里的 `$item` 不会在 `read` 时展开。展开只发生在脚本的词上。印出 `"$name"` 时，印的是读到的字节。这些字节若含有百分号，仍然用 `%s` 当参数，不要拼进格式串。格式串保持你写死的那一份。单引号和双引号的规则不作用于已经读进来的值，它们只作用于还在脚本里的词。

命令替换不能代替 `read`。`name=$(cat)` 不会把标准输入收进 `name`。这种写法放在不能运行的块里。`exit` 不要跟在 `read` 后面把进程提前关掉，否则核对用的 `printf` 不会执行。先读，再判断，再印。判断用上一章的 `if` 和 `=`。围栏固定成钥匙时，期望写已带。你改围栏里的字，就要一起改期望。脚本按读到的值走分支，不按题目的愿望走。

围栏信息行里的 `\n` 是换行的写法，和脚本里 `printf` 的 `\n` 是两层。信息行由文档的解析处理，脚本由壳处理。写成 `stdin="Ada\n"` 时，壳看到的输入已经是 `Ada` 加上换行，不是反斜杠和字母 `n`。若你真的想输入反斜杠，那是另一串字符，课程的例子不这么做。统一带上换行，是为了让「一行」在围栏上就看得见。没有换行时，结束前的剩余字符仍可能构成最后一行，`read` 往往还是拿到字，但边界不如写出来清楚。

`read` 失败时不要用空终端代表失败。接一条利用 `$?` 的打印，或者让 `while` 的「不再打印」和你已知的行数对照。已知两行却印出一行，优先检查本体里是不是多读了一次，而不是怀疑汉字不能进入变量。钥匙已经在前面的章节里进过变量，这一章只是换了入口。


`read` 和 `test` 接在一起时，空输入要单独考虑。围栏若给出空行，`read` 成功，变量是空，`-z` 成立，`if` 可以走「没有这项」的分支。围栏若什么都不给，`read` 失败，变量可能仍是空，但状态是 `1`。只看变量，分不清这两种空。要分清，就在 `read` 之后立刻看 `$?`，把状态抄进 `st`，再去判断值。抄写的纪律没有因为输入来自围栏而改变。围栏只更换了字节的来源。

多行循环的输出最好带上你自己的前缀，例如 `行:`。前缀让空行也能被看见：值为空时，终端上仍有 `行:`。没有前缀时，空行和「没印」在屏幕上都很安静。本章的两行例子没有空行，前缀仍然有用，它表明这些字来自本体里的 `printf`，不是壳自动回显的输入。`read` 不回显。你看见的每一行，都是脚本后来写出去的。

一次运行里的标准输入只能向前读。没有内建把读过的行退回去。围栏里的两行被读完，就结束了。想再看第一行，就要在第一次 `read` 时把它放进变量，后面用变量，而不是再 `read` 一次。文件则不同，你可以再次 `cat note.txt`，因为文件能重新打开。标准输入是一条流，文件是一份可以再开的字节。两者都喂给 `read` 时，这个差别仍然在。


围栏可以只提供一项，脚本用一次 `read` 就把它交给 `if`。这比在源码里写死钥匙更接近「出门时才知道要带什么」。代价是期望必须和围栏一起写定。书里的围栏是固定的，所以期望也是固定的。你在编辑器里改了输入，就要接受分支可能走到另一句。另一句不是壳算错，是条件按新的值成立了。

`read` 读到的值马上就可以参与管道或重定向之后的比较。先读进 `item`，再按文件那一章写进 `note.txt`，是最后一章练习的起点。这一章先把「围栏到变量」走通，确认 `Ada` 或钥匙确实进了名字，再把文件接上去。一次只加一个来源，失败时才知道是输入没到，还是文件没写。

读完若还要循环，就把 `while read` 的本体限制在打印或一次比较上。比较用 `=`。不要在本体里启动外部程序去处理这一行。处理不了时你得到的是 `127`，循环却会继续读下一行，直到输入结束或空转到上限。输入只有两行时，两次 `127` 已经足够说明问题。把处理留在 `printf` 和 `test` 里，每一行的结果都写在终端上，次数和围栏一致。

## 小结

`read` 把标准输入的一行放进一个变量，去掉换行，成功时状态是 `0`，读尽时是 `1`。围栏的 `stdin` 提供这些行。`$#` 不因此增加。整行进入第一个名字。`while read` 会在读尽时停止。输入是数据，不会按脚本的 `$` 再展开一次。
