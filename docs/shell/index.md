清晨出门之前有一张很短的清单：钥匙、水杯、车票。后面每一章都还用这三样东西，因为换一套例子会把注意力从壳的机制上挪开。这一章先不判断、不循环、不写文件，只把清单印出来，并弄清印它们的那个程序为什么不能分身。

平常说的壳，工作方式是分叉。你敲下一个名字，壳先复制出一份自己，再让那份复制品换成磁盘上的另一个程序。复制用的系统调用叫 `fork`，换成新程序叫 `exec`。管道是操作系统在两个进程之间放的缓冲，左边的进程往里写，右边的进程从里面读，两边可以同时活着。子进程里改掉的变量不会回到父进程。两次运行看到的进程号也不一样。教程里那些关于子壳、后台作业、外部命令的说法，都站在「可以再造一个进程」这件事情上。

这门课的运行时没有这件事情。浏览器里的命令模块走 WASI preview1：导出 `_start`，导入只有 `wasi_snapshot_preview1`。这套接口里没有创建进程的调用，也没有宿主级的管道。公开的 bash 或 BusyBox 的 wasm 往往还要额外的进程接口才能 `fork`、`exec`、`wait`。那些导入在这里对不上，所以不能把它们塞进同一个宿主就算作 Shell。课程用的是一只很小的壳，名字叫 wasi-sh，和课程放在同一个仓库里，许可证是 MIT。它被编译成一个 wasm 实例。内建命令是这个实例里的函数，管道是一块内存。源码可以用来核对行为，课文不把 C 贴进来。

由此得到的限制很具体。变量表只有一张，最近一次退出码只有一个，标准输入和标准输出也各有一份。你做的任何事都发生在这一份记忆里，因为根本没有「孩子」可以隔离。`$$` 因此永远是字符 `1`。壳没有去问操作系统要一个会变化的进程号，它在展开 `$$` 时直接写下这个数字。进程只有一个，数字就固定成一个。运行器启动它的方式是壳的程序名再加上脚本文件，没有额外的位置参数，所以 `$#` 是 `0`，`$1` 到 `$9` 都展开成空。`$0` 是脚本自己的路径，拼写由运行器决定。例子可以印出 `$#`，也可以印出 `$0`，但期望文字只去核对稳定的 `$#` 和 `$$`。

名字对不上内建时，壳不会去磁盘上找一个可执行文件。它往标准错误写一行，形如 `shell: ls: external commands are not available (no fork)`，并且让这条命令的退出码变成 `127`。`127` 在别的壳里常常表示「找不到命令」。这里的意思更硬：那条命令也许在别的机器上存在，这个进程却没有办法把它启动起来。清单不能靠 `ls` 去看桌面，它只能记住自己的变量。语法错误是另一条路，退出码是 `2`，进程同样不会假装已经执行了后半段。

能写进可运行例子的名字就这些。`echo` 可以带 `-n`。`printf` 认识 `%s`、`%d`、`%%`，以及 `\n` 和 `\t`。还有 `read`、`cat`、`true`、`false`、`:`、`exit`、`test` 和方括号 `[`。赋值、`$VAR` 与 `${VAR}`、`$?`、`$#`、`$$`、`$0` 到 `$9`、单引号和双引号、`if`、`while`、`for`、分号和换行、`&&` 和 `||`、内建之间的管道、`<`、`>`、`>>`，都在后面的章节里逐个用到。`cd`、命令替换、算术扩展、函数、`source`、通配、here-doc、后台 `&`、子壳、外部程序，只出现在标明不能运行的块里，用来说明它们在这只壳上得不到你从 bash 带来的那种效果。

`printf` 是清单离开进程的方式。格式串是一份很小的说明：`%s` 把下一个参数当文字写出去，`%d` 把下一个参数按整数的十进制写出去，`%%` 写一个百分号并且不消耗参数。`\n` 是换行，因为运行时不会替你补上。`echo` 把参数用空格接起来，默认再加一个换行；第一个参数若是 `-n`，就省掉那个换行。`echo` 不把 `\n` 这两个字符解释成换行。清单要的是干净的一行，所以这一章用 `printf`。

下面三次运行都是新的进程。上一块里的变量不会活到下一块。这和「壳不能 `fork`」是两层事：外层宿主可以重新启动这个 wasm，这个 wasm 内部不能再启动一个自己。所以每一块都把要用的字写全。第一次只印钥匙，确认格式和参数是一对。

```sh run expect="钥匙" title="清单的第一项"
printf '%s\n' 钥匙
```

第二次把三样东西各放一行。三次调用，三行输出。少一次调用，那一项就根本不会出现，壳不会根据「清单应该有三项」去补。

```sh run expect="车票" title="三样东西"
printf '%s\n' 钥匙
printf '%s\n' 水杯
printf '%s\n' 车票
```

第三次看这只壳对自己的描述。`$#` 是参数个数，这里是 `0`。`$$` 是它写死的 `1`。`$1` 展开之后是空的，所以括号里什么都没有。

```sh run expect="args:0" title="没有额外参数"
printf '%s\n' "args:$#"
printf '%s\n' "self:$$"
printf '%s\n' "first:[$1]"
```

`args:0` 和 `self:1` 会一起出现。`first:[]` 里的空括号是空的 `$1`，用来提醒你：不要写一个必须靠额外参数才能成立的例子。运行器没有传入那些参数。

```sh norun title="外部命令和后台都不会变成第二个进程"
ls
echo side &
```

只读的这一块故意不能运行。`ls` 会走到那条 `127` 的路上，标准错误里能看到 `external commands are not available`，并且带上 `no fork`。单独一个 `&` 则在语法上就被拒绝，提示是意外的记号。后台的意思是「这一条先去跑，壳继续往下读」。继续往下读的同时让另一条还活着，需要第二个进程。这只壳连这个记号都不接受，免得你以为作业已经挂到后台。

`cd` 同样不是内建。没有 `chdir`，工作目录就停在宿主预先打开的那一处。后面写文件时用相对名字 `note.txt`，是因为相对名字落在这一处，而不是因为你可以先切到别的目录。`exit` 会结束整个壳，因为可结束的进程只有这一个。可运行的例子让最后一条命令的退出码代表这次运行，不在中间调用 `exit`，否则清单的后半段会被直接丢掉。

`while` 若一直为真，同一个实例会空转。实现在循环超过十万次时停下，并写 `shell: too many loop iterations`。`for` 靠词的个数结束，这一课的词表只有三项。两种循环都保持得很短，空转的例子不会出现。

把「不能分身」说成一句口号是容易的，把它落到一次出门检查上才看得出来取舍。传统的壳把「列目录」「读文件」「算一个数」都推给外部程序，自己只负责切分命令行和等待。那样做的好处是壳可以很小，工具可以各自进化。代价是每一次检查都要付一次创建进程的费用，而且子进程的记忆默认不回来。wasi-sh 把这个取舍翻过来：工具集被写死在壳里面，换来的是这些工具之间可以共享变量、共享最近一次退出码，也可以用一块内存假装管道。清单因此不需要 `ls` 来证明钥匙还在，它需要你把「钥匙」这个词放进变量，再用 `printf` 把它送出来。少了的是整个用户态工具箱，多出来的是一条可以逐步变长、却始终在同一个进程里的检查。

这种翻转也解释了后面几章为什么都围着退出码打转。外部程序不存在时，你没有别的通道可以问「这一步成了没有」。内建命令把答案放在退出码里：`0` 表示这一步按它自己的约定成功，其他数字表示没有。壳在两条命令之间记住最近的那个数字，展开 `$?` 时把它写成十进制。下一章先处理引号，再下一章就把这个数字抄进变量。若现在就去调用一个不存在的工具，你得到的是 `127` 和一行错误，清单本身不会前进。

还有一层和宿主有关。外层可以把 wasm 重新启动一次，所以你点一次运行，变量表是新的，`$$` 却仍然是 `1`，因为新实例里的壳还是按同一条规则写下这个数字。它不变，正是因为它不表示「操作系统分配到的身份」，只表示「这里没有第二个进程」。把 `$$` 印出来是为了看清这条规则，不是为了拿它去区分两次点击。

同一份设计也限制了循环。条件若永远为真，唯一的那个实例就不再去做别的事。`while` 因此有一个上限：超过十万次就停止，并在标准错误里说明循环太多。这不是把无限循环变成一种功能，只是避免页面卡死。课程里的循环用三样东西或三步计数，离这个上限很远。`for` 在实现里靠词表结束，没有同一把计数器，所以词表本身必须是短的、写死的。不要用生成器去堆十万个词，这只壳也没有那种生成器。

从下一章起，同一张清单会长出一种新的能力。引号决定 `$` 要不要展开。赋值把名字留在这张表里，`$?` 则必须趁早抄下来。`test` 把判断变成 `0` 或 `1`。`if` 按这个数字挑选句子。`&&` 和 `||` 在失败或成功时省掉右边。`while` 用一个会变成假的条件数三步。`for` 顺着词走，不去算算术。管道把左边的输出放进内存再交给右边。重定向把一行写进 `note.txt` 再读回来。`read` 从围栏准备的标准输入取一行。最后一章把变量、判断、循环、管道、重定向放进同一次出门检查。

印清单时还有一个很小、但会反复出现的细节。格式串要用引号包住。单引号里的 `\n` 会原样交给 `printf`，由它解释成换行。若把反斜杠露在引号外面，壳在展开阶段会吃掉反斜杠，格式就不再是你以为的那一份。这一章的三块都把格式放在单引号里，输出里的换行才是格式的一部分，而不是词法上的意外。百分号若要出现在格式里，写成 `%%`。清单上暂时没有百分号，后面用到时再写。

## 小结

这只壳跑在一个 wasm 实例里。preview1 没有 `fork`，所以外部程序、后台和子壳都不会出现。外部命令的退出码是 `127`，标准错误里写着 `external commands are not available`。内建命令共享一张变量表。`$$` 固定是 `1`，`$#` 在这种运行方式下是 `0`。清单上的钥匙、水杯、车票要用 `printf` 自己送出去，换行写在格式串里。

下一章用同一个变量看两种引号：单引号留下 `$item` 这几个字符，双引号把清单上的那一项展开。
