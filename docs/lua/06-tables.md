函数已经能往清单末尾追加。这一章回到表本身：键怎么排，长度怎么来，中间缺一格时会发生什么。周衡的纸若第一行写买笔，第二行写交表，第三行写浇花，程序里就是下标 1、2、3。没有第 0 行。`items[1]` 才是买笔。`items[0]` 只有在你曾经用 0 当键写入时才有值，否则是 nil。从别的语言搬来的循环若从 0 走到长度减一，第一条永远看不到，看到的最后一格还是 nil。待办会安静地少掉买笔。

```lua run expect="买笔" title="第一条在下标 1"
local items = { "买笔", "交表", "浇花" }
print(items[1])
print(#items)
```

`#` 在这条清单上是 3。它可信，是因为这张表是一条序列：从 1 到 3 都有值，4 是 nil。长度运算符找的是一个边界。边界是某个非负整数 n，n 为 0 或者 t[n] 不是 nil，并且 t[n + 1] 是 nil（或 n 已经大到整数的尽头）。没有洞的序列只有一个这样的边界，就是条数。`#` 不用走完每一格，它用类似二分的方式找边界，所以长清单的取长度不必是线性扫描。代价是：一旦有两个边界，实现可以交回其中任意一个。语言手册把这种情况留成未指定。你不能把「我这台机器上试出来是 4」写成永远成立的合同。

洞就是这样造出来的。先放两条，再直接写 `items[4] = "浇花"`，下标 3 从来没有值。现在至少有两个边界：2 的下一格是 nil，4 的下一格也是 nil。非空的标题有三条：买笔、交表、浇花。眼睛数是 3。`#` 不会稳定地等于 3，因为它根本不是在数非空键，它是在找边界。下面这一块把眼睛数到的条数和 `#` 放在一起，两者不一样就印出「长度对不上」。无论这次实现交回哪一个边界，只要它不是 3，这句话就成立。而 3 不可能是边界，因为下标 3 本身是 nil，边界要求那一格有值，或者边界是 0。

```lua run expect="长度对不上" title="中间有洞时不要信长度"
local items = { "买笔", "交表" }
items[4] = "浇花"
local nonempty = 0
for i = 1, 4 do
  if items[i] ~= nil then
    nonempty = nonempty + 1
  end
end
if #items ~= nonempty then
  print("长度对不上")
else
  print("碰巧一致")
end
```

ipairs 沿着 1、2、3 往下走，遇到第一个 nil 就停。它不会跳过洞去拿浇花。于是有洞的清单用 ipairs 会少打末尾那一条，用 pairs 则可能看见浇花，但 pairs 的顺序不保证，不能拿来核对先后。待办要顺序，就维持序列，不要挖洞，然后用 ipairs 或数值 for。下面只用 ipairs，输出应当停在交表，浇花不出现。

```lua run expect="买笔,交表" title="ipairs 在洞前停下"
local items = { "买笔", "交表" }
items[4] = "浇花"
local seen = {}
for _, title in ipairs(items) do
  seen[#seen + 1] = title
end
print(table.concat(seen, ","))
```

挖洞的常见手法是 `items[i] = nil` 想表示删除。删除中间一条之后，`#` 和 ipairs 都可能不再看见后面的条目。那不是删除，那是把纸剪开，后半截掉到长度看不见的地方，数据却还在。真正删掉并让后面的前移，要用 table.remove，标准库那一章会做。现在只要记住：nil 不是一个普通的「空标题」。空标题是空字符串，键还在，序列还连续。nil 是键消失。两者在 print 里不同，在长度里更不同。

记录和序列可以住在同一张表里。`{ title = "回信", done = false }` 没有正整数键 1，`#` 通常是 0。这不是说记录是空的，是说它的内容不在序列那一段。用长度判断「有没有标题」会得到 0，然后你把一条写好的回信当成空白纸。取记录要用名字：`item.title` 和 `item["title"]` 是同一格。点号方便，括号适合键放在变量里，或者键不是合法的标识符。下面打印括号形式，证明键是字符串，不是一种特殊的字段语法。

```lua run expect="回信" title="字段就是字符串键"
local item = { title = "回信", done = false }
print(item["title"])
print(#item)
```

第二行是 0。期望写回信，避免和 0 纠缠。阅读时请看第二行，它提醒你不要对记录取长度来问「填了几项」。填了两项，长度仍是 0。要数字段，得自己用 pairs 计数，并且接受顺序不定。待办的展示若依赖字段顺序，就不要靠 pairs 的遍历顺序，把你在乎的键按自己的次序写出来：先标题，再是否完成。

构造函数里可以混写。`{ "买笔", title = "买笔" }` 既有序列的第一项，又有一个同内容的字段。这通常是笔误，不是技巧。两处以后会各自修改，纸上出现两个版本的标题。保持一种形状：清单的元素是字符串，或者清单的元素是记录。不要在同一层既当序列又当那一条自己的字段。嵌套是清楚的：外层只有 1、2、3，内层才有 title 和 done。外层的 `#` 表示有几条，内层的 `#` 不要拿来用。

```lua run expect="2" title="外层序列，内层记录"
local items = {
  { title = "买笔", done = false },
  { title = "交表", done = true },
}
print(#items)
print(items[2].title)
```

赋值 `items[#items + 1] = title` 依赖 `#` 正好落在序列末尾。有洞时，这个「末尾」可能落在洞前的边界上，新标题写进洞里或写到一个已有的边界上，原来的浇花被盖住或仍然挂在外面。所以追加函数的合同是：调用方保证这是一条序列。函数很难在写入前证明没有洞，因为那需要扫描。扫描可以做，但每次追加都扫描，就把 `#` 的对数代价换成了线性代价。小清单线性也可接受。大清单就更应该从一开始别写 nil。合同写在函数上方的注释里，比写一个永远不失败的检查更符合这一章的尺度。

键不一定是字符串或整数。表可以作为键，函数也可以。待办用不到，知道即可：键的相等按值的身份或按字符串与数字的规则。用表当键时，内容相同的另一张表是另一个键。你不能拿一张新构造的 `{ title = "买笔" }` 去取出以旧表为键的值。这条规则阻止了一种隐式的深比较。深比较若要，得自己写，并且为循环引用准备停止条件。待办的查找按标题字符串，字符串按字节内容相等，不按身份。两个都写成买笔的字面量会相等。

数组部分和哈希部分在实现上是分开存储的，这是长度能二分的原因之一。你不需要为了写对待办去迁移这两部分。你需要的是不要制造两个边界。一个边界，`#` 就是条数。两个边界，`#` 只是某一个边界。演示块印出「长度对不上」，就是这个合同被打破时你应当看到的句子，而不是一个偶发的打印错误。

构造一张大清单时，可以先 local items = {} 再逐条写入，也可以在花括号里一次写完。一次写完的好处是读代码的人看见全部标题，不用在脑子里模拟追加。逐条写入的好处是条数来自输入，写代码时还不知道有几条。最后一章的标准输入就属于后一种。两种构造得到的都是表，# 的规则相同。不要在花括号里写 nil 来占位，占位会直接变成洞，后面的字面量可能掉到长度看不见的地方。需要占位时用空字符串，并在显示时把空字符串说成空白，而不是把键删掉。

pairs 会拜访所有键，包括字符串键和整数键。顺序不固定，今天先看见 title 还是先看见 1，都不能写进期望。可以把它用在计数上：数一数这张表到底有几个键，用来发现「记录里是不是混进了序列」。计数的结果是稳定的，顺序不是。待办的展示不要 for pairs 然后 print 标题，那样每运行一次行序都可能变，核对子串虽然仍能找到买笔，顺序错了却看不出来。要顺序，用 ipairs 或数值 for，并保持没有洞。

键的赋值 items["买笔"] = true 可以做成一张集合，用来回答「这件事在不在纸上」。集合的查找不依赖顺序，也不依赖 #。# 对这种表通常是 0，因为没有键 1。这很适合「已经买过的东西不要重复追加」。判断用 items[title] == true，不要用 if items[title]，虽然 true 为真、nil 为假，看起来能用。若你以后把值改成剩余支数，0 也会为真，if items[title] 就不再表示「在不在」。用 == true 或 ~= nil，把「在不在」和「值是什么」分开。分开之后，集合才能安全地变成计数字典。

复制一张清单不能写成 local copy = items。那只是第二个名字指着同一张表，改 copy[1] 就是改 items[1]。要复制内容，得新建一张表，按 1 到 #items 把值抄过去。抄的是值。值若又是表，抄到的仍是引用，内层记录仍共享。待办的标题是字符串，字符串不可变，共享没有副作用。待办若是记录，浅拷贝会让两条纸共享 done 字段所在的那张内表，勾掉一条的完成会勾掉另一条。深拷贝要自己写，并且碰到循环引用时停下来。四条记录的纸，浅拷贝加「内层也新建」就够，不必做通用深拷贝。

长度运算符的代价是它不保存计数。每次问 # 都去找边界。没有洞时结果稳定。你若在循环条件里写 i <= #items，而循环体又在末尾追加，上限每次重新计算，循环可能停不下来。数值 for 的上限只算一次，所以更安全。while 的条件每次都算。追加进 while 时，要有别的停止条件，例如最多处理原来的三条，新追加的留到下一轮。这不是 # 不准确，是停止条件被你自己的写入搬动了。

0 和负数键可以存在，它们不算进 #。items[0] = "封面" 不会让长度变成 4，也不会让 ipairs 看见封面。封面这种「不属于清单」的注记，更清楚的做法是放在另一张表的字段上，而不是借用 0。借用 0 能跑，下一班会以为序列从 0 开始，然后把第一条买笔漏掉。漏掉是安静的，print 仍有交表和浇花，测试若只找交表就会通过。期望里带上第一条的词，才能挡住这种下标习惯。

复制序列时，元素是字符串就按内容相等。四条标题抄完，新旧两张表的第一条用相等比较应当成立，因为字符串看字节，不看是不是同一次构造出来的。只比较相等还不够证明两张纸已经分开。第二个名字指着同一张表时，比较也会成立，可是改一边会改到另一边。证明分开的办法是：抄完之后改掉新表的第一条，再看旧表的第一条是不是仍为买笔。旧表不变，才是复制。相等只说明此刻字节一样。

0 号键上的注记不会被 ipairs 看见，这一点在合并两张纸时还会再出现。若有人把封面信息塞在 0，合并循环从 1 走到长度，封面被留下，既不报错也不出现在新纸上。丢失是静默的。静默的丢失比报错难查，所以封面应放在记录字段里，序列只放待办。合并循环因此可以信任两端都是序列，不必再猜 0 上有没有私货。

## 小结

序列从 1 开始，没有洞时 `#` 等于条数，ipairs 能走完。中间缺一格时存在多个边界，`#` 不必等于非空条数，ipairs 会在洞前停下。记录的字段不参与这段长度，`#` 常常是 0。删除不要写成中间赋 nil，空标题用空字符串，键留在序列里。追加信任 `#` 的前提，就是这张表仍然是一条序列。
