待办写到这里，缺的是几种很具体的加工：把标题里的词换掉、按字节顺序排列、从几条优先级里取出最小的。Lua 把这些放在标准库里，而不是放进语言的特殊语法。这一章只用三张表：string、math、table。它们本身也是表，函数是字段，和上一章的 todo 是同一种形状，只是由语言事先填好。不使用 os.execute，也不用 io.popen 去叫一个外部的排序程序。排序就在进程里完成，结果才稳定，也不依赖那个不存在的壳。

string.gsub 查找并替换。它交出两个结果：新字符串，以及替换了多少次。字符串不可变，所以是新的，原来的标题还在。`local s = string.gsub("买笔买笔", "买", "备")` 时，s 只接到第一个结果，次数被丢掉。丢掉不是失败。你若只关心换完的句子，一个名字就够。你若把 gsub 直接交给 print，两个结果都会印出来，中间是制表符，行尾看起来像多了一个数字。那个数字是次数，不是标题的一部分。核对「备笔备笔」时，多出来的次数会粘在同一行，眼睛容易把次数当成句子的一部分。先放进 local，再打印 s。

```lua run expect="备笔再备纸" title="赋值只留下新字符串"
local source = "买笔再买纸"
local s = string.gsub(source, "买", "备")
print(s)
print(source)
```


第二行仍是买笔再买纸。第一行里两处「买」都换成了「备」。次数这一块单独接住，避免和句子挤在一次 print 里。模式在这里就是普通的「买」，没有用到魔法字符。待办的替换若包含百分号或点号，那些字符在模式里有特殊含义，需要转义。普通汉字没有这层含义，可以直接当字面量。模式按字节工作，不是按「一个汉字字符类」。不要写一个以为能匹配任意汉字的简写就去截标题，它匹配的是字节规则。截取仍然用上一章说过的 string.sub，单位是字节。

```lua run expect="2" title="第二个结果才是次数"
local _, n = string.gsub("买笔再买纸", "买", "备")
print(n)
```

下划线是一个普通的局部名字，习惯上表示「这一格我接到了但不用」。它不会自动忽略结果。忽略是因为你没有再读它。若函数只有一个结果，n 会是 nil，打印 nil。gsub 保证有第二个结果，没匹配到时次数是 0，字符串原样返回。0 和「没调用」不同。可以用次数决定要不要记一条「发生过替换」的待办。

table.sort 就地排序，并且不返回新表。没有返回值时，赋值得到的是 nil。`local returned = table.sort(titles)` 之后，returned 是 nil，titles 的顺序已经变了。就地的好处是不必再分配一张同样大的表，清单很长时这要紧。代价是所有还指着这张表的名字都看见新顺序。你若留了一份「原始次序」的想法，却只复制了引用、没有复制内容，原始次序就丢了。要保留原次序，先把元素抄到一张新表再排序。抄是线性的，比错误地以为 sort 会交还副本便宜得多，贵的是事后发现回信跑到了买笔前面却没有原稿。

默认的比较是 `<`。字符串按字节比较。买、交、浇三个字的编码使得买笔排在交表前面，浇花在最后。这个顺序是编码顺序，不是笔画顺序，也不是拼音顺序。周衡若期望按拼音，默认 sort 做不到，需要自己写比较函数。比较函数接收两个元素，返回真表示第一个应当排在前面。写比较时不要去改元素，排序过程中改表，结果没有定义。下面先用默认顺序，把三条用逗号接成可以核对的一行。

```lua run expect="买笔,交表,浇花" title="排序改的是原来那张表"
local titles = { "交表", "买笔", "浇花" }
local returned = table.sort(titles)
print(table.concat(titles, ","))
if returned == nil then
  print("没有新表")
else
  print("有新表")
end
```

第二行是没有新表。table.concat 只接受序列，在元素之间放上你给的分隔符，它不会在末尾再多放一个，除非你自己的元素里就有。nil 洞会让 concat 停住或报错，视洞的位置而定。排序之前先保证是一条没有洞的序列。sort 同样要求序列。有洞的表交给 sort，不是这一章要演示的成功路径。

比较函数可以按优先级排记录，而不是按标题的字节。优先级小的在前。三条的优先级若是 3、1、2，排完第一条应当是优先级 1 的那件。排序是不稳定的：优先级相等时，谁在前不保证保持原样。待办若有两件优先级都是 1，不要依赖它们排序后仍保持写下的先后。要稳定，就在比较里把原下标带上，优先级相同则下标小的在前。那是第二排序键。没有第二键时，就接受不稳定，或者干脆不排，沿用纸上的顺序。纸上的顺序常常比编码顺序更符合「先写的先做」。

```lua run expect="买笔" title="按优先级把最小的排到前面"
local items = {
  { title = "交表", priority = 3 },
  { title = "买笔", priority = 1 },
  { title = "浇花", priority = 2 },
}
table.sort(items, function(a, b)
  return a.priority < b.priority
end)
print(items[1].title)
```

math.min 可以不排序就取出最小的优先级。三个数都作为参数传入，它只回答最小的那一个，不告诉你是哪一条标题。你只要一个数字来决定「今天有没有低于 2 的事」，min 更直接，也不改动清单。你既要数字又要标题，就得排序或自己走一遍。自己走一遍是稳定的，也能在相等时保留先遇到的那一条。min 的代价是丢失身份，sort 的代价是改顺序。两个都不要，就写一个循环记下当前最小的那条记录。

```lua run expect="1" title="只要最小的数"
local items = {
  { title = "交表", priority = 3 },
  { title = "买笔", priority = 1 },
  { title = "浇花", priority = 2 },
}
print(math.min(items[1].priority, items[2].priority, items[3].priority))
```

math.floor 和 `//` 对正数看起来接近，对负数方向不同的细节，类型那一章已经用整数除法处理支笔。这里若要把平均优先级收成整数，优先用 `//`，让运算本身表明「我要整数」。math.floor 接收的是浮点意义下的向下取整，读代码的人要再想一步。能用整数除就不要先 `/` 再 floor，中间那步浮点会把恰好的整数变成你以为需要再收一次的东西。20/6 那种 3.333 不该进待办的条数字段。

string.format 适合把最小优先级和标题嵌进同一句。`%d` 要整数，`%s` 要字符串。给错类型会报错，pcall 能接住，但这一章让格式和参数对齐，不靠接住来凑。格式串的好处是位置和宽度；坏处是百分号和待办的句子混在一行源码里。三条以内，`..` 仍然更直。超过，尤其有数字宽度时，format 更不容易把制表符又夹回去。不要用 print 的多参数来模拟格式，那会插入制表符。

table.insert 和 table.remove 在末尾使用时是追加和弹出，在中间使用时会搬动后面的元素。搬动让序列保持没有洞，`#` 仍然可信。代价是中间删除是线性的。四条待办可以忽略。你在循环里从前往后 remove，下标会错位，和边走边赋 nil 是不同的错，结果同样是漏掉一条。从后往前删，或者记下下标循环外再删。这些函数不返回一张新清单。和 sort 一样，它们改原来的表。

标准库很大，这一章停在三张表上是有原因的。os 里的日期和壳会把例子绑到运行环境，临时文件名又不可用。io 的读入留到最后一章，并且只读标准输入。utf8 库能按码点走汉字，本课的标题长度已经约定用字节，中途改单位会让「你好是 6」和另一套计数打架。三套工具够把替换、最小值和顺序做完。不够的地方用自己的函数，放进上一章那种本地表，而不是再去 require 一份工具文件。

string.match 只交回匹配到的那一段，没有次数。它适合从「优先级:1」这种短文本里抽出数字那一段，再交给 tonumber。抽不到就得到 nil。gsub 适合改写整句并告诉你改了几处。两件工具都按模式，点号会匹配任意一个字节。标题里若要匹配真正的句点，要把句点转义。待办标题很少有句点，一旦从别的系统抄来带句点的句子，未转义的模式会比你想的匹配得更宽，替换次数变多，句子被挖空。次数突然变大时，先看模式里有没有未转义的魔法字符，再怀疑标题本身。

table.move 能把一段下标搬到另一张表或同一张表的另一个起点。它适合把临时读入的几条合并进正式清单的末尾，而不必手写循环。搬动不创造新的字符串，元素仍是原来的值。记录被搬到新下标后，旧位置若你没有清掉，会留下重复引用。合并之后若旧表还要当「只含未合并」的缓冲，就要自己清。move 不会替你把源范围写成 nil。它不是剪切，它是复制下标。复制引用这一点和赋值相同。

math.max 和 math.min 接受多个数，不接受一张表。要把清单里的优先级交进去，得把它们逐个写上，或者用 table.unpack 把序列展开。unpack 在末尾有洞时会停，中间的洞会让展开的个数变短。又是序列合同。三条优先级直接写进 math.min 最清楚，不必 unpack。条数变多时，循环比较更稳，也不会受参数个数上限的影响。展开很方便，方便的背面是洞会悄悄少传一个数，最小值可能来自不完整的集合。

排序的比较函数若返回的不是真假关系的一致答案，例如一会儿说 a 小于 b，一会儿又在另一次调用说 b 小于 a，结果没有定义，可能报错，也可能得到一个看起来像排过的顺序。比较要稳定成一种秩序：优先级数值小的在前，数值相等时返回 false，不要在相等时再按一个会变的时钟排序。时钟每次运行都不同，期望就写不住。教材里的优先级是字面量 1、2、3，比较只看这个数。

string.format 的 %q 会给字符串加上引号并转义，适合调试，不适合周衡阅读。%s 原样放入。调试输出和给纸面的输出最好分开。给纸面的用 %s 和中文，调试的可以暂时 print 原始的 title。核对通过后，调试那一行不要留在最终示例里，它会让期望多出一个你不想当合同的词。合同应当是排序后的第一条，或替换后的整句。

table.concat 的第二个参数是分隔符，第三个和第四个可以限制下标范围。限制范围时仍要求范围内没有洞。用它印出前两条，可以避免把后面的回信也送进终端。送进终端不一定是错，但期望会变宽，宽的期望更容易被无关的字凑巧满足。范围写清楚，输出就短。短输出是这一章和 print 那一章共同的偏好：一次证明一件事。

## 小结

string.gsub 交出新字符串和次数，赋给一个局部变量时只留下句子。table.sort 就地重排并返回空，默认顺序是字节顺序，不是拼音；相等键的先后它不保证。math.min 只给数字，不改清单。加工清单时仍保持序列没有洞，并且不调用外部程序来排序或替换。
