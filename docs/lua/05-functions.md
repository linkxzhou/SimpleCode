顶层脚本里的循环已经能走过买笔、交表和浇花。再加「拒绝空标题」「记下是第几条」「换一张清单再来一遍」，同一段 for 就会被复制三份。复制的时候容易改掉其中一份的起始下标，两张纸的规则就分叉了。函数把「加一条」收成一个名字。调用的人提供标题，函数负责放进哪一张表、放完之后长度是多少。规则只有一份，分叉要故意改函数，而不是在复制时手滑。

函数是值。`local function add(list, title)` 这种写法会造出一个函数，并让局部名字 add 指着它。它和先 `local add` 再赋值是一类事，只是语法把名字提前放好，方便函数体里递归时看见自己。待办的追加不需要递归。需要记住的是：没有 local 的 `function add` 会变成全局。全局在一份短脚本里能跑，两份功能若都叫 add，后写的把先写的盖掉，打印的条数会来自后一个定义。这一章的函数都带 local。

参数是调用时新的局部变量。函数里给参数赋值，不会改掉外面那个同名的局部变量，因为它们只是同名，不是同一格。表例外在于：参数得到的是那张表的引用，不是一份拷贝。`list[#list + 1] = title` 改的是调用方那张表的内容。调用结束后，外面的 list 能看见新的一条。这是待办想要的：函数存在的意义就是把纸写上。若语言把表也按值拷进函数，追加会发生在拷贝上，外面的纸仍是空白，函数就成了无声的成功。引用的代价是：函数若在错误的位置写入，调用方的其他字段也会被牵连。所以追加只碰下一个整数键，不去改主人或别的名字。

```lua run expect="2" title="追加并交还条数"
local function add(list, title)
  list[#list + 1] = title
  return #list
end
local items = {}
add(items, "买笔")
print(add(items, "交表"))
```

返回值可以有多个。状态既可以是一个中文词，也可以是一个 0 或 1，给以后的计数用。一次 return 交出两个，调用处用两个名字接住。只写一个名字，第二个被丢掉，不会报错。丢掉是静默的，静默适合「我确实只要标题」的场合，不适合「我忘了还有一个结果」。下面把两个都接住，拼成一行，避免第二个在无意中消失。

```lua run expect="未完成:0" title="两个结果都接住"
local function status(done)
  if done then
    return "完成", 1
  end
  return "未完成", 0
end
local label, bit = status(false)
print(label .. ":" .. bit)
```

若把 status(false) 直接放进 print，两个结果会变成 print 的两个参数，中间是制表符。输出仍能找到「未完成」，但冒号那种紧凑的形状没有了。要形状，就先接住，再自己连接。这和 print 那一章的原则是同一条：开放的参数列表会把多余的结果展示出来，固定个数的赋值会把多余的结果丢掉。

闭包把表藏进函数出生的那个环境。make 在里面 local 一张 items，返回另一个函数。返回的函数没有 list 参数，它使用的是外面的 items。调用方只能追加，不能把整张表换掉，除非 make 还把表一并交出来。这是隐私：空标题的拒绝、下标从 1 开始，这些约定不会被调用方用 items[0] 绕开，因为调用方根本拿不到 items。代价是调试时你不能在外面 print(items) 看全部。要看，就再返回一个专门的只读函数，例如 count 或 at。隐私和可见是交换，不是免费的封装。

```lua run expect="2" title="闭包记住自己的清单"
local function make()
  local items = {}
  local function add(title)
    if title == "" then
      return #items
    end
    items[#items + 1] = title
    return #items
  end
  return add
end
local add = make()
add("买笔")
print(add("交表"))
```

再调用一次 add("浇花") 会得到 3。那个 3 活在闭包里，不在全局。再 make 一次，得到的是另一张纸，条数从 0 重新长。两张纸不会串。若你忘了 local items，items 变成全局，第二次 make 会接着上一张纸写，两个人的待办混在一起。local 在这里不是风格，是两张纸的边界。

闭包延长了 items 的寿命。make 已经返回，它的局部变量按常理该消失，但返回的函数还指着 items，于是那张表留着。这就是待办能「记住」的办法，记住发生在同一次进程里。下一次 Run 仍是新进程，闭包不会跨过点击活下来。不要把闭包理解成数据库。它只是一次运行内部的记忆。

函数也可以没有名字，写在参数位置上，或者写成立即返回的值。有名字是为了待办的动作能被说出来：add、status、make。匿名适合真正只用一次的小段，例如稍后在标准库里交给排序的比较。过早匿名，错误信息里只剩一段括号，你不知道是追加坏了还是状态坏了。

多个函数可以合谋在同一张闭包上。make 返回 add 和 count 两个函数，它们看见的是同一张 items。这比返回整张表更窄：外面能问条数，能追加，不能随便 pairs 去改键。返回两个结果即可。调用写成 `local add, count = make()`。顺序要和 return 一致，写反了就会把函数当地址用错，调用时才爆。爆在调用而不是在接住的那一行，因为接住两个函数值完全合法，错的是你以为左边那个会接受标题。

```lua run expect="1" title="追加和计数看见同一张纸"
local function make()
  local items = {}
  local function add(title)
    items[#items + 1] = title
  end
  local function count()
    return #items
  end
  return add, count
end
local add, count = make()
add("回信")
print(count())
```

Lua 支持尾调用：return 一个函数调用时，可以复用栈帧。深的尾递归因此不会把栈撑满。待办的追加不是递归，用不到这个特性。知道它，是为了读到 `return add(title)` 这种写法时不惊讶：那不是忘记写本地逻辑，而是把工作完全交给下一次调用。尾调用的代价是错误栈更短，中间那一帧可能消失。调试时若栈上看不见你以为会在的函数，先看是不是尾调用把那一帧省掉了。

参数个数对不上时，少的参数是 nil，多的参数被丢掉。add 若被调用成 add()，title 是 nil，`#` 的更新会把 nil 写进序列的下一格，也就是什么都没写，还可能把序列截断。所以函数开头可以拒绝 nil 和空串，拒绝的方式下一章还不是 pcall，可以简单地不写入并返回当前长度。不写入比写入 nil 安全。写入 nil 会在表那一章变成洞。这里的闭包例子用空串演示「不增加条数」：add("") 返回的仍是原来的长度。你可以把这个返回值和追加真实标题之后的返回值对比。对比要在同一次运行里做，闭包才还活着。

默认参数没有专门的语法。想让 done 缺省为 false，在函数里写 `if done == nil then done = false end`。不要写 `if not done then`，因为调用方传入的 false 也会被 not 抓住，你无法区分「没传」和「明确未完成」。又是 nil 和 false 的差别。类型那一章把差别说在条件里，这里它决定默认值能不能写对。

把函数放进局部变量之后，可以再把它放进表。放进表不是现在就要做的模块，只是提醒：函数没有特权位置，它和标题一样是值。你可以把 add 交给另一个函数，让那个函数对三张不同的清单各调用一次。高阶用法适合「同一套追加，不同的纸」。不适合在追加内部再隐藏一张谁也看不见、谁也清不掉的纸，除非你确实想要闭包的隐私。想清掉，就让 make 再返回一个 clear。没有 clear 又没有表的引用时，那张纸会一直留到进程结束。进程结束会清掉它，但同一次运行里你无法回到空白，除非再 make 一次。再 make 得到的是新纸，旧纸若还有别的函数指着，旧纸还在。

参数里的表可以是 nil。调用 add(nil, "买笔") 会在对 nil 取长度时出错。出错点在函数内部，调用行看起来像把参数传对了。在函数开头写 if type(list) ~= "table" then return 0 end，能把这种调用变成安静的 0。安静的 0 和「纸是空的」一样，调用方可能继续打印 0 并以为自己成功建了一张纸。更好的做法是让这种调用失败并被看见。失败的方式可以是 error，那是保护调用那一章的事。在那之前，至少不要用一个像成功的 0 把 nil 清单吞掉。吞掉的清单不会在后面突然出现。

递归可以用来走一条嵌套的待办，子项目本身又是清单。四条的纸用不到递归，数值 for 更直。递归的合同是每次调用都更接近停止，例如下标往前移，或者嵌套层数减少。没有停止条件的递归会把栈用满，错误信息和普通的 nil 索引不同，它会说栈溢出。栈溢出不是待办太多这么简单，四条不会溢出，无限的自己调用自己才会。写递归时先写停止，再写调用自己。停止放在后面，第一次调用就已经走错了。

多个结果里夹 nil 时，接收要小心。return nil, "买笔" 然后 local a, b = f()，a 是 nil，b 仍是买笔。若写成 return "买笔", nil，第二个名字是 nil。打印时 nil 会变成文字。若你用 select 去数结果个数，夹在中间的 nil 算一个结果，末尾的 nil 也算，这和「没返回」不同。没返回时个数是 0。待办的状态函数若有时少返回一个值，调用方的第二个名字变成 nil，可能被 or 换成默认词。默认词一出现，你就分不清函数是忘了返回，还是明确给了 nil。个数要稳定，两个结果就总是两个，不用的那个用 false 而不是直接省略。

局部函数看见的是定义时能看见的名字，不是调用时全局里碰巧同名的名字。这叫词法范围。闭包记住 items，是因为 items 在定义 add 的那一层。若 items 是全局，所有闭包共享一张纸，make 就失去了「每人一张」的意义。调试时若两条清单互相看见对方的浇花，先检查有没有漏写 local，而不是先怀疑表的下标从 0 开始。下标问题会少第一条，共享全局会多出别人的条目。两种症状不同，药方也不同。

匿名函数写在 table.sort 的参数位置上时，它也能闭包外面的比较规则，例如「优先级相同就按原来的下标」。那是标准库那一章的比较函数。这里先知道：那种函数用完就没有名字，错误栈上可能只显示一段函数。给它一个局部名字再传进去，栈会好读一些，多一行赋值。待办的排序规则若会改，有名字的函数更容易被两处共用。只用一次的规则，匿名也可以。选择看这条规则会不会被第二张纸复用。

## 小结

函数把追加收成一份规则，表按引用被修改，所以外面的清单看得见新标题。多个返回值用多个局部名字接住，直接放进 print 会夹上制表符。闭包让追加函数记住自己的表，调用方接触不到内部的洞，调试时也就少了一条直接查看的路。另一张纸要再调用一次 make。没传的参数是 nil，不能用 not 把它和 false 混成同一个默认值。

写一个闭包，第一次调用返回 1，再调用返回 2。打印第二次的结果。

::: answer 参考答案：第二次是 2
```lua run expect="2" title="参考答案"
local function make()
  local n = 0
  return function()
    n = n + 1
    return n
  end
end
local next_n = make()
next_n()
print(next_n())
```
