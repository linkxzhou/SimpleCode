待办的标题是字符串。周衡写下买笔两个字，眼睛按字数。Lua 的 `#` 不按字数，它按字节。UTF-8 里一个汉字通常占三个字节，所以 `#"你好"` 是 6，不是 2。买笔同样是 6。这个数字用来分配缓冲、对照传输长度是对的，用来在界面上说「请把标题限制在两个字」是错的。限制两个字却用 `#` 去卡 2，任何一个汉字都过不了关，因为一个汉字已经是 3。下面先把你好的长度印出来，让 6 这个数成为后面的标尺。

```lua run expect="6" title="你好占六个字节"
print(#"你好")
```

字符串的下标从 1 开始，和表的序列一致，和有些语言从 0 开始的切片不一致。string.sub 的第三个参数是结束位置，而且包含这一位。`string.sub("abcdef", 2, 4)` 得到 bcd，不是 bc。少算一位，标题会被截短；多算一位，会把下一件事的头带进来。包含结束位置的好处是：你心里想的「从第 2 个字节到第 4 个字节」就是参数 2 和 4，不用再减一。代价是从别的语言抄来的「结束下标不计」会多取一个字节。多取的那个字节若落在汉字中间，终端上会出现一个不完整的字，看起来像乱码，长度却是你算过的。

```lua run expect="bcd" title="结束下标算在里面"
print(string.sub("abcdef", 2, 4))
```

汉字不能按「两个字就是下标 2」去切。买的 UTF-8 是三个字节，`string.sub("买笔", 1, 3)` 正好是买。切到 2，会把买的第三个字节留在后面，前面那一截不再是合法的文字。这一课不打印那种残缺，只核对完整的前三个字节仍然等于买，并再印一次整条标题的字节数。两行一起看：一个字是 3，两个字是 6。你若写 `string.sub(title, 1, 2)` 想表示「前两个字」，得到的既不是两个字，也不是一个完整的字。

```lua run expect="买" title="前三个字节才是一个汉字"
local title = "买笔"
print(string.sub(title, 1, 3))
print(#title)
```

负的下标从末尾数。`string.sub("abcdef", -3)` 得到 def，省略结束位置表示直到末尾。这在取扩展名时顺手。待办标题很少有扩展名，负下标仍然要知道，否则别人的代码里出现 -1，你会把它当成「出错的正下标」。-1 是最后一个字节，对汉字来说往往是那个字的最后一个字节，单独拿出来同样不是一个字。所以负下标没有魔法，它只是从另一头起算的字节位置。

字符串在 Lua 里不可改。你不能把买笔的第一个字节换成别的。`..` 每次都做出一个新字符串，旧的还在，只要还有名字指着它。短标题这样很安全：连接「买」和「笔」不会让原来的「买」变样，别处若还拿着「买」不会被牵连。代价出现在循环里一遍遍往同一个名字上接。每一轮都复制已经接好的前缀，条数一多，复制的总量近似成平方。待办若只有四条，平方也不可怕。若把一整天的流水接成一份报告，就该把片段放进表，最后一次 table.concat。连接的取舍因此不是「.. 不好」，而是「几次连接对短标题合适，反复连接对长报告不合适」。标准库那一章再用 concat，这里先把新字符串这个事实说清。

```lua run expect="买笔" title="连接得到新标题"
local head = "买"
local title = head .. "笔"
print(title)
print(head)
```

第二行仍然是买。若字符串可以就地修改，head 可能被 title 的构造带走，第一行和第二行就不再独立。不可变让这两个名字的意思稳定。你付出的是多一次分配。四条待办的标题都很短，这次分配可以忽略。不要为了省一次分配去把标题放进一张字节表里手工改，那会把这一章变成缓冲管理，待办的句子反而看不见了。

`#` 对空字符串是 0。空字符串不是 nil。上一章说过它在条件里为真，这里补上长度：真，并且长度为 0。你可以用长度判断「有没有字」，这比真值判断准确，因为空串的真值会骗过 `if title then`。`if #title > 0 then` 才是在问有没有字节。注意问的仍是字节。一个只含空格的标题，长度大于 0，也是真，它不是空标题，只是看起来空。要不要把空格当成没写，是业务规则，语言不会替你 trim，除非你自己写。自己写时要用字节或模式，不要假设一个空格占的位置在所有文字里都一样。汉字标题里夹一个 ASCII 空格，那个空格是一个字节，汉字仍是三个。

单引号和双引号都表示字符串，没有功能差别。选哪一种，只看里面要不要包含另一种引号。待办标题若带书名号，不需要引号，两种都行。长字符串用 `[[` 和 `]]`，可以跨行，里面的换行会成为内容的一部分。跨行标题很少见。长字符串容易和长注释搞混：注释是 `--[[`，字符串没有那两个减号。少写减号，你以为在注释，其实造出了一个没人接收的字符串，然后被丢掉，输出不变。这种错误不报错，所以更要看清开头的两个字符。

字符串和数字在 `..` 两侧会互相迁就，数字被写成十进制。在 `#` 和 string.sub 里没有这种迁就。你不能对数字取 `#`，那是长度运算符用错了对象，运行时会报错。优先级是数字，标题是字符串，先想清楚这一行要量的是哪一个，再伸手。报错信息会说尝试对一个 number 取长度。看到这句话，回到那一行，不要去改 print 的期望。

模式匹配先不展开。string.gsub 会在标准库那一章出现，而且它返回两个值：换过的字符串，以及替换次数。直接写 `local s = string.gsub(...)` 时，s 只留下第一个。这里先不调用它，避免这一章同时讲解字节和多返回值。你只要记住：截取用 string.sub，量长度用 `#`，两者的单位都是字节，结束下标包含在内。

把规则放回四件待办上。买笔、交表、浇花、回信，每一条的 `#` 都是 6。你若写一个「标题太长」的判断，阈值用 2，四条全会被拒绝；阈值用 6，四条刚好放下两个汉字。这个阈值不能抄到含有 ASCII 的标题上。Ada 的长度是 3，它是三个字母，不是一个汉字。同一套界面若既允许中文待办又允许一个拉丁缩写，字节阈值会偏爱短的拉丁字母，让一长串字母通过你以为只够两个汉字的检查，或者让两个汉字挤不进你按字母估的格子。要么按字节明确说「最多 12 字节」，要么先规定标题只用汉字并按 3 的倍数检查。混在一个魔法数字里，两种文字都会觉得委屈。

string.lower 和 string.upper 对 ASCII 字母有效，对汉字通常原样返回。把买笔交给 string.upper，还是买笔。把 ada 交给 string.upper，得到 ADA。待办若用大小写区分状态，只在纯字母的标记上可靠，例如用 x 表示完成。不要试图用大小写折叠汉字。折叠不会发生，比较却会让你以为自己已经忽略了大小写。状态标记留到后面用布尔值，标题保持你写下的样子，连大小写都不要替用户改。

string.find 返回的位置也是字节，而且是包含起点的那种下标，和 string.sub 同一套数法。在「前缀买笔后缀」里找买笔，起点应当是 1 后面的某个字节，而不是第几个汉字。找到之后用那两个位置去 sub，才能把词切出来。找不到时 find 返回 nil，nil 关掉条件，于是「没有这个词」和「找到了位置 0」不会混在一起。位置不会是 0，因为下标从 1 起。把找不到当成 0，是别的语言的习惯，搬进来会让后面的 sub 从错误的一端起算。

两个标题用小于号比较，比的是字节序，不是拼音，也不是笔画。买笔和交表谁在前，取决于编码，不取决于周衡先写了哪一条。排序那一章会把这件事放到整张清单上。这里先记住：相等才表示两个字符串的字节完全相同。多一个空格就不相等。界面上对齐用的空格会让「看起来一样」的两行在 == 里分开。若业务想忽略首尾空格，得自己去掉，语言没有一个会改写原标题的修剪函数必须被调用。你自己做的修剪应交给一个新字符串，旧标题留着，方便核对用户到底输入了什么。

string.rep 把同一段重复若干次。分隔线可以用减号重复，长度按字节正好等于你给的次数，因为减号是一个字节。不要用它去重复汉字并指望次数等于字数的视觉宽度。重复三次「买」，字节数是 9。终端里看起来是三个字，# 是 9。用这个长度去分配一个按「字符」估算的缓冲，会少算。缓冲若只是 Lua 字符串，你不必自己分配，重复的结果就是一个新字符串。需要缓冲的是那些按字节预留的外部接口，这一课碰不到，但单位不能记错。

string.byte 取出某一个字节的数值。买的第一个字节不是字的编码本身的十进制写法那么直观，它是 UTF-8 的前导字节。打印它，是为了确认你切下去的位置落在字的边界上，而不是为了把这个数显示给周衡。周衡要看的仍是买或笔。调试时可以打印 byte，核对通过之后就拿掉，避免期望依赖一个你以后改了编码就会变的数字。标题若只含 ASCII，byte 和字符码一致，Ada 的第一个字节就是 A 的码。中英混排时，不要用一个循环按 byte 加一来「逐字」打印，那样会把汉字拆开。

连接的优先级低于加减时要加括号。1 .. 2 + 3 这种写法会让人猜：是先连接再把结果当数字加，还是先加再连接。Lua 不允许含糊，缺括号会是语法错误，进程不会跑到 print。错误发生在解析，终端上没有你的标题。这是好事，它拒绝了一种会悄悄把 12 和 3 算成 15 或 123 的写法。你必须写成 (1 .. 2) + 3 或者 1 .. (2 + 3)，意图写在括号里。待办的序号很少做这种混合，一旦要做，括号是合同的一部分。

长标题的构造若放在循环里，先收集到一张表再一次 concat，比每圈都 .. 更不容易变成平方复制。收集用的表是序列，从 1 开始，不要在中间放 nil，否则 concat 会在洞处停下，后半段报告消失。这和清单本身的洞是同一类事故，只是发生在「准备打印的片段」上，不是发生在待办条目上。片段表用完可以丢掉，它不是周衡的纸。纸上的四条标题仍然各自是短字符串，用 .. 拼接前后缀完全合适。选哪一种，看片段的个数会不会随输入变长，而不是看哪一种更高级。

## 小结

`#` 量的是字节，你好是 6，买笔也是 6。string.sub 从 1 开始，结束下标包含在结果里，所以从 2 到 4 得到 bcd，前三个字节才是买。字符串不能就地改，`..` 得到新字符串，短标题这样最清楚，长报告再改用表来收集片段。空字符串长度为 0，但在条件里仍为真，有没有字要看长度，不能只看真值。
