周衡清点待办时会遇到好几种「没有」。纸还没拿出来，这是缺了一整张表。某一格还没写标题，键在，值是 nil。他明确把一件事标成不做，那是 false。笔还剩 0 支，这是一个数字。标题栏被涂成空白，那是空字符串。日常汉语里这些都可以叫没有。Lua 的条件只把其中两种当成假：nil 和 false。数字 0 是真，空字符串是真，空表也是真。这一章就把这几种没有放在同一张待办上，免得后面的 if 把「笔用完了」和「这格还没写」印成同一句。

类型的名字用 type 问。表得到 table，字符串得到 string，函数得到 function。数字无论整数还是浮点，type 都回答 number。布尔值得到 boolean。nil 的类型就是 nil。Lua 没有单独的整数类型和浮点类型摆在 type 的答案里。要区分，用 math.type，它会回答 integer 或 float。这个设计让算术少一层声明：你不用先说这条待办的优先级是整数。代价是 `/` 一个不小心就把整数变成浮点，type 仍说 number，你从类型名上看不见事故。math.type 才看得见。待办若用条数做索引，索引必须是整数，浮点索引会被当成另一个键，取出来是 nil。

除法是这条代价最常落地的地方。20 支笔分给 6 个人，`20 / 6` 得到浮点，打印出来大约是 3.3333333333333，前四位是 3.333。它不是 3。每个人分到三支再剩一截，这一截被留在小数里。`20 // 6` 才是整数除法，结果是 3，小数被按朝负无穷的方向收掉，正数看起来就像去掉小数。两种斜杠都合法，都不会报错。选错的那一份脚本会安静地成功，库存却对不上。下面两块分开核对，避免一个期望同时吃到 3 和 3.333 里的那个 3。

```lua run expect="3.333" title="斜杠得到浮点"
print(string.format("%.3f", 20 / 6))
```

```lua run expect="3" title="双斜杠得到整数"
local each = 20 // 6
print(each)
print(math.type(each))
```

第二块先打印 3，再打印 integer。期望锁定 3 时，integer 里并没有单独的 3 这个数字字符混进来造成误会，但阅读时仍要看两行：第一行是商，第二行是 math.type 的回答。若你把 `/` 写进第二块，math.type 会变成 float，商也不再是单独的 3。格式化那一块用三位小数，是为了让 3.333 稳定，不依赖默认打印时小数到底有多长。默认打印的 20/6 确实以 3.333 开头，格式化只是把后面的重复 3 收束掉，好让期望写得短。

条件直接看值的真假，不要求你写成 `if left ~= 0`。把 0 放进 if，它会走进 then，因为 0 不是 nil 也不是 false。这和不少语言相反。那些语言把 0 当成假，空串也当成假，于是「没有剩余」和「没有标题」可以共用一个 if。Lua 拒绝这种共用。剩余 0 支笔仍然是一个已知的数量，空白标题仍然是一个已知的字符串。已知和缺失不该走同一支。下面这一块用剩余支数做条件，0 应当印出「零也要记」。

```lua run expect="零也要记" title="零支笔仍然是真"
local left = 0
if left then
  print("零也要记")
else
  print("被当成没有")
end
```

空标题同样走 then。你若希望空白栏显示成「未命名」，不能写 `title or "未命名"` 就了事。`or` 只在左边为假时才交出右边。空字符串为真，所以 `"" or "未命名"` 交出来的仍是空字符串。nil 才会交到右边。false 也会。这个规则对默认值很有用：字段还没写时用一句 or 补上主人。它对「写了但写成空白」没用。空白是有人涂过的，和从未涂过不是一回事。把两者收成同一个默认词，周衡会以为自己还没写，其实他写过又擦掉了。

```lua run expect="空标题留着" title="空串不会触发 or 的右边"
local title = ""
local shown = title or "未命名"
if shown == "" then
  print("空标题留着")
else
  print(shown)
end
```

nil 和 false 才会关掉条件。未完成若用 false 表示，`if item.done then` 走进 else，这是你想要的。未写的 done 是 nil，也会走进 else。于是「明确标成未完成」和「这个字段还没放上表」在 if 里长得一样。打印时却不一样：一个打出 false，一个打出 nil。若业务要把这两种分开，就用 `== false` 或 `== nil`，不要只靠真值。真值回答的是「像不像缺失或明确的否」，不回答「是哪一种否」。相等比较才回答哪一种。

```lua run expect="false才关掉" title="nil 与 false 走另一支"
local done = false
if done then
  print("已完成")
else
  print("false才关掉")
end
if nil then
  print("不会印")
else
  print("nil也关掉")
end
```

`and` 和 `or` 并不把结果收成 true 或 false。它们交出决定结果的那个操作数。`nil or "买笔"` 得到买笔。`0 or "买笔"` 得到 0，因为 0 已经为真，右边不再看。`false and "买笔"` 得到 false。`1 and "买笔"` 得到买笔。短路是同一套规则的另一面：`and` 在左边为假时不再算右边，`or` 在左边为真时不再算右边。你可以把昂贵的计算放在右边，也可以把会报错的索引放在右边，让左边先挡住 nil。挡住的前提仍是左边真的为假。0 挡不住，空串也挡不住。用 0 当哨兵去保护后面的索引，保护不会发生，该报的错还是会报。

数字里还有一层容易忽略的相等。整数 3 和浮点 3.0 在 Lua 里 `==` 为真。3 和 3.333 不为真。待办的优先级若有时用 `//` 有时用 `/`，相等测试会在「恰好整除」时通过，在「除不尽」时失败。失败的原因不是比较坏了，是两条路径产生了不同的数。想强制整数，就在写进表之前用 `//` 或 math.tointeger。math.tointeger 对带小数的浮点返回 nil，对 3.0 返回整数 3。nil 表示「这不是一个整值」，正好可以拿来拒绝一笔被除花了的支数。

字符串和数字不会在 `==` 里互相凑合。`"3" == 3` 为假。print 把它们都显示成字符 3，眼睛会以为相等，条件却不这么看。从标准输入读来的一行永远是字符串，哪怕看起来像数字。最后一章读到的买笔不会和某个数字键相等。若你要把优先级从文字变成数，得显式转换，转换失败时得到 nil，而 nil 又会关掉条件。转换因此要单独看，不能塞进一个只判断真假的 if 里就当它已经是数。

表的真值和它里面有没有元素无关。空表为真。`if items then` 只说明这个名字指着一张表，不说明上面有买笔。要看条数，看 `#`，并且只在它确实是一条没有洞的序列时相信它。洞的问题属于表那一章。这一章只要记住：用表本身做条件，空白纸也会通过。周衡拿着一张白纸走进 then，然后对 nil 标题做连接，错误出在连接，不在 if。把错误理解成「条件把空表当成了假」，会去改一个没有毛病的真值。

函数也是值，type 回答 function。把同一条规则记在这里，是因为后面闭包会把函数放进变量。你若用 `if add then` 判断「能不能添加」，一个已经创建的函数永远为真，哪怕它闭包里的清单已经不想再接收空标题。能力在不在，和该不该拒绝，是两次判断。第一次看值是不是 nil，第二次看标题是不是空串。两次都用真值，第二次会失败，因为空串为真。

false 和 nil 在表里的差别还会再咬一次。把 done 设成 nil，等于删掉这个键，后面用元表的 __index 还能补回默认值。把 done 设成 false，键还在，值为假，__index 不会介入，因为查找先看见了自己的键。所以「未完成」若希望挡住默认的「已完成」，必须写入 false，不能写入 nil。现在还没有元表，先把这个差别放在类型里：nil 是缺席，false 是出席并否定。出席的否定在条件里和缺席一样关掉分支，在表的键集合里却占着位置。

数字参加比较时走的是大小，不是真值。5 大于 0 为真，这和「0 单独放进 if 也会进去」不矛盾。真值问的是一个值能不能独自打开分支，比较问的是两个数谁大。优先级若直接交给 if，0 和负数都会被当成要处理，因为它们都不是 nil 或 false。该不该插队，应当写成 priority 小于 2 这种比较。比较的结果才是布尔，再交给分支。把优先级本身交给分支，等于宣布除了缺失和明确否定之外，所有数量都一样急。

tonumber 把一串数字文字收成数。成功得到 number，失败得到 nil。格子里若留下的是带引号记忆的「3」，它能变成整数 3，math.type 会回答 integer。带着小数点的「3.5」会变成 float。空串、买笔、只有空格，都得到 nil。nil 会关掉条件，于是转换失败不会被当成优先级 0。静默变成 0 更危险，因为 0 能通过真值检查，一条解析失败的优先级就混进「有数字」的那一支。转换之后还要决定要整数还是浮点。tonumber 不会替你做 //。下标只能要整数，得到 float 时应当拒绝，而不是让 3.5 去取序列。

not 把真假倒过来，倒过来之后才是真正的布尔值。not 0 得到 false，因为 0 为真。not 空串同样得到 false。not nil 得到 true。想用 not 表示「没有标题」，会在空串上失效：空串的 not 是 false，if not title 进不去。没有标题若同时包括没写和涂成空白，就要写成 title 等于 nil 或者 title 等于空串。先把这句比较的结论印成中文再继续。周衡看的是中文，不是 false 这个单词。

整数和浮点相加，结果按浮点走。1 加上 0.5，math.type 是 float。把这个结果存进条数，条数就不再是整数。用它当下标，取到的是 nil，因为 1.5 既不是键 1 也不是键 2。条数只做加一、减一和 //，不要掺进单斜杠。支笔平分可以用单斜杠显示人均大约 3.333，那个数留在说明里，不放回下标。两条路径分开命名，一个名字给整数，一个名字给浮点。名字混用时，type 仍都回答 number，没有编译期的提醒。提醒来自你打印的 math.type。

false 和 nil 在 and 链里都会让右边不执行，交出去的值却不同。false 配上 and 再配上买笔，交出的是 false。nil 走上同一条链，交出的是 nil。若把这个结果存进完成标记，一个是明确的未完成，一个是键的缺失。长度不关心这个字段，以后的默认查找却关心：缺失会去问默认表，false 会自己占住位置。不要为了省事把 and 的结果直接写进字段，除非你清楚左边失败时交出的是哪一种。写之前可以打印 type。类型名稳定，不会掺进每次都变的地址。

主人用字符串时，空主人是空串，未指定主人是 nil。界面上两者都可以显示成未指定，数据上要留着差别，方便以后数「有多少行根本没填」。统计用等于 nil，不要用 not。not 会把空串也算进去，报表就把涂掉的名字和空白格子合成一格。合成在汇报时省事，改正时你不知道该补哪一种。多写一个分支，输出用不同的词。两个词都短，期望才不会互相包含。

## 小结

条件里只有 nil 和 false 为假。0 支笔和空标题都为真，所以不能用 or 把空标题换成未命名。`/` 做浮点除法，20/6 大约是 3.333；`//` 做整数除法，得到 3。type 对两种数字都回答 number，math.type 才分开 integer 和 float。and 与 or 交出操作数本身，短路也按同一套真值决定要不要看右边。
