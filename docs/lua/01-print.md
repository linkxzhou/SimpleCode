待办写在表里，还不算周衡已经看见。进程结束之后，留在终端里的只有写到标准输出的那些字节。没有 print，标题可以好好地躺在字段上，核对的人却对着空白。这一章只处理送出去的方式：先确认通道肯说话，再看多个值并排时中间夹的是什么，最后把注释和局部名字从输出里摘干净。待办仍是那几件。买笔和交表若要出现在同一行，得先决定中间留不留缝。

第一块可运行的例子故意很短。它不读输入，不建表，只打印一个事先写死的词。选这样一个词，是为了让你在任何业务句子之前，先确认解释器、终端和期望指的是同一条通道。词要短，要稳定，不能带上会变的时间或地址。Ada 满足这三点。引号不属于输出。你若把引号也写进期望，核对会失败，因为终端里没有那些引号。

```lua run expect="Ada" title="先确认通道"
print("Ada")
```

终端上是 Ada 这三个字母，然后换行。括号留在源码里。进程以退出码 0 结束。这一块没有定义函数，也没有留下表。下一块即使还想谈同一张书桌，也必须把要印的字再写一遍。上一章已经说明每次运行都是新进程，这里只是照着做。

print 可以接受多个参数。它把每个参数转成文字，在相邻两个之间放一个制表符，整行末尾再加一个换行。制表符不是空格。眼睛有时把那条缝看成空白，复制到别处，缝的宽度会变，按空格去找「买笔 交表」会找不到。教学里若期望的是紧挨着的买笔交表四个字，两个参数的写法就错了。错的不是汉字没送出去，是中间多了一个你没写进期望的字符。下面这一块真的把两个标题交给同一次 print，期望只锁定前面的买笔，用来证明字出去了。紧挨着的拼法在下一块。

```lua run expect="买笔" title="两个参数中间夹着制表符"
print("买笔", "交表")
```

制表符的码位是 9，打印出来往往只是一条宽窄不稳定的空白。要把这条缝变成可以核对的词，可以先拿同样的字符做替换，换成眼睛看得见的记号，再打印替换后的字符串。这不是 print 的第二种模式，而是把 print 会夹进去的那个字符单独亮出来。记号是我们写的，终端上因此会出现「制表符」这三个字。真正的 print 两个参数时，并不会打印这三个字，它打印的是那个不可见的字符本身。

```lua run expect="分隔是制表符" title="点明夹缝是哪一个字符"
local sep = "\t"
local code = string.byte(sep)
if #sep == 1 and code == 9 then
  print("分隔是制表符")
else
  print("不是制表符")
end
```

要让买笔和交表连成一个词，就在调用 print 之前用 `..` 接上。`..` 只做连接，不偷偷插入空格或制表符。你想要的缝，得自己写进字符串里，例如接一个顿号。你不想要缝，就什么都别接。这个麻烦是故意的：连接符不猜测版式，版式留在你看得见的字面量里。print 的多参数形式则相反，它替你插入制表符，适合把几列对齐到表格，不适合拼标题。待办的标题是一个词，不是两列，所以先拼再送。

```lua run expect="买笔交表" title="先拼成一个字符串"
print("买笔" .. "交表")
```

`..` 的两侧若是数字，Lua 会先把数字转成十进制文字再连接。`"第" .. 1` 得到的是「第1」，不会因为一边是数字就拒绝。这很方便，也容易把人惯坏。你本来想做加法，手滑写成连接，1 和 2 会变成字符串 12，而不是 3。待办的序号若参加运算，用 `+`；若参加标题，用 `..`。两种运算符都沉默地成功，成功的方向相反。看输出里的字，比看运算符是否报错更重要。这一章的序号例子把「第」和数字拼在一起，期望里能看见第1。它不计算 1 加 1。

```lua run expect="第1" title="连接时数字会被写成十进制"
local index = 1
print("第" .. index)
```

注释从 `--` 开始，直到行尾。解释器读到这里就把这一行剩下的字丢掉，所以注释里可以写中文、写临时的条数、写「先别删」，都不会变成输出。它服务的是下一个打开这份源码的人，常常就是两小时后的你。它不服务解释器，因此也不能代替 print。长注释用 `--[[` 配 `]]`。里面不要再写 `]]`，否则会提前结束，后面的代码被当成还在注释外，语法可能直接坏掉。本课的例子坚持用行注释。被注释掉的旧句子不要留在可运行块里充当下一个版本。单块源码没有版本历史，留下的旧 print 会冒充当前意图。

局部变量用 local。print 本身是全局函数，这是语言带进来的，不是你要新建的全局。你自己的标题、条数、表，都写成局部的。下面这一块在两行输出之间夹了一行注释。删掉注释，输出不变。把其中一次 print 注释掉，输出就少一行。对照比口诀清楚。

```lua run expect="交表" title="注释不进入终端"
-- 第二行才是今天要核对的那一件
print("买笔")
print("交表")
```

print 对 nil 和 false 也会给出文字，分别是 nil 和 false，不会因为「没有值」就跳过这一次调用。这和条件判断相反。条件里 nil 和 false 会把分支关掉，打印时它们却是两个看得见的词。周衡若把还没写的标题交给 print，终端上出现的是 nil 这三个字母，而不是一片空白。空白表示你没调用 print，或者调用时给了一个空字符串。三种「没有」在终端上长得不一样：不打印、打印空串、打印 nil。调试时先分清是哪一种，再改表。

多个返回值遇到 print，会变成多个参数，中间同样是制表符。字符串那一章还不会展开 string.gsub，这里先记住原则：一个函数若交出两个结果，直接塞进 print，第二结果不会被丢掉，它会排在制表符后面。你若只想要第一个，就先放进一个 local 名字，再打印那个名字。赋值给一个变量时，多出来的结果被丢掉；交给 print 时，多出来的结果被印出来。同一个语言里，两种「多出来」的处理相反，是因为赋值的位置有个数，print 的参数个数是开放的。

还有一个容易忽略的默认：print 每次都会换行，你不能在同一次调用里改掉这个换行。想把两段接在同一行，要么拼成一个字符串一次打印，要么改用 io.write 自己管换行。io.write 不会在参数之间加制表符，也不会自动换行。它更可控，也更容易让你忘记换行，下一行输出就粘在上一行末尾。这一课的核对多数靠「一行一个事实」，所以继续用 print，把版式交给 `..`。io.write 留到你确实需要不换行的时候，而不是为了少写两个字符。

print 是函数，不是一条可以省略括号的语句。括号里可以是零个参数，那样终端上只有一个换行，看起来像空白行。空白行有时被当成「程序没说话」。它其实说了一个空行。待办脚本若在循环里对每一条都 print，空标题会留下一行空白，条数看起来变多。要避免这种空白，就在打印前看标题是不是空字符串，空的那条不送。这个判断属于控制流，这里先知道 print() 本身合法，并且它的输出不是错误。

分号在 Lua 里可写可不写。语句通常靠换行分开。你把两句 print 用分号写在同一行，输出仍是两行，因为换行来自 print，不来自源码的换行。源码排版和终端版式因此是两套。有人把源码里的空行理解成终端里的空行，核对时对不齐，开始怀疑汉字丢了。空行要出现在终端，必须有一次什么都不传或传空字符串的打印。注释行同样不会渗进输出。

布尔值也会被写成文字。未完成若是 false，print 打出的就是 false 这五个字母，不会翻译成「未完成」。翻译是你的工作：先根据值选一个中文词，再把那个词送出去。把 false 直接送进终端，核对的人还得懂英文单词，待办条本身也变得不像周衡的纸。选词可以写在 print 的参数里，用条件表达式。Lua 的 `and` 和 `or` 会交出操作数本身，不只是交出真假，类型那一章会把这个用在默认标题上。现在若只想印一个字，写成 if 更直白，虽然要多占几行。直白的好处是下一班不会把 `done and "完成" or "未完成"` 读成某种会把空串弄丢的捷径。

string.format 能把序号和标题嵌进同一句，例如第 1 件是买笔。这一章故意先不用它。格式串把版式藏进百分号，读的人要同时懂格式和待办。`..` 的每一步都摊在表达式里，多一个顿号就多一个看得见的字面量。格式串的好处是列对齐、数字宽度，那些留到标准库那一章，等标题、条数和排序真的挤在同一行。过早用格式串，这一章就变成在讲百分号，制表符那条缝反而被盖住。

同一行若既要给人读，又要给程序对，就不要在期望里依赖制表符的显示宽度。宽度随终端字体变化，字符本身不变。核对应当锁定汉字或一段确定的拉丁字母，例如通道那一块的 Ada。Ada 没有第二解释，也不会因为全角空格被看走眼。业务句子再长，也是在这条通道已经通了之后才加上去。通道没通时去改待办的措辞，改的是还没被执行到的那一层。

把通道、制表符和连接放回待办上，可以收成一句操作顺序。先在局部表或局部字符串里把标题准备好，再决定这一行要给人看的到底是一个词还是几列。一个词就 `..`。几列才把多个参数交给 print，并且期望里不要假设那些列被空格隔开。注释解释为什么分成两行，解释器不读这句解释。下一章不再讨论怎样送出，改讨论送出之前那些值算不算真：0 件待办和空标题，都不会像 nil 那样把条件关掉。

## 小结

print 把参数写成文字并换行，参数之间是制表符。Ada 那一块用来确认通道，买笔和交表要连成一个词时先用 `..`。注释和引号留在源码里。nil 被打印成文字 nil，和条件里的「假」不是一回事。一个结果放进 local 再打印，才不会把多余的返回值一起送出去。
