四件待办不会同时做。周衡要先看剩余的笔够不够，再沿纸上的行往下走，遇到涂掉的空标题就绕开，不要把它算进今天的件数。Lua 的控制流没有花括号，也没有靠缩进决定结构。then、do、end 这些词标出范围。缩进只是给人看的。这和把空白当成语法的语言相反：你少缩进一截，程序往往仍能跑，跑出来的层次却和眼睛看到的不一致。代价是排版不能替你守住分支。你必须看见 end 配的是哪一个 then 或 do。短的待办脚本里，一个 if 配一个 end，错配会在解析时失败，或者更糟，end 配错却仍然合法，循环比你想的更早结束。

if 后面是条件，then 和 else 分成两支，elseif 可以再加。上一章已经说明只有 nil 和 false 为假。剩余笔数是 0 时，若写成 `if left then`，会走进「还有」那一支。要表达「一支都不剩」，得写成 `left == 0`。相等比较不是多此一举，是在真值不够用的时候改用一个更窄的问题。窄问题和宽问题可以叠在一起：先问是不是明确的 0，再问是不是其他真值，最后才是假。下面这一块把 0 从「其他真值」里挑出来。

```lua run expect="一支不剩" title="零要写成相等比较"
local left = 0
if left == 0 then
  print("一支不剩")
elseif left then
  print("还有余量")
else
  print("不是数量")
end
```

把 left 改成 5，会印还有余量。改成 nil，会印不是数量。三支回答三种纸面：写了 0、写了正数、这格没写。若省掉第一个分支，0 会掉进 elseif，因为 0 为真，周衡会以为还有笔。省掉的那一行在语法上完全合法，测试若只检查程序能跑，就抓不住。所以这一章的期望写的是「一支不剩」，不是一个含糊的「通过」。

沿清单走，用数值 for。`for i = 1, #items do` 里的 i 从 1 到长度，两端都包含，默认步长是 1。循环变量是循环内部的局部名字，循环结束后外面看不见它，除非你在外面自己又声明了一个同名的。这避免了循环把最后一个下标泄漏出去，让后面的代码误用。你若需要结束后的位置，在循环里把它抄到另一个局部变量。步长可以是负数，从高往低走，用来从清单末尾删，不过删除留到表和标准库。现在步长保持 1，和阅读顺序一致。

```lua run expect="4" title="四行都数到"
local items = { "买笔", "交表", "浇花", "回信" }
local count = 0
for i = 1, #items do
  count = count + 1
end
print(count)
```

i 在循环体里可用，这里没有打印 i，是因为要核对的是件数而不是下标。你可以把 print(items[i]) 放进去，四行标题都会出现。期望若写成买笔，四行里只要有它就通过，后三行错了也可能蒙混。件数 4 更严：少走一圈就对不上。严的期望适合循环，松的子串适合确认某个词确实送出去了。两种都诚实，看你这一块想证明哪一句。

空标题要绕开。Lua 没有 continue。你不能在循环中间说「这一圈到此为止，直接下一圈」。常见的替法有三种。把剩下的逻辑放进 `if title ~= "" then`，空的那圈自然无事可做。这是最清楚的，嵌套一层而已。第二种用一个标志变量，后面的语句都问这个标志，读起来像在模拟 continue，标志一多就会缠。第三种用 goto 跳到循环末尾的标签。goto 能做，但一个四行的待办用跳转，下一班要先在脑子里画箭头。我们选第一种。代价是多一层 end，层次变深时函数那一章再把内层提走。现在四条里有一条空的，留下的应当是 3。

```lua run expect="3" title="空标题不计入"
local items = { "买笔", "", "交表", "浇花" }
local kept = 0
for i = 1, #items do
  local title = items[i]
  if title ~= "" then
    kept = kept + 1
  end
end
print(kept)
```

注意比较的是 `~=` 空字符串，不是 `if title then`。空字符串为真，`if title then` 会把空白也计进去，kept 变成 4，纸上却只有三件能做的事。这正是类型那一章的账单在循环里兑现。条件写得宽，循环每一步都放大这个宽。

while 适合「还不知道会走几圈，只知道离开的条件」。例如从 1 累加，直到达到 3。条件在每一圈开始前检查，所以有可能一圈都不进。把条件写反，循环会停不下来。这一课的例子必须停，停的条件要在有限步之内变成假。待办的条数是有限的，不要写一个等某件永远不会发生的事的 while。数值 for 在你知道两端时更不容易写飞，因为两端写在头上。while 的两端藏在循环体里，藏错就飞。

```lua run expect="3" title="数到三就停"
local n = 0
while n < 3 do
  n = n + 1
end
print(n)
```

repeat until 至少做一圈，再判断 until 后面的条件，条件为真才停。这和 while 的「先判断」相反。适合「至少读一次」的场合，例如最后一章从标准输入读，不过那里用 while 配 nil 更直接，因为第一次就可能是文件结束，一圈都不该假装读到了字。repeat 的一个特别之处是：循环体里声明的局部变量，until 的条件还能看见。数值 for 没有这个需要。你若在 repeat 里 local 了一个标题，until 可以问它是不是空。范围比眼睛看到的 do 稍微大一点，大到条件上。知道这一点，就不会以为 until 里的名字是写错了。

break 离开最内层的循环。找到买笔就可以停，不必把后面的浇花也走完。break 只能写在循环里，不能用来逃离 if，除非 if 在循环内而你想离开的是循环。没有 continue 的时候，不要用 break 冒充「跳过这一条」，那会把后面的条目整个丢掉。跳过用 if 包住，离开才用 break。下面找的是交表，找到就停，打印找到时的下标。清单从 1 数，交表在第二条，所以是 2。

```lua run expect="2" title="找到就离开"
local items = { "买笔", "交表", "浇花" }
local found = 0
for i = 1, #items do
  if items[i] == "交表" then
    found = i
    break
  end
end
print(found)
```

若清单里没有交表，found 保持 0。0 在这里是我们自己选的哨兵，表示没找到。它不是语言的假。打印 0 和打印 nil 不同。用 0 当哨兵的好处是它是一个数，可以和别的下标一起参加运算；坏处是 0 恰好不是合法下标，你若忘记检查就去取 items[0]，得到 nil，然后在 nil 上出错。哨兵要在使用前看一眼。也可以用 nil 当「没找到」，`if found then` 就能挡住，因为 nil 为假。两种哨兵都成立。这一块选 0，是为了让输出稳定成一个数字，而不是空。

and 与 or 可以当很短的条件用，但待办的分支一旦超过「选一个词」，还是 if 更清楚。`title ~= "" and title or "空白"` 这种嵌套能工作，也容易在空串上滑倒，因为空串为真，and 的右边会执行，结果并不是你想的默认值。控制流写长一点，换来每一支都能单独打印、单独核对。短表达式省下的行数，会在你排查「空白怎么变成了别的词」时加倍还回来。

for 的上限在进入循环时取得。循环体内若把 items 变长，这一圈的上限不会跟着变。这是稳定性：你不会因为边走边追加而永远走不完。代价是：你在循环里新增的待办，这次不会被拜访，要等下一次循环。边走边删更危险，删除会让后面的元素前移，下标 i 可能跳过一条。这一章的循环只读不改。要改清单，先收集要删的下标，循环完再删，或者从后往前删。这个纪律等表的长度和洞一起讲更合适，现在先不要在 for 里写 items[i] = nil。

数值 for 的步长可以不是 1。从 1 到 10 每次加 2，拜访的是奇数下标。待办若只想看单数行，这样写比在循环里判断 i 除以 2 的余数更短。短的代价是读的人必须记得第三个数是步长，不是结束位置。三个数的顺序是起点、终点、步长。写反成起点、步长、终点，循环会几乎不走，或者走到一个你没准备条目的下标上，取出来是 nil，再去连接就出错。出错信息指向连接，真正的笔误在 for 那一行。看 for 时先数参数个数。

终点在进入循环时就固定。循环体内把清单变长，新的格子这次不会被走到。这让「边走边追加今天临时想到的事」不会变成死循环，也让临时想到的事要等下一轮才能被同一段逻辑看见。想在同一轮看见，就不要用数值 for 的上限绑住旧长度，改成 while，并在条件里重新取长度。重新取长度必须保证每一圈清单都会变短或有一个独立的计数往上走，否则条件永远为真。临时事项更稳妥的做法是先放进另一张表，主循环结束再合并。合并是一次新的、看得见表的动作。

循环变量和外面的同名局部是两回事。外面若有一个 i 记着「当前处理到第几条」，for 里面的 i 不会改它。循环结束，外面的 i 仍是进入循环前的值。这能防止泄漏，也会让人以为自己在循环里更新了进度。进度要留到外面，就写成另一个名字，在循环体内赋值。不要指望 for 的 i 在 end 之后还能打印。打印一个外面的 nil，得到的文字是 nil，很像进度丢了，其实进度从来没有写到那一格。

elseif 的顺序就是优先级。先写「剩余为 0」，再写「剩余小于 5」，再写其他。写反了，0 会先被「小于 5」抓去，专门为 0 准备的句子永远走不到，语法却完全正确。期望若只检查程序退出码，会放过这件事。把最窄的条件放在前面，是 if 链的纪律。窄和宽没有自动排序，语言不会因为你写了 == 0 就把它提到 < 5 前面。它按文本顺序试，试到第一个为真的就停。

嵌套的 if 要配得上 end。缺一个 end，解析失败，整块不运行。多一个 end，也可能把后面的函数或循环截断。缩进对了、end 错了，眼睛会相信缩进。读控制流时用手指点 then 和 end，不要只看空格。四个空格是给人看的台阶，不是结构。从别的语言粘贴过来的代码，台阶可能是对的，词可能缺了。先补词，再谈待办的条数。

break 只跳出一层。两层循环里，内层找到买笔就 break，外层还会继续。若你以为整张纸都停了，后面的清单仍会打出浇花。要离开两层，可以用一个标志，外层每一圈先看标志；或者把查找写成函数，return 会离开函数里的所有循环。函数那一章的 return 比双层 break 更清楚。在只有一层的例子里，break 足够，不要为了练习跳转去包两层。

条件里调用函数是允许的。函数若会改清单，改动发生在条件判断的时候，然后分支再看见改过的表。这种顺序难读：一行 if 里既有真假又有副作用。把追加留在 then 里面，条件只做查询。查询返回布尔或返回条数，不要返回「顺便写好的表」。一条线只做一件事，失败时你才知道该看判断还是该看写入。

## 小结

if 用 `==` 把剩余 0 从其他真值里挑出来。数值 for 从 1 走到长度，两端包含，循环变量不泄漏到外面。空标题用内层 if 绕开，因为没有 continue；break 只用于找到目标后离开整段循环。while 可能一圈不进，repeat 至少一圈。循环里先不要边走边挖洞。
