周衡的书桌左上角钉着一张纸。纸上是待办，没有第二种容器。要记买笔，他就占一行；要记这件事还没做完，他就在行尾留一个空圈。行与行是次序，圈和字是字段。换一种语言，次序常常交给数组，字段交给对象或结构体，行为再交给类。Lua 不给这三样分别发一张身份证。复合的数据几乎都住在表里。清单是表，一条待办上的标题和完成标记也是表，以后把函数收成模块，模块还是表。这门课就沿着这一张纸往下写：买笔、交表、浇花、回信。名字不换，是为了让你的注意力停在语言机制上，而不是每次先记住一套新的业务。

点某一块代码上的 Run，抽屉拉起的是一次新的 Lua 5.4 进程。这一块源码就是整个脚本。进程退出之后，全局名字、你塞进表里的标题、你在脚本里打开过的临时内容，一起结束。下一块即使还在说周衡，也是文章在沿用同一个人，不是解释器记得上一块。所以每一块都得自己把要用的字写出来。重复看起来笨。换来的是你可以把其中一块单独抄走，它仍然站得住，不依赖一段没有印在纸上的历史。

这个限制是课程的选择，不是 Lua 天生健忘。你自己的电脑上完全可以开一个一直活着的交互会话，先放一张表，下一句再打印它。那种会话适合摸索。它不适合当一篇会被人从中间翻开的文章。文章若悄悄记住上一块的赋值，读者会以为那些名字是语言的一部分。复制出去才发现名字不存在，错误还很像「你写错了」，其实是教程在后台替你存了一份看不见的纸。

宿主这边还有几条具体的边界。不要调用 os.execute，也不要调用 io.popen。这两条路都想借一个外部程序，这个进程没有壳可以借。不要调用 os.tmpname。它想要一个临时名字，这套运行时把那条路堵死了，调用不会给你一个能用的文件名。也不要 require 另一份磁盘上的文件。抽屉一次只交给解释器眼前这一份源码，查找路径里没有第二份待办模块。模块那一章会把函数放进同一份脚本里的一张本地表。做不到的事留在只读块里，免得你点了 Run，终端里却是一堆和买笔无关的失败。

```lua norun title="这几件事不要放进可运行的脚本"
-- os.execute、io.popen、os.tmpname 在这个进程里不要调用。
-- require("todo") 会去找另一份文件，这一课不提供那份文件。
```

只读块没有运行按钮。它旁边的字是边界，不是一段写坏了的程序。能点 Run 的例子都在它的前后。改那些例子的时候，不要把这里的调用补进去碰运气。失败信息会谈论进程或查找路径，不会帮你理解表。

表为什么可以独自承担结构，值得在写第一行之前想清楚。数组擅长连续的整数下标，记录擅长用名字取出字段，类擅长把数据和操作捆在一起再继承。三套语法让意图一眼可见，也逼你在边界上做选择题：这一组待办到底该是数组还是对象？Lua 的回答是先不要选。一张表可以同时拥有从 1 开始的整数键，和任意的其他键。`{ "买笔", "交表" }` 这种写法是序列，第一项用 1 去取，不是用 0。`{ title = "买笔", done = false }` 这种写法是记录，title 和 done 是字符串键。你还可以把记录放进序列，得到一张清单。语言不为这两种写法发明两种类型。问 type，答案都是 table。

好处是一种值可以走完后面所有章节。你不必在数组和对象之间搬家，也不必先学一套类声明才能保存「未完成」。代价是语言不会替你禁止混用。你把一张只有 title 字段的记录交给长度运算符，常常得到 0，因为正整数键 1 根本不存在。你在序列中间挖一个洞，长度也不再是你用眼睛数出来的条数。这两件事都不是现在要展开的计算，但它们是「只有一种结构」的账单：自由的背面是你得自己维持约定。表那一章会把洞摊开，让你看见长度运算符找的是边界，不是一份随时更新的计数。

还有一个相关的取舍：这门课不把待办写进真正会留下来的文件。一次运行内部即使造出一些字节，下一轮点击也看不到。标准输入可以，最后一章用围栏把一行字送进 io.read，那一行只属于那一次进程。这样「记住了什么」全部出现在你眼前的源码或围栏里。隐藏的抽屉会让示例在网页上成功、在外面失败。我们宁可让周衡每次重新把买笔写一遍。

下面三块都是各自的新进程。第一块只证明一条待办能放进表再取出标题。第二块把清单和记录都问一遍类型，让你看见它们没有分家。第三块给这张纸一个主人，条目嵌在里面。三块之间没有名字传递。你若在第三块里直接使用第一块的 item，会得到 nil 上取字段的错误，因为那个 item 没有在这一块里诞生。

```lua run expect="买笔" title="一条待办先放进表"
local item = { title = "买笔" }
print(item.title)
```

```lua run expect="table" title="清单和记录是同一种值"
local list = { "买笔", "交表" }
local record = { title = "浇花", done = false }
print(type(list))
print(type(record))
```

```lua run expect="周衡" title="主人是字段，条目嵌在里面"
local board = { owner = "周衡" }
board[1] = { title = "买笔" }
board[2] = { title = "交表" }
print(board.owner)
print(board[1].title)
```

第一块的输出是买笔这三个字，然后换行。花括号和引号留在源码里，终端上没有它们。第二块打出两行 table。期望只要求出现这个词，两行都是它也不妨碍核对。第三块先打出主人，再打出第一条的标题。期望写的是周衡。买笔多出来，核对仍然通过。这是子串核对的习惯：你先找关键的那个词。顺序如果反了，子串可能还在，所以读示例时要自己看完整的两行，不要把测试的宽容当成版式已经正确。

为什么不从第一天就用元表，把待办装成看起来像对象的东西？因为元表是后来加上的查找规则，不是另一种数据。键不存在时，裸的表给你 nil。setmetatable 可以改掉这个回答，让缺的字段去另一张表里找。若一上来就这么做，默认的「未完成」会把 nil 藏起来，你反而不知道这个值是写在自己身上，还是从别处借来的。元表那一章会专门做 __index，并且只用这一种事件。在那之前，缺字段就让它是 nil，缺了就是缺了。

函数也还不是这一章的主角。函数在 Lua 里是值，可以放进表，那是模块的做法。现在把操作摊在脚本顶上，是为了让表本身露在外面：键是什么，值是什么，能不能再嵌一层。过早收进函数，表就变成看不见的内部细节，你会对着函数名点头，却说不清纸上有几格。等顶层脚本长到你不愿意再抄，函数和闭包那一章再往回收。回收是因为脚本变长，不是因为表不够格。

注释从两个减号开始，直到这一行结束。解释器把它们丢掉，它们不会出现在输出里。需要跨行时用 `--[[` 和 `]]` 包住。长注释能暂时关掉一段，代价是里面若出现 `]]`，注释会提前结束。这一课的例子用行注释就够。注释不能代替打印。你把唯一一次 print 注释掉，进程以成功结束，终端是空的。空终端看起来像「今天没有待办」，其实是结果没被送出来。看的时候先看退出码。是 0 但没有字，就回到你以为会执行的那次打印，而不是先去找异常。

局部名字用 local 引出。不写 local 的赋值会落到全局环境。一份很短的脚本里，全局也能跑通，字也印得出来。麻烦出在两处。拼写差一个字母时，你以为在改原来的名字，其实新建了一个全局，旧的还指着原来的表。函数里忘记 local，里面的名字和外面撞车，调用顺序一变，结果就变。后面的例子一律写 local，包括你打算在循环外面保留的那张表。for 自己会把循环变量限制在循环里，那是控制流里再谈的范围，不影响这里「表要有名字」这件事。

数字这一章几乎不用，只先防一句别的语言带来的习惯。20 除以 6，Lua 的 `/` 得到的是浮点，大约是 3.333，不是截成 3 的整数。整数除法要写 `//`。待办若按人数平分支笔，选错斜杠，库存会对不上。类型那一章会把这两种除法放在同一张纸上对照。这里不跑那个例子，是免得开篇同时介绍表和数字的两套规则。

空的表 `{}` 是合法的值，表示纸还在，上面还没有字。它不是 nil。nil 表示这个名字没有指着任何值，或者这个键不存在。把「没有这张纸」和「纸是空白的」分成两种情况，是为了让后面的条件不要把它们揉成一句「没有」。类型那一章会说明：只有 nil 和 false 会把条件关掉，数字 0 和空字符串不会。空表本身在条件里也算真，因为空表既不是 nil 也不是 false。你若写成 `if board then`，空白的纸也会走进去。想知道上面有没有字，得去看长度或某个字段，不能只看这张表在不在。

序列从 1 开始，这个约定会贯穿清单。周衡数第一件要买的东西，说的是第一件，不是第零件。程序若用 0 去取，得到的是 nil，除非你曾经故意把 0 当成键写入。那种键可以存在，它不属于序列的那一段，长度运算符也不把它算进去。强行用 0 当起点，会让 `#`、ipairs 和你手写的循环各说各话。我们不这么做。代价是从别的语言搬来的循环很容易少看第一条，或者在最后多看一格。少看的那一条常常就是买笔。表那一章会用可核对的输出把这件事钉住。

打印是这一章和下一章的交接。没有 print，表可以在内存里建好，你却无从核对。print 的多个参数之间放的是制表符，不是空格。现在的例子每次只送一个值，就是为了让终端上的字和引号里的字一致。下一章会把制表符变成看得见的说明，并要求先用 `..` 拼成一个字符串再送出去。期望若是「买笔交表」四个字紧挨着，两个参数的 print 会对不上，中间那个看不见的制表符会把词劈开。

这张纸后面会长出哪些机制，可以先有一张路线，免得每一章像换了一门语言。类型负责分清假、零和空串。字符串负责标题的字节和切片。控制流负责沿清单走，并在空标题处跳过。函数和闭包负责把「加一条」关起来，同时记住已经记下的那些。表那一章把 1 和下标里的洞说完。元表只补缺字段。保护调用接住故意制造的失败，例如空标题不该变成一条待办。模块把这些函数收进本地表，而不是 require 出去。标准库只用字符串、数学和表。最后从标准输入读一行，围栏里会放上买笔这两个字。路线是文章的，每一块运行仍是独立的。

选表作为唯一结构，还有一层和错误信息有关的后果。很多语言在你把整数当对象用的时候，会早早拒绝。Lua 往往让运算发生，再在不能做的那一步报错，例如对 nil 做索引。报错的位置离你真正弄混的那一行可能有一点距离。所以示例尽量短，一次只引入一种新的取法。短不是为了少讲，是为了让失败仍然指得回那一行。

## 小结

待办这张纸在 Lua 里就是表。清单、记录和以后的模块都不另起一种结构，下标从 1 开始，缺的键先是 nil。每一次 Run 都是一份新的 Lua 5.4 脚本，要用的标题必须写在这一块里。os.execute、io.popen、os.tmpname 以及加载另一份文件，都不在这门课的可运行范围里。打印出来的字是核对的依据，多个参数之间的制表符留到下一章处理。
