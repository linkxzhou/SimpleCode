数组传进函数之后只剩地址，上一章用 `sizeof` 量过那只剩 4 字节。这一章把地址当成明确的值来用，而不是当成退化的意外。对象还是那五个 `int`：18、21、36、22、19。`&room[2]` 是 36 住的地方。`*` 从地址读回对象。两者配成一对：`&` 取地址，`*` 解引用。声明里的 `*` 则是类型的一部分，`int *p` 表示 `p` 是指向 `int` 的指针。同一个符号两处用法，读的时候先看它在不在类型的位置。

```c run expect="36" title="从地址读回"
#include <stdio.h>
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  int *p = &room[2];
  printf("%d\n", *p);
  return 0;
}
```

`p` 的值是地址，不要用 `%d` 去印地址。地址的宽度和整数相同只是这个目标上的巧合，格式仍然不匹配，`-Wformat` 会失败。要看地址之间的关系，就做减法，再印差值。指针相减的单位是元素，不是字节。`&room[2] - &room[0]` 的结果是 2，表示从第一次到阳光那一次隔了两个 `int`。这比把绝对地址印出来有用：绝对地址每次运行都可能变，期望子串无法稳定。差值可以。

```c run expect="2" title="相隔两个元素"
#include <stdio.h>
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  printf("%d\n", (int)(&room[2] - &room[0]));
  return 0;
}
```

字节数是另一回事。把指针先转成 `char *` 再相减，单位变成字节。`room` 的第二个元素和第一个元素相差 `sizeof(int)` 个字节，在这里是 4。指针加一之所以落到下一次读数，是因为加的步长是指向类型的大小，不是因为内存按「一次测量」自然分格。若 `p` 的类型错写成 `char *`，加一会只挪一个字节，落在 18 的内部字节上，小端机器上你可能仍看见像 18 的低字节，然后就走进未对齐的解释。类型是步长。用 `int *` 遍历 `int` 数组。

按值传递让函数改不到调用者，指针把这个限制打开。`cap_sun` 若发现读数不小于 30，就把它写成 30，表示「记录阳光，但报表用封顶值」。调用者把 `&room[2]` 传进去，36 变成 30，数组里真的变了。这是优点：不必返回新数组。也是风险：函数的名字若没说它会写，调用者会以为 36 还在。我们把名字定成 `cap_sun`，并在参数上使用 `int *`，类型已经告诉你「可能写入」。只读的遍历应当使用 `const int *`，编译器会拒绝通过这个指针写入。能加 `const` 却不加，是把保护让掉。

```c run expect="30" title="通过指针封顶"
#include <stdio.h>
void cap_sun(int *reading) {
  if (*reading >= 30) *reading = 30;
}
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  cap_sun(&room[2]);
  printf("%d\n", room[2]);
  return 0;
}
```

封顶之后报表上的异常点变成 30，原始的 36 没有第二份拷贝。若审计需要原始值，就不要在原地改，改一个副本，或者把原始值返回到别的变量里再封顶。指针写入是共享存储，不是复制。这和按值传递正好相反。选择指针的理由只能是「我要共享或我要修改」，不能是「指针更快所以到处用」。一次 `int` 的按值传递在这个目标上就是复制 4 字节，和传递指针一样宽。用指针去「优化」传递温度，没有收益，只有误写的风险。

空指针表示「这里没有读数」。解引用空指针是未定义行为，在 wasm 上常常直接陷阱，进程不会温柔地印出 0。函数若可能收到空指针，进入 `*reading` 之前要判断。判断失败时返回一个状态，不要继续写。这组示例的地址都来自数组元素，不会是空，所以 `cap_sun` 里没有判断。把「示例的前提」说出来，是为了防止你把 `cap_sun` 抄进解析器，第一个参数就来自可能失败的查找。前提变了，函数就要变。

另一个编译器会直接拒绝的写法是返回局部变量的地址。函数里的 `int temp = 36` 活在栈上，函数返回后那块栈可以给别人用。`return &temp` 把一个即将作废的地址交给调用者。`-Wreturn-stack-address` 在 `-Werror` 下让这段过不了编译。保护是实在的，不要用把地址塞进 `size_t` 再转回来的方式绕过警告。你若需要把 36 交给调用者，按值返回 `int`。你若需要一块调用结束后还在的内存，那是申请内存那一章，生存期由 `malloc` 和 `free` 决定，不由栈帧决定。

指针和数组的声明可以写成让人眼花的形式。`int *p` 和 `int* p` 对编译器相同。一口气声明 `int *a, b` 时，只有 `a` 是指针，`b` 是 `int`。阳光读数的地址若误放进 `b`，类型对不上，编译会失败；若你强迫转换，失败会变成运行期的乱读。一行只声明一个指针。这个习惯不改变生成的代码，只减少一种阅读错误。

不要用整数保存地址再加一。`uintptr_t` 上的加一是加一个字节，和 `int *` 上的加一不同。遍历读数用指针运算或下标。下标 `room[i]` 本来就是 `*(room + i)` 的写法，两者等价。下标更不容易把步长搞错，指针则适合「从当前这次走到下一次」这种滑动。五次读数用下标足够。指针这一章存在，是因为函数参数和「修改调用者」离不开它，不是因为下标不够格。

`const` 放在星号哪一侧，含义不同。`const int *p` 不能通过 `p` 改读数，但 `p` 可以改去指向下一次。`int *const p` 是指针本身不能改指向，指向的 `int` 可以改。封顶函数要改读数，所以不能用第一种。遍历时不改读数，应当用第一种。写反了要么编译失败，要么锁错了东西。失败的那种更好。

两只指针可以同时看这五个数。一只停在开头，一只用循环走到第一个不小于 30 的位置，然后两者相减，得到阳光前面有几次。18 和 21 在前面，差是 2，指向的元素是 36。这个差只在两只指针指向同一块数组时有定义。一只指向 `room`，另一只指向函数里的局部 `int`，相减是未定义行为，即使数值上你减出一个很小的整数。不要用指针差去「探测栈上谁挨着谁」。布局不是契约。契约是数组的范围：从 `room` 到 `room + 5` 这六个位置里，最后一个是末尾之后，可以用来相减和比较，不可以解引用。`room + 5` 减去 `room` 得到 5，这是次数。解引用 `room[5]` 才是越界。末尾指针是范围的写法，不是第六次读数。

比较两只指针谁在前，同样要求它们指向同一块数组。用小于号判断「阳光是否还在当前这次之后」是可以的。用小于号比较来自 `malloc` 的一块和栈上的 `room`，没有定义，结果不能当成「堆在栈的后面」。这个目标上的地址空间布局不是你的数据。温度的次序只存在于下标。

别名是指针打开的另一扇门。`int *a = &room[2]; int *b = &room[2];` 之后，通过 `a` 封顶，`*b` 也变成 30。两个名字，一块存储。优化器必须假定这是可能的，所以不要惊讶「我明明用另一个指针，值却变了」。若你希望副本，就复制 `int`，不要复制指针。复制指针是复制地址。这一点和结构体赋值相反，下一章会让副本真正分开。在那之前，若函数收到两只 `int *`，先问它们是否可能指着同一次读数。封顶函数若同时收到「原始」和「报表」两只指针，调用者把同一个地址传了两次，原始值会跟着报表被改掉。参数名救不了你，类型也一样。调用处不要把同一个 `&room[2]` 传进两个都要写的参数。

指针可以是空，数组名不行。`room` 这个数组对象总是在那儿，退化来的地址可以传给函数，不需要判空。`malloc` 来的指针才需要。把两种来源写成同一个 `int *` 之后，类型系统不再记得来源。注释和命名要补上这个差别，或者用不同的函数接收「必定有效的数组首地址」和「可能失败的申请」。五个读数的数组走第一条路。

解引用的时机要放在判空之后，也要放在范围检查之后。`p` 指向 `room` 的开头时，`*(p + 2)` 是 36，`*(p + 5)` 就越过了最后的 19。指针运算不会因为结果「看起来还在附近」就变成合法。把偏移写成变量时，变量必须先和次数比较。封顶函数只收到一只已经取好的元素地址，范围检查是调用者的事，函数内部再检查不了「这是不是数组里的某一格」，它只能假定调用者给的是一次真实读数的地址。假定要写在函数旁边。调用者若把 `room + 5` 传进来，假定被打破，写入会落到数组外面。调用处的偏移用循环变量，循环条件已经保证小于 5。

取地址运算符只能作用在对象上。`&36` 不合法，字面量没有地址。阳光读数之所以能 `&`，是因为它先住进了 `room[2]` 这个对象。先有对象，再谈指针。把常量地址化的企图，说明你其实想要的是值，值直接传递即可。36 这个字面量没有存储，谈不上被阳光「打到某一格」；只有 `room` 的那一格才有地址，封顶也才有地方可写。若函数需要同时看见原值和封顶后的值，就先把 `*p` 抄进一个 `int`，再写回上限。抄走的是数值 36，不是地址。之后原指针上的对象可以变成 30，局部的 `int` 仍留着 36，供你打印对照。少了这一份局部副本，封顶就是覆盖，覆盖之后源码里再也变不出被晒到的那一次。副本要在写入之前拿走。顺序反了，拿走的就是 30，对照也就失去了意义。

## 小结

`&room[2]` 指向 36，`*p` 把它读回来。指针相减得到元素个数 2，不是字节。步长由指向的类型决定，所以遍历 `int` 要用 `int *`。`cap_sun` 通过指针把 36 改成 30，调用者的数组跟着变；按值传递做不到，也不该为了这点修改去把所有 `int` 都换成指针。

返回局部变量的地址会被 `-Werror` 拒绝。需要活过函数的存储时，按值返回，或等到堆上申请。下一章把温度和单位放进同一个结构体，复制时按成员复制，避免平行数组错位。

## 练习

用指针相减打印 19 所在下标和 36 所在下标的差。19 在下标 4，36 在下标 2，差是 2。用减法，不要写常量 2。

::: answer 参考答案：末次减阳光
```c run expect="2" title="参考答案"
#include <stdio.h>
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  printf("%d\n", (int)(&room[4] - &room[2]));
  return 0;
}
```
:::

写一个函数，通过指针把读数加上 1，但只对严格小于 30 的值这样做。对 22 调用后应当打印 23。对阳光读数不应当在这道题里加，因为规则是只调整未越线的探头，避免把 36 变成 37 之后更难和阈值对照。

::: answer 参考答案：只加凉的
```c run expect="23" title="参考答案"
#include <stdio.h>
void bump_cool(int *reading) {
  if (*reading < 30) *reading = *reading + 1;
}
int main(void) {
  int after = 22;
  bump_cool(&after);
  printf("%d\n", after);
  return 0;
}
```
