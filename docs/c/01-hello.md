上一章把下午的和印成了 116，也单独看过阳光打在探头上的 36。这一章仍然不引入新的传感器，只追问 `printf` 凭什么知道该把参数当成整数还是当成文字。这个问题比「怎么输出」更值得先想清楚，因为 C 在调用点不携带参数类型。

`printf` 是可变参数函数。调用约定里，整数和指针按某种宽度传递，浮点会做默认提升，被调用的函数看不到「这是 `int` 还是 `char *`」这种标签。它只能相信格式串。格式串是一份小小的程序：`%d` 表示再取一个 `int`，`%s` 表示再取一个指向字符的指针，`%%` 表示百分号本身，并不消耗参数。编译器若看得见一份字符串字面量，就会替你把这份小程序和后面的实参对一遍。这个抽屉打开了 `-Werror`，对不上就停在编译，链接和运行都不会开始。

这是一种不对称的设计，值得把取舍说透。格式串做成运行时数据，是为了让同一套打印函数能服务日志、协议和人读的句子，也是历史：C 没有后来的泛型，不可能为每种组合写一个不同名的函数。代价是类型检查变成了「尽力而为」。格式串一旦不是字面量，而是你拼出来的缓冲区，编译器就不再检查，错误会变成按错误宽度去读参数区。在别的目标上，那可能是一串垃圾整数，甚至是崩溃。这里因为教学示例一律用字面量，你看到的是诊断而不是垃圾。请把这个运气当成约束：不要把探头送来的字节直接放进 `printf` 的第一个参数。探头的内容是数据，格式串是代码。数据进 `%s` 或 `%d` 的位置。

先印阳光读数。格式只有一个 `%d`，参数只有一个 `int`。换行写在格式串里，因为运行时不会替你补行尾。

```c run expect="36" title="一个整数"
#include <stdio.h>
int main(void) {
  int sun = 36;
  printf("%d\n", sun);
  return 0;
}
```

`sun` 这个名字从上一章留了下来，数值仍是 36。若把格式改成 `%s`，诊断会说格式要的是 `char *`，实参却是 `int`。反过来，把 `"摄氏"` 交给 `%d`，诊断会说要的是 `int`，实参却是指针。两种错都不会走进 `printf` 的函数体。这比运行后对着乱码猜要便宜得多。也别指望用强制转换糊过去：把整数转成指针再按字符串去读，是未定义行为，不是打印方法。

第二次把单位和数字放在同一次调用里。两个转换说明，两个参数，次序跟格式串里出现的次序一致，不是跟你心里「先说单位还是先说数字」的语序商量的结果。

```c run expect="36C" title="数字和单位"
#include <stdio.h>
int main(void) {
  int sun = 36;
  printf("%d%s\n", sun, "C");
  return 0;
}
```

这里的 `"C"` 是字符串，长度包括结尾的空字符，但 `%s` 会在空字符处停下，所以输出是 `36C` 而不是带着看不见的结尾。若单位想用汉字「摄氏」，同样用 `%s`，不要把汉字塞进 `%d`。汉字在源码里是 UTF-8 字节，`%s` 会把那些字节原样写到标准输出，终端再按 UTF-8 显示。`printf` 本身不算「几个汉字」，它只搬字节。字数是类型章里 `strlen` 要揭穿的事，这里先不要用长度来排版。

多一个参数会失败。`printf("%d\n", sun, 21)` 这种写法，21 没有任何转换说明消费它。诊断的名字是格式串没用到的数据参数。少一个也会失败：`printf("%d %d\n", sun)` 有两个转换说明，实参只够第一个。这两种都不是「多印一个空格」的小问题。可变参数函数不会在运行时告诉你参数个数，于是编译器在还数得清的时候就把门关上了。你若真的想忽略一个值，就不要把它放进调用。想印两个读数，就写两个说明。

第三次把坑放进可运行的输出里。18 是下午最早的一次，36 仍是阳光那一次。两个 `printf` 都用对了 `%d`，类型上无懈可击，可是第一个格式串没有换行，也没有空格。

```c run expect="1836" title="粘在一起"
#include <stdio.h>
int main(void) {
  int early = 18;
  int sun = 36;
  printf("%d", early);
  printf("%d\n", sun);
  return 0;
}
```

终端里的 `1836` 像一次真实的读数，甚至像把摄氏误写成了某种十分之一度。它不是。它是 18 和 36 的十进制字形靠在一起。这比类型错误更危险：编译通过，退出码是 0，期望如果只写成很短的 `"18"` 也会碰巧命中，因为 `"1836"` 里含有子串 `18`。所以看输出时要看完整的一行，而不是只看自己希望出现的那几位。把第一次调用改成 `"%d\n"` 或 `"%d "`，粘连才会解开。点工具栏的 Run 才能保住这个修改；再点代码块会把示例盖回来。

百分号本身也容易踩。若你想写「36%」表示某种相对刻度，格式串里要写 `%%`，它不消耗参数。写成单个 `%` 再直接跟别的字符，可能变成一个非法或不完整的转换说明，诊断同样会响。下面这个例子只印百分号，好让 `36%` 这个字形是刻意的，而不是粘连。

```c run expect="36%" title="百分号"
#include <stdio.h>
int main(void) {
  int sun = 36;
  printf("%d%%\n", sun);
  return 0;
}
```

```c norun title="这些调用不会进入运行"
#include <stdio.h>
int main(void) {
  int sun = 36;
  /* printf("%s\n", sun);          类型对不上 */
  /* printf("%d\n", sun, 21);      多出来的 21 */
  /* printf("%d %d\n", sun);       第二个说明没有参数 */
  /* printf(label);                不要让数据充当格式串 */
  (void)sun;
  return 0;
}
```

只读块里那四行保持在注释中，是为了让你看见长相，又不会有人把整块误标成可运行之后立刻编译失败。`(void)sun` 把这个局部变量用了一次，免得你在自己打开 `-Wall` 的环境里复制这一块时先被未使用变量拦住，从而看不见我们真正想讨论的格式问题。

还有一个取舍：要不要用一次 `printf` 印出全部五个数。可以，`"%d %d %d %d %d\n"` 配上 18、21、36、22、19，转换说明的个数必须是五，一个不能多。这样写的好处是一行里次序固定，不会出现上面的粘连。坏处是格式串变长之后，人眼数百分号很容易数错，而数错会直接编译失败。失败是好事，但调试体验是你对着一长串 `%d` 找哪一个多了。五个数以内，一次列完可以接受。再长，就改成循环，每个元素一次 `printf("%d\n", ...)`。循环是控制流那一章的事，格式规则现在已经够用：每一次调用，说明的个数等于参数的个数，说明的类型等于参数的类型。

`printf` 的返回值是写出的字符数，出错时返回负值。这一章的例子不检查它。原因是我们印的是字面量，标准输出又是抽屉的终端，失败几乎不会以「写了半截整数」的形式出现。等格式串变复杂、或者目标变成文件，返回值才值得成为分支条件。现在检查它会多出一个很少为真的分支，把注意力从类型匹配上拉开。知道它存在即可，不要在每个教学例子里写成仪式。

中文说明可以和数字交替出现，只要 `%s` 对字符串、`%d` 对 `int`。不要用 `%c` 去印汉字。`%c` 只写一个字节。汉字的 UTF-8 至少三个字节，只写第一个字节会得到一个残缺的编码，终端可能显示替换字符，也可能把后两个字节留到下一次输出里制造更乱的字形。单位若是单个英文字母 `C`，`%c` 配一个 `char` 是合适的；单位若是「摄氏」，用 `%s`。选择转换说明就是在选择宽度，不是在选择「看起来像不像字」。

最后把这一章和编译阶段的关系再说紧一点。格式诊断发生在编译，所以你修的是源码，不是修终端里的 1836。1836 那种错诊断不了，因为它类型正确，只是人把两行读成了一行。类型系统能拦住的，抽屉会拦住；类型系统不表达的排版，要靠你自己把换行写进格式串，并在看结果时读完整行。

字段宽度是另一种容易和数值缠在一起的格式。`%4d` 在不足四位时于左侧补空格，五次读数可以排成一眼能扫的一列。18 和 36 都占四格，个位对齐。这对人读日志是好处。对这个抽屉是负担：期望子串若写成从行首数起的固定字形，补上的空格会让匹配失败；若只写 `36`，又会在补了空格时仍然命中，你分不清自己有没有对齐。教学块因此坚持裸的 `%d`，终端里的字符就是数值。你以后要给人看表格时再加宽度，并且把期望改成含空格的完整一行。宽度是排版，不是精度，它不会把 23 修约成 23.2。

`char` 传进 `printf` 时会先提升为 `int`。`%c` 再取低位的一个字节，所以单位字母可以这样印。提升不会把整数变成指针，也不会把 36 变成字符串。把温度当成 `%s` 仍然是类型错误。默认提升解释的是「为什么 `%c` 的参数看起来像整数仍能通过检查」，不是一张可以随便换转换说明的许可证。

标准输出带缓冲。终端设备上，许多实现遇到换行才把缓冲交出去。只调用 `printf("%d", 36)` 时，在进程结束前你可能暂时看不见数字。这个抽屉在进程结束时会冲洗，所以粘连的 1836 仍然出现。长循环里若你每秒读一次探头却不换行也不 `fflush(stdout)`，旁观者会以为程序停住了，数字其实堆在缓冲里。五个数不需要 `fflush`。一旦输出要给人盯着看，换行是最省事的冲洗点，`fflush` 是你不想换行时的出口。它返回非零才表示写出失败，五个字面量的例子里这个失败几乎不会发生，所以不把检查写成每章的仪式。

格式串里的标志，例如左对齐的 `-`、补零的 `0`，同样只影响字形。`%02d` 会把 8 印成 `08`，把 36 印成 `36`。前导零让个位数和两位数一样宽，也让后来的解析多一种合法写法。`scanf` 的 `%d` 能读回 `08`，数值仍是 8。若有人用字符串比较判断冷热，`"08"` 和 `"8"` 不相等，阈值逻辑会裂开。数值比较要发生在整数上，补零只放在给人看的最后一步。这一章的块连补零都不做，就是为了让 18 不要变成别的字形。

## 小结

`printf` 不知道参数的类型，它按格式串去取。格式串是字面量时，这个抽屉会在编译期核对个数和类型，多一个、少一个、`%d` 配字符串，都到不了运行。格式串不要用外部数据来充当，数据放在对应的转换说明后面。

换行不会自动出现。18 和 36 会粘成 1836，看起来像另一次测量。百分号要写成 `%%`。下一章离开格式，去看 116 除以 5 为什么不是 23.2，以及「你好」这种两个汉字为什么占 6 个字节。读数仍是 18、21、36、22、19。

## 练习

把最早的 18 和最晚的 19 印在两行上。两行都用 `%d`，每一行自己带换行。不要印成 `1819`。期望能同时看到分行之后的两个数。

::: answer 参考答案：早晚两行
```c run expect="18\n19" title="参考答案"
#include <stdio.h>
int main(void) {
  printf("%d\n", 18);
  printf("%d\n", 19);
  return 0;
}
```
:::

用一次调用印出阳光读数和它后面的 22，中间用空格分开。转换说明必须是两个，参数必须是两个 `int`。这道题拒绝用两次 `printf` 把空格藏进第二段格式串的开头，为的是让你数清楚同一次调用里的说明。

::: answer 参考答案：阳光和随后
```c run expect="36 22" title="参考答案"
#include <stdio.h>
int main(void) {
  int sun = 36;
  int after = 22;
  printf("%d %d\n", sun, after);
  return 0;
}
```
:::
