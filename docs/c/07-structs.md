36 如果没有单位，可以是摄氏，也可以是华氏。华氏 36 是严寒，摄氏 36 在这组数据里是探头被晒到。前面各章默认摄氏，是因为散文一直这么说。源码本身没有证据。把单位放进另一个平行数组，排序或交换时会和数值拆开。结构体让一次测量成为一个值：数值在 `temp`，单位在 `unit`。交换、赋值、传参，默认一起走。

```c run expect="36C" title="一次测量"
#include <stdio.h>
struct Reading {
  int temp;
  char unit;
};
int main(void) {
  struct Reading sun;
  sun.temp = 36;
  sun.unit = 'C';
  printf("%d%c\n", sun.temp, sun.unit);
  return 0;
}
```

`struct Reading` 是类型，`sun` 是对象。成员用点号。`unit` 用 `char` 放一个字母，是因为我们约定只写 `C` 或 `F`，一个字节够用。若单位是汉字「摄氏」，`char` 装不下，那是 6 个内容字节加结尾，应当换成字符数组，并且记得数组成员不能当字符串字面量整体赋值，初始化时要用列表或复制函数。这一章把单位收成一个字母，好让注意力留在「两个字段一起走」，而不是再走一遍字节数。字母用 `%c`，不要用 `%s`，`%s` 会把 `char` 提升后的值当成指针。

五个下午可以是结构体的数组。下标 2 仍是阳光那一次。循环的规则还是 `temp >= 30`，同时检查 `unit == 'C'`。只检查数值会把华氏 36 算成越线。这组例子里五次都是 `C`，检查看起来多余，可是字段既然存在，规则就该读它。否则你只是把单位当注释，结构体没有发挥作用。

```c run expect="1" title="只认摄氏越线"
#include <stdio.h>
struct Reading {
  int temp;
  char unit;
};
int main(void) {
  struct Reading room[5] = {
    {18, 'C'}, {21, 'C'}, {36, 'C'}, {22, 'C'}, {19, 'C'}
  };
  int i;
  int hot = 0;
  for (i = 0; i < 5; i = i + 1) {
    if (room[i].unit == 'C' && room[i].temp >= 30) hot = hot + 1;
  }
  printf("%d\n", hot);
  return 0;
}
```

初始化用嵌套花括号，次序跟成员声明一致：先 `temp`，后 `unit`。写反 `{ 'C', 36 }` 会做转换，字符变成很小的整数温度，36 被塞进 `char`，截断之后单位变成一个碰巧的字节。编译未必失败，因为转换是允许的。这是结构体初始化最安静的坑。防范不是背诵，是打开你依赖的成员名字。C99 允许指定成员的初始化，`.temp = 36, .unit = 'C'`，次序就可以打乱。指定初始化比位置初始化长，换来的是调换两行不会把单位当成温度。示例为了短用了位置，你在自己的日志格式稳定之前，更值得用指定成员。

赋值会复制整个值。`struct Reading copy = sun;` 之后改 `copy.temp`，`sun.temp` 仍是 36。这和指针不同。指针是共享，结构体变量是各自的成员。复制的代价是字节数：下面会看到这个结构体在 wasm32 上是 8 字节，不是 4 加 1。五个元素的数组是 40 字节。按值把结构体传进函数，就是复制这 8 字节。读数很少时，复制让函数无法悄悄改掉调用者的日志，值得。若结构体以后长到含有大缓冲区，复制会变贵，那时再传 `const struct Reading *`。不要在它还只有两个小字段时就全改成指针。指针版本必须处理空指针，调用写起来也更吵。

```c run expect="36" title="副本改不到原件"
#include <stdio.h>
struct Reading {
  int temp;
  char unit;
};
int main(void) {
  struct Reading sun;
  struct Reading copy;
  sun.temp = 36;
  sun.unit = 'C';
  copy = sun;
  copy.temp = 18;
  printf("%d\n", sun.temp);
  return 0;
}
```

8 字节从哪来。`int` 对齐到 4，`char` 放在偏移 4，结构体的对齐取成员的最严对齐，总大小要补到对齐的倍数，于是尾部补 3 个字节，`sizeof` 是 8。`char` 放在 `int` 前面时，中间还要补 3 个字节才能让 `int` 对齐，大小仍是 8。调整成员顺序在这个例子里省不下空间。在别的组合里，把大的成员放前面常常能减少空洞。不要用 `sizeof` 等于字段相加来分配网络报文。空洞里的字节内容是未指定的，按值复制会把空洞也复制走，拿去和另一份「相同测量」做内存比较会失败。比较测量用成员：温度相等并且单位相等。不要 `memcmp` 整个结构体。

```c run expect="8" title="对齐之后的尺寸"
#include <stdio.h>
struct Reading {
  int temp;
  char unit;
};
int main(void) {
  printf("%d\n", (int)sizeof(struct Reading));
  return 0;
}
```

这个 8 是 wasm32 上 clang 的布局。别的 ABI 可能为了紧凑而排成 5，或者仍是 8。写文件时若把结构体原样写出去，读回来的程序必须用同一布局。教学抽屉里的文件活不过这次进程，更不要把布局当成文件格式。要交换日志，就逐个成员写成文本，例如 `36 C`。文本多占空间，却不依赖空洞和字节序。五个小整数的下午，文本是更合适的格式。二进制布局留给真的带宽问题。

指向结构体的指针用 `->`。`p->temp` 就是 `(*p).temp`。括号不能省，因为点号的优先级高于解引用，`*p.temp` 会被读成 `*(p.temp)`，而 `p` 不是结构体，编译失败。失败比读错成员好。函数若要修改调用者的测量，接收 `struct Reading *`，通过 `->` 改 `temp`。只是查询就按值传，或者传 `const struct Reading *`。`const` 放在结构体上，两个成员都不可通过这个指针修改。

结构体没有方法。行为仍是普通函数，第一个参数是这件测量。不要把函数指针塞进结构体来模仿方法表，五个读数不需要。那样做会让每一件测量都带上代码地址，复制时复制的是地址，共享的是函数，调试更绕。越线判断继续做普通函数，读 `reading->temp` 和 `reading->unit`。数据和行为分开，是这门语言的默认，不是少写了关键字。

未初始化的结构体成员不是 0，除非你用 `= {0}` 或明确赋值。局部的 `struct Reading sun;` 之后立刻读 `sun.temp`，读到的是垃圾，可能碰巧像 36。声明时就给成员，或者整个置零再填。置零会把空洞也清掉，对比较没有帮助，对「先当 0 度」有帮助。0 度仍是合法温度，置零表示「还没测量」并不准确。更准确的是另加一个 `int valid` 字段。字段一旦加进去，尺寸和对齐会再变，所有按二进制写出去的假设都会失效。这又一次说明该用文本。

按值返回结构体是合法的，而且适合这件只有两个小字段的测量。函数构造一次 `{36, 'C'}` 交回去，调用者得到副本，函数里的局部对象随后消失，没有人握着悬空地址。这比返回 `struct Reading *` 指向局部变量安全，后者会被返回栈地址的警告拦住。按值返回的代价就是那 8 字节的复制，五个整数的下午付得起。不要为了避免复制而把结果写进全局的 `struct Reading current`。全局会把上一次的单位留到下一次，你忘记赋值 `unit` 时，新的 22 可能仍带着旧的 `F`。局部返回值没有这种残留。

指定成员初始化值得在你离开短示例之后立刻用上。`.temp = 36, .unit = 'C'` 把字段名字写在初始化旁边，调换两行不会把字母塞进温度。位置初始化 `{36, 'C'}` 短，依赖声明次序。声明若在重构时把 `unit` 挪到前面，所有位置初始化都沉默地错位，编译仍通过，因为 `char` 和 `int` 可以互相转换。转换是这个坑能活下来的原因。能编译不表示布局还表达下午。指定成员让多余的字段显式留下，缺了的字段则被零初始化。零初始化的 `unit` 是字节 0，不是字母 `C`。用 `%c` 去印会什么都看不见，用比较 `== 'C'` 会失败，于是越线次数变成 0。你以为阈值坏了，其实是新字段没填。声明初始化之后，把每个会参加比较的成员都写出来。

结构体可以嵌套，例如外面再包一个序号表示第几次采样。嵌套之后赋值仍是整值复制，外层赋值会把内层的温度和单位一起抄走。这是好事。不要拆开逐字段抄，抄的时候容易忘了新加的序号，两件测量看起来温度相同、次序却都是 0。整值赋值的缺点是你无法只共享其中一个成员。需要共享时，再取那个成员的地址，而不是取整个结构体的地址去假装只共享温度。取整个结构体的地址再按 `int *` 去读，依赖 `temp` 是第一个成员、偏移为零。今天这是真的，明天在前面插入 `unit` 就不是。用 `&reading.temp`，让编译器算偏移。

数组套结构体时，`sizeof room / sizeof room[0]` 得到的是测量的次数，不是字节。`room[0]` 的大小是 8，五个是 40。用 40 去除以 `sizeof(int)` 会得到 10，循环会走到结构体的空洞和下一件测量的中间。越界的样子可能是读到单位字节，数值很小，于是最大值仍是 36，错误被最大值的稳定性盖住。次数必须用元素的 `sizeof` 去除，元素是 `struct Reading`，不是 `int`。

成员的类型选择会反过来约束格式。`temp` 用 `int`，`%d` 才能配上。`unit` 用 `char`，`%c` 才能配上。若图省事把单位也塞进 `int`，用 67 这种字符码保存字母 `C`，打印时必须记得换 `%c`，否则终端里是 67，像另一次温度。67 和 36 都是两位数上下的整数，并排时非常像两次读数。格式和字段类型绑在一起，不要让单位看起来像第三支探头。比较单位时用 `'C'` 字符常量，不要用它的码点数字，读代码的人不必去查 67 是什么。

结构体标签 `Reading` 和变量名不要都叫 `reading` 到分不清。标签是类型，变量是某一次测量。函数参数用 `reading`，类型用 `struct Reading`。读声明时先看到 `struct` 关键字，就不会把类型当成一次具体的 36。类型描述的是形状，变量才装那一次被晒到的读数。两者同名时，搜索和口头讨论都会把「改类型」说成「改掉 36」。命名分开之后，改对齐、加字段，影响的是所有测量的形状；改 `sun.temp`，影响的只是阳光那一次。这个区别在五个元素的数组上尤其要紧：你很少想改类型，却经常想改其中一格。改一格用下标加成员，不要重新声明一个同名类型把文件里的测量全部遮住。

## 小结

一次测量同时带着 `temp` 和 `unit`，36 和 `C` 一起打印，一起赋值。副本上的修改到不了原件。越线规则要同时看单位，避免华氏的数被当成摄氏。

布局有空洞，`sizeof(struct Reading)` 在这份 wasm32 上是 8，不是 5。不要按内存比较结构体，也不要把内存映像当日志格式。下一章从标准输入读入一次读数，地址运算符会再次出现，因为 `scanf` 要的是写入的位置，并且必须检查它是否真的写入了。

## 练习

做一次副本，把副本的单位改成 `F`，打印原件的单位。原件应当仍是 `C`。用 `%c`。

::: answer 参考答案：单位留在原件
```c run expect="C" title="参考答案"
#include <stdio.h>
struct Reading {
  int temp;
  char unit;
};
int main(void) {
  struct Reading sun;
  struct Reading copy;
  sun.temp = 36;
  sun.unit = 'C';
  copy = sun;
  copy.unit = 'F';
  printf("%c\n", sun.unit);
  return 0;
}
```
:::

在五次都是摄氏的数组里，找出温度的最大值并连同单位打印。应当看到 `36C`。比较只在单位同为 `C` 时更新最大值，这样函数形状已经为混入华氏留了位置。

::: answer 参考答案：摄氏里的最大
```c run expect="36C" title="参考答案"
#include <stdio.h>
struct Reading {
  int temp;
  char unit;
};
int main(void) {
  struct Reading room[5] = {
    {18, 'C'}, {21, 'C'}, {36, 'C'}, {22, 'C'}, {19, 'C'}
  };
  int i;
  int max = room[0].temp;
  for (i = 1; i < 5; i = i + 1) {
    if (room[i].unit == 'C' && room[i].temp > max) max = room[i].temp;
  }
  printf("%d%c\n", max, 'C');
  return 0;
}
```
:::
