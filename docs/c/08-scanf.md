结构体把 36 和单位写在了源码里。真的探头不会写在源码里，它会把数字送到标准输入。这个抽屉里，标准输入来自代码块信息上的 `stdin`，例如 `stdin="36\n"`。测试或运行开始后，这些字符被推进去，然后默认再送出 EOF。EOF 不是你在字符串里写的四个字母，是输入结束的信号。循环若一直读到转换失败或结束，就会停，而不是永远等下一次按键。你在自己的终端里跑同一份程序时，没有围栏替你收尾，需要自己结束输入。两边的差异在「谁发送 EOF」，不在 `scanf` 的规则。

`scanf` 的格式串和 `printf` 同源，却方向相反。`%d` 表示解析一个整数，写进你提供的 `int`。它必须知道写到哪里，所以参数是 `int *`，调用处写 `&n`。把 `n` 按值传进去，等于把整数 0 当成地址。那不是「没写上取地址所以写进了变量」，是把一个整数解释成了指针。在这个 wasm 上，那通常会陷阱，进程没有正常的温度输出。即便某个平台碰巧不陷阱，写入的位置也不是 `n`。取地址不是仪式，是把存储位置交出去。

返回值是成功转换的项数。读一个整数时期望 1。返回 0 表示手里的字符对不上格式，返回 `EOF` 表示在任何转换之前就结束了。这两种情况下，`n` 里可能仍是你当初设的 0，也可能是上一次循环留下的 36。哪一种都不是「这次输入」。失败之后禁止把 `n` 交出去当读数。先把它初始化成 0，只为了让未初始化垃圾不混进来；0 不是失败的标志，失败的标志是返回值。

```c run stdin="36\n" expect="36" title="核对一项"
#include <stdio.h>
int main(void) {
  int reading = 0;
  if (scanf("%d", &reading) != 1) {
    printf("%s\n", "失败");
    return 0;
  }
  printf("%d\n", reading);
  return 0;
}
```

围栏给的是 `36` 和一个换行。`%d` 会跳过前导空白，所以换行放在数字前面也能读到。成功时打印 36，和源码里的阳光读数相同，但这次 36 来自输入。若把 `stdin` 改成 `sun\n`，转换失败，应当走「失败」那条路，而不是打印当初的 0。打印 0 会让人以为探头测到了冰点。分支要印一个不可能被误认成摄氏的词。这里用「失败」。

第二次读入整个下午。五个整数用空白分开，循环条件就是 `scanf` 返回 1。返回值不是 1 时离开循环，无论那是格式错误还是 EOF。围栏在最后一个换行之后还会送 EOF，所以循环结束，不会停在等待。若默认不送 EOF，而输入里又没有别的结束标记，`scanf` 会继续阻塞，抽屉最后以超时失败。超时看起来像程序写错了循环条件，其实是输入没有尽头。知道 EOF 会来，才能把「读到结束」写成合法的教学例子。

```c run stdin="18\n21\n36\n22\n19\n" expect="116" title="加到结束"
#include <stdio.h>
int main(void) {
  int reading = 0;
  int sum = 0;
  while (scanf("%d", &reading) == 1) {
    sum = sum + reading;
  }
  printf("%d\n", sum);
  return 0;
}
```

和仍是 116。循环里不要在 `scanf` 之后无条件使用 `reading`。正确的形状是：调用、检查、再使用。写成先使用再检查，会把上一次的 36 再加一次，和变成 152，或者在第一次失败时把初始 0 加进去。多出来的 0 不改变和，于是错误被这组数据掩盖。用一组以非数字结尾的输入才能看见，例如在末尾加一个字母。教学例子的输入是干净的五个数，掩盖仍然存在于结构里。结构要写成「失败就不使用」，即使当前输入不会失败。

空输入是第三种情况。围栏可以写成空字符串，运行时仍然送出 EOF。`scanf` 立刻返回 `EOF`，不等于 1，循环体不执行，`sum` 保持 0。打印 0。这个 0 是「没有读数」，不是冰点。没有次数，就不能做上一章那种除法。若在循环后写 `sum / count` 而 `count` 仍是 0，行为未定义。所以次数也要数，平均只在次数非零时去做。下面把次数印出来，空与不空都能看懂：干净的五个数应当是次数 5。

```c run stdin="18 21 36 22 19\n" expect="5" title="数成功的次数"
#include <stdio.h>
int main(void) {
  int reading = 0;
  int count = 0;
  while (scanf("%d", &reading) == 1) {
    count = count + 1;
  }
  printf("%d\n", count);
  return 0;
}
```

同一行用空格分开和用换行分开，对 `%d` 是一样的，因为两种都是空白。不要在格式串里写死「必须是换行」。写成 `"%d\n"` 看起来只是多要求一个换行，实际上下一个 `%d` 本来就会跳过空白，而格式串里的空白会匹配任意一段空白，行为比你想的更贪。人读的说明文字更不要写进 `scanf` 的格式串。你写 `"温度 %d"`，输入就必须先出现那两个汉字。探头不会发汉字。提示语用 `printf` 印到标准输出，解析只保留 `%d`。

`scanf` 不适合读一行里可能残缺的记录，因为它会停在第一个对不上的字符，错误字符留在缓冲区里，下一次调用又看见它，于是永远转换失败，变成死循环。五个纯整数不会触发。一旦输入可能是 `36C` 这种带单位的片段，`%d` 读走 36，留下 `C`。若循环没有别的进展，就会卡死。处理带单位的行，应当一次读入一行再解析。那是文件和行计数章的工具。这里坚持「输入是整数」，并在失败时退出循环，这样留下的脏字符最多导致提前结束，而不是转圈。提前结束会少加后面的数，和不再是 116。你能看见总数变小。转圈则什么都没有。

返回值不要和读到的温度比。`scanf(...) == 36` 问的是「是不是成功转换了 36 项」，不是「温度是不是 36」。一项转换成功时返回值是 1。温度在 `reading` 里。把这两件事写成一次比较，36 度会看起来像失败，失败的返回值 `EOF` 又是负数，更不可能等于 36。

缓冲区溢出这一类问题，`%d` 写一个 `int` 不会把任意长的字符串塞进小数组，它只是可能溢出整数范围。超过 `int` 能表示的数字，行为对 `scanf` 来说是未定义的，或在实现里变成一个失败。五个小温度远离边界。不要用这个函数去读不受信任的超长令牌到 `char` 数组里，除非给出宽度上限。这一章没有 `char` 数组参数，就是为了先把地址和返回值学干净。

`main` 里失败时我们 `return 0`，并且打印了「失败」。也可以 `return 1` 表示进程不成功。取舍是：抽屉的期望常常只看标准输出的子串，退出码非零会被当成运行失败，示例就红了。教学块若想展示失败分支的输出，就在打印之后返回 0，让「失败」这个词成为正常完成的结果。真正的告警程序应当返回非零，让外壳脚本停下来。你离开抽屉之后把 `return 0` 改成 `return 1`。不要在还要展示失败文案的例子里先返回非零，否则你看不见文案是否写对，先看见的是红色的退出码。

前导空白和残留字符要分开想。`%d` 会跳过空格、制表和换行，所以围栏用一行一个数或者一行五个数，循环的形状可以相同。它不会跳过字母。输入若是 `36C`，转换成功读走 36，`C` 留在缓冲区。下一次 `%d` 看见 `C`，立即返回 0。若循环写成「失败就重试」而不把 `C` 读走，就会转圈，直到抽屉超时。超时的诊断不会说「单位没被消费」。消费掉残留的办法是失败时停止，或者改用按行读取。这一章选择停止，因为契约是「输入只有整数」。契约破了就结束，而不是在破损的缓冲里挣扎。

宽度限制对 `%d` 仍然存在，只是不表现为缓冲区溢出，而表现为「最多读这么多位」。一般的温度用不到。真正危险的是把 `%s` 写进 `scanf` 去读一行标签。没有宽度的 `%s` 会一直写到空白为止，你提供的数组不管多短都会被写穿。标签若是「你好」，内容 6 字节，数组至少要 7，而且格式里要写上宽度，宽度要比数组长度少 1 以容纳结尾。这很容易写错。所以本页不读字符串。单位等行计数那一章用 `fgets` 把一行的边界先固定住，再解析。`scanf` 适合已经知道是整数的流，不适合混杂的日志。

返回值 `EOF` 和 `ferror` 不是一回事。结束是正常的，流错误才是异常。五个数的围栏以 EOF 收尾，循环退出是成功路径的一部分，不应当打印「失败」。失败留给返回 0：有字符，但不是整数。把 EOF 也印成「失败」，空输入就会看起来像探头坏了。空输入打印次数 0，更诚实。调用者看到 0 次，就不要去除。这个区分要写在循环条件里：等于 1 才累加，不等于 1 就离开，离开之后不额外根据 `reading` 猜测发生了什么。

多个空格串在格式串里，匹配的是任意空白，不是「恰好两个空格」。输入用一个换行分开两个数，格式写成 `"%d  %d"` 仍会成功。人以为格式在约束排版，实际上空白在 `scanf` 格式里是一类字符。想约束排版，就不要用 `scanf`，把整行当字符串检查。温度解析不需要约束空格个数。

围栏字符串里的 `\n` 是换行，不是反斜杠加字母 n。写进 `stdin` 属性时用转义，程序里的 `scanf` 看见的是真正的换行。把期望也写成含转义的形式时，测试会把它解开再比较。你在散文里举例，不要把转义的两个字符当成探头会发送的内容。探头发送的是空白。空白已经够 `%d` 用了。

## 小结

`scanf("%d", &reading)` 把整数写进 `reading` 的地址。返回值是转换成功的项数，一次整数要见到 1 才可以使用那个变量。0 和 `EOF` 都不是温度。围栏的 `stdin` 提供字符，并默认在末尾送出 EOF，所以读到结束的循环会停。

不要把提示语写进格式串，不要用返回值和 36 比较。输入一旦可能夹带单位，就不要靠 `scanf` 在脏字符上重试。下一章的五个读数不再放在固定数组里，次数仍来自这组数据，存储改到堆上，用完交回去。

## 练习

从标准输入读一个整数。输入是 22。成功则打印它加一之后的 23，失败则打印「失败」。必须取地址并检查返回值。

::: answer 参考答案：随后加一
```c run stdin="22\n" expect="23" title="参考答案"
#include <stdio.h>
int main(void) {
  int reading = 0;
  if (scanf("%d", &reading) != 1) {
    printf("%s\n", "失败");
    return 0;
  }
  printf("%d\n", reading + 1);
  return 0;
}
```
:::

读入两个整数并打印它们的差的绝对值风格的比较结果：若第二个比第一个大，打印 1，否则打印 0。输入用阳光 36 和最初的 18，按这个顺序，18 不大于 36，应当打印 0。返回值要等于 2 才进入比较。

::: answer 参考答案：两项都要成功
```c run stdin="36 18\n" expect="0" title="参考答案"
#include <stdio.h>
int main(void) {
  int first = 0;
  int second = 0;
  if (scanf("%d %d", &first, &second) != 2) {
    printf("%s\n", "失败");
    return 0;
  }
  printf("%d\n", second > first);
  return 0;
}
```
:::
