函数已经能判断一次读数，却要调用五次，次序靠你手写。次序一多，就会漏掉 22 或把 36 写两遍。数组把同一类型的值排成连续的一段，下标从 0 数到 4，时间顺序就是下标顺序。18 在最前，19 在最后，36 在正中间的下标 2。连续存放的意思是：相邻两次读数在内存里挨着，中间不夹别的对象。这带来常数时间的按下标读取，也带来越界时没有「缺席」这个值，只有未定义行为。

```c run expect="36" title="下标二"
#include <stdio.h>
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  printf("%d\n", room[2]);
  return 0;
}
```

初始化列表比上一章逐个赋值短，也让「一共五个」在声明处就能看见。`room[5]` 的 5 是元素个数，不是最后一个合法下标。最后一个合法下标是 4。写成 `room[5] = 20` 在声明之后是越界，不是把数组变长。C 的数组不会变长。想变长要等申请内存的那一章，而且那也不是这个数组对象突然长大，而是另一块内存。

在 `main` 里，`sizeof room` 是整块的字节数。这个目标上 `int` 为 4 字节，五次是 20。`sizeof room / sizeof room[0]` 得到 5。这种写法比手写 5 好一点：若初始化列表改成四个数，同时把声明改成 `[4]`，商会跟着变。若你只改了列表、声明仍写 `[5]`，多出来的元素会被零初始化，长度仍是 5，零会像一次真实的 0 度混进来。所以改长度时声明和列表要一起看。下面印出字节数，确认我们站在 wasm32 的 20 上，而不是站在「元素个数」上。

```c run expect="20" title="整块的字节"
#include <stdio.h>
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  printf("%d\n", (int)sizeof room);
  return 0;
}
```

20 这个数不可移植到「每个 `int` 都是 4 字节」以外的世界，但这个抽屉就是那样的世界。用它来建立直觉：数组是一块扁平的字节，逻辑上的五次读数是你用 `sizeof` 除出来的，不是数组自己带的一个长度字段。没有长度字段，是 C 数组便宜的原因，也是它进了函数就丢尺寸的原因。

函数参数上的数组声明会退化成指针。参数写成 `int room[5]` 或 `int room[]` 或 `int *room`，在函数里几乎是一件事。`sizeof` 作用在这种参数上，得到的是指针宽度。这个目标上是 4，除以 `sizeof (int)` 得到 1。你以为自己问到了 5，实际问到了 1。于是循环只看 18，把阳光那一次留在外面，计数变成 0。这不是阳光没来，是长度问错了对象。若参数仍写成带方括号的数组，再对它使用 `sizeof`，clang 会发出「数组参数上的 sizeof 实际是指针」这一警告，`-Werror` 下例子无法运行。可运行的形式因此把参数直接写成 `int *`，印出的 4 就是那条警告想告诉你的宽度。

```c run expect="4" title="参数只剩指针宽度"
#include <stdio.h>
int pointer_width(int *room) {
  return (int)sizeof room;
}
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  printf("%d\n", pointer_width(room));
  return 0;
}
```

参数列表里的 `[5]` 被忽略，这很伤人，因为它看起来像契约。它不是契约。编译器不用它检查调用者是不是真的传了五个 `int`。你可以传三个元素的数组，编译往往仍通过，循环若按 5 走就会越界。真正的契约是另传一个次数参数，并在调用处用 `sizeof` 算出次数。函数相信这个次数。信任会错：次数若比实际大，仍会越界。语言不替你核对。取舍是性能和简单：调用时不必携带描述符。代价是每个接收数组的函数都要有自己的长度参数，少一个就是坑。

字符串是特殊的数组：元素类型是 `char`，并且约定最后一个内容字节之后有一个 0。`"C"` 是两个字节，字母和空字符。`"你好"` 是 7 个字节的数组，`strlen` 数到空字符之前，得到 6。数组章把这件事和温度数组放在一起，是为了阻止一种类比：五次读数不是字符串，不能交给 `%s`。`%s` 会从那个地址开始读字节，直到碰巧遇见 0。`int` 的内存里没有「读数结束」的空字符约定，它可能在栈上一直读下去。格式错误在字面量上会被 `-Werror` 拦住，所以你写 `printf("%s\n", room)` 时，类型对不上，编译失败。这是好事。不要强制转换成 `char *` 去骗过检查。

```c run expect="6" title="标签仍是字节"
#include <stdio.h>
#include <string.h>
int main(void) {
  char label[] = "你好";
  int room[5] = {18, 21, 36, 22, 19};
  printf("%d\n", (int)strlen(label));
  printf("%d\n", room[2]);
  return 0;
}
```

输出里先有 6 再有 36。期望用 `"6"` 就能命中第一行，36 留在第二行证明温度数组还在，没有被字符串的讨论替换掉。`char label[] = "你好"` 会把字面量复制进一块新数组，包含结尾的 0，所以 `label` 可写。写成 `char *label = "你好"` 则指向字面量本身，字面量不要写入。修改字符串字面量是未定义行为。温度计的标签若只是显示，两者都能 `%s`；若要在后面拼单位，需要可写缓冲区，用数组。

缓冲区要算字节。`"你好"` 复制进去要 7 个字节的空间。声明 `char label[6]` 再去装 `"你好"` 会丢结尾或丢内容，具体取决于你怎么复制。`strlen` 为 6 时，容纳它的数组至少是 7。少算空字符是中文标签最常见的短一截，因为有人把 6 理解成「已经含结尾」或理解成「两个字所以长度 2，开 6 个字节总够」。6 个内容字节刚好塞满 6 字节数组时，结尾无处可去，`%s` 不会停。

数组不能整体赋值。`int other[5]; other = room;` 不是合法的复制。可以逐个元素抄，也可以用标准库的内存复制，但那是按字节的，长度要用 `sizeof` 在数组还没退化的地方算好。整体赋值做不到，是因为数组不是带赋值运算符的一等值。结构体可以整体赋值，下一章之前可以先记住这个对比：若你主要的操作是「把一次测量整体交给别人」，把读数和单位包进结构体比维护两个平行数组更不容易错位。平行数组是 `int temps[5]` 配 `char units[5]`，排序时若只交换温度、忘了交换单位，36 会戴上别人的华氏帽子。一个数组的元素若自己含有两个字段，交换就是交换整个元素。结构体章会写这个。这一章先把温度单独放好。

零初始化的坑放在初始化旁边说。`int room[5] = {18, 21};` 其余三个元素是 0。循环若按 5 次去找最大值，结果仍是 21，0 不会赢。若找最小值，0 会赢，而你并没有测到 0 度。终端里的 0 像一次测量。初始化列表要么写全五个，要么把声明的长度也改掉。不要靠「零看起来无害」来省略。

`room` 和 `&room` 的类型并不相同，尽管在取地址的数值上常常是同一处起点。`room` 用在表达式里会退化成指向首元素的 `int *`。`&room` 是指向「五个 `int` 的数组」的指针。对前者加一，挪过一个温度；对后者加一，挪过整段五个温度。把 `&room` 传给期望 `int *` 的函数，类型对不上，编译会失败。这是保护。不要强转。强转之后，函数里的下标 2 仍可能读到 36，因为起点字节相同，于是错误的类型在这组数据上没有症状。症状会出现在你把返回的指针再加一时：一边跳 4 字节，一边跳 20 字节。打印下标 2 之前，先确认参数类型是指向元素，不是指向整个数组。

多维数组这里用不上。五次读数是一条时间线，不是表格。写成 `int room[5][1]` 只会多一个永远为 0 的下标，`sizeof` 仍然是 20，阅读却要决定哪一个维度是时间。真有「多个探头、每个探头五次」时再加维度，并且记得第一维才是 `sizeof` 除以子数组能问到的那一层。函数参数里最左边的维度同样会退化，右边的维度会留下来，因为它是元素类型的一部分。那是以后的形状。现在一条线足够，不要为了看起来像矩阵而加空的维度。

复制整段数组要用字节数，而且字节数必须在退化之前量好。在 `main` 里 `sizeof room` 是 20，把 20 传给复制函数，五次读数都会过去。在函数里再量，只剩指针的 4 字节，复制会截断，只带走 18 的四个字节，接收端的其余元素是旧内容。旧内容若碰巧是 0，你会以为下午后半段都是冰点。复制的长度参数和遍历的次数参数是同一种契约，只是单位一个是字节、一个是元素。不要混用：按元素次数去复制字节，会只复制前五个字节，18 的整数被切碎。

未写完的数组不能靠「打印看看」来发现越界。越界读取可能拿到栈上别的局部变量，例如刚算好的和 116，终端里出现 116 这个熟悉的数，你以为下标 5 是合法的第六次读数。它不是。熟悉的数比乱码更骗人。循环边界用元素个数，次数从 `sizeof` 来，不要从一次幸运的打印来。

初始化列表比赋值语句更容易看出缺了谁。五个数写在一对花括号里，少写 22 时，那一格变成 0，而不是编译错误。0 会参加最大值以外的所有统计。若你的测试只问最大值，36 仍在，列表的残缺就没有声音。打印一次和，116 对不上 94，残缺才会现形。所以数组章的例子虽然常拿下标 2 做代表，练习仍要求首尾相加。代表值保护不了整段下午。

元素类型一旦选定，整段数组就都是那个类型。不能让下标 2 单独变成浮点而其余保持整数。要混杂单位和数值，用结构体当元素，而不是把数组退化成字节再自行解释。自行解释会把对齐问题引进一排本来对齐良好的 `int`。

## 小结

`room[2]` 是 36，声明里的 5 是个数不是末下标。在 `main` 里 `sizeof room` 为 20。同一个对象传进函数，参数上的 `sizeof` 变成指针宽度 4，`[5]` 不构成契约。次数要另传。

字符串是带结尾 0 的字节数组。`"你好"` 的内容是 6 字节，数组要留结尾。温度数组不是字符串，不要按 `%s` 去打印，编译器会因类型拒绝你。下一章用地址解释为什么参数里只剩指针，以及加一到底跳过多少字节。

## 练习

打印下标 0 和下标 4 的和，也就是最早的 18 加最晚的 19。不要用手写 37 这个常量，用数组元素相加，这样改初始列表时打印会跟着改。

::: answer 参考答案：首尾
```c run expect="37" title="参考答案"
#include <stdio.h>
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  printf("%d\n", room[0] + room[4]);
  return 0;
}
```
:::

写一个函数，接收 `int *room` 和次数，返回最大值。`main` 里用 `sizeof` 计算次数再传入。结果应当是 36。函数内部不要再写死 5，以便你看清次数来自参数。

::: answer 参考答案：次数另传
```c run expect="36" title="参考答案"
#include <stdio.h>
int hottest(int *room, int count) {
  int i;
  int max = room[0];
  for (i = 1; i < count; i = i + 1) {
    if (room[i] > max) max = room[i];
  }
  return max;
}
int main(void) {
  int room[5] = {18, 21, 36, 22, 19};
  int count = (int)(sizeof room / sizeof room[0]);
  printf("%d\n", hottest(room, count));
  return 0;
}
```
:::
