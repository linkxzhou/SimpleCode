C 在这里先由 clang 编译成 wasm，再运行编译结果。点代码块上的 Run，编辑器里的单文件会经过编译和链接。警告当成错误，未使用的变量、格式不对的 printf 都会让这次运行失败。

每次运行都是新进程。没有线程，没有网络，也没有第二份源文件。程序从 main 开始，main 返回 int。要核对的文字用 printf 打到标准输出，并自己写换行。

期望是输出里的子串。编译失败时终端里是诊断，不是你 printf 的那句话。

   警告会让编译失败，不要留未使用的变量。 */
```

  return 0;

```

```c run expect="你好" title="问候"
#include <stdio.h>
int main(void) {
  printf("%s\n", "你好");
  return 0;
}
```

「只读」故意不能运行。先读它旁边的限制，再回到能点 Run 的例子上改一个值。不要把只读块当成坏掉的按钮。

### 读「相加」

做完上一例再做这一例。把代码收成一行来记：`#include <stdio.h> int main(void) { printf("%d\n", 19 + 23); return 0; }`。先盖住终端，写下你预测的输出，里面要能找到「42」。这是子串：前面可以有别的字，后面通常有换行。

然后点这个代码块上的 Run，不要点工具栏。代码块会备份草稿、写入示例再执行。找不到这段文字时，先看退出码。不是 0 就读错误类型，不要改期望。是 0 但内容不对，就只改产生该值的那一处。改完用工具栏的 Run，因为再点代码块会把修改盖掉。预测对了之后点撤销。

### 限制：只读

这一段故意不能运行。旁边的限制是：留下声明了却没用的变量，编译被 -Werror 拦住。。做法是：每个示例都是一份能单独编译的完整程序。。把它留在抽屉里对照，不要粘进主编辑器再点工具栏的 Run。能运行的例子在它前后，改那些例子时不要把这里的调用加进去。

### 只改一处：相加

这一例要避开的失误是：printf 忘了 \n，下一行结果粘在一起。。对应的做法是：格式串用字面量，参数类型和 %d、%s 对齐。。

## 读完再动手

本章要留下的是 「写出能编译的 main」、「用 printf 看见结果」、「知道警告会让编译失败」。合上抽屉之前，用自己的话说出每一项目标对应哪一个示例的标题。对不上标题，就还没有把目标和代码连起来，先别展开练习答案。

练习的答案默认折着。先在编辑器里自己写，再展开对照。对照时只看输出是否包含期望的那几个字。两道都过了再进入下一章。下一次运行是新进程，这次的变量不会留下。

把这一章当成一次可以反复撤销的实验。点代码块上的 Run 会用示例覆盖编辑器，原来的草稿先备份。你改过的内容如果还想留着，先复制到别处，再点下一例。工具栏的 Run 不会从文档重写编辑器，所以它用来看你改过的版本。两种按钮各做各的事。下载进度写在按钮旁边，第一次打开这种语言时要等它结束，再判断示例是不是写错了。

记录你预测错的那一次。写下你以为会打印的文字，以及实际多出来或少掉的部分。进入下一章之前，要能用一句话说清差在哪。通过只说明期望的那几个字还在，不说明你已经看懂产生它的那一行。章节标题下的目标就是这份验收清单。差两个字也不要靠改期望凑过去。

## 常见错误

- 留下声明了却没用的变量，编译被 -Werror 拦住。
- printf 忘了 \n，下一行结果粘在一起。
- main 不返回 int，或走到末尾却没有 return。

## 最佳实践

- 每个示例都是一份能单独编译的完整程序。
- 格式串用字面量，参数类型和 %d、%s 对齐。
- 做不到的事用只读块标出来。
