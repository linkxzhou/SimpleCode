这份 clang 按 C11 编译。`_Static_assert` 失败会让编译停止，成功则不产生运行时代码。`_Generic` 在编译期按控制表达式的类型挑选，不是运行期的 `switch`。下面几个例子都会通过编译并打出一行。

### 编译期断言

`sizeof(int)` 至少是 2。断言的字符串只在失败时给编译器看。成功时程序打印 `ok`。

```c run expect="ok" title="断言通过"
#include <stdio.h>
int main(void) {
  _Static_assert(sizeof(int) >= 2, "int is wide enough");
  printf("ok\n");
  return 0;
}
```

断言通过，输出 `ok`。

### 按类型挑名字

`kind(1)` 的控制表达式是 `int`，选中 `"i"`。`double` 会选 `"d"`，这一次不传浮点。`default` 用来接其他类型。

```c run expect="i" title="int 的标记"
#include <stdio.h>
#define kind(x) _Generic((x), int: "i", double: "d", default: "?")
int main(void) {
  printf("%s\n", kind(1));
  return 0;
}
```

标记是 `i`。

### 匿名成员

外层结构体里嵌了一个没有名字的结构体，成员 `a` 提升到外层。初始化时内层仍要一对花括号。`s.a` 是 3，不必写中间那层名字。

```c run expect="3" title="提升上来的成员"
#include <stdio.h>
struct Pack {
  struct { int a; };
  int b;
};
int main(void) {
  struct Pack pack = {{3}, 4};
  printf("%d\n", pack.a);
  return 0;
}
```

匿名成员的值是 3。

### 练习：对齐字节

`_Alignof(int)` 是 `int` 的对齐要求。在这份 wasm32 目标上它是 4。结果先转成 `int` 再按 `%d` 打印，避免用和平台宽度绑在一起的格式。

《C Primer Plus》后半本也列了 C11，句子不搬：https://book.douban.com/subject/26792521 。

```c run expect="4" title="int 的对齐"
#include <stdio.h>
int main(void) {
  printf("%d\n", (int)_Alignof(int));
  return 0;
}
```

对齐是 4 字节。
