堆上的五个 `int` 随着 `free` 和进程结束消失。若想在计算之前先把下午记下来，就要用文件。这里的文件不是你笔记本上的文件夹。程序是 WASI 命令，能打开的只有宿主预打开的目录。`@runno/wasi` 预打开的是虚拟文件系统的根 `/`。这个根里装着本次运行的材料：编辑器放进去的源码 `/program`，编译和链接留下的目标文件与 wasm，以及编译器自己的 sysroot `/sys`。它不是你家目录的挂载，也不是浏览器外面的磁盘。路径长得像 `/home/某人/下午.txt` 时，仍然落在这棵虚拟树里。写入可能成功，因为整棵 `/` 都预打开了，权限模型在这个实现里并不按 Unix 用户来拒绝你。成功不表示日志进了真实的主目录。它只表示沙箱里多了一个名字。

下一次点 Run，宿主会重新准备文件系统。你上次创建的 `/room.txt` 不在新的树里。跨章节、跨点击的记忆不能靠文件。能靠的仍是写在源码里的 18、21、36、22、19。文件的价值限定在同一次进程：写入，再读回，证明布局是你自己的文本，而不是结构体的内存映像。

打不开和「不存在」先分开看。对一个从未创建的名字做只读打开，返回空指针。空指针不能交给 `fscanf` 或 `fclose` 以外的读取函数。`fclose` 也不要拿去关空指针。失败路径只打印一个固定词。

```c run expect="没有" title="名字不在这棵树里"
#include <stdio.h>
int main(void) {
  FILE *log = fopen("/missing-room.txt", "r");
  if (log == NULL) {
    printf("%s\n", "没有");
    return 0;
  }
  fclose(log);
  return 0;
}
```

这个失败不是磁盘损坏，是预打开的树里没有这个名字。不要改用绝对的 Windows 盘符或一长串真实家目录来「修好」。那些字符串在虚拟根里只是更深的路径，该不存在还是不存在；若你用写模式，还可能在沙箱里把目录层级造出来，制造一种「已经保存」的错觉。

第二次在进程内完成写和读。文本一行五个整数，空格分开。写完要 `fclose`，否则缓冲可能还没进文件，紧接着的只读打开会看见空内容。关闭之后再打开，是两条不同的流。不要在同一只 `FILE *` 上不刷新就改方向。读的时候检查 `fscanf` 的返回值是不是 5。少一项就不要用那些 `int`，它们可能只被填了一部分，其余保持初始的 0，0 会像冰点。

```c run expect="36" title="写回再读出阳光"
#include <stdio.h>
int main(void) {
  FILE *log;
  int a = 0;
  int b = 0;
  int c = 0;
  int d = 0;
  int e = 0;
  log = fopen("/room.txt", "w");
  if (log == NULL) {
    printf("%s\n", "没有");
    return 0;
  }
  fprintf(log, "%d %d %d %d %d\n", 18, 21, 36, 22, 19);
  fclose(log);
  log = fopen("/room.txt", "r");
  if (log == NULL) {
    printf("%s\n", "没有");
    return 0;
  }
  if (fscanf(log, "%d %d %d %d %d", &a, &b, &c, &d, &e) != 5) {
    fclose(log);
    printf("%s\n", "没有");
    return 0;
  }
  fclose(log);
  printf("%d\n", c);
  return 0;
}
```

36 从文件回到了标准输出。路径 `/room.txt` 能创建，是因为 `/` 预打开且可写。`fprintf` 的格式和 `printf` 一样要配平，错了同样过不了 `-Werror`。`fscanf` 需要地址，和 `scanf` 同一条规则。返回值是成功项数，不是温度。

第三次读宿主放进来的源码文件，用来证明「预打开」不是抽象名词。源码路径固定是 `/program`。下面的程序在自己的源码里放了一枚标记 `room-log`，再打开 `/program` 去找它。找到就打印 1。这不是把温度存在源码注释里的建议，而是一次可观察的实验：能读到标记，说明文件 API 看见的是宿主放进虚拟根的那个字节序列，不是你电脑上另一个同名工程。

```c run expect="1" title="源码也在预打开的根里"
#include <stdio.h>
#include <string.h>
int main(void) {
  FILE *source;
  char line[256];
  int found = 0;
  source = fopen("/program", "r");
  if (source == NULL) {
    printf("%s\n", "没有");
    return 0;
  }
  while (fgets(line, (int)sizeof line, source) != NULL) {
    if (strstr(line, "room-log") != NULL) found = 1;
  }
  fclose(source);
  printf("%d\n", found);
  return 0;
}
/* room-log */
```

`fgets` 一次至多读入缓冲区长度减一的字符，并补上结尾的 0。行比 255 字节短时，换行会留在缓冲区里。找标记用 `strstr` 即可，不需要先去掉换行。若标记被切在两次读取的边界上，会漏掉。我们的标记很短，又单独成行，切不开。读日志时如果一行可能很长，就要处理「这一截没有换行所以记录不完整」。五个整数的短行碰不到这个边界，行计数那一章会再遇到换行。

`/sys` 里是编译器的头文件和库，因为编译阶段的文件系统被原样留给了这次运行。你可以打开 `/sys/include/stdio.h` 并且很可能成功。不要把那里当成传感器档案，也不要在示例里解析它来得到 36。它的存在是工具链的副作用。温度只写到你自己创建的 `/room.txt`，或者只存在于源码字面量。混读 sysroot 会让程序依赖抽屉的内部布局，布局一变，日志程序就坏了，而坏的原因看起来像探头没数据。

缓冲是正确性的一部分。`fprintf` 之后若进程在 `fclose` 之前异常退出，最后几行可能还在用户空间缓冲里，文件是短的。教学例子用正常的 `fclose`。不要用 `_exit` 之类跳过冲洗的方式结束，即便这个环境里你也写不出那种调用。对标准输出，`printf` 在终端上常常按行冲洗，所以你带了 `\n` 就看得见。文件不是终端，不要把这个习惯搬过去。看见标准输出有 36，不能证明文件里已经有 36，证明的是你后来又读了一次并且读到了。

错误分支都打印「没有」，是一种妥协。打不开、项数不够，对人是不同的事故，对这个短示例是同一种「不要使用那些 `int`」。真实日志应当把原因写到标准错误，并返回非零。这里返回 0，是为了让失败文案成为可检查的正常输出，和输入那一章的选择相同。你在抽屉外应当把失败分成不同的退出码。

文本比结构体映像安全，上一章已经说了空洞和宽度。`fprintf` 五个 `%d` 是文本。读回用五个 `%d`。不要 `fwrite` 整个 `int` 数组再指望下一份程序用同样的字节序读走。wasm32 是小端，你的笔记本可能也是小端，于是错误的格式会在两台小端机器上碰巧成功，换一台就坏。五个数小到不值得为这种碰巧节省字节。

同一次进程里可以删除自己创建的名字。`remove("/room.txt")` 在关闭之后调用，名字从虚拟树里消失，再次只读打开应当失败。这不能当成安全擦除，它只是让后续的 `fopen` 不再看见下午。虚拟树本来就不会活到下一次 Run，删除的意义是让程序的后半段无法误读旧日志。若你在删除之前还握着没有 `fclose` 的流，行为就不再是「文件没了」这么单纯。先关闭，再删除。删除的返回值非零表示没删掉，随后的打开可能仍成功，于是你以为已经清场，其实 36 还在。检查返回值，和检查 `fopen` 一样，不要只调用。

标准错误和标准输出是两条流。失败的「没有」若打到标准错误，成功的 36 留在标准输出，管道可以只接走温度。这个抽屉的期望看的是程序输出的文本，示例为了让失败词也能被同一处期望看见，把两种都写进了标准输出。这是教学上的妥协，不是日志程序的终态。你在外面应当把诊断送到标准错误，避免有人把「没有」解析成一次读数。单词不会通过 `%d`，所以风险有限，可是行计数若只看行数，诊断行会把次数加一。通道分开，次数才只代表探头。

刷新和关闭的差别在于流还在不在。`fflush` 把缓冲交出去，流仍可写。`fclose` 先冲洗再释放流。写完五个数之后我们不需要继续往同一流里追加，所以直接关闭。追加应当重新以追加模式打开，而不是在已经关闭的指针上再 `fprintf`。关闭之后的指针和 `free` 之后的指针一样，是悬空的。把它置空，后续的误用会变成对空指针的调用，而不是对已经回收的流写 22。示例在关闭后立刻让变量接受下一次 `fopen` 的返回值，没有空窗去误用，所以没置空。窗口一旦变长，置空就是便宜的防护。

不要用 `feof` 当循环条件去读文本。文件结束标志常常在一次失败的读取之后才设立。先读，再看返回值是否是期望的 5 或一行，失败之后若需要区分结束和错误，再查标志。五个整数的 `fscanf` 返回 5 就是成功，返回别的就放弃。在放弃之前不要打印已经写了一半的 `a` 和 `b`。半行不是下午。

路径里不要拼探头的编号来「分文件保存每一次」。`/room-36.txt` 这种名字仍然在虚拟根里，下次运行一样消失，而且你要为每个名字检查打开是否成功。五个数写成一个文本文件，一次检查，一次读回，失败面更小。拆成五个文件不会更安全，只会让其中一次打开失败时，另外四次数还在，和被算成残缺的下午。残缺的和比完整的失败更难发现。要么五个都在，要么整份日志拒绝。

写入模式 `"w"` 会把已有的 `/room.txt` 截断。同一次进程里第二次打开写，前面的五个数就没了。若你想在末尾再加上一次读数，用追加模式，并接受追加不会替你写分隔空白，分隔要自己放进格式串。漏掉空格时，22 和 19 会粘成 2219。读回来的项数会变少，`fscanf` 的返回值不再是 5，程序应当走放弃那条路，而不是把粘连的数当成一次新的高温。放弃好过沉默地少算一个下午。粘连若发生在最后两项，前面的 18、21、36 看起来都正常，只有项数泄露事故。所以检查的是项数，不是「有没有看见熟悉的 36」。熟悉的 36 只证明写入曾经成功过，不证明五项都还在。

## 小结

预打开的只有虚拟根 `/`。`/missing-room.txt` 只读打开得到空指针。`/room.txt` 可以在本次进程里写五个数再读出 36，下一次 Run 不会保留它。`/program` 能读到，是因为宿主把源码放了进去；`/sys` 能碰到，是工具链残留，不是温度档案。

写文件后要关闭再读，`fscanf` 必须返回 5 才使用那些整数。格式继续用文本。下一章不再中转文件，直接数标准输入里的温度行，空行不算，越线的行单独数。

## 练习

把 36 一个数写到 `/one.txt`，读回来打印。路径必须在虚拟根下。检查两次打开和一次 `fscanf`。

::: answer 参考答案：单个文件
```c run expect="36" title="参考答案"
#include <stdio.h>
int main(void) {
  FILE *log = fopen("/one.txt", "w");
  int reading = 0;
  if (log == NULL) {
    printf("%s\n", "没有");
    return 0;
  }
  fprintf(log, "%d\n", 36);
  fclose(log);
  log = fopen("/one.txt", "r");
  if (log == NULL) {
    printf("%s\n", "没有");
    return 0;
  }
  if (fscanf(log, "%d", &reading) != 1) {
    fclose(log);
    printf("%s\n", "没有");
    return 0;
  }
  fclose(log);
  printf("%d\n", reading);
  return 0;
}
```
:::
