文件那一章的 `/room.txt` 活不过下一次点击。最后这一章把日志放在标准输入里，一次进程读完并交出两个事实：有效行有多少，其中不小于 30 的有多少。数据仍是那个下午。行的样子是：

18 单独一行，然后 21，然后 36，然后 22，然后 19。围栏的 `stdin` 写成这五行，末尾默认还有 EOF。`fgets` 读到结束返回空指针，循环停下。若 EOF 不来，`fgets` 会停在下一次等待，抽屉超时。超时不是行数。默认送出的结束信号是这个程序能写完的前提，和 `scanf` 那一章相同，只是读取的单位从「一个整数」换成了「一行」。

一行比一个整数更适合当记录，因为以后可以在同一行写上单位。现在先只放整数，让失败模式少一种。`fgets` 会把换行留在缓冲区里，除非这一行长到装不下。我们的行很短，缓冲 64 字节足够，换行还在。统计之前去掉末尾的换行，否则它只是记录分隔符，不是温度的一部分。去掉之后若一个字节都不剩，这行是空行，不计入次数。空行常常来自手写日志时多按的一次回车，把它算进下午，次数会从 5 变成 6，整数平均的除数就错了。

```c run stdin="18\n21\n36\n22\n19\n" expect="5" title="五行"
#include <stdio.h>
#include <string.h>
int main(void) {
  char line[64];
  int count = 0;
  while (fgets(line, (int)sizeof line, stdin) != NULL) {
    size_t n = strlen(line);
    if (n > 0 && line[n - 1] == '\n') {
      line[n - 1] = '\0';
      n = n - 1;
    }
    if (n == 0) continue;
    count = count + 1;
  }
  printf("%d\n", count);
  return 0;
}
```

`sizeof line` 传给 `fgets` 时要让函数知道缓冲区有多大，它自己会留一个字节给结尾的 0。转换成 `int` 是因为这个目标上的原型用 `int` 表示大小，而 `sizeof` 是 `size_t`。64 远小于 `int` 的上限，转换是安全的。不要把 64 再手写一遍当成第二个魔数，改数组时容易只改一处。

空行插在中间时，次数不应当增加。下面的输入在 21 和 36 之间多一个空行。有效行仍是五。若程序把空行算进去，打印会是 6。期望写 5，就是在钉住这条规则。

```c run stdin="18\n21\n\n36\n22\n19\n" expect="5" title="空行跳过"
#include <stdio.h>
#include <string.h>
int main(void) {
  char line[64];
  int count = 0;
  while (fgets(line, (int)sizeof line, stdin) != NULL) {
    size_t n = strlen(line);
    if (n > 0 && line[n - 1] == '\n') {
      line[n - 1] = '\0';
      n = n - 1;
    }
    if (n == 0) continue;
    count = count + 1;
  }
  printf("%d\n", count);
  return 0;
}
```

只数行还不够，因为六行里若有一行是单词而不是数字，次数仍会增加，随后的平均却不能把单词加进去。解析要第二步。`sscanf` 从已经在手里的行里取整数，返回成功项数。它不碰标准输入，所以不会出现 `scanf` 在脏字符上打转的问题。行是 `"36"` 时得到 36。行是 `"阳光"` 时返回 0，这行可以忽略，或者单独计为坏行。这一章把坏行排除在有效次数之外，好让除数干净。代价是坏行静默消失，排错的人不知道日志里有垃圾。更严的程序应当打印「失败」并停止。五个干净数加上我们故意放进练习的形状，先用「跳过空、拒绝非数字」把主路径定下来。

越线仍是不小于 30。在同一次扫描里同时数有效行和越线行，不要读两遍输入。标准输入不是可以随意重绕的文件，读过的字节不会再来。一遍循环里两个计数器，就是这个约束的写法。

```c run stdin="18\n21\n36\n22\n19\n" expect="1" title="越线的行"
#include <stdio.h>
#include <string.h>
int main(void) {
  char line[64];
  int hot = 0;
  while (fgets(line, (int)sizeof line, stdin) != NULL) {
    int reading = 0;
    size_t n = strlen(line);
    if (n > 0 && line[n - 1] == '\n') line[n - 1] = '\0';
    if (line[0] == '\0') continue;
    if (sscanf(line, "%d", &reading) != 1) continue;
    if (reading >= 30) hot = hot + 1;
  }
  printf("%d\n", hot);
  return 0;
}
```

`line[0] == '\0'` 覆盖两种空：本来就是空行，以及只有换行、去掉之后变空。`sscanf` 失败时 `reading` 保持 0，循环必须 `continue`，不能让这个 0 去参加 `>= 30`。它不会被算成越线，因为 0 不大于等于 30，所以这组判断碰巧安全。碰巧不该当结构。若规则改成「统计低于 22 的次数」，失败留下的 0 会被计入，坏行变成一次寒潮。使用 `reading` 之前坚持看到返回值 1。

`sscanf` 的格式若写成 `"%d"`，行首可以有空白。`"  36"` 仍能读到。行内若是 `36C`，`%d` 仍成功，返回 1，`C` 被留下不看。于是单位被丢弃，36 仍按摄氏越线。这和结构体章的担忧是同一个。当前日志没有单位，成功是完整的。一旦允许单位，应当再检查行的其余部分是不是只有结尾，或者用第二个转换去读一个字符并核对它是 `C`。不核对的解析会把 `36F` 当成摄氏的阳光。数据还没混进华氏，就把这个缺口写在规则旁边，避免你以为 `sscanf` 返回 1 表示整行合法。

缓冲装不下一行时，`fgets` 不会带回换行，下一次调用接着读剩余字节。你的去换行逻辑不会把两截合成一行，计数会多 1，数字也可能被从中间切开，`sscanf` 得到一个前缀数值。64 字节对 `"19\n"` 足够。不要把缓冲区改成 2 来「省内存」，一行 `18` 就会被切开。省下来的字节不值得一次错误的次数。真的长行需要循环拼装，直到看见换行或 EOF。五个温度用不到拼装，知道缺口在哪即可。

函数边界可以收一下，让 `main` 只负责读。判断「这行算不算、是不是越线」放进函数，返回两个结果却没有元组。C 的做法是通过指针写出第二个结果，或者只让函数回答一个问题。这里让函数回答「这一行的温度是否有效」，有效时经指针送出整数。空行和坏行返回 0，调用者不增加次数。指针在无效时不被写入，调用者也不读它。这把前面几章的工具放进同一次扫描：地址用于输出参数，返回值用于是否有效，比较用于越线，堆不必出现，因为一行的缓冲在栈上，下一次循环覆盖它即可。不要把每一行 `malloc` 下来再 `free`，除非你要保留全部原文。我们只要计数，保留是浪费，也多一次忘记释放的机会。

和的复核可以心算。五行若都有效，和仍是 116，越线行是 1。这一章的例子打印次数而不是和，是为了让空行的影响直接显现在被检查的那个数上。和会被 0 的空行掩盖，次数不会。选择打印次数，就是选择一种错误能被看见的输出。

进程模型还是老样子。标准输入在这次运行里读完就没有了，不能在程序后半段再要一次五行。需要两遍算法时，第一遍就要把有效温度放进数组或堆，次数未知时用堆并在结束时 `free`。五行的上限已知，也可以用 `int kept[5]` 并在超出时停止，拒绝第六行。上限是产品规则：这支探头一个下午只记五次，多出来的是另一段记录，不该静默并进平均。例子没写这个上限，因为输入由围栏保证。你把它当成命令行工具时，加上限，并在超出时打印「失败」。

最后一行没有换行时也应当计入。有的编辑器在文件末尾不加强制换行，围栏若写成 `19` 而不是 `19\n`，`fgets` 仍能把这几个字符读进来，缓冲区里没有换行可删，`strlen` 大于 0，`sscanf` 能得到 19。规则要依赖「去掉换行之后还剩不剩内容」，不要依赖「每行必有换行」。空行则是只有换行或什么都没有。两者都处理，次数才不随编辑器的保存习惯摇摆。我们的围栏带换行，是为了稳定，不是因为没换行的行不合法。

回车加换行是另一套结尾。若日志从别处拷来，行尾可能是 `\r\n`。去掉 `\n` 之后还剩 `\r`。`sscanf` 仍能读数字，因为回车算空白。次数不会错。可是你若用整行字符串去和 `"36"` 比较，回车会让比较失败，阳光行被当成坏行，越线次数变成 0。解析用数值，不要用整行相等。需要干净的文本时，在去掉 `\n` 之后若末尾是 `\r` 也去掉。五个数的围栏没有回车，示例不写这步。你接到外部文件时要补上，否则单位核对会莫名其妙地失败。

只含空格的行要不要算空，是产品决定。`strlen` 在去掉换行后仍大于 0，目前的程序会把它交给 `sscanf`。`sscanf` 跳过空白之后若什么都没有，返回 `EOF` 或 0，我们的循环把它当成坏行跳过，不计入次数。结果和空行一样，途径不同。知道途径，你才不会在「空格行被计入」的报告面前去改错地方。改 `strlen` 的判断救不了这行，因为长度确实不为 0。要拒绝纯空白，就在解析失败时保持跳过，这个结构已经是跳过。不要在解析失败时改成计数。

一遍扫描结束之后，输入就耗尽了。若此时才发现需要打印和而不是次数，数已经不在手里。要么当时就累加，要么把有效读数存进数组。五行的上限已知，栈上的 `int kept[5]` 够用，超过五次就停止并打印失败，避免第六次把别的下午并进来。未知上限才需要堆，并在打印之后释放。这章的期望只检查次数或越线次数，所以没有申请内存。离开这个例子去做报表时，把和、次数、越线次数放在同一次循环里算完，不要回过头去再读标准输入。

打印次数之前不要再打印每一行的回显。回显里的 18 或 36 会让只检查子串的人分不清自己数对了没有：期望若是 `1`，回显的 18 里并不含 `1`，可是 21 里含有。越线次数的期望是 `1`，回显 21 就会让错误的计数也被看成通过。示例因此只打印那一个计数。调试时可以临时回显，提交进文档的块要保持输出只有答案。

## 小结

`fgets` 读到 EOF 为止，围栏默认会送出这个结束。去掉换行后长度为 0 的行不计。`sscanf` 返回 1 之后，读数才能参加 `>= 30`。同一遍循环里数越线，因为标准输入不能倒回去。五行的下午得到次数 5、越线 1。

`36C` 这种行会让 `%d` 提前成功，单位被丢掉。缓冲区必须装得下整行，否则次数会被切碎。到这里，同一组读数走过了格式、类型、控制流、函数、数组、指针、结构体、输入、堆和预打开的文件。离开抽屉时，把 `return 1` 还给真正的失败，把 `-Wall` 打开，并记住这里的 `long` 只有 4 字节。
