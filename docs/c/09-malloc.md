固定的 `int room[5]` 把次数写进了类型。下午若只有三次，数组仍占五个；若探头多醒了一次，数组又装不下。堆上的存储按运行时的次数来。次数这一次仍是 5，数仍是 18、21、36、22、19，好让你把注意力放在生存期，而不是放在一套新数据。`malloc` 要的是字节数。五个 `int` 是 `5 * sizeof(int)`，更好的写法是 `count * sizeof *readings`，这样元素类型改了，大小跟着指针的目标类型走，不会只改了一边。

返回值是 `void *`，赋给 `int *` 时在 C 里可以隐式转换。失败时返回空指针。空指针的唯一合法用法是拿去比较，不能下标，不能解引用。失败了还写 `readings[2] = 36`，是未定义行为。这个抽屉的内存足够装五个整数，失败几乎不会发生。仍然要写分支。分支是给「次数来自输入、乘出来的字节数大得离谱」预备的，也是给习惯预备的。失败时返回非零或打印一个固定的词然后返回，不要继续算平均。

```c run expect="36" title="堆上的阳光"
#include <stdio.h>
#include <stdlib.h>
int main(void) {
  int count = 5;
  int *readings = malloc((size_t)count * sizeof *readings);
  if (readings == NULL) {
    printf("%s\n", "失败");
    return 0;
  }
  readings[0] = 18;
  readings[1] = 21;
  readings[2] = 36;
  readings[3] = 22;
  readings[4] = 19;
  printf("%d\n", readings[2]);
  free(readings);
  return 0;
}
```

`stdlib.h` 提供 `malloc` 和 `free`。漏掉这个头文件，在 C99 之后隐式声明会被 `-Werror` 拒绝，而且即使能链接，返回类型也会被当成 `int`，指针被截断。头文件不是可选项。

用完调用 `free`。这一行是本章要辩论的地方。进程马上 `return 0`，操作系统或这个 wasm 运行时会把整个地址空间收回。不写 `free`，本次输出仍是 36，退出码仍是 0。泄漏不会在期望子串里现身。那为什么还写。

因为「这次运行看不出来」不是正确性的定义。第一，同一个函数会被放进循环。每小时申请一块日志、用完不还，短示例里的五次变成两千次，进程在退出前就先把堆用尽，后面的小时打印「失败」或者直接陷阱。你在五次的例子里删掉 `free` 来证明「没差别」，只证明了次数太少。第二，所有权是读代码的人唯一能靠的线索。看见 `malloc` 却看不见 `free`，无法判断这块内存是打算交给别的模块活到进程结束，还是作者忘了。我们的所有权很简单：`main` 申请，`main` 释放，中间没有第二个主人。把释放写出来，阅读就结束了。第三，别的构建会打开泄漏检测，忘记的 `free` 会变成失败。这个抽屉没有那种检测，所以它的沉默没有投票权。

`free` 之后，指针的值还在变量里，但它指向的存储已经还回去了，不能再读 `readings[2]`。那块地址可能被下一次 `malloc` 拿去装别的，也可能仍残留着 36。残留让错误的读取看起来成功。把指针立刻置成空，后续的误用会变成对空指针的解引用，更容易暴露。置空不是 `free` 的一部分，`free` 不会改你的变量。这是两步。

```c run expect="116" title="还回去之后再求和"
#include <stdio.h>
#include <stdlib.h>
int main(void) {
  int count = 5;
  int *readings = malloc((size_t)count * sizeof *readings);
  int i;
  int sum;
  if (readings == NULL) {
    printf("%s\n", "失败");
    return 0;
  }
  readings[0] = 18;
  readings[1] = 21;
  readings[2] = 36;
  readings[3] = 22;
  readings[4] = 19;
  sum = 0;
  for (i = 0; i < count; i = i + 1) sum = sum + readings[i];
  printf("%d\n", sum);
  free(readings);
  readings = NULL;
  return 0;
}
```

求和必须发生在 `free` 之前。顺序反了，就是在已释放的存储上读五个 `int`。示例把打印放在释放之前，置空放在释放之后，是一条能看懂的时间线。不要为了「保险」而 `free` 两次。第二次是未定义行为。置空之后再 `free(readings)` 是安全的，因为 `free` 接受空指针并什么都不做。这是置空的额外好处，不是鼓励你释放两次。

`malloc` 不保证把字节清零。五个位置在赋值之前不要读。若你按未初始化的堆内容去找最大值，可能碰巧读到很大的数，越线判断会凭空多一次。要零用 `calloc`，它把字节清零再交给你，次数和元素大小分成两个参数，乘法溢出的检查也比你自己写的乘法更不容易错。代价是清零本身要时间。温度都会被立刻赋值时，`malloc` 足够，不要为了仪式清零。会留下「未填的次数」时，`calloc` 的零至少稳定，但零仍然像 0 度，更好的办法是另记有效次数，只读已经写入的前缀。

第三块例子把有效次数和越线次数一起做掉，仍然在释放之前读完。这样你能看见堆上的数据和栈上的 `int room[5]` 在算法上没有区别，区别只在谁决定生存期。栈上的数组随着 `main` 返回而消失，不需要 `free`，也不能 `free`。把栈数组交给 `free` 是未定义行为。堆和栈不要混。指针的来源决定它的结尾：取地址来的用作用域结尾，`malloc` 来的用 `free` 结尾。

```c run expect="1" title="释放前数完"
#include <stdio.h>
#include <stdlib.h>
int main(void) {
  int count = 5;
  int *readings = malloc((size_t)count * sizeof *readings);
  int i;
  int hot = 0;
  if (readings == NULL) {
    printf("%s\n", "失败");
    return 0;
  }
  readings[0] = 18;
  readings[1] = 21;
  readings[2] = 36;
  readings[3] = 22;
  readings[4] = 19;
  for (i = 0; i < count; i = i + 1) {
    if (readings[i] >= 30) hot = hot + 1;
  }
  printf("%d\n", hot);
  free(readings);
  readings = NULL;
  return 0;
}
```

重新分配会搬家。`realloc` 可能返回新地址，旧指针作废，即使数值碰巧相同也不能再使用旧地址。这一章不需要把五次扩成六次，所以不写 `realloc`。只记住一件事：所有指向块内部的指针，在搬家之后都要视为失效。若 `cap_sun` 拿着 `&readings[2]`，而你在它返回之前把块 `realloc` 走了，封顶写进的是旧地址。所有权要单线：要么先改完再搬家，要么搬家之后重新取地址。

整数乘法也可能在申请之前溢出。`count * sizeof *readings` 若按 `int` 乘，很大的 `count` 会绕回一个小字节数，`malloc` 成功，循环却按巨大的 `count` 去写，堆被踩烂。五个不会溢出。写成 `(size_t)count * sizeof *readings` 是把乘法放进无符号的字节计数里。若 `count` 来自输入，还要在乘法之前限制上限。没有上限的分配不是健壮，是把拒绝服务交到输入手上。教学例子把 `count` 写成 5，同时把类型写成不会在这五个上溢出的形式，是为了让正确的形式先出现，而不是因为 5 需要保护。

`free` 不是把字节擦成零。敏感数据和温度无关，但「释放等于销毁内容」这个心理模型是错的。释放等于归还所有权。需要销毁内容时要自己先覆写，再释放。温度不需要覆写。不要为了看内存被清零而在 `free` 之后再读一遍，那一步本身就是错误，而且你可能真的看见残留的 36，从而更加相信「释放会清零」或「释放没发生」。两种相信都错。

申请的字节数不包含「次数」这个整数本身。你得到的是五个 `int` 的平坦区域，没有在前面偷偷放一个长度。释放时也不需要把长度交还给 `free`，分配器自己记得这块有多大。这是接口上的不对称：你申请时必须算字节，释放时只交指针。不对称让 `free` 的调用很短，也让你无法在释放前再问这块「能装几个」。能装几个必须由你的 `count` 变量记住。`count` 若丢失，指针还在也没有用，你不敢读下标 2，因为你不再知道 2 是否越界。所有权不止是「谁来 `free`」，还包括「谁记得长度」。两者都放在 `main` 里，就不用跨函数传递这对数。一旦拆进函数，指针和次数要一起传，只传指针等于把上一章的退化问题再演一次。

`malloc(0)` 的返回值在标准里是实现定义的，可能是空，也可能是一块不能读写但可以 `free` 的标记。次数来自输入时，0 次应当在调用 `malloc` 之前就返回，打印 0 次，不要申请。五个是常量，碰不到这个分支。分支仍然要在你把 `count` 改成输入时加上。对 0 次做除法求平均，比 `malloc(0)` 更危险，因为除零的未定义行为不会因为你后来 `free` 了就被抹掉。顺序应当是：次数合法，再申请，再写入，再读取，再释放。任何一步失败，都不进入下一步。

对齐由 `malloc` 保证，适合任何基本类型，也适合我们那个含 `int` 的结构体。不要自己用字节指针加一之后强转成 `int *` 再写入，那会破坏对齐。五个 `int` 的块是对齐的，`readings[2]` 因此安全。你若把块当成字节缓冲，从中间某个奇数偏移取出温度，在有的硬件上会陷阱，在 wasm 上可能表现为错误的数值。下标运算已经把对齐算进去了。优先用下标，而不是手写字节偏移。

栈上的变长数组能按次数分配，函数返回就消失，不用 `free`。它的失败模式是栈溢出，这个目标的栈大小是固定的，不会返回空指针给你判断。五个 `int` 用变长数组也行，可是失败时你没有 `if` 可以进入。`malloc` 的空指针是可以分支的失败。教学例子选择能分支的那一种，以便「失败」这个词有地方可写。不要混用：变长数组的地址不要传给 `free`。

释放的位置要和每一个提前返回配对。失败分支在申请之前返回，没有东西可释放。申请成功之后，任何一条提前离开的路径都要先 `free`。五个赋值都不会失败，所以示例只有成功路径末端那一次释放。一旦中间插入「读到坏数据就返回」，这条路径会漏掉释放。次数少的时候进程马上结束，泄漏仍不可见。把释放收拢到成功路径的末尾，并且让失败发生在申请之前，结构就简单。结构变复杂时再考虑统一的出口标签，而不是复制三遍 `free` 却复制漏一处。

不要用 `realloc` 把块缩小之后仍按旧的次数去读。缩小会把末尾的 19 裁掉，旧次数让循环走到已不属于你的字节。次数要和块一起更新。这五个数的例子不缩小，是因为下午的次数是固定的。

## 小结

按次数申请，检查空指针，写入 18、21、36、22、19，在 `free` 之前做完下标 2 的读取、求和与越线计数，然后释放并置空。栈数组不要 `free`。`free` 两次、释放后读取，都不是这个例子的形状。

即使进程退出时运行时会回收整个堆，仍然要 `free`。本次输出看不出泄漏，循环调用和所有权阅读看得出。下一章把这五个数写进文件再读回来，文件只能落在这次进程预打开的那棵虚拟目录里。

## 练习

申请一块能装下三次 `int` 的存储，写入 21、36、22，打印中间那个，然后释放。期望是 36。失败分支打印「失败」并正常返回。

::: answer 参考答案：三次里的中间
```c run expect="36" title="参考答案"
#include <stdio.h>
#include <stdlib.h>
int main(void) {
  int *readings = malloc(3 * sizeof *readings);
  if (readings == NULL) {
    printf("%s\n", "失败");
    return 0;
  }
  readings[0] = 21;
  readings[1] = 36;
  readings[2] = 22;
  printf("%d\n", readings[1]);
  free(readings);
  return 0;
}
```
:::

申请五个 `int`，全部写成这组读数，数一数严格大于 20 的次数，打印次数后再释放。21、36、22 应当计入，18 和 19 不计入，结果是 3。

::: answer 参考答案：大于二十
```c run expect="3" title="参考答案"
#include <stdio.h>
#include <stdlib.h>
int main(void) {
  int count = 5;
  int *readings = malloc((size_t)count * sizeof *readings);

    printf("%s\n", "失败");
    return 0;
  }
  readings[0] = 18;
  readings[1] = 21;
  readings[2] = 36;
  readings[3] = 22;
  readings[4] = 19;
  for (i = 0; i < count; i = i + 1) {
    if (readings[i] > 20) warm = warm + 1;

```
