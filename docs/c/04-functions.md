循环已经让 `>= 30` 在一个循环体里只写了一次。可是主函数同时还在管存储、计数和打印。下一步若要在两处问「这是不是阳光」，规则仍会复制。函数是给规则一个名字，并规定哪些数从外面进来、哪个数回去。数据还是 18、21、36、22、19，不新添探头。

先写越线。参数是一次读数，返回 1 或 0。返回 `int` 而不是在函数里 `printf`，是因为调用者有时要计数，有时只要第一个，文本会妨碍把结果加进 `hot`。打印留在 `main`，函数保持可计算。取舍是：你不能单跑这个函数就在终端里看见「是」。调试时要多写一行 `printf`。好处是同一个函数既能进循环，也能进以后的断言，不会把「阳光」这个词焊死在英文或中文句子里。

```c run expect="1" title="规则有名字"
#include <stdio.h>
int in_sun(int reading) {
  return reading >= 30;
}
int main(void) {
  int sun = 36;
  printf("%d\n", in_sun(sun));
  return 0;
}
```

36 仍越线，18 若传进去会返回 0。函数体里不要再写死 36。写死之后，名字 `in_sun` 就在撒谎，它只认识一个下午。阈值 30 写在函数里，是因为这是规则的一部分，不是每次调用的数据。若阈值也要变，就再加一个参数。现在不加，避免每个调用都重复 `, 30`，把「规则」和「读数」的地位弄成一样。这是取舍：参数越多，调用越诚实，也越吵。只变读数、不变政策时，政策留在函数体内。

第二次把五次都送进去，数一数。函数每次只看见一个 `int`，看不见数组有多长。长度是调用者的知识。这和后面指针章的痛是同一处伤口，这里先用五个显式调用，让「函数不拥有序列」这件事变得很具体。

```c run expect="1" title="五次各问一次"
#include <stdio.h>
int in_sun(int reading) {
  return reading >= 30;
}
int main(void) {
  int hot = 0;
  hot = hot + in_sun(18);
  hot = hot + in_sun(21);
  hot = hot + in_sun(36);
  hot = hot + in_sun(22);
  hot = hot + in_sun(19);
  printf("%d\n", hot);
  return 0;
}
```

返回值直接加，是因为我们让它是 0 或 1，而不是任意非零。若有人把函数改成「越线就返回温度本身」，36 会加进 `hot`，计数就废了，终端里出现 36，和「有一次」用的是同一个显眼数字，很容易当成计数成功。所以返回值的含义要窄：是就是 1，不是就是 0。不要用温度充当布尔。

第三次把整数平均放进函数，并把坑留在签名能看见的地方。`truncated_mean` 接收和与次数，做的是整数除法。名字里带 truncated，是为了不让调用者以为回去的是 23.2。若名字只叫 `mean`，116 和 5 进去、23 出来，调用者会在散文里把 23 说成平均温度。名字是函数能提供的、编译器并不检查的那一部分契约。编译器检查的是类型：两个 `int` 进去，一个 `int` 出来，除法种类已经被类型决定了。

```c run expect="23" title="截断写在名字里"
#include <stdio.h>
int truncated_mean(int sum, int count) {
  return sum / count;
}
int main(void) {
  int sum = 18 + 21 + 36 + 22 + 19;
  printf("%d\n", truncated_mean(sum, 5));
  return 0;
}
```

`count` 为 0 时，这个函数是未定义行为，整数除以零没有结果。五个读数的例子不会触发，所以不要在这里加一套复杂的错误码来表演健壮。但要知道边界：若以后次数来自输入，调用前必须判断 `count != 0`。判断放在调用者还是放在函数里，取舍如下。放在函数里，所有调用者都安全，函数得决定返回什么来表示「没有平均」。放在调用者里，函数保持一条除法，短，可是任何一个新调用者都可能忘。温度日志若可能是空文件，我倾向在函数里拒绝，返回一个单独的状态，而不是返回 0，因为 0 度是合法平均。这一章的数据不空，函数保持一条除法，拒绝的设计等到输入那一章有失败可谈时再写。

参数是按值传递的。函数里给 `reading` 加一，调用者的变量不变。这是优点：`in_sun` 不能悄悄改掉 36。也是限制：你无法通过 `in_sun` 把越线的那一次替换成一个标记。需要改调用者的数据时，要传指针，那是后面的章。现在不要用全局变量绕过这个限制。全局的 `last_reading` 会让函数看起来没有参数，实际上依赖上次调用留下的值，而每次 Run 虽然是新进程，同一次运行里的两次调用仍会互相污染。五个数的判断应当只依赖传进去的那一个数。

声明要写在调用之前，或者先写原型。C 编译器从前到后读这个文件。`main` 在 `in_sun` 上面时，需要一行 `int in_sun(int reading);`。原型里的参数名可以省略，写成 `int in_sun(int);`，但留下名字，读的人不必翻到定义才知道那一个 `int` 是读数不是阈值。定义和原型不一致时，编译会失败，这是你想要的失败。不要在原型里写 `int`、在定义里改成 `double` 还期望隐式转换救你。隐式转换发生在调用点的实参，不负责把两份声明焊成同一件事。

`static` 函数只在本文件可见。这里本来就只有一个文件，`static` 的链接意义不大，但它表达「不是给别的翻译单元用的」。等你离开抽屉，把文件拆开时，忘记 `static` 的辅助函数会变成全局符号，名字 `in_sun` 很容易和别人的冲突。现在就加上也行，不加也能链接。示例为了短，没加。知道这个取舍即可：单文件里它不改变输出，多文件里它改变名字是否外泄。

返回类型写成 `void` 的函数表示没有值。打印函数可以是 `void`。一旦 `void`，你就不能把它放进 `hot + ...`。选返回类型就是在选它能不能参加表达式。越线判断要参加加法，所以不是 `void`。平均要变成 `printf` 的参数，所以不是 `void`。若函数既打印又返回，调用者会得到双份结果，终端里的 1 可能来自函数内部，也可能来自 `main`，调试时对不上。一件事一条路：计算的不打印，打印的放在 `main`。

还有一个编译器会帮上忙的坑。非 `void` 函数若走到末尾却没有 `return`，诊断会响，`-Werror` 下这个函数写不进可运行示例。`main` 在标准里有豁免，其他函数没有。写 `in_sun` 时不要依赖「忘了返回就会返回 0」。那不是规定。有的路径 `return 1`，另一条路径什么都不写，越线判断会在不越线时变成垃圾，而垃圾可能碰巧非零，于是 18 度也被算成阳光。每条路径都要有 `return`。

函数不要为了五个数去递归。递归阶乘对温度没有意义，也更容易在 wasm 的有限栈上把自己撑满。这组数据的结构是平的序列，循环加函数足够。递归适合树，探头的下午不是树。

五次分开的调用还有一个次序问题。调用本身没有记忆，`in_sun(18)` 不会知道自己是第一次。若规则变成「只有第一次越线才计数」，函数必须额外收到一个「前面是否已经越线」的参数，或者调用者自己保持这个状态。把状态藏进函数内部的静态变量，能让调用看起来仍是一个参数，下一次调用却看见上一次的残留。同一次运行里，你先用练习数据跑一遍，再跑正式的五次，静态变量会把练习的越线带到正式统计里。每次 Run 是新进程，救不了同一次进程里的两次调用。这组读数的判断不需要记忆，所以函数不设静态数据。需要记忆时，把记忆放在调用者的局部变量里，参数传进去，结束就随着栈帧消失。

参数个数也是契约的宽度。只传读数，函数可以在任何循环里用。再传一个阈值，政策就可以按下午调整。再传一个单位，华氏就不会被误伤。每加一个参数，所有调用都要改。五个显式调用改起来还行，将来从数组循环里调用，改一处调用就行。所以参数不要为了「将来也许要」提前堆上。单位留到结构体里，和温度绑在一起，比多一个很容易被传错的 `char` 更不容易错位。函数这一章故意只收 `int`，让你看见最窄的契约长什么样。窄契约的缺点是表达不了单位，优点是你无法把参数位置填反。

返回 `int` 的 0 和 1 还可以直接当数组下标，例如 `bucket[in_sun(reading)]` 把读数分进两格。这很紧凑，也很脆：一旦有人把返回值改成温度本身，下标就变成 36，数组远远没有那么长。返回值的取值集合是契约的另一半。名字、类型和取值集合，编译器只检查中间那一项。另外两项靠你在函数顶上用一句注释写明，并在所有路径上遵守。注释若只重复 `return reading >= 30` 的同义词，没有增加信息。注释应当写「返回 1 或 0，不是温度」。

内联与否不要在源码里猜测。这个目标会做优化，短函数可能被展开，也可能仍是一次调用。展开不改变返回的 23 或 1。为了「性能」把函数拆回 `main` 里复制五份，省下的调用在五个整数上测不出来，复制带来的规则漂移却测得出来。先留函数。等计数变成热点，再看生成的代码，而不是在教学例子里提前展开。

调用的开销不要用「五次太少」来否定函数，也不要用来否定内联以外的所有抽象。真正要避免的是函数在返回值里夹带打印。一旦 `in_sun` 自己 `printf`，五次调用会在次数之外多出五行，期望子串里的 1 不再独占终端，你很难判断它来自返回值还是来自函数内部。计算留下返回值，副作用留给 `main` 的那一次打印。

## 小结

`in_sun` 把 `>= 30` 收成一个返回 0 或 1 的函数，五次调用加起来仍是 1。它不打印，也不改调用者的变量，因为参数按值传递。阈值留在函数里，读数从参数进来。

`truncated_mean` 做的仍是整数除法，116 和 5 得到 23。名字把截断说出来，类型已经决定了运算种类。次数为 0 时不要调用。下一章把五次读数放进真正的数组，并面对「函数里问不出数组有多长」。

## 练习

写一个函数，判断读数是否小于 22，返回 0 或 1。在 `main` 里对 22 调用一次，应当打印 0，因为条件是严格小于，边界不算。

::: answer 参考答案：边界不算
```c run expect="0" title="参考答案"
#include <stdio.h>
int below_22(int reading) {
  return reading < 22;
}
int main(void) {
  printf("%d\n", below_22(22));
  return 0;
}
```
:::

写一个函数接收两个 `int` 读数并返回较大者。用 36 和 22 调用，打印 36。不要在函数里假设这两个数来自固定下标。

::: answer 参考答案：较大的一次
```c run expect="36" title="参考答案"
#include <stdio.h>
int warmer(int left, int right) {
  if (left > right) return left;
  return right;
}
int main(void) {
  printf("%d\n", warmer(36, 22));
  return 0;
}
```
:::
