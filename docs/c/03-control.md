23 和 23.2 已经分开了。现在要问的是另一句人话：这个下午，探头有没有被太阳直射。数据仍是按时间排列的 18、21、36、22、19。规则先定成「不小于 30」。30 是人为阈值，不是语言的一部分。定成 30 是因为其余四次都在 22 以下，只有 36 越线，例子不会出现两个都靠边界的含糊点。你以后换成 25 或 40，结构不用改，结论会变。先用一次比较把 36 认出来。

```c run expect="1" title="越线"
#include <stdio.h>
int main(void) {
  int sun = 36;
  printf("%d\n", sun >= 30);
  return 0;
}
```

比较表达式的值是 `int`，成立为 1，不成立为 0。印出 1 是在看条件的结果，不是在看温度。若印的是温度本身，36 当然也非零，你会误以为「用读数当 `if` 的条件」很合理。上一章说过 0 度会把这个习惯打穿。这里即使没有 0 度，也把比较写全：`sun >= 30`。不要写 `if (sun = 30)`。单个等号是赋值，赋值表达式的值是 30，非零，条件恒真，而且 `sun` 被改成了 30，下午的异常点就在源码里消失了。这份 clang 对「把赋值当条件」默认会警告，`-Werror` 下编译失败。失败是保护。想赋值就写成一条独立的语句；想比较就用 `==` 或 `>=`。

一次比较不够，因为五次读数都要过同一条规则。把五条 `if` 抄开，规则就会漂移：其中一条写成 `> 30`，36 仍然命中，21 也仍然不命中，你看不出抄写错误。等到某天出现恰好 30 的读数，五条分支里才会有一条悄悄不同意。循环的意义不是少打字，是让规则只存在一份。

```c run expect="1" title="数越线次数"
#include <stdio.h>
int main(void) {
  int room0 = 18;
  int room1 = 21;
  int room2 = 36;
  int room3 = 22;
  int room4 = 19;
  int hot = 0;
  if (room0 >= 30) hot = hot + 1;
  if (room1 >= 30) hot = hot + 1;
  if (room2 >= 30) hot = hot + 1;
  if (room3 >= 30) hot = hot + 1;
  if (room4 >= 30) hot = hot + 1;
  printf("%d\n", hot);
  return 0;
}
```

这段故意还不用数组。五个名字很丑，正是为了让你感到复制的疼痛。计数结果是 1，只有 36 被加进 `hot`。注意 `hot = hot + 1` 发生在条件成立时。若你把加一写到 `if` 外面，`hot` 会变成 5，那是次数，不是越线次数。终端里的 5 很眼熟，因为读数就是五个，所以这个错误看起来「像那么回事」。核对时要能指出哪一个数越线，而不是只看一个整数顺不顺眼。

数组还没正式讲，但循环需要一个下标能摸到的序列。这里用一个很局部的写法把五个 `int` 排好，只为控制流服务。下标从 0 开始，最后一次是下标 4。循环条件用 `< 5`，不要用 `<= 5`。多走一步会读到数组外面，那是未定义行为，这个例子不演示崩溃。

```c run expect="36" title="停在第一次越线"
#include <stdio.h>
int main(void) {
  int room[5];
  int i;
  int found;
  room[0] = 18;
  room[1] = 21;
  room[2] = 36;
  room[3] = 22;
  room[4] = 19;
  found = 0;
  for (i = 0; i < 5; i = i + 1) {
    if (room[i] >= 30) {
      found = room[i];
      break;
    }
  }
  printf("%d\n", found);
  return 0;
}
```

`for` 把初值、条件和步进放在头部，是为了让「忘了把 `i` 加上一」这种死循环少一个窝。三个位置空着也能编译，空的条件被视为恒真，那就是死循环，抽屉的运行有超时，超时不是温度。把步进写在头部，读的人不必在循环体末尾找 `i = i + 1`。`for (int i = 0; ...)` 这种把声明放进头部的写法在这里可用，上面写成事先声明，只是想让 `found` 和 `i` 的生存期一样显眼。

`break` 跳出的是最近的循环，不是跳出 `if`。找到 36 就停，是因为问题被定义成「有没有、第一次是多少」。按时间顺序，第一次越线就是太阳开始直射的时刻，后面的 22 和 19 对这个问题没有贡献。取舍要说清楚。提前停省掉剩余次数，也让你失去「一共几次」的信息。这组数据里越线只有一次，提前停和数完全部，印出来的代表值可以都是 36，于是你看不出两种问题的差别。若把规则改成统计次数，`break` 就是错的，它会在第一次之后把后面的越线丢掉。问题变了，控制流就该变，不要把 `break` 当成循环的固定装饰。

`continue` 则是跳过这一轮的剩余语句，进入下一轮。用在这里可以写成：小于 30 就 `continue`，否则累加。效果和 `if` 包住累加相同。它的价值出现在循环体变长的时候，让「不关心的读数」尽早离开视线。代价是阅读时要记得后面的语句对这一轮不执行，缩进不再是唯一线索。五个语句的循环用 `if` 更直；十几行的滤波里，`continue` 才挣回复杂度。不要为了用过一次关键字而在短循环里写成跳跃。

`while` 适合「次数事先不知道」的读取，例如后面从标准输入一直读到结束。这里次数就是 5，`for` 更诚实。若用 `while (i < 5)`，你必须自己写 `i = 0` 和 `i = i + 1`。少写步进，循环不会结束，36 会被一直处理。编译器不把这当成错误，因为恒真与否它并不总能断定，而且你可能是故意的。控制流的坑有一部分编译器会拦（赋值当条件），有一部分只会变成超时（忘了步进）。拦得住的不要绕开，拦不住的要在头部把步进放在眼睛看得到的地方。

`switch` 适合少量离散的类别，不适合温度这种连续量。把 18、21、36 各写一个 `case` 是脆弱的：探头下次读到 20 就会掉进 `default`。用区间判断放在 `if` / `else if` 里。`switch` 若用，记得每个分支的 `break`，否则控制会落入下一个 `case`。落入有时是故意的共享代码，更多时候是忘了。温度分类用比较，就碰不到落入这个坑，这也是选择语句种类的理由之一。

再看一个和整数除法接上的判断。若有人用平均温度 23 去和 30 比，结论是「没越线」。这个结论对平均值成立，对下午不成立。循环看的是每一次，不是看商。把 `sum / 5 >= 30` 当成「有没有被太阳直射」，是把两种问题焊在一起。源码里应该出现对 `room[i]` 的比较，平均值另说。

零次越线时 `found` 保持 0。0 和「第一次读数就是 0 度」分不清。这组数据里没有这个麻烦，因为越线的值是 36，没找到时我们印 0 只是初始值。更干净的做法是另用一个 `int seen = 0` 表示有没有，温度另放。例子为了只印一个数，让 `found` 兼任，这是短示例的妥协，不是建议你在告警系统里用 0 度表示「无」。告警系统里的「无」应当是单独的状态。结构体那一章会有地方放这个状态，现在先记住妥协的边界。

下标从 0 开始这件事会在循环里再咬一次。若把 `for` 的初值写成 1，条件仍是 `i < 5`，18 被跳过，36 仍会被看见，越线计数还是 1。测试若只检查越线次数，错误是绿的。最早的那一次从统计里消失，以后你若改去数「低于 22」的次数，18 的缺席才会把 3 变成 2。所以例子既打印越线，也在练习里打印另一种计数。一种期望保不住全部边界。写循环时用一次真实的首元素和一次真实的末元素分别核对，而不是只拿最显眼的 36 当全部证据。

`else if` 适合互斥的区间。低于 20、20 到 29、不小于 30，可以分成三档。36 进第三档，18 和 19 进第一档，21 和 22 进第二档。区间的边界只能归一边。若两个条件都写成 `>= 20` 和 `>= 30` 却没有 `else`，36 会同时进入两档，计数重叠。`else` 的意义是互斥，不是为了少写花括号。花括号仍然要写。单行 `if` 省略花括号时，后面再插入一条「调试用的打印」，那条打印会落到条件外面，每次都执行。五个读数的循环会多印五行，看起来像规则坏了，其实是悬挂的语句。这个抽屉的示例都带花括号，就是为了让下一行归谁所有这件事由括号决定，不由眼睛决定。

循环变量不要在体内改到和头部步进打架。头部已经 `i = i + 1`，体内再 `i = i + 1` 会跳着看，21 或 22 会消失。36 若恰好还被踩到，越线结论仍对，缺席的读数没有发言权。步进只放一处。需要提前结束就用 `break`，不要把 `i` 改成 5 来伪装结束。改 `i` 能停，但读代码的人要同时理解头部和体内两处对同一个变量的写，停的原因就分散了。

条件里调用函数是可以的，只要函数不改数组。判断越线若会把读数封顶，写在 `if` 的条件里就会让「问一句」变成「改一处」。条件应当像问题，不像手续。手续放在条件为真的分支里，并且花括号把它包住。

还有一种沉默的边界错误：循环写对了，阈值写在了错误的一侧。`reading > 30` 对 36 仍然为真，对恰好 30 的读数为假。这组数据里没有 30，所以 `>` 和 `>=` 印出的越线次数都是 1。练习里「严格小于 22」把 22 留在外面，正是为了让等号的取舍被看见。你在主路径上选用 `>= 30` 时，应在注释里写明 30 本身算越线。不写的话，下一位读者会按数学习惯改成 `>`，而测试数据又帮他隐瞒。测试数据要包含边界，否则分支的等号没有被执行过。

循环结束后要看循环变量停在哪。正常走完时 `i` 等于 5，提前 `break` 时 `i` 等于越线的下标 2。若在循环后无条件打印 `room[i]`，走完的情况下会越界。需要「最后停在哪」时，用单独的变量在循环内记下下标，循环后再读那个变量。不要复用已经走到终点外面的 `i`。把下标记在 `found_at` 这类单独的名字里，循环条件才不会和结果打架。没有找到时让这个名字保持 -1，避免和合法下标 0 混成同一种「停在开头」的假象。

## 小结

规则只写一份。`>= 30` 作用在每一次读数上，五次里只有 36 使它为真，计数是 1。`if (sun = 30)` 这种赋值会被 `-Werror` 拦住，比较用 `>=` 或 `==`。`for` 把步进放在头部，边界用 `< 5`。

`break` 回答「第一次越线是多少」，不回答「一共几次」。问题若是计数，就不要提前停。平均值 23 没有越线，不代表下午没有。下一章把 `>= 30` 和截断平均放进函数，避免循环里再抄一遍规则。数据仍然是这五个数。

## 练习

数一数有多少次读数严格小于 22。18、21、19 三次应当计入，22 本身不计入，36 不计入。用循环或并列的 `if` 都可以，但阈值只能出现一次比较运算符的右边，不要手写一个常量 3 来冒充统计。手写 3 会让测试在你改阈值之前一直是绿的。

::: answer 参考答案：低于二十二
```c run expect="3" title="参考答案"
#include <stdio.h>
int main(void) {
  int room[5];
  int i;
  int cool;
  room[0] = 18;
  room[1] = 21;
  room[2] = 36;
  room[3] = 22;
  room[4] = 19;
  cool = 0;
  for (i = 0; i < 5; i = i + 1) {
    if (room[i] < 22) cool = cool + 1;
  }
  printf("%d\n", cool);
  return 0;
}
```
:::

不使用 `break`，找出五次里的最大值并打印。应当仍然是 36。这道题用来确认你能在不提前退出的情况下看完整个下午。

::: answer 参考答案：看完再取最大
```c run expect="36" title="参考答案"
#include <stdio.h>
int main(void) {
  int room[5];
  int i;
  int max;
  room[0] = 18;
  room[1] = 21;
  room[2] = 36;
  room[3] = 22;
  room[4] = 19;
  max = room[0];
  for (i = 1; i < 5; i = i + 1) {
    if (room[i] > max) max = room[i];
  }
  printf("%d\n", max);
  return 0;
}
```
