On one filesystem, mv is usually just a rename. /tmp on this image is a single tmpfs, so the rename does not copy the bytes.

### A rename is a move within one filesystem

The old path vanishes and the new path appears. cat on the new path should return the text written before the move.

```linux run expect="hi" title="Text under the new name"
echo hi > /tmp/old && mv /tmp/old /tmp/new && cat /tmp/new
```

The new path contains `hi`.

### An existing target is replaced

If /tmp/new already holds different text, a later mv overwrites it. BusyBox does not ask first.

```linux run expect="fresh" title="Text after the replacement"
echo old > /tmp/new && echo fresh > /tmp/fresh && mv /tmp/fresh /tmp/new && cat /tmp/new
```

The surviving text is `fresh`.

### A move into another directory needs the full target

If you name only the directory, the filename is left inside it. ls should list leaf.

```linux run expect="leaf" title="The filename inside the directory"
mkdir -p /tmp/mvdir && echo hi > /tmp/leaf && mv /tmp/leaf /tmp/mvdir && ls --color=never -1 /tmp/mvdir
```

The directory contains `leaf`.
