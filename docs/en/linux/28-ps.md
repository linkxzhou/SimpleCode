ps reads the process table inside the guest. The browser and the editor live on the host, so they never appear in this table.

### ps lists the processes that exist now

The header's first column is PID. init is process 1, and the script's own sh is listed too.

```linux run expect="PID" title="The header row"
ps | head -n 1
```

The header begins with `PID`.

### BusyBox columns are not the procps columns

You get PID, USER, and COMMAND. There is no long GNU stretch of STAT and TIME. The expectation locks the word COMMAND.

```linux run expect="COMMAND" title="The command column"
ps | head -n 1
```

The header includes `COMMAND`.

### Host browser processes stay invisible

The visible rows are init, kernel threads, and the current sh. A browser tab on the host is absent from the table.

```linux run expect="init" title="Process 1"
ps | grep init
```

A row mentions `init`.
