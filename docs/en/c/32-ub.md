Undefined behavior is a form the standard does not assign a result to. It might print some number, or it might stop the run, so it cannot be the expected output of a sample. Checks that have a defined answer stay in the runnable programs. Overflow and use after free stay as shapes only.

### Do not read a null pointer

`p` is null. The test comes before any dereference. This run takes the skip branch and prints `skip`.

```c run expect="skip" title="Test for null first"
#include <stdio.h>
int main(void) {
  int *p = NULL;
  if (!p) {
    printf("skip\n");
    return 0;
  }
  printf("%d\n", *p);
  return 0;
}
```

The null pointer is skipped, and the line is `skip`.

### Check the index first

The array has three cells, so the legal indexes are 0, 1, and 2. `i` is 1, which is inside that range, and the cell holds 5. If `i` were 3, that branch would not read the array.

```c run expect="5" title="Index in range"
#include <stdio.h>
int main(void) {
  int a[3] = {4, 5, 6};
  int i = 1;
  if (i < 0 || i >= 3) {
    printf("out\n");
    return 0;
  }
  printf("%d\n", a[i]);
  return 0;
}
```

Index 1 holds 5.

### Overflow stays unread

`INT_MAX + 1` is undefined for a signed `int`. The listing below is not run. A number that happens to appear in one execution is not a specified result.

```c norun title="Signed overflow"
#include <limits.h>
#include <stdio.h>
int main(void) {
  int x = INT_MAX;
  printf("%d\n", x + 1);
  return 0;
}
```

The listing shows the shape only. The button does not compile it.

### Exercise: copy, then free

The heap value 4 is copied into `saved` before `free`. After that, only the copy is printed. The original pointer is not touched. Use after free is also undefined, so that line is not written here.

```c run expect="4" title="Copy before free"
#include <stdio.h>
#include <stdlib.h>
int main(void) {
  int *p = malloc(sizeof *p);
  int saved;
  if (!p) return 1;
  *p = 4;
  saved = *p;
  free(p);
  printf("%d\n", saved);
  return 0;
}
```

The copy is 4.
