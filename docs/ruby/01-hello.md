puts 把对象打到标准输出，并在末尾加换行。print 不加换行，下一次输出会接在同一行。教学里多数时候用 puts，这样一行输出对应一次调用。注释从 # 开始直到行尾，解释器跳过。注释写错不会让程序失败，却会让你按错误的说明去改对的代码。

字符串外面的引号不属于输出。要在句子里出现引号，外层和内层互换单双引号。puts 多个参数时，每个参数各占一行，而不是用空格拼在一行。这和 Python 的 print 不同，刚从 Python 过来时最容易看错。

空行可以随便留，它不改变语法。缩进在 Ruby 里不是语法，只是给人看的。本教程仍把方法体缩进两个空格，让块的边界清楚。

```ruby run expect="Ada" title="两行"
puts "Ada"
puts "Lovelace"
```

```ruby run expect="AB" title="不换行"
print "A"
puts "B"
```

```ruby run expect="可见" title="注释"
puts "可见"
# 这一行不会出现
puts 2026
```

### 只改一处：两行

这一例要避开的失误是：以为 puts 的多个参数会像 Python 那样用空格连成一行。。对应的做法是：一次 puts 对应一行需要核对的输出。。

把代码收成一行来核对：`puts "Ada" puts "Lovelace"`。盖住终端，先写下预测，里面要能找到「Ada」。然后点这个代码块上的 Run。结果不同时，只改产生该值的那一行，再用工具栏的 Run 看新结果。不要把两处不相关的改动叠在一起。确认之后点撤销，下一例才会从文档里的代码开始。

若出现报错，先看错误类型的名字，再回到本章的常见错误。期望是子串，多出来的说明行不算失败，缺了「Ada」才算失败。

## 读完再动手

本章要留下的是 「用 puts 和 print 打出文本」、「写出注释」、「知道 puts 会换行」。合上抽屉之前，用自己的话说出每一项目标对应哪一个示例的标题。对不上标题，就还没有把目标和代码连起来，先别展开练习答案。

练习的答案默认折着。先在编辑器里自己写，再展开对照。对照时只看输出是否包含期望的那几个字。两道都过了再进入下一章。下一次运行是新进程，这次的变量不会留下。

把这一章当成一次可以反复撤销的实验。点代码块上的 Run 会用示例覆盖编辑器，原来的草稿先备份。你改过的内容如果还想留着，先复制到别处，再点下一例。工具栏的 Run 不会从文档重写编辑器，所以它用来看你改过的版本。两种按钮各做各的事。下载进度写在按钮旁边，第一次打开这种语言时要等它结束，再判断示例是不是写错了。

记录你预测错的那一次。写下你以为会打印的文字，以及实际多出来或少掉的部分。进入下一章之前，要能用一句话说清差在哪。通过只说明期望的那几个字还在，不说明你已经看懂产生它的那一行。章节标题下的目标就是这份验收清单。差两个字也不要靠改期望凑过去。

## 常见错误

- 以为 puts 的多个参数会像 Python 那样用空格连成一行。
- 用 print 之后忘了最后一次要换行，下一行结果粘在一起。
- 注释里写了和代码相反的话，过几天按注释把程序改错。

## 最佳实践

- 一次 puts 对应一行需要核对的输出。
- 注释只写代码看不出来的约束。
- 方法体统一缩进两个空格。

## 小结

puts 负责换行输出，print 接在同一行，# 后面的文字会被跳过。多个参数的 puts 是多行，不是一行。
