条件句在很多语言里问的是「这个值像不像零」。Ruby 问的是另一件事：它是不是那两个专门表示否定的对象之一。只有 `nil` 和 `false` 会让 `if`、`while` 和三元表达式走失败的一支。整数 `0`、空字符串 `""`、空数组、空哈希都走成功的一支。这个规则让「没有值」和「值是零」能够同时存在。分数系统需要这种区分：还没登分，和登了零分，不是同一种记录。把两者都压成假，你就无法写出「零分也要归档」。

代价是从 C 或 Python 来的人会在 `0` 和 `""` 上连续判断错。Python 里空字符串是假，Ruby 里不是。你不能把「真值」理解成「有内容」。空字符串是一个真实的字符串对象，它的长度是 `0`，它本身却不是 `nil`。备注栏存在但还没写字，和备注栏这个字段根本没有，在数据上应该不同。若语言把空串当成假，你得另找一个哨兵来表示「字段缺失」，通常又会发明一个和空串很难分辨的约定。

这一章的分数叫 `score`，备注叫 `note`。两者都从「有值但空」出发：`score = 0`，`note = ""`。三元表达式用括号把整段交给 `puts`，避免和输出方法的返回值缠在一起。条件位置上放的是变量，不是字面量。直接写 `if ""` 会让解释器发出「字符串字面量出现在条件里」的警告，因为那一枝永远成立，多半是笔误。变量里的空串不会触发这句警告，行为上仍然为真。警告在抱怨字面量，不是在改变真值规则。

```ruby run expect="零分也算数" title="零和空串都走真分支"
score = 0
note = ""
puts(score ? "零分也算数" : "当成没有")
puts(note ? "空备注也算有" : "当成没有")
```

两行都走了真分支。`score` 是 `0` 也打印「零分也算数」。若业务想把零分显示成不及格，那是和 `60` 比较的结果，不是真值。比较 `score >= 60` 得到的是 `true` 或 `false`，那两个对象才参与真值。跳过比较、直接把分数放进 `if`，零分会被当成「有分数」，高分也一样。真值不携带大小。

缺失用 `nil`。还没登分时，变量指向 `nil`，三元表达式走假分支，文字用「还没登分」。`false` 则适合一种明确的否定，比如「未提交」。两者都是假，但类不同，`nil` 表示空，`false` 表示否。你若用 `false` 存放「还没登分」，后面一旦调用 `score + 1` 会失败，因为 `false` 不能加。用 `nil` 同样不能加。差别在阅读：看到 `false` 会以为有人做过一次判断，看到 `nil` 会以为这个槽还没放进分数。选错哨兵不会在真值上立刻爆，会在下一个方法调用上爆。

```ruby run expect="还没登分" title="nil 和 false 走假分支"
score = nil
puts(score ? "有分数" : "还没登分")
submitted = false
puts(submitted ? "已提交" : "未提交")
```

第二行是「未提交」。`submitted` 没有拿去和 `score` 混成一个变量，因为一个槽里先后塞 `nil` 和 `false` 会让读的人不知道现在是缺失还是否定。两个名字，两种哨兵。

`||` 和 `||=` 使用同一套真值。`a || b` 在 `a` 为真时返回 `a`，否则返回 `b`。它返回的是对象本身，不一定是 `true` 或 `false`。`0 || 60` 的结果是 `0`，因为 `0` 已经为真，右边根本不算。`nil || 60` 的结果是 `60`。`||=` 是「左边为假时才赋值」的缩写。人们用它填默认值，心里想的常常是「如果还是空的就填上」。空的含义一旦放宽到 `0`，默认值就会把合法的零分覆盖成及格线。这是这条规则最贵的坑，出在你最想偷懒的那一行。

```ruby run expect="0" title="默认值盖不住零"
score = 0
score ||= 60
puts score
missing = nil
missing ||= 60
puts missing
```

第一行保持 `0`，第二行变成 `60`。`missing` 从 `nil` 起步，`||=` 才工作。想给「未填写」默认分，槽里应该是 `nil`，不是 `0`。已经知道是零分，就不要再写 `||=`。想把低于 `60` 的分数抬上去，写比较：`score < 60`。比较看的是大小，`||=` 看的是真值，两套问题不要用一个运算符回答。

`&&` 也返回对象，不强制变成布尔。`score && score + 1` 在 `score` 为 `nil` 时短路，返回 `nil`，不会去算加法。在 `score` 为 `0` 时不短路，返回 `1`。短路是真值规则的好处：你可以用 `score && score.even?` 在缺失时跳过方法。坏处是 `0` 不会触发这层保护，而有时你希望「零分就别再算」。那种希望要写成 `score.nil?` 或 `score == nil`，把问题说成「是不是缺失」，而不是「是不是真」。`nil?` 只对 `nil` 为真，`false.nil?` 为假。问缺失就用 `nil?`，问否定就用 `== false` 或直接把布尔放进条件。`!score` 会把 `nil` 和 `false` 都变成 `true`，也会把 `0` 变成 `false`。感叹号回答的是「真值的反面」，不是「这个数是不是零」。

空数组和空哈希同样为真。`[]` 表示一份已经存在、还没有元素的清单，和 `nil` 表示「清单都没有」不同。后面用数组装书名时，空清单仍能调用 `each`，`nil` 则不能。真值为真，不等于方法一定成功，只等于条件会走进去。走进去之后，`0` 仍可能让除法失败，空数组仍可能让「取第一本」得到 `nil`。条件过了，还要处理值域。

`and` 与 `or` 的真值规则和 `&&`、`||` 相同，优先级更低，低到能切开赋值。`score = nil or 60` 的解析会让人吃惊，常常不是你要的默认值。需要默认值时用 `||` 或 `||=`，并且先确认左边的假只包括 `nil` 和 `false`。这一章的例子不用 `and`、`or`，就是为了少一条优先级。你若在别人的脚本里看见它们，先补括号再读，不要凭英语单词去猜结合顺序。

把 `score` 从 `nil` 填成 `0` 之后，再问一次真值，会从「还没登分」变成「零分也算数」。同一次运行里可以演示这个转变。先打印缺失，再绑定 `0`，再打印零分。不要用 `||=` 做第二步，因为 `||=` 在你把 `0` 写进去时不会再改它，但若你写成 `score ||= 0` 而原来是 `nil`，结果是 `0`，看起来像对了；原来若已经是 `false`，也会被改成 `0`。`false` 和 `nil` 都会被 `||=` 替换。若 `submitted` 那种布尔误放进分数槽，`||=` 会把「未提交」变成数字。槽的类型要稳。

```ruby run expect="零分也算数" title="缺失填上零之后"
score = nil
puts(score ? "零分也算数" : "还没登分")
score = 0
puts(score ? "零分也算数" : "还没登分")
note = ""
puts(note.empty? ? "备注空着" : "备注有字")
puts(note ? "空备注也算有" : "当成没有")
```

四行里，第一行是「还没登分」，第二行变成「零分也算数」。第三行用 `empty?` 问长度，得到「备注空着」。第四行用真值，得到「空备注也算有」。`empty?` 和真值可以同时为真：字符串是空的，对象却存在。要不要接受空备注，是 `empty?` 的问题。字段在不在，是真值或 `nil?` 的问题。两句都打印，是为了防止以后只留一句，把两种问题焊死。

`case` 用 `===` 做分支，和真值不是同一个开关。这一章不展开 `case`。只提醒：你不能用「`when 0` 接住所有假值」这种想法，因为 `0` 不是假，而且 `when` 比的是匹配，不是真值。分数档用比较写在 `if` 里更直接。

`while score` 这种循环在 `score` 为 `0` 时不会停，因为 `0` 一直为真。倒计时应当写 `while score > 0`，让比较产生 `true` 或 `false`。循环条件沿用真值规则，和 `if` 是同一条。人们在分支里记住了「零要单独比」，到了循环又把数字本身当条件，于是零分的记录会让循环空转到你打断它。课程的可运行例子不写这种循环。写的时候先把条件读成「缺失或否定吗」，若你的本意是「数完了吗」，就改成比较。

`unless` 是 `if` 的反面，真值表不变，只是分支对调。`unless score` 在零分时不会进去，因为零分为真。它适合 `unless score.nil?` 这种已经是否定的句子。再套一层否定，读的人要在脑子里翻转两次。分数脚本里优先用 `if score.nil?` 和 `if score >= 60`，把「缺失」和「低于线」写成正面的问题。`unless` 省掉一个 `else` 的场合，是整个方法只在否定时提前返回。那种句子保持很短，里面不要再放三元表达式。

`!!score` 把任意对象收成真正的 `true` 或 `false`。`!!0` 是 `true`，`!!nil` 是 `false`。需要把「有没有分数」存进一个布尔字段时，这比直接存 `score` 更不容易把 `0` 和缺失混掉，前提是你承认零分也算「有」。若零分应该算「没有有效成绩」，`!!` 是错的工具，比较才是。`!!` 的代价是原来的数字没了，你不能再从布尔还原出 `0`。`||` 会保留原对象，`!!` 会丢掉。选择看你下一步要数字还是要布尔。

空数组为真，所以 `if items` 不能用来判断「有没有元素」。书单要问 `empty?` 或 `length`。这一条和空字符串的 `empty?` 是同一个分裂：对象在，内容空。哈希也一样。容器那两章会用到非空的例子，真值不会替你检查长度。在条件里写容器变量之前，先决定你在问字段是否缺失，还是在问元素个数。

`or` 的优先级低于赋值。`score = nil or 60` 先把 `nil` 赋给 `score`，再拿这次赋值的结果去和 `60` 做 `or`。整个表达式的值是 `60`，但这个 `60` 没有写进 `score`。`score` 仍是 `nil`。下一行若打印变量，你会以为默认值没生效，其实表达式的值被丢掉了。`score = nil || 60` 才会得到 `60`，因为 `||` 比赋值更紧，右边先算完再赋。优先级用错时没有异常，变量里留着缺失，后面的加法才会爆。需要默认值就用 `||` 或 `||=`，并且记住它们盖不住 `0`。

```ruby run expect="nil" title="or 不会把默认值赋进去"
score = nil or 60
puts score.inspect
fixed = nil || 60
puts fixed
```

`case` 的 `when` 用 `===` 匹配，不看真值。`when 0` 只接住整数 `0` 这个值，不接住 `nil` 或 `false`。你不能写一个 `when` 去收「所有假」。假只有两个对象，真有无数个，所以分支表适合列举你关心的分数档，不适合列举真值。分数档用范围 `when 0...60` 这种半开区间时，右端不包含，和切片的「长度」不是同一套数字，别混着记。`0...60` 包含 `0`，不包含 `60`。`60` 若要算及格，放进下一档。区间的右端政策写错一位，及格线就会偏。

`tap` 和条件无关，提它只为了防止一种写法：有人用 `score && score.tap { ... }` 来「有分数才做事」。零分会进去，缺失不会。这仍然是真值，不是「分数有效」。有效无效要看你有没有用 `Integer` 成功转换过，或者有没有和及格线比较过。真值只回答哨兵问题。把业务词「有效」直接映射到真，会让零分变成有效成绩里的隐形人，报表里有他，分支里却像没有。

三元表达式的条件位置同样只认 `nil` 和 `false`。把 `score` 放进去之前先问自己：我是在问有没有这个数，还是在问它够不够格。不够格必须写成比较。比较的结果才是布尔。布尔放进三元表达式，零分和六十分才会走向不同的句子。

## 小结

`score = 0` 和 `note = ""` 都会让三元表达式走到真的一支。只有 `nil` 和 `false` 走到假的一支。零分因此可以和「还没登分」分开。空备注也可以和「没有备注栏」分开。比较大小用 `>=`，问是不是空的用 `empty?`，不要把这两件事交给真值。

`||=` 只在左边为 `nil` 或 `false` 时写入。它盖不住合法的 `0`，这通常是你想要的；若你本想用它填充零分，它会什么都不做。`&&` 和 `||` 返回操作数本身，短路能挡住对 `nil` 的调用，挡不住对 `0` 的调用。问缺失用 `nil?`。直接把字符串字面量放进 `if` 会得到警告，因为那一枝恒真。
