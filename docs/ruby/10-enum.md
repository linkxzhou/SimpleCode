一组分数是数组：`scores = [48, 72, 55, 90, 60]`。及格线是 `60`。你常做两件事：留下及格的，再把它们换成另一种数，比如减去 `50` 看超出多少。`select` 负责留下，`map` 负责逐个换成新值。两者都交回新数组，原数组的五个数还在原来的位置上。这和 `each` 不同，`each` 不收集块的返回值。也和就地改不同。流水线默认是复制。复制的代价是中间多占几份小数组，五个数可以忽略。复制的好处是原始成绩还在，你可以先筛选再平移，也可以拿原始数组去算平均，两条结果不会互相毁。

`select` 的块应当交回真或假。`n >= 60` 已经是布尔。块交回别的对象时，真值规则会介入：交回 `0` 会被当成真，从而留下那一项。所以不要在 `select` 的块里写「超出及格线多少」这种数字，数字 `0` 表示刚好及格的超出量，却会让项被留下；若你本意是用返回值当布尔，刚好及格会被错误地留下或你根本没想用数字当条件。条件写成比较。`map` 的块才交回新的数。两个块的返回值含义不同，套用同一种写法会在 `0` 上出错。

```ruby run expect="[72, 90, 60]" title="筛选不改原数组"
scores = [48, 72, 55, 90, 60]
passed = scores.select { |n| n >= 60 }
p passed
p scores
```

第一行是 `[72, 90, 60]`，`48` 和 `55` 不在里面，`60` 在，因为条件是大于等于。第二行仍是五个数的检查形式。`passed` 是新数组。改 `passed` 的槽不会改 `scores`，除非你改的是里面共享的对象。整数不能就地改，所以这里特别安全。若元素是哈希，`select` 选出的是同一批哈希对象，改哈希内部两边都看见。元素越能就地改，筛选的「新数组」越只是新的一层槽。

先筛选再减去 `50`：`72`、`90`、`60` 变成 `22`、`40`、`10`。先减去 `50` 再筛选大于等于 `60`：五个数变成 `-2`、`22`、`5`、`40`、`10`，其中没有任何一个仍大于等于 `60`，结果是空数组。同一组输入，两种顺序，一种有三项，一种是空的。顺序是问题的一部分，不是风格。先问「谁及格」，再问「及格的人超出 `50` 多少」，对应先 `select` 后 `map`。先把所有人平移，再问谁的新值仍不低于 `60`，是另一个问题，这组数据上答案是没人。

```ruby run expect="[22, 40, 10]" title="先筛选再平移"
scores = [48, 72, 55, 90, 60]
p scores.select { |n| n >= 60 }.map { |n| n - 50 }
```

```ruby run expect="[]" title="先平移再筛选"
scores = [48, 72, 55, 90, 60]
p scores.map { |n| n - 50 }.select { |n| n >= 60 }
```

空数组的检查形式是 `[]`。`puts` 打空数组会什么可见字符都没有，因为没有元素可拆行。确认「谁也没留下」要用 `p`，否则空白输出分不清是空数组还是忘了打印。这组例子因此都用 `p`。

链式调用从左到右。前一个方法的返回值是后一个方法的接收者。中间的数组没有名字。调试时可以把它接住，打印检查形式，再决定要不要写回成一行链。链的坏处是失败时你不知道停在筛选还是平移。五个数的课例用链是为了让顺序在一行里读完。更长的链会让块里的变量都叫 `n`，读的人要靠位置分辨现在是原始分还是平移后的分。名字可以改：筛选时叫 `n`，平移后叫 `over`。块参数的名字是给你看的，方法不关心。

`select!` 会改原数组，只留下块认为真的元素，并返回原数组；若没有任何删除，有的版本返回 `nil`。返回值不稳定，正好说明它的主效果是副作用。`scores.select! { |n| n >= 60 }` 之后原始的 `48` 和 `55` 不在 `scores` 里了。你若还要算全体平均，数据已经没了。感叹号在这里是真的会删槽。流水线用没有感叹号的 `select` 和 `map`。只有在内存紧、并且没有别的引用需要旧清单时，才考虑就地版本。这组五个整数不构成那个理由。

不带块的 `scores.select` 返回枚举器，和 `map` 不带块一样。枚举器可以再链，但若你把它交给 `p`，看到的是枚举器而不是 `[72, 90, 60]`。块忘了写时，输出里的 `Enumerator` 是信号。花括号要绑在 `select` 上，不要因为外层还有 `p` 或 `puts` 而挂错。这一章的 `p` 包住整条链的结果，块都用花括号紧贴 `select` 和 `map`。

`reject` 是 `select` 的反面，留下使块为假的项。`scores.reject { |n| n >= 60 }` 得到 `[48, 55]`。用 `reject` 还是用 `select` 写反条件，取决于哪一句更像人话。双重否定比较难读。及格用 `select` 配 `>=`，不及格用 `reject` 配同一个比较，两句可以对照，条件不必写成 `<`。对照时注意 `60` 本身：`>=` 留下它，`reject` 同一个比较会丢掉它。边界只写在一处比较里，另一边用 `reject` 复用，边界才不会出现「`>` 和 `>=` 各写了一次」的裂缝。

汇总可以接在筛选之后。`scores.select { |n| n >= 60 }.sum` 把 `72`、`90`、`60` 加起来。`sum` 不是 `map`。若你先 `map` 再 `sum`，加的是平移后的数。平均分不该用平移后的清单。原始数组调用 `sum` 才会把不及格也算进去。先问清平均的分母是五个人还是及格的三个人，再决定 `sum` 的接收者是 `scores` 还是 `passed`。分母用错，分子再精确也是另一个问题。

`map` 的块里做除法时，整数除法仍向下取整。`90 / 10` 是 `9`，`55 / 10` 是 `5`。这一章的平移用减法，躲开了取整，让顺序问题单独出现。你若把例子改成除以 `10`，先筛选和先映射可能碰巧得到相近的清单，顺序的差别被算术掩盖。设计例子时让两种顺序的检查形式明显不同，读者才信顺序是语义。`[22, 40, 10]` 和 `[]` 足够明显。

块里可以继续用外面的及格线。`line = 60` 放在外面，`select` 的块读它。这比把 `60` 写死在块里更容易改。改一处，筛选和后面的 `reject` 若都读 `line`，边界跟着走。若有一处仍写死 `60`，你又制造裂缝。外面的变量能被块看见，是方便，也要求你不要在块里给 `line` 赋值，除非你故意要改门槛。这一章的块只读 `line` 的话可以写成下面这样，输出应和写死 `60` 的筛选相同。

```ruby run expect="[72, 90, 60]" title="门槛放在块外面"
scores = [48, 72, 55, 90, 60]
line = 60
p scores.select { |n| n >= line }
```

`line` 是局部变量，不是每份分数自己的字段。所有比较共用一条线。若每人的及格线不同，数据就不再是整数数组，而是带字段的哈希的数组，比较时读 `item[:line]`。那是结构升级，不是 `select` 的另一种语法。这组数据每个人共用 `60`，整数数组够用。

`filter_map` 把筛选和平移并成一次遍历。块返回 `nil` 的项会被丢掉，返回其他值的项进入新数组。及格的人交回 `n - 50`，不及格的人交回 `nil`，结果同样是 `[22, 40, 10]`，原数组不动。它少建一张只含及格分的中间数组。代价是 `nil` 同时表示「丢掉」和「转换结果就是空」。分数平移不会合法地产生 `nil`，所以这里合得起来。若某种转换需要保留空值，就回到先 `select` 再 `map`，让「留不留」和「变成什么」分成两个块。一个块里写两个问题，条件一复杂就会把 `0` 和 `nil` 搞混。`0` 会被 `filter_map` 留下，因为 `0` 不是 `nil`。刚好减成 `0` 的及格线边界因此仍在结果里。这和 `select` 里「`0` 算真」不是同一处，但数字 `0` 再次提醒你：空和零在不同方法里有不同的特殊地位。

```ruby run expect="[22, 40, 10]" title="filter_map 合成一步"
scores = [48, 72, 55, 90, 60]
p scores.filter_map { |n| n >= 60 ? n - 50 : nil }
```

`grep` 用另一种匹配留下元素。对整数范围，`scores.grep(60..100)` 能留下及格并且不超过 `100` 的分数。它表达的是「落在这个模式里」，不是任意的布尔块。范围足够时，`grep` 比 `select` 短。条件一旦变成「及格且是偶数」，范围写不出来，回到 `select`。不要为了统一风格把简单范围也写成块，也不要为了用 `grep` 把复杂条件塞进匹配对象。五个数里 `90` 和 `60` 都落在 `60..100`，`48` 不落。`grep` 同样交出新数组。

链的中间若要分支，先接住变量。`passed` 可以既拿去 `map`，也拿去 `sum`，避免筛选块写两遍。写两遍时，日后只改一处的 `>=`，另一处还是旧门槛，两份结果对不上，原数组却仍是对的，你会去怀疑 `map`。共用 `passed` 让筛选只发生一次。内存多了一张三个整数的数组，逻辑少了一处重复。这是这组数据上更值的交换。

`count` 可以带块，数有多少项让块为真。它不交出那些项。你只需要及格人数时，`count` 比 `select` 再 `length` 更直接，也不保留中间数组。你既要人数又要清单，就 `select` 一次，人数用 `length`。先 `count` 再 `select` 会把比较跑两遍。五个数无所谓，比较若会触发昂贵计算，就不要跑两遍。方法的选择看你要不要那张清单，不只看哪一个名字更短。

`lazy` 让 `select` 和 `map` 先不要遍历，直到你真的取结果。五个分数用懒枚举不会更快，反而让类型变成还没算出的链，`p` 时你可能看见的不是数组。小数据用立即的 `select` 和 `map`，检查形式就是数组，调试直接。懒枚举适合输入很长、而且你只要前几项的时候。成绩列表若只有一班人，不要为了「以后可能很大」先改成懒的。等测量到中间数组真的成为问题时再换。提前换的代价是排错变难，收益在这组数字上是零。

`flat_map` 在块返回数组时把一层拆平。分数不需要拆平。若每名的记录是一次考试的多个小题分数，块返回数组，`flat_map` 能合成一张总清单。用 `map` 会得到数组的数组，再 `puts` 时拆行的方式会让人以为结构丢了。选择 `flat_map` 是因为你要一张平的清单，不是因为它名字更花哨。这组 `scores` 已经是平的，继续 `map` 即可。引入 `flat_map` 只为了标明边界：返回值若本身是数组，下一层是否拆开要你显式决定，语言不会帮你看业务。

多次筛选会各走一遍数据。先留下大于等于 `60` 的，再留下偶数，两遍扫描对五个数无足轻重。合成一个块可以少一遍，块里的条件会变长。条件互相独立时，分成两步，每一步的检查形式都能单独 `p`。条件是「并且」关系时，一个块里写两个比较也可以，短路会让前一个失败时不算后一个。不要为了省遍历把难读的条件焊死。这门课的数据规模下，可读的中间清单优先。

块里修改 `scores` 本身，例如在 `select` 的块里 `delete`，会让遍历缺项或行为难料。筛选的块只读 `n`，需要新清单就用返回值。原始的五个数留到脚本结束，便于你对两种顺序的结果做对照。对照结束再考虑要不要把最终清单绑回 `scores`。

## 小结

`scores` 的五个数是 `48`、`72`、`55`、`90`、`60`。`select` 配 `n >= 60` 得到新数组 `[72, 90, 60]`，原数组仍是五个数。`map` 再减去 `50`，得到 `[22, 40, 10]`。先平移再按 `>= 60` 筛选，得到空数组。顺序决定你在问哪一个问题。

`select` 的块要交回条件，不要交回可能是 `0` 的数量。`select!` 会删掉原数组里的项。空数组要用 `p` 才看得见 `[]`。不带块时你拿到枚举器。及格线放在块外的 `line` 上，让每一处比较读同一个数。平均分的接收者必须是你想计入的那一份清单。

## 练习

1. 用这五个分数。`reject` 掉大于等于 `60` 的，`p` 出结果。应当只剩 `[48, 55]`。不要改用 `select!`。

::: answer 参考答案
```ruby run expect="[48, 55]" title="参考答案"
scores = [48, 72, 55, 90, 60]
p scores.reject { |n| n >= 60 }
```
:::

2. 先 `select` 及格分，再 `map` 成「减去 60」。`p` 出 `[12, 30, 0]`。`60` 本身减去 `60` 是 `0`，它应当留在清单里，因为筛选发生在减法之前。

::: answer 参考答案
```ruby run expect="[12, 30, 0]" title="参考答案"
scores = [48, 72, 55, 90, 60]
p scores.select { |n| n >= 60 }.map { |n| n - 60 }
```
:::
