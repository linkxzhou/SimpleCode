数组和范围都支持同一套枚举方法。map 变换，select 过滤，reject 丢掉，sum 合计，any? 问有没有一个为真，all? 问是不是全部为真。它们可以连成一条链。读的时候从左到右，每一步的结果是下一步的输入。

链的中间如果插入带叹号的方法，原来的数组会被改掉，后面的步骤看到的是改过的数据，也让调用方丢失旧顺序。教学例子不用叹号，需要排序时用 sort 得到新数组。

reduce 把元素收成一个值。一定要给初值。空数组没有初值时，reduce 的行为容易看错；给了 0，空数组的和就是 0。sum 对数字更直接，能用 sum 就不必写 reduce。

块里的参数名字保持一种风格。同一条链上用 n 表示元素。不需要下标时不要去要下标。链太长时，先把中间结果放进有名字的变量，报错会更好读。

```ruby run expect="20" title="偶数平方和"
puts [1, 2, 3, 4].select { |n| n.even? }.map { |n| n * n }.sum
```

```ruby run expect="yes" title="有没有负数"
puts([1, -2, 3].any? { |n| n < 0 } ? "yes" : "no")
```

```ruby run expect="yes" title="全部为正"
puts([1, 2, 3].all? { |n| n > 0 } ? "yes" : "no")
```

## 常见错误

- 在链中间 sort!，调用方的数组顺序被改掉。
- 空集合用 any? 的结果去表示「有数据」。空集合的 any? 是 false。
- 一条链写得太长，中间类型已经不是数组还继续 map。

## 最佳实践

- 过滤、变换、合计分成看得懂的三步。
- 不在枚举链里使用带叹号的方法。
- 数字合计优先用 sum。

## 小结

map、select 和 sum 可以连起来，从左到右读。它们产生新结果。带叹号的方法会改原数组，不要放进链里。
