输出看起来像课程里最不值得讨论的部分。你想看见一个词，就叫一下 `puts`。麻烦出在两件被写进语言里的决定：`puts` 自己要不要补换行，以及没有括号时，后面那一整串到底是参数还是另一层表达式。窗口程序用一个计数器 `visitors` 贯穿这一章。它从 `0` 开始，表示还没有人把号码牌取走。`0` 在这里是数据，不是「条件失败」。真假要到后面专章再讲透，这一章只用到一个事实：把 `0` 放进三元表达式的条件位置，Ruby 走「真」的那一支。若你从 C 带过来「零就是假」，下面每一块的文字都会反着。

`print` 把参数的文字写出去，然后停住，不追加换行。适合做还没说完的提示，比如先写「窗口」，再写编号。`puts` 在写完之后补一个换行，适合一行一件事。两者都接受多个参数，但切分方式不同。`print "窗口", "A"` 会把两段紧贴着写成 `窗口A`，中间没有空格，也没有换行。`puts "窗口", "A"` 则是两行。这个差别不是审美，是方法约定：`puts` 把每个参数当成一条记录，`print` 把参数当成连续的字符流。你若用 `print` 打日志，下一条记录会黏在行尾；你若用 `puts` 打一个不该断行的提示，用户会看到提示独占一行，输入跑到下一行的行首。选哪个，先问「这一次写完，行是否该结束」。

```ruby run expect="窗口A" title="print 不换行"
print "窗口"
print "A"
puts
```

最后那个单独的 `puts` 没有参数，它只补一个换行，好让脚本的输出在行尾结束。没有它，`窗口A` 仍然会出现在输出里，只是光标停在同一行。课程的期望看的是子串，少一个收尾换行通常仍能对上。养成补上的习惯，是为了你自己在终端里读下一行，不是为了讨好比较器。

多个参数走 `puts` 时，每个参数各自一行。这和你把它们先拼成一个字符串再输出不是一回事。拼接会让你决定分隔符；多参数把分隔的权力交给了 `puts`，分隔符固定是换行。计数器是整数时，`puts` 会先把它转成十进制文字再写。你不必自己调用转换。代价是你失去了格式：想要前导零、想要固定宽度，多参数帮不上忙，你得先做出字符串。

```ruby run expect="窗口" title="puts 每个参数一行"
visitors = 0
puts "窗口", "A", visitors
```

三行分别是 `窗口`、`A` 和 `0`。`visitors` 仍是整数 `0`，只是这一行看见了它的文字。这里还没有分支。

三元表达式 `条件 ? 真分支 : 假分支` 是一个表达式，会算出两个分支里的一个值，它自己不负责打印。你想看见那个值，就得把它交给 `puts` 或 `print`。Ruby 3.2 对 `puts visitors ? "已开窗" : "未开窗"` 的解析是：三元表达式整个当作 `puts` 的参数。`visitors` 为 `0`，条件为真，参数是字符串「已开窗」，于是输出这一句。有些旧笔记声称没有括号时会先调用 `puts visitors`，再拿返回值去做三元判断。那不是这门课所用的 3.2 的解析。按过时的说法去改代码，你会「修好」一个并不存在的拆法，同时放过真正会出事的写法。

真正把三元表达式套到调用结果上的，是先把调用写完。`puts(visitors) ? "已开窗" : "未开窗"` 里，括号在 `visitors` 之后就关上了，`puts` 先执行，打印 `0` 并返回 `nil`。三元表达式的条件于是是这个返回值。`nil` 走假分支，表达式的值是「未开窗」。这个字符串没有被打印，因为没有任何方法接收它。整句表达式的值被丢掉，终端上只留着 `0`。括号的位置决定了三元表达式是参数还是外层运算。想要的是前者时，写成 `puts(visitors ? "已开窗" : "未开窗")`：括号包住整个三元表达式，`puts` 只负责输出选中的那一支。

```ruby run expect="已开窗" title="三元表达式作为参数"
visitors = 0
puts(visitors ? "已开窗" : "未开窗")
```

`0` 走到「已开窗」，是因为非 `nil`、非 `false` 的对象都让条件成立。这和窗口有没有访客不是一回事。计数器为 `0` 仍是一个清楚的整数，程序没有理由把它当成「缺少计数器」。若你的业务含义是「还没有开窗」，用 `nil` 或 `false` 表达缺失或否定，不要借用 `0`。这一章的例子故意用 `0`，就是要让输出和 C 习惯相反，避免你把「已开窗」误读成「人数不为零」。

把调用先做完的那种括号，输出里找不到分支字符串。下面加一行「结束」，用来证明脚本还在往下走，而「未开窗」从未写出去。你若在终端里只看到 `0`，会以为三元表达式坏了。它没有坏，它的结果被丢弃了。

```ruby run expect="结束" title="三元表达式套在返回值上"
visitors = 0
puts(visitors) ? "已开窗" : "未开窗"
puts "结束"
```

第一行是 `0`，第二行是 `结束`。中间没有「未开窗」。`puts` 的返回值固定是 `nil`，设计成这样是为了让你少把输出方法的结果再拿去运算。大多数时候这是好事：打印是副作用，主值应该来自你自己的计算。少数时候你把三元表达式接在一次已经闭合的调用后面，`nil` 会静默地选择假分支，而副作用已经发生。读这种报错很费劲，因为程序不以异常结束，退出码仍是成功，只是文字不对。所以可运行的例子一律把三元表达式放进 `puts` 的括号里，或者先把分支结果放进变量再打印。不要写 `puts(visitors) ? ... : ...` 这种让返回值去当条件的句子，除非你正在演示这个坑。

`print` 也返回 `nil`。把三元表达式套在 `print` 的闭合括号后面，同样会先打印参数，再丢掉分支的值。它和 `puts` 的差别只在有没有换行，不在返回值。有人希望输出方法返回写下的字节数，好用来判断写进去没有。Ruby 不把这个信息放在返回值里。写失败会走异常，而不是交回一个负数。你少了一种「看返回码」的写法，也少了一种把字节数误当成布尔值的机会。在这个运行环境里，标准输出是同步的，写出去的文字会按顺序出现，不必为了刷新而额外做别的事。

多个参数和三元表达式叠在一起时，先把要打印的值算清楚。`puts` 的多参数形式没有义务帮你保存三元表达式的结果。下面先把窗口状态放进 `label`，再和编号分两行打出。`visitors` 从 `0` 加到 `1`，用的是重新绑定，不是把整数对象改写。状态文字跟着新的数值再算一次。两次都是「已开窗」，因为 `0` 和 `1` 都不是 `nil` 或 `false`。这进一步说明：这条三元表达式问的不是「人数是否为正」。

```ruby run expect="已开窗" title="先算再分两行"
visitors = 0
label = visitors ? "已开窗" : "未开窗"
puts label, visitors
visitors = visitors + 1
label = visitors ? "已开窗" : "未开窗"
puts label, visitors
```

四行是「已开窗」、`0`、「已开窗」、`1`。加法的结果绑定回 `visitors`，否则加出来的 `1` 会丢掉，名字仍指向 `0`。输出方法不会帮你完成这个绑定。

`p` 和 `puts` 还不是一回事，数组那一章会用 `p` 看容器的内部写法。这里只提前定一条边界：调试一个布尔或一个短字符串时，`puts` 够用；你要看引号、换行是否藏在字符串里时，`puts` 会把它们「渲染」掉，你需要的是检查形式。不要在这一章用 `p` 代替 `puts` 来打印「已开窗」，检查形式会多出引号，期望子串若写得过于死板就会对不上你的阅读预期。课程里的期望写成稳定的业务词，正是为了让你改空白时仍知道自己在对哪一件事。

还有一种静默失败：分支里写了 `print`，外层却没有人接收，同时又发生了别的打印。读输出时你会把两处文字拼成一段故事。减少这种叠加的办法是每一行只做一件副作用。计算用变量接住，输出单独一行。行数会变多，调用顺序会变得可以指着讲。三元表达式很短，短会诱使你把它嵌进任意调用。嵌进 `puts` 的参数位置是合适的；嵌进已经闭合的调用右边，是在用返回值做选择。

若条件本身需要计算，先放进变量再交给三元表达式，括号仍包住整段。`enough = visitors > 2` 这种比较的结果已经是 `true` 或 `false`，再写三元表达式只是把布尔翻译成业务句子。比较和输出分离之后，你可以用同一份 `enough` 决定两句不同的文字，而不必把比较复制到两处 `puts` 里。复制比较的代价是以后门槛从 `2` 改成 `3` 时容易漏一处，两行输出开始互相矛盾。

窗口从 `0` 开到更大的数，文字可以仍是「已开窗」。想表达「人多需要加柜」，就把门槛写进条件，而不是指望 `puts` 的参数个数来表达逻辑。参数个数只决定行数。逻辑放在参数算出来之前。

标准输出在这门课的解释器里是同步的。同步表示每次 `print` 或 `puts` 都会尽快把文字送出缓冲区，不会等凑满一块再出现。不同步时，提示已经调用过了，屏幕上却还没有字，用户以为程序还没运行到那一行。同步的代价是很多次很小的写出，系统调用更碎。窗口例子只有几行，这个代价可以忽略。你不必再写额外的刷新。换到不同步的环境，若提示和读入连在一起，才需要关心缓冲区。

顶层的 `puts` 看起来像函数，其实是 `Kernel` 上的私有方法，几乎每个对象都能在自己的方法里直接写它，因为类混入了 `Kernel`。写成 `self.puts` 会碰上私有规则而失败。这个限制让输出保持「过程」的样子，也避免 `visitors.puts` 这种把接收者写成计数器的误导。要明确写到哪一条流，用 `$stdout.puts`。例子不替换 `$stdout`，所以文字都进同一条输出，期望的子串不会跑到别的流里。测试里替换输出对象是为了捕获，课程脚本不需要那一层。

整数写成 `1_000` 时，下划线只存在于源码里，值是 `1000`。`puts` 不会把下划线打印回来。`Integer("1_000")` 却接受这种分组，因为它沿用字面量的宽松。窗口编号若从输入来，不要假设用户会写下划线，也不要假设 `Integer` 会拒绝它。显示格式、字面量写法和输入语法是三件事。`puts` 只负责第三步之前你已经算好的值的文字。分组、进制和补零都应当在变成参数之前定下来。

`puts nil` 打出一行空白，因为 `nil` 的文字是空的，换行还在。`print nil` 则几乎不留下可见字符。调试时看到空白行，先想是不是打到了 `nil`，再想是不是三元表达式的分支根本没被打印。这一章那个被丢掉的「未开窗」就是后一种：不是空白，是根本没有调用输出。空白行是调用了、值的文字是空的。两种安静不一样。

## 小结

`print` 把文字连着写，不补换行；`puts` 写完一条就换行，多个参数就是多行。两者的返回值都是 `nil`，打印失败靠异常而不是靠返回码。计数器 `visitors` 从 `0` 起步时，三元表达式仍然走到真分支，因为这一章用 `0` 表示「人数是零」，不表示「没有这个值」。

Ruby 3.2 把 `puts visitors ? "已开窗" : "未开窗"` 解析成参数位置上的三元表达式。`puts(visitors) ? "已开窗" : "未开窗"` 才是先打印再拿 `nil` 做条件，分支字符串不会出现在输出里。要打印选择结果，写成 `puts(visitors ? "已开窗" : "未开窗")`，或先放进变量。括号包住谁，决定三元表达式是给输出方法的，还是在消费输出方法的返回值。

## 练习

1. `visitors` 仍从 `0` 开始。用 `print` 连续打出「柜」和「口」，不要在这两次之间换行，最后用无参数的 `puts` 结束这一行。下一行用带括号的三元表达式打印「已开窗」或「未开窗」。输出里应能找到 `柜口` 和 `已开窗`。

::: answer 参考答案
```ruby run expect="柜口" title="参考答案"
visitors = 0
print "柜"
print "口"
puts
puts(visitors ? "已开窗" : "未开窗")
```
:::

2. 演示闭合调用的坑，但把丢掉的分支接住。`visitors` 为 `0`。先执行 `puts(visitors)`，用它的返回值做三元表达式，把结果放进 `discarded`，再单独 `puts discarded`。输出里要有单独一行 `0`，也要有 `未开窗`。

::: answer 参考答案
```ruby run expect="未开窗" title="参考答案"
visitors = 0
discarded = puts(visitors) ? "已开窗" : "未开窗"
puts discarded
```
:::
