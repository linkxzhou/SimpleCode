一笔 `19` 元要由 `5` 个人分。若你写下 `total / people`，心里大概期待 `3.8`。Ruby 的整数除法不给这个结果。两个 `Integer` 相除，商是整数，余数另算。商的方向是向下取整，也就是朝负无穷，而不是朝零把小数截掉。正数上看不出这两种规则的差别：`19 / 5` 得到 `3`，剩下 `4`，因为 `3 * 5 + 4 = 19`。负数上两种规则会分裂。这一章先把正数的账做完，再用一笔负债把方向看清楚。单位用符号 `:yuan` 带着走。符号不是带引号的文字，它和字符串 `"yuan"` 各有各的相等规则。

用整数保存金额，是在拒绝二进制浮点去表示十分位。`0.1` 这种值在 `Float` 里常常不是你写下的那个十进制。分成五份时，误差会以一种很难对账的方式出现。整数分的代价是你必须决定余数归谁。`19` 元分给 `5` 人，每人先拿 `3` 元，剩下 `4` 元不能再按整数元切开。你可以把余数留给公账，也可以改用「分」做单位，让 `1900` 分被 `5` 除尽。单位越小，整除越常常除尽，数字也越长。用浮点去除，写起来像口算，对账时却要再引入误差政策。这门课的运行环境没有金额库，例子就停在整数和一次故意的浮点对照上，不假装 `Float` 能当会计。

```ruby run expect="3" title="十九元五个人"
total = 19
people = 5
puts total / people
puts total % people
```

`%` 是余数方法的中缀。它和除法成套：商向下取整之后，余数要满足「商乘除数加余数等于被除数」。正数时余数非负，看起来就像小学里的余数。`div` 和 `/` 在整数上是同一个方向，`total.div(people)` 也是 `3`。需要同时拿到商和余数时，用 `divmod`，它返回一个两元素数组。数组怎么打印会占一行还是多行，后面再专门说。这里如果你只 `puts total.divmod(people)`，会看到两行 `3` 和 `4`，因为 `puts` 遇到数组会逐个元素换行。想看一对括号包住的结果，得用检查形式。在还没习惯之前，分开 `puts` 商和余数更不容易读错。

把同一笔账换成浮点，只需要让接收者变成 `Float`。`total.to_f / people` 得到 `3.8`。`to_f` 产生新的浮点，`total` 仍是整数 `19`。这和「问整数要一个新对象」是同一类动作，只是新对象的类变了。除法的接收者决定方法的版本：整数的 `/` 整除，浮点的 `/` 做浮点除。参数 `people` 仍是整数也没关系，浮点的除法会按浮点规则处理。反过来若你写 `people / total.to_f`，接收者是整数时已经走了整除，那是另一笔账，不要和这一笔混着记。想稳定地做浮点除，让左边是浮点。

```ruby run expect="3.8" title="换成浮点再除"
total = 19
people = 5
puts total.to_f / people
puts total
```

第二行仍是 `19`。浮点结果没有写回 `total`。若业务后来需要整数元，你得另外决定怎么把 `3.8` 收回整数，`to_i` 会朝零截断，`round` 会按四舍五入。这些方法和整除的向下取整又不是同一条规则。一条流水线上混用三种取整，账单会对不上。这一章的可运行例子在用完浮点后不把它写回去，就是避免一条脚本里出现两种商。

负债把方向从口诀变成数字。`debt` 为 `-7`，`share` 为 `2`。朝零截断的商会是 `-3`，因为 `-3.5` 去掉小数是 `-3`。Ruby 向下取整，`-3.5` 走向更小的整数 `-4`。于是 `-7 / 2` 得 `-4`，余数是 `1`，因为 `-4 * 2 + 1 = -7`。余数的符号跟着除数走，在除数为正时余数非负。有人用「余数和被除数同号」来记 C 的规则，那条记法在这里会算出错误的 `1` 或 `-1`。核对的办法不是背口诀，而是用商乘除数加余数，看是否回到被除数。对不上，就是方向记反了。

```ruby run expect="-4" title="负债也要除尽关系"
debt = -7
share = 2
puts debt / share
puts debt % share
```

这个结果会让「把负数金额按人头截断」的业务代码少分或多算一人的份额。若你确实想朝零，要自己写，例如先取绝对值再把符号安回去，并且为余数另定规则。语言不提供一个「请按 C 的方式除」的默认开关。选 Ruby 的整除，就是接受向下取整这一套和 `%` 配套；选自己写朝零，就要在项目里只留一种，否则 `-7` 这种值会在不同文件里得到 `-3` 和 `-4`。正数测试发现不了这个分叉。

单位若用字符串 `"yuan"` 到处传递，每次写出引号都会新建一个字符串对象，内容可以相等，身份通常不同。符号 `:yuan` 在源码里出现多次，指的是同一个符号对象。相等可以用 `==`，身份可以用 `equal?`。符号和字符串即使文字一样，`==` 也是假，因为类不同，它们不会自动互相迁就。需要文字时调用 `to_s`，得到一个新的字符串，再去和 `"yuan"` 比较。这个转换是显式的，所以你不会在哈希查找里被一种「看起来像」的键悄悄匹配上。代价是你得多写 `to_s` 或 `to_sym`。隐式转换省掉的那一次调用，会在键对不上时变成 `nil`，而 `nil` 很安静。

```ruby run expect="false" title="符号和字符串"
total = 19
people = 5
unit = :yuan
label = "yuan"
puts total / people
puts unit == label
puts unit.to_s == label
puts unit.equal?(:yuan)
```

四行里，第一行仍是这笔账的商 `3`，说明单位没有参与除法。第二行是 `false`，符号不等于字符串。第三行是 `true`，转成文字之后内容一致。第四行是 `true`，源码里的两个 `:yuan` 是同一对象。字符串做不到这第四点：两个分别写出的 `"yuan"` 内容相等，`equal?` 为假。你若把 `equal?` 用在单位字符串上，会把同一单位看成两个。符号躲开了这个问题，也带来别的约束。符号没有 `<<` 这种改内容的操作，它不是缓冲区。`:yuan` 拼不出 `:yuan_note`，你只能做成新的字符串再决定要不要 `to_sym`。运行中大量 `to_sym` 会制造许多符号。Ruby 2.2 之后，动态创建的符号可以被回收，不再是「一旦创建就永远占着内存」的旧账。源码里写下的符号仍然会留在进程里。用符号做单位、做方法名、做哈希键，是因为身份稳定、写法短；不要用它做用户输入的原文，用户输入是开放集合，字符串更合适。

`to_sym` 和 `to_s` 是桥，不是合并。走过桥之后你手里是另一类对象。`label.to_sym == unit` 为真，`label` 自己仍是字符串。和整数的 `to_f` 一样，转换不改接收者。在金额脚本里把单位从字符串改成符号，要写回变量，否则下一行的键还是旧的那一种。

余数和符号可以放在同一句输出里，但不要让符号去参加算术。`unit + 1` 没有这种方法，会以找不到方法结束。整数才能 `+`。若你想显示「3yuan」，先把商变成字符串再拼接：`(total / people).to_s + unit.to_s`。拼接的结果是新字符串。这种显示用的文本不再适合拿回去除。计算留在整数上，展示时再靠近文字。颠倒过来的脚本会在某一行突然需要 `to_i`，而 `to_i` 对不合法文字的态度很宽容，那是错误处理一章的主题，这里只要避免把展示字符串当金额。

`19` 和 `5` 都是上一章那种整数对象。除法和求余是消息，写不回 `total`，除非你写 `total = total / people`。写回之后你失去了原始总额，余数也就不能再从旧的总额复核。要复核，就保留 `total`，用别的名字接商。这不是格式洁癖，是负数额上那条「商乘除数加余数」需要三个角色同时在场。

除了 `/` 和 `%`，整数还能向你要别的商。`total.quo(people)` 得到有理数，打印出来是 `19/5`。有理数把分子分母留着，再运算仍是精确的，直到你把它变成浮点。分母在反复运算里可能变大，打印也会变长。`fdiv` 直接给你浮点 `3.8`，和 `to_f` 之后再除是同一类结果，误差政策也相同。会计若要「每人 3 元余 4 元」，用整除和余数。若要「精确的五分之一再参与下一步分数运算」，用 `quo`。若只是给屏幕一个小数，用 `fdiv`，并接受它不是十进制精确值。三条路都不要写回 `total`，否则原始的 `19` 没了，余数无法再复核。

```ruby run expect="19/5" title="有理数和浮点商"
total = 19
people = 5
puts total.quo(people)
puts total.fdiv(people)
```

负数上，`%` 跟着向下取整的商走，余数在除数为正时非负。`remainder` 使用朝零的余数。`debt` 为 `-7`、`share` 为 `2` 时，`modulo` 是 `1`，`remainder` 是 `-1`。两个方法都自称余数，还原公式却配不同的商。你若拿 `remainder` 的 `-1` 去配向下取整的商 `-4`，乘回去对不上 `-7`。对账时商和余数必须来自同一对方法。`divmod` 配的是 `modulo` 这一边。朝零的需求用 `remainder`，就不要再和 `/` 的商混在一行说明里。正数上 `remainder` 和 `modulo` 常常相同，所以只测 `19` 和 `5` 发现不了这个分裂。

```ruby run expect="-1" title="两种余数"
debt = -7
share = 2
puts debt.remainder(share)
puts debt.modulo(share)
```

符号没有算术，也不要拿它当格式串。若单位需要按语言切换文字，符号适合当内部代码，字符串适合当已经翻译好的句子。`:yuan` 可以做哈希的键去取出 `"元"`，取出的值才拿去拼接。这一步把「稳定身份」和「给人看的字」分开。等号比较身份或内容，拼接只发生在字符串上。内部代码若直接打印，用户会看到 `yuan` 这种词，除非你在输出前做了映射。映射表缺失时应当失败得显眼，而不是把符号的 `to_s` 悄悄展示出去。

有理数乘回人数，应当回到总额。`share = total.quo(people)` 之后，`share * people == total` 为真。这是 `quo` 相对浮点的理由：`3.8 * 5` 在这组数字上碰巧也回到 `19`，换别的除数就不一定。用一次碰巧整除的样例去证明浮点可靠，会在下一次除数上失败。有理数的代价是结果可能保持分数形式，显示给用户之前仍要决定取整。取整放在最后一次，中间步骤保持精确，误差只出现一次。若每一步都 `fdiv`，误差会叠。五个人的这一笔记账用整数余数已经够用，`quo` 是在你下一步仍要按比例分配时才值得。

```ruby run expect="true" title="有理数乘回去"
total = 19
people = 5
share = total.quo(people)
puts share * people == total
```

人数若是 `0`，整数除法会直接失败，而不是得到无穷大。这和「零在条件里为真」是两回事：除法关心的是除数能不能做除数。写 `total / people` 之前，人数来自输入时要先保证它大于零。大于零是比较，不是真值。`people` 为 `0` 时真值仍然成立，除法却不成立。两套检查都要在，缺一不可。

## 小结

`total` 为 `19`、`people` 为 `5` 时，整数除法得到商 `3` 和余数 `4`。商向下取整。`debt` 为 `-7`、`share` 为 `2` 时，商是 `-4`，余数是 `1`，因为要满足乘法还原。朝零截断不是 Ruby 的默认。需要浮点商时让接收者变成浮点，`total` 本身保持整数，避免一条流水线上混进第二种取整。

`:yuan` 和 `"yuan"` 不相等，`to_s` 之后文字才相同。源码中的同名符号是同一个对象，同内容的字符串则不是。符号适合做封闭的单位和键，不适合做可改的缓冲区，也不适合做未经限制的用户原文。动态符号可以被回收，这不构成把一切字符串都转成符号的理由。金额留在整数上运算，展示时再转成文字。
