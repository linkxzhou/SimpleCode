书单是有顺序的清单。这一章只保留一份，名字叫 `books`，三本是 `"ruby"`、`"rail"` 和 `"rake"`。顺序就是下标的顺序，`books[0]` 是第一本。数组是对象，`length` 和后面的迭代方法都是发给它的消息。空数组 `[]` 也是对象，条件里为真，`length` 为 `0`。`nil` 没有 `length`。所以「还没有书单」和「书单是空的」不要混用一个值。这一章的书单始终有三本，空与不空留在规则里，不拿来当主例子。

`each` 把每本书交给块，块里的参数我们叫 `title`。块是一小段借给方法的代码，完整的写法下一章再展开。这里先用它把每本书处理一次。`each` 的用途是做事情：打印、累计、写入别处。它返回的是原数组自己，不是块的返回值组成的新清单。块里写 `title.upcase` 会得到大写的新字符串，但 `each` 把这个返回值扔掉。大写方法不修改原字符串，`"ruby".upcase` 交回 `"RUBY"`，`title` 仍是小写。两层都不保存的话，循环结束时书单看起来像没运行过。这不是块没执行，是两个返回值都没人接。

`map` 把块的返回值收成一份新数组，原数组保持原样。你想要大写书名清单，用 `map`。你只想逐本打印，用 `each`。用 `map` 去打印，会得到一份全是 `nil` 的新数组，因为 `puts` 返回 `nil`，`map` 很认真地收集了这些 `nil`。用 `each` 去生产新清单，会把新清单丢在地上，手里还是旧的。两个方法都没错，错在让它们干对方的活。

打印数组时还有一层容易混的约定。`puts books` 并不打印检查形式。数组被特殊处理：每个元素各自一行，元素若又是数组会继续拆开。三本书就是三行 `ruby`、`rail`、`rake`，没有括号，没有引号，没有逗号。这适合把书名当三行文本交出去。它不适合调试，因为字符串和符号打印出来可能看不出引号，嵌套结构也被拆平。`p books` 走检查形式，也就是 `inspect` 的结果，一行里能看到 `["ruby", "rail", "rake"]`，引号和逗号都在。`p` 的工作是给程序员看值的结构，`puts` 的工作是给输出流写记录。同一份书单，两种方法，两种读者。

```ruby run expect="ruby" title="puts 把书单拆成行"
books = ["ruby", "rail", "rake"]
puts books
```

三行都是小写书名。没有括号。若期望里写了方括号，会对不上，不是书单坏了，是 `puts` 没有义务保留数组的外观。

```ruby run expect="[\"ruby\", \"rail\", \"rake\"]" title="p 显示检查形式"
books = ["ruby", "rail", "rake"]
p books
```

检查形式里逗号后面有一个空格，这是 `inspect` 的固定样子。用这个子串去对输出时，要把空格也算进去。少写空格会匹配失败，多出来的别的行则不影响子串是否出现。

`map` 之后原书单还在。`loud` 接住大写的新数组。`p` 两份，就能看见新的一份是大写、旧的一份仍是小写。`upcase` 没有改 `"ruby"` 那块缓冲区，它交回新字符串。`map` 也没有改 `books` 的槽位。两层都是「交出新的」。若你写 `books.map!`，感叹号版本会把原数组的槽换成块的返回值，`books` 自己变成大写。感叹号在这里是真的会替换槽位。非感叹号的 `map` 更安全，代价是多占一份数组。三本书的清单不值得为了省这份内存去改原清单；一份被多处引用的书单，`map!` 会让别的引用也看见大写，那才是要慎重的时候。

```ruby run expect="[\"RUBY\", \"RAIL\", \"RAKE\"]" title="map 留下原书单"
books = ["ruby", "rail", "rake"]
loud = books.map { |title| title.upcase }
p loud
p books
```

输出两行检查形式，先大写后小写。块参数 `|title|` 只在块内有效。块外面没有 `title` 这个变量。有人在 `each` 之后打印 `title`，会遇到未定义的名字。迭代变量不是循环结束后的「最后一项」遗物，除非你在块外事先用过同一个名字。Ruby 的块会看见外面的局部变量，这既方便累计，也会让你无意中改掉外面的 `title`。这一章的块不给外面的名字赋值。

`each` 丢掉块返回值的事实，用 `p` 可以一次看清。`p` 打印的是 `each` 的返回值，也就是原书单的检查形式，仍然小写。块里的 `upcase` 执行了，结果没有进入 `p` 所看见的那个数组。若输出是大写，说明你调用的其实是 `map`。

```ruby run expect="[\"ruby\", \"rail\", \"rake\"]" title="each 交还原书单"
books = ["ruby", "rail", "rake"]
p(books.each { |title| title.upcase })
```

括号包住 `each` 和它的块，是为了让 `p` 的参数明确。花括号块会尽量和左边紧挨着的方法结合。这里左边是 `each`，结合是对的。若写成 `p books.each do |title| ... end`，`do` 和 `end` 的结合优先级更低，块可能挂到 `p` 上而不是 `each` 上。那种句式放到块的专章里用同一份书单演示。这一章的块都用花括号，并且让 `p` 的括号包住整个调用，避免把「迭代」和「打印检查形式」绑错对象。

`puts books.map { |title| title.upcase }` 会先得到大写数组，再被 `puts` 拆成三行 `RUBY`、`RAIL`、`RAKE`。你看不见方括号。这很适合导出，不适合确认 `map` 是否真的返回了数组。确认结构用 `p`。两者连着写也可以：先 `p` 再 `puts`，读者要知道前一行是检查形式、后三行是记录。不要用一种打印去推断另一种的格式。

```ruby run expect="RUBY" title="puts 拆开 map 的结果"
books = ["ruby", "rail", "rake"]
puts books.map { |title| title.upcase }
```

下标仍然从 `0` 开始。`books[0, 2]` 的第二个数是长度，不是终点，和字符串切片同一套数字含义：起点 `0`、长度 `2`，得到前两本组成的新数组。原书单仍是三本。范围 `books[0..1]` 用下标。数组切片和字符串切片在「长度还是终点」上同样容易看错，只是元素变成了整本书名，错一位会少一整本，而不是少一个字母。负数下标从末尾数，`books[-1]` 是 `"rake"`。`-1` 不是「找不到」。找不到时返回 `nil`。对 `nil` 调用 `upcase` 会失败。迭代比下标安全的地方，就是块里的 `title` 一定是元素，不会是表示越界的 `nil`，除非你的书单里真的放了 `nil`。不要把 `nil` 放进这三本书里当占位，否则 `map` 到那一项会停住。

`each` 可以用来累计而不制造书名数组。比如数有几个以 `r` 开头。计数器放在块外面，块里做加法并写回。`map` 不适合这个目的，它会造出一个布尔数组，你还得再数一遍。选择的标准是：结果是不是和原清单等长的一份新清单。是，用 `map`。是一个汇总值或一串副作用，用 `each`。过滤出一部分书是另一种结果，长度会变短，那是 `select` 的工作，留到同一组数据上做流水线的那一章。这里的三本书都保留。

书名是字符串，可以就地修改，但通过 `each` 拿到的 `title` 就是数组里的那块缓冲区。`title << "!"` 会改掉书单里的那一项。`title.upcase` 不会。你在块里想留大写副本，就接住 `upcase` 的返回值；你若写 `title.upcase!`，感叹号版本会改缓冲区本身，书单里的字会变成大写。非感叹号是默认选择。书单被别处继续当作小写键使用时，`upcase!` 会把键改掉，查找就会落空。

`join` 把元素用你给的分隔符拼成一个字符串，不会逐行拆开。逗号拼接的结果是 `ruby,rail,rake` 一行。这适合放进一句说明。`puts` 的逐行适合当清单。两种都不是检查形式，都没有方括号。你要在句子里嵌入书名，用 `join`；你要导出三行，用 `puts`；你要确认引号和元素个数，用 `p`。`join` 不修改原数组，它交出新字符串。分隔符写错不会报错，只会让书名黏成难读的一串。

```ruby run expect="ruby,rail,rake" title="join 合成一行"
books = ["ruby", "rail", "rake"]
puts books.join(",")
```

下标越界时，`books[3]` 返回 `nil`，`books.fetch(3)` 抛出 `IndexError`。这和哈希的 `[]` 与 `fetch` 是同一对政策：短写法用 `nil` 表示失败，严格写法用异常。`nil` 再 `upcase` 会变成另一个错误，离越界已经远了一步。书单长度固定为三时，优先 `each` 或 `map`，让块收到的一定是书名。只有在下标来自外部计算时才用 `fetch`，让坏下标停在取元素的那一行。`first` 和 `last` 是负下标和零下标的可读写法，空数组上它们返回 `nil`。三本书的清单上，`first` 是 `ruby`，`last` 是 `rake`。

`include?` 问的是有没有相等的元素，用 `==`，不改数组。它不告诉你下标。`index` 告诉你第一次出现的下标，没有时返回 `nil`。用这个 `nil` 去取元素会取到另一本或失败。先判断再取，或只用 `include?` 做分支。三本书都不重复，`index` 的「第一次」看不出来。有重复时 `index` 不会列出全部，`select` 才按条件收集。这里的相等是字符串内容相等，两块内容相同的缓冲区会算作包含。不要用身份去判断书名在不在清单里。

`map` 的结果如果马上 `join`，就不必把大写数组留在变量里。链从左到右，先有新数组再有新字符串，原书单仍是小写。链越长，越要记住每一段的返回类型：`map` 给出数组，`join` 给出字符串，字符串上没有 `each` 的书名语义，只有字符。把 `join` 的结果再当书单用，会按字符迭代。类型在链的中间变了，变量名若还叫 `books`，读的人会以为里面仍是三本。接住中间结果并换名字，比省一行更清楚。

`reverse` 交出倒序的新数组，原书单仍从 `ruby` 开始。`reverse!` 把原数组本身倒过来，返回值也是它自己。两本以上的清单用倒序来做「最近加入的放前面」时，就地倒序会让所有引用这张数组的地方一起看见新顺序。`map` 出的大写清单若再 `reverse`，原书单的小写顺序还在。打印倒序用新数组，避免把书架的陈列顺序改掉。`sort` 同样默认交新数组，字符串按字符序。`"rail"` 和 `"rake"` 前两字都是 `ra`，第三字 `i` 比 `k` 小，所以 `rail` 在 `rake` 前面，`ruby` 因为第二字 `u` 更大而排在最后。不要凭词义记顺序，打印检查形式核对。排序会改换位置，和 `map` 逐项变换不是一回事。

```ruby run expect="[\"rail\", \"rake\", \"ruby\"]" title="排序交出新数组"
books = ["ruby", "rail", "rake"]
p books.sort
p books
```

`uniq` 去掉内容相等的重复项，交出新数组。三本书现在都不重复，`uniq` 看起来像没做事。加上第二本 `"ruby"` 才能看见它留下第一次出现的那本。去重不排序。若你既要去重又要排序，先决定哪一步在前，顺序会影响稳定性以外的阅读，不会影响这组字符串的最终集合，但会影响你调试时的中间检查形式。就地版本 `uniq!` 在没有重复时返回 `nil`，有删除时返回数组。用它的返回值当清单，会在「本来就没有重复」时拿到 `nil`。这和「没变化就返回 `nil`」的就地方法是同一类陷阱。要清单就用没有叹号的 `uniq`，再决定是否赋回变量。

## 小结

`books` 这三本的顺序固定。`each` 把块的返回值扔掉，自己交还原数组。`map` 用块的返回值拼一份新数组，原书单不变。`upcase` 也不改原字符串。想要大写清单就用 `map` 并接住；只逐本做事就用 `each`。

`puts books` 把每个元素打成一行，没有括号和引号。`p books` 打出 `["ruby", "rail", "rake"]` 这种检查形式。导出用 `puts`，确认结构用 `p`。切片的第二个数仍是长度。块里的 `title` 出了块就没有，除非你在外面已经用过这个名字。不要把 `nil` 塞进书单再去 `upcase`。

## 练习

1. 仍用这三本书。`map` 出长度的数组并 `p` 出来。检查形式应是 `[4, 4, 4]`，因为三个书名都是四个字符。原书单不要改成大写。

::: answer 参考答案
```ruby run expect="[4, 4, 4]" title="参考答案"
books = ["ruby", "rail", "rake"]
p books.map { |title| title.length }
```
:::

2. 用 `puts` 打印原书单，确认是三行小写而没有方括号。再 `p` 一次 `each` 的返回值，确认仍是小写的检查形式。

::: answer 参考答案
```ruby run expect="[\"ruby\", \"rail\", \"rake\"]" title="参考答案"
books = ["ruby", "rail", "rake"]
puts books
p(books.each { |title| title.upcase })
```
