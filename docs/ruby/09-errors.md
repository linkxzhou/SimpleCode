分数栏里读到的是文字。用户可能输入 `12`，也可能输入 `no`。你要一个整数对象才能和 `60` 比较。转换有两条常见的路，政策相反。`"12".to_i` 和 `Integer("12")` 都得到 `12`。`"no".to_i` 得到 `0`，并且不抱怨。`Integer("no")` 抛出 `ArgumentError`，信息是 `invalid value for Integer(): "no"`。一条路把坏文本收成零分，另一条路拒绝继续。零分在这个语言里是真值，也会被当成合法成绩归档。用 `to_i` 处理 `"no"`，后面的程序分不清「用户写了零」和「用户写了拒绝」。`Integer` 选择把这件事变成失败，让你在转换的现场处理。

失败会中断紧接着的语句，直到被 `rescue` 接住，或让整个脚本以非零状态结束。教学例子把 `ArgumentError` 接住，打印异常的类名，这样输出稳定，脚本也能正常结束。接住不是把坏文本变成 `0`。接住之后你打印「无效」，并且不要再使用一个没赋上的分数。`rescue` 的范围越小越好。只包住 `Integer` 那一行，不要把后面的「是否及格」也包进去，否则比较里的别的错误也会被说成输入无效。

```ruby run expect="ArgumentError" title="no 不能变成整数"
raw = "12"
puts Integer(raw)
raw = "no"
begin
  Integer(raw)
  puts "通过"
rescue ArgumentError => error
  puts error.class
end
```

第一行是 `12`。第二行是 `ArgumentError`。不会出现「通过」，因为 `Integer("no")` 没有返回，控制权进了 `rescue`。`error` 这个名字指向异常对象，`.class` 是它的类。信息字符串里带有原始的 `"no"`，你也可以 `puts error.message`，那一行更长，适合给人看。类名足够用来确认你接住的是哪一种失败，而不是把所有异常都说成输入问题。

`to_i` 的宽容是有规则的：从开头能认出的整数前缀会留下，其余丢掉。`"8abc".to_i` 是 `8`。`"no".to_i` 开头就不是数字，于是得到 `0`。空字符串也得到 `0`。它几乎不抛异常。这种政策适合刮掉混杂文本里的一个数，不适合当唯一的成绩解析。你以为自己在拒绝垃圾，实际上垃圾变成了零分，零分又和及格线比较，用户看到「不及格」而不是「请重填」。两个结果都是否定，只有一种能让人改对输入。

```ruby run expect="0" title="to_i 把 no 收成零"
raw = "no"
puts raw.to_i
raw = "8abc"
puts raw.to_i
```

两行是 `0` 和 `8`。同一方法，两种静默。`8abc` 丢掉的 `abc` 不会出现在返回值里，你无法从 `8` 知道曾经有后缀。若后缀表示单位，单位被丢了，数字还被当成完整成绩。`Integer("8abc")` 则会失败，因为整段都必须是整数的写法。整段这个要求才是 `Integer` 值得用在成绩上的原因。

前导零是另一条不直观的规则。`Integer("010")` 得到 `8`，因为带前导零的写法按八进制读，`010` 八进制等于十进制 `8`。`"010".to_i` 得到 `10`，它按十进制看前缀，不把前导零当八进制标记。同一种看起来像「十前面补了一个零」的文本，两条路差了 `2`。成绩若允许用户补零对齐，`Integer` 会把 `010` 收成八分而不是十分。`08` 更糟：`Integer("08")` 直接 `ArgumentError`，因为 `8` 不是合法的八进制数字。用户只是补了零，解析器却按另一种进制拒绝。`to_i` 对 `"08"` 得到 `8`，看起来更接近补零的意图，却仍然放过 `"no"`。

`Integer` 可以收第二个参数当进制。`Integer(raw, 10)` 强制按十进制读，`"010"` 得到 `10`，`"08"` 得到 `8`，`"no"` 仍然抛 `ArgumentError`。这比先 `to_i` 再自己检查字母更接近「十进制且整段合法」。不写第二个参数时，前导零才回到八进制。两种调用差一个参数，结果可以差 `2`，也可以一个成功一个失败。成绩录入应当把 `10` 写上。省略它不是更短的同义词，是另一条进制规则。代价是你要记住这个可选参数，读别人的 `Integer(raw)` 时不能假设它也是十进制。

```ruby run expect="8" title="前导零的两种读法"
raw = "010"
puts Integer(raw)
puts raw.to_i
```

指定进制之后，同一段 `raw` 不再走八进制。`08` 也能转换。`no` 仍失败。三行输出把「十进制的补零」「补零里的数字 8」和「拒绝字母」放在一起，避免你只记住不带参数的那一种。

```ruby run expect="10" title="强制十进制"
raw = "010"
puts Integer(raw, 10)
raw = "08"
puts Integer(raw, 10)
raw = "no"
begin
  Integer(raw, 10)
  puts "通过"
rescue ArgumentError
  puts "ArgumentError"
end
```

`Integer` 也认识 `0x` 和 `0b` 这种前缀，`"0x10"` 是 `16`。成绩栏通常不需要十六进制。若用户输入碰巧像 `0x10`，`Integer` 会给出 `16` 而不是失败。这也是「整段合法整数」比「整段十进制数字」更宽。宽度是取舍：科学计算的小脚本喜欢 `Integer` 的前缀；录入分数的表单喜欢只认十进制。你可以把 `Integer` 的结果再检查是否等于按十进制 `to_i` 的结果，不一致就拒绝。那是额外的政策，例子里先不叠上，只把单条规则看清楚。

空白上两者都比较宽容。`Integer(" 8")` 和 `Integer("8\n")` 能得到 `8`。行尾若还在，不一定要先 `chomp` 才能转换。尽管如此，先 `chomp` 再转换仍然更清楚，因为你之后若把原文存进记录，不会把换行存进去。`Integer` 的宽容空白不应当成为保留换行的理由。空字符串则不行，`Integer("")` 抛 `ArgumentError`，`"".to_i` 得到 `0`。用户直接回车，两条路再次分裂。

异常对象能携带信息，也能只被用来跳转。只跳转、不看类，会把 `KeyError` 或其他失败一起收进「分数无效」。`rescue ArgumentError` 写上类，就是在缩小网。裸的 `rescue` 会接住标准错误这一支，网太大。课程例子写明类名。接住之后不要再 `raise` 同一个对象，除非你是在记录日志后继续把失败交给外层。这一层已经把失败翻译成了输出，脚本就应当正常结束。

`Integer` 是方法，也是以大写开头的名字。Ruby 允许方法名大写，这个方法和类名 `Integer` 撞在同一拼写上。调用 `Integer("no")` 是在调用方法。写 `Integer.new` 不是转换文本的路。看到大写不要自动当成构造器。转换失败的类型是 `ArgumentError`，不是一个名叫 `Integer` 的异常。打印 `error.class` 时你应当看到 `ArgumentError`。

把 `raw` 从 `"12"` 改成 `"no"` 再改成 `"010"`，是同一变量的三种文本，不是三种类型系统。类型在成功时才变成 `Integer`。失败时你没有得到一个「无效整数对象」，你得到一次跳转。不要预先造一个 `-1` 来表示无效，`-1` 会流进平均分。无效就停在转换处。

`ensure` 里的代码无论转换成功还是失败都会执行。它适合关闭你已经打开的东西，不适合再算一次分数。成绩脚本没有要关的资源，不必为了对称写一个空的 `ensure`。写了就要保证它自己不再抛错，否则你会看到后一个错误，前一个 `ArgumentError` 被盖住。`else` 子句可以放「没有异常时才做」的打印，和 `rescue` 并列，范围比把打印放进 `begin` 更清楚。短例子把打印放进 `begin` 是为了少一层关键字。脚本变长以后，成功路径挪到 `else`，失败路径留在 `rescue`，转换单独留在 `begin` 里。

接住之后重新抛出，用没有参数的 `raise`，它会把当前这个异常继续交出去。写成 `raise error` 往往也可以，但要确认你没有在中间换了一个新异常把原始信息丢了。这一章的例子选择翻译成「类名出现在输出里」并且不重新抛出，是为了让脚本以成功状态结束，输出里仍有 `ArgumentError` 这个词。真实的录入程序有时应当以失败状态结束，让外层停止。那是进程的政策。打印了无效却仍以成功结束，外层会以为这名已经处理完。你要在「每名都有一句人话」和「整批以失败停下」之间选。例子选前者，所以接住。

比较两个转换政策时，用同一份 `raw` 先后调用，不要换文本。`"010"` 不带进制和带 `10` 的差异，只有同一字符串才有说服力。换一个 `"10"` 再去比，两种调用都会得到 `10`，八进制问题消失，你会以为参数可有可无。边界数据要故意带前导零、带数字 `8`、带字母。只测 `"12"` 和 `"72"` 的套件会把 `Integer` 的两种进制都说成「能用」。

`Kernel#Integer` 与类上的转换方法同名，文档里能查到可选进制和可选异常政策。还有一种调用让失败时返回 `nil` 而不是抛出，那是另一种「不要异常」的接口。返回 `nil` 时你必须处理缺失，好处是没有跳转，坏处是 `nil` 容易流进加法。这门课的例子用抛出加 `rescue`，让失败在语法上单独成支。若你改用返回 `nil` 的形式，分支改成对 `nil?` 的判断，不要再写 `rescue`，否则你会接住一个不会来的异常，无效输入反而落到别的分支。

`ArgumentError` 是 `StandardError` 的一种，`rescue` 不写类名时接住的就是 `StandardError` 这一支。`Exception` 更靠上，连系统退出的信号一类也在里面。写成 `rescue Exception` 会把不该吞的失败也变成「分数无效」。网要收在 `ArgumentError`，至少不要宽于 `StandardError`。你在日志里看到的类名应当保留，不要一律打印成「出错了」。类名是后续决定要不要重试的依据。转换失败不该重试同一段文本，缺文件才可能重试。两种失败若被收成同一句人话，外层无法选择。

`raise ArgumentError, "分数无效"` 可以抛出你自己的信息。接住 `Integer` 的异常再抛一个更短的，会丢掉原始信息里的 `"no"`。更好的做法是保留原始异常，把人话打印到输出，或者把原始异常当原因包进新异常。短脚本选择直接打印类名和停止后续计算，不包装。包装适合层次多的程序：内层知道文本不合法，外层知道这是第几名。一层脚本同时知道这两件事，不必再抛一次。

失败信息里的引号和原文来自 `Integer`，不要自己拼一份看起来像、实际上对不齐的英文句子。测试若比对整句英文，解释器一升级措辞变了就会碎。比对类名，或比对你自己打印的中文「分数无效」，都比比对库的英文整句稳。例子里两种都出现过：类名用来确认接住的是哪一种，中文用来给录入结果。库的 `message` 适合人眼看一次，不适合当协议。

转换成功之后的整数才和 `60` 比较。不要在 `rescue` 里把 `score` 设成 `0` 再掉进同一个比较。那样 `"no"` 又会变成再试，只是绕了远路。失败分支应当结束这一名的处理。成功分支才持有整数。两个分支不要共用一个事后补上的默认分数。

## 小结

`Integer("12")` 得到整数 `12`。`Integer("no")` 抛出 `ArgumentError`，信息里带有这段文本。`to_i` 把 `"no"` 收成 `0`，把 `"8abc"` 收成 `8`，不抛异常。零分因此会混进「用户拒绝填写」。成绩要用整段都合法的转换，并接住 `ArgumentError`，且只包住转换那一步。

不带进制参数时，`Integer("010")` 按八进制得到 `8`，`"010".to_i` 得到 `10`，`Integer("08")` 会失败。第二个参数写 `10` 之后，`"010"` 是 `10`，`"08"` 是 `8`，`"no"` 仍然失败。空白通常挡不住 `Integer`，空字符串可以。方法名 `Integer` 与类同名，调用它不是 `new`。
