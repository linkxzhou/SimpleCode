最后这一章把读入、转换和判断收成一份能单独运行的成绩记录。它不发明新的容器，也不再解释每个方法的全部背景。重点是这些决定放在一起时，数据怎么流，失败停在哪一层。输入固定两行：第一行姓名，第二行分数字段。样例用 `Ada` 和 `72`，再换成 `48`，再换成 `no`。同一个脚本骨架，只换输入，输出从「通过」变成「再试」，再变成「分数无效」。

`print` 适合做停在行尾的提示，但提示文字也会进程序的输出。批改看的是结果行，不是提示。为了让结果干净，可运行的脚本不再打印提示，两行输入按位置消费：第一行给 `name`，第二行给 `raw`。你在真实终端里想加提示，可以在读之前 `print`，不要让提示影响你对结果行的判断。位置协议很脆：两行对调的话，姓名会进 `Integer`，多半失败。脆弱是因为我们没有字段名，只有行序。哈希那一章的键在这里用不上，标准输入没有替你标好 `:name`。行序就是这份小程序的格式。格式要写在脚本顶部的一两句意图里，不要只写在某次样例里。

`gets` 各自读一行。先放进变量再去掉行尾，得到的姓名才是 `Ada` 而不是带着换行的那一串。第二次 `gets` 读的是分数那一行，不是再读姓名。把 `gets.chomp` 写两次是对的，因为协议就是两行。写三次会在样例结束处得到 `nil`。不要为了「保险」多读。

分数文本交给 `Integer(raw, 10)`。第二个参数把进制钉在十进制上，成功才有整数可以和 `60` 比较。`72` 大于等于 `60`，打印姓名、空格、分数，再打印「通过」。比较用数字，不用真值。`0` 若真的被合法读入，应当走「再试」而不是被真值当成通过。所以分支是 `score >= 60`，不是 `if score`。

```ruby run stdin="Ada\n72\n" expect="Ada 72" title="七十二分通过"
name = gets.chomp
raw = gets.chomp
score = Integer(raw, 10)
puts "#{name} #{score}"
puts(score >= 60 ? "通过" : "再试")
```

两行结果是 `Ada 72` 和 `通过`。插值里的空格是格式的一部分。不要靠 `puts` 的多参数来插空格，多参数会变成多行。姓名和分数属于一条记录，所以先拼成一个字符串。

同一骨架，第二行换成 `48`。转换仍然成功，比较走另一支。输出里仍有姓名和分数，第二句变成「再试」。及格线只出现在比较里。若「通过」那一支里再写一个不同的数，两条输入会得到无法解释的组合。把 `60` 放进局部变量 `line`，两支都不要再写死一个新的门槛。这个脚本很短，写死一次 `60` 还能看完。一旦复制粘贴出第二处比较，就改成变量。

```ruby run stdin="Ada\n48\n" expect="再试" title="四十八分再试"
name = gets.chomp
raw = gets.chomp
line = 60
score = Integer(raw, 10)
puts "#{name} #{score}"
puts(score >= line ? "通过" : "再试")
```

`48` 能被 `Integer` 接受。失败的例子把第二行换成 `no`。若不接住异常，脚本停在转换，姓名那一行也来不及按我们的格式打印，退出状态表示失败。成绩录入更希望每一名都有一句结果。`rescue ArgumentError` 时打印 `Ada 分数无效`，并且不要再打印「通过」或「再试」。无效不是再试。再试表示一个数字低于门槛，无效表示没有数字。两种句子分开，后面的人才能决定是重考还是重填。

```ruby run stdin="Ada\nno\n" expect="分数无效" title="no 停在转换"
name = gets.chomp
raw = gets.chomp
line = 60
begin
  score = Integer(raw, 10)
  puts "#{name} #{score}"
  puts(score >= line ? "通过" : "再试")
rescue ArgumentError
  puts "#{name} 分数无效"
end
```

`begin` 包住转换和成功之后的打印。失败时成功分支里的 `puts` 不会执行。有人担心范围太大，比较几乎不会抛出 `ArgumentError`。若你在成功分支里还做别的可能失败的事，就把 `Integer` 单独包住，成功后再打印。当前三行里，转换是唯一预期会抛 `ArgumentError` 的地方，包在一起可以保证无效时只有一句结果。不要用 `to_i` 代替这里的 `Integer`。`"no".to_i` 变成 `0`，比较会打印「再试」，把拒答收成了不及格。这个脚本的政策是拒答必须可见。

转换写成 `Integer(raw, 10)`，进制固定为十进制。这样 `010` 会得到 `10` 而不是八进制的 `8`，`08` 也能通过。字母仍然失败。若录入还想拒绝空白、拒绝前导零这种「看起来补齐过」的写法，就在调用之前自己检查字符。负号在成绩里通常也该无效，所以检查不接受减号。检查越严，空格和字母越进不来，合法的 `72` 仍进得来。下面把检查加进同一骨架，仍然读两行。`72` 通过检查。这里用逐字符判断，不引入正则。空字符串无效。带空格的 `"72"` 无效，即使带进制参数的 `Integer` 能接受空白。政策选择变严：成绩字段不要空白。把空格删掉再解析，是另一种政策，会把 `"7 2"` 收成七十二分还是拒绝，需要另定。这里拒绝。

实现上，先确认每个字符都在 `"0"` 到 `"9"` 之间。可以 `raw.each_char` 配 `all?`。`all?` 在每一项都使块为真时为真，空字符串上为真，所以还要求长度大于零。空字符串若只靠 `all?` 会漏进 `Integer`，`Integer` 会再抛异常，结果仍是「分数无效」，碰巧安全。长度条件是为了把理由放在检查里，而不是靠下一步的异常。`all?` 遇到第一个不是数字的字符就停，这是短路，和真值短路是不同层面的「少做后续」，不要混成一个词。

```ruby run stdin="Ada\n72\n" expect="通过" title="只收十进制数字"
name = gets.chomp
raw = gets.chomp
line = 60
digits = raw.length > 0 && raw.each_char.all? { |ch| ch >= "0" && ch <= "9" }
if digits
  score = Integer(raw, 10)
  puts "#{name} #{score}"
  puts(score >= line ? "通过" : "再试")
else
  puts "#{name} 分数无效"
end
```

`72` 仍通过。`no` 不会进 `Integer`。只检查「每个字符都是数字」时，`010` 会通过检查，再被十进制规则收成 `10`，然后走「再试」。那是十分，不是八分，但仍然把补零悄悄收成了另一个分数。若业务认为补零可疑，就再拒绝「长度大于 `1` 且以 `0` 开头」。`0` 本身应当是合法的零分。这个条件把「一个零」和「一串带前导零的数字」拆开。零分是再试，`00` 走无效。下面的块加上这条，并用 `0` 作为输入，确认走「再试」。

```ruby run stdin="Ada\n0\n" expect="再试" title="零分仍是数字"
name = gets.chomp
raw = gets.chomp
line = 60
leading = raw.length > 1 && raw[0] == "0"
digits = raw.length > 0 && raw.each_char.all? { |ch| ch >= "0" && ch <= "9" }
if digits && !leading
  score = Integer(raw, 10)
  puts "#{name} #{score}"
  puts(score >= line ? "通过" : "再试")
else
  puts "#{name} 分数无效"
end
```

`raw[0]` 在空字符串上是 `nil`，不过空字符串已经在 `digits` 里被长度挡住，并且 `leading` 要求长度大于 `1`。`0` 的长度是 `1`，不是前导零形式。输出是 `Ada 0` 和「再试」。真值没有把 `0` 判成无效，比较也没有把它判成通过。

这份脚本还缺循环。真实录入会有很多名，直到读到结束。结束时 `gets` 返回 `nil`，你要在 `chomp` 之前停下来。循环的退出条件就是这个 `nil`，不是空字符串。空字符串可能是用户留空的一行，`nil` 才是没有更多输入。把两者都当成结束，会让留空和文件结束合成一种反应。小项目可以规定留空结束，那是你的协议，要写出来，并且不要再把留空当成「分数无效」。一份协议只选一种。这一章的样例只有两行，不写循环，是为了让失败政策先稳定。加上循环而不处理 `nil`，第一个会炸的是 `chomp`。

也可以把一名收成哈希 `{ name: name, score: score }`，键用符号。无效的那一名不要放一个 `0` 进 `:score`。可以不放进清单，或放 `:error`。清单的元素形状要一致，否则后面的 `map` 会在某一项上找不到 `:score`。一致性比「先存下来再说」更重要。五个名字以内，数组套哈希够用。要按姓名查找时再考虑外层用姓名当键，并决定重名怎么办。重名是数据问题，不是哈希的语法问题。

提示若加回去，应当用 `print`，并且放在对应的 `gets` 之前。输出里会先出现提示再出现结果，因为输入不会自动回显到你用来核对的那条结果上。有的终端会把按键再画出来，那是终端的回显，不是 `puts` 打的。核对子串时认 `"Ada 72"` 这种结果，不认提示。把提示和结果拼在同一行会让子串难找，也会让两行协议变成「提示占了半行」。教学脚本省掉提示，是为了结果只有记录。加上提示的版本应当仍读满两行，不能因为多了文字就多一次 `gets`。

循环读到没有更多行，骨架是先 `name_line = gets`，为 `nil` 就停，否则再读分数行。分数行单独缺失，也是协议错误，应当算无效，而不是让 `chomp` 碰到 `nil`。内层先判断再 `chomp`。外层的结束只认姓名那一次读到的 `nil`。这样空姓名和文件结束仍然不同：空姓名是空字符串，可以按无效处理；`nil` 是停止。样例只有两行时不写这个循环，是为了把无效政策先固定住。循环是在同一政策外套一层，不是另一套及格规则。

一名的结果若要放进数组，成功时放 `{ name: name, score: score }`，失败时不要放 `score: 0`。可以放 `{ name: name, error: :invalid }`。后面的 `select` 用 `item.key?(:score)` 找出能比较的项，再用 `map` 取出分数。键的约定比再写一个平行数组更不容易错位。平行数组里姓名和分数分属两张清单，插入一处漏了另一处，人就会配到别人的分。一张表一个人，缺的字段用键的存在与否表示，而不是用 `0`。`0` 已经留给真实的零分。

多人的及格人数是对这张清单做 `select` 再取长度，不是在读入循环里顺便用真值累加。累加条件若写成 `if score`，零分会被算进「有成绩」甚至被误加。累加应当发生在已经确认 `score` 是整数之后，条件用 `score >= line`。读入循环负责制造清单，统计负责提问。混在一个循环里也能跑，但无效、零分和及格三种计数容易共用一个加一。分开之后，这一章的单人脚本只是清单长度为 `1` 的特例。

无效行若来自一份长名单，人话里最好带上原始的 `raw`，而不是只写姓名。`Ada 分数无效` 在只有一名时够用。十名里有两名无效，只看姓名还要回到输入里找他们写了什么。把 `raw` 放进句子要先去掉换行，否则换行会把一条记录拆成两行，下一行的姓名看起来像分数的续行。格式可以是姓名、空格、原始文本、空格、固定的「无效」。原始文本若包含空格，句子会难切分，这时才需要更严格的分隔。两行协议的课例没有这个长度，句子保持短。等循环出现，再把原文加进无效结果，不要等用户抱怨分不清谁写了 `no`。

零分、及格、无效三条路径的输出动词不要复用。通过、再试、分数无效，三句里没有互相包含的子串，核对时不会把一条误认成另一条。「再试一次」如果包含「再试」，子串检查会把两句当成同一结果。教学输出因此用完整且不嵌套的词。你自己改文案时保持这个性质，比文案好听更重要。程序的决定已经由比较和异常做完，句子只是把决定念出来。

## 小结

两行输入先变成 `name` 和 `raw`，行尾在绑定之前去掉。`Integer` 成功之后才用 `score >= 60` 决定「通过」或「再试」。`Ada` 配 `72` 通过，配 `48` 再试。`"no"` 进 `rescue`，输出「分数无效」，不会被收成零分再去比较。

`Integer(raw, 10)` 把进制固定成十进制，字母仍会失败。只允许数字字符时，空格也进不来。长度为一的 `"0"` 是零分，走「再试」；更长且以 `0` 开头的文本走无效，避免把补零收成另一个十进制分数。留空和读到结束不是同一种值。循环以后再加，退出看 `nil`，无效不要写进分数槽。
