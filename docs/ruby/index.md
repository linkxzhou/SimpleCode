很多人第一次坐到 Ruby 前面，会把「对象」理解成自己用 `class` 声明出来的那种东西。座位号、页数、金额都被当成配角，好像它们只是方法参数里的原料。这个印象会在后面每一章里收费。Ruby 的求值规则更扁：一个字面量先变成对象，对象能接收消息，消息的名字就是方法。`42` 在被你放进任何变量之前，已经是一个整数对象。你写 `seat = 42`，只是让名字 `seat` 指向它，并没有把一个「原始数字」升级成对象。

这种安排来自 Smalltalk 那一支的口味，而不是来自「先有机器字，再在上面盖一层对象系统」。好处是脑内只有一套说法。问一个座位是不是偶数、问它的类、给它加八，都是把消息送给同一个接收者。代价也直白：一次加法在概念上是一次方法调用，解释器得花功夫把它做快。你交出的是一点点「整数应该像寄存器里的裸值」的直觉，换来的是以后写自己的对象时不用再学第二套调用规则。觉得 `seat + 8` 看起来不像发消息，是因为语言在语法上给少数方法发了通行证，不是因为加法走了另一条语义。

下面每个代码块都是一份单独的脚本。后一块不会接着前一块里的变量继续活，所以还要用到的名字会再写一遍。这是为了让某一块能单独运行，不是 Ruby 规定两个文件之间必须失忆。这一章的脚本都围着同一个座位号转。

```ruby run expect="偶数座位" title="座位接收 even?"
seat = 42
puts(seat.even? ? "偶数座位" : "奇数座位")
puts seat.class
```

`even?` 末尾的问号是方法名的一部分，不是三元运算符。Ruby 允许方法名以 `?` 或 `!` 结尾，用来提醒读代码的人：这个方法在提问，或者这个方法会改动接收者。`even?` 属于前者。它的返回值不是整数 `1` 或 `0`。条件成立时你得到的是对象 `true`，不成立时是对象 `false`。打印出来像两个英文单词，那只是它们的文字外观。`true` 的类是 `TrueClass`，`false` 的类是 `FalseClass`。把它们当成「数字的另一种写法」会在后面判断真假时栽跟头，这里先记住：提问方法交回来的是答案对象。

`seat.class` 打出来的是 `Integer`。老教材里常出现 `Fixnum` 和 `Bignum`，那是按机器字长把整数分成两类的年代。Ruby 3.2 对外只留一个 `Integer`。实现内部仍然会在数字变大时换一套表示，你的代码看不到那个切换，也不该按类名去分支。统一的代价是你少了一个「这个数是不是塞得进一个字」的类型标签；换来的是类名不再泄漏实现。若你在旧笔记里看到 `kind_of?(Fixnum)`，在这门课的解释器上它不会是你想的那种判断。

问号方法还有一个容易被看漏的点：`seat.even?` 只是查询。它不把座位改成别的数，也不该改。整数对象拒绝被就地改写，这不是风格建议，是值的身份。若 `42` 这个对象能被改成 `43`，进程里所有指向 `42` 的地方会一起变，加法就没有稳定的含义了。所以「让数字变大」在 Ruby 里永远是「算出另一个整数，再决定要不要让变量改指过去」。

`succ` 把这件事表现得很具体。它的意思是后继，对 `42` 来说就是 `43`。调用本身产生新对象，左边的变量纹丝不动。有人写完 `seat.succ` 就去打印 `seat`，看到仍然是 `42`，会怀疑方法坏了。方法没有坏，是返回值被丢掉了。你要么把返回值交给 `puts`，要么把它绑定到新的名字上。下面这一块把两件事都做了：`next_seat` 接到后继，原来的 `seat` 仍是 `42`。输出里先出现 `43` 再出现 `42`，就是这个契约。

```ruby run expect="43" title="后继是另一个整数"
seat = 42
next_seat = seat.succ
puts next_seat
puts seat
```

若你只想要后继的文字、不关心旧座位，可以写 `puts seat.succ`。那一行的接收者仍是 `42`，打印的是返回值。不要在同一行里既指望它修改 `seat`，又指望它把新数字交出来。一个方法可以有副作用，也可以有返回值；整数的 `succ` 选择了只有返回值。字符串那一章会遇到相反的选择，有的方法改缓冲区本身。两种设计都合理，混着记就会在「为什么这个变量没变」上反复停下来。

加号是同一套消息机制，只是写法特权更多。`seat + 8` 是 `seat.+(8)` 的糖。点号后面的 `+` 是方法名，括号里的 `8` 是参数。解释器允许你把这个方法写成中缀，是为了让算术仍然看得下去。你以后可以给自己的类定义 `+`，于是中缀也能用在那些对象上。特权的另一面是优先级和结合性变成了语法问题，不只是方法调用的问题。你以为自己在发消息，解析器先按运算符表把式子拆开。这一章的可运行例子把加号写成方法调用的样子，就是为了把糖剥开看一眼。日常代码里继续写 `seat + 8` 即可，两种写法调用的是同一个方法。

`zero?` 和 `even?` 一样，是提问，不修改接收者。`42` 不是零，所以答案对象是 `false`，打印出来就是 `false`。`send` 则把方法名当成数据：`seat.send(:even?)` 和直接写 `seat.even?` 走的是同一条调用。符号 `:even?` 在这里只是方法名的携带方式，符号和字符串的差别放到整数除法那一章再拆。眼下要警惕的是 `send` 的权限。它能叫到私有方法。用来在练习里确认「名字就是消息」是合适的，用来绕过别人类上故意不公开的接口，会把封装变成装饰。课程里的例子只 `send` 我们刚刚已经直接调用过的公开方法。

```ruby run expect="50" title="加号也是方法"
seat = 42
puts seat.+(8)
puts seat.zero?
puts seat.send(:even?)
```

这一块的三行输出是 `50`、`false`、`true`。`50` 是加法的返回值，`seat` 仍然是 `42`，只是这次没有再把它打印出来。`false` 来自 `zero?`，`true` 来自 `even?`。三个结果的类型并不一样：一个是整数，两个是布尔对象。`puts` 只负责把它们各自的文字写到输出里，它不会把 `false` 变成整数 `0`。若你把这三行用别的语言的习惯去加总，会先撞上类型，而不是先得到一个总和。

整数还有一层更容易被忽略的身份问题。小整数在实现上常常是立即值，同一个数值会是同一个对象。`42` 和另一个 `42` 用 `equal?` 去问，答案是 `true`，因为它们根本是一个对象。这不意味着「整数按对象身份比较」。一旦数字大到装不进立即值，两个数值相等的整数会是两个对象：`==` 仍为真，`equal?` 为假。`==` 问的是数值，`equal?` 问的是是不是同一个对象。你若用 `equal?` 去判断座位号相不相等，在小数字上会碰巧通过，在大数字上会无故失败。比较座位、页数、金额，用 `==`。

`eql?` 比 `==` 更挑剔，它还在乎类。`42 == 42.0` 在数值比较里为真，`42.eql?(42.0)` 为假，因为一个是 `Integer`，一个是 `Float`。哈希表用 `eql?` 配哈希码来认键，所以整数 `1` 和浮点 `1.0` 不会落进同一个键。这一章先把现象看清楚，哈希的用法以后再说。选 `==` 还是 `eql?` 是一种取舍：`==` 适合人类说的「这个数一样大」，`eql?` 适合容器说的「这个键是不是同一类东西」。混用的坑就在 `42` 和 `42.0` 这种看起来相等、放进哈希却分家的一对。

```ruby run expect="false" title="数值相等和同一对象"
small_a = 42
small_b = 42
puts small_a.equal?(small_b)
big_a = 10**30
big_b = 10**30
puts big_a.equal?(big_b)
puts big_a == big_b
puts 42.eql?(42.0)
```

输出四行是 `true`、`false`、`true`、`false`。第一行是两个小 `42` 为同一对象。第二行是两个 `10**30` 数值相同但不是同一对象，`**` 是幂。第三行说明数值比较仍然成立。第四行是整数和浮点在 `eql?` 下分开。`10**30` 这种写法本身也是方法：`**` 和 `+` 一样是消息，只是中缀。幂的结果是一个新的大整数，它不会把 `10` 这个对象改掉。

浮点不是「更精确的整数」。`42.0` 的类是 `Float`，它能表示小数，也带着二进制浮点的误差。座位号不该用它。这一章坚持用 `Integer`，是因为座位的后继、奇偶、是否为零都有确切答案。什么时候值得把整数除成浮点，留到除法那一章，在那里取舍会具体到「一个人分到多少」。这里只要记住：多写一个 `.0`，你就换了一个类，而不是把同一个对象变得更细。

还有一个和语法缠在一起的细节。`42.even?` 能工作，是因为 `even?` 不可能是浮点字面量的一部分，解析器把点号看成方法调用。你不需要写成 `(42).even?`，虽然那样也对。真正要防的不是这个点号，而是把返回值扔掉，或者用 `equal?` 比较大整数的数值。括号在这一章的作用很窄：`puts(seat.even? ? "偶数座位" : "奇数座位")` 里的括号是为了让三元表达式明确地当作 `puts` 的参数。没有这层括号时，这一句在 Ruby 3.2 里碰巧也是这个意思，但下一章会遇到括号一挪、三元表达式就改嫁给返回值的情况。在还没讨论输出方法之前，可运行的例子把参数括号写上。

负数仍然是 `Integer`。`refund = -8` 之后，`refund.abs` 交回 `8`，`refund` 自己保持 `-8`。绝对值和后继是同一类契约：查询或换算产生新对象，接收者不变。写 `-8.abs` 在 Ruby 3.2 里会先取负再求绝对值，结果也是 `8`。老版本里一元负号和点号的结合曾经让人吃惊，现在这条式子的结果是正数，但读代码的人仍会停顿。要给人看的例子写成 `refund.abs`，让接收者先有名字。不要靠「负号写在字面量前，方法就会改掉那个字面量」这种想象，字面量从来就不是一个可以改的槽。

`pred` 是 `succ` 的反方向，`42.pred` 得到 `41`，同样不改接收者。有它不代表你该用它来写倒计时。循环和数组会提供更清楚的次数控制。这里提 `pred`，只是为了把「后继」从魔法词还原成整数上的一对方法。你能在文档里继续找到 `gcd`、`lcm`、`digits`。`digits` 把 `42` 拆成数组 `[2, 4]`，个位在前，这和你从左往右读十进制的习惯相反。这个顺序适合从低位做进位，不适合直接拿去拼接成显示用的字符串。若你只是想要十进制文字，`puts seat` 已经会做；`digits` 是在要每一位的数值。用错方向时，你会把 `42` 显示成 `24`，而测试仍可能因为「数字都在」而放过你。

把这一章收成一句能用的话：变量是箭头，整数是箭头指向的、不能就地修改的对象。消息可以问它问题，也可以向它要一个新的整数。你保存哪个返回值，决定下一行看见的是后继还是原座位。类名告诉你它是 `Integer` 还是 `Float`，比较符告诉你你在问数值还是在问身份。后面写数组、哈希和自己的类时，都是在给别的对象发消息。若数字这一关仍然觉得「只有类的实例才算对象」，那些章节的方法调用会显得像另一门语言。

## 小结

整数从字面量诞生时就是对象。`even?`、`zero?`、`succ` 和 `+` 都是发给它的消息；问号方法交回 `true` 或 `false`，`succ` 和加法交回另一个整数。`seat.succ` 不会让 `seat` 改指新值，你必须自己接住返回值。Ruby 3.2 里这些值的类是 `Integer`，不再用 `Fixnum` 和 `Bignum` 作为你要分支的类型。

`==` 比较数值，`equal?` 比较是不是同一个对象，`eql?` 还要求类一致，因此 `42` 与 `42.0` 会在数值上相等、在哈希键的意义上分开。小整数的 `equal?` 可能为真，大整数则不要靠身份来判断相等。运算符是方法的中缀写法，方便阅读，也把优先级问题留在语法里。保存返回值、选对比较，比记住「万物皆对象」这句口号更决定你下一行的输出。
