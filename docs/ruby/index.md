Ruby 在这里由随仓库提供的 Ruby 3.2 解释器执行。点代码块上的 Run，示例会换进主编辑器并马上跑。原来的草稿先备份，可以撤销。每次运行都是新进程：上一段里的变量、打开的文件都不会留下。

这里没有网络，也装不了 gem。能写的是语言本身：puts、数组、哈希、方法、块和类。需要别的文件或第三方库时，把那段标成只读，并写明原因。期望输出是子串。程序可以多打一行说明，只要关键结果还在。

工具栏上的 Run 和代码块上的 Run 是同一个按钮。代码块负责写入示例再运行；工具栏只运行编辑器里已经有的内容。下载进度写在按钮旁边。

```ruby norun title="只读"
# gem install 在这里不会成功，也不要在可运行示例里访问网络。
# require "net/http"
```

```ruby run expect="42" title="相加"
puts 19 + 23
```

```ruby run expect="你好" title="问候"
puts "你好"
```

「只读」故意不能运行。先读它旁边的限制，再回到能点 Run 的例子上改一个值。不要把只读块当成坏掉的按钮。

### 读「相加」

做完上一例再做这一例。把代码收成一行来记：`puts 19 + 23`。先盖住终端，写下你预测的输出，里面要能找到「42」。这是子串：前面可以有别的字，后面通常有换行。

然后点这个代码块上的 Run，不要点工具栏。代码块会备份草稿、写入示例再执行。找不到这段文字时，先看退出码。不是 0 就读错误类型，不要改期望。是 0 但内容不对，就只改产生该值的那一处。改完用工具栏的 Run，因为再点代码块会把修改盖掉。预测对了之后点撤销。

### 限制：只读

这一段故意不能运行。旁边的限制是：把上一次运行的变量当成还在。每次 Run 都是新进程。。做法是：每个示例都写成能单独运行的完整脚本。。把它留在抽屉里对照，不要粘进主编辑器再点工具栏的 Run。能运行的例子在它前后，改那些例子时不要把这里的调用加进去。

### 只改一处：相加

这一例要避开的失误是：在可运行块里 gem install 或访问网络。。对应的做法是：做不到的事用只读块标出来。。

把代码收成一行来核对：`puts 19 + 23`。盖住终端，先写下预测，里面要能找到「42」。然后点这个代码块上的 Run。结果不同时，只改产生该值的那一行，再用工具栏的 Run 看新结果。不要把两处不相关的改动叠在一起。确认之后点撤销，下一例才会从文档里的代码开始。

若出现报错，先看错误类型的名字，再回到本章的常见错误。期望是子串，多出来的说明行不算失败，缺了「42」才算失败。

## 读完再动手

本章要留下的是 「知道每次运行都是新进程」、「分清可运行示例和只读示例」、「用 puts 看到结果」。合上抽屉之前，用自己的话说出每一项目标对应哪一个示例的标题。对不上标题，就还没有把目标和代码连起来，先别展开练习答案。

练习的答案默认折着。先在编辑器里自己写，再展开对照。对照时只看输出是否包含期望的那几个字。两道都过了再进入下一章。下一次运行是新进程，这次的变量不会留下。

把这一章当成一次可以反复撤销的实验。点代码块上的 Run 会用示例覆盖编辑器，原来的草稿先备份。你改过的内容如果还想留着，先复制到别处，再点下一例。工具栏的 Run 不会从文档重写编辑器，所以它用来看你改过的版本。两种按钮各做各的事。下载进度写在按钮旁边，第一次打开这种语言时要等它结束，再判断示例是不是写错了。

记录你预测错的那一次。写下你以为会打印的文字，以及实际多出来或少掉的部分。进入下一章之前，要能用一句话说清差在哪。通过只说明期望的那几个字还在，不说明你已经看懂产生它的那一行。章节标题下的目标就是这份验收清单。差两个字也不要靠改期望凑过去。

## 常见错误

- 把上一次运行的变量当成还在。每次 Run 都是新进程。
- 在可运行块里 gem install 或访问网络。
- 把期望写成整段终端横幅，而不是稳定的子串。

## 最佳实践

- 每个示例都写成能单独运行的完整脚本。
- 做不到的事用只读块标出来。
- 用 puts 打出你要核对的那一个值。

## 小结

Ruby 101 的例子在一次新的 Ruby 3.2 进程里运行。没有 gem 和网络。puts 把结果写到终端，期望是子串。
