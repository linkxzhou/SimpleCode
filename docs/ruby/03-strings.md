整数不能就地改，字符串可以。这个对比不是为了让字符串显得更灵活，而是两种数据的身份不一样。整数 `42` 的身份就是这个数值，改掉它会连累所有指向它的人。字符串是一块带编码的缓冲区，名字指向缓冲区，缓冲区里的字符允许更换。你拥有这块缓冲区时，`<<` 和按下标赋值会改它本身，别的仍指向它的变量会看见变化。你不拥有它时，就地改就是把别人的句子改了。Ruby 3.2 默认不把源码里的字符串冻住。有的项目会打开冻结字面量，于是 `"ruby"` 不能再 `<<`。这门课的解释器没有打开那个开关，例子里的修改是真的会发生。换到打开了开关的项目，同样的行会以运行错误停住。写库的人因此常在修改前先 `dup` 出一块自己的缓冲区。多一次复制，换来不碰调用者的字符串。

这一章的缓冲区叫 `title`，内容从 `"rubyist"` 开始。七个字符，都是英文，下标和「第几个字」一致，暂时不必处理「一个汉字几个字节」。Ruby 的字符串下标按字符计，不按字节计。`"入门"[0]` 是 `"入"`，不是某个字节。`bytesize` 才会看见编码后的字节数。把字节下标用在字符接口上，会在汉字处切出半个字符。下面的例子先用英文把长度问题看干净，练习里再碰一个短的中文。

`title[0, 4]` 里的两个数不是「起点和终点」。第一个数是起点下标，从 `0` 开始。第二个数是要取的长度。起点 `0`、长度 `4`，得到 `"ruby"`，而不是一直取到下标 `4`。下标 `4` 上的字符是 `i`，若有人把第二个数当成终点，他会想把 `i` 也包括进去，实际结果却停在 `y`。范围写法 `title[0..3]` 才是两端都包含的下标，结果同样是 `"ruby"`，因为下标 `3` 是 `y`。两种写法都能用，数字的含义不同。从别的语言带来「切片右端不包含」或「第二个数是终点」时，会在长度为 `4` 的时候碰巧和某种习惯对齐，在别的长度上错一位。看第二参数时先问：这是长度还是下标。

```ruby run expect="ruby" title="长度不是终点下标"
title = "rubyist"
puts title[0, 4]
puts title[0..3]
puts title.length
```

三行是 `ruby`、`ruby` 和 `7`。`length` 是字符数。切片没有改 `title`，它返回一个新的字符串。你若指望 `title[0, 4]` 把变量截短，下一行仍会看到完整的 `rubyist`。截短要赋值回去，或者用替换。

替换时，第二个数仍是长度。`title[0, 4] = "RUBY"` 把从下标 `0` 起的 `4` 个字符换成这四个大写字母，后面的 `ist` 还在，结果是 `RUBYist`。新写上去的内容不必和删掉的长度相同。写成 `"R"` 就会变短，写成更长的一串就会把后面的字往后推。这是就地修改：没有把 `title` 这个名字改绑到另一个对象，是这块缓冲区的内容变了。若还有别的变量指着同一块，那些名字也会看到新内容。方法若接收了调用者的字符串并在内部切片赋值，调用者的变量会变，这是副作用，不会写在返回值里。

`<<` 也是就地的，它在末尾追加。`title << "!"` 之后，原来的对象末尾多了一个感叹号。`+` 则不同，它返回新字符串，不改左边。`title + "!"` 若不去接住返回值，`title` 仍是旧内容。一个人在同一段代码里混用 `<<` 和 `+`，会觉得「有时改了有时没改」。规则其实稳定：带叹号的方法名，以及 `<<`、下标赋值，常常表示动接收者；`+` 和切片读取表示交出新值。叹号不是语法强制，是命名习惯。没有叹号的 `<<` 同样会修改。不要只靠有没有 `!` 来判断。

```ruby run expect="Rubyist!" title="就地追加并改首字"
title = "rubyist"
title << "!"
title[0] = "R"
puts title
```

`title[0] = "R"` 替换的是长度为 `1` 的那一个字符。单下标赋值和「起点加长度」是同一家族，只是长度省略成一个字符。把 `"RR"` 赋给单下标，会在那个位置插入多余的字符，缓冲区变长。你若只想替换、不想改变长度，赋一个字符，或明确写出长度。

下面把切片读取和切片赋值接在同一份 `title` 上。先读出前四个字符，确认是 `ruby`，再按长度 `4` 替换成 `RUBY`，最后应当看到 `RUBYist`。中间没有新建一个叫 `title` 的替换变量。

```ruby run expect="RUBYist" title="按长度替换前四字"
title = "rubyist"
puts title[0, 4]
title[0, 4] = "RUBY"
puts title
```

`gets` 读入一行。它的契约是：若输入在换行处结束，返回的字符串里包含那个换行；若文件在没有换行时结束，返回的字符串不包含换行；若已经没有内容，返回 `nil`。课程里的样例输入会带上换行，于是 `gets` 拿到的是内容加一个 `\n`。这个换行是行协议的一部分，不是用户「输入了反斜杠和一个 n」。你把它留在字符串里，后面的比较会失败：`"Ada\n" == "Ada"` 为假。`chomp` 去掉结尾的换行，交回一个新字符串，原来的缓冲区还带着换行。想就地去掉，用 `chomp!`。最清楚的写法是 `title = gets.chomp`，让名字直接指向去掉行尾之后的那一份。调用两次 `gets` 会再读一行。一行输入上写 `gets.chomp` 两次，第二次读到结束，得到 `nil`，`nil` 没有 `chomp`，脚本以找不到方法停住。先把一行放进变量，再决定要不要去掉行尾。

```ruby run stdin="Ada\n" expect="带着换行" title="gets 保留行尾"
title = gets
puts(title.end_with?("\n") ? "带着换行" : "没有换行")
```

样例输入是 `Ada` 加换行。`end_with?` 问的是缓冲区末尾，不是问用户有没有在屏幕上看见换行。终端常常把换行显示成「跳到下一行」，你看不见一个字符，它却在字符串里。用 `puts title` 去观察时，这个换行和 `puts` 自己补的换行叠在一起，看起来像多了一行空白。那是两套换行，不是 `puts` 坏了。要看清隐藏字符，可以问 `end_with?`，或打印检查形式。检查形式里的换行会显示成反斜杠和 `n`，那是给程序员看的转义，不是用户输入了两个字符的反斜杠和 n。

去掉行尾之后，末尾不再是换行，内容是 `Ada`，长度为 `3`。`chomp` 只处理结尾的换行，不删中间的空白，也不删行首的空格。用户若输入了空格，那些空格还在。`strip` 才会削掉两端的空白，它的动作比 `chomp` 大。登录名这种字段用 `chomp` 通常就够；若你还想拒绝前后空格，要明确再削，并接受「两个空格」和「零个空格」被收成同一个名字的后果。

```ruby run stdin="Ada\n" expect="没有换行" title="chomp 之后的标题"
title = gets.chomp
puts(title.end_with?("\n") ? "带着换行" : "没有换行")
puts title
puts title.length
```

三行是「没有换行」、`Ada` 和 `3`。这一块的 `title` 和前面几块同名，但是一份新的脚本，内容来自输入，不再是 `rubyist`。同名是为了让你看见：缓冲区从字面量来，或从输入来，修改和切片的规则相同。输入来的字符串同样可以 `title[0, 1] = "a"`，那会就地改掉用户刚才给的字。改输入缓冲区本身没有问题，只要你知道后来的比较用的是改过的内容。

`chomp` 和 `chomp!` 把「要新字符串」和「改原缓冲区」拆开了。`raw = gets` 之后，`cleaned = raw.chomp`，`raw` 末尾仍是换行，`cleaned` 没有。这和 `+` 同类，和 `<<` 相反。`raw.chomp!` 才会把 `raw` 自己的行尾拿掉，并返回改过的那一块；若末尾本来就没有换行，`chomp!` 返回 `nil`，表示没有发生修改。把 `nil` 当成去掉之后的正文，会在「用户最后一行没有换行」时丢掉正文。所以读入用 `gets.chomp` 接住返回值，不要用 `chomp!` 的返回值当内容。需要保留带换行的原文时，保留 `raw`，另用一份 `cleaned`。

切片和输入会碰到同一处边界。用户输入 `rubyist` 加换行，你先 `chomp` 得到七个字符，再取 `title[0, 4]`，才是 `ruby`。若忘记 `chomp`，长度会变成 `8`，最后一个字符是换行。取前四个字符碰巧仍是 `ruby`，因为换行在末尾，短切片看不出来。取 `title[-1, 1]` 或比较整个字符串时才会暴露。坑藏在「短切片碰巧对」里。所以读完一行先处理行尾，再谈下标。

空输入也要有个说法。若在还没有一行时调用 `gets`，返回 `nil`。对 `nil` 调用 `chomp` 会失败。课程样例都会提供一行，例子里不写分支。真正面对可选输入时，要先接住 `gets` 的返回值，判断是不是 `nil`，再 `chomp`。把 `gets.chomp` 写成一个习惯句，在有输入时很顺，在结束时会炸。这个炸是明确的，比悄悄得到空字符串更容易发现，也要求你在调用点做一次判断。

`dup` 复制一块新的缓冲区，之后对原件 `<<` 不会改到副本。这是字符串可变带来的必要动作。你把 `title` 交进一个会追加的方法之前，若调用者还要旧内容，就传 `title.dup`。不复制的代价是快，调用结束时两边看见同一句。复制的代价是多一块内存，两边从此分家。只复制数组、不复制里面的字符串，是另一层问题，书单那一章的槽位和这里的字符缓冲区不是同一次复制。

```ruby run expect="rubyist!" title="副本不跟着改"
title = "rubyist"
snapshot = title.dup
title << "!"
puts snapshot
puts title
```

`freeze` 把缓冲区钉住。对钉住的字符串 `<<` 或按下标赋值，会以冻结错误结束，而不是安静地没改。钉住适合放进哈希当键之后，防止键的内容变了、哈希却还按旧内容找。课程例子默认不钉住字面量，所以 `title << "!"` 能成功。你若在别的项目看到同样一行失败，先看文件顶部有没有把字面量钉住的开关，再怀疑方法名。自己调用 `freeze` 是局部决定，开关是整个文件的决定。局部决定更容易看出来，文件开关更容易漏。

编码默认是 UTF-8 时，汉字按字符计长度。`"入门".length` 是 `2`，`bytesize` 更大。切片的长度也按字符。把字节数传进 `title[0, n]` 会在汉字中间切坏，或者切进下一个字。英文的 `rubyist` 看不出这个差别，因为一个字符一个字节。处理姓名时不要用 `bytesize` 当屏幕宽度，宽字符的显示宽度又是第三个数。长度、字节数、显示宽度，三个接口，三种用途。下标用第一种。

`<<` 返回接收者自己，所以可以连着追加。返回的不是「追加了几个字符」的计数。你若把 `title << "!"` 放进条件，条件看的是字符串对象，字符串为真，追加总会被认为成功。想知道有没有真的变长，比较前后的 `length`。返回接收者是为了能链式写，不是为了报告成败。失败会用异常表示，例如钉住之后再追加。

## 小结

`title` 从 `"rubyist"` 出发时，是一块可以改的缓冲区。`<<` 和下标赋值改的是它本身，切片读取和 `+` 交出新字符串。`title[0, 4]` 的 `4` 是长度，得到 `ruby`；范围 `0..3` 才用两端下标。按长度替换前四字，后面的 `ist` 还留着。

`gets` 在样例这种带换行的输入里，会把换行留在字符串末尾，于是和 `"Ada"` 不相等。`title = gets.chomp` 去掉这个行尾。再读一次 `gets` 是在要下一行，结束时会得到 `nil`。先处理行尾再做切片，避免换行只藏在你没看的那一端。
