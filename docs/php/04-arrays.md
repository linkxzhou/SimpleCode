一张小票很少只有一行。铅笔、橡皮、直尺要按店员写下的顺序留在纸上，合计还要能按品名找到已经累加的分。PHP 的数组同时承担这两件事。它是有序映射：每个元素有一个键，键和值的配对按插入顺序排列。列表和字典在别的语言里常常是两种结构。在这里它们是同一种结构的两种写法。小票因此可以既按行号遍历，又按品名取值。代价是你要自己记得某个数组这一次是当列表用，还是当价目表用。混在同一个数组里也能运行，下一班会很难看出下标 `0` 和键 `"铅笔"` 为什么并肩出现。

列表写成 `[350, 200, 450]`。没有写出的键会从 0 开始编号。第一件的下标是 `0`，不是 `1`。小票的行号若想从 1 开始给顾客看，那是显示时加一，不是把数组的第一项放在下标 1。硬把第一项写成 `1 => 350`，后面用 `[]` 追加的项会接在最大整数键之后，顺序仍在，下标却不再连续地从 0 数。课程的行列表保持自动下标。顾客看见的「第 1 行」由打印时的计数器产生。

价目表写成 `["铅笔" => 350, "橡皮" => 200]`。键是品名，值是单价的分。字符串键区分精确的文字。`"铅笔"` 和 `" 铅笔"` 是两个键，前面多一个空格就不会命中。上一章的 `trim` 若只用于打印、不用于做键，查找会落空。做键之前先把两端空白去掉，是数组和字符串交界的地方。整数键和数值字符串键会在 PHP 里被收成同一个整数键。`["0" => 350]` 的键其实是整数 `0`。货号若真的需要保留字符 `"0"` 和整数 `0` 的差别，不要用数组的键来保留。这是映射的一个老规则，为了让 `$row[$i]` 在 `$i` 是 `"0"` 时仍能工作。小票的品名是汉字，不会撞上这条规则。一旦出现纯数字的货号，就要记住键可能被转成整数。

读取不存在的键会发出警告。警告在 php-cgi 里是一段 HTML，后面也许还跟着一个空值，小票就脏了。`??` 在键缺失或值为 `null` 时给出你写的默认，并且不发出那条警告。`$price["尺子"] ?? 0` 在没有尺子时得到 `0`。默认值的选择是业务决定，不是语法决定。缺失的单价若默认成 `0`，这支尺子会变成免费。巷口纸品不卖免费的尺子。示例里若用 `0`，只是为了让纸上有一个可见的数，并在旁边的句子里说明这个 `0` 表示「表里没有」，不表示「价格是零」。更稳的打印机会在缺失时印出「无此品」，而不是把零分加进合计。`??` 不把整数 `0` 当成缺失。表里若真有一个键，值是 `0`，`??` 会留下这个 `0`。`0` 分和「没有这个键」因此可以分开，只要你不要用 `?? 0` 把第二种也变成 `0`。想分开，缺失时就用一个不会和价格混淆的默认，例如不去加总，先印出固定的词。

空数组 `[]` 在条件里为假。`if ($lines)` 在一张还没有货行的小票上会走假分支。这能用来跳过空单，也会把「变量还没有准备好」和「准备好了但没有货」并成同一种假，只要两边都呈现为空数组。更明确的问法是 `count($lines) === 0`。`count` 回答元素个数，不回答字节，也不回答金额。三行货，`count` 是 3，即使每行的金额很大。`array_sum` 才把数字加起来。它会把数值字符串转成数再相加。价目表的值若都是整数分，`array_sum` 得到合计。值若混进品名字符串，PHP 8 里非数值字符串会让求和发出警告并按 0 参加。不要把品名和金额放在同一个列表里交给 `array_sum`。品名放在键上，或放在另一列。金额单独成一个只含数字的列表时，求和才安静。

顺序是插入顺序。先放入铅笔，再放入橡皮，`foreach` 会先看见铅笔。这不是哈希表「键的顺序无定义」的那种模型。小票依赖这个顺序：顾客要按购买顺序阅读，不是按品名排序。排序是额外的决定。你若调用排序函数，顺序会按那一次排序改变，原来的购买顺序就丢了，除非你另存一份。课程的价目表不排序。后写入的键排在后面。同一个键再赋值，不新增元素，只换值，位置留在第一次插入的地方。铅笔先以 350 写入，后来改成 380，它仍在第一位，金额变了。这个行为适合改价，不适合「再买一次就追加一行」。再买一次若要单独的一行，就用列表追加，不要用品名当唯一键。两种数组因此对应两种小票：按品名合并的价目，以及按次数保留的明细。这一章两边都看，合计项目会选定明细列表，因为顾客要看见两支铅笔是不是分两行写下的。

`foreach` 可以只取价值，也可以同时取键。`foreach ($prices as $name => $cents)` 里，`$name` 是品名，`$cents` 是分。循环变量在循环之后仍留着最后一次的值。下一块脚本若误用同名变量，会接到这个尾巴。每一块示例都是新进程，所以尾巴不会跨块。在同一个文件里，循环结束要意识到 `$name` 还在。把它放进更小的函数，是后面那一章的事。这里先把遍历写在脚本顶层，并在遍历结束后只打印你准备好的合计，避免再去用循环变量。

不要把数组交给 `echo`。引擎会试图把它转成字符串，转不成你要的清单，纸上出现的是 `Array` 这个词，同时还有一条转换警告。警告的 HTML 里也含有 Array 的字样。顾客不会把这个词理解成三行货。要印内容，就印某一个元素，或用下一章会细讲的 `implode` 把字符串列表收成一行。这一章先印单个单价、个数，以及 `array_sum` 的合计。故意印整个数组的那一块，是为了让 `Array` 这个词被看见一次，以后才不会把它当成合计。

追加用 `$lines[] = "铅笔 350"`。空的方括号表示「下一个下标」。它不覆盖已有的行。按键赋值 `$prices["铅笔"] = 350` 则是写入或覆盖那个键。两种写法差在键从哪里来。明细用追加，价目用键。删掉一个键用 `unset`。`unset` 之后，`count` 减少，后面的元素不会为了填补空洞而重新从 0 编号。列表中间空了一个下标时，`foreach` 会跳过那个下标，不会把后面的货顶上来变成新的 `0`。若你用 `for` 从 0 数到 `count - 1` 去取下标，空洞会让你读到缺失的键。小票的遍历用 `foreach`，它跟着存在的元素走，不跟着下标的空隙走。

下面的例子都写全数组，不依赖上一块。

```php run expect="550" title="按购买顺序合计"
<?php
$prices = ["铅笔" => 350, "橡皮" => 200];
echo $prices["铅笔"] + $prices["橡皮"], "\n";
$prices["直尺"] = 450;
echo count($prices), "\n";
```

第一行是 550，只用了前两件。第二行是 3，因为直尺在加法之后才写入。这个顺序说明：写入立刻改变数组，可是已经算完的 550 不会自动更新。合计是那一刻的值，不是和数组绑死的公式。你若希望合计永远跟着价目走，就要在每次改价之后重新 `array_sum`。把 550 存进变量再改价，变量不会跟着变。这是值的复制。小票上已经印出的那一行，也不会因为你后来改了数组而改写终端里的旧输出。要改纸面，就再印一次。

```php run expect="无此品" title="缺失的品名不发警告"
<?php
$prices = ["铅笔" => 350];
$found = $prices["橡皮"] ?? null;
if ($found === null) {
  echo "无此品\n";
} else {
  echo $found, "\n";
}
```

橡皮不在表里。`?? null` 把缺失收成 `null`，再用 `===` 判断。不把默认设成 `0`，是为了避免把「没有橡皮」印成 0 分并让人以为可以免费。若键存在且值就是 `null`，`??` 也会换成右边。价目表里不要存放 `null` 价格。要么不放这个键，要么放整数。这样 `null` 只表示缺失。

```php run expect="Array" title="整个数组不能当小票"
<?php
$lines = ["铅笔", "橡皮"];
echo $lines, "\n";
```

纸上会有 `Array`，并且带有转换警告。这一块是故意的。它的期望能对上，不表示它是一张合格的小票。合格的写法是下一块：只印个数，或印具体的一行。看见警告仍去改期望，是把失败伪装成成功。正式代码不要留下这一句 `echo $lines`。

```php run expect="2" title="空数组为假，有货再数"
<?php
$empty = [];
echo $empty ? "有货" : "空单", "\n";
$lines = ["铅笔 350", "橡皮 200"];
echo count($lines), "\n";
echo array_sum([350, 200, 450]), "\n";
```

第一行是空单。第二行是 2，第三行是 1000。三件金额的和是 1000 分，也就是十元。`array_sum` 的参数是只含整数的列表，和品名列表分开。空单那一行若改成 `count($empty)`，会印出 `0`。`0` 在纸上和「合计为零」长得一样。印「空单」这个词，是为了让没有货和合计为零在字面上分开。有货但每件都是 0 分时，`count` 不是 0，`array_sum` 是 0。两个函数回答两个问题。小票的页眉可以印行数，页脚印合计，不要用一个数充当两个角色。

数组可以嵌套。一行货可以是 `["name" => "铅笔", "qty" => 2, "cents" => 350]`，明细则是这些小数组的列表。外层用追加保持购买顺序，内层用字符串键保持字段名字。读取时写成 `$lines[0]["name"]`。外层下标从 0 开始，内层不靠下标。这种形状比平行的三个数组更难把品名和金额配错。平行数组占的内存看起来更扁，配错时铅笔会挨上橡皮的价格，而且类型系统不会出声。嵌套的代价是多一层方括号。小票的字段就三四个，这一层值得付。后面的函数和类会接收这种小数组，或把它们收进对象。这一章先让列表里放两个这种元素，并只印第一件的品名，确认层次是对的。嵌套不改变「有序映射」的定义。内层仍然是数组，仍然不能整个 `echo`。

把价目和明细的取舍说清楚，这一章才算用在打印机上。按品名合并，适合回答「铅笔一共多少分」，再买一次就加到同一个键上，纸上只有一行铅笔。按明细保留，适合回答「刚才那两次分别是多少」。巷口纸品的顾客小票用明细，因为退货时要指出是哪一行。库存汇总可以用合并。两种数组可以同时存在：明细是列表，汇总是映射。汇总从明细算出来，而不是两套各写各的，否则改一行就要记得改两处。算汇总是循环的事，下一章写循环。这里先把容器的形状定下来。

## 小结

PHP 的数组是有序映射。列表用自动下标，价目用品名做键，顺序按插入保留，覆盖已有键不改变位置。缺失的键用 `??` 读取，避免警告。空数组在条件里为假，行数用 `count`，金额用 `array_sum`。`echo` 整个数组只会得到 `Array` 和一条转换警告。明细用追加，合并用键，两套形状不要混在同一个数组里还指望下一班能看懂。
