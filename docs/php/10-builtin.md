前面各章把小票的规则写成了自己的函数和类。有一些动作不必自己从头写：把几段收成一行、把一行拆开、数有几件、把分加起来、问一张表里有没有这个品名。PHP 的内置函数做这些事，而且不需要 `curl`、`mysqli` 或 `gd`。这一章只使用字符串和数组上的函数。不打开文件，不发请求，不画图。巷口纸品的这一遍扫描，输入是已经放在源码里的数组和字符串。

`implode` 把数组收成一个字符串。第一个参数是分隔符，第二个是数组。`implode(" ", ["铅笔", "350"])` 得到 `铅笔 350`。分隔符放在前面，是现在的签名。把数组放在前面、分隔符放在后面，在 PHP 8 里会得到 `TypeError`，脚本停住。旧代码里两种顺序都曾出现，记混时失败很响。响比印出错列要好：你不会把一张参数颠倒的小票交给顾客。调用时先写下分隔符，再写下数组。分隔符可以是逗号、空格或空字符串。空字符串表示直接连接，品名和金额会粘住，那是你选择的分隔符，不是函数偷偷去掉了空格。

`implode` 只接受元素能变成文字的数组。元素是整数时，会转成十进制文字。元素若是数组，转换会失败或发出警告。明细的内层数组要先取出品名，收成一个只含字符串的列表，再 `implode`。不要把嵌套数组直接交给它。返回的是新字符串，原来的数组还在。你可以既保留列表供下一行继续追加，又把当前列表印成一行预览。

`explode` 按分隔符拆开，返回数组。`explode(" ", "铅笔 350", 2)` 的第三个参数限制最多两段。第一段是品名，第二段是余下的全部，即使余下部分里还有空格。不写限制时，每个空格都切开。品名若是「红 铅笔」，不限制会被切成三截，单价找不到家。巷口纸品的品名目前没有空格，限制仍然写上。限制是为了下一次品名变长时规则不用改。限制为 2 的代价是你不能在同一次拆分里同时得到品名、数量和单价三列。三列都要时，先限制成「品名」和「余下」，再对余下拆一次。两次拆，每次的含义都写得清。一次拆成许多段，看起来短，栏位一多就会把最后一栏的空格切碎。

`count` 数元素个数。它不看字符串长度，也不看金额。三行货就是 3，哪怕其中一行的数量是 0。若 0 数量的行根本没有放进数组，`count` 不会把它们算进来。所以「纸上有几行」取决于你追加之前有没有跳过。`count` 回答的是数组里现在有几项，不是店员敲过几次回车。`array_sum` 把数值加起来。价目的值若是单价而不是行金额，`array_sum` 得到的是单价合计，没有乘数量。不要把这个数印成顾客应付的总额。行金额先乘好，放进一个只含整数的列表，再求和。`array_sum` 对空数组返回 0。空单的合计是 0，和「有货但免费」的 0 在数字上相同。页眉若已经用 `count` 印出 0 行，顾客能看出这是空单。只有合计、没有行数时，0 的含义不够。两个函数一起印。

`in_array` 查找一个值是否出现。默认用 `==`。`in_array(0, ["0"])` 会为真，因为宽松比较把整数零和字符串零看成相等。第三个参数 `true` 改成严格比较，相当于用 `===`。`in_array(0, ["0"], true)` 为假。`in_array("铅笔", ["铅笔", "橡皮"], true)` 为真。金额和货号用严格查找。品名是字符串，和整数不混在同一个列表里时，宽松和严格的结果常常一样。一旦列表里既有数又有文本，默认的 `==` 会让 350 命中 `"350"`。命中之后你分不清表里存的是数还是刚读到的文字。第三个参数写上 `true`，查找的合同就和前面各章的 `===` 一致。找不到时返回 `false`。用三元表达式把它印成 `yes` 或 `no`，不要直接 `echo` 布尔值。`echo false` 是空，纸上会像是函数没被调用。

`str_replace`、`trim`、`strlen` 在字符串那一章已经用过。这里把它们接进一行货的整理：先 `trim` 掉店员多打的空白，再替换掉不想印的连字符，再用 `strlen` 看字节。这些函数都不修改原字符串。你要接住返回值。`array_key_exists` 问的是键在不在，和 `in_array` 问值在不在是两件事情。价目表用键保存品名时，用 `array_key_exists("铅笔", $prices)` 或用 `??`。`in_array` 会去翻值，单价 350 可能恰好等于另一件的单价，从而答非所问。问品名，就问键。问「有没有一行是 350 分」，才问值。

`array_map` 可以用一个函数处理每一项并返回新数组。它适合把明细收成行金额的列表，再交给 `array_sum`。循环能做的事，`array_map` 也能做。循环的中间变量更明显，`array_map` 更短。小票的行数很少，两者的运行成本都不是问题。选择取决于你想不想在转换里写一个具名函数。具名函数可以单独测试。匿名函数写在调用旁边，短，也更难给它一个失败时能读懂的名字。这一章用 `foreach` 把行金额收进列表，再用 `array_sum`，名字都在脚本里。不为了短而把规则藏进匿名函数。

下面四块都是完整脚本，只用字符串和数组函数，外加 `echo` 和控制结构。

```php run expect="铅笔 350" title="分隔符写在前面"
<?php
echo implode(" ", ["铅笔", "350"]), "\n";
echo implode(",", ["铅笔", "橡皮"]), "\n";
```

第一行用空格，得到小票的一行。第二行用逗号，得到品名列表。两行的第一个参数都是分隔符。期望锁定带空格的那一行。逗号那一行让你看见分隔符换了，连接的方式就换了，数组本身没有保存分隔符。分隔符是每次收成文字时的决定。

```php run expect="铅笔" title="最多拆成两段"
<?php
$parts = explode(" ", "铅笔 2 350", 2);
echo $parts[0], "\n";
echo $parts[1], "\n";
```

第一段是铅笔。第二段是 `2 350`，中间的空格还在，因为限制是 2，后面不再切。若去掉第三个参数，会得到三段，`$parts[1]` 只是 `2`。两种结果都合法，合法取决于你是否还要把数量和单价分开。这一块故意把单价留在第二段里，让限制的效果可见。下一行若要单价，再对 `$parts[1]` 做一次 `explode`。

```php run expect="1000" title="行数与金额分开回答"
<?php
$cents = [350, 200, 450];
echo count($cents), "\n";
echo array_sum($cents), "\n";
echo count([]) === 0 ? "空单" : "有货", "\n";
```

3 行，合计 1000 分，然后是空单。空数组的 `array_sum` 若也印出来，会是 0。这里印「空单」，避免和 1000 旁边的 0 混淆。`count([]) === 0` 用严格比较，虽然 `count` 返回的本来就是整数。习惯保持严格，和查找那一块一致。

```php run expect="no" title="严格查找分得开两种零"
<?php
echo in_array(0, ["0"], true) ? "yes" : "no", "\n";
echo in_array("铅笔", ["铅笔", "橡皮"], true) ? "yes" : "no", "\n";
$prices = ["铅笔" => 350];
echo array_key_exists("铅笔", $prices) ? "yes" : "no", "\n";
```

第一行是 `no`，整数 0 不在严格意义上等于字符串 `"0"`。第二行是 `yes`，品名在列表里。第三行是 `yes`，品名作为键存在。三行都印 yes 或 no。若把第一行的 `true` 去掉，结果会变成 `yes`，和这一章要记住的严格合同相反。第三个参数不要省。

`str_replace` 可以清理一行里的制表符。店员偶尔会用制表符当间隔，`explode(" ", ...)` 就拆不开。先把制表符换成空格，再拆。`str_replace("\t", " ", $line)` 返回新行。连续两个空格会让 `explode` 产生空段。限制段数可以减轻伤害，空段仍可能出现在末尾。拆完之后若某一段是空字符串，按失败处理，不要当成品名。清理和拆分是两步。一步做两件事时，你很难看出空段来自制表符还是来自店员多按的空格。

这些函数的共同特点是不记住上一张票。每次调用只看你传入的值，返回一个新值。合计要累加，就由你的变量记住，函数不会替你留一张全局的小票。这和「每次运行都是新进程」贴在一起：即使在同一进程里连续调用，`array_sum` 也不会把上一次的参数加进来。状态在数组里，不在函数里。下一章的记账会把状态放在一个局部数组里，用这些函数去改写和读取它。命令文本也放在数组里，不从标准输入读。

使用内置函数的取舍是：你少写循环，也接受函数的既有合同。`implode` 的参数顺序、`in_array` 的默认宽松、`explode` 的不限制，都是合同的一部分。合同和你的直觉不一致时，以合同为准，在调用处写明分隔符、限制和严格比较。不要再包一层同名函数去「修正」它们，除非整个店的代码都通过那一层。一层包装能统一严格查找，也会让人不知道真正调用的是哪一个。这一章的示例直接调用，把合同摊在纸面上。

查找还可以问「第一次出现在哪」。`array_search` 返回键，找不到时返回 `false`。键 `0` 和找不到都很容易在条件里变成假，所以要用 `!== false` 来判断找到了没有，并且打开严格比较。小票若只关心在不在，`in_array` 的布尔更直接，没有键 `0` 和 `false` 的纠缠。若关心是第几行，再用 `array_search`，并且记住列表的第一行键是 `0`，`0` 表示第一行，不表示失败。失败只由 `false` 表示。这两种返回挤在同一个函数里，是这个函数难用的地方。能用 `in_array` 回答的问题，就不要换成 `array_search`。

字符串函数里，`substr` 按字节切。`substr("铅笔", 0, 3)` 才可能切出第一个汉字，切两个字节就会得到坏的半个字。小票不靠 `substr` 来缩短品名。品名要么整段留下，要么在进入数组之前就用完整的字来取舍。取舍可以用 `mb_strlen` 看字数是否超过纸宽，超过就换一行打印，而不是切掉后半个字。换行是版式，切字节是损坏。内置函数给了你刀，不表示每一刀都该砍在品名上。

`implode` 之前若数组里混进了 `null`，它会变成空串，分隔符仍在，纸上会出现连续的分隔符，像「铅笔,,橡皮」。连续分隔符让人以为有一件没有名字的货。组装之前先去掉空名字，或在发现空名字时整行失败。内置函数不会替你理解空名字是不是一件货。它只负责把剩下的值用分隔符接上。理解是你的循环的事。函数是接上的事。这个分工和前面把「算钱」与「打印」分开是同一类。

## 小结

`implode` 的第一个参数是分隔符，第二个是数组。`explode` 用第三个参数限制段数，避免把品名里的空格切碎。`count` 回答有几项，`array_sum` 回答数值之和，空数组的和是 0，要用行数把空单分开。`in_array` 的第三个参数 `true` 才是严格查找。问品名在不在价目的键上，用 `array_key_exists` 或 `??`。这些函数每次只处理传入的值，不替你保存上一张小票。
