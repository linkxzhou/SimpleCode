上一章的打印机已经能把店名和合计送出去。真正的小票很少只有一个数。一行里要同时有品名和金额，两行之间要能盖章。`echo` 负责把参数写成文字，它不负责替你设计版式。这一章把同一张巷口纸品的小票拆开看：参数怎样连在一起，换行从哪里来，注释为什么不会印到顾客那一张上。

`echo` 是语言结构，不是普通函数。它可以接受多个参数，参数之间用逗号隔开。逗号只表示「还有下一个参数」，不表示「在纸上留一个空格」。`echo "铅笔", "350"` 得到的是 `铅笔350`。品名和金额粘在一起，是因为两段文字本来就没有间隔，引擎没有义务插入间隔。有的语言的打印函数默认用空格连接多个参数，读起来像一句人话，代价是你想紧贴的时候要再去关那个默认。PHP 把这个默认拿掉了。你得到对每个字节的控制，也接下「忘了空格」的责任。

空格是数据，写在字符串里。`echo "铅笔", " ", "350", "\n"` 的第三个参数是一个空格字符，纸上才会变成「铅笔 350」。把空格写进品名字符串的末尾，效果相同：`"铅笔 "` 已经带着间隔。两种写法差在你以后改版式的时候。单独一个空格参数，眼睛容易把它看成多余的逗号；写进前一段的末尾，间隔跟着品名走，换品名时可能把空格一起换掉。小票这一章选用单独的空格参数，是为了让「间隔是写出来的」这件事在源码里站得住。店里的正式格式若固定是「品名、两个空格、金额」，把那两个空格放进一个常量式的字符串更清楚。眼下只有一个空格，单独写就够了。

换行同样不会自动出现。`echo` 写完参数就停，不追加行尾。字符串里的 `\n` 才是换行。两句 `echo` 若都没有 `\n`，第二句会接在第一句后面，顾客看见的仍是一行。两句都带 `\n`，才是两行。一句 `echo` 里写两个带换行的字符串，也可以得到两行，因为换行在字符里，不在语句的个数里。选择多句还是一句，取决于下一班店员要不要单独改某一行。语句多，改一行时不用在一长串参数里找位置。语句少，源码更紧，漏一个 `\n` 时两行会粘住，粘住的样子和逗号没写空格很像，都是「纸上的空白少了」。

数字会先变成文字再送出。`echo 350` 纸上是三个字符 `350`，不是内存里的整数格式。`echo 350, 200` 会得到 `350200`，因为两个数字的文字被直接接上，中间没有空格，也没有加号。加号必须出现在表达式里。`350 + 200` 先得到整数 `550`，再被打印。逗号出现在 `echo` 的参数之间时，它不是加法，也不是连接运算。这个区分会在字符串那一章再遇到一次：连接用点号，参数列表用逗号。点号产生一个新字符串，你可以把它存进变量再决定印不印。逗号只在输出的那一刻把几段拼到纸上，拼完没有一个字符串留给下一行。小票若只是立刻印出来，逗号够用。小票若要先算出一行、再决定放进合计还是丢掉，就得先得到那一行的字符串。那是后面的事，这里先把纸面印对。

注释从 `//` 开始，直到这一行结束。`/*` 和 `*/` 可以包住一段，包括换行。注释不会进入输出，也不会参与计算。它服务的是下一个打开这份源码的人。在纸品店，这个人常常是下一班的店员，也可能是两小时之后的你。注释不服务引擎，所以它不能代替 `echo`。你把唯一一句 `echo` 注释掉，进程会安静地成功退出，终端是空的。空输出的退出码仍是 0。核对会说期望的字没出现。你若先去找异常，会一无所获。这是注释最容易踩到的情况，它就发生在你以为自己只是暂时关掉一行的时候。

注释还有一种更隐蔽的用法：用它保存已经被放弃的旧价格，让源码里同时存在两套金额。下一班分不清哪一套才是现在的价。与其留着被注释的 `echo`，不如删掉。在这门课的单块源码里没有版本历史，留着的注释就是唯一的旧句子，它会冒充当前的意图。连续多行的说明，就连续写多行 `//`，或者用一对 `/* */`。块注释要注意闭合。少写一个 `*/`，后面的代码会被吞进注释，纸上又变成空白，而且仍然可能成功退出。写块注释时，先写下结尾，再填中间的话。

下面这一块故意不写空格，让你看见粘连。期望是 `铅笔350`。它不好看，它却是逗号的真实行为。下一班若觉得纸面应该有空格，要改的是字符串，不是去找一个「打开空格」的开关。没有那个开关。

```php run expect="铅笔350" title="逗号不插入空格"
<?php
echo "铅笔", "350", "\n";
```

输出是铅笔和 350 紧贴，然后换行。引号和逗号都留在源码里。你若在期望里写上引号，核对会失败，因为纸上没有那些引号。这一块的难看是教材，不是笔误。正式的小票不该这样交给顾客。紧接着的一块把空格加回去，两块对照着看，比记一句口诀更牢。

```php run expect="铅笔 350" title="空格写在字符串里"
<?php
echo "铅笔", " ", "350", "\n";
```

三个参数的文字依次是品名、空格、金额。纸上是「铅笔 350」。把中间那个 `" "` 删掉，就退回上一块的样子。把空格写成两个，纸上就空得更宽。宽度是你放进去的字符个数。`echo` 不会把全角空格和半角空格换成同一种。小票若混用两种空格，眼睛对齐了，按字节比较却对不齐。这一章的间隔用半角空格，和金额的阿拉伯数字同一套字符宽度习惯。中文品名本身占的宽度是另一件事，字符串那一章会谈到字节。

注释和两行输出可以放在同一份脚本里。下面这一块先印店名，再用注释说明为什么金额单独一行，然后印 550。注释那一行删掉之后，输出不变。把印金额的那一句前面加上 `//`，纸上就只剩店名。这个对照用来记住注释的边界。

```php run expect="550" title="注释不进入小票"
<?php
echo "巷口纸品\n";
// 金额单独一行，方便盖章
echo 350 + 200, "\n";
```

输出两行：先是巷口纸品，然后是 550。期望只要求出现 550。店名多出来也不妨碍核对。顺序若反了，子串期望仍然能对上。这是子串的局限。读示例时要自己看完整输出，确认店名在金额上面。注释写在两句之间，它不占纸上的一行。有人以为注释会变成一个空行，于是在核对时去数空白，数不到就开始怀疑 `echo` 丢了输出。源码里的说明和纸上的空白是两套东西。空白要出现在小票上，就必须是某次 `echo` 的内容，或者是字符串里的换行。

`echo` 没有有用的返回值，你不能把 `echo` 的结果再交给另一个 `echo`，也不能用它的结果做条件。打印是副作用，发生在调用的当时。旁边的 `print` 只能接受一个参数，并返回整数 `1`。返回 `1` 几乎不携带「印成功了吗」的信息，纸上写失败时你靠的是错误，不是这个 `1`。多个片段要一次送出时，`echo` 的参数列表更直接。课程的小票统一用 `echo`，避免同一张纸上混两种打印。`print` 的返回值若被拿去做条件，你会在已经印出文字之后又走进一个分支，纸上的顺序会让下一班困惑。不把打印的返回值接进逻辑，逻辑就只取决于金额和数量。

还有一种安静要和「忘了 echo」分开。`echo ""` 会送出空字符串，纸上没有可见字符，若你同时写了 `\n`，就有一个空行。进程是成功的。把 `echo` 整句注释掉，则连空行都没有。看的时候先看有没有你写的那一行字，再数空行。空行是写出来的换行，不是语句之间的空白行。源码里两句 `echo` 之间空一行，只影响人的阅读，不影响顾客看见的行数。

把参数连在一起还有一个上限问题：一行小票若分成十个碎片，每个标点都单独做参数，改一个品名要数很多个逗号。碎片太多时，先在脑子里把整行读出来，再决定哪些片段确实要分开。这一章分开品名、空格和金额，是因为三者的来源不同：品名是字，空格是版式，金额是数。来源相同的字就放在同一个字符串里，例如店名「巷口纸品」不必拆成四个参数。拆开不会改变输出，只会让逗号的个数变成噪音。

数字和文本混在一次 `echo` 里是允许的。引擎把整数转成十进制文字，不带前导零，不带千分位。`350` 就是 `350`。若你希望金额显示成 `3.50` 元，那是格式化，不是 `echo` 的默认。格式化会把整数变成带点的字符串，一旦变成字符串，再拿去和别的金额相加就要小心类型。这一章保持印出「分」的整数文字。元和分的换算留到类型那一章，那里会看到除法怎样把整数变成浮点。在还没有那一层之前，小票上的 350 就是三百五十分，不是三点五零元。

最后把三块的纸面对一下。第一块证明逗号不插入空格。第二块证明空格可以成为参数。第三块证明注释不占行，换行只来自 `\n`，加法发生在打印之前。三块的店都是巷口纸品，三块的进程互不相通。你在编辑器里改某一块时，只改那一块。点代码块上的 Run 会用文档里的源码覆盖你的草稿。想保留改过的版本，先复制到别处。

## 小结

`echo` 把每个参数的文字依次写到标准输出，逗号不插入空格，也不会自动换行。空格和 `\n` 要写进字符串。整数在送出前被转成十进制文字，加法要写在表达式里，写在参数之间的逗号不是加号。注释用 `//` 或 `/* */`，不进入小票。把唯一的 `echo` 注释掉，进程会成功，纸上却是空的。

## 练习

用一次 `echo` 打出「橡皮 200」，品名和金额之间有一个空格，末尾换行。

```php run expect="橡皮 200" title="参考答案"
<?php

```

分两行打印。第一行是店名「巷口纸品」，第二行是 `800`。800 由 350 与 450 相加得到。注释可以写，但不要让注释代替任何一行输出。
