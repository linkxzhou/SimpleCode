价目和明细已经能放进数组。打印机还要决定哪些行真正印出来，以及合计怎样从许多行里长出来。控制流就是这些决定。`if` 看条件，`foreach` 顺着货行走，`for` 和 `while` 按次数重复。巷口纸品的规则很具体：数量为假的行不占纸面，有数量的行把「单价乘数量」加进合计，循环必须在货看完时停住。

`if`、`elseif`、`else` 组成一条链。条件为真时走进那一支，其余支跳过。条件里的假，上一章的类型已经列过：`0`、`0.0`、`""`、`"0"`、`[]`、`null` 和 `false`。数量 `"0"` 会让 `if ($qty)` 走假分支，这一行货不印。若你的规则就是「零不占行」，这是对的。若这一行的 `$qty` 可能还是文本货号，这条规则会伤及货号。小票的循环里，变量名用 `$qty` 表示已经确认过的数量。确认的办法是严格比较，或先 `intval` 再比较整数。`elseif` 用来加第二道门槛，例如数量大于 10 时印「成盒」。门槛的顺序要先写更具体的那一支。先写 `> 0` 再写 `> 10`，大于 10 的数量会先被第一支接走，第二支永远不会走到。更具体的条件放在前面，是链的结构，不是口味。

`foreach` 顺着数组的插入顺序走。明细是列表时，`foreach ($lines as $line)` 先看见最早追加的那一行。价目是映射时，`foreach ($prices as $name => $cents)` 同时给出品名和分。循环内部可以再写 `if`。数量为 0 时用 `continue` 进入下一件，不把 0 加进合计。`continue` 只跳过这一轮的余下语句，不结束整个循环。`break` 才离开循环。小票一般不要在第一件零数量时 `break`，后面的橡皮还要算。`break` 适合已经找到要退货的那一行、不必再往下看的时候。选错其中一个，纸上会少掉后半张，或把零数量也加进去。

`for` 适合你确实握着下标的时候。`for ($i = 0; $i < count($lines); $i++)` 会走过连续下标。若数组中间被 `unset` 出了空洞，按下标去读会碰到缺失。明细不用 `unset` 来「跳过一行」，而用条件跳过，下标就保持连续。`count` 放在条件里，每一轮都会再数一次。货行不多时这点成本可以忽略。若循环里还在追加元素，`count` 会跟着变，循环可能停不下来。小票的合计循环不在遍历时追加。要追加，先把新行放进另一个数组，遍历结束再合并。这样停止条件在进入循环之前就已经是一个有限的长度。

`while` 的条件在每一轮开始时检查。你要在循环体内把条件推向结束。`$left = 3` 然后 `while ($left > 0)`，体内必须减少 `$left`。忘了减少，抽屉里的运行会一直转，直到被掐掉，纸上可能已经印出几千行。这种失败没有语法错误。写 `while` 时，先写下让条件变假的那一行，再填身体里其余的计算。小票的主循环更适合 `foreach`，因为件数由数组决定，不由一个单独的计数器决定。`while` 留在「还要再切一盒，直到剩下的支数不够一盒」这种真正的剩余量上。盒数其实用 `intdiv` 一次就能得到，不必循环。循环版只在你想看见每一盒被减去时才值得。能一次算完的，不要写成可能忘记递减的 `while`。

只在循环外面打印合计，纸上就是一个数，期望好写。在循环里面每一次都 `echo` 品名，期望就得包含每一行，顺序也变成测试的一部分。教学时两种都有用。看顺序时，循环内打印。看金额对不对时，循环外打印合计。这一章的主例子把明细的贡献累加到 `$total`，最后只印 `$total`。另一块在循环里计数，印出「非空行有几条」。不要在循环里打印调试用的「到了这里」。那些字会粘进小票，子串期望也许仍能对上，顾客却会看见店员的草稿。

`match` 是另一种分支。它按 `===` 选择一支，并得到一个值。`$qty` 为字符串 `"0"` 时，`match` 的 `0` 那一支不会命中，因为类型不同。`if ($qty)` 却会把 `"0"` 当成假。两种分支对「零」的态度不一致。小票若已经把数量收成整数，`match (0 => ...)` 很清楚。数量若还是文本，先转换再 `match`，或者在 `match` 里写 `"0"` 那一支。`match` 没有命中且没有 `default` 时会抛出 `UnhandledMatchError`。写上 `default`，未知数量才有一个固定的去处。`if` 没有 `else` 时，未知情况是静默地什么都不做。静默有时等于漏印。合计循环里，未知情况应当 `continue` 或记一笔失败，不要什么都不做还让店员以为每一行都算过了。

下面的脚本仍是一张巷口纸品的小票。数量里夹着 0 和空字符串，用来把假值走一遍。

```php run expect="1150" title="跳过零数量再合计"
<?php
$lines = [
  ["name" => "铅笔", "qty" => 2, "cents" => 350],
  ["name" => "橡皮", "qty" => 0, "cents" => 200],
  ["name" => "直尺", "qty" => 1, "cents" => 450],
];
$total = 0;
foreach ($lines as $line) {
  if ($line["qty"] === 0) {
    continue;
  }
  $total += $line["qty"] * $line["cents"];
}
echo $total, "\n";
```

铅笔两支是 700，橡皮被跳过，直尺 450，合计 1150。这里用 `=== 0` 而不是 `if (!$line["qty"])`，是因为数量已经是整数，规则写成「整数零就跳过」更精确。若某一行的数量是字符串 `"0"`，`=== 0` 不会跳过，乘法会先把字符串转成数，`"0" * 200` 得到 0，合计不变，可是这一行并没有按你以为的比较被认出来。数据进入循环之前，类型要先定成整数。这一块的三行都是整数，所以结果干净。

```php run expect="2" title="空品名不计数"
<?php
$n = 0;
foreach (["铅笔", "", "直尺"] as $name) {
  if ($name === "") {
    continue;
  }
  $n += 1;
}
echo $n, "\n";
```

空字符串用 `=== ""` 判断。若写成 `if ($name)`，字符串 `"0"` 也会被跳过。品名一般不是 `"0"`，可是规则一旦从「空串」放宽成「凡是假都跳过」，以后货号走进同一个循环就会少计。计数器从 0 开始，每见一个非空品名加一。循环外打印。`2` 是铅笔和直尺。

```php run expect="3" title="剩余支数每次减一盒"
<?php
$left = 20;
$boxes = 0;
while ($left >= 6) {
  $left -= 6;
  $boxes += 1;
}
echo $boxes, "\n";
echo $left, "\n";
```

二十支，每盒六支，循环得到 3 盒，剩下 2 支。这和 `intdiv(20, 6)` 以及 `20 % 6` 是同一笔账。循环版把「减去」写在身体里，忘记 `$left -= 6` 就会停不住。一次除法没有这个风险。店里算盒数时用 `intdiv`。这一块留下循环，是为了让 `while` 的停止条件被看见：`$left >= 6` 在剩下 2 时为假，循环结束。两个 `echo` 分别是盒数和零头。期望锁定盒数。你要自己确认零头是 2，而不是 0。若条件写成 `$left > 0` 又每次减 6，最后一轮会把剩余减成负数。门槛用「还够不够一盒」，不用「是不是还有剩余」。

```php run expect="跳过" title="match 不把字符零当成整数零"
<?php
$qty = "0";
echo $qty ? "印出" : "假分支", "\n";
echo match ($qty) {
  0 => "整数零",
  "0" => "跳过",
  default => "其他",
}, "\n";
```

第一行是假分支，布尔转换把 `"0"` 当成假。第二行是跳过，`match` 命中的是字符串那一支。两行放在一起，是为了防止把 `if` 的习惯带进 `match`。`match` 的分支用逗号隔开，最后可以留一个逗号。它产生一个值，所以可以放进 `echo`。不要在 `match` 的分支里既打印又返回，否则纸上的字会重复。分支只产生词，打印留在外面。

`for` 也可以用来生成行号。从 1 数到行数，显示给顾客的行号就不必再加一。数组下标仍是 `$i - 1`。这个减一是显示和存储的差，写错时会读到前一行，或在最后一轮读到缺失键。能用 `foreach` 就不必引入这个减一。行号若必须印，在 `foreach` 里另放一个 `$no`，从 1 开始，每轮加一。计数器和数组下标分开，各自的起点就清楚了。

花括号标出分支和循环的身体。PHP 允许身体只有一句时不写花括号。小票不使用这种省略。下一班加一行「印品名」时，若花括号不在，新行会落在循环外面，变成只执行一次，或者紧跟 `if` 却不受条件约束。多写的花括号不改变金额，只固定结构。缩进用四个空格，让花括号里的层次眼睛能数。缩进本身不构成结构，花括号才构成。只缩进、不写花括号，引擎不认为那是身体。这和靠缩进分块的语言相反。从那些语言把小票抄过来时，要补上花括号，不能只保留空格。

布尔运算用 `&&` 和 `||`。数量大于 0 并且单价大于 0 才累加，写成 `$qty > 0 && $cents > 0`。两个都要成立。`||` 是有一个成立即可。它们的优先级容易把赋值卷进来，条件整体用括号括上，放进 `if`。不要用 `&` 和 `|` 来做逻辑，那是按位运算，对整数的每一位动手，小票的「并且」不是按位。`and`、`or` 这些单词形式的优先级更低，和赋值写在一起时会让结果出乎意料。课程只用符号形式，并且把条件放在括号里。

把控制流收成打印机的一遍扫描。进入循环前，合计是 0，这个 0 是整数起点，不是「没有这张单」。循环里用严格比较跳过数量为 0 的行，用乘法把单价和数量合成这一行的分，加到合计上。循环后只印合计。`while` 若出现，身体里一定改写条件。`match` 按严格相等选择词语。下一章把「一行多少分」和「要不要跳过」收进函数，调用处就不必每次重写这几行。

循环里的合计还有一个起点问题要单独说。`$total = 0` 写在循环前面，这个 0 会参加加法，但它不是一行货。若你在循环内部才把 `$total` 设为 0，每一行都会把前一行的成果清掉，最后只剩下最后一件。这种错误的纸面仍是一个整数，期望若只写了「有一个数」就会放过它。把起点放在循环外，是结构，不是排版。同样，`continue` 之前不要先把这一行加进去再反悔。先判断再加，纸上的合计和你心里的规则一致。先加再 `continue`，`continue` 就只跳过了打印，没有跳过金额。跳过的范围是它后面的语句，不是这一轮已经做过的事。

多层循环在小票里偶尔出现：外层是每一张票，内层是票里的每一行。内层的 `break` 只离开内层，外层还会继续下一张票。若你以为 `break` 会结束今天所有的票，后面的顾客会被漏掉。需要离开两层时，PHP 允许 `break 2`。数字写错会离开过多或过少。小票的示例保持一层，就是为了不使用这个数字。一张票一个循环，打完再打下一张，用函数把一张票的扫描包起来。函数返回时，循环自然结束，不必数层次。这个包法下一章会写成函数，这里先在控制流里把层次压到一层。

条件里不要写赋值。`if ($qty = 0)` 会把数量改成 0，再把这个 0 当成条件，条件为假，分支不走，数量却已经被清掉。纸上的合计少了这一行，变量也毁了。比较用 `===`，赋值留在单独的语句里。两个符号的差别只有一个等号，读的时候值得放慢。小票的数量来之不易，不应在判断时被改写。

## 小结

`if` 把 `0`、`""`、`"0"`、空数组和 `null` 当假。更具体的 `elseif` 要写在更宽的条件前面。`foreach` 按插入顺序遍历，`continue` 跳过这一行，`break` 离开整个循环。合计放在循环外打印。`while` 必须在体内把条件推向结束，能用 `intdiv` 一次算完的盒数不必冒险写循环。`match` 使用严格比较，字符串 `"0"` 不会落入整数 `0` 那一支。花括号写出分支和循环的身体。

## 练习

把 1 到 4 加起来并打印。用 `for`，在循环外打印总和。

```php run expect="10" title="参考答案"
$total = 0;
for ($n = 1; $n <= 4; $n++) {
  $total += $n;
}
echo $total, "\n";
```
