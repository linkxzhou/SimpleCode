循环里的乘法已经能算出一行货的分。若每张小票都把 `$qty * $cents` 再写一遍，改规则时要改许多处。函数把规则收成一个名字。巷口纸品至少需要两个：给定数量和单价，返回这一行的分；给定品名和这一行的分，返回可以印的文字。打印留在调用处。函数自己不 `echo`，这样同一笔账既能放进合计，也能放进预览，不会在你只想要数字时把字提前印到纸上。

`function` 定义函数。参数按位置传入。`line_cents(2, 350)` 里，`2` 是数量，`350` 是单价。调换顺序不会有类型来拦你，若两个参数都是整数，你会得到 `350` 支、每支 `2` 分这种安静的错账。名字和调用写在一起时，把参数的含义放进形参名：`$qty`、`$cents`。调用处暂时还没有命名参数的必要。PHP 8 可以写 `line_cents(qty: 2, cents: 350)` 这种具名调用，它能防止传反。课程的例子仍用位置，因为参数只有两个，而且每一块都短。一旦参数超过三个，具名调用更不容易把折扣和数量对调。具名调用的代价是调用行更长。两个整数的行金额，位置加上清楚的形参名就够了。

`return` 把值交回调用处，并且立刻结束函数。交回的值不会自动出现在终端。调用者要 `echo line_cents(2, 350)`，纸上才有 `700`。忘记 `echo`，进程成功，纸面空白，和把 `echo` 注释掉是同一类安静。忘记 `return`，函数交回 `null`，`echo` 这个 `null` 得到空，纸上像是印了一行什么都没有的金额。两种空白看起来接近。看源码时先找 `return`，再找调用处的 `echo`。一个函数只做一件事时，`return` 通常靠近末尾，中间用条件提前返回也可以。数量为 0 时返回 0，调用者把 0 加进合计，合计不变。返回 0 和什么都不返回不同。什么都不返回是 `null`。`null` 加到整数上会把合计弄出警告。金额函数永远返回整数，包括「这一行不收钱」时的整数 0。

默认参数写在参数列表的右边。`function line_cents($qty, $cents = 350)` 表示省略第二个参数时按 350 分计，也就是按铅笔的单价。默认值在调用没写那个参数时使用。它不是「如果传入 0 就改用 350」。传入 0，用的是 0。这个区别和 `??` 类似：默认填的是省略，不是零。把铅笔单价做成默认，调用短了一点，也把函数绑在了某一种商品上。橡皮调用若忘了写单价，会按铅笔计价，错得安静。小票的单价默认因此要很克制。更合理的默认是数量：`function line_cents($cents, $qty = 1)`，省略数量时按一支算。一支是常见情况，忘了写数量时按一支，比按另一种商品的价格更可解释。默认参数不能放在没有默认的参数左边。把 `$qty = 1` 放在 `$cents` 前面，定义时就会失败。常用的、可以省略的，放在右边。

函数里给参数赋值，不会改调用者的变量。`$qty = $qty * 2` 只改函数内部的那一份。外面的数量还是原来的数。这是按值传递的效果。数组在 PHP 里也是按值交给函数的，引擎用写时复制把成本摊到真正修改的那一次。你在函数里 `$lines[] = ...`，调用者的数组不变，除非你 `return` 那个数组并由调用者接住。引用参数写成 `&$lines`，函数里的修改会直接作用于调用者。引用少一次返回，也让人看不出这一行会不会改你的明细。两个人读同一份打印机，一个以为函数只是查询，另一个通过引用把行删了。课程的金额函数不用引用。要更新明细，就返回新的数组，调用处写 `$lines = add_line($lines, ...)`。赋值显眼，数据流是从右到左读得懂的。

不要在算钱的函数里 `echo`，又在调用处 `echo` 返回值。纸上会打出两遍。调试时暂时在函数里打印，忘了删，正式小票就重复。把副作用留在脚本的最外层，函数保持「进数、出数」。最外层就是没有包在函数里的那些语句，它们在加载时执行。这个文件没有单独的 `main`。你定义的函数在被调用之前不会执行身体。只定义、不调用，纸上什么都没有，退出码仍是 0。每一块示例因此都在定义之后用具体的数调用一次。具体的数是铅笔的 2 和 350，不是空着的变量。例子能被单独运行，就靠这些写死的实参。

函数名用小写字母和下划线，和变量一样可以从左读到右：`line_cents`、`format_line`。PHP 的函数名不区分大小写，`Line_Cents` 会调用同一个函数。不区分看起来宽容，两套拼写会让下一班以为有两个函数。课程只用一种拼写。类的方法名同样保持一种拼写，下一章再说方法。函数要先定义再调用，同一份脚本里把定义放在调用上面。条件里面定义函数是允许的，可是第二次执行到那个定义会报重复声明。小票的函数放在顶层，只声明一次。

默认值若写成可变的数组，并在函数里修改那个数组，旧版本里多次调用会共享同一份。PHP 8 对可变默认值的处理比早期严格，仍不要把会增长的明细当成默认参数。默认用整数或字符串。需要新的空明细时，在函数体内写 `$lines = []`，或由调用者传入。每次调用都从新的空数组开始，上一张小票的铅笔不会留在下一张里。进程结束本来就会清掉内存。同一进程里连续打两张票时，共享的默认数组仍会串单。不共享，是为了这一种连续打印。

下面三块各定义自己的函数。名字在别的块里不存在，所以每块都把要用的函数写全。

```php run expect="700" title="一行的分交回来再打印"
<?php
function line_cents($cents, $qty = 1) {
  return $cents * $qty;
}
echo line_cents(350, 2), "\n";
echo line_cents(200), "\n";
```

第一行是铅笔两支的 700。第二行省略数量，按默认的一支，橡皮是 200。两个结果都是返回值，`echo` 在调用处。函数体内没有打印。你若把 `return` 改成 `echo`，函数会在调用时直接印出数字，再把 `null` 交给外面的 `echo`，纸上的版式会多出空行或粘连。保持 `return`。

```php run expect="铅笔 700" title="格式化不负责合计"
<?php
function format_line($name, $cents) {
  return $name . " " . $cents;
}
function line_cents($cents, $qty = 1) {
  return $cents * $qty;
}
$row = line_cents(350, 2);
echo format_line("铅笔", $row), "\n";
```

`format_line` 只拼接，不乘法。乘法已经在 `line_cents` 里做完。两个函数的边界按「算」和「写成一行」切开。切开之后，合计可以只调用 `line_cents`，预览才调用 `format_line`。若一个函数又乘又打印又拼接，你无法把金额加进合计而不弄脏纸面。返回的字符串不含换行，换行由 `echo` 的参数加上。这样返回值还可以放进数组。

```php run expect="1150" title="函数累加三行明细"
<?php
function line_cents($cents, $qty = 1) {
  if ($qty === 0) {
    return 0;
  }
  return $cents * $qty;
}
$lines = [
  ["cents" => 350, "qty" => 2],
  ["cents" => 200, "qty" => 0],
  ["cents" => 450, "qty" => 1],
];
$total = 0;
foreach ($lines as $line) {
  $total += line_cents($line["cents"], $line["qty"]);
}
echo $total, "\n";
```

零数量返回 0，不参加有意义的金额，加进去也不改变合计。1150 来自 700 与 450。橡皮那一行的单价没有被乘进去。把判断放在函数里之后，循环身体变短，规则集中在一个地方。若某一张票想把零数量印成「赠送」而不是跳过，改的是函数的返回，或另写一个函数，而不是在每个循环里找 `if`。另写函数比加一个布尔参数更清楚。布尔参数 ` $as_gift` 会让同一个名字在两种规则下摇摆，调用处必须去看定义才知道 `true` 是哪一种。两个名字，`line_cents` 和将来的 `gift_line`，读调用就能知道规则。

参数可以是数组。`function row_cents($row)` 从 `$row["qty"]` 和 `$row["cents"]` 取值。调用处少传两个位置，错键的风险换到了数组内部。键名写错时，缺失键的警告会在函数内部冒出来。函数开头用 `??` 读键，缺失时返回 0 或直接返回一个表示不行的值。返回 0 又和「免费」相混。这一章的函数仍接收已经拆开的整数，键的检查留在组数组的那一层。层次分开，函数的参数列表就是它的合同：两个整数进，一个整数出。

匿名函数可以赋给变量，小票暂时不需要。具名函数能够在文件后部被找到，也能够被下一张票的代码直接调用。匿名函数适合交给数组函数做短转换，内置函数那一章若用到 `array_map` 再谈。现在写出名字，让合计的来源在调用栈上可读。

函数这一章把打印机的规则从脚本正文里抬起来。抬起来的好处是三块示例可以共用同一种算法，尽管进程不共享定义，算法在文字上是同一份。代价是你必须记得调用，并且记得打印返回值。下一章把品名、明细和这些函数收进一个对象，数据跟着这一张票走，而不是散在许多参数里。

函数的返回值还可以是布尔，用来回答「这一行能不能入账」。回答和金额分开，调用者先问能不能，再取金额。若一个函数既返回 `false` 又返回整数 0，调用者用 `if ($n)` 会把合法的 0 分和失败混成同一种假。金额函数不要用 `false` 表示失败。失败用上一章会讲的异常，或用一个永远是整数的返回再加上一个单独的检查函数。检查函数返回 `true` 或 `false`，打印时仍把它们换成「可以」或「不行」，避免 `echo false` 的空白。这样纸上的词和返回值的类型各自稳定。

参数个数也可以变。PHP 允许你不声明每一个参数，在函数里用 `func_get_args` 去取。小票不用这个办法。一行货的数量和单价是固定的两栏，多出来的参数多半是调用写错了。固定参数让写错在阅读时就能看见：调用只有一个数，定义却有两个，眼睛对得上。可变参数适合把许多行一次传进去求和。那件事用数组更清楚，数组有 `count`，参数列表的个数要额外去问。数组是这一张票的数据，参数是这一次调用的数据。不要把整张票拆成十个位置参数。

递归也能累加明细：函数取出第一行，加上对剩余行的调用。行数很少时递归能工作。它把「结束条件」藏在空数组上，忘了写结束就会一直调用到栈溢出。循环把结束写在 `foreach` 的边界上，空数组就是不进入身体。小票的合计用循环，不用递归。递归留给结构本身是树的数据。一张票是列表，不是树。

## 小结

函数用 `return` 交回一行的分或一行文字，`echo` 留在调用处。省略的参数才使用默认值，传入的 0 不会被默认替换。默认参数放在参数列表的右边，用整数这种不会在多次调用间共享状态的值。函数内部对参数的赋值不改变调用者的变量。要更新数组，就返回新数组并由调用者接住。算钱的函数不要自己打印。

## 练习

写一个函数，返回一个数的平方。打印 6 的平方。

::: answer 参考答案：平方
```php run expect="36" title="参考答案"
<?php
function sq($n) {
  return $n * $n;
}
echo sq(6), "\n";
```
:::

写一个函数，返回两个整数里较大的一个。打印 `larger(3, 9)` 的结果。

::: answer 参考答案：较大的金额
```php run expect="9" title="参考答案"
<?php
function larger($a, $b) {
  return $a > $b ? $a : $b;
}
echo larger(3, 9), "\n";
```
