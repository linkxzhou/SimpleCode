前面十一章把打印机的零件做完了：输出、类型、字符串、数组、分支、函数、对象、异常、一行文本的整理，以及现成的字符串和数组函数。这一章把它们收成一次运行里的记账。店员的命令已经放在一个数组里，每一项是一行文字，例如「记 铅笔 350」。脚本依次解释这些行，把金额加到按品名分开的账上，最后印出铅笔的合计和全单的合计。不读标准输入，不读超全局变量，不写文件。进程结束，账就消失。再运行一次，要从数组里的那些行重新累加。

账是一个数组，键是品名，值是已经累加的分。`记 铅笔 350` 执行两次，铅笔的值是 700，不是两行明细。这是按品名合并的形状，适合回答「这种货一共记了多少」。顾客那张按购买顺序的明细仍可以用列表另做。记账这一章选择合并，因为命令的目的就是累计。合并用 `??`：`$book[$name] = ($book[$name] ?? 0) + $cents`。键还不存在时从 0 开始加。键存在且值为 0 时，`??` 不会把 0 换成 0 再误解，它留下 0，加上新的金额。这里的 0 只在键缺失时出现，出现之后立刻加上这一笔，不会单独停留成「免费的铅笔」。

命令行用 `explode(" ", $line, 3)` 拆成最多三段：动词、品名、金额文字。限制为 3，是为了金额留在最后一段。若品名将来含有空格，这种拆法会把空格分给品名和金额之间，三栏就会错位。巷口纸品的品名约定不含空格。约定写在拆分旁边，比假装 `explode` 能懂中文名字更诚实。动词只认「记」。其他动词印「失败」，继续看下一行，不让这一行的异常结束整次运行。未知命令是数据问题，后面的橡皮还要入账。若改成抛出未接住的异常，进程停在第一处笔误，纸上没有后半段的合计，店员分不清哪些已经记上。印「失败」并继续，是这次记账的政策。政策可以改成「一处失败就整单作废」，那就要在失败时停止，并且不要印一个看起来有效的合计。两种政策都说得通。这一章选择继续，所以合计只反映动词正确的那些行，失败的行有可见的词。

空行先 `trim`。得到空字符串就 `continue`。空行不是金额 0，也不印「失败」。空行是店员留下的间隔，跳过它，纸上才不会在两笔记账之间夹一条失败。这和「未知动词」不同。未知动词是写了字但不认识。空行是没有字。两套规则在循环开头分成两个判断：先看空，再拆，再看动词。

金额文字用 `intval` 之前，先确认它不是空的。`记 铅笔` 只有两段时，第三段缺失，用 `?? ""` 得到空串，然后印「失败」，不加账。`intval` 对空串返回 0，若省略这道检查，会把残缺命令记成 0 分，键却被创建出来。创建出一个 0 分的铅笔，下一笔 `??` 会在这个键上累加，表面上还能算对，可是「残缺命令创造了键」会让 `count` 多出一件没有成功的货。检查失败时不要创建键。

函数 `post` 接收账、品名和整数分，返回新的账。调用处写 `$book = post($book, $name, $cents)`。不用引用参数。返回让赋值留在循环里，读代码的人能看见账被换上了新值。函数内部对参数数组的修改不会自动回到调用者，所以必须接住返回值。忘记接住，纸上的合计仍是 0，进程却成功。这是这一章最值得自己走一遍的失败：函数算对了，调用者把结果扔了。示例里每一笔都接住。

命令文本放在数组 `$lines` 里，不向键盘要下一行。这样一次运行的输入是源码的一部分，期望写得死。你改一行里的金额，再运行，合计跟着变。你若从键盘读，抽屉这边的管道并没有接上，脚本会在读取处失败，后面的记账全部无法核对。输入的来源和解释分开，上一章已经这样做了。这一章的来源是数组，解释是循环。

未知命令和空行的例子要能在纸上同时看见。一个块里放四行命令：一笔铅笔、一个空行、一笔未知动词、再一笔铅笔和一笔橡皮。纸上应有一次「失败」，铅笔合计 700，全单 900。失败词来自未知动词「退」，空行不产生失败词。700 是两笔 350。900 是再加上橡皮 200。

另一块不走文本，直接调用 `post`，用来证明账的规则不依赖拆分。拆分是入口，累加是核心。核心可以单独核对。入口可以单独拿一行「记 铅笔 350」来核对。两块都要，是为了坏在入口时不怀疑加法，坏在加法时不怀疑 `explode`。

第三块只拆一行，印出动词，确认限制为 3 时金额还是最后一段。这一块不入账，避免一次示例做太多事。

负数金额在 `post` 里拒绝：返回原来的账，并由调用者印「失败」。拒绝放在函数里，入口和直接调用走同一条规则。函数返回数组，怎么通知失败呢？可以抛 `Exception`。这一章的循环已经决定未知命令不抛到顶层。函数内部对负数抛 `Exception`，循环里接住，印「失败」，账保持调用前的值。因为 `post` 在抛出之前没有被赋值回去，旧账还在 `$book` 里。这要求 `post` 在修改之前检查，并且调用者只在没抛出时接收返回值。`try` 里写 `$book = post(...)`，抛出时赋值不发生。这个顺序比「返回 null 表示失败」更不容易把账换成 `null`。`$book = null` 之后，下一笔的下标会出警告。异常跳过赋值，类型还是数组。

下面三块是同一次记账思想的三个切面，进程仍互不共享变量。

```php run expect="700" title="两笔记账合成铅笔"
<?php
function post($book, $name, $cents) {
  if ($cents < 0) {
    throw new Exception("负数");
  }
  $book[$name] = ($book[$name] ?? 0) + $cents;
  return $book;
}
$book = [];
$book = post($book, "铅笔", 350);
$book = post($book, "铅笔", 350);
$book = post($book, "橡皮", 200);
echo $book["铅笔"], "\n";
echo array_sum($book), "\n";
```

铅笔 700，全单 900。期望锁定 700。全单在第二行。`array_sum` 把各个品名的值加起来。不要去 `echo $book`，那会印出 `Array`。键的个数可以用 `count($book)`，这里是 2，表示两种货，不是两笔铅笔。笔数和种类是两个数。这一块没有单独计笔数。若业务要笔数，就在 `post` 之外另加计数器，不要用 `count` 冒充笔数。

```php run expect="900" title="空行跳过，未知命令失败"
<?php
function post($book, $name, $cents) {
  if ($cents < 0) {
    throw new Exception("负数");
  }
  $book[$name] = ($book[$name] ?? 0) + $cents;
  return $book;
}
$book = [];
$lines = ["记 铅笔 350", "", "退 铅笔 350", "记 铅笔 350", "记 橡皮 200"];
foreach ($lines as $line) {
  $line = trim($line);
  if ($line === "") {
    continue;
  }
  $parts = explode(" ", $line, 3);
  $verb = $parts[0];
  if ($verb !== "记") {
    echo "失败\n";
    continue;
  }
  $name = $parts[1] ?? "";
  $amount = $parts[2] ?? "";
  if ($name === "" || $amount === "") {
    echo "失败\n";
    continue;
  }
  try {
    $book = post($book, $name, intval($amount));
  } catch (Exception $e) {
    echo "失败\n";
  }
}
echo $book["铅笔"] ?? 0, "\n";
echo array_sum($book), "\n";
```

「退」不是「记」，印出失败，然后继续。两笔铅笔仍然记上，橡皮也记上。纸上的顺序是：失败、700、900。空行没有额外的词。期望锁定全单 900。你要看见失败在合计之前，并且只有一次。若空行也被印成失败，就会有两次「失败」，子串仍能对上，所以要数次数。一次失败来自未知动词。这是政策：跳过空，报告未知，继续记账。

```php run expect="记" title="命令最多三段"
<?php
$parts = explode(" ", "记 铅笔 350", 3);
echo $parts[0], "\n";
echo $parts[1], "\n";
echo $parts[2], "\n";
echo count($parts), "\n";
```

三段分别是记、铅笔、350，个数是 3。`count` 在限制为 3 且确实有两处空格时就是 3。若字符串只有动词，个数是 1，后面的下标不要直接读，要用 `??`。这一块的字面量是完整的，三段都在。它不入账，所以改金额不会影响别的块。块与块之间没有共享的账。

把整章收成店里的一次结账。账从空数组开始。每一行文本先去掉两端空白。空则跳过。否则按空格最多拆成三段。动词必须是「记」。品名和金额都要在。金额先变成整数，负数由 `post` 拒绝。成功则用返回的新数组替换旧账。循环结束后印出关心的那个品名，以及 `array_sum` 的全单。再运行一次，数组字面量还在源码里，账会重新从空开始加到同样的数。这不是数据库。它是一次进程内的折叠。真要留下昨天的账，需要这份运行时没有准备的存储。在没有存储时假装有，会写出一批失败的文件函数。课程停在进程内。停在这里，是因为打印机的语言机制已经都用上了，再往外是另一门课的话题：持久化、权限和真正接上的标准输入。

品名不含空格这条约定，是拆分简单的原因。若约定守不住，就换一种分隔，例如用制表符或逗号，并在 `explode` 里改分隔符。分隔符改了，金额里就不能再含有那个字符。选择分隔符，就是选择哪种字符不允许出现在栏位里。空格不允许出现在品名里，是这一章的选择。代价是「红铅笔」必须写成没有空格的四个字，不能写成两个词。店里的品名本来就是一个词，这个代价可以接受。

这次运行的边界还可以再写死几条，免得它看起来像一个常驻的收银台。脚本没有循环去等下一行键盘。命令的份数就是数组的长度，`foreach` 走完就结束。结束之后进程退出，不留下服务。若你在末尾再写一个 `while (true)` 去等输入，这份运行时不会把输入送给你，循环只会空转，直到被停掉。空转不是记账。记账在 `foreach` 里已经做完。

失败词「失败」可能出现零次或多次。期望若只锁定期望中的合计，多次失败仍会通过核对。读纸面时要数失败的次数，并和未知命令的条数对照。一条未知命令对应一次失败。空行对应零次。残缺的「记」也对应一次。这个对照是政策的测试。政策改成「遇错即停」时，失败应当只有一次，而且合计不该再包含错误行后面的橡皮。现在的政策是继续，所以橡皮的 200 仍在 900 里。900 这个数本身就编码了政策：它不是「把所有行都当记」的总和，因为「退」那一行没有被减去，也没有被加上。退货没有实现。没有实现的动词不要偷偷当成减法。未知就是未知，只报告，不改账。

品名作为键，大小写和空格都算差别。PHP 的字符串键区分「铅笔」和「铅笔 」。`trim` 只作用在整行，拆开之后的品名若还带着空格，就会变成另一个键。`explode` 在单个空格上切开时，品名两端通常没有空格。连续空格会产生空的段。发现空段就失败，不要把空段当成品名去创建键。创建一个空字符串键，`echo` 时像是没有名字的金额，`count` 却增加了。空键比缺失更难发现，因为 `??` 不会替换已经存在的空键。拒绝空品名，就是不让这个键出生。

最后把十二章收成一台能解释的打印机。它用 `echo` 写纸，用整数分算账，用 `===` 比较，用点号拼接，用有序映射记住货，用循环扫描，用函数归拢规则，用私有字段保住一张票，用 `Exception` 拒绝坏行，用字符串代替还接不上的键盘，用内置函数拆行和求和，最后在一次运行里把命令折叠成账。每一章都把上一次的零件留在这张小票上。零件可以单独运行，是为了能核对。真正的店员脚本会把它们放进同一个文件，那个文件仍然从 `<?php` 开始，仍然不读超全局变量，仍然不假装自己是一次网页请求。

## 小结

记账是一次运行内的有序映射，键是品名，值是累加的分。命令放在字符串数组里，不读标准输入。`explode` 最多拆成三段，空行跳过，动词不是「记」时印「失败」并继续。`post` 返回新数组，调用者接住返回值。负数在修改之前拒绝。进程结束，账不保留。全单用 `array_sum`，某一种货用键去读，读不到时用 `??` 给出 0。
