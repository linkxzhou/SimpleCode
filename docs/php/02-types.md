巷口纸品的单价一直用分，是整数。铅笔 350，橡皮 200，直尺 450。整数相加得到的仍是整数，上一章的 550 就是这样来的。类型一旦放宽，纸上的金额会开始说谎。这一章看三件会让小票说谎的事：除法什么时候变成浮点，条件里什么样的零算「没有」，以及 `==` 怎样在比较之前改写两边的类型。

`20 / 6` 在 PHP 里做的是浮点除法。二十支铅笔按六支一盒来分，商的文字是 `3.3333333333333` 这一串，类型是浮点数，不是整数 3。你若把这个结果当成「能装几盒」写上小票，顾客会看见一长串小数，仓库也不会按零点三三盒出货。整数商用 `intdiv(20, 6)`，结果是 `3`。剩下的两支用 `%`，`20 % 6` 是 `2`。三盒加上零头两支，才是二十支。`intdiv` 的两个参数都应当是整数。它向零截断，正数时看起来像丢掉小数。课程的支数和分都是非负的，截断方向不会在这一章制造负数盒数。

选择整数分，是为了让合计可重复。二进制浮点不能精确表示许多十进制小数，`0.1` 元加十次，不一定是干净的 `1` 元。把单价存成分，加法就是整数加法，三百五十分加两百份一定是五百五十分。代价是你不能在源码里写 `3.5` 来表示三点五元，你写 `350`，显示成元是打印之前的格式问题。格式可以晚做，账必须早做对。若某一行的单价来自「总价除以支数」，而你用了 `/`，那一行就悄悄离开了整数。小票上再把它和别的整数加在一起，浮点会把整张合计拖进小数。能用 `intdiv` 的地方就用 `intdiv`，余数单独成行，不要让余数藏在小数点后面。

变量在第一次赋值时诞生。`$price = 350` 之后，`$price` 是整数。PHP 不要求你先声明类型。这个自由让小票的草稿写得很快，也让一个名字在几行之后改抱别的类型。`$price = "350"` 看起来还是三百五，类型已经变成字符串。后面用 `===` 和整数 `350` 比较，会得到不相等。草稿阶段少一个引号，账就会分叉。课程的单价保持不带引号的整数。从文本来的数字，要等你明确转换之后才参加加法。转换用 `intval`，它会读出字符串开头的整数。`intval("350")` 是 `350`。`intval` 不是检验。它碰到空串会给出 `0`，而 `0` 分和「这行根本没写价格」在纸上可能长得一样。检验留在条件和后面的失败处理里，不把 `intval` 当成「这串字是否合法」的回答。

条件里的假，范围比「布尔值 false」宽。`false`、整数 `0`、浮点 `0.0`、空字符串 `""`、字符串 `"0"`、空数组 `[]`、`null`，在 `if` 里都走假分支。非空的 `"00"`、`"0.0"`、`"false"` 却是真。这套规则靠近 C 的「零为假」，又比 C 多认了几种文本。`"0"` 是 PHP 里特别容易让小票沉默的一个值。数量如果从一行文本来，读者写下的零是两个字符：数字零。你写 `if ($qty)` 想表示「有数量才印这一行」，字符串 `"0"` 会让这一行消失。消失有时正是你要的，零支铅笔不必占用纸面。消失有时是错的：货号、柜号、批号也可能是 `"0"`，那不是「没有这行」。判断「有没有文本」时，用 `=== ""` 或看字节长度，不要把任意字符串丢进 `if`。判断「支数是不是零」时，先确定它已经是整数，再和 `0` 用 `===` 比较。

`==` 会在比较之前做类型转换。`0 == "0"` 为真，因为两边被看成同一个数值。`1 == "1"` 也为真。`===` 同时要求类型相同，`0 === "0"` 为假，`1 === "1"` 也为假。小票上的数量若一边是你写的整数、一边是刚读到的文本，`==` 会让它们看起来相等，后面的分支就按「已经对上」继续走。对上的是数值，不是「这两边是同一种东西」。PHP 8 收紧过一部分比较：非数字的字符串不再随便等于整数 `0`，`0 == ""` 是假，`0 == "铅笔"` 也是假。`"0"` 仍然等于整数 `0`，因为它是数值字符串。旧笔记里「任何字符串都等于零」的说法，在这门课的 8.2 上不成立。不要把那句旧话写进打印机。要写的是：数值字符串仍会在 `==` 下和整数对齐，所以精确比较用 `===`。

`==` 的宽松带来的好处是草稿快。你从文本拿到 `"350"`，用 `==` 去对整数 `350`，条件会成立，你少写一次转换。代价在边界上才出现。`"350"` 和 `350` 在宽松比较里相同，在严格比较里不同。空字符串和 `0` 在 PHP 8 的宽松比较里不同，在条件判断里却都是假。两套规则叠在一起，店员会觉得「零就是零」。拆开看，比较是一种规则，布尔转换是另一种规则。小票的数量检查要先选定用哪一套。课程选定严格比较和明确的空串检查。布尔转换只在你确实想说「这个值在 PHP 的条件里算不算有」时才用，并且字面上要能看出你知道 `"0"` 会落进假。

下面四块各自完整。第一块印整数商和余数。第二块印浮点除法的文字，好让两种除法并排记住。第三块用严格比较回答 `0` 和 `"0"` 是否同一类型的相等。第四块把字符串 `"0"` 放进条件，看它会不会被当成有数量。

```php run expect="3" title="二十支装成几盒"
<?php
echo intdiv(20, 6), "\n";
echo 20 % 6, "\n";
```

第一行是 `3`，第二行是 `2`。期望只锁定了 `3`。你自己要看见余数还在。若把 `intdiv` 换成 `/`，第一行会变成一长串小数，`3` 这个子串也许仍然出现在开头，核对会放过你。所以读这一块时要看整行是不是只有一个 `3`。余数用 `%`，不要用浮点去减出剩下的两支。浮点减法会在别的数上留下很难看的尾巴，支数这种必须整除的量不该走那条路。

```php run expect="3.333" title="同一式子的浮点商"
<?php
echo 20 / 6, "\n";
```

纸上是 `3.3333333333333`。这是引擎把浮点按它的规则印出来的样子，不是「三点三三元」。把它存进合计，后面的整数分会被抬成浮点。`intdiv` 拒绝这个含糊。两种写法都合法，合法不等于都适合做盒数。单价若本来就是「一盒的价格除以盒内支数」，而店员要的是每支大约多少分，浮点可以留下，但要单独放在一个名字里，不要和合计的整数混在同一个累加器。这一章的合计仍是整数。浮点那一行只用来被看见。

```php run expect="no" title="严格比较拒绝字符串零"
<?php
echo (0 === "0") ? "yes" : "no", "\n";
echo (0 == "0") ? "yes" : "no", "\n";
```

第一行是 `no`，第二行是 `yes`。三元表达式先得出字符串，再交给 `echo`。括号把比较括起来，是为了让运算符的优先级不要把 `===` 和三元表达式搅在一起。两行放在一起，是为了让宽松和严格的差别出现在同一张纸上。只印第二行，会让人以为零和字符串零「本来就相等」。它们在数值转换之后相等。类型并排看时，它们一个是整数，一个是字符串。小票的货号若允许是 `"0"`，不要用 `==` 去对整数货号 `0`。对上之后你分不清架上的标签是数字还是文本。

```php run expect="跳过" title="字符串零在条件里为假"
<?php
$qty = "0";
echo $qty ? "印出" : "跳过", "\n";
echo ($qty === "") ? "空" : "非空", "\n";
echo ($qty === "0") ? "字符零" : "其他", "\n";
```

第一行是跳过，因为 `"0"` 在条件里为假。第二行是非空，因为这不是空字符串。第三行是字符零，严格比较认得出它。三行一起说明：布尔眼中的「没有」、空串、以及字符零，是三件不同的事。打印零支铅笔时，若你的规则是「零支不占行」，第一行的跳过是对的，但你应当在注释或函数名里写明这条规则，并且先确认 `$qty` 是数量而不是货号。若货号 `"0"` 表示货架最左边那一格，第一行的跳过会把那一格从单子上抹掉。抹掉之前用第三行那种比较看一眼，成本是一次 `===`，换来的是格子还在。

`null` 表示这个名字没有值。没赋值的价格不应当悄悄变成 `0` 分。读取一个还没有的名字会发出警告，警告在 php-cgi 里常常是一段 HTML，小票就脏了。后面数组那一章用 `??` 给缺失的键一个默认值，默认值要由你选定：缺失的单价用 `0` 会把「没标价」印成免费。那是危险的默认。这一章先不读缺失的键。这里只记住 `null` 在条件里为假，它和整数 `0` 用 `===` 比较并不相等。`0 === null` 是假。免费和没标价必须在纸上能分开，分开的办法是严格比较，以及不要用一个假值同时表示两种意思。

布尔值自己印出来也不直观。`echo true` 得到字符 `1`，`echo false` 得到空。所以这一章的例子不直接打印布尔值，而打印 `yes`、`no`、`跳过` 这样的字。字是我们选定的，引擎的 `1` 和空白会和金额、空行混在一起。选定短词，期望才稳。

把类型收束到这张小票上。盒数用 `intdiv`，零头用 `%`，合计用整数分。从文本来的数量在放进条件之前，先想清楚它是不是允许为字符零。比较金额和数量时用 `===`。`==` 仍会在数值字符串上把 `0` 和 `"0"` 看成相等，PHP 8 并没有取消这一种转换。下一章看这些数怎样嵌进一行文字，以及中文品名占多少字节。

金额的显示和金额的存储还可以再分开看一次。存储用分，是整数。显示若要写成元，就要在打印前把分转换成带两位小数的文字。转换是字符串格式的工作，不是再做一次除法然后把浮点存回去。存回去之后，下一行的加法就离开了整数。小票可以在最后一行把合计的分除以 100 只为了给人看，那一行的结果不要再加回 `$total`。`intdiv($total, 100)` 是元的整数部分，`$total % 100` 是剩下的分。两段都是整数，拼成文字时自己补齐两位。这个拼法比把合计交给浮点除法更长，换来的是纸上的元和账上的分不会来回污染。

布尔转换还有一层和数组相交的地方，这里先点明，细节留给数组那一章。空数组为假，所以一张还没有货行的票在 `if ($lines)` 里会像数量零一样被跳过。跳过空单往往是对的。把同一套 `if` 用在价目表上，空表和「单价是 0」不是一回事，表是容器，0 是容器里的值。容器为空，用个数判断。值为 0，用 `=== 0` 判断。类型这一章把这两句规则放在一起，是为了防止「凡是假就当没有货」变成一句口诀。口诀在 `"0"`、`0` 和 `[]` 上会做出三种不同的删除，店员却以为自己只写了一个条件。

比较运算符的选择也影响排序和查找，虽然这一章还没有数组函数。`==` 适合你已经确定两边都是整数分的草稿。一旦有一边可能来自文本，就改用 `===`，或先 `intval` 再 `===`。先转换的好处是转换发生在一个看得见的调用里，后面的比较恢复成整数和整数。转换的代价是非法文本变成 0，必须在转换前把空串剔掉。不转换、直接 `===` 的好处是非法文本永远不等于整数，失败更明显。两套都可以做对小票，前提是不要在同一行里混用。混用时，`"350" == 350` 成立而 `"350" === 350` 不成立，分支会按你手滑的那一个运算符走。

## 小结

`20 / 6` 是浮点，`intdiv(20, 6)` 才是整数商，余数用 `%`。单价用整数分，是为了让合计停留在整数里。条件中的假包括 `0`、`0.0`、`""`、`"0"`、`[]` 和 `null`。`"0"` 不是空字符串。`==` 会把数值字符串和整数对齐，`===` 还要求类型相同。判断有没有文本时用严格比较，不要把任意字符串丢进 `if`。
