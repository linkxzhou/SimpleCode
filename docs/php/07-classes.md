函数已经能算一行的分。店名、明细和合计仍散在调用处的变量里。打第二张票时，你要记得换掉那些变量，否则两张票会共用同一份列表。类把「这一张票」收成一个值。`new` 一次，得到一张票。再 `new` 一次，得到另一张。巷口纸品的类名叫 `Receipt`。它记住店名，记住每一行的金额，并交出合计。它不负责读键盘，也不负责连接网络。那些事不属于这一张纸。

字段写在类里，这一章用经典的写法。先声明 `private $shop;` 和 `private $total;`，再在 `__construct` 里赋值。PHP 8 允许把 `private` 写在构造函数的参数上，一行里既声明字段又完成赋值。那种省写会把字段的名单从类的前部挪到参数列表里，短类看起来很轻，字段一多，参数列表就变成唯一的清单。课程不使用那种写法。字段在类身体的上方能被扫到，构造函数只负责把传入的值放进 `$this`。多几行，换来的是下一班不用在参数的修饰符里找「这张票到底记住了什么」。

`$this` 指向这一张票自己。方法里写 `$this->total` 才是字段。写成 `$total` 则是另一个局部变量，可能尚未赋值。未赋值的局部变量会带来警告，字段却原封不动，纸上的合计会变成空。这个笔误很常见，因为美元符号都在，少的是 `->`。`->` 才表示「这个对象的」。没有 `$this->` 的名字，和对象无关。静态属性用 `self::$` 或类名访问，它属于类，所有票共享。不要把某一张票的合计放进静态属性。第二张票 `new` 出来时会看见第一张留下的分，两张顾客的账就串了。静态属性适合真正与个别票无关的东西，例如某种固定的栏宽常数。合计、店名、明细都是个别票的数据，放在普通私有字段里。

私有字段从类的外面读不到。`$ticket->total` 会得到 `Error`，进程若没有接住它就会停。外面只能调用公开的方法。`cents()` 返回合计，`shop()` 返回店名。方法是合同，字段是存储。合同可以以后改成「合计从明细重算」，调用处仍写 `$ticket->cents()`。若外面直接读字段，你就无法再把存储从「一个整数」换成「一个列表」。私有是这扇门。它的代价是调试时不能在类外随便看一眼字段，要看就加一个方法，或在方法里暂时返回。加方法比把字段改成 `public` 更稳。`public` 字段谁都可以改，打印机的合计会被外面加上一笔没有明细的数，纸面和账对不上。

构造函数在 `new Receipt("巷口纸品")` 时运行。参数是这张票的店名。合计的初值在构造函数里设为 `0`，不由调用者传入。调用者若能传入初值，就可能造出一张「还没有货、合计却是 500」的票。初值为 0 的含义是：明细还是空的，金额从零开始累加。这个 0 是起点，方法名 `add` 才负责把货的分加进去。`add` 检查数量为 0 时不去加，或者加上 0。加上 0 不改变合计，也让调用次数和明细行数可能不一致。更清楚的做法是数量为 0 时方法直接返回，不增加合计。返回可以是 `$this`，让调用连成 `$ticket->add(350, 2)->add(450, 1)`。返回 `$this` 的代价是 `add` 的结果不是金额，而是票本身。若调用者 `echo` 了 `add` 的返回值，就会去印对象。这一章的 `add` 不返回 `$this`，它什么都不返回，调用者再调 `cents()` 取合计。两步分开，每一步的结果类型都单纯。

对象不能直接交给 `echo`。引擎会说这个类的对象无法转成字符串，抛出的是 `Error`，不是你在下一章要接的 `Exception`。纸上没有店名。想印票，就 `echo` 方法返回的字符串。若你希望 `echo $ticket` 能工作，类里要定义 `__toString`，返回店名和合计的文字。`__toString` 不能抛出 `Exception`，它被限制在转换这条路上。小票的转换若可能失败，不适合放进 `__toString`。课程用普通方法 `text()` 返回文字，失败的情况留到异常那一章用可以抛出的方法来做。`text()` 的实现就是店名、一个空格、合计。它读字段，不修改字段。查询和改账分开，读方法可以多次调用，结果一样。`add` 会改合计，调用两次就会加两次。不要在打印用的方法里偷偷 `add`。

每一张票是单独的对象。两个变量可以指向同一张票。`$copy = $ticket` 之后，`$copy->add(200, 1)` 会改变 `$ticket` 看见的合计，因为两个名字是同一对象，不是两份明细。这和数组赋值不同。数组赋值在修改时会分开，对象赋值不分开。需要第二张独立的票时，再 `new` 一次，或写一个方法返回新对象。课程的例子每次只 `new` 一张，并只用一个名字，避免别名把账加两次。知道别名存在，是为了在你写出 `$copy = $ticket` 时明白自己在做什么。

类的定义在一份脚本里出现一次。第二块示例是新进程，类要再写一遍。方法里调用同一张票的另一个方法，用 `$this->cents()`。不要在方法里写 `Receipt::cents()` 这种不带对象的调用，合计在对象上，不在类上。没有静态的 `cents`。

下面三块分别看构造、累加，以及直接打印对象时的失败。失败被接住，是为了让这一块仍能跑完并印出固定的词。接住 `Error` 用 `catch (Error $e)`。它和 `Exception` 是两条线，下一章会把这个分叉说透。这里先看到：印对象不是小票的正常路径。

```php run expect="巷口纸品" title="构造时记下店名"
<?php
class Receipt {
  private $shop;
  private $total;
  public function __construct($shop) {
    $this->shop = $shop;
    $this->total = 0;
  }
  public function shop() {
    return $this->shop;
  }
  public function cents() {
    return $this->total;
  }
}
$ticket = new Receipt("巷口纸品");
echo $ticket->shop(), "\n";
echo $ticket->cents(), "\n";
```

店名是巷口纸品，合计是 0。0 出现在第二行。期望锁定店名。你要看见合计从 0 开始，而不是从残留的数开始。字段是私有的，脚本没有写 `$ticket->total`。构造函数把 0 写进 `$this->total`。若把这行漏掉，第一次读合计时字段是 `null`，印出来是空，再拿去加法会发出警告。构造函数的工作就是让一张新票的每个字段都有合法的起点。

```php run expect="1150" title="只通过方法累加"
<?php
class Receipt {
  private $shop;
  private $total;
  public function __construct($shop) {
    $this->shop = $shop;
    $this->total = 0;
  }
  public function add($cents, $qty) {
    if ($qty === 0) {
      return;
    }
    $this->total += $cents * $qty;
  }
  public function cents() {
    return $this->total;
  }
}
$ticket = new Receipt("巷口纸品");
$ticket->add(350, 2);
$ticket->add(200, 0);
$ticket->add(450, 1);
echo $ticket->cents(), "\n";
```

700 加 450 是 1150。数量为 0 的橡皮在 `add` 里返回，不改合计。调用三次，只有两次生效。方法没有返回合计，脚本用 `cents()` 取走整数再打印。`$this->total` 始终留在类内。你若在类外把字段改成能直接赋值，这两道 `add` 的规则就可以被绕过。私有让规则只存在于方法里。

```php run expect="无法直接印出" title="对象不是一行文字"
<?php
class Receipt {
  private $shop;
  public function __construct($shop) {
    $this->shop = $shop;
  }
  public function shop() {
    return $this->shop;
  }
}
$ticket = new Receipt("巷口纸品");
try {
  echo $ticket;
} catch (Error $e) {
  echo "无法直接印出\n";
}
echo $ticket->shop(), "\n";
```

`echo $ticket` 抛出 `Error`，被接住后印出「无法直接印出」。接着仍通过方法印出店名。若没有 `try`，进程会停在 `echo $ticket`，店名那一行不会执行。接住是为了把这条死路演示成可见的词。正常的打印机不要靠接住转换错误来工作，它从一开始就调用 `shop()` 或 `text()`。`catch` 的类型是 `Error`。写成 `catch (Exception $e)` 接不住这一次失败，下一章会做一个对照。

继承可以做出「带税率的小票」，子类覆盖 `cents()`。巷口纸品的第一版没有税，不急着继承。过早的子类会让店名和合计的归属变得难找。先让一个类把一张票说完。真出现第二种票时，再决定是继承、还是两个类各写各的、还是一个类加一个明确的费率参数。费率参数比继承浅，适合只有一个数不同的情况。行为差很多时，才值得分成两个类。这个取舍现在先记着，示例保持一个类。

方法的可见性用 `public` 和 `private`。辅助的乘法可以是私有方法，外面不必看见。私有方法仍通过 `$this` 调用。把所有方法都公开，类的表面会和内部草稿一样大。表面只留 `add`、`cents`、`shop`。三个方法够打出这一章的小票。明细列表若也要记住，可以再加一个私有数组字段，在 `add` 里追加。合计既可以存着，也可以每次从明细重算。存着更快，重算更不容易和明细不一致。这一章的合计是存着的整数，因为还没有保存明细。一旦保存明细，就要选定单一来源：要么只信明细、合计现算，要么每次 `add` 同时改两处并在测试里核对它们相等。单一来源更省心。下一章在失败时抛出异常，那时候若有两处存储，失败路径还得把两处一起回滚。存一个数，回滚就是不去加。

一张票的生命周期还可以再收紧。对象在 `new` 时诞生，在进程结束时消失。没有析构函数要写，因为没有要关闭的连接。若你加上空的 `__destruct`，它会在对象不再被用到时运行，运行时刻不一定紧挨着你的最后一次 `echo`。空的析构不改变合计，却会让人以为打印和销毁之间还有一步隐藏的账。没有隐藏的账。合计只在 `add` 里变化，只在 `cents` 里被读走。

比较两张票是否「同一笔账」，不要用对象的默认比较去猜。两张票的店名和合计相同，它们仍是两个对象。顾客补打一张，应当 `new` 出第二张，再把同样的货 `add` 一遍，而不是把第一张的变量赋给第二个名字。赋值得到的是同一张，补打时再 `add` 会把合计翻倍。翻倍之后两张纸都错，因为它们根本是一张。需要相同内容的副本时，写一个方法，用现在的店名和合计去 `new` 一张新的，返回那个新对象。方法把「复制」说出来。赋值不说。

类名用名词，方法名用动词。`Receipt` 是票，`add` 是记一笔，`cents` 是读合计。`cents` 这个名字没有写成 `getCents`，是为了短，也因为它不修改任何字段。若方法会修改，名字里就要带上动作，避免把 `add` 叫成 `total` 然后在读取时偷偷累加。读取时累加，印两次就会加两次。查询方法的合同是多次调用结果相同，只要中间没有别的方法改过字段。这个合同让你可以在打印前先读一次合计做检查，再读一次去印，不用担心检查本身改了账。

## 小结

类用私有字段保存这一张票的店名和合计。字段在类里声明，在 `__construct` 里赋值，不把可见性写进构造参数来省掉声明。方法通过 `$this->字段` 访问，外面通过公开方法取走整数或字符串。静态属性属于类，不拿来放某一张票的合计。对象不能直接 `echo`。两个变量指向同一对象时，`add` 会同时改变两边看见的金额。

## 练习

类保存一个整数。方法 `twice` 返回它的两倍。构造时传入 21，打印 `twice` 的结果。

::: answer 参考答案：两倍
```php run expect="42" title="参考答案"
<?php
class Num {
  private $n;
  public function __construct($n) {
    $this->n = $n;
  }
  public function twice() {
    return $this->n * 2;
  }
}
echo (new Num(21))->twice(), "\n";
```
