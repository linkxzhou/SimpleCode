小票的下一行常常来自店员刚刚键入的那一行字。别的环境里，你会写 `fgets(STDIN)` 去读它。这份 `php -q` 做不到。常量 `STDIN` 没有定义，一执行到 `fgets(STDIN)` 就是致命错误：未定义常量。`fopen("php://stdin", "r")` 返回 `false`，再把 `false` 交给 `fgets` 同样失败。`fopen("php://fd/0", "r")` 也返回 `false`。`php://input` 读不到抽屉送进标准输入的字节，它的长度是 0。这些入口在网页 SAPI 或完整的命令行 SAPI 里往往有定义。这里的二进制是 cgi 那一支，又跑在没有把标准输入接进 PHP 的运行时上。抄来的读行教程会在第一行就停住，停住时纸上没有金额。

可运行的示例因此不调用这些入口。需要「店员刚刚的一行」时，把那一行写进字符串，末尾可以带上 `\n`，表示它曾经是一行。处理这串文字的步骤，和将来真能读到键盘时要做的步骤是同一套：先去掉行尾，再看是不是空的，再拆出品名和数字。键盘那一头什么时候接上，不改变这一套。现在就把它在字符串上演练对。只读的那一块把不能用的调用记下来，免得你从手册抄进可运行的脚本。那一块不会被执行。把它留在抽屉里对照即可。

`rtrim` 去掉右端的空白，包括换行和回车。`rtrim("铅笔 2\n")` 得到 `铅笔 2`。左端的空格还在。若行首没有空格，`rtrim` 就够了。`trim` 两边都去，行首的栏宽空格也会消失。小票的输入行不靠前导空格对齐，用 `trim` 更不容易留下看不见的空白。这一章的例子两种都演示：行尾换行用 `rtrim` 就能够着，因为它只粘在右边。去掉之后再判断空。判断要用 `=== ""`。空行 `rtrim("\n")` 得到空字符串。空字符串不是数量 0。`intval("")` 会给出整数 `0`，纸上像是店员输入了零。零支和「什么都没打」应当分开。空行印「失败」，不要入账。这和上一章的异常是同一个词，这里用 `if` 就够了，因为空是看一眼就知道的。

看起来像整数的文字，再用 `intval`。`intval("41")` 是 41。`intval` 允许前面有空白，也允许后面跟着不是数字的尾巴，它会读出开头的数。`"41支"` 会得到 41，尾巴被忽略。忽略在草稿里方便，在小票里危险：单位被吃掉，你以为整行都是数。更严的检查是去掉空白之后，确认每一个字符都是数字，再转换。这一章的数量字段在拆开之后应当整段都是数字。示例用已经干净的 `"2"` 和 `"41"`。若整段不是数字，就印「失败」，不要调用 `intval` 之后再猜。`intval("铅笔")` 是 0，又和空行撞车。所以顺序固定为：去行尾、判空、拆字段、再对数字字段转换。任何一步不对，都停在「失败」，合计保持原样。

拆字段可以用空格。`"铅笔 2"` 用 `explode(" ", $line, 2)` 得到品名和余下的部分。限制成两段，是为了品名里若有空格，余下的部分仍留在第二段。这一章的品名不含空格，限制仍然写上，习惯就和后面的命令行一致。`explode` 的细节在内置函数那一章还会再看。这里只要能拿到数量字符串，并在它为空时失败。

下面第一块是只读的，里面写着不能运行的调用。后面三块都可运行，分别去掉换行、把带换行的数量加一、以及把空行印成失败。三块都不出现 `STDIN`。

```php norun title="键盘这一行现在读不到"
<?php
// fgets(STDIN) 会因为常量 STDIN 未定义而致命退出。
// fopen("php://stdin", "r") 返回 false，不能再交给 fgets。
// fopen("php://fd/0", "r") 同样返回 false。
// file_get_contents("php://input") 看不到抽屉送入的标准输入。
```

这一块故意不能运行。注释里的调用若删掉注释，脚本会失败或什么都读不到。可运行的例子都在它后面，改那些例子时不要把 `fgets(STDIN)` 加进去。只读块不是坏掉的按钮。它用来对照手册和这台打印机的差别。手册假定标准输入已经接好。这台没有接好。

```php run expect="铅笔" title="去掉行尾换行"
<?php
$line = "铅笔\n";
echo rtrim($line), "\n";
```

字符串里的 `\n` 是数据，不是源码的换行。`rtrim` 把它去掉，再由 `echo` 写一个新的换行，保证纸上仍有行尾。若不 `rtrim` 就直接 `echo $line`，纸上也会看见铅笔，因为换行本来就在字符串末尾，期望仍可能对上。差别要在后面拼接时才显出来：没去掉的换行会把下一列挤到第二行。处理行的函数应当返回不带行尾的内容，由最后一次打印负责换行。

```php run expect="42" title="带换行的数量加一"
<?php
$line = rtrim("41\n");
if ($line === "") {
  echo "失败\n";
} else {
  echo intval($line) + 1, "\n";
}
```

`41` 去掉换行后转成整数，加一得到 42。加一不是小票的业务，它用来证明转换之后的值能参加算术，而不是还带着换行的字符串。字符串 `"41\n" + 1` 在 PHP 8 里会得到类型错误，进程失败。先 `rtrim` 再 `intval`，加的是整数。空字符串的分支在这一块不会走到，它仍要写上，因为这是处理行的完整形状。删掉空分支，这一块的 41 仍能算出 42，下一班把输入改成空行时就会掉进 `intval` 的 0。形状留全。

```php run expect="失败" title="空行不是零"
<?php
$line = rtrim("\n");
if ($line === "") {
  echo "失败\n";
} else {
  echo intval($line), "\n";
}
```

空行走到失败，不会印出 0。`else` 里的 `intval` 在这次运行中不执行。它留在那里，是为了展示非空时才会转换。若有人把判断改成 `if ($line == 0)`，空字符串在某些比较里的表现会和整数缠在一起，PHP 8 里 `"" == 0` 是假，可是 `""` 在条件里仍是假。不要用宽松比较来识别空行。`=== ""` 只认空字符串。字符串 `"0"` 不是空行，它是店员输入了零。零的处理可以用上一章的规则拒绝，或按「零不占行」跳过。那是数量规则。空行是「没有输入」的规则。两套规则分成两个判断，先看空，再看是不是零。

再补一块把品名和数量一起从带换行的字符串里取出，证明这套步骤能服务小票，而不只是服务单个数字。这一块也是可运行的。

```php run expect="700" title="从一行文字算出两支铅笔"
<?php
$line = trim("铅笔 2\n");
if ($line === "") {
  echo "失败\n";
} else {
  $parts = explode(" ", $line, 2);
  $name = $parts[0];
  $qty_text = $parts[1] ?? "";
  if ($qty_text === "") {
    echo "失败\n";
  } else {
    $cents = 350;
    echo $name, "\n";
    echo intval($qty_text) * $cents, "\n";
  }
}
```

第一行输出是铅笔，第二行是 700。单价仍写在脚本里，因为这一行文本只带了品名和数量，没有带单价。单价来自价目表是数组那一章的形状。这里把 350 写在旁边，是为了让这一块自己能跑完。`explode` 限制为 2，`$parts[1]` 用 `??` 防止只有品名时去读缺失的下标。只有品名时印失败，不把单价乘上一个不存在的数量。

将来若运行时真的把标准输入接进了 PHP，要改的是取得 `$line` 的那一行，换成读取函数的返回值，后面的 `trim`、判空、`explode`、`intval` 都不用改。把「取得」和「解释」分开，就是这一章把读入写成只读块、把解释写成可运行块的原因。现在改读取函数，只会让解释一起无法核对。解释先在字符串上变成绿的，等入口可用时再接一根管子。

不要用 `$_POST` 或 `$_GET` 假装那是键盘。第一章已经看过，那些数组里没有店员刚刚打的字。标准输入和请求参数是两条通道。两条现在都不是小票的来源。来源是字面量字符串。字面量的好处是期望稳定。代价是你看不到自己在键盘上打字的过程。课程用稳定换可核对。练习也用字符串，不要求从键盘读。

行的来源还可以再列一次，免得和别的通道混在一起。标准输入是进程的一条字节流，键盘只是其中一种接法，文件重定向也是一种。这份运行把这条流挡在 PHP 外面，所以两种接法都看不见。`$_POST` 是另一条通道，属于请求体，这一次没有请求体。命令行参数在 `$_SERVER["argv"]` 里，那里有脚本路径，没有店员要记的货。课程不从 `argv` 读品名，是为了让示例不依赖启动参数的个数。启动参数多一个，拆分就会错一位。字符串字面量的位数是写死的，错了也只错在这一块源码里。

`rtrim` 的默认字符集合包括空格、换行、回车、制表符和几个较少见的空白。它不去掉汉字，也不去掉数字。`"铅笔\n"` 会变成 `"铅笔"`，`"铅笔  "` 会变成 `"铅笔"`，末尾的空格一并消失。若金额和品名之间的空格在行尾之外，不受影响。若某一栏故意用空格补齐到固定宽度，`rtrim` 会把补齐吃掉，栏就歪了。固定宽度的行不要用默认的 `rtrim`，只去掉你知道存在的那个换行。可以写成 `rtrim($line, "\n")` 只删换行。第二个参数收窄了集合，行尾的空格得以保留。收窄的代价是回车 `\r` 不会被删。从别的系统复制来的行可能是 `\r\n`。先把 `\r` 也放进第二个参数，或先统一换成 `\n` 再删。小票的示例字符串只用 `\n`，默认 `rtrim` 就够。知道第二个参数存在，是为了下一张票的行尾不那么干净时有办法，而不是换一个函数。

空行和只含空格的行，在 `trim` 之后是同一种空字符串，在 `rtrim` 之后不是。只含空格的行，`rtrim` 会把空格去掉，因为空格属于默认集合，结果仍是空字符串。所以对「整行都是空白」来说，默认 `rtrim` 和 `trim` 都会得到空。差别出现在行的左端还有非空白、右端有空格的时候。品名在左、误按的空格在右，两者都能收拾。品名在右、左端有空格，只有 `trim` 能收拾。输入行没有固定栏宽时，用 `trim`。这一章有的块用 `rtrim`，是为了把「去掉右边的换行」这个动作的名字留在标题里。行为在这些示例上和 `trim` 一致，因为左端没有空格。

转换之后的整数若要写回字符串，用拼接或插值，不要以为 `intval` 会改掉原来的那一行。原来的 `$line` 还是字符串。你把整数加一，得到的是新整数。再印出来时，它不再带有品名。若希望纸上仍是「铅笔 42」，就要把品名留下，只替换数量那一段。替换发生在拆开之后的重组，不是 `intval` 的副作用。`intval` 没有副作用。它只读，只返回。这个性格和 `rtrim` 一样。小票的处理链因此全是「旧值进，新值出」，你可以在任何一步打印中间值来核对，不用担心打印破坏了下一笔。打印中间值时记得事后删掉，否则顾客会看见 41 和 42 两行。

只读块里的注释使用了 `//`，所以那一块即使被误运行，注释也不会去调用 `fgets`。这是双保险。保险的第一层是块标记为不运行。第二层是调用写在注释里。两层都在，是因为只靠一层时，有人会把标记删掉，或把注释删掉。两层同时被删，才真的会碰到未定义常量。到了那一步，失败是诚实的：这台打印机确实没有 `STDIN`。不要为了让误运行也能成功，而写一个捕获未定义常量的空壳。空壳会让人以为输入已经读到了。读到的只能是我们放进字符串的那一行。

## 小结

这份 `php -q` 里 `STDIN` 未定义，`php://stdin` 和 `php://fd/0` 打不开，`php://input` 也看不到标准输入。可运行的例子把一行放进字符串。`rtrim` 或 `trim` 去掉行尾换行，空字符串印「失败」，不把空行 `intval` 成 0。数字字段在确认非空之后再转换。`fgets(STDIN)` 只出现在不运行的对照块里。
