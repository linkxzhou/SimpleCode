上一章的名称、件数、单价是三个并排的名字。打印时要自己记住次序，复制一笔订单时要复制三行。这一章把它们收进一个结构体 `Order`。一笔订单仍然是茶，单价 1800 分。新的问题是：把订单赋给另一个变量之后，改件数会不会影响原来那一笔；方法写在值上和写在指针上，差在哪里。

结构体是一组有名字的字段。`Order` 里放 `Name`、`Qty`、`Cents`，类型分别是字符串和两个整数。字段名在这个课程里用大写开头，因为 Go 用首字母大小写决定能不能被其他包看见。这一份文件只有 `package main`，没有其他包来导入它，大写在抽屉里并不增加调用方。仍然写成大写，是为了和你以后把 `Order` 放进真正的包时一致。小写字段在单文件里一样能用。选择大写的代价是示例看起来像导出 API。换来的是抄到多文件工程里不必再改一遍名字。

字面量 `Order{Name: "tea", Qty: 2, Cents: 1800}` 按字段名填值。带名字的字面量不怕你以后调整字段顺序。不带名字的 `Order{"tea", 2, 1800}` 更短，可是一旦有人在 `Qty` 和 `Cents` 之间插入一个字段，数字会滑到错误的列上，两杯可能变成单价 2 分。订单这种会长大的数据，用带名字的字面量。

方法是带接收者的函数。接收者写在 `func` 和名字之间。`func (o Order) Line() int` 表示 `Line` 属于 `Order`，调用时写成 `o.Line()`。值接收者拿到的是订单的一份副本。函数里给 `o.Qty` 加数字，加在副本上，调用结束后副本丢掉，原来的变量还是旧件数。指针接收者 `func (o *Order) AddPtr(n int)` 拿到的是地址。通过地址写入，原来的件数会变。

先看值和复制。`a` 是一杯茶。`b := a` 把整份结构体复制给 `b`，两个变量各有自己的件数。把 `b.Qty` 改成 4，`a.Qty` 仍是 1。打印 `1 4`。这就是「复制丢掉修改」的意思：修改发生了，但发生在副本上，你若还拿着原来的名字，就看不见那次修改。

```go run expect="1 4" title="复制之后各改各的"
package main

import "fmt"

type Order struct {
	Name  string
	Qty   int
	Cents int
}

func main() {
	a := Order{Name: "tea", Qty: 1, Cents: 1800}
	b := a
	b.Qty = 4
	fmt.Println(a.Qty, b.Qty)
}
```

复制整份结构体是 Go 的默认。没有隐式的引用。这和很多把对象默认当成引用的语言不同，值得把取舍说透。默认复制让「把订单传给一个函数」变成安全的阅读：函数若接收值，它改不到你的件数。你可以把一笔订单交给计算金额的函数，不必担心它顺手改了数量。代价是大结构体复制要花拷贝的时间，而且任何「我想改原件」的意图都必须写成指针，写漏了就会出现上面这种 `1 4`：你以为两处是同一笔，其实是两笔。订单字段才三个整数级的量，复制的成本可以忽略。后面字段里若放了切片，切片的头会被复制，底层数组仍共享。那是切片那一章的事。现在三个简单字段，复制就是深的，改 `b` 完全碰不到 `a`。

值接收者把这件事放进方法里。`AddValue` 的接收者是 `Order` 而不是 `*Order`。调用 `a.AddValue(2)` 时，语言复制一份 `a` 交给方法，方法里的 `o.Qty` 变成 3，方法返回后那份副本消失。`a.Qty` 仍是 1。接着 `AddPtr` 的接收者是指针。`a.AddPtr(2)` 时，即便 `a` 是一个值而不是指针，Go 也会自动取地址，只要 `a` 是可寻址的变量。方法通过指针把 1 加上 2，得到 3。打印 `1 3`，两个数字分别是两次调用之后的件数。

```go run expect="1 3" title="值接收者不写回"
package main

import "fmt"

type Order struct {
	Name  string
	Qty   int
	Cents int
}

func (o Order) AddValue(n int) {
	o.Qty += n
}

func (o *Order) AddPtr(n int) {
	o.Qty += n
}

func main() {
	a := Order{Name: "tea", Qty: 1, Cents: 1800}
	a.AddValue(2)
	afterValue := a.Qty
	a.AddPtr(2)
	fmt.Println(afterValue, a.Qty)
}
```

自动取地址只发生在接收者是变量的时候。若你写 `Order{Qty: 1}.AddPtr(2)`，字面量没有稳定的地址可以取，这种调用在正式编译器里会失败。课程的例子先把订单放进变量 `a`，再调用方法，两条工具都能接受。读方法签名时先看接收者是不是指针。是指针，就默认它可能改字段。是值，就默认它只读，除非它返回一个新的订单让你自己赋值回去。

第三段让值接收者做它适合做的事：计算，不修改。`Line` 用件数乘单价，返回整数。两杯茶是 3600。方法不改 `Qty`，所以用值接收者是诚实的。若一个方法既计算又修改，签名会撒谎。读代码的人看见值接收者，会以为调用前后订单一样。让修改集中在指针接收者上，让查询集中在值接收者上。这样 `Line` 可以放心对副本调用，包括对 map 里取出来的临时副本，而不必先想「这会不会把柜子里的订单改掉」。

```go run expect="3600" title="值接收者只计算"
package main

import "fmt"

type Order struct {
	Name  string
	Qty   int
	Cents int
}

func (o Order) Line() int {
	return o.Qty * o.Cents
}

func main() {
	a := Order{Name: "tea", Qty: 2, Cents: 1800}
	fmt.Println(a.Line())
}
```

也可以写成普通函数 `func Line(o Order) int`。方法和函数在这一章都能算 3600。方法的好处是调用点读起来像订单自己的能力：`a.Line()`。函数的好处是它不占据类型的方法集，同一种计算可以服务多种类型。金额这种完全由字段决定的运算，放成方法是为了后面的接口能按方法集来要求「能报出金额」。接口那一章会把 `Cents` 或 `Line` 收成一个小接口。现在先让方法落在结构体上。

指针还有一种用法是让变量缺席。`var p *Order` 的值是 nil，它不指向任何订单。对 nil 指针取 `p.Qty` 会在运行时崩溃。值类型的 `var a Order` 则是一张字段全零的订单，可以读 `a.Qty` 得到 0。所以「可能没有这笔订单」用指针表达，「一定有一张表，只是还没填」用值表达。加件数的方法若写成指针接收者，调用前要保证指针不是 nil。这一章的 `a` 是变量，取地址一定成功。空指针的崩溃留到零值那一章，和「零值本身可用」放在一起比较。

字段的比较也跟着复制走。两个 `Order` 若字段都是可比较类型，可以用 `==`。字符串和整数都可以比较，所以两笔茶、件数和单价都相同的订单，`==` 为真。这是值相等，不是「是不是同一个变量」。`b := a` 之后，在改 `b` 之前，`a == b` 成立，即便它们是两份内存。你若需要身份，也就是「是不是柜台里的那一笔」，值相等帮不上忙，要靠指针是否指向同一地址，或者靠一个显式的订单号字段。这一章还没有订单号。相等就是三个字段都相等。

把修改写回去的另一种风格是返回新值：`func (o Order) WithQty(n int) Order`，里面改副本的件数，返回副本，调用者写 `a = a.WithQty(3)`。这种风格完全不用指针，每一笔修改都在赋值时发生，旧订单若还被别人拿着就保持原样。代价是调用者必须记得把返回值赋回去。忘了赋值，和用了值接收者却指望原件变化，是同一种疏忽：结果被丢掉了。指针接收者把「写回去」放进方法内部，调用者不容易忘，却也更容易在共享的订单上产生副作用。小店的柜台若同一笔订单只由一个变量持有，指针接收者直接。若订单值会交给日志、交给计价、交给打印，值接收者或返回新值更安全。

包子可以是另一笔 `Order{Name: "bun", Qty: 1, Cents: 600}`。它和茶的类型相同，字段相同，所以 `Line` 和 `AddPtr` 不用重写。类型是模板，字面量是具体的一笔。这一章的可运行块只用茶，是为了让 `1 4` 和 `1 3` 的来源单一。练习里再填包子。

[Go by Example](https://gobyexample.com/) 的结构体和方法页能对上语法。[Learn Go with Tests](https://quii.gitbook.io/learn-go-with-tests) 会把这种小类型放进测试里断言。这里的 `1 4` 是复制，`1 3` 是两种接收者。

字段的零值和「没写进字面量」是同一件事。`Order{Name: "tea", Cents: 1800}` 漏写 `Qty` 时，件数是 0，金额方法会得到 0。这不是字面量把件数丢掉了，是未写出的字段保持零值。带名字的字面量因此要在复习时逐项对：名称、件数、单价。漏掉单价，茶会变成免费，而且程序照样跑完。把 `Line` 配上后面的错误返回，才能拒绝 0 件。这一章先让 0 可见，所以示例都把三个字段写全。

指针接收者还有共享的含义。`a` 取地址交给两个函数，两个函数看到的是同一笔件数。值接收者则各拿各的副本，谁都改不到柜台的那一笔。共享在小店里出现在「购物车只有一份」的时候：加一杯和减一杯必须打在同一张单上。不共享出现在「把当前金额记进日志」的时候：日志应该留下当时的副本，之后购物车再加包子，日志那一行仍是当时的茶。选接收者就是在选这张单要不要被调用方改写。

方法名和字段名不要抢同一个词的职责。字段 `Qty` 是数据，方法 `AddPtr` 是动作。若再写一个方法也叫 `Qty`，调用和读取会缠在一起。Go 允许方法和字段同名时要看表达式的位置，读的人要停下来分辨。订单这种小类型，字段用名词，方法用动词，金额用 `Line` 这种能看出是计算的名字。打印时优先打印字段或 `Line` 的返回值，而不是把整个结构体交给 `Println`。整个结构体的默认格式会带上花括号和字段，期望字符串会变脆。课程的块只打印整数，整数的字形稳定。

把一笔订单放进函数参数时，写清是值还是指针。`func printLine(o Order)` 保证打印过程不改件数。`func add(o *Order, n int)` 保证加件数写得回去。两个函数可以同时存在。调用点若传来 `nil` 指针，`add` 必须先判断，否则一取 `o.Qty` 就 panic。值参数没有这个缺口，因为值一定是一张单，哪怕是零值的那张。这是值的另一个好处：签名本身排除了缺席。

字面量里的字段若来自变量，变量先声明再填入。`name := "tea"` 然后 `Order{Name: name, Qty: 2, Cents: 1800}`。结构体不会反向创造外面的名字。外面的 `name` 再被赋成 `"bun"`，已经造好的订单不会跟着变，因为字段里存的是字符串的副本。字符串在 Go 里修改时本来就会产生新字符串，订单持有的是当时的那一串字节。这个行为和整数件数一致：都是值。

## 小结

`Order` 把名称、件数、单价放在一起。赋值会复制整份结构体，改副本不影响原件。值接收者的方法改的是副本，指针接收者写回原件。只计算金额时用值接收者。下一章把多笔订单放进切片，并把茶和包子的单价放进映射。映射在没有 `make` 之前不能写入。
