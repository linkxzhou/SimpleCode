上一章把两杯茶乘成了 3600，名称、件数、单价都靠短声明出现。这一章把声明本身拆开。订单仍然是茶 1800 分、包子 600 分。问题变成：一个名字从哪一刻开始存在，没写初值时它是什么，以及为什么同一块里不能把 `qty` 再用 `:=` 声明第二次。

Go 的声明有两条常见的路。`var` 可以写在函数外面，也可以写在函数里面。它允许你只写类型，不写初值。短声明 `:=` 只能写在函数里面，它根据右边的值推断类型，并且至少要引入一个当前块里还没有的名字。两条路都是在给订单的字段找一个可以反复使用的名字。选择哪一条，取决于你是想强调类型和零值，还是想让右边的具体数字决定类型。

先看不写初值的 `var`。整数的零值是 0，字符串的零值是空串，布尔的零值是 false。这三样刚好能描述一张还没填写的订单：件数为 0，名称为空，还没付款。零值是语言给的，不是内存里的随机残留。你声明了 `var qty int`，就可以立刻把它交给 `fmt`，不必先写 `qty = 0`。打印出来的 `0||false` 把三样零值排在一起：数字 0，然后一个空串，所以两个竖线贴在一起，然后是 false。空串是有值的，它的值是长度为零的字符串。它和「这个变量不存在」不同。变量存在，内容是空。

```go run expect="0||false" title="三样零值"
package main

import "fmt"

func main() {
	var qty int
	var name string
	var paid bool
	fmt.Printf("%d|%s|%t\n", qty, name, paid)
}
```

零值让「忘了赋值」和「故意是空的」在打印上看起来一样。这是代价。一张件数还没填的订单和一张明确买零杯的订单，在整数上都是 0。语言选择给每个类型一个可用的零值，是为了让你少写一遍初始化，也是为了让结构体在后面整块变成零值时仍然可以被调用。代价是 0 不能单独充当「未填」的信号。若业务上零杯和未填必须分开，就要另加一个布尔，比如 `filled`，或者把件数换成指针。指针的零值是 nil，能和「指向一杯茶」区分开。那是零值那一章要展开的取舍。这一章先记住：`var qty int` 已经是 0，打印它是合法的，拿它去乘单价会得到 0，终端里的 0 是算出来的，不是空白。

短声明把声明和第一次赋值并成一步。`qty := 2` 的类型是 `int`，因为 2 是无类型整数常量，短声明把它落成默认的 `int`。`cents := 1800` 同样是 `int`。`name := "tea"` 是 `string`。你不必在左边再写类型。推断的好处是订单行变短，读的人先看见 2 和 1800。坏处是类型藏在右边。右边若是一次函数调用，返回值的类型要到函数签名里才看得见。这一章的右边都是字面量，推断没有歧义。

```go run expect="3600" title="短声明乘出金额"
package main

import "fmt"

func main() {
	qty := 2
	cents := 1800
	fmt.Println(qty * cents)
}
```

3600 和上一章相同，因为数字没变。变的是你现在知道 `:=` 在做两件事：让 `qty` 和 `cents` 从这一行开始存在，并且立刻带上右边的值。存在的范围是包住它们的这一对花括号，也就是 `main` 的函数体。函数返回之后，这两个名字消失。下一次 Run 是新的进程，不会记得上一次的件数。

已经存在的名字再用 `:=` 声明一次，会失败。下面这一段保持不可运行，因为它在同一块里把 `qty` 声明了两次，右边没有任何新名字。解释器的诊断是短声明的左边没有新变量。这不是运行到一半才发现的逻辑错误，是这份文件在开始执行 `main` 之前就站不住。

```go norun title="同一个名字不能再短声明"
package main

import "fmt"

func main() {
	qty := 2
	qty := 3
	fmt.Println(qty)
}
```

失败的原因值得说清楚。短声明的语义是「声明，必要时顺便赋值」，不是「无论是否存在都覆盖」。若它允许把已有的 `qty` 再声明成 3，读者就分不清这一行是新开了一个内部变量，还是改了外面的件数。Go 选择让纯重复的短声明直接失败，迫使你改用赋值 `qty = 3`。赋值不引入名字，只替换已有名字的内容。声明和赋值分成两个记号，`:=` 和 `=`，就是为了让这一眼能看出来。

短声明有一条容易看漏的放行规则。如果左边有多个名字，其中至少一个是新的，整行可以使用 `:=`，已经存在的那些名字会被重新赋值。这不是「可以随便再声明」，这是「这一行里仍然有声明发生」。茶的件数从 2 改成 3，同时引入一个新的备注 `note`。`qty` 是旧的，`note` 是新的，所以这一行合法。打印出来是 `3 tea`。若你把 `note` 也提前声明了，左边就再没有新名字，同一行会回到上面的失败。

```go run expect="3 tea" title="至少有一个新名字"
package main

import "fmt"

func main() {
	qty := 2
	qty, note := 3, "tea"
	fmt.Println(qty, note)
}
```

这条放行是为了 `n, err :=` 这种反复调用。第一次调用时 `n` 和 `err` 都是新的。下一次调用，`err` 已经存在，但 `n` 若是新的，或者反过来，短声明仍然能用。错误那一章会大量遇到它。在订单的件数上，它的危险是：你以为自己在声明一个新的 `qty`，其实只是因为旁边多写了一个新名字，旧的 `qty` 被悄悄改掉了。读这种行时，先标出哪个名字是新的。新名字是这行得以存在的理由，旧名字只是被赋值。

`var` 也可以带初值。`var qty int = 2` 把类型写在中间。`var qty = 2` 让编译器从右边推断，效果和短声明接近，但它可以出现在函数外面。函数外面没有 `:=`。课程的可运行块把订单数据放在 `main` 里，所以两种写法都能用。函数外的 `var` 适合整个程序共享的常量级数据，可是全局的件数会让每一块示例互相看不见，也无法单独重置。教学块因此把 `var` 留在函数内部，用来展示零值。你在自己的文件顶部放 `var defaultCents = 1800` 是合理的，因为标价是店的事实，不是某一笔订单的事实。件数是每一笔订单自己的，放在函数里。

常量 `const cents = 1800` 是第三条路。常量在编译期就固定，不能被赋值改掉。标价若永远是 1800，常量比变量更诚实。这一章仍用变量，因为后面要演示赋值和短声明的差别。常量没有零值问题，也不能用 `:=`。等标价稳定下来，再把它收成常量。现在若收成常量，`cents = 600` 这种把茶改成包子的练习会直接失败，失败的原因会和短声明的失败混在一起。

作用域再补一层。花括号会打开新的块。在 `if` 的条件里用短声明，名字属于那个 `if`，出了 `if` 就看不见。这对 `err` 很方便，错误的名字不会漏到后面。对件数不方便：你在 `if qty := 2; qty > 0` 里声明的 `qty`，到了 `if` 后面想打印就找不到了。订单的件数若还要在判断之后使用，就在 `if` 之前声明。把名字的寿命写成和它的使用一样长。寿命太短，后面要用时只能再声明一个同名的，两个 `qty` 各算各的，读的人会以为它们是同一个。

类型一旦在声明时定下，就不能在同一个名字上换成另一种。`qty := 2` 之后，`qty = "tea"` 会失败，因为左边是整数，右边是字符串。这是静态类型在订单上的直接后果。件数和名称看起来都是「这一列的值」，语言拒绝让一个名字前后充当两列。你要同时保住两者，就用两个名字，或者用后面的结构体把它们收成一笔订单的两个字段。结构体是下一章的事。这一章用两个变量已经能把 2 和 `"tea"` 同时留下来。

未使用的局部变量，正式编译器会拒绝。声明了 `spare := 600` 却从不读取，等于店里进了包子的标价却没有任何订单用它。解释器有时对这种变量比编译器松。课程不留。每个名字要么参与打印，要么参与乘法。否则下一章的读者会以为 600 已经进入了合计。

把赋值和声明放在同一笔账里再走一遍。开始时 `var qty int` 是 0。然后 `qty = 2` 把它改成两杯。`cents` 用短声明直接是 1800。合计是两者相乘。这条路径和一开始就 `qty := 2` 的路径得到同一个 3600，差别在中间多了一次零值。多出来的零值在这段里没用，所以生产代码会直接短声明。教学代码留下它，是为了让你看见 0 是真实的起点，赋值才把订单填上。

包子的 600 分这一章还没有进可运行块的合计。它出现在叙述里，是为了给下一道练习留一个还没被声明的数字。你在练习里声明它时，选择 `var` 还是 `:=`，要看你想不想先看见零值。两种选择都能把 600 交到打印里。交不到打印里的声明，对终端来说等于没写。

[Go by Example](https://gobyexample.com/) 有变量和常量的页。[Learn Go with Tests](https://quii.gitbook.io/learn-go-with-tests) 从整数讲起，用测试钉住结果。这里的竖线和 `3 tea` 是订单自己的例子。

再把包子放进同一块里看一次赋值和声明的边界。`teaCents := 1800` 之后，`bunCents := 600` 是一个新名字，短声明成立。合计若写成 `total := teaCents*2 + bunCents*4`，类型仍是 `int`，因为乘法的两边都是整数，结果也是整数。没有隐式地变成浮点。四只包子 2400，两杯茶 3600，加在一起是 6000。这个 6000 里没有任何舍入。你若中途把其中一个因子写成 `2.0`，短声明会把那个名字推断成浮点，后面再和 `int` 相加就会失败。失败比悄悄转换成浮点更符合这门课的单价：分是整数，全程保持整数。

块的嵌套还会制造同名的新变量。在 `main` 里 `qty := 2`，再在一对花括号里写 `qty := 9`，内层的 `qty` 是另一个变量，挡住外层，直到右花括号。外层的两杯还在。这种挡住能编译，也容易把人看晕。订单的件数在一份函数里最好只有一个名字。内层若只是临时的折扣件数，就叫 `discountQty`，不要复用 `qty`。短声明允许同名，是因为块是新的作用域；允许不等于这笔账需要它。

`var` 一次可以声明多个名字：`var qty, cents int`。它们都是 0。这行适合你想强调「这两个都是整数，先留空」。短声明一次也可以多个：`qty, cents := 2, 1800`。右边的个数要和左边一致。个数不一致会在解释前失败。失败比跑起来之后少乘一个因子要早。早一点停，终端里就不会出现一个看起来像单价的 1800，让你以为合计已经算完。

## 小结

`var` 不写初值时，件数是 0，名称是空串，付款标记是 false。短声明在函数内同时完成起名和赋初值。左边全是已有名字时，`:=` 会失败，应改成 `=`。左边还有一个新名字时，旧名字会被赋值。下一章把名称、件数、单价收进同一个结构体，并看复制一份订单之后改件数，原来的那份还在不在。
