`:=` 在函数里同时声明和赋值，类型由右边推断。`const` 是编译期就定下来的名字。`iota` 在一组常量里从 0 开始数。

包级变量用 `var`。短声明只能出现在函数内部。

```go run expect="Ada" title="名片"
package main

import "fmt"

const boiling = 100

func main() {
	name := "Ada"
	fmt.Println(name)
	fmt.Println(boiling*9/5 + 32)
}
```

```go run expect="0 1 2" title="iota"
package main

import "fmt"

const (
	red = iota
	green
	blue
)

func main() {
	fmt.Println(red, green, blue)
}
```

```go run expect="2000" title="单位换算"
package main

import "fmt"

func main() {
	km := 2
	fmt.Println(km * 1000)
}
```

:= 在函数内部同时声明和赋值，类型从右边推断。同一行里至少要有一个新名字，否则不能用 :=。函数外面没有 :=，包一级用 var 或 const。短声明因此不会出现在示例的顶层，只出现在 main 里面。

const 在编译期就定下来。iota 在一组 const 的括号里从 0 递增，下一组 const 重新从 0 开始。不要以为文件里的 iota 会一直加下去。跳过一个值可以写 _ = iota。

整数运算的类型必须一致。int 和 int32 不能直接相加，要转换。教学例子全用 int，避开宽度问题。Yaegi 里 int 够放本章的数。除法是去尾的整数除法，20/6 得 3，不是 3.333。

单位换算先写成乘法再写除法时，注意先乘后除可以减少整除丢掉的余数。先除后乘可能变成 0。示例把 254/100 这种比例写成先乘再除。

短声明的「至少一个新名字」经常在 if 里出现：if v, err := fn(); err != nil。这里的 v 和 err 都是新的，所以可以用 :=。下一行如果再 := err，就会报错，因为没有新名字。

iota 适合一组相关常量，例如状态编号。不相关的常量分开写，避免读者以为它们的数值有顺序含义。打印 iota 的结果时把三个值都打出来，一眼能看出从 0 开始。

整数溢出不在本章讨论。例子里的数都很小。单位换算如果先除，3 * (254/100) 里 254/100 先变成 2，结果少 1。先乘再除得到 7，这是整数算法的细节，不是打印错了。

函数内部用 := 同时声明和赋值，至少要有一个新名字。n := 1 之后可以写 n, m := 2, 3，因为 m 是新的。如果两个名字都已经存在，再写 := 会失败。if 里的短声明同样遵守这条：if v, err := fn(); err != nil 里的名字对这个 if 是新的。函数外不能用 :=，包一级用 var 或 const。

const 是编译期常量。iota 在常量组里从 0 递增，换一组就重新从 0 开始。不要假设 iota 会跨组连续。整数相除会丢掉小数。3 * 254 / 100 先乘再除得到 7；若先除再乘，254 / 100 先变成 2，结果就不同。换算时先乘后除，并确认中间不会溢出你关心的范围。

var 声明而不赋值，得到类型的零值。整数是 0，字符串是空，布尔是 false，切片和 map 是 nil。零值不是「未初始化所以不能读」，读它是合法的，写 nil map 才不合法。打印零值可以确认声明成功，但不要把零值当成用户输入过。

未使用的局部变量也会让程序无法运行。教学示例里每一个名字都要么打印，要么参与下一次运算。

## 最佳实践

- 函数里用 :=，包一级用 var 或 const。
- 每一组 const 里的 iota 都从 0 重新数。
- 整数比例先乘后除，避免提前变成 0。

## 小结

:= 只属于函数内部，const 和 iota 按组计数。整数相除会丢掉小数，换算时先乘后除。

## 常见错误

- 在函数外使用 :=。短声明只属于函数内部。
- iota 写在单独的 const 里却以为会继续加。每组 const 都会重新从 0 开始。
