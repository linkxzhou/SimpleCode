茶的名称在字符串切片里，单价在整数切片里。取出「下标 0 的那一项」这件事和元素类型无关。若为字符串写一个 `PickString`，为整数再写一个 `PickInt`，两份函数的函数体完全一样，改下标检查时要改两次。泛型让函数带上类型参数，函数体写一次，调用时再确定是字符串还是整数。这一章只写 Yaegi 0.16 能够运行的简单函数。订单仍是茶 1800 分、包子 600 分。

类型参数写在函数名后面的方括号里。`func Pick[T any](xs []T, i int) T` 的意思是：`T` 可以是任何类型，参数是这种类型的切片和一个下标，返回值也是这种类型。`any` 是空接口的别名，约束很宽，因为 `Pick` 并不对元素做运算，只是把元素交回去。调用 `Pick([]string{"tea", "bun"}, 0)` 时，`T` 推断为 `string`，返回 `tea`。同一次程序里再调用 `Pick([]int{1800, 600}, 1)`，`T` 推断为 `int`，返回 `600`。两行输出因此是商品名和包子的单价。

```go run expect="tea" title="取出名称或单价"
package main

import "fmt"

func Pick[T any](xs []T, i int) T {
	return xs[i]
}

func main() {
	fmt.Println(Pick([]string{"tea", "bun"}, 0))
	fmt.Println(Pick([]int{1800, 600}, 1))
}
```

推断发生在调用点。你也可以写明 `Pick[string](...)`。写明的好处是类型在调用处可见，坏处是和参数重复。参数已经是 `[]string` 时，重复通常没有新信息。推断失败时再写明。`Pick` 的两个调用都能推断，所以块里不写方括号实参。

`any` 做不了比较。若要问两笔单价是不是同一个数，约束要收紧成 `comparable`。`comparable` 表示可以用 `==`。整数和字符串都可以。`Same` 返回布尔。1800 和 1800 得到 true，`tea` 和 `bun` 得到 false。打印时 `Println` 会把布尔写成 `true` 和 `false` 两行。

```go run expect="true" title="能比较的类型才相等"
package main

import "fmt"

func Same[T comparable](a, b T) bool {
	return a == b
}

func main() {
	fmt.Println(Same(1800, 1800))
	fmt.Println(Same("tea", "bun"))
}
```

约束是泛型相对接口的一个不同点。接口在运行时携带具体类型，方法调用去找动态的那一份。泛型在编译或解释时就把 `T` 定下来，函数体里能做的事受约束限制。`Same` 能写 `a == b`，是因为约束承诺了比较。`Pick` 不能写 `a == b`，除非把约束改成 `comparable`。约束写宽，能服务的类型多，函数体能做的事少。约束写窄，能做加法或比较，切片和通道这种不支持比较的类型就被挡在外面。订单的名称和单价都支持比较，`Same` 够用。订单结构体里若以后放了切片，整个结构体就不再 `comparable`，比较要改成你自己写的函数，按字段看。

最小值是窄约束的例子。茶和包子的单价取较小的一个，应该得到 600。Go 1.21 有内建的 `min`，这个解释器没有那个内建，直接调用会报未定义。下面的块只保留长相，不运行。

```go norun title="这个解释器没有内建 min"
package main

import "fmt"

func main() {
	fmt.Println(min(600, 1800))
}
```

自己写一个泛型 `Min` 就能运行。约束用 `~int`，表示底层类型是 `int` 的类型，包括 `int` 本身和 `type Cents int` 这种定义类型。函数体比较两个数，返回较小的。`Cents` 的 600 和 1800 比较，结果是 `Cents(600)`，打印出来仍是 600。用 `~int` 而不是写死 `Cents`，是为了让普通 `int` 的件数也能调用同一份函数。写死 `Cents` 的话，件数又要再抄一遍。

```go run expect="600" title="较小的单价"
package main

import "fmt"

type Cents int

func Min[T ~int](a, b T) T {
	if a < b {
		return a
	}
	return b
}

func main() {
	fmt.Println(Min(Cents(600), Cents(1800)))
}
```

`~int` 不允许字符串混进来。`Min("tea", "bun")` 会在解释时失败，因为字符串的底层类型不是 `int`。失败是约束在起作用。若你希望名称也能取字典序较小的一个，约束要放宽成一组类型，或者写成两种函数。一组类型的联合约束这个解释器也能跑简单的加法，可是订单的最小值目前只发生在金额上，收成 `~int` 更诚实。名称的先后用切片的下标表达，不拿来做算术。

泛型函数仍然必须放在这一份 `package main` 里。它不是一个可以单独导入的包。想把 `Pick` 放进 `shop/seq` 再导入，抽屉里没有那个目录。不可运行的导入和第一章的说明相同。泛型没有改变「单文件」这条界限，它只减少同一文件里的重复。

类型参数也可以出现在结构体上，比如 `Box[T any]` 里面放一个 `T`。简单的字段和取值方法在这个解释器上能运行。课程仍把可运行的重点放在函数上，因为计价需要的是「取出」和「取较小」，不是再包一层箱子。箱子会把 `Cents` 藏起来，每取一次多一次方法调用，订单的字段本身已经是名字清楚的整数。泛型结构体值得用的时候，是容器真的和元素类型无关，比如一个你自己写的栈。单价表用映射就够了，不必写成泛型栈。

和接口的分工可以放在这笔账上。`Priced` 适合「茶和包子的计算方法不同，调用者只想要一个整数」。泛型 `Pick` 适合「计算方法相同，只是元素类型不同」。若你用接口去取下标，每个元素都要实现一个方法，切片却仍然是具体类型，接口帮不上「让一份函数体服务两种切片」。若你用泛型去隐藏茶和包子的不同算法，约束里就得列出所有运算，最后写成一个巨大的接口约束，读起来比直接写两个方法更绕。金额的差异用接口，容器的相同动作用泛型。

下标要合法。`Pick` 不做边界检查，下标越界仍会 panic。泛型不改变运行时的切片规则。调用处保证下标来自 `len` 的范围内。这一章的下标 0 和 1 都落在长度为 2 的切片里。若要让 `Pick` 交回错误而不是 panic，签名可以变成 `(T, error)`，空切片时用 `errors.New`。那是错误那一章的形状加上类型参数，能写，但期望会分成两路。这一章的切片非空，返回值只有 `T`。

[Go by Example](https://gobyexample.com/) 的泛型页从类型参数讲起。[Learn Go with Tests](https://quii.gitbook.io/learn-go-with-tests) 把泛型用在真的消除重复的地方。这里重复的是取出元素和取较小的整数。

类型推断偶尔会在嵌套调用里失败。`Pick(Pick([]int{600, 1800}, 0), 0)` 这种写法并不合法，因为内层返回的是 `int` 不是切片。推断失败的诊断会指出类型参数无法确定，或者参数类型对不上。这时先把内层的结果放进一个有名字的变量，看清它是整数还是切片，再决定外层。订单的名称和单价不要挤在一次嵌套里。变量 `name` 和 `cents` 本身就是文档。

约束里的方法集是另一种写法。`func CentsOf[T interface{ Cents() int }](v T) int` 能调用 `v.Cents()`。这和上一章的接口参数很像，差别是泛型在实例化时就绑定具体类型，接口在运行时才知道具体类型。茶和包子要放进同一个切片时，元素类型必须是接口，泛型函数帮不上「一个切片两种具体类型」。切片的元素类型是单一的。`[]Tea` 和 `[]Bun` 可以分别交给同一个泛型函数，只要函数只用它们共有的操作。混装仍用 `[]Priced`。

`~int` 把定义类型纳入进来，是为了不强迫你把 `Cents` 转回 `int` 再转回去。转换会让一笔金额在某个瞬间失去「这是分」的标记。`Min` 返回的仍是 `Cents`，调用者不会突然拿到一个裸 `int` 再误当成件数。件数若是另一个定义类型 `Qty`，它的底层也是 `int`，`Min` 同样能用，但你不能把 `Qty` 和 `Cents` 放进同一次调用，因为同一次调用的 `T` 只有一个。这阻止了「件数和单价取最小」这种没有业务意义的比较。想比较它们，先各自转换成 `int`，并在那一行看见自己正在丢掉单位。

泛型不会替你做边界检查，也不会替你分配映射。`Pick` 的切片若是 nil，长度是 0，下标 0 仍会 panic。nil 切片交给泛型函数和交给普通函数是同一种 panic。不要以为类型参数改变了容器的零值规则。该 `make` 的映射还是要 `make`。泛型只去掉重复的函数体。

这个解释器跑得动的范围，课程停在函数、`any`、`comparable` 和 `~int`。再复杂的约束、再深的嵌套，若某一天 Run 报出解释器内部的错误，就把那一块标成不可运行，留一个更小的 `Pick` 或 `Min` 作为能跑的对照。能跑的对照必须仍是 `package main` 和 `func main`，输出仍是订单上的数。对照失败时，先缩小类型参数，而不是改用 `time.Sleep` 或拆成第二个包。

调用 `Min` 时两个参数的类型要一致。`Min(600, Cents(1800))` 会失败，因为一个是 `int`，一个是 `Cents`，没有唯一的 `T`。先决定这张单子用定义类型还是用裸整数，再全程保持。课程的可运行块在同一次调用里两边都是 `Cents` 或两边都是 `int`。混用看起来像都能代表钱，类型系统把它们分开，是为了防止件数和分在同一次 `Min` 里比大小。

`Pick` 返回的是元素的副本。元素若是结构体，改返回值不会改切片里的那一笔。元素若是指针，副本的是指针，两边指向同一笔订单。泛型不改变元素本身的值语义。你把 `[]Order` 交给 `Pick`，拿到的是一笔订单的副本，改件数要再写回切片下标。这一点和接口那一章把值放进接口时的复制是同一条语言规则，只是容器从接口换成了切片。

把 `Pick` 用在订单切片上时，下标来自人的选择，比如客人要看第一笔。下标若来自外部输入，先和 `len` 比较，越界就返回错误，不要让 panic 代替错误。泛型函数可以把这个检查写进函数体，返回 `(T, error)`。零值的 `T` 在失败时一并返回，调用者只在 `err == nil` 时使用它。这和 `charge` 的契约相同，只是成功值的类型是参数 `T` 而不是写死的 `int`。本章的下标是字面量 0 和 1，检查省掉了，契约仍值得记着。

`Same` 对字符串比较的是内容，不是变量是不是同一个名字。两处写的 `"tea"` 内容相同，`Same` 为 true。订单名称用这个比较就够了。指针是否指向同一笔，要用指针类型，不能用 `Same` 去比两个结构体的地址，除非你传入的就是指针。

`Min` 在两数相等时返回哪一个都可以，因为值相同。茶和包子单价不同，600 是唯一的较小值，打印没有歧义。相等的用例留给 `Same`，不相等的大小留给 `Min`，两个函数各管一种比较。

类型参数的名字用 `T` 就够了。订单这里没有第二个类型参数，不必写成 `TItem` 这种更长的名字。等函数真的同时涉及商品名和金额两种类型，再分别叫 `T` 和 `U`，并在约束里写清各自能做什么。一个函数里类型参数越多，调用越难读。`Pick` 和 `Min` 各有一个，读起来和普通函数差不多。

## 小结

`Pick[T any]` 能从字符串切片取出 `tea`，从整数切片取出 `600`。`comparable` 允许 `==`，`~int` 允许比较大小。内建 `min` 在这个解释器里不可用，自己写 `Min`。下一章在一份文件里把结构体、错误和切片接成一整张订单的合计。
