类型参数写在函数名后面的方括号里。`T any` 表示任何类型。简单的恒等函数用来确认这条路径能跑。

Yaegi 0.16 对泛型的支持有限。带复杂约束、类型推断嵌套或泛型数据结构的代码标成只读，请在官方 `go` 命令里试验。

```go run expect="42" title="恒等函数"
package main

import "fmt"

func Identity[T any](v T) T {
	return v
}

func main() {
	fmt.Println(Identity(42))
}
```

```go run expect="y" title="取第二个"
package main

import "fmt"

func Second[T any](a, b T) T {
	return b
}

func main() {
	fmt.Println(Second("x", "y"))
}
```

类型参数写在函数名后面的方括号里。T any 表示调用时可以是任何类型。函数体里只能做对任何类型都合法的事，例如原样返回，不能假设 T 有某方法，除非你写了约束。

Yaegi 0.16 能跑恒等函数、返回其中一个参数这种简单形式。带复杂约束、泛型数据结构或很深的类型推断时，行为和官方编译器不一致。那些例子标成只读。练习如果只是想要「两个 int 相加」，写成普通函数更稳，不必为了出现方括号而冒险。

类型参数不是运行时的盒子。编译器（或解释器）在调用点确定 T。你不能在运行中往同一个泛型函数里混入两种不相关的类型，除非约束允许。简单例子每次只实例化一种。

读代码时，先忽略方括号，看函数对值做了什么。如果去掉类型参数仍然清楚，说明这里可能不需要泛型。泛型是为了少写一遍相同的函数，不是为了让签名更长。

方括号里的 T any 读作「T 可以是任何类型」。函数体里如果写 v + v，就要求 T 支持加法，any 不够。那样需要约束。约束在这个解释器上不可靠，所以可运行的泛型函数不做运算，只挑选或返回参数。

具体类型的 Add 更好读，也更好测。本章练习故意用普通函数，是为了让你把「泛型不是目的」记住。目的是少重复，而两个整数相加没有重复。

练习如果只是两个整数取较大值，写成普通函数。能用具体类型写对的逻辑，不要为了出现方括号去冒险。复杂泛型留在只读说明里，到本地的 go 命令再试。

打印时打印具体的值，例如字符串 go 或整数 3，让期望不依赖类型名字。类型名字在运行时不会自动出现在输出里。

### 读「恒等字符串」

## 练习

写一个返回两个同类型参数之和的泛型函数，只实例化成 int，打印 20+22。

::: answer 参考答案
```go run expect="42" title="参考答案"
package main

import "fmt"

func Add(a, b int) int { return a + b }

func main() {
	fmt.Println(Add(20, 22))
}
```
:::

写普通函数返回两个整数中较大的一个，打印 8 和 3 的结果。

::: answer 参考答案：较大值
```go run expect="8" title="参考答案"
package main

import "fmt"

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func main() {
	fmt.Println(max(8, 3))
}
```
:::

## 最佳实践

- 只把 Yaegi 上验证过的简单泛型放进可运行块。
- 能用具体类型写清楚时不必加类型参数。
- 复杂约束留在只读块，到本地 go 命令里试验。

## 小结

简单类型参数在这里可以运行。复杂泛型不可靠，练习优先用具体类型把逻辑写对。

## 常见错误

- 为了练泛型而把所有函数都加上类型参数。具体类型更清楚时不必泛化。
- 在 Yaegi 里调试失败的复杂泛型。先换成具体类型确认逻辑，再拿到本地 Go 里恢复类型参数。
